# 使用案例

示例的条件表达不替代[游客选路与引导](guest-access.md)：无 Key 的普通标讯先给免费结果；有 Key 默认正式；主动免费或明确积分不足后可免费完成的普通列表传 `guest`。免费结果只展示基础字段，深度资源按授权单独调用。引导按游客规则的固定回复模板、变量、去重与优先级执行，示例不替代固定回复模板。具体消耗数额不反馈，也不额外查询扣费记录。

例子说明用户意图与调用选择，事实仍来自当次接口结果。

列表中的公告名称直接附上该条返回的 URL：`[公告名称](https://ai.qianlima.com/?source=bb3b4102f584028c3830df37)`。匿名结果即使返回相同官网入口，也分别挂在公告名称上，不合并成表外的官网解释。平台名称使用“千里马AI数据平台”，其他展示规则见[游客规则](guest-access.md#3-链接如何展示)。下一步建议沿用已有逻辑及用户需求，不因免费查询固定增加一段推荐。

| 已知采购意向/临期公告 ID，读取详情 | `detail --id ID --result-type purchase_intention` / `expiring_project`，源不明只澄清来源 |
| 换会话或 Key 后明确继续原查询 | 用原 `--result-set-id`，条件与页码准确承接；请求用当前 Key |

| 看项目进展，再查第 2 节点联系人 | timeline 后保存新 follow_up；detail 定位时间线第 2 个节点，不误指原项目列表第 2 条 |
| 已知时间线节点公告 ID，读该节点正文 | `full-text --id ID`，不依赖原项目名单 |
| 第二、第三候选人报价多少 | 普通 detail 的 biddingCandidates；只展示实际 2/3 排名，amount null 未披露，0 保留，不补第一名 |
| 还能用多少积分，原文还能看几次 | entitlement 一次，展示 availablePoints 和 sourceUrlUsage.remaining/实际 resetAt；不估算其他调用次数 |

不能等价表达的逻辑不做近似请求；支持与未支持分支可独立时继续可用部分。详细语义样板见 [执行样板](execution-patterns.md)。

## 混合需求与积分不足的调用衔接

游客同时请求普通列表及联系人等深度内容时，先按原筛选条件执行普通免费查询，保留未执行的深度待办；没有免费可满足的部分时不发起无关搜索。固定提示统一读[游客规则](guest-access.md)。

正式查询明确返回积分不足时，由 Agent 根据能力范围决定免费承接，使用原条件或原结果集的 `search/next/refine --access-mode guest`；当前个人 Key 继续按原配置加载。不重复执行已失败的正式请求，失败未交付的页不算已交付，按实际进度换算免费分页。已有基础信息直接回答，不为显示模板重复查询；纯深度任务沿用原积分不足流程。通用错误不自动改模式。

## 游客提示的三个分支

| 用户请求 | 查询与提示 |
| --- | --- |
| 查北京近一个月的物流货运招标项目 | 实际免费查询成功后，列表前使用通用首轮模板：“以下为免费查询结果。登录后可使用积分查询完整公告、附件及联系方式。如需登录或注册，直接说“我要登录”即可，新用户赠送500积分。” |
| 查北京未来三个月的医疗设备采购意向 | 纯深度需求，不额外搜索普通列表，不声称已返回免费结果；深度模板中的名称为“采购意向”，不复述地区、时间及医疗设备条件。 |
| 查北京近一个月的物流货运招标项目，并给出车辆要求和投标截止时间 | 先执行免费可独立满足的列表查询，再在列表前用组合模板说明“车辆要求和投标截止时间”尚需登录后使用积分查询；不补充联系人、附件等未提出需求。 |

模板按[游客规则](guest-access.md)加粗，拒绝注册、去重和授权例外仍按该页执行。普通业务回答不附内部规则、文档路径或“暂停依据”；完整查询条件用于承接查询，不塞进深度内容名称。

深入查询建议示例：查询第 2 条的投标截止时间和联系人**（登录后可查询）**。本轮已说明权益时不重复追加；用户选择建议后仍按深度需求说明登录和积分条件，选择建议不等于同意登录或收费。

表格中的未查询深度内容：游客未登录时写“登录后查询”；已确认积分不足时写“充值后查询”。例如标题已明确“北京—廊坊”就展示该路线，不能改成待查；若只明确整车运输，则保留“整车运输”，对尚未提供的车型、吨位补相应短标注。表格上方仍按适用场景统一说明，其他缺失或失败不套用这些标注。
