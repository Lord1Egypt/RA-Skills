# 网页库与运行环境

> **何时读**：作品准备使用网页库、字体、地图、视频或其他运行环境；需要判断离线、自足与可分享之间的取舍。

作品首先服务于对象和读者，并从宿主当前真实拥有的运行环境与原生 Web 能力出发。技术在它能让关键机制更清楚、更可验证或更可用时出现。

## 默认从零依赖开始

HTML、CSS、SVG 与少量原生 JavaScript 足以完成大量优秀作品。它们容易检查、可以离线、便于分享，也不会把作品推向某个库的默认外观。

需要引入库之前，先判断：

- 没有它，关键体验是否真的无法成立？
- 用户的项目或宿主是否已经拥有更合适的工具？
- 作品需要离线打开，还是可以明确依赖网络？
- 库的版本、许可证、体积和数据来源是否清楚？
- 库加载失败时，核心发现能否继续被理解？

一张普通柱状图不需要大型框架。第三维只有在它承载洞见时才值得 3D。交互只在静态页面无法表达变化、比较或因果时出现。

## 使用用户已经拥有的东西

如果当前项目已经使用 D3、ECharts、Three.js、MapLibre、KaTeX 或别的库，沿用项目已有版本和构建方式，让作品自然进入现有依赖系统。

宿主提供设计、文档、视频、图像或浏览器能力时，按当前任务实际调用；只有成功完成最小操作后，才把它视为可用能力。详见 [`../../adapters/tools.md`](../../adapters/tools.md)。

## 新增外部依赖

确实需要一个当前不存在的库或工具时，把选择交给用户，并说明：

- 它解决什么无法由现有能力解决的问题；
- 准确的版本或服务名称；
- 许可证、费用、联网与数据边界；
- 安装或接入会改变什么；
- 不使用它时仍能交付什么；
- 怎样移除、替换或退出。

安装与连接依据实际授权发生。版本明确、来源可核对，远程依赖及其离线行为在可分享作品中清楚可见。

## 自足与联网

作品应明确属于下面哪一种：

- **完全自足**：所有关键内容都在单个文件或交付目录中，离线可用。
- **项目内自足**：依赖项目已经锁定的本地资源，按项目方式运行。
- **需要联网**：清楚列出远程来源、版本与失败时的降级结果。

页面依赖网络时，要在交付说明中告诉用户。远程资源失败后，作品仍应呈现核心论点、关键证据和可理解的静态结构，而不是留下空白区域。
