# 公允价值·逐条挂源

给一份财报或公告，把**公允价值的披露**读成一张**每条都能回到原句**的登记表：公允价值计量概况、公允价值层次归属、估值技术与输入值、层次间转换、第三层次变动。

公允价值这一块最容易被读成「估值意见」：既然披露了第三层次、既然写了折现率，那是不是就说明估值合理？可披露里能确认的只有「哪些资产按公允价值计量、各多少钱、披露说它属于第几层次、用了什么估值技术、输入值是否可观察、本期转进转出多少、第三层次期初怎么滚到期末」——层次划得对不对、估值是否公允、往后一期公允价值会怎么变，都不是附注能回答的，也不是本件该回答的。

层次归属只认附注原话，不按资产类别自己归层；估值技术与输入值照抄原句，不补「应该用 DCF」这类技术意见；转换金额、期初余额、当期损益、期末余额各占各行，不轧净额。

本件不评价层次划分、不做估值建模、不测算减值、不给评级与目标价。

## 一、零依赖三分钟上手

只装 Python 3，不给任何数据文件，也能跑出一份完整合规的成品，看它长什么样、判据怎么打：

```bash
python3 scripts/check_fair_value.py --demo
```

把这份样例存下来再跑一遍机检——它会照七节形制、三元组与另外三道内容判据逐条判，零发条、退 0：

```bash
python3 scripts/check_fair_value.py --demo > 样例公允价值稿.md
python3 scripts/check_fair_value.py 样例公允价值稿.md   # 打印「—— 机检：0 条发条」，退 0
```

接着换成你自己那份稿子：

```bash
python3 scripts/check_fair_value.py 你的公允价值稿.md
```

退码语义：`0` 五道全过｜`1` 有发条（逐条打印 `码 行号 说明`）｜`2` 用法错（没给稿子路径，也没给 `--demo`／`--selftest`）｜`3` 读不到文件或空稿。零发条但有判据尚未落字时同样退 3——这条规则照旧成立：rc=0 只留给「五道全过」，没跑的道不能算过，报告里那几道计「不可判」，**不等于合规**；它是将来某道回退成空壳时的护栏。**本件当前不触发**：五道已全部落字，好样零发条即退 0。

拿不到成品时，从原文开始的三步：

1. **定主体与报告期**，拿到年报或半年报附注「公允价值的披露」一节、其中的层次表、转换表与第三层次变动表（附注）。
2. **每节抄事实，连原句一起抄**：一条 = 一行，行末挂 `「原句」〔锚：页/表〕[S#]`；披露没写的就写 `未取到：项名`，不留空、不借「上市公司股票当然属于第一层次」这类常识补。
3. **跑一遍自检**，红一条改一条：

```bash
python3 scripts/check_fair_value.py --selftest   # 内置夹具自检（档数与结果以末行现报为准）
```

三档一起跑（自测→好样→坏样，坏样注入必先断言落地）：

```bash
bash scripts/fixtures/run_fixtures.sh
```

## 二、五道机检在管什么

**五道全已落字**：形制与锚是地基，另外三道（层次归属、估值技术与输入值、红线）今天起也由脚本强制，没有空壳、没有「只人读」的道。单稿零发条即退 0。

| 码 | 名称 | 判什么 | 最常拦住的情况 | 现状 |
|---|---|---|---|---|
| `FV-STRUCT` | 形制 | 头部四件自标逐字在位、`主体：`／`报告期：` 行首裸行在场非空、七节齐且按序、前五节各至少一条发现行、「口径与未取到」与「来源」两节不得为空；认不出的节标题与多出同名节记 stray 逐条发 | 把 `主体：` 写成 `- 主体：`；某节只有散文没有发现行；节名改了个字就整节认不出 | **已落字** |
| `FV-QUOTE` | 原句与锚 | 发现行以「」原句＋〔锚：…〕＋`[S#]` 收尾且三元组落在行末，可挂多组，缺哪件点名哪件；来源行 `- [S#] 标题 \| URL \| 检索日 YYYY-MM-DD`，URL 须为可点 http(s)；引用的 `[S#]` 须已登记，来源节一条合规行都没有则单独发一条。例外只有三形：`未取到：` 行、`[待人工]` 行、`〔自算〕` 行 | 只写「第三层次 5.00 亿元」没抄原句；正文引用了 `[S3]` 而来源节没有这一号；检索日写成 `2026/03/20` | **已落字** |
| `FV-LEVEL` | 三层次归类只认原句 | 只判「公允价值层次归属」节：登记值写「第一层次／第二层次／第三层次」（含 `第 1 层次` 阿拉伯写法）而同行原句没有同一个层次词即发；反之漏登记不判。没有「」原句的行整行跳过（缺原句归 `FV-QUOTE`，同一行不发两道） | 附注只说「采用不可观察输入值」、层次词被删净，登记值自己写「第三层次」 | **已落字** |
| `FV-TECH` | 估值技术与输入值只认原句 | 只判「估值技术与输入值」节：登记值的「市场法／收益法／成本法」与「可观察输入值／不可观察输入值」须逐个在同行原句找到同词。输入值词按整词前缀判——`不可观察输入值` 含 `可观察输入值` 这串子串，裸 `in` 会把原句的「不可观察」误算成登记「可观察」的命中 | 原句写「市场法」、登记值写「收益法」；原句「均属不可观察输入值」、登记值写「可观察输入值」 | **已落字** |
| `FV-LINE` | 红线 | 轧账词（净额／轧差／相抵／合计影响）只在**发现行正文**里判，散文与节名不算，「口径与未取到」整节豁免（那节本来就要写「不轧净额」交代口径）；估值意见（估值偏高／偏低／合理、应该用、建议采用）与评级目标价（目标价、买入、增持、减持、评级为）全稿命中即发 | 把转换金额与期末余额写成「净额」；写「第三层次估值偏高」；写「目标价」 | **已落字** |

`--selftest` 逐档打印每档结论，末行自己报 `自测档数=N｜不合=0｜不可判=N`（**两处 N 都以现跑为准，本文不复述数字**）。夹具分类：好样——零发条一档；坏样·形制——头部缺自标、节标题写成认不出的样子、整节删掉「来源」；坏样·锚——摘掉「」＋〔锚〕只留 `[S#]`、来源行检索日写成斜杠式、正文引一个来源节没有的 `[S#]`；坏样·层次——登记值写第三层次而原句里层次词被删净；坏样·技术——登记值写收益法而原句写市场法、原句「不可观察」而登记值写「可观察」；坏样·红线——发现行自己下「估值偏高」的判断；反证——原句写了层次而登记值没写（漏登记不该发）、口径节写「不轧净额」「不相抵」（整节豁免不该发）。自测另有四道机械自证：**覆盖自证**（每道已落字码都至少有一档期望恰含它，缺反例即报）、**空壳自证**（未落字的码调用即抛并点名自身，已落字的码不得抛）、**不崩自证**（空稿／乱头／只头无节均返回二元组）、**单稿退码自证**（好样落盘单跑，退码与「是否还有未落字」绑定现算：有未落字即退 3 且输出须含「不可判」与「这不等于合规」，全落字后自动改判 0 且不得再出现该句）。

## 三、四条红线（这件的立身之本）

> **口径提示**：第 1—3 条对应的机检判据（`FV-LEVEL`／`FV-TECH`／`FV-LINE`）今天起已由脚本强制——归层、估值技术与输入值只认原句，估值意见与评级目标价零命中，撞上了会直接出在机检发条里。

1. **层次归属只认附注原话。** 某项资产属于第几层次，只认附注写的原话；附注没写就写 `未取到：层次归属`，一律 `[待人工]`，不按输入值可观察与否自己判——「股票按收盘价，所以就是第一层次」是常识，不是这一家的披露。
2. **不补估值技术判断。** 市场法／收益法／成本法只照抄原句；不写「应该用 DCF」这类本件自己的技术意见；输入值可观察与否同样只认原话。
3. **不评价层次划分、不估值。** 层次划分是否恰当、公允价值是否公允、目标价与目标市值、买入／卖出／增持评级，一律 `[待人工]`；本件不构成投资建议。
4. **不轧账。** 转换金额、期初余额、当期损益、期末余额各占各行，不写「净额」「合计」「轧差」「抵销」；缺口两向点名：正文写「未取到 X」，第六节也点名 X；零缺口写 `未取到：无`。

## 四、数据通道

发现先行，匿名取 live 目录，拿到 `routing` 后再连接发 `tools/list`，以现场返回为准，不硬编码工具名与工具数：

```bash
curl -sS https://cuecue.cn/api/mcp-catalog -o /tmp/mcp-catalog.json
python3 -c "import json;d=json.load(open('/tmp/mcp-catalog.json'));print(d.get('routing') or d)"
# 拿到 routing 后，带 token 发 tools/list：
curl -sS -X POST "$ROUTING_URL" -H "Authorization: Bearer $CUE_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

- **原文腿**：年报附注·公允价值的披露、公允价值层次表、估值技术说明走数据腿；该域是否开放、是否实时，以 catalog 返回为准，本件不承诺。
- **正文腿**：附注与估值说明常夹在数百页 PDF 里（层次表、转换表、第三层次变动表），长附件与扫描件交 `cue-omni-reader` 解析——先取大纲，再按节取用；计费与可用性以服务端返回为准。
- **深研**：`cue-research` 是独立入口（自带运行脚本），凭据同一把 key。
- 配置页只给指针、不复述开通步骤：数据腿 <https://cuecue.cn/hub/mcp>；解析腿 <https://cuecue.cn/hub/omni-reader>；取 key <https://cuecue.cn/hub/api-key>。

不装通道也能跑：只拿用户直供的附注截图或层次表，五节骨架照样出，代价是看不到附注里的完整层次表与第三层次变动表，只能登记随附材料汇总的那几行，证据密度降为单份材料且没有出处可回查。

本件不发请求、不代付费，消耗以服务端返回为准。

## 五、本件不做什么

| 不做 | 谁来做／怎么办 |
|---|---|
| 判某项资产该归第几层次、划分得对不对 | 一律 `[待人工]`；本件只登记附注写的层次原话 |
| 给估值技术意见（「应该用 DCF」「折现率取值偏高」） | 一律 `[待人工]`；技术只照抄原句 |
| 按资产类别或输入值自行归层、按比率反推公允价值 | 层次、技术与数只照抄附注原句 |
| 把转换金额、期初余额、期末余额轧成净额 | 各占各行、各挂各的原句 |
| 重算公允价值变动带来的暂时性差异 | `cn-deferred-tax-cn` 管递延所得税；本件只挂涉及的那条原句 |
| 测算公允价值变动对每股收益的影响 | `cn-eps-cn` 管每股收益；本件不测算影响数 |
| 减值测试与商誉减值判断 | `cn-goodwill-impairment-risk` 管商誉；本件只在披露相互引用时挂原句 |
| 给评级、目标价、目标市值、高低估 | 一律 `[待人工]`；本件不构成投资建议 |

## 六、和另外几枚包怎么分

| 你手上是 | 用哪枚 |
|---|---|
| 公允价值的计量概况、层次归属、估值技术与输入值、层次转换、第三层次变动 | **本件** |
| 会计政策变更的性质与依据、追溯调整与累积影响 | `cn-accounting-policy-change-cn` |
| 递延所得税的确认、计量与转回 | `cn-deferred-tax-cn` |
| 基本与稀释每股收益、加权平均股数 | `cn-eps-cn` |
| 商誉减值测试与减值风险台账 | `cn-goodwill-impairment-risk` |
| 其他权益工具（永续债／优先股）的条款与分类依据 | `cn-other-equity-instruments-cn` |

本件只管**公允价值这一块**：政策变更涉及公允价值计量的，本件只挂披露原句，变更性质与追溯调整归 `cn-accounting-policy-change-cn`；公允价值变动引起的递延所得税影响，本件只挂披露原句，暂时性差异与税率归 `cn-deferred-tax-cn`；商誉减值测试里出现的可收回金额与公允价值，本件只登记披露怎么写的，减值判断归 `cn-goodwill-impairment-risk`。同一家公司既有商誉减值又有第三层次估值时，两件各管各的节，不互相代填。
