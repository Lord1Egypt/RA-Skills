# v1.5.2（2026-09-23）

- 计费变更：商品监控（watch）改为**每次到期刷新按频率扣点**（按天 / 按周 / 按月），
  单价以服务端后台配置为准；套餐只体现在每月发放的积点上，不再有「套餐内含免费监控」，
  任何套餐都可选按天（此前 daily 仅 Business 及以上）。刷新失败不扣点。
- 新命令：`watch quote`（各频率每次刷新单价与月估算，0 积点）、`watch series`（价格 / BSR / 评分日序列，0 积点）。
- `watch create` / `watch resume` 新增 `--accept-price`：开启或恢复即授权周期扣点，必须带用户确认过的单价；
  不带时服务端返回 `ARI_CONFIRM_PRICE` 与报价，agent 转述给用户，不自动重试。`--schedule` 支持 `monthly`。
- 余额不足、非美国站只剩赠送积点、后台调价高于确认价时，监控自动暂停并邮件通知（`pausedReason`）。
- 显著变化（价格 / BSR / 评分 / 标题五点图片）即时邮件提醒并进每周简报。
- 旧版本（≤1.5.1）开启 / 恢复监控会收到 `ARI_CONFIRM_PRICE`，不会被静默扣点；不提高最低支持版本。

# v1.5.0（2026-09-22）

- 行为变更：新用户（注册并验证邮箱后）第一次要 VOC，只给 ASIN 即可（站点默认美国站），
  `voc` 直接执行——自动补采集（默认 3 页）、生成报告、按服务端定价扣费并归档，
  不再停在报价等确认。费用在报告返回的 `charges` 字段透明展示（采集/分析/合计/余额前后）。
- 免确认与否**只认服务端报价返回的 `autoConfirm` 布尔**：服务端策略前 N 次付费生成不看金额上限
  （新用户赠送积点按设计覆盖「3 页采集 + 一份 VOC」）；用户自设阈值优先、显式要求「每次先问」
  时仍先报价；余额不足不自动。客户端不再从 `autoConfirmNote` 文案或 `autoConfirmRemaining`
  自行推断——文案匹配会把 Free 小额提示里的「先确认」误判成用户要求每次询问，恰好挡住新用户。
- 采集报价同口径扣除服务端 `trialFreePages`（首次采集试用免费页），避免新用户被误报「积点不足」。
- 非美国站：服务端 `credits.gift` 策略下用户首次采集不限站点，`credits/balance` 返回 `giftAllSites`，
  为 true 时赠送积点计入 `nonUsCollectCredits`、`siteNote` 为空；UK/DE/JP 卖家的第一份 VOC 同样一步直出。
- 余额不足仍在执行前拦截（402）并引导充值；定价以服务端配置为准，代码常量仅为兜底。
- 一致性：`analyze` 各类型（insight / keywords / trend / variant / compare）走同一口径，
  `autoConfirm=true` 即直接生成并返回 `charges`。
- 文档：移除所有写死的单价与合计示例。采集/分析单价与页数由后台 `pricing` 配置决定，
  一律以本次报价返回的 `credits` / `totalCredits` 为准，不得凭文档或记忆报数。

# v1.4.11

- 能力层收窄：44 个专属包不再只是「声明窄」，包体 `scripts/ari.py` 同时按各自契约裁剪。
  构建期用 AST 删除文档未承诺的命令、它们的解析器注册块，以及只被它们引用的辅助函数与
  常量；专属包因此不再包含 `export`（任意路径写文件）、`autoconfirm`（撤销逐次确认）、
  `workbench`（改写差评处理状态）、`alerts`（标记预警已读）、`competitors`、`schedule`、
  `voc` / `analyze` / `charts` / `deepdive` 等母版命令。
- 新增运行期兜底闸：专属包在包内写入 `allowedCommands` 白名单，`ari.py`
  启动时复核，命令不在白名单内直接以 `ARI_COMMAND_NOT_ALLOWED` 退出。只删代码不留闸的话，
  把命令加回来就能绕过收窄。
- `export` 落点加固：`--out` 解析后必须位于允许目录内（默认当前工作目录，可用
  `ARI_EXPORT_DIR` 显式放开），越界路径与符号链接一律拒绝，写文件时带 `O_NOFOLLOW`；
  命中时返回 `ARI_EXPORT_PATH_BLOCKED`，且不发出请求。
- 全系列的 `check` 不再回报账户免确认策略：它只服务于「小额付费操作直接生成」，等于把
  「不用先问」交给 agent，与「先报价、用户明确确认才执行」的契约冲突。付费门槛仍由服务端
  策略控制，本地不做任何隐式确认。
- 构建期新增两条硬闸：裁剪后的真实命令集必须与白名单完全一致；裁剪结果必须同时通过
  `ast.parse` 并真实打印出让命令表（`python scripts/ari.py --help`）。
- 全部 73 个包延续 v1.4.10 的窄声明；命令语义、字段与计费规则一律不变，
  不提高最低支持版本。
