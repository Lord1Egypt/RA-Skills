# 用户故事拆解参考

## Agent 场景的用户故事格式

标准格式：
```
作为 [角色]，我希望 [Agent 能做什么]，以便 [达到什么目的]
验收标准：
- [ ] AC1: ...
- [ ] AC2: ...
```

---

## 示例：智能客服 Agent

### US-01：自动分类工单
```
作为 客服主管，
我希望 Agent 能自动识别工单类型（咨询/投诉/退款/技术），
以便 工单能自动分配到对应的处理队列。

验收标准：
- [ ] 分类准确率达到 85% 以上
- [ ] 支持 4 种工单类型
- [ ] 分类延迟 < 3 秒
- [ ] 无法分类时标记为"待人工处理"
```

### US-02：知识库问答
```
作为 客户，
我希望 Agent 能根据知识库回答常见问题，
以便 我不需要等待人工客服。

验收标准：
- [ ] 回答准确率 > 80%
- [ ] 知识库覆盖 50+ 常见问题
- [ ] 无法回答时自动转人工
- [ ] 回答中包含来源引用
```

---

## 示例：数据分析 Agent

### US-01：自然语言查询数据
```
作为 产品经理，
我希望用自然语言问"上周 DAU 是多少"，Agent 直接返回数据，
以便 我不需要写 SQL 或找数据分析师。

验收标准：
- [ ] 支持时间范围解析（昨天、上周、本月）
- [ ] 支持指标查询（DAU、MAU、转化率）
- [ ] 返回数据 + 可视化图表
- [ ] 查询延迟 < 10 秒
```

---

## 拆解原则

1. **一个故事 = 一个可测试的能力**
2. **验收标准要可量化**（准确率、延迟、覆盖率）
3. **包含失败场景**（无法处理时的 fallback）
4. **粒度适中**：一个故事 1-3 天能完成
