# 阶段 2 规程 — Ingest 文档锚点抓取（辅助）

目标：为时效性硬事实（版本号、API 签名、破坏性变更、最新特性）提供外部锚点，交叉验证模型内生知识。**本阶段是辅助**——抓取失败不阻塞流水线。

## 抓取流程（每个 subdomain）

1. webfetch 领域配置声明的 `doc_seeds` 官方根页（markdown 格式）。
2. 从抓回的索引页内容中**发现**关键页面链接，按优先级挑选，受 `page_budget` 上限约束：
   1. 升级指南 / 迁移指南 / 发布日志 / 版本页（时效性锚点价值最高）
   2. 入门 / 主概念页
   3. API 参考索引页
   4. 边界轮清单指向的待验证页面（来自阶段 1 第 4 轮）
3. 逐页 webfetch（markdown 格式）。存储采用**单文件聚合**形态：该 subdomain 全部抓取结果合并入 `corpus/<domain>/<subdomain>/docs/_anchors.md`（每页关键事实一小节 + 抓取日志表）；单页全文过长需保留时，可按页拆分 `docs/<slug>.md`。

## 硬性规则

1. **URL 红线**：只 fetch (a) 领域配置声明的种子地址，(b) 从已抓回页面内容中出现的链接。**禁止**凭记忆构造、猜测、拼接任何 URL。
2. **预算纪律**：`page_budget` 是上限而非目标；锚定版本等硬事实所需的页数通常远低于上限。优先级不够的页面果断放弃。
3. **容错**：单页失败 → 跳过并在该 subdomain 的抓取记录中登记；种子根页失败 → 该 subdomain 降级为纯模型知识模式（阶段 3 在来源索引标注「未经文档验证」），继续处理下一个 subdomain。
4. **格式**：只存 markdown 正文与关键事实（版本号、API 签名、破坏性变更列表），超长页面只保留相关小节，不必全文照抄。

## 产物格式

默认形态——`corpus/<domain>/<subdomain>/docs/_anchors.md`（多页合并记录）：

```markdown
---
subdomain: <子领域>
source_type: doc_anchor
fetched_at: <YYYY-MM-DD>
---

# <子领域> 文档锚点（多页合并记录）

## 抓取日志

| 页面 | 结果 |
|---|---|

页面预算使用：N / page_budget。是否降级。

## 关键事实（版本锚定，硬事实）

<每页一小节：版本号、API 签名、破坏性变更、与模型知识冲突的原文摘录，附 [官方文档](url) 标注>
```

可选形态——按页拆分 `docs/<slug>.md`（单页全文过长时）：

```markdown
---
source_url: <真实来源 URL>
fetched_at: <YYYY-MM-DD>
---

# <页面标题>（文档锚点）

<关键事实摘录>
```

抓取登记不单独设 `_fetch_log.md`——聚合形态内置于「抓取日志」表。
