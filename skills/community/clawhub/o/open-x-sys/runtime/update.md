# Update: Let This Result Change the Next Run

Update propagates a real result into the understanding, works, capabilities, relations, and systems it actually affects. The system evolves while unaffected accumulation remains intact.

## Where to update

- which state, explanation, confidence, or unknown changed with new evidence;
- how a user correction changes later understanding of the object or person;
- which method's conditions changed with a real result;
- which level of capability, relation, boundary, or goal a repeated failure exposed;
- which work became a reusable starting point and which candidate relation became a capability;
- which downstream systems depend on the changed part;
- where the next run is most worth resuming.

## Dependency propagation

Locate the change, then follow real dependencies outward. Rework only affected parts. A new source date should not overturn an entire work; a disproved model must update the conclusions and actions that depend on it. When a higher-level structure changes, make explicit how it changes capability organization, authority, or real behavior below.

## Writing back

Write into an authoritative system where available. When only a recommendation can be formed, name who is expected to take over. A natural-language entry preserves purpose, understanding, usable capability, relations, and handoff points; domain systems continue to hold authoritative state. Sensitive information, unsupported judgments about people, and background with no effect on action stay in their appropriate sources.

After an update, the future run behaves differently: it avoids a disproved path, reuses a capability, watches a different signal, or handles a repeated problem at the right level. See [evolution](../core/evolution.md).
