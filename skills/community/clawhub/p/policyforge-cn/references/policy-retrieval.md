# 政策原文检索：渠道顺序、检索式与核验留痕

本文件解决一件事：在写任何一段正文之前，先把“可引用的原句”拿到手，并且知道它出自哪份文件、何时发布、由谁发布。

## 1. 渠道顺序

按下面顺序推进，不要从搜索引擎开始：

1. **国家级官方政策库**——能给文号、发布日、发布机关与官方链接，四元组一次拿齐。
2. **省级政府门户与主管厅局栏目**——省级文件不在国家级库里，只能到本级门户找。
3. **地市转发版**——用于补全正文与文号，但引用时仍引上级文件。
4. **搜索引擎**——只用来定位 URL 与发现没想到的文件名，不作为证据来源。

顺序的理由很实际：搜索引擎给不出稳定文号，转载页会改标题、丢附件；而政策库给的是结构化字段，可以直接进依据清单。反过来做，通常要重来一遍。

## 2. 国家级政策库

### 2.1 接口形态

```text
https://sousuo.www.gov.cn/search-gov/data
  ?t=<类型>&q=<URL 编码关键词>&timetype=timeqb
  &sort=score&sortType=1&searchfield=title&p=1&n=20
```

请求需要带浏览器 User-Agent；境内直连通常可达，走代理反而容易在 TLS 环节失败，必要时先关闭代理再请求。

### 2.2 类型参数（易错点）

| 参数值 | 覆盖范围 | 可用性 |
|---|---|---|
| `zhengcelibrary_gw` | 国务院及其办公厅公文 | 可用 |
| `zhengcelibrary_bm` | 部门与部委规范性文件 | 可用 |
| 其余取值 | — | 对任何关键词都返回零命中 |

**零命中首先怀疑参数，而不是怀疑文件不存在**。这是本流程里最省时间的一条经验：换成上表两个值重试，绝大多数“查不到”会消失。

### 2.3 字段参数

| 写法 | 行为 | 适用 |
|---|---|---|
| 带 `searchfield=title` | 只匹配标题 | 已知文件名或主题词 |
| 不带该参数 | 全文匹配 | 只记得某句话、不知道文件名 |

全文匹配的价值在于反向找文件：手里有一句流传的提法，用它能定位到出处，再回标题确认是不是同一份。

### 2.4 返回字段与用法

- `pcode`：文号，形如“发文机关代字〔年份〕序号号”。
- `pubtimeStr`：发布日期，`YYYY.MM.DD`。
- `title` / `url` / `summary`：标题、官方链接、摘要。
- `totalCount` / `totalpage`：命中总数与页数。
- 年份分布直方图：一次查询即返回逐年命中数，用来判断某领域近两年是不是政策密集期——密集期说明有新文件，值得优先补检。

### 2.5 脚本调用

```bash
python scripts/gov_doc_search.py search 关键词 --t bm
python scripts/gov_doc_search.py fulltext "某句流传的提法"
python scripts/gov_doc_search.py doc "https://……/content_xxxxx.htm"
python scripts/gov_doc_search.py so "某主题 实施方案 转发"
```

接口参数会随站点改版调整。调用失败时先人工打开官方检索页确认现行参数，不要靠反复试错消耗轮次。

## 3. 中央文件不在政策库内

中央层面的意见、决定、规划建议，以及每年的一号文件，通常不在上述政策库中，而是挂在门户的“中央文件”栏目下，URL 形态为 `/zhengce/YYYYMM/content_*.htm`，其中的编号无法推算。

处理办法：用搜索定位候选链接 → 回抓该链接并核对页面标题与目标文件是否一致 → 通过后才进入依据清单。若只拿到地方政府网站的转载全文，正文可用于摘句，但必须标注“转载来源，建议以门户原文核对”。

## 4. 省级与地市

| 目标 | 入口类型 | 说明 |
|---|---|---|
| 省政府文件 | 省门户“政策文件库”栏目 | 省政府与省府办文件的主渠道 |
| 涉农、补贴、资金管理办法 | 省级财政厅（局）通知公告与政策解读栏目 | 这类文件在该栏目最集中 |
| 行业主管领域 | 对应厅局门户 | 医保、商务、金融管理等各有独立入口 |
| 省级最新表述 | 政府工作报告栏目 | 站位最高、时效明确，是本地落地层的首选 |

省级政务搜索接口通常只返回新闻流与办事指南，对政策文件检索帮助有限，可当线索生成器，不要当检索主力。

**地市转发版技巧**：省级文件全文常先出现在地市门户的转发通知里，且逐字保留省文件文号与附件。检索式为“地市名 + 转发 + 省 + 主题 + 实施方案”。拿到后仍引上级文号，并回国家级库或省门户确认上级文件真实存在。

## 5. 兜底搜索

- 引擎选择：中文政策文本以 360 搜索最稳，可连续多次查询；部分引擎仅前几次返回服务端渲染内容，百度与必应中文对政策短语切词严重，不宜作为主力。
- 取 URL：正则提取结果页里的链接，按 `gov.cn`、主管部委域名过滤，去掉引擎自身域名，去重保序。
- 取正文：逐个直取，取第一个正文长度足够（例如超过 800 字）的页面，过滤栏目页与导航页。
- 别忽略“相关搜索/为您推荐”区块——那里常直接列出目标文件的准确标题，是发现同主题文件的高效入口。

## 6. 正文提取与逐字摘句

- 正文容器：优先切 `id="UCAP-CONTENT"`、`class="pages_content"` 一类容器，再剥标签；整页直接剥标签会混入导航与页脚噪声。
- 切句：按句号、分号、换行三种边界切，**不要只按句号**——中文条款常以分号分隔，按句号切会把一条完整要求切碎。
- 选句：保留含关键词、长度在十余字到二百字之间的句子，这类句子既完整又便于直接嵌入正文。
- 指标句单独抓：以“到某某年”“不低于”“不高于”“覆盖率”“比重”等为锚点检索。这类句子最有说服力，也最容易被截断，抓不全时回原文段落补，不凭记忆补。

## 7. 核验与留痕

每份保留文件记录四元组：**文号、发布日期、发布机关、官方链接**，并摘出 1–3 句逐字原文。

三类附件清单：

1. **文件清单表**：序号、名称、文号、发布日、发布机关、链接、引用价值（用星级或一句话说明用途）。
2. **逐字原文摘录**：按文件分节，每节列可直接复制的句子。
3. **待核清单**：只有转载、无文号或无法确认发布机关的，写明“缺什么”与“通常走哪个渠道核”（如上级机关转发件、办公系统收文、主管部门公开目录）。

另附**检索日志**：渠道、查询式、时间、命中数。它有两个用处——下次复用不必重来，以及被问到“这个结论怎么来的”时能当场答复。

## 8. 轮次预算与红线

- 一轮政策库检索可覆盖 10–15 个短词；兜底搜索每轮 3–4 个查询，间隔一至两秒。超预算就换角度或收工，别反复重试同一查询。
- 红线一：不把地市转发版当原件引用。
- 红线二：不因为参数无效就断言“没有该文件”。
- 红线三：不编造文号、发布日期、条款句；拿不到就进待核清单，并在正文用不含文号的通用表述。
- 红线四：不把行业通用说法当成条文原句，两者在评审眼里差别很大。
