# 应付职工薪酬·离职后福利与辞退福利

产出稿的头部就照下面这几行起（三件自标「AI 整理初稿」「请回原文核对」「不构成投资建议」逐字在位；`主体：`／`报告期：` 是**行首裸行**，不带 `- ` 前缀）。判断位一律写成 `[待人工]`：

```
# 示例材料（600000.SH）应付职工薪酬登记稿

AI 整理初稿 ｜ 请回原文核对 ｜ 不构成投资建议
主体：示例材料（600000.SH）
报告期：2025 年年度报告·附注·应付职工薪酬
```

**定位**：给一份年报，把附注里**「应付职工薪酬」那一段**读成一张**每个数都能回到附注原句**的登记表——薪酬总额怎么滚动、短期薪酬由哪几项构成、离职后福利里两类计划各是多少（设定受益计划还要交代折现率与精算利得）、辞退福利有多少。**四数恒等由机检现算**，本件只负责把数抄对、把两类计划分开、把原句挂上。

这一段常被跳读，但它回答的是「公司这一年在人身上花了多少、还欠多少」：期初 1.24 亿、本期增加 0.86 亿、减少 0.72 亿、期末 1.38 亿——期末这 1.38 亿是**负债**，不是花掉的成本。本件把这条滚动摆出来，**不替你说「这个薪酬水平偏高还是偏低」**——那一步要口径判断，交 `[待人工]`。

切割说清楚：本件只读**「应付职工薪酬」这一节附注**。成本费用里的职工薪酬分摊（生产成本／销售费用各占多少）不在本件；股权激励的费用（股份支付）是另一件，见 `cn-share-based-payment-cn`；高管薪酬与关联方交易见关联方那一件。本件**不问谁拿了多少**，只问总额怎么滚动、由什么构成。

### 是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 六节逐条登记（概况／短期薪酬／离职后福利／辞退福利与其他长期福利／口径与未取到／来源），缺项也占一行点名 | 薪酬水平高低、人员结构好坏、要不要裁员降薪（一律 `[待人工]`） |
| 每个数字带 `〔口径：…〕` 标签（本期末／本期发生额） | 按表格位置认项（第三行就是期末余额那种） |
| 四数现算：期初＋本期增加−本期减少 vs 期末，差 > 0.01 万元即发条 | 只抄期末一个数，期初与增减空着，让滚动无从复核 |
| 两类离职后福利**必须分列**：设定提存计划／设定受益计划各占一行 | 把两类合成一行「离职后福利计划合计」 |
| 每个数挂「」原句＋〔锚：…〕＋`[S#]` 三元组，来源行两向对应 | 只写数字不抄原句，事后补一句「据年报附注」 |
| 数据通道＝用户直供的附注原文（零网络） | 承诺任何实时行情、预测或工具清单 |

### 触发场景

「公司一年在人身上花多少、还欠多少」「应付职工薪酬期末余额是怎么来的」「设定受益计划和设定提存计划各多少、折现率多少」「辞退福利今年提了多少」「精算利得／损失是多少」。输入形态＝**年报附注里「应付职工薪酬」「离职后福利」「设定受益计划」「辞退福利」那几段**（截图／PDF／解析回来的表格文本）。

## 六节各登记什么

节名必须逐字照这几个（`## ` 起节，节名后面紧跟字母或数字就认不出，会被记成野节）：

| 节 | 登记什么 | 最常犯的错 |
|---|---|---|
| 应付职工薪酬概况 | 期初余额／本期增加／本期减少／期末余额**四个数**，`〔口径：本期末〕`／`〔口径：本期发生额〕` | 只抄期末一个数，前面的增减全省——四数恒等就没有比对对象 |
| 短期薪酬 | 工资奖金津贴补贴／职工福利费／社保公积金等**分项逐行**，`〔口径：本期发生额〕` | 只抄「短期薪酬合计」，分项全省 |
| 离职后福利 | **设定提存计划**与**设定受益计划**各一行（金额）；设定受益计划还要有**折现率**一行与**精算利得／损失**一行 | 把两类合成一行；写了设定受益却不给折现率；精算利得当成年内新增计提 |
| 辞退福利与其他长期福利 | 辞退福利金额一行，`〔口径：本期发生额〕`；有其他长期福利（长期残疾福利、长期利润分享等）各占一行 | 把辞退福利混进短期薪酬；把「拟裁员」的意向写成已确认的辞退福利 |
| 口径与未取到 | 取法口径 ＋ 缺口逐项点名；零缺口写 `未取到：无` | 正文写了未取到而本节没列，或反之 |
| 来源 | 每条 `[S#]` 一行：`- [S#] 标题 \| URL \| 检索日 YYYY-MM-DD` | 引用了 `[S#]` 却没有登记行；检索日写成斜杠式 |

同一条 = 一行：行首写项名与标签，紧跟金额与「万元」，再挂 `「原句」〔锚：页/表〕[S#]`。附注里没有的数写 `未取到：项名`，不留空、不借常识补。

⚠️ **折现率不是金额**：折现率那一行写的是百分比（如 `3.25%`），不写「万元」。它是设定受益计划义务现值计算用的折现率，抄成金额那一行会被机检当成画面上的一个数。

## 五道机检在管什么

现状以脚本里 `UNIMPLEMENTED` 的现值为准：五道**全部已落字**。将来某道若回退成空壳，它会调用即抛、由机检收进「不可判」，既不判也不放行，单稿退 3；`rc=0` 只留给「五道全过」。

| 码 | 名称 | 判什么 | 最常拦住的情况 | 现状 |
|---|---|---|---|---|
| `EB-STRUCT` | 形制 | 头部三件自标逐字在位、六节齐且按序；认不出的节标题与多出同名节记 stray 逐条发。只判「形」，不判内容；**不判** `主体：`／`报告期：` | 节名改了个字就整节认不出；一节写了两次 | 已落字 |
| `EB-QUOTE` | 原句与锚 | 四个内容节里每个带数字的行须挂齐「」原句＋〔锚：…〕＋`[S#]` 三元组；例外只有 `未取到：` 行、`[待人工]` 行、`〔自算〕` 行三形；来源行须合格式，正文与来源**两向**都要对得上（正文引了来源没登记、来源登记了正文没引用，两向都发） | 数字行只写数没抄原句；来源行检索日写成 `2026/03/20`；引了 `[S2]` 却没登记 | 已落字 |
| `EB-ROLL` | 四数滚动 | 「应付职工薪酬概况」节里期初余额、本期增加、本期减少、期末余额四个数：期初＋增加−减少 vs 期末，差 > 0.01 万元 ⇒ 发。**任一侧缺失 ⇒ 「口径与未取到」节已声明缺项则整条跳过，否则发「缺数」**，不猜、不按 0 算、不借别节的数 | 期末改了数没改增减；某个标签匹配到两行（多义即发，不敢瞎比） | 已落字 |
| `EB-PLAN` | 两类计划分列 | 「离职后福利」节里设定提存计划与设定受益计划**必须各占一行**（同一行同时含两者 ⇒ 发「合成一行」）；有设定受益计划时，还须有折现率一行、精算利得或精算损失一行，缺哪项报哪项。该节为空时返回空表不报——缺节归 `EB-STRUCT` | 把两类写成「离职后福利合计 1,280 万元」；写了设定受益净负债却不给折现率 | 已落字 |
| `EB-LINE` | 红线 | 四组越界词，**只扫四个内容节**，`口径与未取到` 与 `来源` 两节整节豁免：① 投资建议（买入／卖出／增持／减持／目标价／推荐／建议持有）② 前瞻预测（预计／预测／有望／将会／看好／预期增长／预判）③ 主观评价（合理／不合理／偏高／偏低／高估／低估／显著偏低／显著偏高）④ 越界口径（人工成本率／人均创收／薪酬竞争力／裁员／降薪／优化人员／对标薪酬／行业均值／效率提升空间）。**同组命中只报不被别的命中词包含的那些**——「不合理」里的「合理」不另报，但「不合理」与「显著偏低」互不包含，各报一条 | 自己写了一句「薪酬水平偏高」；把「预计明年人工成本上升」抄进正文；抄引文时把裁员降薪方案一起抄进来 | 已落字 |

## 退码

| 码 | 含义 |
|---|---|
| `0` | 五道全过，零发条 |
| `1` | 有发条 |
| `2` | 用法错（缺参数或未知参数） |
| `3` | 读不到文件、或空稿、或零发条但仍有判据未落字（此时输出会明写「**这不等于合规**」） |

---

## 数据通道

零网络、纯标准库、单文件。输入就是用户直供的附注文本，本件不联网取数、不缓存、不上传。
`CUE_API_KEY` 是**可选**的：带上才走 `cue-data-mcp`／`cue-omni-reader` 那条取证腿去取原文，
缺位时只把用户贴进来的附注排版成上面那张登记表——**形状一样，数只能来自用户**。

## 快速开始

```bash
# 看一眼样例（零输入可跑，打印一份六节齐的登记稿）
python3 scripts/check_employee_benefits.py --demo

# 跑包内夹具自检（末行会给「自测档数=N｜不合=0｜不可判=0」，N 以现跑为准）
python3 scripts/check_employee_benefits.py --selftest

# 机检自己的稿子
python3 scripts/check_employee_benefits.py 我的登记稿.md
```
