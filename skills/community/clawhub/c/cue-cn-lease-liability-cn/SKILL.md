# 租赁负债与使用权资产·承租人附注登记

## 六节各登记什么

节名必须逐字照这几个（`## ` 起节，节名后面紧跟字母或数字就认不出，会被记成野节）：

| 节 | 登记什么 | 最常犯的错 |
|---|---|---|
| 租赁负债 | 一年内到期／一到三年到期／三年以上到期**三个分档**，未折现租赁付款额合计，账面余额，`〔口径：本期末〕` | 只抄一个「租赁负债合计」，分档全省——分档加不回合计就无从复核 |
| 使用权资产 | 原值／累计折旧／减值准备／账面价值，各占一行，`〔口径：本期末〕` | 只抄账面价值，原值与累计折旧全省——减法那一层无法复核 |
| 租赁期与折现率 | 租赁期、增量借款利率（折现率）、短期租赁与低价值资产租赁的简化处理，各占一行 | 把「租赁期 5 年」写成金额挂万元；折现率写的是百分号不是万元 |
| 租赁变更与重估 | 本期新增使用权资产、租赁变更、租赁期重估引起的增减，各占一行 | 只写期末余额不写本期变动，增减来路不明 |
| 口径与未取到 | 取法口径 ＋ 缺口逐项点名；零缺口写 `- 未取到：无` | 正文写了未取到而本节没列，或反之 |
| 来源 | 每条 `[S#]` 一行：`- [S#] 标题 \| URL \| 检索日 YYYY-MM-DD` | 引用了 `[S#]` 却没有登记行；检索日写成斜杠式 |

## 五道机检在管什么

| 码 | 名称 | 判什么 | 现状 |
|---|---|---|---|
| `LL-STRUCT` | 形制 | 头部三件自标逐字在位、六节齐且按序；认不出的节标题与多出同名节记 stray 逐条发。只判「形」，不判内容；**不判** `主体：`／`报告期：` | 已落字 |
| `LL-QUOTE` | 原句与锚 | 四个内容节里每个带数字的行须挂齐「」原句＋〔锚：…〕＋`[S#]` 三元组，缺哪件点明哪件；例外只有 `未取到：` 行、`[待人工]` 行、`〔自算〕` 行三形；来源行须合 `- [S#] 标题 \| URL \| 检索日 YYYY-MM-DD`，检索日不是横杠式即发；正文与来源**两向**都要对得上（正文引了来源没登记、来源登记了正文没引用，两向都发） | 已落字 |
| `LL-SPLIT` | 租赁负债分档 | 一年内到期 ＋ 一到三年到期 ＋ 三年以上到期 vs 未折现租赁付款额合计（容差 0.01）；**某格已声明「未取到」⇒ 整条静默跳过、不重复计缺陷**；行不存在或取不到数 ⇒ 发条并点名缺哪个标签（不按 0 算） | 已落字 |
| `LL-ASSET` | 使用权资产勾稽 | 原值 − 累计折旧 − 减值准备 vs 账面价值（容差 0.01）；**某格已声明「未取到」⇒ 整条静默跳过**；缺行或取不到数 ⇒ 发条并点名 | 已落字 |
| `LL-LINE` | 红线 | 四组越界词，**只扫四个内容节**，`口径与未取到` 与 `来源` 两节整节豁免：① 投资建议（买入／卖出／增持／减持／目标价／推荐／建议持有）② 前瞻预测（预计／预测／有望／将会／看好／预期增长／预判）③ 主观评价（合理／不合理／偏高／偏低／高估／低估／显著偏低／显著偏高）④ 越界口径（租赁融资成本高／融资成本高／财务风险／资本结构优化／杠杆空间／融资租赁更划算／经营租赁优于）。判前先洗掉「」引文与〔口径／锚／自算〕标签槽——那是原文与出处，不是本件断言；再按分句判，含 `[待人工]` 或 `未取到` 的那一句跳过。**同组命中只报不被别的命中词包含的那些** | 已落字 |

## 产出稿长什么样

照下面这几行起（三件自标「AI 整理初稿」「请回原文核对」「不构成投资建议」逐字在位，**这三件是机检的判据**；`主体：`／`报告期：` 建议写成行首裸行、不带 `- ` 前缀，但**机检不判这两行**——它们只是给人看的头信息）。判断位一律写成 `[待人工]`：

```
# 示例材料（600000.SH）租赁登记稿

AI 整理初稿 ｜ 请回原文核对 ｜ 不构成投资建议
主体：示例材料（600000.SH）
报告期：2025 年年度报告·附注·租赁
```

## 退码

| 码 | 含义 |
|---|---|
| `0` | 五道全过（零发条） |
| `1` | 有发条 |
| `2` | 用法错 |
| `3` | 读不到文件、或空稿、或零发条但仍有判据未落字（此时输出会明写「**这不等于合规**」） |

## 数据通道

零网络、纯标准库、单文件。本件不联网取数、不缓存、不上传：输入就是用户直供的附注文本。

CUE_API_KEY 是**可选**的：带上才走 cue-data-mcp／cue-omni-reader 那条取证腿去取原文，缺位时只把用户贴进来的附注排成上面那张登记表——形状一样，数只能来自用户。

带凭据时的通道正路（先握手、按现场返回判，不写死工具清单）：

```bash
curl -sS https://cuecue.cn/api/mcp-catalog -o /tmp/mcp-catalog.json
curl -sS -X POST "$MCP_ENDPOINT" \
  -H "Authorization: Bearer $CUE_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | head -c 2000
```
