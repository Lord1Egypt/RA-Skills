# 免费普通标讯搜索接口

`POST /api/free/search`

用于普通标讯的免费搜索、翻页和修改条件。免费请求不得发送 `numPerPage`，即使值为 30；请求和响应以本页契约为准。共用筛选条件按需读取[搜索入参](api-projects.md#入参字段)及[关键词匹配规则](api-projects.md#关键词匹配规则)，不复制正式请求示例中的分页参数，也不套用正式返回字段。

行为选路与会话承接统一见[游客规则](guest-access.md)。共用搜索规则和免费专属约定分别维护，不将正式响应字段用于免费结果。

## 请求

请求使用 JSON，`Content-Type: application/json`。基础请求示例：

```json
{"keywordGroups":[{"keywords":["服务器"],"matchScopes":[2]}],"currentPage":1,"sourceCode":"bb3b4102f584028c3830df37"}
```

| 参数 | 免费请求约定 |
| --- | --- |
| `keywordGroups` | 必填；各组含非空的 `keywords` 和 `matchScopes` 数组；组内 OR、组间 AND，位置枚举见[共用入参](api-projects.md#入参字段) |
| `currentPage` | 从 1 开始，默认第 1 页；示例显式指定页码 |
| `sourceCode` | JSON 请求体中的来源标识；本包固定为 `bb3b4102f584028c3830df37`，由脚本统一注入，用户查询参数不能覆盖 |
| `numPerPage` | **禁止发送**，不可传 null 或 30；免费固定按 30 条分页，末页可不足。搜索、翻页、修改和恢复请求均须移除该字段 |
| 其他筛选条件 | 复用[共用入参](api-projects.md#入参字段)和[匹配规则](api-projects.md#关键词匹配规则)，不缩减条件、不复制正式请求的分页参数 |

无 Key 时匿名，不填共享或占位 Key。有 Key 主动免费时沿用 `qianlimaApiKey` 请求头，使用已配置的真实个人 Key，不能因鉴权错误静默去掉 Key 重试或改用收费接口。Key 不进入 URL、查询状态或日志。两类免费查询均不扣积分、仅返回基础字段，并受免费额度约束。

## 来源传递

`Skill 请求体 sourceCode → 后端识别来源并生成带 source 的官网链接 → Skill 原样展示`。免费搜索、翻页、修改条件、完整上下文恢复及切回免费时均由请求构造层注入本包固定来源；匿名和携带 Key 使用同一来源值。来源不是业务筛选，不放入 `--query-json`、`effective_query` 或查询快照；`request_query` 记录实际发送的完整请求体，包含脚本注入的 `sourceCode`。

不要把字段写成 JSON `source`，也不要用 URL 的 `?source=...` 代替请求体 `sourceCode`。JSON `source` 返回 `10004`，消息“不支持请求字段[source]”。Agent 不选择传参方式，不增加试探、重试或额外归因请求。此约定用于免费搜索；登录请求沿用独立登录契约，不向其他查询接口自动扩散。

服务端返回的 URL 和参数原样保留，不由 Skill 补写 `source`。有效 Key 的详情链接继续使用服务端返回的完整路径，不擅自向票据链接追加参数。

## 响应字段与分页

查询外层使用 `code/msg/data/success`。免费成功响应的基础字段为 `rowCount/pageCount/list`；扩展模式和分页字段可以省略。执行模式由本次选用的免费接口确定，不能因缺少扩展字段阻止正常续查。

| 字段 | 用途 |
| --- | --- |
| `accessMode` | 可选；提供时为 `GUEST`，不是脚本的 `--access-mode` 参数；缺省不代表正式模式或未登录 |
| `currentPage` | 可选；提供时须与请求页码一致；缺省使用本次明确请求的页码 |
| `numPerPage` | 可选；提供时须为 30；缺省仍按免费固定每页 30 条执行，禁止作为请求字段发送 |
| `rowCount` | 真实命中公告总数，不截成 300 |
| `pageCount` | 接口原始页数，允许为真实总页数或截到 10 页的可访问页数；脚本另按 `ceil(rowCount/30)` 计算真实总页数 |
| `viewablePageCount` | 可选；缺省按真实总页数与 10 的较小值计算；提供时须为合法边界，不得扩大范围 |
| `maxViewableRows` | 可选；缺省使用已定上限 300；提供时最多 300，不扩大固定上限 |
| `list` | 当前页基础卡片列表 |

基础卡片字段：

| 字段 | 用途 |
| --- | --- |
| `id` | 公告标识，用于正式详情等接口续查，不直接展示 |
| `title` | 标题 |
| `purchasingUnit` | 招标／采购单位 |
| `winningBidderUnit` | 中标单位，按实际披露展示 |
| `areaName` | 地区 |
| `infoType` | 阶段 |
| `budgetAmount`、`biddingAmount` | 预算／中标金额，单位为元，展示换算万元 |
| `publishTime` | 发布时间 |
| `url` | 无 Key 或无效 Key 官网入口／有效 Key 公告详情入口，见下节 |

免费白名单仅为上述字段；不返回 `hasAnnex`，但保留同名筛选条件。服务端负责字段裁剪，客户端隐藏多余字段不能证明权限合格。空值表示未公示，0／false 保留；免费未开放的内容不解释为公告没有此内容。

脚本的 `page_count` 是按总数与固定页大小计算的本地事实，`page_count_source` 标明计算依据；`api_page_count` 与 `api_responses` 保留接口原值。不能把原始 `pageCount=10` 说成只命中 300 条，不能把本地推导结果冒充服务器返回字段。

同组有效条件最多前 10 页／300 条，总量与可访问量分开处理。本地可避免第 11 页，但不能代替服务端限制。必要字段缺失或类型错误、明确返回的扩展字段冲突、页数既不等于计算总页数也不等于截断后的可访问页数时记录响应异常，不据异常字段继续翻页、不改收费或放宽上限；保留原始业务响应，不将协议异常伪装成服务端业务错误。正常空列表不当作限流。

跨模式续查及已交付位置换算见[游客规则](guest-access.md#分页限制与续查)。特别注意[正式搜索](api-projects.md#入参字段)的综合排序含页内重排：不能仅凭相同 `sortType` 推定不同页大小下全局顺序一致；实际排序不一致时按游客规则说明衔接限制。

## 限流与错误

请求携带 `numPerPage`（即使为 30）时，返回 HTTP 400、业务码 `10004`、`msg=免费查询固定每页30条，请勿传每页条数`。请求构造层应移除该字段。

`currentPage=11` 等超过免费可访问范围的请求返回业务码 `10004`，消息说明免费最多查看前 300 条。该码不能单独用来判定字段写错；按本次返回消息区分分页上限与入参错误，不因达到免费上限自动重试或转收费。

限制原因按服务端明确返回的信息处理。不能仅凭通用 `429` 判断分钟、小时、日额度或恢复时间，不把服务保护说成额度耗尽；分页上限不代表没有更多匹配结果。缺少恢复信息就省略，不自行推算。请求频率限制不追加登录／积分续查引导，不额外查个人积分；明确的累计次数额度耗尽与分页上限分别按游客规则处理，不连续重试或拆条件绕限。

无效 Key 请求按匿名模式返回基础结果及官网链接，符合预期。该成功响应不作为鉴权错误或链接异常，不据此声称 Key 有效，不另查权益验证、不去掉 Key 重试、不要求用户先修复 Key 才交付基础结果。

若接口实际返回鉴权失败，沿用现有错误处理：`401` 表示未认证，`10001` 表示 API Key 无效；按实际返回的状态、业务码和消息说明，不切收费或匿名重试。`503` 及“免费查询暂时繁忙”按服务繁忙处理，不误判为 Key 无效或某档额度耗尽。网络失败、非 JSON 或协议字段异常如实说明，不推断为额度耗尽；正常空列表不当作限流。具体额度和交互规则见[游客规则](guest-access.md)。

## 详情链接与计费边界

- 无 Key 或无效 Key 的 `url` 为 `https://ai.qianlima.com/?source=bb3b4102f584028c3830df37`，即千里马AI数据平台官网入口；历史链接登录后不变。有效 Key 免费结果返回对应公告详情链接，列表仍不扣积分。两类结果均由公告名称承载实际返回的 URL，展示规则统一见[游客规则](guest-access.md#3-链接如何展示)。
- 列表请求、链接生成／展示及自动预览不触发详情扣费；用户实际查看时，后端按授权账号权益和正式详情规则计费。不得为生成链接逐条调用收费详情，不自动打开或预取收费详情。
- 浏览器不自动携带本机 Key。后端须提供账号与公告绑定的鉴权衔接，个人 Key 不放 URL、不交页面脚本。
- 详情页按现有方式展示有权查看的内容；后端校验详情访问权限，使用正确账号权益并按规则扣除积分，处理积分不足、凭证失效及重复访问。不要求页面展示实际消耗积分、计费账号或额外积分提示，不为展示计费信息新增接口字段。Agent 不自行构造访问凭证或模拟页面认证。
- 官网入口不称“公告详情”或“原文”，不因请求携带 Key 就提示点击官网扣费；正常响应无需附加链接类型辨析。链接与契约不一致时，脚本给出 `link_contract_issues` 和 `link_instruction`，保留原始 URL，不伪造详情链接或认证成功；账号接入引导使用文档规定的完整来源链接。
- 积分查询的交互说明统一见[游客规则](guest-access.md)：只说明查询会消耗账号积分，不报告本次具体消耗数额，不为此额外查询扣费记录或用余额差计算。实际鉴权、计费和页面反馈仍由对应服务执行。
