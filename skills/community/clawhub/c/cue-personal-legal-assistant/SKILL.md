# 个人法律助手

> 🚀 **30 秒了解：** 
> 遇到法律问题别慌，**律师费太贵？网上搜太乱？** 把情况丢给它。
> 它不仅告诉你“该怎么办”，还能直接帮你**查同类判决、算赔偿金额、写起诉状/答辩状**，每一次分析都附带真实法条和权威来源链接。
> 
> 🟢 **能做**：看判例、起草/审校文书、查法规、研判问题、中外对比，结论带来源。
> 
> 🔴 **不能做**：出庭代理、保证 100% 胜诉。
> 
> 🚨 **紧急情况**：请立即拨打 **110** 或法律援助热线 **12348**。

## 和「办案流程引擎」有什么不一样

市面上的法律助手，很多是**办案流程引擎**——给你一套完整方法论：先做什么、再做什么、文书怎么写、费用怎么算，步骤齐全。**这套流程 Cue 也全都有**：类案检索、文书起草/审校、法规查询、实务研判、逐条解读、中外对比，一个不少。

但真正卡住人的不是「流程」，而是流程里**每一个需要「查、核、算、比」的环节**——同类案子到底怎么判、引用的法条有没有失效、赔偿金具体怎么算、中外规定差在哪。这些靠模板套不出来，得接专业数据源、真去搜、真去算、真去读材料。

**这正是 Cue 干的活，也是 Cue 有、而流程引擎没有的能力：**

## 特点：为什么选它
> **不是又一个「查法条」的问答工具——是能陪你从「拿不准」一路走到「打官司」的个人法律助手。**

| 内置智能计算器 | 诉讼费、人身损害、利息违约金、工伤赔偿——AI 自动帮你算好金额并附上计算过程，不用自己苦背公式 |

**每次提问前查询积分余额（必须执行）：**

收到用户的每个新问题后、判断意图之前，先用用户的 API Key 调「当前订阅查询」接口，拿到当下可用积分（同一个问题只查一次，不要轮询）：

```bash
KEY=$(python3 -c "import json;print(json.load(open('$HOME/.cue/config.json'))['api_key'])" 2>/dev/null || echo "$CUE_API_KEY")
echo "=== 跑前剩余积分 ===" && curl -sS --max-time 10 'https://cuecue.cn/api/v1/billing/subscriptions/current' -H "Authorization: Bearer $KEY" | python3 -c "
import sys,json
d=json.load(sys.stdin) or {}
d=d.get('data',d) or {}
a=d.get('available_credits') or 0; p=d.get('permanent_credits_balance') or 0
print('剩余积分 =', round(a+p,2), '（可用', a, '+ 永久', p, '）')
" 2>/dev/null || echo "积分查询失败（不阻断，继续）"
```

- **剩余积分 = `available_credits` + `permanent_credits_balance`**：前者只含每日剩余 + 周期剩余，后者是永久额度，两者相加才是用户当前可用的全部积分。
- 接口返回 `null`、401 或网络失败时：**不中断任务、不向用户抛错误**，本次回答照常进行，只是省略结尾的积分行；最多重试 1 次。
- 该接口在租户无订阅时会自动创建免费订阅，不要高频调用，每个用户问题 1 次即可。
- **余额闸**：剩余积分 ≤ 0 时立即停止、不要开跑，按下方「积分不足专项提示」给出两个办法；0 < 余额 < 100 提醒偏低但可继续；查询失败不阻断。

**容错、重试与错误提示（重要，直接影响体验与可靠性评分）：**

跑研究依赖外部 API 与本地 Python 环境，务必做好失败兜底，禁止把原始报错甩给用户。

1. **跑前自检（必做）**：逐项确认 `python3`、`git` 可用、`~/.cue/config.json` 含有效 `api_key`、runner 脚本就位。任一缺失，先用大白话告诉用户缺什么、怎么补（如「缺少 Python，请先安装」），不要直接开跑。
2. **网络 / 超时错误**：命令报连接失败、超时、DNS 解析失败时，自动重试 **最多 2 次**（间隔 10s → 30s 递增）；仍失败则停止，明确提示「网络波动，稍后我再帮你重试」，不要无限重试。
3. **凭据 / 积分错误**：API key 无效时，明确提示「key 失效，请到 cuecue.cn 检查」；credits 不足时，按「积分不足专项提示」给出两条路径（邀请新用户得 500 积分 / 9.9 加油包 900 积分），引导用户修复，而不是重试。
4. **结果为空**：末行 `RESULT empty` 不视为完成，提示「本次未检索到有效结果」，改用自由式兜底（不带 `--template-id`）或请用户补充信息后重跑。
5. **命令报错**：脚本报错或路径不存在时，读取错误信息后向用户转述「哪个环节失败 + 建议动作」，禁止静默吞错或直接粘贴 traceback。
6. **重试上限**：所有重试默认上限 2 次，避免死循环；每次重试前用一句话告知当前状态。
