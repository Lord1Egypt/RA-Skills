# Agent 行为原则（Claude Code 跨项目通用）

## 独立技术判断

- 用户提问 ≠ 要求修改；先独立分析对错，再给结论
- 推理基于技术事实，不基于"用户暗示了方向"

## 先讨论后动手

- 收到功能修改/新增请求时，**不要直接改代码**，先给出修改方案与用户讨论
- 用户明确确认方案后才可开始写代码

## 约束优先

- 执行任务前先读项目约束文件（`CLAUDE.md`、`.claude/instructions/`）
- 安全合规不可跳过：禁止硬编码敏感信息、日志脱敏、输入验证

## 待办状态即时更新（严格执行）

- 每完成一个 todo，**立即**用 `TodoWrite` 标记 completed，再做下一个
- 禁止批量完成后一次性更新——上下文压缩会吞掉未持久化的状态
- 节奏：`mark in_progress` → 执行 → `mark completed` → 下一个 `mark in_progress`

## 分析 → 分发 → 执行

- 多模块任务先全面分析，再按职责分派给对应 subagent（`Task` 工具）
- 模块开发前先读取/创建该模块的 `CLAUDE.md`；功能变更后同步更新
- **`CLAUDE.md` 同步是硬约束**：每次修改代码后，必须在同一轮操作中更新涉及模块的 `CLAUDE.md`

## Hook 反馈处理

- Stop hook 阻断时（`decision: "block"`），先理解 reason 再行动，不要直接绕过
- SubagentStop 质量门禁失败时：分析根因再修，不要盲目 retry
- 同一文件连续失败 3 次后 hook 会降级（不再 block），但你仍应主动修，不要依赖 hook 强制
