# 产物 skill 结构规范与质量红线

本文件定义蒸馏产物（领域专家 skill）的标准结构。阶段 3（蒸馏）与阶段 4（组装）必须遵守；阶段 5（校验）按此核对。

## 目录结构

```
output/<skill_name>/
├── SKILL.md              # 唯一入口（目录内不得再出现其他 SKILL.md）
└── kb/                   # 知识库（全部 .md）
    ├── laws.md           # 全局宪法：跨领域不可违背原则（横切，LAW-N 编号）
    ├── <subdomain>.md    # 每个子领域一份（含领域法则小节）
    ├── ...               # 其余子领域
    ├── ai-mistakes.md    # AI 写该领域代码的典型错误集（横切）
    ├── gotchas.md        # 跨子领域高频坑点 Top 汇总（横切）
    └── patterns.md       # 通用最佳实践模式（横切）
```

横切文件按领域配置 `cross_cutting_files` 生成，未配置时默认四件：`laws` / `ai-mistakes` / `gotchas` / `patterns`。

扩展子领域按领域配置 `spin_off_subdomains` 登记：深化轮从既有子领域拆分出的独立 kb（如 WCAG 逐条审计检查表、行业主题图谱）。每条字段：`name`（与 kb 文件名一致）/ `title` / `corpus_home`（语料寄居路径）/ `origin`（拆分由来）。此类 kb 无独立 corpus 目录，刷新时按 `corpus_home` 取语料；未配置该字段的领域视为无扩展子领域。

## SKILL.md 规范

### frontmatter

```yaml
---
name: <skill_name>        # 小写字母数字+连字符，≤64 字符，必须与目录名完全一致
description: ...          # 必填，缺失会导致 skill 被过滤不生效
---
```

### description 公式

```
[领域定位一句话：做什么]。Use when [触发场景：写/调试/选型/迁移的具体关键词]。
Triggers: [description_keywords 全部或 ≥80%，逗号分隔]。[版本锚定一句：Covers <主框架+版本>。]
```

要求：
- 第三人称（"Use when..."，不用 "I help..."）。
- 关键词**前置**（模型/加载器靠它们匹配触发）。
- 长度 ≤1024 字符。
- 覆盖领域配置中 ≥80% 的 `description_keywords`。

### 正文骨架

1. `# <标题>` — 一句话定位。
2. **知识库索引表** — 每个 kb 文件一行：文件、内容、何时读；laws.md 置顶。
3. **决策树** — 用户问题类型 → 应加载的 kb 文件（列表或嵌套列表形式）。
4. **Top 法则内联摘要** — 从 laws.md 提炼的最致命 5~8 条 LAW 条款（含编号），让 agent 不读 kb 也不越红线。
5. **Top 坑点内联摘要** — 从 gotchas 提炼的最致命 5~10 条一句话版。
6. **回答规范** — 引用 kb 条目时保留来源标注；生成代码前逐条自检 LAW 条款；不确定时明说，不编造 API。
7. **知识回流** — 触发条件与回写规程指引（引用 refine 规程路径，回写时标注 `[实战回流]`）。

## kb 知识文件规范

### 三层知识金字塔

产物以**正向指导为主轴**，三层知识比例目标：**法则 ≈ 15% / 最佳实践 ≈ 45% / 坑点 ≈ 40%**。

| 层次 | 性质 | 形态 |
|---|---|---|
| 法则 | 约束性（不可违背） | MUST/NEVER/ALWAYS 编号条款 + 违反后果 + 溯源 |
| 最佳实践 | 建设性（指导行动） | 场景 → 推荐路径 → do/don't 对照 → 边界条件 |
| 坑点 | 防御性（解释故障） | 速查表为主，Top 1~3 条完整展开 |

### 骨架（子领域文件）

```markdown
---
subdomain: <name>
version: 1                # 每次内容更新 +1
updated: <YYYY-MM-DD>
---
# <子领域标题>

## 定位与心智模型
## 法则                  # 编号条款 <PREFIX>-<N>：MUST/NEVER + 违反后果 + 溯源
## 核心概念速览
## 最佳实践              # 场景化：推荐路径 + do/don't 代码对照 + 边界条件
## 高频坑点（速查）       # 表格速查为主；Top 1~3 条保留完整结构
## API 速查表
## 版本注意              # 硬事实，必须有文档佐证
## 与其他子领域的集成要点
## 来源索引              # 必需小节
```

- 「法则」与「最佳实践」是灵魂章节：先回答"该怎么做/什么不能做"，再谈"犯了错怎么解释"。
- 法则条款必须**可判定**（能机械判断是否违反）、**配后果**（违反会怎样）、**可引用**（编号稳定）。
- 官方明文规则（Rules of Hooks 等）优先升格为法则并附文档 URL。
- 坑点必须能反向指向某条法则或实践——孤立的坑点砍掉或并入速查表。
- 横切文件骨架可简化（laws / ai-mistakes / gotchas / patterns 各自定义），但「来源索引」小节一律必需。
- 骨架适配与豁免（类型化：非编程域/模板类/横切/审计类 spin-off）及标题别名表见 [prompts/distill.md](../prompts/distill.md)「骨架适配与豁免」——豁免按子域类型自动成立，模板正文以 `<!-- template-body: start/end -->` 定界不参与骨架判定。

### laws.md（全局宪法）规范

1. 收录跨领域不可违背原则：各 subdomain 法则化萃取的 `[GLOBAL]` 候选 + 跨领域通用原则，去重合并。
2. 统一编号 `LAW-1`、`LAW-2`...，按主题分组（版本纪律/状态纪律/安全纪律/数据纪律等）。
3. 每条：编号 + MUST/NEVER + 条款 + 违反后果 + 溯源（指向来源 kb 或文档 URL）。
4. 数量 10~20 条，宁缺毋滥——宪法不是清单。

### 三级来源标注（反幻觉红线）

| 标注 | 用途 | 硬约束 |
|---|---|---|
| `[官方文档](url)` | 有文档佐证的知识 | url 必须真实来自阶段 2 抓取 |
| `[模型经验]` | 模型内生隐性经验 | 必须附"为什么/何时适用"；**不得用于**版本号、API 签名等硬事实 |
| `[推断]` | 推断性内容 | 必须附推理依据；不得出现在「高频坑点」「API 速查表」「版本注意」区块 |

另有回流专用标注 `[实战回流]`：来自真实使用中修复问题的知识，最高价值之一。

### 质量红线

1. 单文件非空、≤2000 行、含「来源索引」。
2. 产物总体积 ≤2MB（2048KB，`validate_skill.py MAX_TOTAL_BYTES` 红线；超限在蒸馏阶段拆分）。
3. 全部 UTF-8，无乱码。
4. 内容语言跟随领域配置（默认中文），代码/API 名/术语/报错保留英文。
5. 产物目录内**有且仅有一个** SKILL.md。
6. 每个知识原子（坑点/速查条目/实践）自带来源标注，不靠上下文推断来源。

## 校验对应关系（阶段 5 核对项）

| 校验项 | 执行方式 |
|---|---|
| frontmatter 可解析、name/description 合规 | 脚本 + 人工 |
| name 与目录同名、小写连字符、≤64 字符 | 脚本 |
| description 覆盖 ≥80% keywords | 脚本（--keywords） |
| kb 文件齐全（配置的 subdomains + spin_off_subdomains + 横切文件） | 人工（对照领域配置） |
| 新域/并行会话交付：三项补账（配置对齐 / frontmatter 骨架 / 横切对账在位） | 人工 |
| 单文件 ≤2000 行、含「来源索引」、UTF-8 | 脚本 |
| 总体积 ≤2MB | 脚本 |
| 硬事实有文档佐证标注 | 人工抽查 |
| 嵌套 SKILL.md 检查 | 脚本 |
