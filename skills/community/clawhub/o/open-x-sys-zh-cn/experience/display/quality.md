# 质量流程

> **何时读**：一份成果有了初稿，就要交付；有条件请批评者审视；或者有样东西让你觉得做完了，而你还没有看过它。

一份成果写出来了，不算完成。它被看过、被批评过、被改过，才算完成。

```text
渲染 → 在桌面和手机宽度下看 → 宿主允许时由懂行的批评者审视 → 至少改一轮
```

这是在描述一份完成的成果经历过什么。走几圈、按什么顺序，由你判断。

## 把它渲染出来看

用这个人会用的方式打开成果：网页在浏览器里，视频播放出来，演示稿进入放映，文档按读者看到的样子。你看到的，常常不是你以为的。

- **桌面和手机宽度。** 大多数分享出去的链接是在手机上打开的。检查没有东西溢出，字读得清，揭示仍然打得中，控件用拇指够得着。
- **从头，按阅读的速度。** 前三秒里有没有继续看下去的理由？每一屏有没有回答上一屏提出的问题？
- **揭示。** 你是走到它面前的，还是划过去的？转折之前，那个“以为”有没有被留出空间？
- **每个控件。** 每个都用一下。它有没有让人看见静止的页面上看不见的东西？没有的，去掉。
- **每个数字和名字**，对着来源核一遍。渲染的时候，才会注意到一个写反了的数字。
- **断网的情况**，如果页面本来打算能离线工作。
- **明与暗**，如果两种都支持。

宿主没法渲染时，像读者那样把源文件读一遍，并明确说明这份成果没有经过渲染和检查。

## 两个检验

1. **去掉所有控件、面板和说明，它还令人惊叹吗？** 如果页面只是因为东西在动才显得厉害，那实质就不在了。
2. **懂这个领域的人看完，会不会停下来说“我从没这样看过”？** 正确、完整、好看是起点，不是标准。

一份通不过第二个检验的成果，问题在上游，在认识里。改版式救不了它。回到 `engines/understand.md`。

## 懂行的批评者

宿主允许时，把成果交给一位没见过你推理过程的审视者：一个子代理，被要求以这个领域的从业者、以一位挑剔的读者的身份来读。要具体的意见：

- 行家会在哪里皱眉？哪个论断其实比它听起来的要弱？
- 哪句话是凑数的？哪一屏只是为了显得完整才在那里？
- 读者会带走的那一样东西是什么？是不是本来想让读者带走的那一样？
- 一位内行的读者会期待、而这里没有的是什么？
- 有没有哪里看起来像模板？

把审视的意见当作证据，不当作命令：批评者也会错，由你来决定。任何关于事实的反对意见，都对着来源核一遍。

宿主不允许子代理时，由你自己完成批评这一轮：把作品放下，然后读两遍，一遍作为这个领域里最多疑的从业者，一遍作为新来的人。用一句话说明这次批评是你自己做的。

## 至少改一轮

初稿总有可改的地方。真正要紧的典型修改：

- **开头**：删掉热身；从那个反常的事实、那个被推翻的直觉或那个场景开始。
- **揭示**：往前挪，给它空间，去掉与它争抢的东西。
- **中段**：删掉为了完整而存在的那一屏。
- **结尾**：结束在新的看法上，而不是结束在一段总结上。
- **论断**：批评者怀疑过的，软化它或给出来源；推断就标成推断。
- **控件**：没通过第一个检验的，去掉。
- **雷同**：看起来像从上一份成果借来的地方，改掉。

## 签名检查

交付之前，确认本质、揭示和证据真实有分量。所选签名元素要帮助读者认出、理解、复用或者接着探索。采用路线条时，显示真正塑造成果的那条路（见 `experience/display/signature.md`）。

## 诚实检查

- 每个关键事实都有来源和日期。事实、推断与猜测在页面上分得清。
- 没有任何占位内容。没有编造的引语、数据、人物或例子顶替真实的。
- 没能核实的地方，成果里会说。
- 对人物和公司的描述，只到来源支持的程度。
- 分享包里的各项说的和成果是同一件事，只是更短，条件原样保留。

## 各种形式的专业水准

| 形式 | 完成的标志 |
|---|---|
| **网页** | 从一个文件打开；加载快；手机宽度下读得清；键盘可达；控制台没有报错；没有版面跳动；图片有替代文字 |
| **视频** | 关掉声音也看得懂；前两秒配得上后面的十秒；字幕在安全区内；没有一帧只是在凑时间 |
| **演示稿** | 每页一个想法；标题直接说出论点；这个人不用你的备注也能讲 |
| **文档** | 读者可以据此行动；答案在第一页；来源在后面 |
| **代码或工具** | 在这个人的电脑上跑得起来；在真实的输入上跑过；说明它需要什么；失败时说得清楚 |
| **文字** | 上面没有 OpenXSys 这个名字，也值得一读 |

## 时间

质量流程是全力开启的一部分，包含在你开头说的那个时间里。这个人要的是简短版时，流程会短一些，但渲染和诚实检查不跳过。一份没被看过的成果，交付时要说明这个事实。

## 交付之后

流程和这个人一起继续。这个人对一个事实的纠正、在某一屏上的困惑、停下不读的地方，都是证据。改的是同一份成果；条件变了，就让之前和之后看得见；把关于“怎样对这个人讲最好”学到的东西记进系统。
