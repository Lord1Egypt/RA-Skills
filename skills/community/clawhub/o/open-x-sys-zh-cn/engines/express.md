# 表达：从认识到成果

> **何时读**：认识已经能讲清楚，到了做点什么的时候；这个人要某种结果（“把它做成视频”“写出来”“给我一个方案”）；或者后来的一句话，让已有的成果不再合用。
> 身份线索、形式、库、传播和质量流程的细节在 `../experience/display/` 里。

成果，是认识真正到达这个人的那一刻。同一个洞见，平平地说出来，让人点点头；说得好，让人记住、转给别人，并且想继续往下走。认识可以很深，成果让人容易进入。

## 让论点、结构与形式彼此咬合

从核心论点出发，组织读者抵达它的结构，再让形式把结构变成体验。制作过程中三者可以互相修正，但每个视觉和交互选择都能追到它服务的认识。

- **论点**：这份成果要让人看见的那一件事。一句话，能改变看法，由真实的研究支撑。在成果里，它以**揭示**的样子出现：“你以为…… → 其实……”。写不出来，就回到 `engines/understand.md`。
- **结构**：从读者站着的地方，走到那一件事的路径。开头给出一个继续看下去的理由：一个反常的事实、一个即将被推翻的直觉、一个具体的场景。中段一层一层揭开，每一层回答上一层留下的问题。结尾回到本质，读者带着一种新的看法离开。
- **形式**：最后才选，并且为内容而选。

## 认识要深，进入要容易

系统里有十个结构，成果只展示最可能让人说“原来是这样运转的”的那一两个。其余的没有浪费。它们留在系统里，是下一批问题的答案，也是下一组选择的来源。

容易进入意味着读者可以从自己的概念出发，看见系统发现的深层结构；看完之后，手里多了一种观察其他事物也用得上的方式。

**从这个人已经理解的地方出发。** 用这个人的概念，和这个人熟悉的东西。同一份认识，讲给刚入门的人和讲给行内人，是两份不同的成果。

## 作品的核心与自由

本质、揭示和可信的依据撑住一件研究作品。激活标志、方法标签、路线条、来源呈现和继续问法可以让作品容易理解、学习与分享，具体用哪些由对象和使用者的需要决定（见 `experience/display/signature.md`）。

字体、色彩、节奏、版式和叙述声音都从对象中长出来。问自己：哪些部分真正属于这个对象，怎样让核心发现拥有只有它配得上的形式？

## 形式跟着需要走

先问读者需要在头脑里完成什么。下面这些形式提供创作可能，系统可以组合、改造或创造新的形式。

| 读者需要…… | 可以用的形式 |
|---|---|
| 看见一个机制如何运转 | 可逐步推进的探索、动画图解、简短的讲解视频 |
| 感受一个尺度 | 同屏的比例对照、可以缩放的尺度 |
| 检验自己的直觉 | 先预测，再揭示 |
| 理解来龙去脉 | 在转折点停留的叙事时间线、滚动叙事 |
| 比较几种未来或几个选项 | 在关键维度上并排比较 |
| 看清一个结构 | 剖面、分层、标注过的真实图像。节点连线图只在拓扑本身是重点时使用 |
| 亲手试一试 | 模拟，只在动态本身就是洞见时使用 |
| 掌握一个数学或物理思想 | 概念动画 |
| 行动 | 一份计划、一个工具、一套演示稿、一份文档、代码 |
| 被打动 | 文字。一篇写得好的文章，常常胜过一个平庸的交互页面 |

一份成果可以混合几种形式，其中一种是主体。请求说得简单，不会限制结果：一句话，也可以换来一份完整的成果。

## 全力开启时的媒介

当视频、动画或演示稿能服务这个需要，而且宿主当前确实具备相应能力时，直接做出来。能力缺失时，把实际可以完成的表达做成一份独立可用的成果。它可以是单文件网页、静态卡片、完整分镜或适合读者的文档。说明当前真正交付的形式，并把核心发现完整传给人（见 `../adapters/tools.md`）。

## 两个检验

1. **去掉所有控件、面板和说明，它还令人惊叹吗？** 交互只出现在它能让人看见页面静止时看不见的东西的地方。每个控件都要过这一关，过不了就删掉。
2. **懂这个领域的人看完，会不会停下来说“我从没这样看过”？** 正确、完整、好看，还不够。

## 把探索接回对话

成果可以成为下一轮系统运行的入口。值得接着走的方向来自真实缺口与连接，可以直接回到对话、复制成问题，也可以进入另一件作品或能力（见 `engines/explore.md`）。

## 专业水准

- **真实**：真实的数据、名字与图像；可以追溯的来源；推测标明是推测；任何地方都没有占位内容。
- **可读**：清楚的层级、舒适的行长、克制的配色、足够的留白；每一屏只讲一件事。
- **独立**：它能被单独打开和分享，不依赖这次对话，也不依赖你的环境。
- 文章、报告、代码、脚本与分镜、演示稿和方案，用的是同一个标准：做到专业人士愿意署名的程度。只能输出文字的宿主，损失的是形式，不是信息。

把成果渲染出来看一遍，包括手机宽度。宿主允许时，请懂行的批评者审视。至少改一轮。完整的流程见 `experience/display/quality.md`。

## 当这个人要的是某种结果

“把这些研究做成一支视频”让系统长出一种新的表达形式。用上已有的认识、实践与连接；需要补足媒介能力时，研究并建造它（见 `engines/build.md`），再按这个人的条件、受众与品味来做。结果里的每个关键论断仍然能追回到那份认识和它的来源。

## 成果放在哪里，怎样改变

- **成果属于这个人。** 放在这个人平时放这类东西的地方，沿用那里已有的组织方式。没有既定方式，就放在一个清楚可见的位置，并说明在哪里。写入之前，先看那里已经有什么。
- 后来的一句话改的是同一份成果，不是重新开始。条件变了，就让“之前”和“之后”看得见。大改之前，留住旧版本。
- 这个人亲手改过的成果，以这个人的版本为准。

## 这个引擎在这个人的系统里读写什么

- **读**：对象的认识（论点从这里来）；根系统里的第二份记录和偏好的表达方式（从哪里讲起，用什么声音）；已有的实践（这类东西上次是怎样做成的）。
- **写**：系统保存认识，并指向成果。在入口里记下成果在哪里、它展示了什么。做的过程中被证明有效的做法，交给 `engines/build.md` 和 `engines/evolve.md`，成为实践记录。
