## 十六点五、派发硬验证（v2.15.7 新增；与 SKILL.md `coordinator_spawn_hard_gate: true` 配对）

> **真源**：本节为「主控 spawn 子代理前必须有 sessions_spawn 实际 tool_call 返回值」规则的本文件侧真源。SKILL.md frontmatter `coordinator_spawn_hard_gate: true` 仅声明启用；具体判据在本节。
> **适用**：所有 `sessions_spawn(...)` 调用，包括主控派发 T1-T9 + T9b + Phase 1.5 定向回查 + Phase 4.3 定向回查等所有派发节点。

### 硬规则（四条，缺一不可）

1. **必须捕获 tool_call 返回值**：主控每次发起 `sessions_spawn(...)` 后，必须把**完整返回值**保存到一个本地变量（典型名 = `spawn_result`），不得「口头描述『已派发』」即跳走。
2. **返回值非空 ⇒ 才能写派发清单**：仅当 `spawn_result.runId` + `spawn_result.childSessionKey` + `spawn_result.resolvedModel` 三项均存在时，才允许在 `status.md` 写「派发清单」行；缺一项 ⇒ 视为 spawn 失败，按既有降级路径处置（节点接管 / 静默升级 / 主人三选一）。（字段名以实测为准：sessions_spawn 返回 `runId` / `childSessionKey` / `resolvedModel`，2026-10-02 实测验证）
3. **禁止 `yield` 前未列 runId**：调用 `sessions_yield` 进入等待前，必须保证**当前 phase 所有 spawn 的 runId + sessionKey 都在 status.md 派发清单可读**；任意一个缺失 ⇒ 禁 yield（继续补 spawn 或显式报错）。
4. **失败 spawn 也必须留痕**：即便 spawn 返回值为空 / 抛错 / 无响应（含平台侧中断），仍须在 `status.md` 写一行 `派发失败 = <node_id> @ <attempt_time>（原因：<error_msg 摘要>）`，然后再走降级。**禁止**静默跳过。

### 反面实况（v2.15.7 前的坑）

- 主控 spawn 后立即 yield，子代理实际从未启动 ⇒ 主控以「已派发」措辞回报主人，主人误判为在跑，等 1-2 小时后才发现零产物
- spawn 返回值含 `runId` 但主控未读 → 写派发清单时漏掉 → 主人拍板时无法定位 worker session
- 失败 spawn 被主控「吞掉」（仅口述失败，未写 status）→ 节点表长时间 `Inbox`，触发不了降级

### 与既有机制的分界

| 既有规则 | 关系 |
|----------|------|
| §三「任务书必含叶子声明」 | **前置**：spawn 任务书必含叶子声明；本节管返回值 |
| §十六「边界介入」 | **互不重叠**：§十六管「主控该不该亲自下场」；本节管「spawn 是否真发出去了」 |
| phase-order.yaml `provider_silence_escalation` | **下游**：spawn 真发出但 worker 静默时走；本节管 spawn 本身 |
| `model_fallback_takeover_protocol.md` | **更下游**：fallback 模型启动后不知如何续跑时走；本节管主控一次性派发 |

### 字段规范（status.md 派发清单每行）

每次 spawn 成功后在 `status.md` 写一行：

    - **<node_id>** @ <ISO 8601 时间> | runId=<runId> | sessionKey=<childSessionKey> | model=<resolvedModel>

任一字段为空 ⇒ 该行记 `incomplete_dispatch`，M-Exist 终检按「路径或参数错误」档处置。

### 派发前 weight 校验（v2.15.7 新增；skill 自包含阈值，宿主零配置）

主控每次 spawn 任何子代理前，必须根据本任务**预期字符数 + 预期 worker 数**判定 session 选型，并显式记录到 spawn 任务书头部：

| 预期字符数（含产物总和） | 预期 worker 数 | 推荐 session | 必填动作 |
|---|---|---|---|
| < 2000 | 任意 | 任意 session | spawn 任务书头部声明 `weight=light` |
| 2000 ~ 10000 | < 10 | 业务 session 可（如飞书 bot）| spawn 任务书头部声明 `weight=medium` |
| 2000 ~ 10000 | ≥ 10 | **可见主 session** | 同上 |
| ≥ 10000 | 任意 | **可见主 session**（禁塞飞书 bot 等业务 session）| spawn 任务书头部声明 `weight=heavy` + §十六点五 第 3 条同步触发 |

**真源**：本节阈值表（skill 自包含；论衡对宿主零配置要求，见 SKILL.md「执行能力边界」）。当初误把自造键 `recommended_session_for_weight` 写进宿主 openclaw.json 并标为真源——已撤回：平台无此键，skill 行为判据不得依赖宿主配置。

**若实际选型与推荐不符**（如主人显式要求塞业务 session）⇒ 主控必须在 status.md `§八 模型接管声明` 之外**新增一行**说明：`[weight-overridden HH:MM] chars=<N> workers=<N> recommended=<X> actual=<Y> reason=<主人显式要求 / 其他>`。未记录 ⇒ 视为违规派发，T8 终检按 P1 处置。

**反面实况（v2.15.7 前的坑）**：本类长跑任务（≥10000 字、≥10 worker）被默认塞进飞书 bot session，飞书 bot 模型上下文预算吃紧 ⇒ worker 静默失败 + 主控失联 + 主人侧无任何提示。

## 二、status.md 并发写控制

**status.md 主控独占写**（主控与子代理并发写同一文件存在竞态）：
- **主控独占写**：`status.md` 只能由主控（主 agent）写入，子代理**不得直接 `write`/`edit`** status.md——子代理通过心跳文件（如 `run/<项目>/.tmp/<role>-heartbeat.md`）向主控发信号，主控按心跳节奏独占写入 status.md
- **子代理标识状态**：子代理在产物路径写**自己的阶段文件**（如 `drafts/<role>-status.json`），主控轮询阶段文件后更新到主 status.md

### 结构化重写

markdown 表格列多、edit 易漂移（空格漂移 / old_string 不匹配 / 重复行）。**主控更新 status.md 一律用「key:value 文本替换」**：

- **角色状态行替换策略**：`**T5 写作**: ⬜ Inbox` → `**T5 写作**: ✅ Done (2026-08-25 11:30, 5686 字)`（一行替换，零空格依赖）
- **闸门清单**：保留 `- ` 格式（仅打钩，**主控不用 replace**）
- **产物路径**：`final/定稿: final/定稿.md` key:value 格式（路径不变，仅替换 value）
- **方法论足迹**：保留表格（实时数据有数字变化，主控用 row replace）

## 三、任务书工具边界声明

每次 spawn 子代理的任务书必含「本环境无 exec/process/shell 工具，禁止尝试；验证用 read 工具」声明，防子代理误试 exec 空转。

**任务书必含叶子声明**（与上句并列，同一次 spawn 写）：

> 你是本流水线的**叶子 worker**：不得调用 `sessions_spawn` 派生任何子代理，不得用 `subagents` / `sessions_list` / `sessions_history` 查看或管理其他会话（平台默认开启递归委派，你可能「拿得到」这些工具，但未被授权）。需要额外检索/人手 → 在交接报告写「需求回执」（缺什么/为何缺/建议派谁），由主控决定。

**为什么**：平台默认开启有界递归委派时，子代理实际拿得到 `sessions_*` 递归工具；子代理自行 spawn 的孙辈产物**不上传主控**（产出静默丢失）。**主控侧自检**：**标准架构恒为多 Agent 九角色**，按叶子架构派发（直接子代理即叶子），并在每次 spawn 的任务书内确认叶子声明已写 → `status.md` 记派发清单；worker 失败/不可用 ⇒ 只接管该节点并记录。**论衡不读取、不校验、不修改宿主的权限配置文件 / 网关配置**（不读宿主配置、不就宿主配置告警）；**自身会话可见工具面仍做非侵入式自检与披露**（见本文件「能力自检」段；精确口径真源 = [`_shared/真源/external-services.md`](../_shared/真源/external-services.md) §「不读取宿主网关配置（精确口径）」）。

## 四、案例检索并行化

> **硬关卡（Phase 0 consent gate）**：本节任何 spawn 行为**仅在 Phase 0 主人显式勾选「检索类外发同意」后**才执行；未勾选 ⇒ 主控亲为的「不联网 + 不用 web_*」路径（该节点由主控接管并记录；见 SKILL.md「执行前安全须知」段）。T1/T2/T3 任何外发调用**前**必须显式核对同意记录。

**Phase 0 确认需要案例时，spawn T3 案例检索员**，与 T1/T2 三方并行，互不干涉；T3 worker 不可用 ⇒ 主控接管该节点并记录：
- **并行触发**：通过 `pre_spawn_enforcement` 前置核验后，主控并行 spawn T1 + T2 + T3 三个独立 sessions
- **0 条场景降级协议**（cases = 0 时）：T3 spawn 但 prompt 写「本次任务无案例需求，输出空案例卡 + 显式声明 `本次无案例需求，N 条案例卡`」
- **决策依据**：写入 `status.md` 案例决策行（记录 `result=required|empty_card|waived`、cases 需求量、依据文件和产物路径）。`empty_card` 必须确实 spawn 并写 `[C-空]`；`waived` 必须有明确理由；不得用 `Skipped` 掩盖状态。

### Phase 1.5 定向回查窗口（显式但不隐形）

### 子会话回执复验门

> 子会话「完成回报」 ≠ 写盘证据：回执本身也是子会话生成，不可作为自我验证。

**主控复验 4 件套**（收到任何「完成」汇报必跑）：

> ⚠️ **语义口径**：以下「列出 / wc / 检查 / find / stat」描述的是**语义等价动作**（产物存在性、数量对账、标记计数、时间戳新鲜度），主控用 `read` / `sessions_history` / 文件元数据**推理实现**，不执行任何 shell；论衡零 exec。下列命令形态仅为语义说明，主人可在 host shell 手动复核。

1. **产物存在性**：产物路径存在且非空
2. **数量对账**：产物行数/字节数与子会话回执报告数**对得上**（差值 > 20% 即异常）
3. **完成标记计数**：修订类必核完成标记（`<!-- P[0-2]-.*✅`）数 = 任务书条数
4. **新鲜度**：产物修改时间**晚于**任务书

**节点推进前置校验（防「跳步」）**：

每跑完一个节点、**推进到下一个节点之前**，主控**必须**核验三件：

1. **`next` 目标存在**：`phase-order.yaml` 里该节点 `next` 指向的 id **必须在 `pipeline` 中真实存在**（注意区分「节点 id」与「动作名」）；
2. **产物存在**：该节点的**产出**（yaml `output` 声明；无声明则按阶段文档的产物路径）在磁盘**真实存在**；
3. **不满足即停**：任一不满足 → **停下报错并告知主人**，**不得**凭「看起来做完了」继续推进。

> 反面示例：节点被误判为别名后按错误 `next` 推进，曾整段跳过 `t7_audit`。故必须区分「节点 id」与「动作名」。

**交付说明产物清单核验**：`final/交付说明.md` 的产物清单**每一条都必须逐条核验存在性**（`read` / 文件元数据语义核对）；**清单中不得出现未落盘的产物**；核验结果记 `status.md`。
> 交付说明声称存在的产物必须逐条在盘上真实存在——**交付物对自己撒谎是最危险的一类缺陷**。

**spawn 后 SOP（零 exec 语义版；本段即唯一真源）**：
1. **spawn 后不轮询、不 sleep** → `sessions_yield` 等 completion 事件（平台准则：不要用 `exec` sleep 搭轮询）
2. **收事件后跑「复验 4 件套」**（上文 1-4 条，全部以 `read` / 文件元数据语义等价实现）
3. **零产物 ∧ 超过该角色 `runTimeoutSeconds`**（见 SKILL.md「硬卡阈值表」）→ 主控亲写兜底 + `status.md` 记 `failed_silent_watchdog` + 告知主人；**不重试 spawn 同一任务**
4. **token**：从 completion event 末尾 Stats line 取（精确值）
5. **sha256 与 bytes 不跑**：由主人 host shell 回填；未回填不得判通过
6. **兜底唤醒（与第 1 条并存不冲突）**：spawn 后**必须**安排一次定时自唤醒（触发时间 = 该角色硬卡阈值 + 缓冲）；到点**主动 `read` 核对磁盘产物**。**推进判据以磁盘产物为准**，completion event 仅作**加速信号**——兜底唤醒是第 1 条的**补充**，专治「worker 收尾挂起 → 完成事件不达 → 主控零动作」。唤醒面以本 skill 声明为准（**不得调用未声明工具**）；宿主无可用定时面 ⇒ 退化为「下一次进入本会话即复核」+ `status.md` 记 `watchdog_unavailable`（不得静默）。示例工具 `automations` 在 `denied` 内，本协议**不授权调用**。详见 [`00-主控-coordinator.md`](00-主控-coordinator.md)「主控兜底唤醒」节。

**不通过处理（唯一状态机）**：

> **唯一仲裁原则：人在环检查点 > 一切自动降级。** 任何超硬卡/失败处置**不得绕过** Phase 0 / 2.5 / 3.5 / 5 的主人决策；自动降级仅适用于 **worker 可用性**（子代理失活），不适用于 owner checkpoint。不转报假数据（「编造」与「采信」同型）。

| 情形 | 判定标记 | 处置（唯一） | 重试？ |
|---|---|---|---|
| 子代理静默（零产物 ∧ 超 `runTimeoutSeconds` ∧ 心跳未续） | `failed_silent_watchdog` | 主控亲写兜底 + status 记录 + 告知主人 | ❌ 同任务不重试 |
| 平台机械超时但产物已落盘 | 超时 ≠ 零产物 | **先 `read` 核对**，产物完整则采纳；缺失部分才兜底 | ❌ 不重试 |
| 复验 4 件套不过 | 可修复缺陷 | 退回**同一子会话**补写（不新建 spawn）；二次仍不过 → 主控亲自 edit + 记教训 | ⚠️ 仅原会话补写 |
| 资源/认证层错误（401/403/429/配额/billing） | `degraded` | 产物已写盘则先 read 验收；配额预授权已勾选→按预授权执行；未勾选→**停在人环**等主人 | ❌ 等主人 |
| 心跳缺失（超 2 分钟宽限）但产物正常 | worker 可用性异常 | **该节点由主控接管继续**（本表唯一允许的自动接管）+ status 记录 + 告知主人；**不影响 owner checkpoint** | — |
| 会话崩溃 / session rebound（平台层） | 平台责任 | 中断续跑规程（[`关键协议.md`](../_shared/真源/关键协议.md) 四步：读断点→核产物→取 next→校入参）；**不从零重跑** | — |

> **处置优先级规则（唯一权威口径）**：本表是**硬卡超阈 / 失败处置的唯一真源**；判情形一律按下列优先级，**先产物、后信号**（核心判据 = 「**超时 ≠ 零产物**」）：
> 1. **「产物存在且校验通过」 ＞ 「平台信号」** —— completion event / 平台信号与磁盘产物冲突时**以产物为准**：先 `read` 核对，完整即采纳；**不得**因信号先到就丢弃已落盘产物。
> 2. **「硬超阈后零产物」 ⇒ 恰好一条回退路径** —— `failed_silent_watchdog` → 主控亲写兜底 + status 记录 + 告知主人；**无第二分支、不重试**。
> 3. **「同档重派 ≤2 次 → 降档」只适用于「未启动 / spawn 丢失」**（tokens=0 ∧ history 停在初始 prompt）—— 属**平台层恢复**，真源 = [`执行韧化协议-design.md`](../_shared/真源/执行韧化协议-design.md) §零产物决策树；**已启动但硬卡静默**（零产物 ∧ 超 `runTimeoutSeconds` ∧ 心跳未续）**不走该树**，按本表第 1 行处置。
> 4. **能力 / 模型档可用性失败**（401/403/429/配额/`degraded`）⇒ **换档**重派（真源 = [`模型候选池.md`](../_shared/真源/模型候选池.md) §三）；配额耗尽 ⇒ 停人环等主人。

> **删除的旧语义（防回潮）**：① 「kill 后可 respawn 同任务」——与「不重试」互斥，已删；② 「心跳缺失 → 主控接管」曾隐含可无主人推进——已限定为**仅 worker 可用性**场景，owner checkpoint 一律 fail-closed。

## 十二点五、子代理错误码语义分层

**错误码分层**（收到子代理报错时先分层——资源/认证层错误 ≠ 产物缺失——再决定是否兜底）：

| 错误类型 | 典型信号 | 产物状态 | 主控动作 |
|---------|---------|---------|---------|
| **资源/认证层错误** | HTTP 401/403/429 / quota exceeded / 欠费 | **产物可能已完整写盘** | 先 `read` 验证产物，**不立即兜底** |
| **工具调用错误** | tool_error / protocol 错误 | 产物可能部分 | `read` 验证 + 补缺 |
| **显式未完成** | status=incomplete / degraded | 产物缺失或部分 | 按 degraded 协议走 fallback |

**主控兜底声明格式**：兜底时必须在产物头部 + status.md 写「**子代理实际工作 vs 主控叠加**」分层记录，不得笼统称「主控兜底」：
- 子代理实际产出：<列出子代理已写盘的内容>
- 主控叠加：<列出主控补写的内容>

**核验顺序**：兜底之前，先 `read` 确认产物是否已存在、是否与子代理回传一致——**先核对，再决定兜底**。

## 十五点五、Spawn 前能力断言 + 架构声明 + 不读取宿主配置（承继立场） <!-- 精确口径唯一真源 = `_shared/真源/external-services.md` §「不读取宿主网关配置（精确口径）」 -->

### Spawn 前能力断言

- **能力白名单（与 SKILL.md frontmatter 逐项对齐）**：base 3（read/write/edit）+ coordinator_only 8 + research_extra 4（web/tavily 检索）+ academic_extra 23（学术检索与元数据，opt-in）= **38 项** —— **逐项清单真源 = SKILL.md frontmatter `metadata.tools`**
> **会话管理原语作用域**：以上 6 个会话原语**全部硬限定为主控自己 spawn 的子代理树**——`sessions_history` / `sessions_list` 只读**自己** spawn 的子代理；`sessions_yield` 只等**自己** spawn 的子代理的完成事件；`subagents(action=cancel|list)` 的 taskId/runId 必须来自**本主控会话**派发的孙辈。**禁止**用它来枚举、读取或取消**其它会话**（含其它项目的协调会话）。越权调用**视为 SKILL.md frontmatter 工具面越权**，与白名单外调用同等处理。
- ⚠️ **通配符族写法禁止再入本文件**（`memory_*` / `sessions_*` / `ov_*` 曾被外部审计判「与顶层 denied 冲突的模糊授权」）——一律逐项列举，新增工具先过 frontmatter 真源
- **校验失败 → 人在环**：记录错误到 status.md + 告知主人能力越权请求

### 能力自检

**背景**：五档白名单**不能被机械强制**（`sessions_spawn` 无 `toolsAllow`）。本修订不改这一事实，而是把它从「纯声明」升级为「**可观测 + 可阻断**」：

- **主控侧（Phase 0 必走）**：核验自身可见工具是否**超出** frontmatter `metadata.tools` documented 集；按「**计数 + 高危类别具名**」记入 `status.md`「能力自检」段（① 可见计数 ② 差值计数 ③ 高危类别具名——执行类 / 外发类 / 写入类 / 会话类；其余超限项计入差值、不逐条枚举；仍**禁止只写「通过」**），并**在 Phase 0 向主人披露**（不阻断——主控工具面由宿主决定）。
- **子代理侧（每次 spawn 的首步）**：子代理按 [`_shared/真源/dispatch-header.md`](../_shared/真源/dispatch-header.md)「启动自检」核验自身工具面是否符合本档白名单，**按两级判据分开处置**：**铁律：工具面超限 ≠ 调用许可**（超限只说明平台给的工具面比本档声明宽，不授权调用其中任何工具）；① **工具面超限 = 警告级**（属常态 → 记录 + 披露 + **呈主人裁决**：敏感题材可要求主控接管该 worker；未裁决前仅继续手头已授权动作，**不调用任何超限工具**）；② **实际调用越权工具 = 阻断级**（停止、不写盘、回报 `capability_excess`）；③ 主控未给裁决时返回 `degraded` 并**继续执行**。
- **阻断规则**：主控收到 `capability_excess` ⇒ **不采纳该产物**，记录并告知主人；若**实际调用**涉及 `exec` / `process` / `browser` / `terminal` / `sessions_*` ⇒ **该档停用**，改走主控接管该节点并披露。
- **⚠️ 工具面提示不等于调用越权**：当前会话可见工具多于本角色声明时，不中止、不要求宿主处理；只要未实际调用未声明工具，角色照常工作。实际调用未声明工具才停止、拒收产物并走主控接管。
- **记录位**：`status.md`「能力自检」段（主控工具面 / 各档子代理自检结果 / 越权回报）。
- **诚实边界**：本自检只约束本角色自己的调用行为，不读取宿主配置；工具面可见范围由 OpenClaw 平台负责。实际调用未声明工具才阻断并转主控接管，不产生任何宿主侧状态。

### 架构声明（标准架构恒为多 Agent 九角色）

**背景**：OpenClaw 原生提供多 Agent 与子代理能力。论衡只声明派发清单、角色边界与接管记录；宿主工具策略、沙箱和额外机械限制属于平台/宿主责任，不是本 skill 的前置条件。

- **唯一标准架构**：**多 Agent 九角色流水线**——T1-T7/T9/G14 各自落盘角色产物；主控 T0/T8 负责状态、权威同步、配图、定稿组装、终检
- **不设总开关**：架构恒为标准模式，不存在启动/关闭多角色的开关项
- **触发时机**：首次 spawn 子代理前，于 Phase 0 简报中说明派发清单
- **worker 接管（异常路径）**：worker 失败/不可用 ⇒ **只接管该节点**（`on_worker_failure`），status.md 记接管记录 + 交付说明披露 L1 独立性影响。⚠️ **例外（盲审节点）**：`independence: blind_review` 节点（当前 = T9）**禁主控接管** —— 只能重试 spawn 独立子代理，仍失败则记 `missing_blind_review` + 显式告知主人（真源 = [`_shared/真源/phase-order.yaml`](../_shared/真源/phase-order.yaml) `t9_review.independence_failure_policy`）
- **敏感题材**：主人可**显式要求**主控接管涉密 worker 节点（其余节点照常派发）
- **论衡不读取、不修改宿主配置，也不对宿主的权限设定作任何前提假设**
- **记录位置**：status.md「项目元数据」段 `**架构**: 多 Agent 九角色` + 「worker 接管记录」（**不记 deny 明细、不记 enforcement 等级**）

### 不读取宿主配置

**核心承诺**：论衡运行**不调用、不读取、不干预**宿主 gateway / config / 任何宿主配置读取工具。**无例外**。

- ❌ 不调用 `gateway(action="config.get" | "config.schema.lookup" | "update.run")`
- ❌ 不读取 ``<OpenClaw数据目录>`` 等宿主配置文件
- ❌ 不基于宿主配置做"建议收紧"、"告警"、"阻断"——平台工具策略由宿主自行维护，与论衡运行无关
- ❌ 不读 OpenClaw metadata（平台 metadata 无 `tools.denied` 字段，亦不读其他字段）

**为什么**：纯 skill 定位下，工具权限是**宿主侧**的事——宿主可按 OpenClaw 官方文档自行收紧。论衡**不读取、不校验、不修改宿主配置文件 / 网关配置，也不就宿主配置状态阻断或告警**，也**不附带宿主侧配置配方**（配置配方随宿主版本演进，写死在 skill 里必然过期）。

**🧭 两层别混**：以上「不读取 / 不告警」口径**只针对宿主配置文件 / 网关配置**，**不等于不做运行时可观测** —— 本文件 §「能力自检」要求主控在 Phase 0 核验**自身可见工具**是否超出 `metadata.tools` documented 集、把超限项记入 `status.md` 并**向主人披露**，该条**保留且必须做**（自检读的是当前会话自身可见工具面 = agent 环境内已有信息，不读任何宿主机文件；子代理侧同理，见 [`_shared/真源/dispatch-header.md`](../_shared/真源/dispatch-header.md)「启动自检」）。精确口径唯一真源 = [`_shared/真源/external-services.md`](../_shared/真源/external-services.md) §「不读取宿主网关配置（精确口径）」。

**「零 exec」的准确定性**：论衡的「零 exec」是**文档层零授权**声明，**不是隔离保证** —— 子代理工具面由**宿主 OpenClaw** 决定。纪律层保障（`全文档零授权 + 自检门 M 门扫描 + 外部内容不可信原则`）是**唯一的 agent 侧保障**。

## 十八、「据行业经验估算」限定使用条件

**限定使用条件**（满足**全部**才能使用）：
1. **三源检索全失败**：① T1 文献检索 + ② T2 数据检索 + ③ web_search 补充均**未找到任何可引用的数字**
2. **段落顶部加注**：每次使用前在该段落开头写明 `[行业估算，非数据卡]` 标记
3. **附估算依据**：该数字必须能基于「业内常识」「从业者经验」「结构性推理」之一推导（不能凭空出现）
4. **不超过全文 3 处**：全文章「据行业经验估算」类措辞累计 ≤3 处（防止滥用）
5. **T7 审计必查 G2.5 估算标记**：T7 在 G2 数据溯源里加一条专门查估算使用频次，超过 3 处 → P1

**禁止使用的场景**：
- ❌「据行业经验估算」+ 具体百分比/元数（更精确 = 更需数据卡）
- ❌ 同一论点同时使用数据卡数字 + 估算（混用 = 不可验证）
- ❌ 全文结论性数字（必须可溯源）

**示例**：
- ✅ 正确：开模打样成本「据行业经验估算」动辄「数十万元」（有范围、无精确值）
- ❌ 错误：开模打样成本「据行业经验估算」47 万元/ SKU（伪装精确度）
- ❌ 错误：同一段同时使用 D15（顾家 184.8 亿）+ 估算数字（数据混用）
- 写手收到含主人洞察的指令时，按本协议做转换；如拿不准，**默认 A 档客观化**
