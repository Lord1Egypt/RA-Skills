# 科技内容多视角阅读

从成稿出发，按本篇定位选几个相关读者视角把读到的东西说出来，供作者裁决。面向以行业读者为对象、要建立稳定个人判断力的深度长文。

这是阅读工具，不是评审团。视角没有权威等级，观察不自动等于缺陷，反馈也不会自动变成长驻规则。

## 它做什么

1. 记一次定位锁：文章类型与平台、主要读者与阅读任务、主判断、有意划定的范围与排除项、深度与技术层级目标。这些是作者的决定，不交给读者重新讨论。
2. 按可回溯来源核验事实与原创性。这是唯一必须过的检查。未公开稿件衍生的外部检索，先确认授权。
3. 按本篇选 2–4 个视角：领域专家、运行时/基础设施专家、企业决策者、跨域行业读者、战略/投资读者、传播编辑、母语语感读者、直率的一般读者。默认不全用。
4. 每个视角报告：读出的判断、在哪里停住或滑过、触发句、可选的试改。观察分四类——误解、缺桥、不同意、偏好不同，不合并成一张缺陷清单。
5. 作者裁决：已核实的错误修；破坏定位理解的桥梁可定向修；偏好择优或停放并简记理由。只复看受影响段落，然后停。

模拟视角必须标注为**模拟阅读**，不冒充真实读者反应。

## 何时使用

**适用**：已完成的科技/AI/数据产业深度解读、产业判断与研究稿，作者想再看一遍论证落地情况。

**不适用**：新闻资讯、营销文案、产品文档、技术教程、观点短评，也不作为发布审批门。

## 怎么用

成稿之后：

> "从两三个相关读者角度读一遍这稿，报你观察到的东西。"

不打分、不判通过/不通过、不设 must-fix 分级、不要求挑出指定数量的问题、也不跑第二轮会审。`tech-writing-pipeline` §4 的表达诊断与 `references/depth-playbook.md` 的纵深方法只是出现具体症状时才打开的工具，没有命中数量要求。
