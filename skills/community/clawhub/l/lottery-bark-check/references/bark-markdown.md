# Bark markdown 颜色 / 字体 / 下划线：事实与取舍

本文件记录「彩票开奖核对」技能配色方案的源码级依据，供后续维护者参考，避免反复试错。

## 1. 能力边界（已查证）

- Bark 的 `markdown` 参数在手机端由 `NotificationServiceExtension/Processor/MarkdownProcessor.swift` +
  `Common/MarkdownParser.swift` 解析，只支持**基础 markdown**：粗体、斜体、标题、列表、引用、链接、行内代码。
- **没有任何自定义颜色参数**，也不支持 HTML `<font color>` 之类标签。
- 能出现的彩色只有**「链接蓝」**（来自 `visitLink`）与**「行内代码蓝」**（来自 `visitInlineCode` 的 `codeTextColor`），本质都是蓝色，没有红/绿/橙等其它颜色。
- `title` / `subtitle` 是 APNs 系统字段，**纯文本、不走 markdown**，无法着色、无法加粗。
- `subtitle` 字段可用于显示「中奖 / 未中奖」这类副标题（本技能采用）。

## 2. 两种蓝色载体（源码行为对照）

| 载体 | 写法 | 颜色 | 字体 | 下划线 | 点击行为 |
|---|---|---|---|---|---|
| 链接 `visitLink` | `[NN](url)` | 蓝 | 系统字体（不改字体） | **自带**（`underlineStyle = single` 写死，无开关） | 可点开网页 |
| 行内代码 `visitInlineCode` | `` `NN` `` | 蓝（`codeTextColor`） | **等宽字体** `monospacedSystemFont`（可能带浅灰底块） | 无 | 不可点 |

结论：**「蓝色 + 无下划线 + 与黑字同字体」三者不可兼得。**

- 要「字体一致」→ 用链接，接受下划线；
- 要「无下划线」→ 用行内代码，接受等宽字体与黑字不一致。

## 3. 本技能定稿选择

用户经过多轮对比，最终定稿**优先「字体一致」**：

- 蓝色号码 = 链接写法 `[NN](https://bark.day.app)`，与黑色号码同为系统字体；
- **接受链接自带的下划线**（这是 Bark 无法关闭的），以换取两行号码字体统一；
- 中奖「中奖」二字与金额 = `**[文字](url)**`（蓝色加粗，同样带下划线）；
- 未中奖保持黑色。

## 4. iOS 电话号码自动识别（易踩坑）

iOS 会把「连续多组两位数」（如 `03 04 11 13 28`，5 组）自动识别成电话号码并染成蓝色带下划线，
导致「我的」行里**未命中的号也变蓝**，与预期「仅命中变蓝」冲突。后区只有 2 组通常不触发。

解决：在每个号码之间插入**不可见词连接符 U+2060（word joiner）**再跟一个空格，
即 `(U+2060 + " ").join(parts)`。它打断自动识别，视觉上仍是单空格、不改变字体，
让未命中号码回归黑色、只保留我们显式上色的命中号。

> 注意：Bark 通知扩展最终会把 markdown 取纯文本 `body` 并压缩空行，
> 锁屏横幅 / 通知中心那一层的蓝色可能来自 iOS 系统链接识别，Bark 侧无法精确控制；
> 可精确上色的是 Bark App 内的通知详情 / 历史预览。

## 5. 换行规则

Bark markdown 只认两种换行：
- `\n\n`：段落分隔，产生**空行**；
- 行尾两个空格 + `\n`：硬换行（渲染效果需实测，不保证）。

**单个 `\n` 会被当成软换行合并成空格**，导致「开奖」「我的」两行被挤到同一行。
本技能四段之间统一使用 `\n\n`（含「开奖」与「我的」之间空一行）。

## 6. 提醒强度（历史问题，勿再改）

- `level=timeSensitive` 只提升通知在专注模式下的送达优先级，**不会关闭声音**；
- `level=critical` + `volume` + `call` + `sound=alarm` 属「强提醒」，会连响约 30 秒，用户已明确要求**改回原强度**；
- 曾有「收到但没响」的情况，最终确认为偶发（设备侧铃声音量/临时静音/注视感知），`sound=bell` 有效，参数无需改动。

本技能锁定：`level=timeSensitive`、`sound=bell`、`group=彩票`。
