# 机器输出与结果解释
<!-- reference-type: common -->

> **范围**：跨命令读取结构化结果并形成有依据的答复；不定义各组专属参数，不执行自动导出或批量调用。
<!-- slot: 范围 -->

## 选择可解析输出

| 输出方式 | 如何读取 |
|---|---|
| 默认 `table` | 适合人工阅读；机器处理使用结构化模式。 |
| `-o json` | 外层 `{code,msg,data,total}`，部分命令有 `meta`；成功封装码为 `200`，先核对进程退出码，`code` 不是 HTTP 状态。 |
| `-o json --jq '表达式'` | 内置过滤器对外层 JSON 执行表达式，无需系统 jq；投影后可能不再包含外层信封。过滤发生在请求之后，不减少后台消费。 |
| `-o ndjson` | 列表每条一行，对象输出单个对象；不带整体 `total/meta`，不能与 `--jq` 合用。 |

脚本需要总量、窗口或去重语义时使用 JSON。空列表是空集合；原始 JSON 中的 `null` 按具体命令解释为未知或未请求，真实 `0` 才是零，不要彼此替换。记录/产品 ID 保持字符串，禁止转浮点数或经过有损的大整数解析。

`--jq` 访问不存在的键也会得到 `null`。投影出现 `null` 时先对照该命令的输出字段名；能读取已留存原始 JSON 时，用 `keys` 或 `has("字段名")` 区分键不存在与原值为 null。不能仅凭投影 null 断言原接口没返回、明文字段被隐藏或账号无权限；没有原始数据就保留原因未知，不为检查拼写重跑可能消费的请求。

错误也由 CLI 本机封装为 JSON，参数错误等未发请求的失败同样可能输出 `code:500`。报告优先记录进程退出码、错误文案和 `cli_json_code`；没有独立 HTTP 证据时，不将该值标记为 `http_status` 或 `http_business_code`，不据此声称服务器返回了 500。

## 报告口径而不是夸大结论

答复包含任务范围、观察到的数量口径、少量关键样例和限制。只摘需要的字段，不把整页正文或个人信息塞入报告；用户明确要原始请求时仍说明截断及敏感过滤。

`total`、去重对象数、桶内请求数、当前页条数是不同口径。聚合可能近似；不将当前页相加当全量，不合并同名产品或相同脱敏名称。未知脱敏状态不能当明文，字段可回填也不等于账号有权查询。

没有结果只能说明当前账号、条件和有效窗口下未返回记录，不能证明目标安全；收到攻击请求不等于攻击成功，也不能仅凭请求推断 CVE、行为人或系统已失陷。

## 把查询结果变成业务答复

先直接回答用户要判断的事，再按需要组织以下内容，不必机械列齐：

1. **结论**：说明观察到了什么行为或分布；不能判断攻击成功时直说证据不足，不用模糊形容词替代实际结果。
2. **范围和数量**：实际环境、请求日期、原条件及必要的后台窗口限制；每个数字写清是请求、不同 IP、桶还是样例条数，并保留近似标记。
3. **关键证据**：少量时间、方法、URL、产品标签；需要复核单条时附同条 ID、日期、产品编号。先后行为按实际时间与方向解释，同秒记录不自行编毫秒顺序。
4. **可见边界或下一步**：哪些字段打码、截断、未请求或未知；只在这些缺口影响结论时提出具体补证动作，不用泛泛的“继续深入分析”结尾。

来源 IP 问题应说明活动和请求特征，URL 问题应说明命中条件及来源/路径，产品问题应说明名称匹配范围及是否涉及多个 ID。只问一个计数时直接给计数、口径和窗口，避免附上无关长报告。报告中的值全部取自本次真实结果，示例值不作为答案；没有实际运行或读取证据时，不宣称已完成查询。

同一批结果可重复用于回答和本地筛选，不重复发起可能消费的检索来换一个展示格式。保留需要的原始结构与关键元数据，投影前对照真实字段；导出或落盘仅在任务需要时进行，并去除 Key、个人身份、敏感头和非必要正文。
