# 体检报告与前三项行动

由读取技能的 Agent 写作；`analyze.py` 不拼文章。参考[完整演示报告](../examples/success/品牌体检报告.md)，使用本次实际证据重新组织内容。

报告开头就回答用户关心的问题，并同时交代品牌实体、用户提供资料的适用版本、样本范围、采集时间范围、平台/模型/联网模式。采集时间缺失显示“未提供”，不能用文件生成时间填补。无时间的样本仍可分析内容，但不用于时间趋势。

呈现六个观察面，每项按适当单位给分子/分母与未知数。总有效样本数不是所有维度的共同分母。区分“原生引用总数”和“出现引用的回答占比”；同一回答带五个链接仍只算一份回答命中。引用存在不代表肯定推荐；中性提及也不能替代推荐。

逐问题至少保留问题 ID、记录 ID、有效样本数、是否提及、是否推荐、原生来源采集完整性、URL 或未取得原因、相关原句和事实核对依据。原文太长可在报告摘录，完整正文留 JSON。回答缺失的问题写“未获得回答”，不能列入“品牌缺席”。

准确性部分逐项区分：

- 有当前可靠依据的冲突：列原句、事实来源和适用时间，说明错误对用户决策的影响。
- 只有用户资料的冲突：明确依据来自用户，建议确认资料公开页与版本。
- 没有依据：只写待核验，给具体缺少哪项事实。

三个优先行动按证据选择，不能按固定标题套所有品牌。例如价格被说错时交付一段明确的版本/价格说明和公开依据；移动端被误识别时交付支持平台与限制表；某购买场景缺席时交付该真实问题的答案及使用条件，不能为了提及率编造产品能力。

每条行动包含：优先级、问题/记录 ID、证据与影响、修改对象、负责角色、具体交付物、验收和复测条件。证据不足时，第一条可以是补采集而非改内容；已有两条实际问题时，第三条可补事实确认或复测设计，说明其性质。不要提出未经授权的发布、刷提及或固定增幅目标。

复测沿用原问题、语言/地区、联网模式、模型可见版本和上下文设置，记录新采集时间与每次 run_id。可建议同题分次采集，但在未运行之前不能填预期成功结果。分别比较提及、推荐和原生引用，标明样本变化，单次结果不外推全平台。
