同一篇文章，换一套版式，读完率会差一倍。差别通常不在好不好看，而在读者能不能一直知道自己在哪：读的是哪一章，这一段是结论还是过程，后面还有多长。

# 上篇 · 先做减法

## 01 一篇文章只留一个判断

写长文最容易犯的错，是把所有想说的话都放进去。读者不是来收集信息的，他是来找一个能带走的判断。所以第一件事不是排版，是删。

删的标准只有一条：**删掉之后，读者会不会误解上文。**会，就留下；不会，就还有删的余地。

- 删掉重复的解释，同一个意思只说一次
- 删掉自我介绍的段落，读者不关心过程
- 删掉没有结论的铺垫
  - 尤其是「让我们先来看看」这类过渡
  - 以及为了对称硬写的排比

删完之后，正文通常只剩原来的六成。这时候再谈版式，才有意义。

> TIP
>
> 先删后排。版式救不了一篇结构松散的文章，只会让松散更显眼。

> 读者记住的从来不是字数，是他合上文章之后还能复述的那一句话。

```fold 01 · 我删掉的第一段｜开场白是最贵的版面
第一版开头写了三百字，讲我为什么要写这篇文章。删掉之后，正文从第一个判断开始，读完率反而更高。读者不关心你为什么写，只关心他能拿走什么。开场白是最贵的版面，也是最容易删掉的部分。
```

## 02 版式是给读者的路标

版式不负责好看，负责回答三个问题：我在哪，这是什么，还要读多久。回答清楚了，读者才愿意继续往下滑。

1. 章首给编号，让位置可数
2. 小节用竖线，和章节区分开
3. 重点只加粗，不换颜色

这三条对应三种层级：章节、小节、句内强调。层级超过三层，读者就开始迷路。

| 层级 | 手段 | 频率 |
| --- | --- | --- |
| 章节 | 墨青页签 + 20px 标题 | 每 600–900 字 |
| 小节 | 3px 竖线 + 17px 标题 | 每章 ≤2 个 |
| 强调 | 墨色加粗 | 每段 1–2 处 |

> NOTE
>
> 表格只做对照，不做装饰。超过四列，就改成「条目 + 说明」两段式。

### 一处只放一个结构件

同一屏里，图、表、引文、提示块只出现一个。两个结构件挨在一起，读者的视线会先打架，再放弃。

![同一篇文章在不同字号下的阅读密度](/covers/preface.png)

*图 01｜同一篇文章，字号与行高不同时的阅读密度*

图是证据，不是气氛。截图就截全，别裁掉上下文；图注只说明这是什么，不抒情。

## 03 发布前，逐条过一遍

排版是手艺，手艺靠检查，不靠感觉。下面这张清单，每次发布前跑一遍，能挡掉八成问题。

> WARNING
>
> 不要用 &lt;details&gt; 做折叠。微信会把它剥成裸文字，展开语义直接消失。

> IMPORTANT
>
> 正文只认内联样式。class、id、&lt;style&gt; 在粘贴后都会失效，样式必须已经算好。

如果一定要在正文里放可交互的东西，只剩内联 SVG 加 SMIL 这一条路。渲染脚本里最关键的一步在这里：

```javascript
const kept = style
  .split(";")
  .filter((part) => !/^height\s*:/i.test(part));
```

这一步不做，`<svg>` 的高度动画会被一条 `height:auto` 压死。

> 「版式的最高目标不是被看见，是被忽略。读者应该记住内容，而不是记住你用了什么字体。」
>
> —— 一位做了十年纸刊的编辑

---

```fold 02 · 三次改版的记录｜三次改版，只动了三把尺子
第一版：正文 15px，行高 1.7。手机上每行四十多个字，密得喘不过气。第二版：字号加到 16px，行高 1.85，段距 18px。每行降到三十八字左右。第三版只改了一处：把小标题的字号和正文拉开 4px，层级立刻清楚。三次改版没有一次动颜色，动的是字号、行高、段距这三把尺子。
```

```fold 03 · 发布前检查表｜六条全过，再点发布
一、手机上 390px 宽预览，正文是否落在 36 到 42 字一行。二、标题只有两级，字号差是否大于 3px。三、每五到六段，是否有一张图或一个结构件，没有连续六段纯文字。四、图注是否不超过两行，编号是否连续。五、暗色模式下，有没有白底图、消失的线、读不清的字。六、粘进后台之后，样式有没有丢。六条全过，再点发布。
```

```end
这篇是排版样例，不是教程。真正的判断标准只有一个：你在手机上从头滑到尾，有没有哪一处让你想停下来喘口气。
```
