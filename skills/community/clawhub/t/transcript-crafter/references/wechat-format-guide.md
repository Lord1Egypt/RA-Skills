## 二、Markdown 元素使用规范

### 2.1 标题层级

| 层级 | 语法 | 使用规范 | 数量控制 |
|------|------|---------|---------|
| H1 | `# 标题` | 文章标题，20-28字，全文仅1个 | 1个 |
| H2 | `## 标题` | 主要段落/章节 | 3-5个 |
| H3 | `### 标题` | 子论点/补充说明/数据注释 | 谨慎使用，不超过H2数量 |
| H4-H6 | 不使用 | 访谈长文不需要过深层级 | 禁止 |

**标题格式要求**：
- H1 不加标点符号结尾
- H2 简洁有力，12-20字，可带判断性表述
- H3 陈述性，10-16字
- 标题之间不留空行（markdown-it 会正确渲染间距）

### 2.2 强调

| 元素 | 语法 | 使用场景 | 频率控制 |
|------|------|---------|---------|
| **加粗** | `**文字**` | 关键判断/核心数据/金句强调 | 每段最多1-2处 |
| *斜体* | `*文字*` | 英文术语/书名/次要强调 | 适度使用 |
| ~~删除线~~ | `~~文字~~` | 修正/对比场景 | 极少使用 |

**禁止**：
- 大面积加粗（超过一行）
- 连续多段加粗
- 加粗+斜体叠加（`***文字***`）
- 用加粗代替H2/H3

### 2.3 引用

```markdown
> 「AI竞赛不仅是算力竞赛，更是存储竞赛」—— 桑杰，美光CEO
```

**使用场景**：
- 专家原话（配合 quote_handling 参数）
- 关键数据引用
- 第三方观点呈现

**格式标准**：
- 原话用中文引号「」包裹（非双引号，兼容 anti-ai-rules.md）
- 署名格式：`—— 姓名，身份`
- 引用块内不加多余格式

### 2.4 行内代码

```markdown
`GPT-4o` `Python 3.12` `HBM3E` `CUDA 12`
```

**使用场景**：
- 具体产品名/型号/版本号
- 技术术语缩写
- 命令/函数名

**不用于**：普通中文术语（如"大模型"不用行内代码）

### 2.5 代码块

````markdown
```python
# 仅技术访谈中使用
model = AutoModel.from_pretrained("bert-base")
```
````

**使用场景**：仅技术人物访谈中保留代码片段
**非技术访谈**：不使用代码块

### 2.6 列表

```markdown
1. 第一步：明确问题边界
2. 第二步：收集基线数据
3. 第三步：设计对照实验
```

**使用场景**：
- HOWTO 实操步骤（practitioners-notebook 覆盖层）
- 方法论拆解

**禁止**：
- 用列表罗列观点（破坏叙事流）
- 超过5项的长列表
- 非实操场景使用有序列表

无序列表仅在"要点速览"类补充信息中使用，正文以段落叙事为主。

### 2.7 表格

```markdown
| 指标 | 2024 | 2025E | 变化 |
|------|------|-------|------|
| HBM营收 | 30亿 | 120亿 | +300% |
| DRAM CR3 | 92% | >90% | 稳定 |
```

**使用场景**：
- 数据对比/竞品分析
- 时间线数据变化
- 多维度指标呈现

**格式要求**：
- 列数 ≤ 5 列（手机屏幕适配）
- 表头简洁，2-4字
- 数据单位统一

### 2.8 图片

```markdown
![HBM3E内存芯片实物图](https://example.com/hbm3e.jpg)
```

**格式标准**：
- 使用标准 Markdown 图片语法
- alt 文字必须描述性（非空），rico-md 用其作图片说明
- 外部URL图片：rico-md 会自动处理
- 无可用图片时，用占位注释：`<!-- 📷 建议插入：{描述}，搜索关键词：{关键词} -->`

**图片使用原则**：
- 访谈长文非必须，有则加分
- 每篇最多2-3张，避免图多文少
- 数据图表优先于装饰性图片

### 2.9 链接

```markdown
[美光2025Q2财报](https://investors.micron.com/xxx)
```

**公众号限制**：公众号文章内链接不可点击跳转

**处理方式**：
- 保留 Markdown 链接语法（rico-md 会渲染，供编辑参考）
- 重要URL需在正文或脚注中以纯文本形式写出
- 数据来源链接按来源分级决定放置位置（详见第六节）

### 2.10 分割线

```markdown
---
```

**使用场景**：章节大转折时使用，一篇文章最多1-2处

## 三、公众号特有限制与规避

| 限制 | 规避方式 |
|------|---------|
| 无下划线渲染 | 用加粗替代强调，不使用 `<u>` 标签 |
| 外链不可点击 | 重要URL正文化，链接保留供编辑参考 |
| 图片需手动上传 | AI输出图片URL → 用户下载后上传公众号图床 |
| 数学公式可能丢失 | 简单公式用文本表达，复杂公式用图片替代 |
| HTML标签被过滤 | 不使用自定义HTML，纯Markdown输出 |
| 表格过宽溢出 | 列数 ≤ 5，rico-md 自动加横向滚动 |
| 字体不可控 | 依赖主题样式，不在Markdown中指定字体 |

## 四、格式适配检查清单

文章撰写完成后，按以下清单逐项检查并修正：

### 结构检查
- [ ] 仅1个H1，3-5个H2，H3数量 ≤ H2数量
- [ ] 无H4-H6
- [ ] 标题间无多余空行

### 格式检查
- [ ] 加粗每段 ≤ 2处，无大面积加粗
- [ ] 无下划线 `<u>` 标签
- [ ] 无自定义HTML标签
- [ ] 引用块内格式简洁，署名规范
- [ ] 行内代码仅用于产品名/版本号/技术术语
- [ ] 列表仅用于实操步骤，不超过5项
- [ ] 表格列数 ≤ 5

### 公众号兼容检查
- [ ] 重要URL已在正文中以纯文本出现
- [ ] 图片alt文字有描述性内容
- [ ] 无图片处有占位注释
- [ ] 数据来源链接集中在文末

### rico-md 导入检查
- [ ] Markdown 语法标准无错（可在 md.ricoui.com 直接粘贴验证）
- [ ] 已推荐对应主题（见映射表）
- [ ] 代码块标注了语言（如有）

## 五、文末固定格式

每篇文章末尾统一附加，按来源分级分类排列：

```markdown
---

**参考来源**

**官方文件**
- [来源标题](URL) — 简要说明

**权威报道**
- [来源标题](URL) — 简要说明

**行业研究**
- {机构名} {报告名} — 简要说明（无公开URL时用纯文字）

**其他来源**
- 来源描述 — 简要说明

*本文基于{访谈/会议}实录整理，增量信息已标注来源，实录观点已标注发言者。*
```

## 六、引用与链接规范

### 6.1 发言原话引用块

**判断标准**——哪些原话用 `>` 引用块：

| 用引用块 | 不用引用块（行内） |
|---------|-----------------|
| 金句/判断性原话（>15字） | 简短技术参数（<15字） |
| 颠覆认知/反常观点 | 架构描述/流程说明 |
| 有传播力的原话 | 过渡性/背景性原话 |
| 情绪型/人物性格型原话 | 数据陈述（"营收XX亿"） |

**引用块格式**：

```markdown
> 「我们早在2014至2015年前后就实现正向现金流，依靠自身营收自给自足。」—— 埃隆·马斯克，SpaceX CEO
```

- 原话用「」包裹
- 署名格式：`—— 姓名，身份`
- 引用块内不加多余格式

### 6.2 出处引用链接

按来源分级（详见 `tool-router.md`）决定链接策略：

| 来源分级 | 正文写法 | 是否附URL | URL位置 |
|---------|---------|----------|--------|
| Tier 1 官方 | `数据（[来源名](URL)）` | 必附 | 正文行内 |
| Tier 2 权威媒体 | `数据（[媒体名](URL)）` | 必附 | 正文行内 |
| Tier 3 行业研究 | `数据（据{机构}{报告名}）` | 有则附 | 正文行内或文末 |
| Tier 4 聚合/二手 | `数据（据{来源}报道）` | 选附 | 文末参考来源 |
| Tier 5 社区/推断 | `数据（行业观点认为）` | 不附 | 无 |

**正文链接密度控制**：每段最多1个行内链接，全文行内链接 ≤ 8个。避免链接过多破坏阅读流。

**示例**：

```markdown
SpaceX 2025年全年营收186.74亿美元（[S-1/A招股书](https://sec.gov/xxx)），其中Starlink业务营收113.9亿美元。

2026年HBM产能已售罄（据TrendForce 2026年HBM供需报告），DRAM紧缺态势预计延续至2028年。

Terafab全阶段投资上限1190亿美元（据[华尔街日报](https://wsj.com/xxx)报道）。

行业观点认为，太空数据中心将在2030年前实现商业化部署。
```

## 七、来源导语格式

### 7.1 位置与格式

来源导语放在 **H1 标题之后、第一个 H2 之前**，用斜体+分割线与正文区分：

```markdown
# 文章标题

*来源导读：{导语内容，200-400字}*

---

## 第一个H2段落
```

### 7.2 不同来源类型的导语要素

| 来源类型 | 导语核心要素 | 字数 | 示例开头 |
|---------|------------|------|---------|
| 访谈/对话 | 5W1H：谁+什么场合+什么时候+为什么重要 | 200-400字 | "2026年6月5日，马斯克在摩根大通投资者大会上..." |
| 会议/圆桌 | 会议背景+议题+参与者分量 | 200-400字 | "2026年SNEC大会太空能源分论坛上..." |
| 学术论文 | 核心论点+研究价值+发表背景 | 150-300字 | "斯坦福大学2026年3月发表在Nature上的论文指出..." |
| 公众号/网页 | 来源+核心观点+为什么值得深读 | 100-200字 | "知名科技博主XX近日发文分析..." |

### 7.3 人设适配

导语语气必须跟随人设，不是千篇一律的"本文基于XX"：

| 人设 | 导语风格 | 示例 |
|------|---------|------|
| curious-explorer | 口语化发现感 | "我最近看到一个很有意思的访谈，马斯克在摩根大通的大会上聊了整整两小时..." |
| industry-observer | 专业简明 | "2026年6月5日，SpaceX CEO马斯克在摩根大通投资者大会上系统阐述了上市战略..." |
| cold-analyst | 数据先行 | "SpaceX S-1招股书披露2025年营收186.74亿美元，马斯克在摩根大通专场访谈中首次公开回应上市逻辑..." |
| sharp-journalist | 冲突切入 | "一家早已盈利的公司为什么要上市？马斯克在摩根大通350位顶级投资者面前给出了一个出人意料的答案..." |
| midnight-friend | 温暖叙事 | "上周有一场访谈让我感触很深，马斯克和他母亲同时出现在摩根大通的舞台上..." |
| warm-editor | 人文关怀 | "当梅耶·马斯克站在350位投资者面前对儿子说出'我无比爱你'时，这场关于太空的商业对话有了不一样的温度..." |
| humor-storyteller | 轻松有趣 | "马斯克又搞了个大新闻——不过这次不是发推特，而是在摩根大通的大会上正儿八经地聊了两个小时..." |
| tech-coder | 技术切入 | "SpaceX自研的三款定制芯片已完成流片，这个细节是马斯克在摩根大通投资者大会上透露的..." |
| khazix-writer | 好奇+口语 | "我前两天刷到一个访谈，马斯克在摩根大通的大会上说了好多有意思的东西，关于太空的、关于芯片的、关于为什么要上市的，我整理了一下，分享给你..." |

### 7.4 导语撰写检查

- [ ] 包含来源类型关键信息（访谈=5W1H，论文=论点+价值，会议=背景+议题）
- [ ] 语气与人设匹配
- [ ] 字数在规定范围内
- [ ] 用斜体格式，与正文视觉区分
- [ ] 不与H1标题内容重复
