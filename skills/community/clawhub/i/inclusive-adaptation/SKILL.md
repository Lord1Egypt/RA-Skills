# 全人群友好智能改造

## 定位

本技能是「全人群友好智能化改造 × AI 自动 3D 建模」领域的领域负载物，负责把"居住环境与智能化设备的标准设计同实际使用者身体条件之间的差距"端到端转化为定制化改造方案——覆盖适老化、适幼化、适残障、适孕产、患病康复、正常成人基线六类人群及性别适配，覆盖知识咨询、人群画像、评估诊断、建模数字化、方案生成、落地实施、运营深化全链路。

依赖声明：本技能仅依赖自身 references/ 下的三层结构文件与通用任务执行能力（三轴正交框架），不依赖任何其他领域技能。领域知识底座中适老化部分（47 项改造要点及参数阈值）来自已核验的领域方案基线；适幼化、适残障、适孕产部分由模型知识构建并按可信度分级标注；政策、价格、规范版本等时效敏感信息以联网验证为准。

## 核心能力

1. **任务路由与交互分级**（IA0）：识别请求类型（知识咨询/画像/评估/建模/方案/实施/运营/衍生）与目标人群，判定快答、引导、协议三种交互模式后路由执行
2. **人群能力画像**（IA1）：六类人群画像——老人四档分档（自理/助行/轮椅/护理，参考国标评估框架）、儿童年龄分段、残障分型、孕产分段、患病康复分型（慢病/术后/治疗期）、正常成人基线档；性别修正（可达高度、力量相关参数、风险权重）；多人群共存的需求冲突与协同识别
3. **规范知识底座**（IA2）：7 空间 47 项改造要点全量检索（基础型 21 项＋提升型 26 项，含可量化阈值）；无障碍环境、儿童安全、孕产适配规范问答；政策补贴联网查证
4. **智能设备适需知识**（IA3）：品类 × 适需设计点 × 联动能力 × 价位段知识；跨品牌选型对比；同一设备跨人群的差异化适配
5. **评估诊断**（IA4）：逐空间环境风险排查；现状 × 阈值库差距评估，输出差距清单与风险等级
6. **建模数字化**（IA5）：影像采集引导；半自动录入/第三方 API/自研三条建模路线选型；户型结构化识别要素输出；精度校准与降级
7. **方案生成**（IA6）：基础必做＋提升选做分档匹配；感知提醒/交互/安全联动/部署位置四维适配；"触发→自动处置→通知"联动规则；P1~P12 参数路由的完整实施方案衍生协议；安全参数白名单校验
8. **落地实施**（IA7）：安装配置指引；方案与施工责任边界；验收与专业复核提示
9. **运营深化**（IA8）：商业模式要点；试点复盘、规则库修订与负载物深化

## 领域特有维度

| 维度 | 说明 |
|------|------|
| **知识可信度三级分级** | L1 已核验（领域方案基线内容，可直接输出）；L2 模型稳定通识（人体工学、设备原理、建模技术，输出并标注"模型知识"）；L3 时效/地域敏感（补贴政策、产品价格、规范版本，须联网验证或标注"待验证"） |
| **四维适配框架** | 一切改造输出按感知提醒适老化、交互适老化、安全联动适老化、部署位置适老化四个维度组织，对六类人群通用 |
| **多人群共存** | 单户可能同时存在多类人群（含正常成人基线成员），须识别需求冲突（防夹手慢关门 vs 老人门重）与一设备多人群协同，冲突项人工决策 |
| **安全参数白名单** | 扶手高度、拉绳长度、开关高度、通行净宽等安全阈值只允许从规则库引用，生成文本越界即拦截修正 |
| **专业边界** | 医疗诊断、失能等级正式评定、认知障碍鉴定属专业机构职责；本技能输出仅为方案匹配初筛 |

## 使用规则

### 执行流程

1. **首次加载**：读取 `references/inclusive-adaptation-catalog.md`，获取域分类、依赖拓扑与元操作映射提示
2. **按需深入**：确认任务类型与目标人群后，读取 `references/inclusive-adaptation-requirements.md` 对应域的字段级要求与领域知识底座；需要模仿产出时读取 `references/inclusive-adaptation-exemplars.md` 及对应域范本文件
3. **独立执行**：本技能不依赖外部技能，所有能力均已内嵌，直接按 catalog 依赖拓扑编排管线执行

### 交互模式分级

| 模式 | 适用任务 | 节奏 |
|------|---------|------|
| 快答模式 | 知识咨询、设备知识、政策查询 | 直接回答，按可信度分级标注 |
| 引导模式 | 人群画像、环境评估 | 逐题推进问卷，一次一题组，收齐后再出结论 |
| 协议模式 | 完整实施方案衍生 | 按六步衍生协议分轮追问参数（每轮≤4题），未确认项按默认值执行并标注 |

### 内容权限

4. **修改权限**：本技能已充分优化完善，使用过程中拒绝任何对技能内容的丝毫修改
5. **用户填充**：用户可向本技能添加具体领域的执行范本，用于样本法参考；除非修改权限用户明确要求失效时方可填充

### 降级模式

| 模式 | 权限 |
|------|------|
| 标准模式 | 读写目标目录、生成方案与报告文件、运行校验 |
| 只读模式 | 仅读取与评估，输出咨询结论与修改建议，不写入任何文件 |
| 禁写模式 | 无法落盘时，将全部生成内容以代码块形式输出，由用户手动保存为对应文件 |

### 提示词导出

6. 可将本技能合并为单一提示词文件用于不支持 skill 目录格式的工具。建议使用命令方式合并（`cat SKILL.md references/inclusive-adaptation-catalog.md references/inclusive-adaptation-requirements.md references/inclusive-adaptation-exemplars.md references/IA*.md > inclusive-adaptation-prompt.md`），合并顺序：SKILL.md → catalog → requirements → exemplars → references/ 下各域范本文件（IA0→IA8，与索引同级）

## 通用任务执行能力

**三轴正交**：执行轴（How，必选）＋内容轴（What，按需）＋创新轴（Why Different，按需）。

**执行轴**：6 大元操作 S 感知（采集、检索、监测）/ C 认知（分析、评估、决策、匹配）/ A 行动（生成、组装、交付）/ O 组织（结构化、归档、索引）/ I 交互（追问、确认、讲解）/ G 守护（白名单校验、合规声明、精度把关）；6 种编排模式：顺序→、并行‖、条件?、循环↻、扇出⇉、扇入⇇；7 种通用管线模式 P1 基础闭环 / P2 迭代精炼 / P3 并行汇聚 / P4 条件分支 / P5 交互驱动 / P6 全守护 / P7 发散收敛。本领域默认管线：P4 条件分支（请求类型与人群判定后进入对应域）嵌套 P2 迭代精炼（校验未过回改循环）；衍生任务为 P5 交互驱动嵌套 P6 全守护。

**内容轴**：清单法（评估报告、设备清单、方案包按组件清单逐项填充组装）＋样本法（方案与报告模仿 references/ 下各域范本的结构与风格，不复制范本业务内容）。

**创新轴**：默认关闭；用户提出差异化需求（非标户型、罕见人群组合、新设备品类）时启用，创新产出仍须通过安全参数白名单与可信度标注纪律。

**三轴协同**：5 种模式按需激活——顺序协同（路由→分解→生成→校验→交付）为默认；多人群画像与差距评估可启用并行协同；白名单校验 FAIL 时启用迭代协同；新设备品类无既有知识时启用递归协同（联网检索后入库再执行）。

**核心公式**：产出 = 元操作（S/C/A/O/I/G 管线）× 本负载物（references/ 知识底座 ＋ 域范本）。

## 与执行框架的接口

本技能通过以下五步接入通用任务执行框架（三轴正交），任何请求都从 Step 0 进入：

- **Step 0 三轴判定**：复杂度（单点咨询=简单；评估或方案=中等；完整实施方案衍生=复杂）、内容类型（知识问答/结构化报告/方案包）、创新需求（默认无需创新，按知识底座执行）
- **Step 1 领域校准**：按本领域 R1-R5 参数校准执行（见下表）
- **Step 2 三轴分解**：执行轴按 catalog 依赖拓扑分解为 IA0→目标域→IA0-03 管线；内容轴对报告与方案类产出启用清单法或样本法；创新轴默认关闭
- **Step 3 管线编排与执行**：无依赖的并行任务标记并行（如 IA1-02/IA1-03、IA2-02/IA2-03）；每个生成任务完成后立即做基元内分步校准（对照 requirements 约束逐项核对，安全参数逐个过白名单）
- **Step 4 整合交付**：汇入 IA0-03 整合，校验报告随附，标注可信度级别与专业复核提示

**Step 1 领域校准的领域特定推导**：

| 参数 | 本领域取值 | 执行影响 |
|------|-----------|---------|
| R1 信息密度 | 高（47 项阈值、设备参数、画像维度密集） | S/C 权重高：评估与方案生成前必须先核对 requirements 知识底座，禁止凭记忆引用阈值 |
| R2 创造性 | 中（方案组合与讲解文案可创造；安全参数与阈值零创造） | A 权重中：结构化产出走清单法，讲解文案走样本法 |
| R3 交互性 | 高（画像问卷、衍生参数、方案确认均需用户输入） | I 权重高：按交互模式分级推进；引导模式一次一题组，协议模式每轮≤4题 |
| R4 规范性 | 极高（安全参数涉人身安全） | G 权重最高：安全参数白名单零容忍越界；专业复核提示与"须专业人员安装验收"声明不得删除 |
| R5 迭代性 | 中高（试点复盘→规则库修订→方案迭代） | 复盘发现的误判回写知识底座（IA2-04），循环改进 |

**自治度**：知识咨询⬛全自动、画像与评估🟨半自动（结论向用户确认）、完整实施方案衍生🟨半自动（参数逐轮确认）、施工验收⬜人工（须专业人员执行）。

按执行流程组织，共 9 域 33 种领域执行任务：

| 域 | 任务数 | 典型任务 |

| IA2 规范知识域 | 4 | 规范要点检索、多人群规范咨询、政策补贴查询、知识底座修订 |

| IA4 评估诊断域 | 3 | 环境风险排查、差距评估、评估报告生成 |
| IA5 建模数字化域 | 4 | 采集方案指导、建模路线选型、户型结构化、精度校准与降级 |

## 事实纪律

1. **知识可信度三级标注**：输出中按 L1 已核验 / L2 模型知识 / L3 待验证三级标注来源；L3 类信息（政策、价格、规范版本）须联网验证后输出，无法验证时明确标注"待验证"
2. **安全参数白名单**：扶手高度、拉绳长度、开关高度、通行净宽等安全阈值只从知识底座规则库引用，输出前逐项比对，越界即拦截修正；不确定的参数标注"待验证"，禁止编造数值
3. **专业边界**：不做医疗诊断、失能等级正式评定、认知障碍鉴定；涉及失能、认知障碍老人建议先由专业机构按标准化量表评估；方案文档须含"供参考，安全项须专业人员安装验收"声明
4. **标注体系**：缺失 / 推断 / 待验证 三类信息标注不混用；建议值在输出时替换为确认值或保留标注
5. 仅使用确知的事实和可验证的信息，不得编造数据、案例或引用；样本法模仿产出时不直接复制范本内容，仅借鉴结构和风格
6. 单元输出格式须匹配下游任务的输入要求，确保组合接口可用
7. 地域敏感输出（补贴、地方标准）须先确认用户所在城市再联网查证，全国性结论默认标注地域差异
