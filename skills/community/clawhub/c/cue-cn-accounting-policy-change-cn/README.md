# 会计政策变更·逐条挂源

给一份财报或公告，把**会计政策变更的披露**读成一张**每条都能回到原句**的登记表：会计政策变更概况、变更性质与依据、变更前后会计处理、追溯调整与累积影响、不切实可行的处理。

会计政策变更是附注里最容易被讲成故事的一块：既然改了政策，多半是为了更公允；既然有累积影响数，多半影响利润。可披露里能确认的只有「改了什么、依据哪一号文件、前后分别怎么算、累积影响多少、追不追溯」——变更合不合理、有没有调节利润的动机、往后一期会增厚多少，都不是附注能回答的，也不是本件该回答的。

性质类别只认披露归的那一类，不按变更内容推断；变更依据只认原句里的准则号、解释号或文件名；累积影响数与比较报表调整照抄原句，跨单位按元对平；追溯调整与未来适用法按时披露的方法登记，不按性质推。

本件不评变更合理性、不判盈余管理、不测算利润影响，不给评级与目标价。

## 一、零依赖三分钟上手

只装 Python 3，不给任何数据文件，也能跑出一份完整合规的成品，看它长什么样、判据怎么打：

```bash
python3 scripts/check_policy_change.py --demo
```

把这份样例存下来再跑一遍机检——它会照七节形制、三元组与红线逐条判，应当零发条：

```bash
python3 scripts/check_policy_change.py --demo > 样例政策变更稿.md
python3 scripts/check_policy_change.py 样例政策变更稿.md   # 打印「结论：五道全过（零发条）」，退 0
```

接着换成你自己那份稿子：

```bash
python3 scripts/check_policy_change.py 你的政策变更稿.md
```

退码语义：`0` 五道全过｜`1` 有发条（逐条打印 `码 行号 说明`，并汇总「发条码：…」）｜`2` 用法错（没给稿子路径，也没给 `--demo`／`--selftest`）｜`3` 读不到文件或空稿。

拿不到成品时，从原文开始的三步：

1. **定主体与报告期**，拿到年报或半年报原文（附注「重要会计政策变更」「会计估计变更」、变更公告三处）。
2. **每节抄事实，连原句一起抄**：一条 = 一行，行末挂 `「原句」〔锚：页/表〕[S#]`；披露没写的就写 `未取到：项名`，不留空、不借「准则要求追溯调整」补。
3. **跑一遍自检**，红一条改一条：

```bash
python3 scripts/check_policy_change.py --selftest   # 内置夹具自检（档数与结果以末行现报为准）
```

三档一起跑（自测→好样→坏样，坏样注入必先断言落地）：

```bash
bash scripts/fixtures/run_fixtures.sh
```

## 二、五道机检在管什么

| 码 | 名称 | 判什么 | 最常拦住的情况 | 现状 |
|---|---|---|---|---|
| `PC-STRUCT` | 形制 | 头部四件自标逐字在位、`主体：`／`报告期：` 行首裸行在场非空、七节齐且按序、前五节各至少一条发现行、节内只许 `- ` 行；认不出的节标题与多出同名节记 stray | 把 `主体：` 写成 `- 主体：`；某节只有散文没有发现行；节名改了个字就整节认不出 | 已落字 |
| `PC-QUOTE` | 原句与锚 | 发现行以「」原句＋〔锚：…〕＋`[S#]` 收尾且三元组落在行末；来源行带可点 URL 与检索日；引用的编号须已登记 | 只写「执行新收入准则」没抄原句；正文引用了 `[S3]` 而来源节没有这一号 | 已落字 |
| `PC-CHANGE` | 性质与依据只认原句 | 登记值写了某类别（会计政策变更／会计估计变更／两者难以区分）而同行原句没有该类别即发；登记两类而原句只写一类也发；把估计变更登记成政策变更（或反之）另发；登记了依据而原句没有准则号／解释号／文件名即发；全稿一条性质都没登记，在第一处发一次 | 原句只说「本公司变更了收入确认时点」，登记值写成「会计政策变更」；用「法定变更」顶替性质类别 | 已落字 |
| `PC-RETRO` | 追溯与累积影响只认原句 | 累积影响数、比较报表调整的金额在原句里找不到可折算相等的数即发（`1,200.00 万元` ↔ `12,000,000.00 元` 算相等）；追溯调整与未来适用法写反即发；「不切实可行：否」却登记替代处理、「是」却没有替代处理即发 | 累积影响数自己轧出来填进去；原句写「未来适用法」，登记值写「追溯调整」 | 已落字 |
| `PC-LINE` | 红线 | 变更合理性评价（变更合理／有利于／有助于提升／恰当反映）、盈余管理判断（盈余管理／调节利润／利润平滑／操纵利润／粉饰报表）、利润影响测算（预计影响／增厚利润／预计增利）、评级与目标价，零命中；引文先洗掉，紧跟「数／额」的名词术语（预计影响数）与紧邻否定词罩着的边界声明都不算踩线 | 写「本次变更预计影响 2026 年净利润」；写「该变更有利于提升毛利率」；把「预计影响数」这种照抄披露的金额名也判红 | 已落字 |

五道现读全已落字；`--selftest` 逐档打印每档结论，末行自己报 `自测档数=N｜不合=0｜不可判=0`（**N 以现跑为准，本文不复述数字**）。夹具分类：好样——零发条；坏样——形制、锚、性质两类、追溯金额、不切实可行、红线自推、自指主语套名词后缀、非自指（管理层）主语套名词后缀、本报告主语套名词后缀、主语＋状语拉开距离、非追溯节登记金额在引文里找不到；反证——项名带类别词、类别词只在引文里、万元与元折算相等、术语「预计影响数」、术语「预计影响金额」、纯术语打头「预计影响数额」。反证档专验「照抄披露的写法不该误判」：类别词只出现在引文里、或项名带类别词而登记值只写变更方式时不该发，万元与元折算相等不该发，紧跟「数／额」的名词术语也不算自推。

## 三、四条红线（这件的立身之本）

1. **性质类别只认披露归的那一类。** 改了收入确认时点不等于会计政策变更——两者在追溯处理上完全不同：政策变更原则追溯调整，估计变更适用未来适用法。原句没归类别的，正确写法是性质未取到，而不是按变更内容替披露归。
2. **依据只认原句里的文号或文件名。** 「依据新准则」「按最新规定」不算依据；原句里要有准则第 N 号／解释第 N 号／财会〔YYYY〕N 号／《…》之一，没有就写依据未取到。
3. **累积影响数与比较报表调整照抄，不互轧。** 两个数各自挂各自的原句；金额跨单位按元对平（`1,200.00 万元` 就是 `12,000,000.00 元`），折算后对不上就是没照抄。判「不切实可行：否」就不该有替代处理方法，判「是」就该有——三件套要自洽。
4. **不替披露判断、不往前推一期。** 变更合不合理、有没有盈余管理动机，一律 `[待人工]`；利润影响只能照抄披露的数，「预计影响」「增厚利润」这类往前推一期的写法即发。只有「预计影响数」这种紧跟「数／额」的名词术语不判——那是附注里的金额名称，和「累积影响数」同形。

## 四、数据通道

发现先行，匿名取 live 目录，拿到 `routing` 后再连接发 `tools/list`，以现场返回为准，不硬编码工具名与工具数：

```bash
curl -sS https://cuecue.cn/api/mcp-catalog -o /tmp/mcp-catalog.json
python3 -c "import json;d=json.load(open('/tmp/mcp-catalog.json'));print(d.get('routing') or d)"
# 拿到 routing 后，带 token 发 tools/list：
curl -sS -X POST "$ROUTING_URL" -H "Authorization: Bearer $CUE_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

- **原文腿**：年报附注·重要会计政策变更与会计估计变更、变更公告、追溯调整表的原文走数据腿；该域是否开放、是否实时，以 catalog 返回为准，本件不承诺。
- **正文腿**：附注常夹在几百页 PDF 里（政策变更明细表、累积影响数表、追溯调整表），长附件与扫描件交 `cue-omni-reader` 解析——先取大纲，再按节取用；计费与可用性以服务端返回为准。
- **深研**：`cue-research` 是独立入口（自带运行脚本），凭据同一把 key。
- 配置页只给指针、不复述开通步骤：数据腿 <https://cuecue.cn/hub/mcp>；解析腿 <https://cuecue.cn/hub/omni-reader>；取 key <https://cuecue.cn/hub/api-key>。

不装通道也能跑：只拿用户直供的附注截图或变更公告，五节骨架照样出，代价是看不到交易所原文那一路、累积影响数表与追溯调整表多半缺页，只能登记材料里那几行，证据密度降为单份材料且没有出处可回查。

本件不发请求、不代付费，消耗以服务端返回为准。

## 五、本件不做什么

| 不做 | 谁来做／怎么办 |
|---|---|
| 评变更合不合理、该不该做、是否更真实公允 | 一律 `[待人工]`；本件只登记披露怎么写的 |
| 判盈余管理动机（调节利润／利润平滑／粉饰报表） | 一律 `[待人工]`；动机判断要有披露之外的证据 |
| 测算利润影响、往前推一期（预计影响／增厚利润／预计增利） | 只照抄披露给的累积影响数与比较报表调整，不自己推 |
| 给评级、目标价、目标市值、高低估 | 一律 `[待人工]`；本件不构成投资建议 |
| 认定某项变更属于政策变更还是估计变更 | 披露归哪一类就登记哪一类；没归类别的写未取到 |
| 重算递延所得税、合并范围、每股收益 | `cn-deferred-tax-cn`／`cn-consolidation-scope-cn`／`cn-eps-cn` 各自管；本件只挂涉及的那条原句 |
| 判断前期差错的性质与更正 | `cn-accounting-error-correction-cn`；本件只登记政策变更这一侧 |

## 六、和另外几枚包怎么分

| 你手上是 | 用哪枚 |
|---|---|
| 政策变更的性质与依据、前后处理、累积影响与追溯、不切实可行 | **本件** |
| 前期差错的性质、更正与重述 | `cn-accounting-error-correction-cn` |
| 递延所得税的确认、计量与转回 | `cn-deferred-tax-cn` |
| 合并范围与合并报表口径 | `cn-consolidation-scope-cn` |
| 基本与稀释每股收益、加权平均股数 | `cn-eps-cn` |
| 会计估计变更本身的估计参数与敏感性 | 一律 `[待人工]`；本件只登记披露写的估计变更类别与影响 |

本件只管**政策变更这一块**：变更引起的递延所得税调整，本件只挂披露原句，暂时性差异与税率归 `cn-deferred-tax-cn`；变更涉及合并范围变动的，范围归 `cn-consolidation-scope-cn`；追溯重述对每股收益的影响，本件只登记披露给的数，重算归 `cn-eps-cn`。同一家公司既有政策变更又有差错更正时，两件各管各的节，不互相代填。
