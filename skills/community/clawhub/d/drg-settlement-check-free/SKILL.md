# 医保结算清单与DRG入组核对（免费）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：财务、出纳等岗位在**每月结账 / 对账 / 盘点**这类固定节点上，
必须把这张表核一遍才能往下走。

**这张表会逐项核对什么**：医保结算清单与DRG入组核对表的逐行算术、合计勾稽、重复与空缺检测。

每条结论都带**原文行号与出处**，可被第三方用同一口径复算；
材料不足时**不给结论**，会明确列出还缺什么。

## 常见错法（这张表里真的会有人这么填）

1. **主要诊断选错，入组跟着错**：把次要诊断 / 症状性诊断当主要诊断填（例如用「肺部感染」
   代替「急性阑尾炎伴穿孔」），或者编码与名称对不上（编码写 I50.900、名称还是上一份病例的）。
   主要诊断是 DRG 入组的第一入口，选错就会进到权重完全不同的组：轻则少拿钱，
   重则被医保局判成"高套分组"追回并扣分。分不清哪条该作主诊断时，先找病案室按主诊断选择规则定，
   再重新入组。
2. **手术操作漏填**：做了手术却没在清单里填操作编码 / 名称（或者只填了名称、编码空着）。
   手术操作是外科 DRG 入组的关键要素，漏填的直接后果是**入不了外科组**、掉进保守治疗组，
   权重差一大截。核对时把手术记录与操作编码逐条对一遍，别只看诊断。
3. **费用明细与结算清单口径不一致**：清单上的费用总额、医保支付金额、个人自付三格对不上
   （个人自付 ≠ 费用总额 − 医保支付金额），或者合计行与明细行对不上 —— 明细改了、合计没跟着改。
   最常见的原因是医保支付金额取错口径：把个人账户支付、大病保险、医疗救助也算进了基金支付。
   本工具会把这三格的复算逐行打出来，对不上就报。
4. **高低倍率病例没单独处理**：病例费用远超或远低于 DRG 支付标准（一般看偏离 ±50% 甚至更多）时，
   仍然按 DRG 支付标准结算。高倍率病例通常要按项目付费 / 特病单议 / 按比例分担，
   低倍率病例通常按实际费用结算或折算点数 —— 一律按标准拨付，不是被拒付就是白干。
   核对时先把偏离参考区间的病例挑出来，再按本地政策走单独流程。
5. **「个人自付」与「个人自费」混用**：个人自付（医保目录内、按比例由个人负担的部分）与
   个人自费（医保目录外、全额由个人负担的部分）是两列，口径和用途都不同。把自费填进自付列，
   或者两列填同一个数，勾稽式看着闭合，实际上把患者该自付的钱算错了 ——
   患者投诉与医保局对账都会找上门。填之前先确认这一列取的是哪个字段。

## 需要完整档时（可选）

本免费版是**完整可用的核心产出**，本版本**不包含**下面这些项：

- DRG 组代码为空或含占位符提示（未入组）
- 权重超出参考区间（0~10）提示
- 医保支付金额大于费用总额提示
- 同一病历号重复入组提示
- 高低倍率病例（费用总额偏离 DRG 支付标准 ±50%）提示

同名工具的**完整档**是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别**就是上面这些，没有别的**。

## 边界（请务必知道）

本工具**不做**引擎 `CHECKS_OUT_OF_SCOPE` 里列的那些判断；
材料不足时**不给结论**，也不会输出「未发现问题」。
