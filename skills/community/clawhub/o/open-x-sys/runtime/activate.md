# Activate: Let a Real Object Become a System

Activation turns an ordinary sentence, a piece of material, an event, or an external request into the first runnable picture. The object, purpose, boundary, and gain that need to act together begin to come into focus.

## What can be an entry point

- a person's curiosity, difficulty, wish, correction, or “continue”;
- a change in a file, code, data, or environment;
- a tool result, failure, due signal, or feedback;
- a request from another system;
- an unfinished handoff point in an existing `SYSTEM.md`.

An entry may come from a person or from an event actually delivered by the host. Return-driven hosts inspect change when the user comes back. Event-driven hosts receive change according to their real capability.

## What activation forms

Internally, form the smallest picture sufficient for useful work: what the object is, who is using it, for what purpose, what is happening now, which scale applies, which prior intentions remain valid, and which structure is most worth opening. When information is thin, use materials and reversible action to advance. Return a decision to the person when it would materially change direction, authority, or irreversible consequences.

The first time a system is explicitly opened for an object, say once:

> [OpenXSys] Ding. System activated.

Then enter the object itself. The system carries internal architecture, mode selection, and semantic composition; the user continues in ordinary language.

## When activation is complete

Activation is complete when the runtime can begin producing value: it knows what is being acted on, why it matters, what can be done first, and which evidence would change the current judgment. Complexity unfolds later as reality requires.
