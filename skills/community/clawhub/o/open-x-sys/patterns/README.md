# The pattern library

> **When to read**: Loops, X-ray or Leverage has found a structure that looks familiar; the person says "it's a flywheel" or "it's a vicious circle" and you need to check; or you are about to put a pattern's name in a reveal.

Many reveals are the moment someone recognizes a known pattern in their own situation: "this is the thing that happens to every growing team", "we are doing exactly what those two companies did to each other". A named pattern gives the person a handle they can keep and reuse.

A pattern is a recurring structure of cause and effect that produces a recognizable behavior over time. Each page states its **source**, **how to recognize it**, and **where it usually breaks**.

## The ten patterns

| Pattern | In one line | Typical behavior over time |
|---|---|---|
| [Flywheel](flywheel.md) | Several steps in a circle, each making the next easier | Slow start, then accelerating momentum |
| [Network effect](network_effect.md) | Each user makes the thing more valuable to the others | Hard to start, then self-reinforcing; winner tends to take most |
| [Compounding](compounding.md) | Growth in proportion to what has already accumulated | Flat for a long time, then steep |
| [Success to the successful](success_to_the_successful.md) | The early leader is given more, so leads more | Two paths diverge from a small initial difference |
| [Limits to growth](limits_to_growth.md) | A growth process runs into something that slows it | Growth, then a plateau or decline despite more effort |
| [Fixes that fail](fixes_that_fail.md) | A quick fix whose delayed side effect brings the problem back | Relief, then a worse return, repeatedly |
| [Shifting the burden](shifting_the_burden.md) | A symptom-relief that weakens the real solution | Growing dependence on the quick fix |
| [Escalation](escalation.md) | Two parties each responding to the other's last move | Both sides spending more and more for no relative gain |
| [Tragedy of the commons](tragedy_of_the_commons.md) | Each gains from using a shared resource; all bear the cost | Rising total use, then the resource degrades |
| [The moving bottleneck](moving_bottleneck.md) | Relieving the constraint moves it somewhere else | A jump in output, then a new stall in a new place |

## Naming a pattern honestly

- **The structure must really be there.** A pattern is a specific set of causal links. Name it only when you can point to each link in this subject, with evidence. A resemblance in the story is not enough.
- **A name is not an explanation.** "It is a flywheel" becomes a finding only when each turn is shown: what causes what, through which mechanism, and how strongly.
- **Say where it usually breaks.** Every pattern has typical failure points and typical places to intervene. They are the useful part.
- **Say what does not fit.** Real systems are rarely a pure case. State where this subject departs from the textbook form.
- **Several patterns can be at work together.** Growth by a flywheel that is approaching a limit is two patterns, and the interesting question is which one dominates now.
- **Use the person's words.** If the pattern has a name in the person's language or field, use that name and mention the standard one.

## Patterns and methods

- **Loops** finds the feedback structure and checks it against these pages.
- **X-ray** reaches a pattern at its "structure" level.
- **Leverage** uses each pattern's known intervention points as candidates, then ranks them for this system.
- **What-if** uses the pattern's typical behavior over time as a first projection, then corrects it for this subject.
- **Invert** asks how the pattern's usual failure would show up here.

## Adding a pattern

The library is deliberately small. New patterns join through the contribution ladder with a source, a way to recognize it, where it breaks, and real cases. A person's own recurring patterns can be recorded in their system.
