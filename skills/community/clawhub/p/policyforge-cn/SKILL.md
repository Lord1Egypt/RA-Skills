# PolicyForge 政策专报智研

把「政策原文检索 → 帽子体系 → 骨架 → 正文 → 公文格式 Word → 视觉校验」六段链路固化成可照做的流程，让只有一句主题的政策专报，在交付时同时具备可回溯的依据、可逐条打勾的质量门槛和可直接报送的 Word 版式。

## 这是什么

- **解决的问题**：任务下达时往往只有一句主题（“写一篇某条线业务推进的专报”），既没有结构，也说不清该引哪份文件。大量返工不是文笔问题，而是**先搭骨架、后凑依据**造成的错位——帽子挂不上去，章节对不上文件，最后整篇推倒。本技能把顺序倒过来：依据决定帽子，帽子决定结构，结构决定篇幅。
- **产出物形态**：一份公文格式 `.docx` 主件（A4、仿宋三号、行距固定值、带页码与附表），加三份配套附件——《政策依据清单》《占位符清单》《校验记录》。
- **和“通用大模型直接问”的区别**：
  1. 每条引用必须落到“文号 / 发布日 / 发布机关 / 官方链接”四元组，拿不到就进待核清单，不生成看起来像的条款句；
  2. 结构由帽子体系反推，主轴线取政策与业务的分类维度，不按行政区划铺开；
  3. 业务数据一律留红色占位符并附取数指引，绝不编造数字；
  4. 交付前必须完成 Word → PDF → PNG 的抽页目视校验，未看过的 `.docx` 只算草稿。
- **为什么值得固化成流程**：这类材料跨条线高频复用，同一套帽子与骨架换个业务线即可重跑；把检索口径、结构判据、版式参数与验收清单一次定死，比每次重新试错省得多。
- **适用对象**：政府与事业单位办公室文字岗、国企与金融机构综合研究岗、政策研究员，以及需要替领导起草材料的业务条线人员。

## 适用场景

1. 我要写一篇某某业务推进情况的专报，领导只给了主题，没说分几节、按什么维度分。
2. 我要把材料扣上政策帽子，但不确定该引哪一层文件、一层引几份才算够。
3. 我要一份能直接复制进正文的逐字原文摘录，不要“文件强调了这项工作的重要性”这种转述。
4. 我要按业务线而不是按地区分章，可手里拿到的数据偏偏只有分地区的。
5. 我要一份版式合规的 Word，字体、字号、行距、页码都要对，拿去就能打印报送。
6. 我要在报送前自查：哪些引用还没核到文号，哪些数字还是空的。
7. 我要把一份已经写好的汇报材料改成专报结构，事实保留、骨架重排。
8. 我要给新同事一套可照做的写作流程，而不是一堆口口相传的经验。

以上场景的共同点：**输入信息不完整，输出必须正式**。流程因此设计成“先补齐依据，再补数据”，缺料一律以占位符和待核清单显式落地，而不是靠推测填空。

## 何时不要使用

- 手上没有任何一手材料，只想让模型"发挥"政策判断：先去 `references/policy-retrieval.md` 建检索清单，空手写出来的专报必然空。
- 要红头文件、带签章或正式文号的成品：本技能只产内容与版式骨架，签发流程不在范围内。
- 材料涉密或含未脱敏的个人信息：本技能不接触涉密载体，遇到即停并转人工。
- 需要预测政策落地时间或量化影响：只输出"看什么信号、怎么跟"，不做时间点承诺。

## 输入与输出

### 输入字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 主题 | 是 | 一句话说明写什么业务、报给谁；含糊时追问到“业务 + 对象”两要素齐全 |
| 材料类型 | 是 | 专报、汇报材料、情况报告、调研报告、工作要点之一，决定骨架与篇幅 |
| 报送层级 | 是 | 报上级机关、报本单位领导、平级交流；决定帽子高度与开篇口径 |
| 本单位角色 | 是 | 承保方、协办方、代理渠道、管理方、监管对象之一；角色写错是硬伤 |
| 可提供数据 | 否 | 分年度、分业务线、分机构口径；未提供的字段一律生成占位符 |
| 篇幅偏好 | 否 | 默认 6,000–8,000 字（约 10–13 页），可指定“精简版”4,000 字左右 |
| 引用与检索约束 | 否 | 默认优先近 3 个月新文件；政策库 10–15 个短词、兜底搜索 3–4 次查询 |
| 回避表述 | 否 | 不适用的提法或口径，正文与附件均不出现 |

### 输出文件

四份文件放同一个命名目录，校验用的 PDF 与 PNG 放其中的 `_preview/`，交付前删除。

- `政策专报.docx`：公文格式主件，六章加附表，6,000–8,000 字，预计 10–13 页（按正文 600 字/页折算，最终以渲染页数为准）。
- `政策依据清单.md`：文件清单表（序号、名称、文号、发布日、发布机关、链接、引用价值）、逐字原文摘录（按文件分节）、待核清单（缺什么、通常走哪个收文渠道）、检索留痕（渠道、查询式、命中数）。
- `占位符清单.md`：按章节分组的全部 `【填入：…】` 与 `【起草提示：…】`，逐条标注该去哪条线取数。
- `校验记录.md`：预估页数与渲染页数对照、抽页检查结论、字体回退情况、未通过项及处理结果。

### 章节与篇幅分配（默认 6,000–8,000 字）

| 章节 | 占比 | 建议字数 | 核心内容 |
|---|---|---|---|
| 一、政策背景与形势 | 15%–20% | 1,000–1,500 | 帽子区，四层由高到低，开篇落最高层 |
| 二、推进情况 | 55%–60% | 3,500–4,500 | 按业务线分节，每节“要求 → 情况 → 差距” |
| 三、合规与风险防控 | 10%–15% | 700–1,100 | 现行办法的直接约束，独立成章 |
| 四、存在的困难和问题 | 8%–10% | 500–750 | 主动列短板，交代口径与结构性原因 |
| 五、下一步工作措施 | 8%–10% | 500–750 | 与问题一一对应，可执行、可考核 |
| 六、请求支持事项 | 3%–5% | 200–350 | 明确要什么支持、由谁办 |
| 附：主要政策依据清单 | 不计入 | 1–3 页 | 表格，单独起页，表头跨页重复 |

600 字/页是三号仿宋、版心宽约 15.6 厘米时的折算值；表格、另起页与标题留白会再加 1–3 页，报页数时要一并说明。

## 工作流

六步，每步给出五个字段，步骤之间不可跳跃，尤其第 1 步不得延后。第 5、6 步的环境前置：Python 3.9 及以上，`python-docx` 用于渲染，视觉校验另需 Windows 下已安装的 Microsoft Word、`pywin32` 与 `PyMuPDF`，三者缺一即走“仅参数自检”降级路径。

### 第 1 步：政策原文检索与核验（先依据，后结构）

- **做什么**：按 `references/policy-retrieval.md` 的渠道顺序检索——gov.cn 政策库（`scripts/gov_doc_search.py`）→ 省级政府门户与主管厅局栏目 → 地市转发版补全文 → 搜索引擎兜底。每份保留文件落四元组，并摘出 1–3 句可直接引用的逐字原文。
- **检索短词矩阵**（标题检索下每个短词都能拉出一整片，十来轮即可把某领域近两年文件捞一遍）：

| 维度 | 短词示例 |
|---|---|
| 行业与条线 | 行业名、条线名，如“普惠”“涉农”“养老”“科技” |
| 业务对象 | 险种、产品、服务类型等直接对象名 |
| 政策主题 | 五篇大文章、乡村振兴、风险防控、数字化转型 |
| 动作与文种 | 实施方案、指导意见、管理办法、试点、专项治理 |

- **产出**：《政策依据清单》初稿，含文件清单表、逐字摘录、待核清单、检索留痕。
- **判据**：拟设的每个章节至少对应 1 条可引用原文；帽子四层中至少 3 层有实体文件；只见转载、拿不到文号的文件全部进入待核清单。
- **失败怎么办**：`totalCount=0` 先怀疑参数，换成有效 `t` 值并去掉字段限定做全文检索；仍无结果改用兜底搜索定位 URL 后直取正文，并回抓页面标题核对；三轮仍拿不到，该章节改为“待核”占位，禁止用转述冒充实引。
- **常见错误**：把地市转发版当作原件引用；参数无效就断言“没有这份文件”；用长句检索导致零命中。

### 第 2 步：定帽子体系

- **做什么**：按 `references/hat-framework.md` 由高到低扣五层——总纲 → 主线框架（含 1+N 闭合验证）→ 领域专项 → 本地落地 → 合规底线。开篇第一段必须落到最高一层，并逐字引出其核心提法与时间节点。
- **产出**：一页“帽子对照表”，左列层级、中列文件与可用原句、右列拟放章节。
- **判据**：开篇段落能指名到具体文件；领域专项层与正文分节一一对应；本地落地层优先采用政府工作报告一类高规格文本；合规底线若存在必须独立成章，不塞进“下一步措施”。
- **失败怎么办**：某层确实没有对应文件，允许上下层合并，但必须在依据清单标注“该层空缺”，不得为凑层级造文号、造提法。
- **常见错误**：一段里叠三条以上依据；帽子层与章节对不上；把行业通用说法当成条文原句。

### 第 3 步：定骨架与篇幅分配

- **做什么**：主轴线取政策与业务的分类维度（业务线 / 险种 / 领域），区域只作章节末尾的案例或一次横向对比。用梯队制分篇幅：必写领域各一节、新出文件的增量内容各半节、本地独有亮点合并 1–2 节、合规要求独立一章。
- **产出**：带字数的章节大纲，每节标题后附“对应依据编号”。
- **判据**：一级标题里不出现行政区划；每节标题都能对应一条政策要求；问题章主动列出短板；合规章独立存在。
- **失败怎么办**：手里只有分地区数据时，保持业务线主轴，把地区数据降级为该节末的一句对比，并在占位符清单注明还缺哪一维数据。
- **常见错误**：按行政区划铺开，每节都写成“各地都在做”的流水账；合规内容塞进“下一步措施”。

### 第 4 步：写正文（含占位符）

- **做什么**：每节按“政策要求 → 本单位情况 → 差距或举措”三件套展开；一条结论配一条最硬依据；业务数据写成 `【填入：…】`，需要补数据处写 `【起草提示：…】`；核定本单位在业务链上的角色后再落笔。
- **产出**：全书正文标记文本，加《占位符清单》。
- **判据**：全文没有自造数字；每条判断句都能回溯到某条依据；占位符可被检索到且与清单条数一致；正文不出现状态标记符号。
- **失败怎么办**：数据拿不到就保留占位符与起草提示，不删段、不估算；依据不足的结论降级为“待核”表述或删除，不硬留。
- **常见错误**：把协办写成承保；规模指标与结构指标的年份口径混用；为凑篇幅复述文件原文。

### 第 5 步：生成公文格式 Word

- **做什么**：把正文写成脚本约定的标记文本，运行 `python scripts/make_gongwen_docx.py 源文件.md 输出.docx`。脚本先打印字体选择结果与字数/页数预估，再渲染成文；版式参数见 `references/gongwen-format.md`。
- **产出**：`政策专报.docx`，含页码域与另起页的附表。
- **判据**：A4 与四边页边距正确；四级字体字号符合参数表；行距为固定值；页码显示为 `— N —`；附表另起页、表头跨页重复；占位符显示为红色。
- **失败怎么办**：字体缺失按回退链降级并在校验记录写明；脚本报错先查标记文本的层级符号是否混用；渲染页数与预估偏差超过 3 页，回头调篇幅而不是硬压字号。
- **常见错误**：只设 `run.font.name` 导致中文仍是宋体；页面留着 Letter 默认值；固定行距只设规则不设磅值。

### 第 6 步：视觉校验与交付

- **做什么**：运行 `python scripts/verify_docx_render.py 输出.docx`，得到 PDF 与逐页 PNG；抽查五类代表页（标题页、表格页、含占位符页、附表页、末页），对照 `references/quality-checklist.md` 逐条打勾，最后清理 `_preview/`。
- **产出**：`校验记录.md`，加清理后的四份交付文件。
- **判据**：五类代表页全部通过；无字体回退造成的方框或乱码；表格不越出页边距；页码存在；Word 统计页数与预估偏差在 ±2 页内。
- **失败怎么办**：发现溢出或字体错误，回到第 5 步改参数重渲染，不得交付没看过的 `.docx`；运行环境没有 Word 时降级为“仅参数自检”，并在校验记录里明确写“未完成视觉校验”。
- **常见错误**：只看 Word 未看 PDF；只抽查标题页就交付；预览目录留在交付包里。

## 输出格式

```
标题（陈述判断，不写"关于……的报告"）
导语：一句话结论 + 适用范围
一、形势判断（三层帽子：上级要求 / 本级实际 / 趋势走向）
二、问题与成因（每条：现象 → 数据 → 成因）
三、对策建议（每条：动作 → 责任主体 → 时限 → 验收口径）
风险提示（不确定项与前置假设）
资料来源（可追溯，不写"据了解"）
```

## 质量门槛

交付前逐条打勾，任一条不过即不得报送。每条的“不过怎么办”是当场要执行的动作。

- [ ] **引用可回溯**：每条引用具备文号、发布日、发布机关、官方链接四元组，或已在待核清单登记“缺什么 + 收文渠道”。不过则：缺项降级为待核表述，正文去掉文号，不留半截引用。
- [ ] **零自造数字**：全文业务数据均为 `【填入：…】`，条数与《占位符清单》一致，无估算值与推测值。不过则：逐条替换为占位符，并在清单补写取数口径与责任条线。
- [ ] **帽子完整**：四层中至少三层有实体文件，空缺层已在依据清单标注；开篇落在最高一层。不过则：补检一轮新近文件，仍缺则合并层级并标注空缺，不虚构文件。
- [ ] **结构合规**：一级标题不出现行政区划；合规要求独立成章；问题章主动列短板。不过则：区域内容下沉为节末案例，合规内容从“措施”里整体切出。
- [ ] **单条依据**：同一结论下不并列三条以上依据，避免帽子叠罗汉。不过则：删弱留强，其余移入附表供查。
- [ ] **角色准确**：本单位在业务链上的角色已核定，全文表述一致，未把协办写成承保。不过则：回到输入字段重新确认，全文替换相关动词与主语。
- [ ] **正文与交付目录干净**：正文无状态标记符号与来源批注；交付目录无临时文件、无绝对路径。不过则：状态信息移入依据清单或校验记录，临时文件交付前删除。
- [ ] **版式达标**：A4、页边距、四级字体字号、固定行距、页码域、附表另起页、表头重复，逐项核对通过。不过则：回到第 5 步调参数重渲染，附差异说明。
- [ ] **目视校验**：五类代表页抽查通过，无溢出、乱码、方框；页数偏差在 ±2 页内。不过则：定位到具体页与具体元素，修完重跑校验，不跳页交付。
- [ ] **版本核验**：所引公文处理条例与版式标准的现行版本号已人工核对，结论与日期写入校验记录。不过则：标注“待核版本”，正文改用不含版本号的通用表述。

## 能力边界

- **不外联取数**：不接入内部收文系统，不读取未公开的转发件与密级文件；只交付公开渠道可得的文本，其余进待核清单。
- **不编造**：拿不到逐字原文时，不写“看起来像”的条款句与文号；也不判定政策的现行效力，只给核验路径与待核标注。
- **不代填业务数据**：不估算、不推算业务量、机构数、占比等口径，只留占位符与取数指引。
- **不承诺结果**：不承诺审核结论，也不承诺被采纳；只承诺流程可复核、门槛可打勾、来源可追溯。
- **不接收敏感信息**：材料含涉密内容或他人个人信息时转线下处理，本技能不接收、不留存。
- **不做非公文版式**：演示文稿、公众号排版、图表美化不在范围内；需要时只交付正文文本与骨架。

这几条边界的共同取向：宁可留着空位被追问，也不填一个看起来对的答案。占位符与待核清单限制了成品的表象完整度，却让报送方清楚该补什么，比无法回溯的漂亮句子安全。

## 常见陷阱

- **帽子套得比内容高**：写满"重要指示"却没有本级数据，审稿第一眼就被打回 → 每层帽子必须有对应材料支撑。
- **通篇转述、没有判断**：把文件复述一遍当专报 → 每节末尾必须落到"所以我们要做什么"。
- **数据无出处**：出现"约""左右"却给不出统计口径 → 要么给口径，要么标"待核"。
- **把建议写成决定**：用"必须""立即"替领导拍板 → 改成"建议""可考虑"，并写明前置条件。

## 交付示例

**输入（3 行）**

- 主题：某条线年度业务推进情况，报上级机关。
- 材料类型：专报；篇幅 6,000 字左右。
- 数据：只有分地区完成量，缺分业务线口径。

**输出骨架（节选）**

```text
标题：关于【填入：XX】业务推进情况的报告
副标题：——【填入：报送单位】　【填入：报送日期】
一、政策背景与形势
　（一）国家层面：扣第一层总纲，逐字引核心提法【依据 01】
　（二）主线框架：1+N 结构是否闭合，闭合则分层引用【依据 02–03】
　（三）本地落地：政府工作报告相关表述【依据 04】
　（四）合规底线：现行办法对本业务的直接约束【依据 05】
二、推进情况（按业务线分节，每节末附一句区域对比）
　（一）【业务线 A】：政策要求 →【填入：A 线完成量】→ 差距
　（二）【业务线 B】：政策要求 →【填入：B 线完成量】→ 差距
三、合规与风险防控
四、存在的困难和问题（主动列短板，含规模与结构口径说明）
五、下一步工作措施
六、请求支持事项
附：主要政策依据清单（表格，另起页）
```

**同步产出的三份附件**：依据清单 5 条均落四元组，其中 1 条标注“待核，建议核收文系统”，附检索留痕 4 行；占位符清单按章节列出 12 处 `【填入：…】` 与 3 处 `【起草提示：…】`，注明取数条线；校验记录写明预估 11 页、渲染 11 页、五类代表页通过、字体回退 1 项。

**依据清单的表格形态**

| 序号 | 文件名称 | 文号 | 发布日 | 发布机关 | 引用价值 |
|---|---|---|---|---|---|
| 01 | 【填入：总纲文件全称】 | 【填入】 | 【填入】 | 【填入】 | 最高层，开篇落点 |
| 02 | 【填入：主线意见】 | 【填入】 | 【填入】 | 【填入】 | 1+N 主框架 |
| 03 | 【填入：配套方案】 | 【填入】 | 【填入】 | 【填入】 | 与 02 闭合 |
| 04 | 【填入：本级政府工作报告】 | 无文号 | 【填入】 | 【填入】 | 本地落地，规格最高 |
| 05 | 【填入：现行办法】 | 【填入】 | 【填入】 | 【填入】 | 合规底线，独立成章 |

“无文号”不是缺项，而是政府工作报告这类文本的常态，需在备注写明是哪一年的哪一次会议。
