# 可复制的分阶段测试提示词

按需选择相关阶段，替换占位路径，不要求每次任务全部执行。普通用户任务之外的检查应与改动风险相称。

1. 版本与入口：只读核对当前专家隐藏plugin.json和其skills路径中的SKILL.md/版本清单，报告专家、技能及build_id。用可信ZIP和verify_install.py核对实际安装目录，保存命令与退出码；不修改安装文件。
2. 生成任务：把我提供的工作经验整理成技能，生成WorkBuddy专家和技能包，其他目标为Trae、Codex、Claude Code、Cursor、GitHub Copilot、Hermes等。保留稳定机器名，名称/简介明确平台与支持范围；无需先询问已给出的信息。专家头像必须随ZIP打包并正确引用。
3. 实际交付核对：从最终ZIP读取入口、引用与版本；用publish.py check --profile expert --expected-avatar核对指定图片。解压到独立目录，用包内脚本验证已审查的合成样例。逐项报告离线、客户端、市场状态，不能拿源码目录测试代替压缩包检查。
4. 故障验证：按本次改动选择缺头像、错头像、旧版本断言、缺资源或错误绑定等反例。先确认正确样本在同一检查/合同下通过，再注入单个故障并确认预期诊断。保存原始输出、退出码、工具/合同/文件摘要；环境错误和工具崩溃不算拦截成功。
5. 日志迭代：根据脱敏对话日志和实际交付文件列出问题案例、影响、证据和修复建议；区分模型误归类与有效对比。仅将跨项目可复用的经验写入通用技能。已授权的修复继续完成，未授权外部发布单列；交付明确哪个文件用于哪个导入入口。
