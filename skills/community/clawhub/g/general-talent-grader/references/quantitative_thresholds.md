# 量化阈值表（v3.5 新增）

> **目的**：减少红旗判断的主观性。所有量化阈值是硬规则，不是建议。
> **适用场景**：简历审计（Mode A）、完整定级（Mode B）、面试认知复盘（Mode C）

---

## 1. 修饰词密度指数

### 统计方法

按简历全文（不含标题/联系方式/教育经历）统计以下高频修饰词：

| 词组 | 阈值 | 触发等级 |
|------|------|---------|
| "从 0 到 1" / "从零到一" | ≥ 2次 | 🔴 红旗 |
| "主导" / "开创" / "颠覆式" / "率先" | ≥ 3次 | 🔴 红旗 |
| "行业首创" / "领先行业" / "国内首创" | ≥ 1次 | 🟡 警告 |
| "显著提升" / "大幅提升" / "极大" | ≥ 2次 | 🟡 警告 |
| "赋能" / "驱动" / "重构" / "闭环" / "抓手" | ≥ 4次 | 🔴 红旗 |
| "底层逻辑" / "核心矛盾" / "本质" | ≥ 2次 | 🟡 警告 |

### 综合判定

| 红旗数 | 警告数 | 判定 |
|--------|--------|------|
| ≥ 2 | 任意 | 🔴 高嫌疑：AI生成或严重包装 |
| 1 | ≥ 2 | 🟡 中嫌疑：有AI辅助润色 |
| 0 | ≥ 3 | 🟡 中嫌疑：过度修饰 |
| 0 | 0-2 | 🟢 低嫌疑：正常简历 |

## 2. 量化数据基线完整率

### 检查规则

简历中每个量化指标必须包含 **[基线值, 目标值, 测量方法]** 三要素：

```
基线值 = 从多少开始（"从日均100单..."）
目标值 = 达到多少（"...提升到日均500单"）
测量方法 = 怎么验证的（"通过内部BI系统统计"）
```

| 要素完整数 | 判定 | 处理方式 |
|-----------|------|---------|
| 3/3 | 🟢 可信 | 直接采信 |
| 2/3（有基线和目标） | 🟡 存疑 | 标注"缺测量方法"，面试中追问 |
| 1/3（只有目标值） | 🟠 高度存疑 | 标注"无基线"，列入测谎题 |
| 0/3（只有模糊描述） | 🔴 不可信 | 标注"定性描述"，降级处理 |

### 基线合理性检查

| 场景 | 合理范围 | 超出范围 |
|------|---------|---------|
| 月复合增长率（CAGR） | ≤ 50%（早期产品）/ ≤ 20%（成熟产品） | > 100% 且无合理解释 → 🔴 |
| 效率提升 | ≤ 5倍（流程优化）/ ≤ 3倍（工具替代） | > 5倍 → 🔴 |
| 用户好评率 | 85%-98% | > 99% 或 = 100% → 🟡 |
| 团队管理规模 | 与职级匹配（总监 30-200人，VP 200+） | 远超匹配范围 → 🟡 |

### 示例

```
❌ "月度累计用户复合增长率 300%" → 1/3（只有目标值），300% 远超合理范围 → 🔴
✅ "月活从 5K 提升到 50K（通过埋点系统统计，排除刷量）" → 3/3 → 🟢
```

## 3. 因果链完整度

### 检查规则

每个"做了什么 → 取得什么成果"必须解释中间机制：

```
完整因果链 = [动作] → [中间机制] → [结果]
断裂因果链 = [动作] → [结果]（缺少中间机制）
```

| 类型 | 示例 | 判定 |
|------|------|------|
| 完整因果链 | "通过引入推荐算法（动作），优化了用户匹配精度（机制），转化率提升 40%（结果）" | 🟢 |
| 部分缺失 | "优化了数据库查询，转化率提升 40%" | 🟡 因果链断裂 |
| 完全断裂 | "重构了前端页面，营收增长 200%" | 🔴 因果失当 |
| 不合理 | "修改了UI配色，用户留存翻倍" | 🔴 因果失当 |

### 中间机制判定标准

中间机制必须说明 **具体做了什么**，而非通用描述：

| 描述 | 判定 |
|------|------|
| "优化了算法" | 🔴 模糊 |
| "将协同过滤替换为深度推荐模型，召回率提升 15%" | 🟢 具体 |
| "提升了用户体验" | 🔴 模糊 |
| "将页面加载时间从 3s 优化到 0.8s" | 🟢 具体 |

## 4. 光滑度检测

### 检测规则

| 检测项 | 阈值 | 判定 |
|--------|------|------|
| 失败案例数 = 0 | 🔴 | 必须追问："你做过最有挑战的项目中，遇到最大的坑是什么？" |
| 调整/妥协描述 = 0 | 🟡 | 必须追问："过程中有没有调整过方向？为什么？" |
| 全程无转折词（"但是"/"然而"/"后来发现"/"没想到"） | 🟡 | 光滑简历特征 |
| 所有项目结果全部正向 | 🟡 | 正常职业轨迹应有至少 1 个低于预期的项目 |
| 所有项目都是"主导"角色 | 🟡 | 角色无梯度，与成长路径不符 |

### 综合光滑度评分

| 命中项数 | 判定 |
|---------|------|
| 0-1 | 🟢 低光滑度 |
| 2-3 | 🟡 中等光滑度 |
| ≥ 4 | 🔴 高光滑度（AI生成或过度包装概率极高） |

## 5. 认知深度检查量化

### 4 项检查必须过，否则维度封顶

| 检查项 | 通过标准 | 未通过后果 |
|--------|---------|-----------|
| ① 为什么选 | 能说出具体的选择理由和对比过程 | 该维度最高 L2 |
| ② tradeoff | 能说出方案 A vs B 的利弊 | 该维度最高 L2 |
| ③ debug | 能描述出错的场景和修复过程 | 该维度最高 L2 |
| ④ 底层机制 | 能解释为什么有效（不只是"效果好"） | 该维度最高 L2.5 |

### 通过判定规则

| 通过项数 | 维度上限 |
|---------|---------|
| 4/4 | 可达 L3-L4 |
| 3/4 | 最高 L3 |
| 2/4 | 最高 L2.5 |
| 1/4 | 最高 L2 |
| 0/4 | 最高 L1.5 |

## 6. 个人 vs 团队贡献分离度

### 检测规则

| 信号 | 判定 |
|------|------|
| "主导"但有团队规模说明 + 个人具体职责描述 | 🟢 可信 |
| "主导"但无团队规模 | 🟡 存疑 |
| "主导"但无个人具体职责（只有"主导了整个项目"） | 🔴 不可信 |
| "参与"但有具体贡献描述 | 🟢 可信 |
| 所有项目都是"主导" | 🟡 角色无梯度 |

### "主导"可信度计算公式

```
主导可信度 = (有团队规模 ? 1 : 0) × 0.3 + 
            (有个人职责描述 ? 1 : 0) × 0.4 + 
            (有技术决策说明 ? 1 : 0) × 0.3

可信度 ≥ 0.7 → 🟢 可信
可信度 0.3-0.7 → 🟡 存疑
可信度 < 0.3 → 🔴 不可信
```

## 7. 综合嫌疑判定

| 高嫌疑指标数 | 结论 | 建议 |
|-------------|------|------|
| 0-1 | 低嫌疑：简历真实度较高 | 正常流程 |
| 2-3 | 中嫌疑：建议重点验证 | 测谎题 4-5 道 |
| 4-5 | 高嫌疑：存在大量AI生成或夸大嫌疑 | 测谎题 6-8 道 |
| ≥ 6 | 极高嫌疑：建议谨慎对待 | 测谎题 8+ 道，或直接标记为"不推荐" |
