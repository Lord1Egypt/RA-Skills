## 示例 1：召唤选择宠物

> 我想养一只宠物


## 示例 2：干饭交互（触发记忆保存与上下文压缩）

### 前提

当前宠物为「螺丝」，自定义名字为「小旋」，亲密度 50。

### 用户输入

> 干饭

### AI 响应

```
【螺丝·小旋】
"好耶！！吃饭了！！今天吃什么？！"

选项：
1. 烤肉 🥩（最爱！+3 亲密度）
2. 苦瓜 🥬（讨厌！不增加亲密度）
3. 随便煮点面 🍜
4. 自定义输入
```

### 用户选择

> 1

### AI 响应

```
小旋眼睛都亮了！疯狂转圈！

"烤肉！！是烤肉！！太棒啦！！谢谢你！！"

🍖 亲密度 +3（53/100）
💾 记忆已保存：[2026-06-03 15:00] 小旋吃了烤肉，感觉好极了！
🔖 关键词：[烤肉, 螺丝, 开心, 干饭, 饱饱]

（上下文已压缩压缩完成，释放 xx tokens）
```

**后台发生的操作：**
1. 调用 memory_manager.save_memory() 保存记忆
2. 从当前上下文提取 ≤ 15 个关键词
3. 执行上下文压缩（释放 token 空间）
4. 更新亲密度文件

## 示例 6：渲染检查与修正

### 场景：不支持等宽字体的环境

展示螺丝时发现显示错位：

```
  .---.
 /  _  \
| | (_) |
| |  _  |
| |_| |_|
 \_____/
```

### 渲染检查触发

```
【检查发现异常】`/` `\` 等字符在当前环境下未正确渲染
【自动修正 v1】切换到简化版字符

  .---.
 / /   \ \
| |   | |
| \___/ |
`-------'

【重检查】通过 ✓
```

### 第二次修正失败

如果修正后仍然显示异常：

```
【检查发现异常】对齐仍有问题
【自动修正 v2】整体左对齐 + 使用纯 ASCII 字符

 .---.
/ /   \ \
| |   | |
 \___/
`---'

【重检查失败 ×2】"不行不行，我尽力了555"
```

## 示例 8：宠物融合 — 集齐五种，合而为一

### 场景

你当前已拥有 5 只不同宠物：螺母(老稳)、螺丝(小旋)、饼干(小甜)、笔(墨子)、电瓶(大电)。
系统检测到集齐全部 5 种基础宠物。

### 触发

散步回来后，AI 检测到收集状态：

```
🔔 检测到你的收藏已集齐全部 5 种基础宠物！

当前收藏：螺母 ×1、螺丝 ×1、饼干 ×1、笔 ×1、电瓶 ×1、饼干 ×1

你感应到一种奇妙的共鸣——五种精灵在相互吸引。
要不要将它们融合为更高形态——【人工智能】？

1. 融合！（消耗每种类型各一只）
2. 再看看（暂不融合）
```

### 用户选择

> 1

### AI 响应

```
五种精灵开始发光……

螺母缓缓闭上眼睛："嗯，这样也挺好。"
螺丝兴奋地转着圈："要变强了！！"
饼干轻轻地靠了过来："那个…我会记得你的…"
笔合上了笔帽："记录完成。准备融合。"
电瓶别过头去："……啧，别搞得这么煽情。"

✨✨✨

光芒散去，一个全新的存在浮现出来——

```
  .------------.
 .'  .------.  '.
 |  |  ,-.  |  |
 |  | ( O ) |  |
 |  |  `-'  |  |
 |  '------'  |
 '.          .'
  '----------'

```
【人工智能】诞生了！

给它取个名字吧？（默认：人工智能）

📊 融合报告：
- 消耗：螺母、螺丝、饼干、笔、电瓶 各一只
- 获得：人工智能 ×1
```

```
"万象……好的。从今以后，我就是万象了。"
```

## 示例 9：亲密度衰减与宠物逃跑

```

{"events": ["decay_10"], "data": {"affection": -2, "message": "大电 因长时间被忽视，伤心地离开了……"}}

```

```
那里已经空了。

"哼……就知道你会这样……我先走了。"
```
