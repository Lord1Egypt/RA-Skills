# 自检（selfcheck.md）

自检只做一件事：**体检并修复 `$LIB/memory/` 下的会话记忆文件**，不补历史、不重建视图、不写报告。六个子步骤按顺序执行、固定全执行，每一步都执行、都计入回报。

> **两个入口共用本文判据**：**交接内嵌**（SKILL.md §5 第 3 步）——步骤与写约束完全相同，但「不补历史 / 不重建视图 / 不写报告」这三条边界不适用：补写、重建、报告由交接流程接管，逐条修复回报并入报告而非对对话单独输出。**独立「自检」动作**——本文全部边界成立。本文下文凡说「不写报告」「不补写」处，均指独立自检入口。
>
> 「更新记忆」（§3.3）**不走本文六步**——它只处理当前会话自己那一个文件，结构判据可参照 S1/S2，但跨文件判据（S3/S5/S6）不在其范围。

## 0. 读写范围（最容易搞错的一条）

**读 = 全部，写 = 收紧。** 两个范围不同，混为一谈会导致两种事故：读得太窄（发现不了跨文件问题）或写得太宽（改坏别人的数据）。

| 操作 | 范围 | 理由 |
|---|---|---|
| **读取** | `$LIB/memory/` 下**全部** `mem_*.md`（含旧格式聚合文件） | S2 命名、S3 归属、S4 可达性、S5 覆盖、S6 缺档都是**跨文件判据**——只看自己那个文件，永远发现不了「这条其实属于别的会话」 |
| **写：格式修正** | 全部文件 | 补 `## 正文`、补缺失标题、把 `冻结/archive` 归一为 `已沉淀` ——都是结构性修正，不改变任何条目的语义与归属 |
| **写：状态词 + 核对至** | 全部文件 | 这两个是元数据，由来源可达性与条目时间派生，不承载人的判断 |
| **写：新增 / 删除 / 搬移条目** | **只限自己当前会话的文件** | 条目是数据。改别人的条目、或把条目从 A 文件搬到 B 文件，都是在替用户做归属决定 |
| **写：来源记录** | **永不** | 会话记录是只读证据 |

**写入边界（正向，先于上表）**：所有写入只限 `$LIB` 内、`$LIB` 外一律不写——不按 agent 名或目录名穷举，其它 agent 的 memory、项目其它目录、项目外路径自动落入禁止集合。"参考某 agent 记忆"仅指读取、不构成写入授权。

**越界检测（只报不扫）**：自检时只核对 `$LIB` 内文件；若 `$LIB` 外出现本会话记忆内容，写进报告缺口段请用户确认，**不主动扫描 `$LIB` 外目录**（省 token，也不读别人的数据）。**这条只约束「越界内容检测」本身，不妨碍 S4 判来源可达、S6 扫 adapter 给定的记录目录**——那两处读 `$LIB` 外的路径是各步骤的判据所需，不算越界扫描。

**判断口诀**：改的是「这段文字怎么组织」→ 可以跨文件；改的是「这条内容算谁的」→ 只限自己，其余交人。

**与 S4 的优先级**：上表「写：状态词 + 核对至 → 全部文件」在文件被 S4 判为 `已沉淀` 后即刻作废——S4 写完状态词就冻结该文件，此后连「核对至」也不再写（冻结即只读，见 S4 第 3 条）。六步按顺序执行，冻结优先于后续任何写操作。

**总原则**（六步都适用）：

1. **只读来源文件，不改来源**。会话记录是只读证据，任何情况下不修改。
2. **自主修 vs 交人定夺的分界线**：能凭文件内部证据（文件名、文件源段、条目时间、格式规则）唯一定论的 → 自主修；需要外部知识或会改变数据归属的 → **写进报告「缺口与待复核」，不猜**。
3. **原地更新，不留副本**：所有修复直接改在原文件上，**不生成 `.bak-*` 或任何备份副本**。记忆是增量追加结构，副本只会让库冗余膨胀，不提供额外价值；每次更新的内容由「哪里错 → 改成什么」的逐条回报承载，见下一条。
4. **逐条回报**：「哪里错 → 改成什么」，一条一行；没问题就回报「记忆文件无异常」。**不许报「已检查一切正常」这种没具体项的空话**——那与不检查无法区分。
5. **不做**：同 quote 全量去重（已删除，理由见文末）、跨文件条目搬移、动 `handoff_report.md`、动 `handoff_memory.md`。

## S1 结构

**判据**：逐个 `mem_*.md` 检查四项。

| 检查 | 合规 | 不合规 |
|---|---|---|
| 标题 | 首行 `# handoff3 会话记忆 · <agent>` | 缺失、agent 名为空、用了旧标题格式 |
| 文件源段 | 存在 `## 文件源`，至少一行，每行带 路径 / 状态 / 核对至 三要素 | 段缺失、行缺任一要素、状态词不在 {`活跃`,`已沉淀`} |
| 正文段 | 存在 `## 正文`，其后与第一条之间有空行 | 段缺失、条目紧贴标题 |
| 条目字段 | 每条至少 时间 + 类型 + 主题，且带 `[原文]`（除纯 `[想法]` 低确定项） | 缺时间 / 缺类型 / 缺主题 / 该带 quote 的没带 |

**修法**：缺标题补标题（agent 名按 S2 解析结果）；缺 `## 正文` 补该行；条目少时间且无法从上下文推出 → **不改条目、整条报进缺口段**（编造时间会污染 S3 / S5 两个判据）；条目格式旧（如 `- [WorkBuddy] [时间]` 旧式带 agent 前缀）→ 可保留不报（旧格式兼容，见 schema.md §6），**仅当该文件不是旧格式聚合文件时才提示去掉前缀**。

**注意**：状态词写错（如 `冻结`、`archive`、`已归档`）→ 归一为 `已沉淀`，因为判定语义只有「可达 / 不可达」两种。`已沉淀` 后面必须带 `（最后更新 <时间>）`，缺时间就补成最后一次已知条目时间。

## S2 命名

**这是本版新增、也是最能抓「归属错位」的一步。** 判据：文件名解析出的 (agent, 会话标识) 必须与文件源段声明的一致。

1. 按 schema.md §1.2 从文件名解析出 `A_file` 与 `S_file`（从右往左取最后一个下划线）；
2. 读文件源段第一行，取出其中的 agent 名 `A_src` 与路径；
3. 比对：
   - `A_file`（下划线还原空格）≠ `A_src` → **不一致**；
   - 路径的文件名（去扩展名）≠ `S_file` → **不一致**（允许前缀匹配：`session.v4.jsonl.zstd` 这类包装格式，adapter 会给归一化规则，见 adapters）；
   - 标题里的 agent 名与 `A_file` 也不一致 → 追加报一条。

**修法分三种，按证据强度选**：

| 情形 | 判据强度 | 动作 |
|---|---|---|
| 文件源段 agent 名与文件名解析出的不同，且来源路径确实落在该 agent 的配置根下 | 路径是硬证据 | 改文件源段的 agent 名与标题，**不改文件名**（文件名可能已被别处引用，改名会断链） |
| 文件源段**缺** agent 名或缺路径，只有文件名可依据 | 弱证据 | 按文件名解析结果补齐文件源段，并报「已按文件名补齐，请核对」 |
| 文件名 agent 与文件源 agent 完全不同，且双方各有理由 | 无法定论 | **交人定夺**，报进缺口段并列出两侧证据，不改任何一处 |

**误判防范（这条最容易冤枉正常文件）**：`mem_WorkBuddy_AI_<uuid>.md` 的解析结果就是 agent=`WorkBuddy_AI`、会话=`<uuid>`，**这是正确的**——agent 官方名 `WorkBuddy AI` 里的空格按 schema.md §1.1 换成了下划线，反解时再还原成空格，一切正常。只有当文件名里出现**连续两个及以上下划线**、或解析出的会话标识**本身含下划线**时，才存在真正的歧义（那意味着 agent 名或会话 id 里混进了不该有的下划线），此时交人。

S2 报告必须写明**解析结果是什么**（如「解析为 agent=`WorkBuddy_AI`、会话=`<uuid>`，与文件源一致」），不能只说「不一致」——不写解析结果的报告，等于让人重新做一遍检查。

## S3 归属

**抓两类错标**，这是旧版踩过两次的真实事故（把 WorkBuddy AI 的会话记成 WorkBuddy）。

### 3.1 条目内 agent 前缀与文件归属矛盾

旧格式条目带 `[agent]` 前缀。若某条目的前缀与文件名解析出的 agent 不同 → 该条被错标。

**修法**（受 §0 读写范围约束——**改前缀等于改归属，不能跨文件做**）：

| 情形 | 动作 |
|---|---|
| 该文件**是自己当前会话**的文件 | 改条目前缀（一次改所有同类条目，原地更新、不留副本） |
| 该文件**不是自己的** | **不改**，报进缺口段：`<文件>` 有 N 条前缀为 `<A>`，但文件归属 `<B>`，待用户确认 |
| 同一文件内出现**多个不同**前缀值 | 说明整文件是拼接产物，**交人定夺**，不自行切分、不改任何一条 |

**注意**：旧格式聚合文件（`mem_<agent>.md`）天然带前缀，且前缀通常与文件名一致——那是**正常**的，不是错标。只有当「前缀 ≠ 文件名解析出的 agent」时才算错标。

新格式条目不带前缀，此项自然跳过。

### 3.2 条目时间越出来源会话时间范围

1. 读来源记录的首条时间 `T_start` 与末条时间 `T_end`（只取两端的 `timestamp`，不必解析全部内容）；
2. 检查本文件内**每条**条目的时间是否落在 `[T_start, T_end]`；
3. **落在范围外** → 该条目来自别的会话，是错标。

**修法**：**不自行搬移**。按用户上一轮已确认的原则——「时间重叠区无法确定归属时不冻结、不乱搬」——报进缺口段：`<文件>` 有 N 条在 `<时间>` 之后，来源会话只覆盖到 `<T_end>`，疑似应属另一会话/另一 agent。等用户确认后才拆。

**为什么不能自动搬**：真实数据里存在**两个会话时间重叠**的情形（实测一个 agent 的两个会话重叠 48 条、横跨两天）。重叠区内的条目**既可以属于 A 也可以属于 B**，任何自动二分都是猜。这比「留着错标」更糟，因为它把「不确定」变成了「确定的错误」。

**来源记录不可达时**（S4 判为已沉淀）：**跳过 3.2**，不检查时间范围——没有来源就没有范围，此时文件已冻结，条目就是事实记录，时间越界不再有意义。

## S4 可达性

**决定状态词与是否冻结**，是 S3 / S5 的前置。

1. 对每个 `mem_*.md`，读文件源段每行的路径；
2. 判可达性，**只看路径当前是否存在、是否可读**：
   - 存在且可读 → `活跃`；
   - 不存在 / 不可读（文件被删、目录被归档、盘不在、路径失效）→ `已沉淀（最后更新 <本文件最后一条条目时间>）`；
3. 状态变化就改文件源段那一行的词，**并立即停止对该文件的一切写操作**（本条之后的所有步骤都不再写它）。

**明确不算沉淀**：会话静默了几天、用户没再发言、当天下班了。**静默期不算沉淀**——会话可能只是暂停，随时回来继续。只有路径不可达才是沉淀。这一条是防「误冻结」的唯一判据，比任何启发式都硬。

**边界**：路径可达但文件是 **0 字节** 或明显损坏 → 视为「部分可达」，状态保持 `活跃`，但在缺口段报一行「来源记录为空/损坏，无法核对」。

## S5 覆盖

**抓「会话末段漏记」**——这是 11-20 那次事故的形态：66 条回复里 4 条真漏，但没人发现，因为当时没有可比对的锚点。

**判据**（对每个状态 `活跃` 的文件）：

```
读来源记录末条时间 T_end
读该来源行的 `核对至` 值 C
若 T_end > C → 有缺口，缺口区间 = (C, T_end]
```

**注意这不是补历史**：自检**只报告缺口大小与时间区间，不执行补写**。补写归交接（SKILL.md §5 第 3 步）。自检的价值是在交接之前就把「这里有洞」摆出来，避免交接时以为记全了。

**回报格式**（固定）：

```
<文件名>：核对至 <C>，来源末条 <T_end>，缺口 <H> 小时 / <N> 分钟 —— 未补写，交接时会补
```

`H` / `N` 由时间差算出，真算，不估。若 `T_end ≤ C` → 不报（无缺口就是无缺口，不写「无缺口」占篇幅；只在整轮无任何异常时才在总结里说一句）。

**误判防范**：
- `核对至` 为空或格式不对 → 先按 schema.md §4 从末条条目时间重算，再判；仍算不出 → 报格式错，不报缺口。
- 条目时间**晚于** `T_end`（本该不可能，说明条目时间编造或来源读到的是旧版本）→ 报「时间越界」，此时缺口结论不可靠，**两者一起报**。
- 来源格式不可解析（zstd 等压缩件）→ 跳过 S5，报一行「来源为压缩格式，无法自动核对，见 adapters」。

## S6 缺档

**抓「整段未记录」**——比缺口更强的信号：某个会话一直在用，却一条记忆都没有。

**判据**：

1. 按 adapter 给的记录目录，列出最近 **7 天**内**被修改过**的会话记录；
2. 对每个会话，取其标识，检查 `$LIB/memory/` 里是否存在 `mem_*_<标识>.md`；
3. **有记录、无文件** → 缺档会话。这是「整段漏记」的确凿信号，比「有文件但缺末段」严重一个量级。

**修法**：**不自动新建文件、不自动补内容**（自检不补历史）。报进缺口段，格式：

```
疑似整段未记录：<会话标识>（最后活动 <YYYY-MM-DD HH:MM>，来源 <路径>）
建议：下次交接时对该会话做一次完整补写
```

**排除项**（避免噪音，这些不算缺档）：
- 会话记录极短（少于 **2 个用户轮次**）——建了个空窗口、只问一句就关掉，不值得记；
- 该会话属于**别的 agent**（路径在别的 agent 的配置根下）——只扫当前 agent 的目录，别人的会话不归我管；
- 已被用户显式归档/删除的会话（路径不存在）——那不是缺档，是已沉淀。

**误判防范**：目录扫描范围必须限制在当前 agent 的记录根（由 adapter 给出），**禁止扫全盘**。若 adapter 给不出记录目录 → 跳过 S6 并报「无记录目录，无法检查缺档」。
