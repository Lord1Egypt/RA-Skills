## Phase 1 并行检索（T1 ∥ T2 ∥ T3）

### 执行顺序

```
主控 spawn 三方并行：
1. T1 文献检索员（literature/文献卡.md）
2. T2 数据检索员（data/数据卡.md）
3. T3 案例检索员（cases/案例卡.md）

sessions_yield 等待三方完成
主控执行「Phase 1 覆盖对账」（见下节）
```

## Phase 1 覆盖对账（v2.17.0 新增；三方检索员的**事后合同**）

> **动机**：T1∥T2∥T3 各自独立检索，缺少共同基线 ⇒ 子问题可能被集体漏检（全面性缺口），且同指标冲突无机制性发现点。**矩阵是三角验证的事前合同**（三角验证 = 事后验收）。

### 对账输入

| 文件 | 内容 | 生产者 |
|---|---|---|
| `analysis/检索覆盖矩阵.md` | 3-5 个子问题 × L/D/C 需求格位 + 最低条数 | Phase 0 主控建表（模板 = [`templates/检索覆盖矩阵-template.md`](../../templates/检索覆盖矩阵-template.md)）|
| `literature/文献卡.md` | [Lxx] 按子问题分组 | T1 |
| `data/数据卡.md` | [Dxx] 按子问题分组 | T2 |
| `cases/案例卡.md` | [Cxx] 按子问题分组 | T3 |

### 对账四步（主控执行）

1. **数量对账**：逐格位核对「实际条数 ≥ 最低条数」。低于 → 标缺口。
2. **缺口分类**（决定处置路径，二者不可混）：
   - **客观缺口**（该证据确实不存在 / 该库不收录 / 数据库无此数据）→ 标「缺口：未检索到」+ 写入局限性；**不走 T1b**。
   - **检索缺口**（换关键词 / 换库可补）→ **触发 T1b 定向回查**补检索（`dispatch/T1b-定向回查.md`），单子问题 ≤1 轮；补后仍缺 → 转客观缺口。
3. **冲突仲裁**（v2.17.0 新增）：对账时同步检查**同指标多来源矛盾**。命中时：
   - **强制并列呈现**：所有来源 + 各自口径（统计范围 / 样本 / 时点）一并写入卡，**禁止静默二选一**；
   - **口径差异归因**：区分「真矛盾（口径不同）」与「伪矛盾（同一口径下报错）」，后者 = 🔴 可疑数据，须送 T1b 优先复核；
   - **L/D 冲突**：文献结论与数据趋势相反时，不得调和为单一叙事——交大纲「反方论证规划」或局限性，由 T4/T6 裁决。
4. **冻结**：对账完成后矩阵冻结，不增删子问题；缺口处置结果写入 `status.md`（`coverage_ledger` 行），作为 T2.5 闸门输入。

### 失败处置

对账表缺失 / 条数与卡片实际数不符（>20%）⇒ 按 M-Exist「路径或参数错误」档处置：**不重跑三方检索**，先 `read` 核对产物，产物在则补对账，产物缺才走节点接管。

### T3 空卡协议

**重要**：Phase 0 已确认需要案例时，T3 案例检索即 spawn（含 cases = 0 空卡协议）；T3 worker 不可用/失败 ⇒ 主控接管该节点并记录降级。

**0 条场景处理**：
- T3 检索后确认「该主题无需案例卡」或「检索无果」
- 产出空卡：`cases/案例卡.md` 文件存在，但内容为：
  ```markdown
  # 案例卡（空）
  
  **检索结果**：本主题为理论/数据分析主题，无企业行为/事件需要案例支撑。
  
  **检索范围**：[列出已检索的关键词/数据源]
  
  **结论**：0 条案例卡，符合主题定位。
  ```
- M-Exist-1 门承认空卡合法（含「空」标记的案例卡通过）

**为什么在多 Agent 路径中保留 spawn**：
1. 主控不能代替 T3 判断「是否需要案例」
2. 空卡是**显式的检索结果**，不是静默跳过
3. 审计追溯需要：T7 能看到「T3 检索过但无果」vs「根本没检索」

## Phase 1.5 定向回查（条件触发）

### 触发条件

1. **任务简报标记 [Dxx/Lxx 待复核]**：主人在 Phase 0 投喂的数据/文献（v2.13.0 P0-1 起含文献级 [Lxx]），需回溯一手源
2. **🔴 二手转引未回溯**：T1/T2 产出的数据卡含「二手转引」标记
3. **【v2.17.0 新增】覆盖矩阵判定为「检索缺口」**：Phase 1 对账时某子问题格位低于最低条数，且主控判定「换关键词/换库可补」⇒ 派 T1b 补检索（客观缺口不走本窗口）
4. **【v2.17.0 新增】冲突仲裁发现「伪矛盾」**：同指标两来源在同一口径下报错 ⇒ 优先送 T1b 复核来源真伪
5. **上一轮 T9 审稿报告指出证据强度不足**（**v2.12.55 S-6 口径修正**：**仅续跑场景可达**——首轮时 T9（Phase 4.5，seq 19）尚未运行，不可能存在「上一轮 T9 报告」。**已移除**旧表述「T9 证据强度评分低」：该写法在首轮时点**必然不可命中**，属占位条件（真源 `phase-order.yaml` `phase1_5_targeted_review.trigger_conditions` 已登记移除）。⇒ 首轮 Phase 1.5 窗口内实际可用的命中项**为第 1/2/3/4 项**）

### 执行流程

```
if 触发条件命中:
    1. 主控 spawn T1b（定向回查子代理）
       任务：回溯 [Dxx] 的一手源（原始统计局/期刊/数据库）
    
    2. T1b 产出：
       - 更新 data/数据卡.md（原 [Dxx] 条目）
       - 添加「回查记录」字段：
         * 原二手源：URL
         * 回溯到的一手源：URL + 数据发布时间
         * 数据一致性：一致 / 有差异（列出差异）
    
    3. 重跑 T2.5 闸门（数据信任级别重新评估）
    
else:
    status.md 记录：
    **Phase 1.5**: not_triggered
    **依据**：任务简报无待复核标记 / T1-T3 产出无🔴标记 / T9 未触发
```

### 未触发也必须记录

**重要**：Phase 1.5 未触发 ≠ 静默跳过。

主控必须在 `status.md` 写入：
```markdown
## Phase 1.5 定向回查

**状态**：not_triggered

**触发条件检查**：
- [ ] 任务简报 [Dxx 待复核] 标记：无
- [ ] 🔴 二手转引标记：T1/T2/T3 产出卡片中无🔴
- [ ] 上一轮 T9 审稿报告指出证据强度不足（仅续跑场景适用；首轮无 T9 报告）

**结论**：Phase 1.5 不触发，直接进入 Phase 2。
```

**为什么必须记录**：
- 审计追溯：T7 能看到「主控检查过触发条件」
- 防止静默跳过：显式记录 vs 忘了检查

## 检索边界

### 论衡能主动采集

- ✅ 已发布的学术文献（PubMed / CNKI / Web of Science 等数据库）
- ✅ 已发布的统计数据（教育部 / 统计局 / 行业协会等公开数据）
- ✅ 已发布的案例与报道（媒体 / 法院判决 / 行业报告等公开案例）
- ✅ 政府发布的统计 / 报告 / 调查 / 政策文件

### 论衡不擅长主动采集

- ⚠️ **一手原始数据采集**：实验设计 / 调查问卷投放 / 用户访谈 / 田野调查 
  → 主人亲自调研，原始数据投喂为「数据源」

- ⚠️ **统计分析**（SPSS/R/Python）：论衡可以引用统计结果，但**不执行统计计算** 
  → 主人用专门工具跑分析，结论以「数据 + 方法描述 + 结果」形式投喂

- ⚠️ **图表原始数据采集**：论衡生成的是**数据可视化**（主控手写 SVG），数据本身需主人提供 
  → 主人用爬虫/OCR 等工具采集，原始数据投喂后论衡制作图表

- ⚠️ **原创图片 / 视频生成**：论衡**不调用** `image_generate`（封面与图件去留均由主人自行操作）；数据图表由主控 `write` 本地手写 SVG。论衡**不能拍摄实物照片 / 录制视频** 
  → 主人拍摄后投喂文件路径，论衡可在文末引用

- ⚠️ **代码执行**：`exec` 在「禁用面（denied）唯一真源」列表（`permissions.md`；frontmatter `denied_high_risk` 摘录） 
  → 主人用专门环境执行，结果投喂为证据

**判断口诀**：问「这个证据是**已发布**的数据 / 文献 / 案例吗」 
→ 是，论衡主动采集 
→ 不是（是一手原始数据 / 自己拍的素材 / 自己跑的计算），主人投喂后再用

## 强相关性原则（防材料堆砌）

### 核心规则

**每条材料必答「它支撑哪个论点」**

- 卡片「与本文的关联」字段必填
- 答不出不收
- 相关性 vs 时效性冲突：**相关性优先**

### 数量封顶

| 类型 | 数量上限 | 说明 |
|------|---------|------|
| [Lxx] 文献卡 | 8-12 条 | 宁缺毋滥 |
| [Dxx] 数据卡 | 30-50 条 | 数据密集型可达上限 |
| [Cxx] 案例卡 | 5-8 条 | 案例是示例，不是堆砌 |
| **总计** | **50-70 条** | 封顶，加一起不超过 70 |

**注**：T3 检索可按需产出更多案例卡，但**正文引用**仍封顶 5-8 条 
→ 检索量 ≠ 引用量

### 反向淘汰自查（交付前必走）

主控在 Phase 5 终检时，逐条问：

> 「删掉这条材料，哪条论点会塌？」

- 无影响 → 砍掉
- 有影响但弱 → 降级为脚注

### 案例卡特别警惕

问自己：「这是**示例**还是**证据**？」

- **示例**：用来说明概念，可替换 → 降级为正文引用，不进案例卡
- **证据**：支撑论点，不可替换 → 进案例卡

## 原创性保证（防重复已公开文章）

### 先行者检索（T1）

T1 文献检索时，除了检索支持文献，还要**主动搜索**：

> 「该主题是否已有公开深度文/论文写过类似核心论点？」

**产出**：先行者清单（`literature/先行者清单.md`）

```markdown
# 先行者清单

## 已发表的相似主题文章

1. **标题**：《XXX》  
   **作者**：XXX  
   **发表时间**：YYYY-MM  
   **核心论点**：[摘要]  
   **与本文的重叠度**：高 / 中 / 低  
   **差异点**：[本文与它的区别]

...
```

### 差异点声明（T4）

T4 分析大纲必须包含章节：

```markdown
## 本文与已有研究的差异

**已有研究**：[列出先行者清单中的 2-3 篇代表作]

**本文差异点**：
1. 角度不同：[举例]
2. 数据更新：[举例]
3. 方法创新：[举例]
```

### G7 原创性审计（T7）

T7 审计时检查：

- **P0 致命**：核心论点与他人重复且**未声明差异点**
- **P1 严重**：差异点声明模糊（「更全面」「更深入」等空话）
- **Pass**：差异点清晰且有实质内容

## 三角验证原则

任何论点必须能映射到：

```
[Lxx] 文献卡 + [Dxx] 数据卡 + [Cxx] 案例卡
```

**最低要求**：至少两项齐全

**特殊规则**：
- 涉及**企业行为/事件**的论点 → 必须配案例卡
- 纯理论论证 → 可只要文献卡，但需在分析大纲说明「为何不需要数据/案例」

**检索不到就标缺口**，严禁编造。

## 时间锚点显式化

### 所有卡片必带年份

- **文献卡 [Lxx]**：作者 + 年份 + 标题
- **数据卡 [Dxx]**：数据点 + 年份 + 来源机构
- **案例卡 [Cxx]**：事件 + 时间窗口 + 主体

### 案例卡额外要求

```markdown
## [C01] XXX 案例

**事件时间窗口**：YYYY-MM-DD ~ YYYY-MM-DD  
**检索截止日期**：YYYY-MM-DD  
**数据时效**：🟢 当前 / 🟡 1-3 年 / 🔴 3 年以上
```

**为什么需要时间窗口**：
- 案例可能有多阶段（爆发 / 发酵 / 判决 / 后续）
- 审计时能判断「作者引用的是哪个阶段的情况」
