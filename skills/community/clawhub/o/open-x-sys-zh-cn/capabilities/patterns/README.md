# 系统模式库

> **何时读**：回路、透视或杠杆找到了一个看着眼熟的结构；这个人说“这是个飞轮”或“这是个恶性循环”，你需要核对；或者你要把一个模式的名字放进揭示里。

很多揭示，是一个人在自己的处境里认出了一个已知的模式：“每个在长大的团队都会遇到这件事”“我们正在做的，就是那两家公司对彼此做过的事”。一个有名字的模式，给了这个人一个可以留下、可以再用的把手。

模式，是一种反复出现的因果结构，它会随时间产生可以辨认的行为。每一页都写明它的**来源**、**怎样识别**，以及**通常在哪里失效**。

## 十个模式

| 模式 | 一句话 | 随时间的典型行为 |
|---|---|---|
| [飞轮](flywheel.md) | 几个环节围成一圈，每一环让下一环更容易 | 起步慢，然后势头越来越快 |
| [网络效应](network_effect.md) | 每个用户都让这样东西对其他用户更有价值 | 难以起步，之后自我增强；赢家往往拿走大部分 |
| [复利](compounding.md) | 增长与已经积累的量成正比 | 很长时间是平的，然后变陡 |
| [强者愈强](success_to_the_successful.md) | 早期领先的得到更多，于是领先更多 | 两条路从一个很小的初始差别分开 |
| [成长上限](limits_to_growth.md) | 一个增长过程撞上了让它慢下来的东西 | 增长，然后停滞或下滑，尽管更卖力了 |
| [饮鸩止渴](fixes_that_fail.md) | 一种见效快的修补，它延迟出现的副作用把问题带了回来 | 缓解，然后更糟地回来，一再如此 |
| [舍本逐末](shifting_the_burden.md) | 一种缓解症状的办法，削弱了真正的解法 | 对快办法的依赖越来越深 |
| [恶性竞争](escalation.md) | 两方各自回应对方的上一步 | 双方投入越来越多，相对位置却没有变化 |
| [公地悲剧](tragedy_of_the_commons.md) | 每个人都从使用一种共享资源中得利；代价由所有人承担 | 总使用量上升，然后资源退化 |
| [移动的瓶颈](moving_bottleneck.md) | 缓解了约束，它就移到别处 | 产出跳一下，然后在一个新地方再次停滞 |

## 诚实地说出一个模式的名字

- **结构必须真的在那里。** 一个模式是一组具体的因果环节。只有你能在这个对象里指出每一环，并且有证据，才说出它的名字。故事上的相似不够。
- **名字不是解释。** “它是个飞轮”要成为一个发现，得把每转一圈都展示出来：什么引起什么，通过什么机制，有多强。
- **说出它通常在哪里失效。** 每个模式都有典型的失效点和典型的干预点。那才是有用的部分。
- **说出哪里不符合。** 真实的系统很少是纯粹的案例。写明这个对象在哪里偏离了教科书上的样子。
- **几个模式可以同时起作用。** 靠飞轮增长、同时正在逼近上限，是两个模式，而有意思的问题是现在哪一个在主导。
- **用这个人的词。** 如果这个模式在这个人的语言或行业里有名字，就用那个名字，并提一下标准的叫法。

## 模式与方法

- **回路**找到反馈结构，并对着这些页面核对。
- **透视**在它的“结构”那一层走到一个模式。
- **杠杆**把每个模式已知的干预点当作候选，再为眼前的系统给它们排序。
- **推演**把模式随时间的典型行为当作最初的投射，再针对这个对象修正。
- **反过来想**问这个模式通常的失效，在这里会以什么样子出现。

## 添加一个模式

这个库是有意保持小的。新模式通过贡献阶梯加入，要有来源、识别的办法、在哪里失效，以及真实的案例。一个人自己反复遇到的模式，可以记在这个人的系统里。
