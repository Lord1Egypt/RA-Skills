# 每日工作日记

## 概述

把"这一天做了什么"沉淀成一篇结构化日记，双通道归档（笔记 + 知识库），形成可回看的连续工作轨迹。

核心价值：**稳定**——同样的触发永远按同样模板、同样格式产出，不靠临场发挥，不会漏章节。

## 首次配置（必读）

本技能**不含任何预设归档目标**——你的笔记笔记本、知识库文件夹都需要自己填。

1. 确认环境变量 `IMA_OPENAPI_CLIENTID` / `IMA_OPENAPI_APIKEY` 已配置（通常由平台注入）。
2. 把技能根目录的 `config.example.json` 复制为 `config.json`，填入你自己的目标：

```json
{
  "note_notebook_id": "",
  "note_notebook_name": "工作日记",
  "knowledge_bases": [
    { "kb_id": "", "folder_id": "", "kb_name": "", "folder_name": "每日工作日记" }
  ]
}
```

- `note_notebook_id` 留空则新建笔记到默认位置（不移动）。填了才会移入该笔记本。
- `kb_id` / `folder_id` 怎么拿：用 `ima-knowledge` 技能的 `search_knowledge_base`（取 kb_id）、`create_folder`（建 folder 取 folder_id）。
- 想归档到多个知识库，就往 `knowledge_bases` 数组里多加几项。

## 触发方式（两路并行）

1. **口令触发**：用户说「写日记 / 写今日日记 / 写日报 / 总结今天 / 今天做了啥 / 每日总结」等 → 立即执行。
   - 未指明日期 → 默认写"今天"。
   - 「补写昨天 / 补写 X 月 X 日」→ 写对应日期；一次可写多天，逐日各出一篇。
2. **被动补写**：每轮新对话开始时，用**一次**标题检索轻量检查"上一天"的日记是否存在；缺失且当日确有实质内容时，在回答完用户当前问题后补写并告知。
   - 检查要轻，不得打断正在处理的紧急主线；判定当日无实质内容则跳过，不做无声写入。

## 素材来源（严禁编造）

素材来自"当日对话记录"，逐日取数：

1. 优先用记忆检索工具（如 `memory_recall`）按日期取当日工作记录；
2. 当前会话上下文（正在进行的对话若属于当天，一并纳入）；
3. 当天上传/产出的文件、知识库条目、笔记，列入"产出物清单"。

**检索不到任何记录**：明确告知"没找到该日的工作记录"，请用户口述要点或确认是否生成空模板；**不编造**任何进展、数字、人名。

## 日记模板（固定结构）

```
# 工作日记 · YYYY年MM月DD日（周X）

> 一句话概览：<当天主线的凝练>

## 一、数字看板
| 指标 | 数值 | 口径 / 备注 |
|------|------|-------------|
| <指标A> | <数值> | <来源 / 同比 / 目标达成率> |

## 二、项目推进
- **<项目/事项A>**：<进展、结论、关键数字>

## 三、关键决策与结论
- ……

## 四、待办与下一步
- [ ] ……

## 五、与助手的协作记录
- <诉求 → 产出>；……

## 六、产出物清单（如有）
- <文件 / 文档 / 知识库条目 / 笔记名>
```

写作要求：
- 条目化、结果导向，一件事一行。
- **数字看板只收录当日确凿出现的量化指标**；当日没有就写"今日无新增关键数字"，**绝不估算或编造**。
- 不确定的内容标注"待确认"。

## 归档流程

1. 按模板把日记写成 `.md` 文件，命名 `工作日记_YYYY-MM-DD.md`。
2. 运行脚本一次性完成多通道归档：

```bash
python3 scripts/archive_diary.py --date YYYY-MM-DD --file /path/to/工作日记_YYYY-MM-DD.md
```

脚本行为：
- **笔记端**：在目标笔记本内**列目录实时比对标题**（标题取 md 首个非空行去掉 `#`）→ 已存在则默认**跳过**（同日不重复写入；`--append` 可追加）；不存在则新建并按 config 移入笔记本。
- **知识库端**：在目标文件夹内**列目录比对文件名** → 同名跳过；不存在则上传。
- 可选参数：`--dry-run` 只检测不写入。

3. 脚本输出 JSON 报告，逐项确认各通道状态；失败按 `references/troubleshooting.md` 排查。

> **为什么用列表接口查重**：`list_note` / `get_knowledge_list` 是实时目录；`search_note` / `search_knowledge` 有索引延迟，刚写入的内容短时间查不到，会导致查重失效、产生重复件。

## 命名与幂等

- 文件与笔记标题统一 `工作日记_YYYY-MM-DD`。
- 同一天重复触发 → 默认跳过已存在项，不产生多篇笔记或多份文件；确需补充用 `--append`。

## 边界

- 只做"日记"，周报/月报/项目专报另行要求。
- 不编造未发生的进展；检索不到就如实说。
- 密钥、账号、证件号、私人联系方式等敏感信息一律不入日记。

## 示例

**示例 1｜口令写当天**
> 用户：写日记
> 动作：取当前日期 D → 检索当日记录 → 生成 `工作日记_D.md` → 跑 `archive_diary.py --date D` → 回报各通道结果。

**示例 2｜补写昨天**
> 用户：昨天忙忘了，补写昨天的日记
> 动作：D = 昨天 → 检索 D 的记录 → 按 `--date D` 归档；若查无记录，先回："昨天没检索到工作记录，你口述下要点，或我先出空模板？"

## 资源目录

- `scripts/archive_diary.py` — 多通道归档（笔记 + 知识库），读 `config.json`
- `config.example.json` — 归档目标配置模板
- `references/troubleshooting.md` — 常见错误码与坑位
