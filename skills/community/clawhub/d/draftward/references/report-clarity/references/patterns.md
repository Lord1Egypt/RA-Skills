# Contextual patterns and counterexamples

These are decision criteria, not global search-and-replace rules. Adapt examples to the actual evidence; example rewrites are not assertions about the user's project.

| Pattern | Diagnose and repair | Retain when |
|---|---|---|
| Hidden reader prerequisites | Introduce purpose before relying on a component, dataset or code identifier. Explain an exported record collection before saying the export. Monospace identifies code visually; it does not define its role. | The preceding explanation already gives the reader what is needed. |
| Unsupported assurance | Unpack words such as safe, automatic, complete or verified into the actual mechanism, responsible actor and established limits. For example, supplied record references do not by themselves guarantee anonymisation. | The mechanism and relevant assurance are already defined and supported. |
| Ambiguous artefact identity | State which specification, dataset, tool or interface is meant. Distinguish a published service description from the language used to express it. Include names without version strings in the check. | A locally established short name is unambiguous. |
| Unclear referent or status | Replace unsupported references such as the study, the library, earlier implementation, or a version with their specific subject when needed. Establish whether a proposed comparison artefact is complete, partial or undocumented. | Its referent and status are already clear. An unperformed comparison alone does not prove the artefact is absent. |
| Sequence and reasoning | Read across paragraph boundaries. Present an initial design, its relevant obstacle, the resulting choice and consequence coherently. Keep setup near results and assumptions near affected claims. | An abstract or conclusion appropriately leads with outcomes; an overview is not necessarily backtracking. |
| Compressed meaning | Unpack phrases that conceal comparison subjects, counting units, authority or responsibility. Explain what a matched comparison holds constant. | The intended audience can interpret the concise wording without guessing. |
| Incidental history | Replace private meeting, semester, drafting or export-negotiation history with the relevant method or limitation. Preserve historical configurations that determine the evidence. | History explains a justified design decision or scope boundary. |
| Relevance and repetition | Ask what each passage contributes to the argument or rubric. Consolidate repeated caveats near the claims they qualify. Remove irrelevant content rather than relocating it automatically. | Repetition provides a necessary local qualification in a different context. |
| Internal navigation | Link consequential summaries to precise evidence or methods; check that the target actually supports the claim. Explain essential meaning locally. | A pointer adds clutter, repeats an adjacent reference, or compromises a self-contained abstract. |
| Authorship and responsibility | State who supplied inputs, chose assumptions, ran analysis or interpreted findings when it matters. A role name is acceptable when it clarifies actual responsibility. | A neutral construction remains clear and does not imply independent review. |
| Visual meaning | Check captions, headers, arrows, legends, units and surrounding explanation. Make intentional contradictory data in a worked example explicit. Distinguish illustrative examples from measurements. | The visual and local explanation already communicate their purpose without duplicate jargon. |

## Calibration examples

- A decision to use offline assessment appears before the obstacle that motivated it. Reorder the causal account; do not invent a motivation or claim the general design became restricted to offline use.
- A conclusion says the experiment used a recorded dataset but never identifies it. Give a descriptive local reminder and, where useful, one precise results reference.
- A test table says an operation finished within its deadline while only one of two items was complete. Explain that the timing rule passes while the count-consistency rule fails; do not change the example's data to eliminate the intended contrast.
- An earlier implementation produced historical results. Name the software and results explicitly. This does not imply inferior performance or that no subsequent assessment exists.
- A short reflection mentions an export without introducing supplied records. Explain the records locally. Do not assume that the reflection's examiner has just read the main report.
- The phrase the compiler follows an explanation of its inputs and outputs in the preceding paragraph. Retain it rather than repeating the definition.

## Twelve conventions to consider

Apply where relevant, with assignment/venue requirements taking priority: prepare readers; use consistent terms; order prerequisites sensibly; write precise prose; clarify responsibility; keep the principal contribution central; give sections distinct purposes; connect conclusions to evidence; manage abbreviations and citations consistently; use purposeful visuals; provide useful navigation; state artefact availability honestly.

Check unfamiliar abbreviations at the entry points readers use independently, such as the abstract and main body, following actual style requirements. Essential meaning should be local; a glossary or appendix is supplementary, not a substitute for first-use context.

These are editorial criteria, not a claim of compliance with any named standard. Consult current primary guidance before asserting a specific venue's citation, first-person, caption, length or formatting rule. A format choice approved for one report does not automatically apply to another.
