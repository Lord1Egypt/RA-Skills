# repair-recipes · 废稿修复 SOP（三套）

> 来源：2026-11-26 三张海报实战提炼（每套均实测通过：目检 + 数值双复验）。何时读：水印修复（生成后必做）/ 乱码文字替换 / 任何「背景局部污染」类废稿救援。
> 定位：让「带水印/乱码的废稿」变成可交付成品的最后一步。修复是本地免积分操作（Pillow + numpy），不消耗 ImageGen 积分。

## 通用前置（三套 SOP 共用）

1. **定位靠目视，不靠深色检测**：引擎水印（混元/豆包右下角「AI生成」+「WORKBUDDY」）在浅背景上是**半透明白色字**，比背景更亮，「找深色像素」扫不到。流程：裁剪目标区域 2 倍放大 → ViewImage 目检给边界框 → 换算回原图坐标。
2. **坐标交叉验证**：目检坐标可能有 1-2 倍坐标系偏差（实测踩坑：乱码实际宽度比目检报告宽一倍以上）。目检后必须数值复核：`np.abs(区域 - 背景参照).sum(axis=2) > 阈值` 扫描确认污染的真实 bbox。**bbox 四周一律外扩 10-15px 再修**（实测踩坑：极淡水印左缘估窄残留半条字痕，形似「刮痕」，被网点纹理冲淡后目检难判——外扩 + 修复后逐列亮度复查「持续亮列」兜底）。
3. **安全检查（动手前必做）**：检测修复区内 `偏离背景 > 60` 的像素数。**必须为 0**（意味着区内无产品色/黑线条/图形元素，只有污染）。非 0 则缩小修复范围或换源区域，防止误伤主体。
4. **留原稿**：修复写入成品文件前，先确认成品是独立文件；重要交付物先备份原稿。

## SOP-1 · 纯色/平滑渐变背景去水印（每列回归外推）

**适用**：水印落在纯色或平滑渐变背景（米白/奶油底、平滑台面）上，区域内无纹理、无产品。

**步骤**（Pillow + numpy）：
1. 在水印上方取干净采样窗（高度 ≥ 40px、同 x 范围；先用标准差确认纯净，`std < 2.5` 为佳）。
2. 逐列线性回归：`slope = Σ((win - win.mean)·(y - ȳ)) / Σ(y - ȳ)²`，`intercept = mean - slope·ȳ`。
3. 对修复区每行每像素：`填充值 = intercept + slope·y`（保留背景自然竖向渐变）。
4. 外扩修复 bbox 10-15px（水印字迹边缘发虚，覆盖不足会留半透明残影）。

**复验标准**：
- 上下衔接差（修复区上邻行 vs 首行均色差）`< 1.5`
- 修复区与采样窗整体色差 `< 3`
- 目检 2 倍放大无残留、无色块边界
- 实测战绩：颈肩星光海报，衔接差 0.43（二次校准后 0.19）

**已知残留问题**：若背景本身带轻微颗粒（`采样窗 std > 2`），回归填充会抹掉颗粒留「光滑感」→ 走 SOP-2 的颗粒叠回步骤。

## SOP-2 · 带纹理/颗粒背景去水印（周期对齐块复制 + 颗粒叠回）

**适用**：水印落在带半调网点/颗粒噪点的台面或背景上（纯色填充会留无纹理光滑块）。

**步骤 A——纹理块平移复制**（网点呈规律点阵时首选）：
1. 源块取**水印同行左侧**同宽区域（同行保证 y 向纹理对齐，台面横向通常均匀）。
2. 周期对齐：遍历偏移量 offset 0-25px，选 `|a[y, 源块最左列] - a[y, 水印左邻列]|` 总差异最小的 offset（网点周期整数倍时差异最小）。
3. 复制源块 → 覆盖水印区，交界 x 处做 6-10px 线性羽化。
4. **注意脚本陷阱（实测踩坑）**：offset 搜索循环的边界条件要先算 `xs = 水印左 - 宽度 - offset` 是否越界再进循环，否则 break 逻辑吞掉全部候选。

**步骤 B——回归 + 颗粒叠回**（纹理为随机颗粒、无严格周期时）：
1. 按 SOP-1 回归填充。
2. 从采样窗提取残差（`win - 回归预测值`，即颗粒本身）。
3. 修复区每行取一行残差（行号平铺 + 小随机抖动）叠加到回归基线上。
4. 复验：修复区**行内标准差与采样窗对齐**（实测 9.3 vs 9.1 参照，差异 <5% 即合格）。

**实测战绩**：琥珀海报（深棕版）网点台面——步骤 A 目检网格连续无接缝；琥珀海报（穿字版）颗粒台面——步骤 B 无痕。

## SOP-3 · 乱码文字替换（擦除 + 重排真文字）

**适用**：AI 生成的小字退化为伪英文乱码（复古卡诗句类），或需替换画面内文字。

**步骤**：
1. **定位**：数值扫描（深色阈值 `sum(RGB) < 330`）扫出全部文字像素的行/列分布；目检给初步 bbox 后**必须数值交叉验证**（实测：乱码 x 范围到 969，目检只报了 412——擦窄了会留半片残留，返工两遍）。
2. **划定擦除区**：外扩至数值确认的真实 bbox；避开缩略图框、大字等设计元素（先数值扫描确认大字顶部位置划下界）。
3. **擦除**：二维平面回归（`f = a + b·x + c·y`，逐通道 lstsq）+ 颗粒残差叠回（同 SOP-2 步骤 B）。采样窗用上方干净带 + 左侧干净带。
4. **重排真文字**：
   - 字体：`/System/Library/Fonts/Supplemental/Courier New.ttf`（打字机风格英文，macOS 自带）
   - 字号：匹配原字高（PIL size ≈ 原字高含升降部 × 1.1）；行距 29-32px
   - 颜色：取原文字色系（深棕近黑 `rgb(41,35,29)` 类）
   - 位置：原行位附近重新排版（可用两段结构：段内行距近、段间距大）
5. **内容**：替换文本从用户输入或 skill 填槽的 {{诗句文本}} 取，不要现场编。

**复验标准**：
- 逐字转写目检：新文字清晰完整、无裁切
- 深色像素扫描：旧乱码位置零残留
- 设计元素无损：缩略图/大字/产品遮挡关系不变
- 实测战绩：深棕版琥珀海报，六行乱码 → 四行真诗，全图复检通过

## 修复流程在管线中的位置

生成 → 验收（负面清单+记忆点三问）→ **本 SOP 修复（水印必做）** → 复验 → 交付 → 新坑回写 gotchas。

> 原则：**没修水印的不算成品**（v0.2.0 起 SKILL.md Step 4 已内置）。云端图像处理（buddy-image-processing erase）可用时优先云端，授权失败时走本文件本地 SOP，两条路都通才算管线稳。
