# 资产负债表日后事项·逐条挂源

给一份财报或公告，把**资产负债表日后事项**读成一张**每条都能回到原句**的登记表：日后事项概况、调整事项、非调整事项、对财务报表的影响、持续经营与审计意见。

日后事项是附注里最容易被读反的一块：有事项不等于要调账，写了事件名不等于归了类。**调整事项**是对资产负债表日已存在的情况提供了新证据——要**调账**；**非调整事项**是资产负债表日后新发生的情况——**不调账，只披露**。两者的会计处理完全相反，写反就是把账调错了。本件逐条登记披露原话，判断留给人。

调整事项与非调整事项只认披露原句，不按事项性质推定；影响金额照抄原句，不自算、不轧差；日期三件（资产负债表日、财务报告批准报出日、事项发生日）分列。

本件不判披露是否充分、不评持续经营能力、不预判审计意见，不给买卖建议、损益预测、评级与目标价。

## 一、零依赖三分钟上手

只装 Python 3，不给任何数据文件，也能跑出一份完整合规的成品，看它长什么样、判据怎么打：

```bash
python3 scripts/check_subsequent_events.py --demo
```

把这份样例存下来再跑一遍机检——它会照七节形制、三元组、归类、影响金额与红线逐条判，应当零发条：

```bash
python3 scripts/check_subsequent_events.py --demo > 样例日后事项稿.md
python3 scripts/check_subsequent_events.py 样例日后事项稿.md   # 打印「结论：五道全过（零发条）」，退 0
```

接着换成你自己那份稿子：

```bash
python3 scripts/check_subsequent_events.py 你的日后事项稿.md
```

退码语义：`0` 五道全过｜`1` 有发条（逐条打印 `码 行号 说明`）｜`2` 缺参数（没给稿子路径，也没给 `--demo`／`--selftest`）｜`3` 读不到文件或空稿。

拿不到成品时，从原文开始的三步：

1. **定主体、报告期与两个日期**，拿到年报或半年报原文（附注「资产负债表日后事项」「或有事项与承诺」、审计报告三处）。
2. **每节抄事实，连原句一起抄**：一条 = 一行，行末挂 `「原句」〔锚：页/表〕[S#]`；披露没写的就写 `未取到：项名`，不留空、不借常识补。
3. **跑一遍自检**，红一条改一条：

```bash
python3 scripts/check_subsequent_events.py --selftest   # 13 档内置夹具自检
```

## 二、五道机检在管什么

| 码 | 名称 | 判什么 | 最常拦住的情况 | 现状 |
|---|---|---|---|---|
| `SE-STRUCT` | 形制 | 头部四件自标逐字在位、`- 主体：`／`- 报告期：` 行在场、七节齐且按序、前五节各至少一条发现行、第六七节不得留白 | 某节只有散文没有发现行；节序被调换；多出一节同名或认不出的节 | 已落字 |
| `SE-QUOTE` | 原句与锚 | 发现行以「」原句＋〔锚：…〕＋`[S#]` 收尾且三元组落在行末；来源行带可点 URL 与检索日；引用的编号须已登记 | 只写「股权转让」没抄原句；正文引用了 `[S3]` 而来源节没有这一号 | 已落字 |
| `SE-KIND` | 归类只认原句 | 登记值与同行原句归属相反即发，并点明两者会计处理相反；登记了归属而原句没有也发；类别位（项名含 类别／性质／类型／划分／归类／归属）拿事件名代替即发；前五节一条归属都没登记，发一次 | 原句写「非调整事项」，登记值写成「调整事项」；类别位只写「销售退回」 | 已落字 |
| `SE-ADJUST` | 影响金额与方向只认原句 | 登记值里的金额在同行原句里找不到可折算相等的数即发（万元×1e4／亿元×1e8／千元×1e3／元×1，相对容差 1e-6，取数前剥掉〔锚〕与 `[S#]`）；「调整／不调整」写反即发。只判「对财务报表的影响」一节 | 登记 9,000,000.00 元而原句是 8,000,000.00 元；原句写「不调整」，登记值写「调整」 | 已落字 |
| `SE-LINE` | 红线 | 买卖建议（建议买入／卖出／增持／减持／建仓／止损）、损益预测（预计影响／预计增厚／预计扭亏）、评级与目标价、确定性断言（稳赚／零风险／保证收益）零命中；节名含「合规红线」「数据通道」的整节豁免；紧邻否定（「本件不给评级」）不算违规 | 正文顺手写一句「预计影响 2026 年利润」；把「建议买入」写进事项行 | 已落字 |

五道现读全已落字，`--selftest` 十三档内置夹具的末行读数是 `自测档数=13｜不合=0｜不可判=0`（含好样零发条一档；形制、锚、归类、影响金额、写反、红线各钉坏样；另有归类反证、折算相等反证、引文反证、边界声明反证——反证档专验「词只出现在「」引文里、或只是本件在划边界时不该发」）。

## 三、三条红线（这件的立身之本）

1. **归类只认披露写的那一类。** 有事项不等于归了类，写了「销售退回」「火灾」「诉讼判决」也不等于归了类——同一个事件名在不同情况下可能是调整也可能是非调整。原句没写归属，正确写法是归类未取到，而不是按事件性质替披露归类。写反的（原句非调整、登记调整）是最该拦的一型：**调整事项调账，非调整事项只披露**，写反就是把账调错了。
2. **影响金额只认原句。** 调整科目、金额、去向都照抄；登记值与原句对不上就发条，不改数迎合、不自行轧差补算。跨单位写法（登记 800.00 万元、原句 8,000,000.00 元）折算相等即算对得上。
3. **调整与不调整不得写反。** 「不调整××年度财务报表」是披露对非调整事项的处理结论，方向取原句，不取本件对该事件的理解。

## 四、数据通道

发现先行，匿名取 live 目录，拿到 `routing` 后再连接发 `tools/list`，以现场返回为准，不硬编码工具名与工具数：

```bash
curl -sS https://cuecue.cn/api/mcp-catalog -o /tmp/mcp-catalog.json
python3 -c "import json;d=json.load(open('/tmp/mcp-catalog.json'));print(d.get('routing') or d)"
# 拿到 routing 后，带 token 发 tools/list：
curl -sS -X POST "$ROUTING_URL" -H "Authorization: Bearer $CUE_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

- **原文腿**：年报附注·资产负债表日后事项、审计报告、期后事项公告与股权转让协议的原文走数据腿；该域是否开放、是否实时，以 catalog 返回为准，本件不承诺。
- **正文腿**：附注常夹在几百页 PDF 里（日后事项明细、判决文书、协议摘要），长附件与扫描件交 `cue-omni-reader` 解析——先取大纲，再按节取用；计费与可用性以服务端返回为准。
- **深研**：`cue-research` 是独立入口，凭据同一把 key。
- 配置页只给指针、不复述开通步骤：数据腿 <https://cuecue.cn/hub/mcp>；解析腿 <https://cuecue.cn/hub/omni-reader>；取 key <https://cuecue.cn/hub/api-key>。

不装通道、没有 key 也能跑：只拿用户直供的附注截图，五块骨架照样出，代价是看不到交易所原文那一路、影响金额明细与判决原文多半缺页，只能登记截图里那几行，证据密度降为单份材料且没有出处可回查。

本件不发请求、不代付费，消耗以服务端返回为准。

## 五、和另外几枚包怎么分

| 你手上是 | 用哪枚 |
|---|---|
| 日后事项的归类、报表影响、持续经营与审计意见 | **本件** |
| 或有事项（未决诉讼、对外担保）与承诺事项本身 | `cn-contingency-commitment-cn` |
| 会计政策变更的性质、依据与追溯调整 | `cn-accounting-policy-change-cn` |
| 审计意见的完整读法、关键审计事项 | `cn-audit-opinion-cn` |
| 债务重组的方式与重组损益 | `cn-debt-restructuring-cn` |
| 外币报表折算差额与折算方法 | `cn-foreign-currency-translation-cn` |

本件只管**日后事项这一块**：或有事项与承诺事项本身归 `cn-contingency-commitment-cn`，同一段披露里本件只登记日后事项那一句；会计政策变更的累积影响数归 `cn-accounting-policy-change-cn`；审计意见的完整读法归 `cn-audit-opinion-cn`，本件只在日后事项涉及审计报告日后补充信息时登记意见类型那一句。同一家公司同时有这几类披露时，各件各管各的节，不互相代填。
