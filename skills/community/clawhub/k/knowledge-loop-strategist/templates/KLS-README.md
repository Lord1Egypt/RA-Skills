## 项目包模板组（KLS-package-*）

八个文件构成一个可直接开工的三方协作项目包（配方方 / 验证方 / 建议方）。

**先分清性质：这八个是成品，不是本目录的说明。**

它们的读者是项目里的三方，不是技能维护者——所以 `KLS-package-README.md` 里通篇讲的是"产品拆解优化作业包"，与 KLS 技能没有字面关系，这是对的。它复制后即包内的 `产品拆解优化作业包（README）.md`，会**跟着包一起发出去，不留在技能里**。

本文件（`KLS-README.md`）才是这个目录的索引。两个 README 不重复：一个管"目录里有什么、怎么复制出去"，一个管"包到手后怎么开工"。

**加前缀只为与本目录其他模板区分。复制成实际项目包时，按下表去掉前缀**——去掉后文件名即与文件内标题一致。

| 模板文件 | 复制后的文件名 |
|---|---|
| KLS-package-README.md | 产品拆解优化作业包（README）.md |
| KLS-package-项目信息.md | 项目信息.md |
| KLS-package-归属与许可.md | 归属与许可.md |
| KLS-package-作业契约.md | 产品拆解优化作业契约.md |
| KLS-package-作业契约.html | 产品拆解优化作业契约.html |
| KLS-package-轮次页模板.md | 轮次页模板.md |
| KLS-package-配对数据册.md | 配对数据册.md |
| KLS-package-判据台账.md | 判据台账.md |

**设计指引不在本目录**：给**非产品拆解**场景设计同类项目包时，读 `references/knowledge-loop-strategist-requirements.md` 末节「项目包构建」（适配性自检、五位置翻译法、八件套迁移要点、两个场景示例）。

它不复制、不填充、只读，所以归 `references/` 而不归本目录。**判定标准只有一条：会不会被复制出去。** 会 → templates；只读 → references。

**开新项目包：一条命令**

```
python scripts/KLS_package_init.py <父目录> [--name 项目名]
```

它会一次做完三件事：建文件夹（名 = 项目名）→ 按上表复制并改名 → 把 `项目信息.md` 第一节的项目名写成同一个名字。**项目名与文件夹名由此保证一致，不靠人工核对。**

默认项目名 `产品拆解优化作业包`；目标已存在时脚本中止，不覆盖。

**手动四步（无 Python 环境时）**

1. **建文件夹，名字就用项目名**（默认 `产品拆解优化作业包`）
2. 把八个文件复制进去，按上表去掉前缀改名
3. 打开 `项目信息.md` 第一节，把项目名改成与文件夹名**逐字一致**
4. 按包内 README 开工

> 复制不会自动按标题恢复文件名——文件系统只看文件名，不看文件里写了什么。所以第 2 步不能省，也不能指望工具代劳。

**关于"文件夹名 = 项目名"**：这条规则从第 1 步建好文件夹那一刻才开始生效。**模板态下没有所属文件夹，规则不适用**——八个文件散放在本目录里，此目录名不是项目名，也不需要是。但第 1 步和第 3 步不能省，否则包一落地就是不一致状态。

**本组是模板态**：项目名为默认值、参与人为空、账本零行。复制后先改名再填内容，不要在模板原件上填。

**版本联动**：本组随方法层同版本维护。方法层升级后，已复制出去的项目包不受影响（快照），新开的包应重新复制。

## 登记规则

**本目录新增任何文件，必须在上面的表格里登记一行，否则视为孤儿文件。**

孤儿文件的麻烦不在于占空间，在于没人知道它是什么、什么时候用、能不能删。一个模板库最后失控，几乎都是从"临时放一下"开始的。

同理，删除文件时同步删掉表里那行——**表与目录必须一一对应**。

**放错目录也是同类问题**：本目录只放"会被复制出去"的文件。只读的方法文档、判定标准、操作指引，一律放 `references/`——它们的读者是要执行任务的人或模型，不是要填表的人。

## 填充说明

1. 占位符统一为 `{{名称}}` 形式，填充后删除占位符与行内注释；
2. 表格字段顺序为契约，不得调整列序；
3. 裁决类字段必须使用三态取值：已裁决/已校验/待裁决；
4. 无法给出依据的时间估计标注"待验证"；
5. 填充完成后运行校验：`python scripts/KLS_validate_position.py <产物> --type <diagnosis|roadmap|verifier|question>`。

## 运行时数据（不在技能包内）

问题资产目录文件由使用者随时指定路径（多册并存；禁止指向技能包内部）；文件不存在时按 KLS-question-asset-template.md 的骨架懒创建；追加只增行不改骨架。数据路径协议详见 references/knowledge-loop-strategist-requirements.md 中 KLS4 域级说明。
