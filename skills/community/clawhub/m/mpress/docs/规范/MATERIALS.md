## 1. 组件化主题库（重点）

### 1.1 gzh-design-skill（甲木 × 摸鱼小李）

- 来源：https://github.com/isjiamu/gzh-design-skill ｜ 说明文：https://www.mdnice.com/writing/66d9721320784dd7bbb3ed1b4c59c25a
- 体量：约 4k star，AGPL-3.0，2026-10 仍在更新；6 套主题 + 主题生成器 + 校验脚本。
- 视觉主张：**主题不是一套配色，而是一套组件库**。每套主题包含「设计变量 + 30 余个组件完整 HTML + 文章骨架 + 文章类型配方 + Markdown 映射规则」，同一篇文章只用一套，不跨主题借组件。
- 可借鉴的具体做法：
  - **三层视觉层级**：锚点层（全文 ≤3–5 处）／标记层（每段 1–3 处关键词）／容器层（引用、卡片、分节条）。这解决了「强调一多就等于没有强调」。
  - **配额写进规范**：橙色锚点全篇 ≤3 处；头图卡全文唯一；暗色收束块只在结尾一次；一篇文章分节样式不超过 2–3 种。
  - **文章类型 → 组件配方**：教程、盘点、观点、数据、访谈、随笔、案例各有一套核心组件组合，保证同类文章气质稳定。
  - **组件编号与语义分离**：各主题编号不统一，装配时按语义找组件，不按编号硬套。
  - **平台红线明确**：全部内联样式；文字节点包 `<span leaf="">`；禁 `<style>` / `class` / `grid` / `position:fixed` / CSS 变量；渐变默认不用（可能触发暗色模式检测）。
- 从源码读到的具体参数（橄榄手记主题）：正文 14px / 1.9，全局 1.75，容器 677px，内边距 8px，区块间距 24px，圆角 6px，几乎无阴影；关键词下划线 2px 实色；图注 13px / 1.7 居中。
- 从源码读到的具体参数（石墨极简主题）：正文 15px / 1.8 / 字距 0.3px，章节间距 56px，水印编号 48px `#E4E4E7`，正文下划线 2px 石墨灰，橙色锚点全篇 ≤3 处，图片 1px 细线框、无圆角。
- 可信度：**A**。源码完整可读，参数与配额自洽，且有校验脚本兜底。

### 1.2 doocs/md

- 来源：https://github.com/doocs/md ｜ 在线版 https://md.doocs.org
- 体量：约 13.5k star，WTFPL，TypeScript / Vue3。
- 视觉主张：**编辑器应该简洁，让作者专注写作**；主题通过主色与 CSS 变量定制，不鼓励堆装饰。
- 可借鉴的具体做法：
  - 主题色单一变量驱动，代码高亮主题独立于页面主题（和本站「代码块由 Shiki 负责，不进页面颜色体系」的判断一致）。
  - 微信外链自动转底部引用（公众号正文不能跳外链，这是硬约束下的产品化处理）。
  - 内置 20+ 代码高亮主题，说明「代码块是独立子系统」，不应和正文强调抢颜色。
- 可信度：**A**（平台适配与工程结构）／**B**（视觉风格偏通用）。

### 1.3 @rbbtsn0w/wechat-markdown

- 来源：https://www.npmjs.com/package/@rbbtsn0w/wechat-markdown
- 视觉主张：**两层样式**——内置主题（tech / grace / geek）+ `customCss` 覆盖；主题负责气质，覆盖层负责品牌。
- 可借鉴的具体做法：
  - 明确列出微信排版引擎的怪癖：`<li>` 周围的换行会产生「幽灵圆点」；class / id 会被清洗，但计算后的内联 style 会保留；外链自动转脚注。
  - 这解释了为什么主题必须以「内联样式 + 结构规整」为前提，而不是先写漂亮 CSS 再指望微信保留。
- 可信度：**B**。文档具体，源码未逐行读。

### 1.4 NoteToMP（Obsidian 插件）

- 来源：SegmentFault 实操文 https://segmentfault.com/a/1190000046852625
- 视觉主张：主题 = `themes.json` 注册项（name / className / desc / author）+ 一份 CSS；自定义主题就是复制一份现有主题改。
- 可借鉴的具体做法：
  - **主题注册表**：名称、类名、说明、作者四字段，和本站 `theme-index` 的做法同构。
  - 作者给出的自定义规范是「标题字号 / 颜色 / 左竖线 / 渐变背景」这类逐项描述，说明社区普遍把主题理解为「元素级配方」，而不是整体设计语言。
- 可信度：**B**。

### 1.5 xiaohu-wechat-format

- 来源：https://agskills.dev/xiaohuailabs/xiaohu-wechat-format/xiaohu-wechat-cover
- 视觉主张：30 套主题，按 5 类组织，先看画廊再用真实文章预览选主题。
- 可借鉴的具体做法：**按内容气质分类**（报纸衬线、霓虹、极简等），以及「用你的真实文章预览，而不是看样张」。
- 可信度：**C**。营销页信息为主，未读到主题源码。

### 1.6 mdnice 墨滴

- 来源：https://www.mdnice.com/
- 视觉主张：在线 Markdown → 公众号，主题 CSS 可在界面中直接查看和导出。
- 可借鉴的具体做法：主题 CSS 直接暴露给用户改，降低了「从模板到自有体系」的门槛；这也是本站 `theme.css` 的同类路径。
- 可信度：**B**。闭源，但 CSS 可见。

## 3. 实操方法论（参数与流程）

| 来源 | 给出的参数 / 方法 | 可借鉴 | 可信度 |
| --- | --- | --- | --- |
| 135 编辑器《公众号排版怎么做？》 | 五步：定风格→理层级→套样式→调参数→手机预览；正文 14–16，小标题 18–20，注释 12–14；行距 1.6–1.8；段距 10–16px；每 5–6 段一张图 | 流程化、先层级后参数 | B |
| 搜狐《公众号排版参数标准》 | 一级 20–24 / 二级 17–18 / 正文 15–16 / 注释 12–14；标题要同时占「字号 + 字重或颜色」两个差异；2–3 千字约 8–12 个标题 | 「差 1px 看不出来，差 4px 才有落差」 | C+ |
| 秀米攻略 | 正文 16，主标题 20–24，副标题 16–18，注释 14；颜色 ≤3；行距 1.75–2；两端缩进 16；一段 ≤5 行 | 缩进与段长的经验值 | B |
| 少数派《排版自动化》 | 字距 0.5px；纵向节奏里「段间距最重要」 | 段间距优先于行距微调 | B |
| 掘金《看过上百个优质公众号》 | 四原则：风格固定、简约美观、结构清晰、重点突出；配色 ≤3；不用斜体；正文 14–17 | 四原则可直接作为验收维度 | C |
| 微信官方《编辑器插件开发规范》§4 | 暗色模式算法保留信息、平衡对比度；渐变会先混合成纯色再转换 | 不用渐变；正文对比度要适中，不要纯黑纯白 | A |

**横向收敛值**（多来源重合，可作为行业基线）：

- 正文 15–16px；行距 1.6–1.8；注释 12–14px；标题与正文差 ≥4px。
- 颜色 ≤3 种；正文不用纯黑；不首行缩进；两端缩进 8–16px。
- 一段 3–6 行；每 5–6 段一张图；标题层级最多 2–3 级。

**分歧点**（必须自己选边，不能取平均）：

| 分歧 | 两派 | 本站取向 |
| --- | --- | --- |
| 正文衬线还是黑体 | 少数派/文学号用宋体；工具号几乎全用黑体 | 公众号正文用黑体，宋体只给引文（原因见草案 §3） |
| 正文 14 还是 16–18 | 精致派 14；舒适派 16–18 | 16px，长文优先可读性 |
| 关键词用下划线还是加粗 | gzh-design 以下划线为标志；石墨用灰色下划线 | 加粗为主，下划线只作低频标记且不用强调色 |
| 章节要不要大编号 | 石墨/橄榄用超大编号；槽边往事几乎不用 | 只用小号实心页签，且仅在顺序有信息时出现 |

## 4. 平台约束（官方 + 实测）

| 约束 | 结论 | 来源 | 可信度 |
| --- | --- | --- | --- |
| 样式 | 只认内联 `style`；`class` / `id` / `<style>` 会被清洗 | gzh-design SKILL、doocs/md 实践 | A |
| 文字节点 | 需 `<span leaf="">` 包裹，否则粘贴后样式易丢 | gzh-design 校验脚本 | A |
| 布局 | `display:grid` 不可靠；`flex` 有限可用；`float` / `fixed` / `absolute` / `sticky` 禁用 | gzh-design 平台红线 | A |
| 外链 | 正文不能跳外链，需转脚注或底部引用 | doocs/md、wechat-markdown | A |
| 字体 | 不能依赖 `@font-face` / 外链字体；只能用系统字体栈 | 小墨鹰、猫啃网 | B |
| 暗色模式 | 背景约 `rgb(36,36,36)`，亮字约 `rgb(230,230,230)`；CSS 颜色会被重映射，**SVG 与图片不反转** | 135 编辑器暗色指南 | B |
| 暗色模式 | 渐变背景会被混合为纯色；对比度过低或过高都会被算法调整 | 微信官方插件规范 §4 | A |
| 暗色模式 | 白底 JPG / 白边截图在暗色下会刺眼；应使用透明 PNG 或避免白底 | 36氪、135、半撇私塾 | B |
| SVG | 暗色下不反转，深色图形会难以辨识；`fill` 建议用中间灰或 `currentColor` | 135 编辑器 | B |
| 历史口径 | `#232323 → #c3c3c3`、`#333333 → #b3b3b3`（2020 年文章，算法已迭代，仅作方向参考） | 腾讯云社区 | C |

**对本站最重要的三条**：

1. 站点 `#f5f7f7` 纸色在公众号里无法作为页面底——公众号画布固定白色。纸色只能作为「块级面」出现。
2. 站点 17 个颜色角色不能原样搬——没有 hover / focus / disabled，`accent` 的「可交互」语义在公众号里失效，必须重新定义职责。
3. 暗色模式是第二套渲染环境，任何依赖「浅底 + 深字」的组件都要先过暗色检查。

## 6. 归纳：一套「体系」由什么构成

从上面材料能抽出的体系构件，不是参数表，而是七件事：

1. **视觉原则**：这个号相信什么（文字优先 / 克制 / 结构服务理解）。
2. **层级模型**：锚点 / 标记 / 容器三层，各自有频率上限。
3. **阶梯**：字号、行高、间距、行宽，四把尺子互相咬合。
4. **组件规格**：每个组件有用途、结构、尺寸、适用场景、禁用场景。
5. **配额**：强调色、色块、大编号、引用、收束块，各有每屏/每篇上限。
6. **配方**：不同文章类型用哪几件组件，保证同类文章气质稳定。
7. **验收**：手机预览、暗色模式、复制粘贴、字号层级，四项可检查。

判断「是不是一套体系」的标准：**换一篇文章，不换规则；换一个作者，产出仍然像同一个号。**

## 7. 对本站可直接使用的结论

1. 采用「三层层级 + 配额」模型，而不是堆组件。
2. 公众号正文改用黑体 16px / 1.8–1.9；宋体只保留给引文，作为「声音」而不是正文。
3. 强调色只保留墨青一个，且只用于章节页签与链接；关键词强调用墨色加粗，不用彩色下划线。
4. 圆角、阴影、卡片、渐变全部禁用，和站点一致。
5. 章节编号用小号实心页签，不用超大 watermark 编号——那是石墨主题的识别度，不是本站的。
6. 文末只允许一个墨青收束块，对应站点的「收束区」。
7. 图片无边框、无圆角；图注 12px 次要色，带「图 01」编号。
8. 封面沿用「墨青刊头 + 白字标题」的构图，主次图共用同一网格。
9. 所有组件先过暗色模式，再谈好看。
10. 主题 CSS 与站点令牌同源，但**不共用变量名**——公众号是独立渲染环境，混用会让人误以为可以互相覆盖。
