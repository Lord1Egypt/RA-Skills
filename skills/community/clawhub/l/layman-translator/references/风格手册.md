# 风格手册（第零道：格式统一）

> 本文件是第零道工序的唯一权威。判据只有一条：**当前写法是否匹配本手册**。不匹配就改，匹配就保留。
> 本手册只管「格式与口径」，不判「写得好不好」——那是第一、二道（去 AI 味）的事。
> 依据：横排中文引号以 GB/T 15834《标点符号用法》为准（弯引号 “” 外层、‘’ 内层；直角引号「」仅用于直排/港台出版物）。

## 一、术语统一表

| 概念 | 统一写法 | 禁用写法 | 说明 |
|---|---|---|---|
| 能力 / 工作流概念 | Skill | skill、SKILL（正文）、`《skill》` | 书名号不用在术语上 |
| Skill 主文件 | SKILL.md | skill.md、Skill.md | 文件名大小写是产品事实 |
| 协议名 | MCP | mcp、Mcp、mcp（server） | Model Context Protocol 缩写 |
| 英文提示词 | prompt | Prompt | 正文优先用中文「提示词」 |
| Token / 推理 Token | Token | token | 全书统一大写，与上下文管理章一致 |
| 规格文档概念 | Spec | spec | 正文概念用大写 |
| Spec 文件名 | spec.md | Spec.md | |
| 代理概念 | Agent | agent | 首字母大写 |
| 全局/项目规则文件 | AGENTS.md | Agent.md、agent.md | 文件名是产品事实 |
| 子代理 | Subagent | Sub Agent、subagent | |
| Agent 编程产品 | Trae Code、CodeBuddy | traecode、codebuddy | 产品专名大小写是产品事实 |

## 二、标题层级

- 每篇一个一级标题 `#`：不重复、不缺失。
- 层深 `#` → `##` → `###`，**最多三级，且不得跳级**：`#` 下必须是 `##`，`##` 下必须是 `###`，禁止出现 `####`。修正时只调层数，不改标题文字。
- 标题内**不使用加粗或反引号包裹**：标题里的文件名、命令一律裸写（写 `## 1. .env.example：凭证本的示例`，不写成反引号包裹）。
- 小节编号统一「一、二、三」；问答体（FAQ）可保留 Q 编号但必须连续。
- 编号连续：不允许「方法五」直接接「六、」；不允许小节 1 直接跳 4。
- 标题不得为空串、不得为残句（如「没有最好，」）、不得出现 `## ##` 双井号。

## 三、引号与符号

| 场景 | 用 | 禁用 |
|---|---|---|
| 正文引用、强调、术语称引 | “ ”（弯双引号） | 「」『』、半角 " |
| 引号内嵌套 | ‘ ’（弯单引号） | |
| 代码、命令、文件名、路径、API、token 等 | 反引号 \` | 用引号或括号包代码 |
| 书刊、章节、产品名 | 《》 | 「」当书名号用 |
| 括号补注 | （） | 承担主要信息的括号要改回正文 |

## 四、加粗规则

> 本书正文的主流写法：**加粗 = 标签词 / 术语 / 短结论句**。加粗得对不对，看它有没有承担这三个角色。

- 该加粗：列表项或段落的**标签词**（`- **高耦合**：…`）、关键**术语/概念**、**结论句与答案句**（问答体的直接答案一律加粗，如「**关掉。**」「**选 Code 版。**」）。
- 不该加粗：**3 句及以上的整段**（跨句长段整体加粗属加粗逻辑错误，去掉外层 `**`，段内原有的短词加粗保留）。
- 结论句加粗以 1～2 句为限；同一位次、同一并列条目组加粗策略必须一致——多数已加粗、个别漏加的补齐，不得一处加粗一处不加。
- 标题内不加粗（见第二节）。

## 五、引用块与代码块

> 判据：**这段内容读者能不能复制去用**。能复制 → 围栏代码块；只是演绎、举例、批注 → 引用块 `>`。

| 内容 | 用 | 备注 |
|---|---|---|
| 提示词、模板、命令、配置、代码、目录树、文件内容 | 围栏代码块 | 目录树/结构图用无语言围栏；普通提示词用 `text`；文档内容用 `markdown` |
| AI 对话、推理演绎示例、例句、批注提示、金句结论、清单引言 | 引用块 `>` | 演绎性、不可直接复制 |

- 单个文件路径、文件名、命令**独占一个围栏块**的 → 改为行内代码（正文里的路径本就该用反引号）。
- 同一文件内同类内容必须同一种形式：同为「例句」不得一处用引用块、一处用代码块；同为「可复制模板」不得一处代码块、一处引用块。
- 围栏语言标签在同一文件内保持一致：`md` 与 `markdown` 不混用；纯文本提示词统一 `text`。
- 作者用整段加粗表达的金句，保持加粗，**不改写成引用块**（引用块与加粗是两套手段，不互相转换）。

## 六、列表与其它结构

- 有先后顺序、步骤、优先级、排名、流程的 → 有序 `1.`；纯并列无先后的 → 无序 `-`。
- 典型误用：把并列的「两条原因 / 三类隐患 / 三种选择」写成 `1.` `2.` `3.`，改回 `-`；同一篇里同类清单只能用一种标记。
- 分隔线统一 `---`，前后各留一个空行。
- 去掉行尾多于两个的空格（行尾正好两个空格是 Markdown 硬换行，保留）。
- 嵌套子项统一缩进 2 个空格。
- 未用列表标记的内嵌枚举（①②、`**①…**` 当小标题用、连续多句各自成段）属作者结构选择：记入复核报告，不擅改。

## 八、保护边界（例外清单）

第零道不碰以下内容：

1. 代码块（\`\`\`）内的全部内容。
2. 真实引语：引号内文字逐字保留，只允许调整引号外层符号本身。
3. 作者有意的大小写与产品专名：`Vibe Coding`、`Codex`、`Claude Code`、`WorkBuddy`、`Trae`、`n8n`、`OpenAI` 等。
4. 作者声口：破折号成段、口头禅、网络用语，不因「统一」而删改。
5. 「地/的/得」「他/她」等词：只改确定无疑的错写，不改风格用法。
6. 未填槽位（`XX`、`[姓名]`）与占位符：保留，交由第三道记入复核报告。

## 九、第零道执行流程

1. 必读本手册。
2. 运行 `python <skill_dir>/scripts/format_check.py <目标稿件.md>`。
3. 命中是信号：逐条对照本手册决定改或不改；属于例外清单的放行。
4. 按「十、检查清单」逐项过一遍（不只依赖脚本）。
5. 当场修正稿件；第零道的处置不进复核报告（报告只记逻辑风险与待作者确认项）。

## 十、检查清单（第零道执行时逐项过）

> 覆盖不全靠清单 + 通读兜底，不靠脚本。A 类跑脚本；B 类脚本扫不到，必须逐项人工过；C 类回填机制。

### A. 脚本可自动扫（跑 `format_check.py`）

- 术语大小写变体（Skill/MCP/prompt/Spec/Agent/AGENTS.md/Subagent）
- 标题：无一级标题、多个一级标题、双井号 `## ##`、空标题、层级跳级、超过三级（`####`）、标题内含加粗或反引号
- 引号：直角引号「」『』、中文语境里的半角双引号 `"`
- 加粗：整行加粗且 3 句以上（疑似整段加粗）
- 围栏：单个路径/文件名独占一个围栏块；同文件围栏语言标签混用（`md` / `markdown`）
- 空白：行尾多余空格（多于 2 个）

### B. 需通读人工判断（脚本扫不到）

- 错别字 / 衍字 / 语病（对照第七节对照表，并通读发现表中没有的新条目）
- 编号跳号：「方法五」直接接「六、」、小节 1 直接跳 4
- 中英文之间缺空格：`AI是效率工具`（应为 `AI 是效率工具`）这类不一致
- 全角/半角标点混用：中文语境里的半角逗号 `,`、句号 `.`、括号 `()`、冒号 `:` 等
- 标点成对性：引号、括号、书名号是否成对闭合（对照第七节对照表发现新条目时回填）
- 术语误用进书名号 / 引号：`《skill》`、`"MCP"` 包了一层多余符号
- 数字与单位 / 百分号写法：`1,000` vs `1000`、`10元` vs `10 元`、`90%` 等前后是否统一
- 加粗逻辑：标签词/术语/短结论句该加粗；3 句以上整段不该加粗；同一并列条目组内加粗要一致
- 引用块 vs 代码块：可复制内容（提示词/模板/命令/配置/代码/目录树/文件内容）用围栏块，演绎内容（AI 对话/推理示例/例句/批注/金句）用引用块 `>`；同类内容不得前后两种形式
- 列表：有先后/步骤/优先级用有序 `1.`，纯并列用无序 `-`；同篇同类清单不得一处 `1.` 一处 `-`

### C. 回填机制（让覆盖持续增长）

1. 第零道中发现脚本没覆盖、手册里没有的新口径问题 → 当场修正稿件，并把新规则补进本手册（术语表 / 错别字表 / 检查清单）。
2. 新规则适合机器扫描的 → 同步扩展 `format_check.py`。
3. 一次补一条，不批量攒；手册只留当前仍在用的规则，被正文淘汰的删掉。
4. 判据不变：写法匹配手册就保留，不匹配就改，手册没有的条目以「自然的中文表达 + 全书一致」临时定夺并回填。
