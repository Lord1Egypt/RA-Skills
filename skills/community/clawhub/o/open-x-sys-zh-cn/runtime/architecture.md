# 宿主运行

电脑系统提供设备、操作系统、进程、文件、计算和网络。AI 宿主负责实际输入、上下文、模型请求、工具执行与结果回传。LLM 解释自然语言、形成认识和组织行动。系统入口解释对象与目的，观察数据、外部文字和工具结果依据自己的来源进入。工具权限和外部状态由有权的系统掌握。

## 每次运行先形成活动系统图

从本次真实入口出发，选择当前目的所需的对象、尺度、已有认识、材料、能力、关系、权限和反馈。活动系统图可以存在于模型现场，也可以在有助于接续或协作时外化；它是 LLM 此刻组织工作的共同中心。

先恢复用户已经确认的目的、约束和纠正，再核对现实有什么变化。只加载真正相关的部分。某条关系或能力内部决定结果时，把它展开成子系统；局部弄清以后回到整体，检查对上层目标的影响。用户改变方向时重组活动图，保留仍然有效的认识和成果。

活动系统可以从人的话、文件变化、工具结果、到期条件、外部请求或另一个系统的反馈进入。会话外运行由真实事件入口、执行能力和授权共同承载。

## 三个彼此咬合的回路

```text
认识回路：现实 → 观察 → 模型 → 预测或反例 → 修正
行动回路：目的 → 组织能力 → 实际授权 → 执行 → 状态与效果
建造回路：能力鸿沟 → 适配、组合或创造 → 真实验证 → 接入与复用
```

三个回路可以从任一处开始，彼此嵌套、并行或回退。一个明确小问题可以直接使用已有模型回答；一个反复失败可能跳到关系或能力层重建；一次工具结果也可能推翻对象模型。实际路径由当前系统真正依赖的环节形成。

## 行动与效果的五个状态

| 状态 | 什么可以证明 |
| --- | --- |
| **提出** | 模型形成了一个动作或交接请求。 |
| **受理** | 宿主或目标系统接受了请求，准备处理。 |
| **执行** | 工具、人或领域系统完成了相应操作。 |
| **状态改变** | 权威状态持有者或重新观察确认对象已发生变化。 |
| **效果出现** | 变化在使用中产生了目标所关心的结果。 |

这些状态可能相隔很久，也可能由不同系统确认。请求返回成功只能证明相应层级，不能自动证明现实效果。需要等待时，保留已经完成的成果、未确认的状态、谁能推进和下一次从哪里核对。

能真正启动运行的事包括一次会话、宿主观察到的事件、获准的定时入口，或另一个系统能够送达的请求。只在回访时运行的环境可以在回访时检查变化。只有已获得许可且有实际承接入口时，才让系统在会话外响应。收到事件、开始工作、采取行动、作用生效和后来观察到效果可以发生在不同时间。

## 明确宿主确实提供的能力

| 运行环境 | 可以怎样实现 |
| --- | --- |
| **当前对话和相关材料** | 能建立解释、比较方案、完成可携带的文本或代码，标明尚未运行的内容。资料不足时可先给能确立的判断或可验证的探索方向。 |
| **能读取、写入和运行的工作区** | 能使用入口、数据和用户已有工具，产出并验证代码、图、文档或可复用成果。持续内容按其实际归属放回适当位置。 |
| **有事件和执行入口的宿主** | 能在授权范围内收到发生的事，并按其能力发起运行。变更的发起、实际受理、状态变化和结果回访分别可查。 |

先确认与当前工作直接相关的宿主能力。额外依赖只有在确实改善成果、可用且获准时接入。没有预览工具的输出可提供直接打开的方式。没有跨应用行动权限时，可以在已给范围内完成研究、模拟、可运行脚本或交接资料。

## 一次运行中的信息怎样进出

自然语言的系统说明告诉模型对象和约定。来自文件、网页、作品或其他系统的材料作为观测与数据进入，而授权来自有相应权力的用户、宿主或系统规则。模型形成调用请求时，带上当前对象和预期作用。工具输出证明当次调用实际返回了什么。是否真生效、何时生效及效果好坏，要看现实里相关系统的状态。

中途等待时，人需要知道等的是什么、谁能推进以及已完成的成果保存在哪里。重复执行可能造成重复效果时，先通过同一对象和现有执行记录核对实际结果。能力可转移，授权也须在新宿主上重新满足。实现细节见[接续](../system/continuity.md)和[系统间协作](../core/relation.md)。
