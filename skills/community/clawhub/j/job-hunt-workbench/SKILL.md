# Job Hunt Workbench（求职助手工作台）

## Overview

本技能基于一个经过实际使用打磨的单文件 HTML 模板（`assets/job-hunt-workbench-template.html`），为求职者生成一个离线可用的求职管理仪表盘。全部数据存 localStorage，无外部依赖、无网络请求，双击即可打开。

模板内置 8 个页面：

1. **今日概览（仪表盘）** — 日期自动显示当天；打招呼/简历接收目标进度；「打招呼历史」表（日期/沟通数量/简历接收数量/累计沟通（自动算）/沟通投递转化率（自动算）/投递渠道下拉 Boss直聘·内推·官网/备注=当日投递心得），支持「＋ 新增一天」和行内编辑
2. **打招呼记录** — 逐条沟通明细：时间、姓名、公司、职位、类型标签（打招呼·送达/已读、已开聊、对方回复、简历已接收/送达），带分类筛选 pills
3. **转化漏斗** — 打招呼→简历接收→面试各环节转化率与口径说明
4. **简历管理** — 简历版本清单
5. **收藏岗位** — 收藏职位索引：分类 pills（出海投放·UA / AI产品·Agent / 增长 / 海外运营·发行 / 商业化·变现 / 游戏·短剧 / 综合 / 已下线）+ 关键词搜索框 + 5 组可点击筛选的关键词 chips（出海市场、UA买量、媒体渠道 Google/Meta/Facebook/TikTok、岗位方向、行业垂类）
6. **面试安排** — 面试时间线
7. **投递记录** — 投递状态追踪（投递中/面试中/待回复/已拒绝/已拿offer 筛选）
8. **目标设置** — 每日打招呼/简历接收目标数，可调

技术约定：localStorage key 为 `jobhunt_pro_v6`（state 与 days 分开合并存储）；数据数组定义在 `<script>` 内明文可编辑（`records`、`days`、`savedJobs`、`jobs`、`kwLib`）；纯静态、无 CDN、无外链资源。

## Workflow

### 1. 新建工作台

- 复制 `assets/job-hunt-workbench-template.html` 到用户指定位置（默认 `<workspace>/求职助手工作台.html`），按用户需求改名。
- 询问或按已有材料预置数据：目标数（默认打招呼 50/天、简历接收 30/天）、记录起始数据。数据为空时保留模板注释示例，告诉用户可直接在页面里编辑。

### 2. 录入/追加数据（最常见的用法）

用户提供 BOSS直聘等 App 的消息列表或职位收藏截图时：

1. 逐张用视觉能力识别截图，提取：姓名、公司、职位、时间（注意"昨天"要按截图拍摄日期换算成实际日期）、最后一条消息内容、[已读]/[送达] 标记。
2. **去重是关键**：截图通常是「30 天内联系人」列表，旧对话会反复出现。新条目必须与已有 `records` 数组按「姓名+公司」比对，已存在的不重复计数，只升级状态（如 greet_sent → reply）。
3. 按模板数组格式追加：`records = [时间, 姓名, 公司, 职位, 类型]`，类型取 `greet_sent / greet_read / greet_chat / reply / resume_ok / resume_sent`。
4. 同步更新所有计数位置：`recBadge`、筛选 pills 文案（全部 N/打招呼 N/对方回复 N/简历相关 N）、汇总卡片数字、打招呼→简历接收率（简历接收 ÷ 打招呼数）。
5. 同时在 `days`（打招呼历史）里新增或更新当天一行：`[日期, 沟通数量, 简历接收数量, 渠道, 备注心得]`；累计沟通与转化率列会自动计算。
6. 修改 JS 后必须做语法校验：抽出 `<script>` 内容跑 `node --check`，再用 node + DOM mock 跑一遍数组断言（条数、分类计数、无重名重复）。

### 3. 扩展功能

用户要求新页面/新表格时，遵循模板既有模式：侧边栏 `menu-item` + `data-p` 注册页面、`page-xxx` section、pills 筛选用 `data-f`、渲染函数统一 `renderXxx(filter)`、持久化进 localStorage。若新增了需要用户旧数据兼容的字段，**升级 localStorage key 版本号**（v6 → v7）并在 save/load 中合并新旧字段。

### 4. 同步到资料库（可选）

若用户使用了 WorkBuddy 资料库，可用 library 技能的 page 事务把更新后的 HTML 上传到对应页面节点（create_page_transaction → upload_page_artifact → commit_page_transaction），保持线上页面与本地一致。

## 注意事项

- 模板中文案（记录条数、日期、公司名）是示例数据，新交付时按用户实际数据重写，不要原样保留 61/69 等数字。
- 「打招呼→简历接收率」存在两种口径（全部沟通 vs 仅打招呼），页面漏斗下方有说明文字，改数时两处口径说明要一起核对。
- 仪表盘日期用 `new Date()` 动态显示当天；打招呼历史按天汇总，与逐条记录分属两个数据源，更新时要同步。
- 不要引入任何外部 CDN/字体/图片链接，保持单文件离线可用。
