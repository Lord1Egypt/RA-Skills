## Description:

Create and reuse a secure shared terminal handoff when a human must authenticate first and the agent must resume work in the same shell session afterward.

This skill is ready for commercial/non-commercial use.

## Use Case:

Developers and operators use this skill when a human must complete SSH, sudo, or browser-terminal authentication before an agent resumes work in the same tmux-backed shell session. It helps avoid sharing passwords, OTP codes, or private keys in chat while preserving terminal state for follow-on work.

### Deployment Geography for Use:

Global

## Known Risks and Mitigations:

Risk: Temporary shared terminal access can expose or compromise a user shell, especially with unsafe token or temporary-file handling.

Mitigation: Review before installing, prefer plain tmux handoff, keep browser modes on localhost, use short TTLs, and harden the implementation before routine sensitive use.

Risk: LAN browser-terminal exposure can allow unintended access if it is used on a shared or untrusted network.

Mitigation: Restrict LAN access with a firewall to one trusted client IP, prefer TLS where applicable, and do not expose the terminal through public tunnels or reverse proxies.

Risk: Authenticated sudo or root shells increase the impact of any misuse or exposure.

Mitigation: Avoid sudo or root shells unless the task truly requires them, inspect the tmux pane before continuing, and ask before destructive actions.
