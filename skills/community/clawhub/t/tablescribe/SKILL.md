# TableScribe 表格智取

把图片、扫描件、PDF 截图、手机拍摄的纸质表格还原成结构准确的 Excel／CSV／JSON，用“视觉读语义、OCR 读坐标、程序化交叉校验做裁判”三路互证，专门解决合并单元格、勾选列、多页续表、数字串位这些通用 OCR 会错的地方。

## 这是什么

- 解决的问题：通用光学字符识别（Optical Character Recognition，OCR）能做整页文字识别，但表格的三个要害它不管——合并单元格的跨度、勾选标记的列归属、数值的列位与行位。错一格，整表作废。
- 产出物：主表（一行一条记录）、列字典、校验报告、还原说明四件套，格式为 Excel（.xlsx）、CSV 或 JSON。
- 与“直接问通用大模型”的区别：通用大模型看图转写会编数字、编行，而且编得通顺；本技能不让它自由转写，只让它回答结构化问题，数值以 OCR 坐标与算术校验为裁判。
- 三路互证：视觉模型负责语义（表头、列归属、合并跨度、单位），OCR 负责坐标（文本块位置、勾选标记字形），程序化校验负责裁判（行列合计、跨页连续性、量级与格式）。
- 验收口径：不看“模型自评读对了”，只看交叉校验是否闭合、每个数值能否指回原图的一个文本块。

## 适用场景

- “我有几张某系统导出的表格截图，要变回能筛选、能透视的 Excel。”
- “扫描件是两页续表，第二页重复了表头，接缝处的行被吃掉了。”
- “表里有合并单元格，直接用 OCR 导出来整列错位。”
- “这是手机拍的纸质表，有反光和轻微倾斜，数字位置对不上。”
- “表格带勾选列（对号／圆点／叉），要判断每行勾了哪几列。”
- “还原完了但合计差一点，我要知道差在哪一行哪一格。”
- “我要把一批同版式的表批量还原，并留下可审计的校验记录。”

## 何时不要使用

- 手写体、严重透视变形、盖章遮挡的表格：识别率不可控，应转人工录入。
- 表格里某一列的含义需要业务判断（该不该算、算多少）：本技能只做还原与校验，不做业务判断。
- 扫描分辨率低于 800px 或字号小于 12px：先重扫，硬抽必错。
- 要直接修改原始数据或补全缺失值：只允许标注缺失，不允许编造填充。

## 工作流

### 1. 图像预处理与分区

- **做什么**：先读像素尺寸与字高估算可读性；再做灰度化、自适应二值化、去噪、倾斜纠正（水平线角度超过 1.5° 即纠偏），按 2 倍 LANCZOS 放大后送 OCR。随后切三段：表头带、数据区、表尾区（合计行／备注／签章）。数据区按高度分片，每片不超过 15 行或 300 px，相邻片重叠 1 行作为缝合锚。
- **判据**：分片行数之和减去重叠行数等于全图行锚数；缝合行在相邻两片文本一致；表头带内检出水平线不少于 2 条。
- **失败怎么办**：切不出表头带 → 先做页面类型判断（数值表／勾选表／纯文字／票据），再决定是否按数据形态反推列；输出被截断 → 减小片高，不要降低分辨率；纠偏后行线仍不水平 → 判为透视变形，转人工录入建议。
- **硬规则**：缩略图拼版（contact sheet，把多张图缩小拼成一张）只能用于页面类型分类，不得用于任何数值读取。已判定含数值的区域，必须回到单张原图、放大 ≥ 1.8 倍、必要时上下切段后读取。

### 2. 表头与列锚点识别

- **做什么**：把表头带单独裁剪放大，只问视觉模型“从左到右每列的完整列名、单位、是否为多级表头”，不让它看数据区；同时用 OCR 取每个表头文字块的 x 中心作为列锚点，用竖线检测的 x 坐标交叉核对。相邻锚点中点之间即为列带。
- **判据**：列带互不重叠；每个表头文字的 x 中心落在其所属列带内；多级表头能拆成“父列—子列”两层，子列跨度之和等于父列宽度。
- **失败怎么办**：多级表头拆不开 → 先按最底层列名建列，父列名写入列字典的 group 字段；无表头（截图从中间开始）→ 用数据形态反推列类型（数字密度、勾选标记占比、文本长度分布），列名标记为“推定”并写入还原说明。

### 3. 单元格切分与 OCR

- **做什么**：用形态学开运算提取横竖线得到网格；无框线表回退到“行 y 锚点 + 列带”的轻量切分。逐格或逐行条带 OCR，保留每个文本块的坐标、文本与置信度。行归属按 y 中心聚类，允许 ±0.4 行高漂移。数字一律用正则从文本块中提取，不做整串强制转换，先做全角转半角、去千分位与货币符号。
- **判据**：每行至少命中一个行锚（序号、名称或唯一键）；行锚数与分片规划一致；置信度低于阈值的单元格进入复核队列并计数。
- **失败怎么办**：网格检测失败（浅色虚线、无框线、合并打乱）→ 改用行条带切分；行锚缺失 → 该行标“无锚”，不得进入主表；通道都读不出 → 该格留空并打 flag，禁止猜值。

### 4. 视觉语义复核

- **做什么**：不让模型整表转写。每片一次调用，任务限定为三类结构化问答：列归属（这段文字属于哪列）、合并跨度（该单元格跨几行几列）、单位与量纲（表头单位与单元格是否一致）。提示词用列字母锚定（A、B、C……），要求只输出 JSON，单元格文字照抄不概括。调用参数固定为温度 0、关闭思考、输出上限给足。
- **判据**：视觉返回行数等于该片行锚数；每行能对上一个行锚；结束原因为正常结束而非长度截断；JSON 可解析。
- **失败怎么办**：输出被截断 → 再分片并降低单次行数；返回行数多于锚点 → 判定编行，删除无锚行并记录；语义与坐标冲突 → 以 OCR 坐标为准，视觉只作列归属参考。

### 5. 数值、勾选与合并单元格处理

- **做什么**：数值列不逐行读，改为“只取该列 x 带内的数字块、按 y 升序排成有序序列、再与行位置逐项对齐”——列内自然顺序即行顺序，可避开跨行串位。勾选列用标记文本块的 box 中心 x 归入列带，用行 y 与标记 y 的距离判定行归属，并区分“空白／漏检／未勾”三态。合并单元格按跨度矩阵处理：文本列可向下或向右填充，但必须记录源行与跨度；数值列默认不填充。
- **判据**：数值列重建后的序列长度等于数据行数（差额必须能解释为空白行或非数值备注）；勾选列的勾选数加未勾数加漏检数等于行数；每个合并区都有跨度与填充策略记录。
- **失败怎么办**：序列长度对不上 → 先查列带是否吃进了相邻列的数字（打印该带内全部文本块坐标核对）；整列无标记 → 不得判“该列无勾选”，回视觉对关键行定点确认；跨度不确定 → 保留空白并打 flag。

### 6. 交叉校验（行列合计与跨页连续性）

- **做什么**：跑三类校验。算术类：行合计、列合计、总计等于分项之和，容差取最小货币单位的半个或 1e-6；连续性类：跨页续表识别重复表头与页脚、序号断点与重号、接缝重复行；形态类：小数位一致性、负号与括号负数、单位一致、相邻值量级跳变超过 10 倍。差额用“合计减其余项”反解到具体单元格。
- **判据**：全部校验闭合；未闭合项必须给出解释（原表本身不平、含税口径不同、四舍五入），并写入还原说明；每项校验都含期望值、实际值、差额三个字段。
- **失败怎么办**：差额无法定位 → 回到该行列的原始像素区做高位放大定点复核；仍不平 → 标“待人工确认”，不得改数凑平；跨页接缝丢行 → 按重叠行重新缝合。

### 7. 导出 Excel（格式规范）

- **做什么**：导出四张表：主表、列字典、校验报告、还原说明。数值写成真数值并设数字格式，不写成文本；表头冻结、首行加粗、列宽按内容设置、行高按该行最长单元格实算（不给固定行高，否则长文本被静默截断）；字体显式指定，不依赖主题默认；日期用 ISO 格式；空值留空，不填 0 也不填占位符；合并单元格导出时拆平为重复值加源行标记，便于筛选与透视。写盘用临时文件加读回校验后替换。
- **判据**：读回文件后行数、列数、各合计与校验报告一致；字体名全部为显式指定值；无公式错误；四张表齐全；单行行高足以容纳最长单元格。
- **失败怎么办**：目标文件被占用 → 另存新名并保留临时文件；读回不一致 → 停止交付并输出差异清单；读回发现数值被存成文本 → 重设单元格类型与数字格式后再读回一次。

### 8. 人工复核清单

- **做什么**：交付前按风险顺序过复核队列：合计行与总计单元格、勾选列、合并单元格区、跨页接缝、单位与量纲、序号断点、无锚行、空白与 0 的区别、源表自身的不平项。每个疑点给出页号、行号、列名、原图裁剪建议、两个候选值与判定建议。
- **判据**：复核队列全部有结论（确认／修正／接受原表）；“接受原表”的项在还原说明里写原因；交付说明写出校验通过率与未闭合项数量。
- **失败怎么办**：疑点超过总量的两成 → 判定该批图像质量不达标，退回补拍或改走人工录入，并列出具体不达标项。

```
1) 表格：CSV（UTF-8）或 Markdown 表，首行表头，空值留空不填 0
2) 校验报告：
```

## 质量门槛

- [ ] **行数守恒**：主表行数等于行锚数；分页表等于各页数据行之和，接缝重复行已去重并记录。
- [ ] **列数守恒**：主表列数等于列模型列数；无空列名、无全空列；推定列名已标注。
- [ ] **算术闭合**：所有声明合计的行与列在容差内闭合；期望值、实际值、差额三字段齐全。
- [ ] **数值可溯源**：每个数值都能指回一个 OCR 文本块或一条视觉定点答案，无来源数值为零。
- [ ] **勾选三态**：每个勾选列给出勾选、未勾、漏检三个计数，三者之和等于行数。
- [ ] **合并有记录**：每个合并区有跨度、填充策略、源行三项记录；数值列无自动填充。
- [ ] **无编造行**：每行有行锚；无锚行数量为零，或已全部标出并排除在主表之外。
- [ ] **导出可读回**：读回校验通过，字体显式、行高实算、数值为真数值、四张表齐全。
- [ ] **疑点零静默**：未通过校验的项全部进入还原说明，无静默丢弃、无改数凑平。
- [ ] **拼版零使用**：所有数值可追溯到单张原图的放大裁剪，缩略图拼版未参与任何数值读取。

## 能力边界

1. **只处理有行列结构的表**：无表头的自由文本、合同正文条款、纯票据字段（金额大写、印章文字）不在范围内。
2. **不承诺手写体与印章遮挡**：手写、骑缝章压字、强透视变形时降级为“结构建议 + 人工录入”，并明确写出降级原因。
3. **不做业务判断**：不判断某个值“应该”是多少、不替用户改数凑平；只做还原与校验。
4. **不引用脱离场景的准确率数字**：验收口径是交叉校验通过率与未闭合项清单，不是模型自评。
5. **不翻译**：外文表按原文字面还原，表头翻译另作一份可选对照表。
6. **图像低于可读阈值时拒答**：长边小于 800 px 或字高小于 12 px，说明补拍要求（正对、去反光、单页单图、字高不低于屏宽的四十分之一）。

## 常见陷阱

- **多层表头只读最下面一行**：导致列名丢层级 → 先重建表头树，再映射数据区。
- **千分位与小数点混淆**：`1,234` 与 `1.234` 在不同地区含义不同 → 按表内其他列的小数位习惯反推。
- **把合计行当数据行**：多算一遍总额 → 合计行单独标记，不进明细。
- **单位只写在标题里**：抽出来全是裸数字 → 每个数值列必须携带单位字段。
