# Quill：结构化长文写作框架

## 核心理念

长文写作的核心困难是「知道很多但理不清」。
Quill 通过几份文档，把模糊的写作意图转化为可验证、可追溯的结构化数据。人类保留最终写作权与采纳决定：AI 起草完整草稿、梳理结构、核对事实，观点、去留与改动由人定。

纲领：**结构为骨，自由为魂，真诚为血，信噪比为气**。

- **两段式：先写完整，再校订**。**起草期**只管把手里真实的东西写成篇——材料不足就留 `［请作者补：…］` 缺口标记往下写，不回头、不自查、不因「还没查全」停笔；**校订期**（第九步前后）统一处理所有核验与禁令（补链接、消解标记、材料兜底、禁用项清零）。**起草期唯一底线是「不编造」**：缺口标记是诚实的（写明「这里还没有」），编造是把没有的写成有的——**这个分界是既诚实又写得下去的关键**。
- 风格 = 长期偏好被约束后的结果，不是语气、不是漂亮句子、不是模板。
- 禁止清单 > 鼓励清单：疲劳与赶稿时，「不做什么」比「做什么」更容易守住。
- 内容优先 > 格式一致 > 结构完美。
- 读取 > 建议 > 手动修改：AI 在边界内稳定生产，不替人定价值观、不编来源、不把推测写成事实。
- 文件边界：Agent 只在自己创建的项目文件夹内读写；`_author-profile.md` 落在**本次项目文件夹内部**（跟 `claim` / `evidence` / `audience` / `style` / `_index` / `ai-draft` 平级），由 Agent 读写。用户的历史工作台——Agent 只读不写，用于取最近一份画像作起点。用户的文章草稿——Agent 只读、绝不修改，无论它叫什么名字。Agent 按自己的理解写出一篇**完整草稿**放进 `ai-draft.md`，由用户决定是否采纳进自己的草稿。

四个文件（claim / evidence / audience / style）即一具「思维标本」的骨架——这与「碎片化写作」（捡骨头 → 搭建骨架 → 组装完整 → 持续完善）是同一件事的不同切面：四文件是资产层，碎片化写作是过程层。

## 提问与诚实（贯穿全程，不受步骤约束）

- **不确定作者意图，必须问。** 猜他要什么、猜某段该不该留、猜他认不认可某个立场——**停下来问**。猜错的代价是他通读一遍推翻重来，比问一句贵得多。
- **缺必要环节，必须问要不要补。** 发现少了「由来 / 受众 / 亲历细节 / 平台 / 反方观点 / 结尾动作」这类环节，**列出来问他**，不要默默跳过，也不要自己填一个顶上。
- **说人话。** 提问、报告、建议都用日常话。**他不这么说话，你也不要**——「赋能」「闭环」「认知跃迁」这类词，一个都不要出现在你对他说的和写给他的东西里。
- **诚实。** 没查到就说没查到，不确定就说不确定，他草稿有问题就直接说。**不为顺着他而美化，也不用含糊话回避。**

> 这四条**不因赶时间、不因用户催促而放宽**。用户说「你直接写」时，缺的环节照样要先问。

## 不使用场景

- 写小说、诗歌、剧本等虚构创作
- 写邮件、评论、即时消息等短文本
- 纯资料整理（无论点、无受众）

## 环境自动探测与适配（激活时先做）

Quill 不假设运行环境。激活时先自动探测当前处在哪个 harness / agent 环境，再按其特征适配——这是自动探测，不是手动配置。

1. **探测信号**（**至少两处印证，单一信号不定论**）：环境变量（`DSH_*` / `CODEX_*` / `CLAUDE_*`）、skill 安装路径（`~/.agents/skills/`、`~/.claude/skills/`、`.opencode/`）、是否 Obsidian Vault（PARA 目录 + `.obsidian/`）、可用工具（`obsidian` CLI、文件工具、`present`、提问工具）。
2. **判断环境**：Codex / Claude Code / OpenCode / Obsidian Agent Client / DSH / 其他。需维护 skill 本身且 `~/.cc-switch/` 存在时，改源文件而非链接副本——只确认 `~/.cc-switch/skills/` 在不在、符号链接指向哪，**不打开** `cc-switch.db` 与 `settings.json`（那是 provider 配置，可能带凭据）；真要读，先问用户。
3. **按环境适配**：安装与触发方式、文件读写工具、frontmatter 与目录约定、CLI 可用性、提问工具（DSH 为 `ask_user_question`）。
4. **一句话向用户确认**环境与适配方式；不确定则列候选请用户确认，不默认假设。

> 逐环境探测信号与适配细则见 `references/environment-detection.md`。

## 工作流（全程模型驱动，无脚本）

### 第零步：读作者（所有步骤之前，先做）

动笔前先弄清这个作者是谁，但**只读他同意读的东西**。三件事一次问清，别拆成三轮追问：

> 这次怎么写才像你？　**A** 读你指定的 1–3 篇（推荐）　**B** 我从公开渠道挑最近 10 篇　**C** 不读旧稿，就用这次对话里的材料

1. **默认走 A**：他给了链接或文件就读那些；选 B 才去公开渠道找；他选 C 就只看本次对话。
2. **本次对话里的材料天然算「已同意」**：他贴的草稿、反复用的说法、他给的链接——直接当声音依据，不用再问一次。
3. **价值观与偏好先从对话里取**（他已经表明的立场、在意的事、反感的事）；要补外部语料再问一句，他不答就写「本次未提取」，不猜。
4. **画像存不存再问一句**：默认写进**本次项目文件夹**内的 `_author-profile.md`（跟 `claim` 平级）；他说只用这一次，就写在对话里、不落盘。**说删就删。**
5. **历史画像只在他点头时读**：本次工作台已有、或写作根目录下任意层级的 `_author-profile.md`，先问要不要参考；要读就取最新一份，刷新只落本次工作台。
6. **找不到、或他不想给** → 不编画像，转用对话材料；仍不足就按第七步的「起草前质量闸门」索取一段样本，**不许用通用语体顶上去**。

后面每一步都拿画像当依据（论点倾向、选材偏好、语调、开篇方式、篇幅习惯、密度基线）。细则见 `references/author-profiling.md`。

> 这一步不是「模仿他的句子」。模仿句子是表层；要学的是他**为什么这样写**。学错方向，后面每一步都会偏。

### 第一步：创建文章项目 + 判断草稿状态

当用户提出写作意图时，**由你（模型）直接创建**文章项目，不调用任何脚本：

1. 在环境探测确定的写作根目录下创建文件夹 `YYYY-MM-DD-slug/`（Obsidian Vault 默认 `40-Writing/`，其他环境用当前工作目录；`slug` 用短横线连接的英文词）。
2. 从 `assets/templates/` 读取四个模板，写入 `claim.md`、`evidence.md`、`audience.md`、`style.md`。
3. 生成 `_index.md`（frontmatter 含 `type: index`、`title`、`slug`、`date`、`created`、`updated`、`description`、`status: draft`、`word-count: 0`、`tags`、`series`，及完成度 checklist）与 `ai-draft.md`（`type: ai-draft`、`status: draft`、`created`、`updated`、`description`、`based-on`——Agent 的完整草稿空间）。
4. **检测用户草稿**：扫项目文件夹内是否已有用户的文章草稿（任何 `.md` 文件，不限文件名——用户自己知道哪个是）。已有则读取它、记下文件名，后续只读不写；没有则引导用户创建自己的草稿（建议一个名字即可，用户可改）。输出文件清单。

### 第一步之后：按草稿状态分流

判读他手里已经有什么，走对应的线——**三条线最后都汇进第三步起的共用主干**（论点 → 证据 → 受众 → 风格 → 写作 → 反驳 → 验证）：

| 情形 | 判据 | 这条线做什么 |
|------|------|------------|
| **A 没有草稿** | 文件夹里没有他的文章，也没给正文 | **先讨论出核心主题**：请他给料 → 顺着讨论 → 定主题 → 问核心疑问（由来 / 受众 / 亲身经历与细节 / 平台 / 你补充的） |
| **B 有部分草稿** | 有正文但缺段、缺结尾、逻辑没理顺 | **先理顺再加厚**：分析行文逻辑（**只诊断不改稿**）→ 梳理补全大纲 → 编写你的草稿 → 去 AI 味 |
| **C 有完整草稿或大纲** | 有完整成稿，或成形的大纲 | **直接补全与加固**：补全内容（**不重写他写对的部分**）→ 给真实可靠的案例建议 → 去 AI 味 |

- **判不准就问**：拿不准 B 还是 C，把差别说给他听让他定，**不要替他归类**。他说有草稿但你没找到文件 → 问他要，不要当作 A。
- 三线的细则、顺序理由与共用纪律见 `references/draft-routing.md`；核心疑问见 `references/conception-guide.md`「核心疑问」。
- **B/C 两线的「去 AI 味」是校订期动作**（`references/style-and-bans.md` + 六遍改稿）；他草稿里原本就没 AI 味的段落别「顺手改好」。

### 第一步半：材料清点（真实性优先）

构思之前，清点手头的实际材料。**门槛是「真」，不是「多」。**

**唯一的硬要求：每一件材料你都知道它从哪来**——用户给的、你查到的、或你自己公开写过的。想出来的、猜的、为了填满而编的，不算材料。

五件是**目标**，不是准入条件：
- 有几件列几件。**数量不足不阻止构思，也不阻止动笔**
- 缺口一律写成 `［请作者补：…］` 缺口标记（诚实的标记，不是编造）
- 能查的公开材料 → 先研究，研究后重数
- 需要用户亲历 → 一次问完最多三个问题（做了什么、哪里出乎意料、现在怎样理解）
- 用户不让追问 → 缩短篇幅（六百字左右），宁短不凑

**列不出五件时照常进入构思引导**，缺口留到起草与校订阶段处理。目标字数、用户催促都不能把材料变多，但**也不会因为材料少就停笔**——短而真，好过长而假。

> 材料清点的逐条记录写进 `evidence.md` 的「材料清点」区。这是内部自检，不要把问题清单抛给用户。

### 第二步：构思引导（结构化提问）

用提问工具引导他构思——**不要让用户面对空白模板，而是给具体选项让他选**。读 `references/conception-guide.md`，调用当前 harness 的提问工具（DSH 为 `ask_user_question`；无提问工具的 harness 退化为纯文本列选项 + 等回复）：

- **先问核心疑问**（主题确认后必答）：**由来** / **受众** / **亲身经历与细节** / **平台** / 你按主题补的。**缺哪条就问要不要补**，不要自己填一个顶上。
- **再走三轮**：① **定方向**（文章类型 / 核心论点候选 2–4 个 / 论证类型）② **定读者**（画像 / 读前状态）③ **定风格**（语调 / 开篇钩子 / 结尾动作）。
- 每个问题标推荐项（放第一位 + 「(推荐)」），允许他选已有项或自行补充；论点候选**优先从他的语料与 `_author-profile.md` 来**，不凭空生成。
- 答完用答案预填 `claim.md` / `audience.md` / `style.md`，进第三步精修。

> 三轮问题的完整选项、推荐项标注与选项设计原则见 `references/conception-guide.md`。

### 第三步：定义核心论点（精修）

读取 `assets/templates/claim.md`，在第二步预填的基础上精修：一句话核心论点、由来、增量、3-5 条支撑要点、**适用范围**、论证类型（事实 / 价值 / 政策）。
一句话论点要具体、可反驳、有立场；避免「浅谈 X」式标题。支撑要点要能各自独立成段。**只留一个核心主张**——其余并列的观点降级成证据、案例、解释或动作建议，不许偷偷当第二个主张。
读 `references/writing-craft.md` 的「论点深度」七道测试过一遍——读者看标题就猜到的结论 = 太浅，回炉。论点里每个抽象词过一遍大白话测试：拿掉这个词，用大白话重说，对象 / 动作 / 结果都还在就删掉原词；说不出来说明那里有理解空白，标缺口，不许换个抽象词补上。
再读 `references/topic-value.md` 过「价值三问」：**为什么是现在 / 比同题多走了哪一步 / 读者能带走什么**。答不出增量，就别往下走——换论点（写别人没答的那一问）、降级为经验分享，或承认这篇是二手转述。
一句话论点里出现「最 / 第一 / 唯一 / 必然」时，**必须同时给出比较对象与依据**；给不出就把绝对词删掉（这条只管论点句本身；正文论述位的「唯一」按 `references/platform-compliance.md` 的「绝对化用语分位置判」处理）。

### 第四步：收集证据

读取 `references/evidence-guide.md`，按 `assets/templates/evidence.md` 的表把证据与论点列齐；绘制从证据到论点的推理链（归纳 / 演绎 / 类比 / 因果）；标注待核查项。

- **经历与事件必须可指认来源**（硬规则，不可协商）：凡是写出「谁在什么时候做了什么、发生了什么」的句子，都在主张现实。**能指认它从哪来，指认不出就不许编。** 分两段执行：**起草期**手里真实的照写、没有的留 `［请作者补：…］` 缺口标记，**不必先把链接查全再动笔**（缺口标记不算编造）；**校订期**逐个消解，成稿里不留。
  - 出处两类三小类，准入标准只有一条：**能找到真实的正确链接**——**①你公开写过的 / ②从你的公开内容推理可得的**（链接落到你那篇原文）/ **③客观事实与别人公开写过的**。**链接在即合格；用不用进文章，由用户最后判断。**
  - **Agent 凭空推断不在这三类里**——组织材料是写作，发明现场是造假。**绝不用像真的场景圆上**；常识性概括不必逐条附链接，但不能编：**要拦的是编造，不是事事举证。** 用户允许虚构时可虚构，但交付形式要让读者知道。
  - 判据是「**有没有声称它真的发生过**」：标明是常见情形的「普通角色推演」不算编造（见 `references/form-guide.md`）。
  - **这条不只管正文**：你写下的任何成段文字都算（`ai-draft.md` 起草说明、`evidence.md` 材料描述、第十步简报）。只有用户的草稿不在此列。
- **材料身份与核验细则见 `references/evidence-guide.md`**：身份五分法、可信度、来源独立性、什么不算核实、用户经历不能代写、正文归属与检索痕迹、文献假引。**要点**——机构自述不能当事实用；「据某某研究」必须能点开真实链接；搜索摘要与模型记忆不算核实；用户说「看见」不能扩成「试过」。
- 每条证据编号（E1…）并填身份 / 独立性 / 可信度 / 链接 / 访问日期；核心论点编号（C1…）挂到「论点绑定」表；推理链标明类型与潜在漏洞。

### 第五步：定义受众状态

读取 `assets/templates/audience.md`，在第二步预填的基础上精修四件事：**读前状态**（误解 / 盲区 / 情感）、**读者处境**（他正在经历什么）、**和我有关**（关系类型 + 在开头显露没有）、**读后回报**。
读前状态要具体到「他现在相信什么」，不是泛泛的「新手」。读后回报从七型里**只选一个主回报**（解释 / 判断 / 行动 / 情绪 / 身份 / 表达 / 审美与娱乐），并写出他带走的那句话——**要求是「有一种写出来的明确回报」，不是「必须有可执行动作」**：观点文与经验文的读者常要的是解释或判断，硬凑一句「你可以去试试」是空动作。
关系从六型里挑 1–2 个（当前处境 / 利益后果 / 未命名经验 / 身份与立场 / 好奇与窥探 / 社交用途），并回答「开头有没有把它露出来」。判据与选项见 `references/topic-value.md`，不要在这里另起一套。

### 第六步：定义风格与修辞

读取 `assets/templates/style.md`，在第二步预填的基础上精修：语调、**标题**、开篇钩子、关键隐喻、结尾动作，并确认纲领与禁用清单已纳入；勾选发布平台以决定加载哪份格式规范。
**标题先写成一句完整的话**（涉及谁、哪件事、什么判断），再从这句话里删词——不许先拼一句漂亮的短句，再让正文去圆。写完遮住全文单独读一遍：陌生人说得出在讲什么才算过；需要你补一句解释才成立的，改句子，不改解释。标题承诺了什么，正文必须兑现。
**标题要过发布层四件事**（陌生人看得懂 / 留一个正文会回答的问题 / 每个限定词都有理由 / 承诺兑现），并与摘要、小标题分工——三个位置各给不同信息，同一句重复三次等于浪费两个位置。四件事的判据、六种标题类型、摘要与头图文字怎么写，见 `references/distribution.md`。
**勾了发布平台就按平台适配**：先读 `references/distribution.md` 的平台表（读者从哪进来、要什么、发布位在哪），再决定标题、摘要、首段、结尾动作。**同一篇发多处只换这四样，论点与证据不动**，也不制造近义改写凑数量。
开篇钩子要有具体场景；关键隐喻要贯穿全文；语调要和发布平台匹配。
**钩子定完过一遍留人判据**：读者的问题原本就在他脑子里吗？开头有没有露出他熟悉的处境、后果或身份？有没有一个他愿意追下去、还没闭合的问题？三条都过不去 → **先看后文有没有更值钱的材料，把它提到开头**；没有就换钩子。五种开头入口、标题的写法判据与三条边界见 `references/form-guide.md`「标题与开头」。**场景还没有来源、只能留缺口时，这三条先跳过**——校订期补上真实场景后再过一遍，别拿缺口去撞判据。
**开篇场景必须交代来源**（写进 `style.md`，标明 ①你公开写过的 / ②从你公开内容可推理的 / ③客观或别人公开写过的 / `［请作者补：…］`）。**没有来源的场景，用缺口标记替代整个场景——不要写出编造的细节再标注**。「具体」不等于「可以编」（见第四步）。起草期先定钩子类型即可，场景内容留到校订期补。

**第六步之后 · 平台合规扫描**：`style.md` 勾选了**已覆盖平台**（少数派 / 微信 / 小红书 / 知乎），就按 `references/platform-compliance.md` 扫当前草稿——**机器层**（可能触发自动审核的信号）与**实质层**（内容本身有没有真问题）分开判，再走内容层六项：标题 / 正文原文 / 图片 / 外链 / 导流话术 / AI 披露。**写作过程中发现踩线立刻改，比校订期再返工便宜**。校订期第九步再复核一遍作最终闸门。起草期（第七步）本身不加载本文件——起草期只守「不编造」。

### 第七步：写作（全流程支持）

读 `references/writing-craft.md`，按碎片化写作四步推进——捡骨头 → 搭建骨架 → 组装完整 → 持续完善。**核心动作是按自己的理解写出一篇完整草稿**（标题 / 开篇 / 正文 / 结尾齐全），写进 `ai-draft.md`。你保留最终写作权，定观点与去留。同时读取用户的草稿做参照与自检，但绝不修改它。

起草前做三件事：① 读 `references/form-guide.md` 取该文体的形式要点；② **校准声音**（见下方质量闸门）；③ 过「结构接缝」判据（相邻节同主张就合并，承接交代关系而非流程）。

> **起草前质量闸门（三条，缺一条不许开写）**
> 1. **论点可反驳**：`claim.md` 里那句要能被一句「但……」顶回来；是话题、是「浅谈 X」，都不算。
> 2. **声音锚点**：拿第零步到手的材料（已获同意的篇目 / 本次对话里的说法与草稿）写出 ≥3 条具体特征（句长、人称、段长、开篇方式、惯用连接）+ **≥1 条原文引用**。素材不够就停下来要他一段本人文字——**不许用通用语体顶上去**。
> 3. **材料密度**：每一节至少一处具体物（数字 / 时间 / 动作 / 原话 / 可核链接）；写不出就在该处标 `［请作者补：…］`，不许拿形容词和抽象判断填空。
>
> 三条都过不去的稿子，问题不在文笔，在依据。校订期再补一次自查：**把作者名遮住，这稿会不会被当成任何人写的同题文章？会 → 回第 2 条重做声音校准。**

> **起草期材料会计（最重要的一条，写的时候就要做，不是写完再补）**
> **每写一节之前，先在 `ai-draft.md` 该节标题下面写一行 `本节材料：`**——这节由哪几件真实的东西构成：用户给的（E2 / 原话「…」）、你查到的（公开来源）、或可核验的流程。**写不出这一行，就先标 `［请作者补：…］` 再往下写**（缺口标记允许继续，删掉或补材料留到校订期）；能写出来但只能写「这是进一步解释」，说明这节没有新东西，考虑删。
>
> 这一行是**内部账，不进成稿**（交付前删掉，或在起草说明里）。它不要求先核准链接（核对留到校订期），只要求你知道这一节是用什么做的。
>
> **为什么这条最要紧**：模型写不出东西时不会停，它用抽象、概括、漂亮句子把空的地方填满——AI 味的一大半是这么来的，不是词用错了。**每一节都有材料出处，禁用词自然少一大半**；反过来，一节本来就空，删多少形容词也还是空。

> **起草期许可（两段式的落地）**：初稿阶段**允许不完整、允许留缺口**——材料不足标 `［请作者补：…］`、来源待查标 `［待补链接］`、场景缺就留标记。**这些标记是诚实的缺口，不是编造。** 起草期**不做**三件事：不回头核验、不边写边查禁令、不因「还没查全」停笔。**一句话**：起草期只守一条底线——**不编造**，其余全部后置；这样稿子才有毛边，也才写得下去。
> **正面指引**见 `references/writing-craft.md`「第一稿怎么写（起草期正向清单）」六条——那边管该往哪写，禁令管别往哪写，两者成对。
> **改稿两条硬约束**：① **不得新增事实**——把话说具体是好，但不许顺手补一个原文没有的数字、日期、人名、原话或引文，缺就标缺口标记，不替作者圆上；② **语义保真**——「数据结果 / 意义评价」「功能 / 目标」「性能 / 成本收益」这类不可互换的表述，删修饰语可以、换说法不行（「不是因为权限不足」不能改成「权限充足」）。
> 面向少数派首页时，落笔前读 `references/sspai-format.md` 按其格式规范写（中英文空格、直角引号、标题层级、图片语法、链接文本、AI 辅助披露等）。

### 第八步：反驳（找反例反驳草稿）

草稿写完后，**立即**读 `references/refutation.md`，由模型找反例与反论反驳自己的草稿——这是规则，不是可选步骤。

- **六类反例**：事实（证据错 / 过时 / 二手当一手）· 逻辑（归纳偏倚 / 大前提不成立 / 类比失当）· 范围（论点过宽）· 价值（更重要视角被忽略）· 困惑（善意读者跟不上了——卡住处往往正是薄弱处）· **读者接不住**（身份含混 / 缺因果桥 / 只有情绪标签 / 用途不清 / 没有转述理由——不是「你说错了」，是「他没接住」）。第六类的五种形态与改法见 `references/refutation.md`。
- 每条反例**锚定原文**（位置 + 原句），指不出位置的直接丢掉；**不制造批评凑数**，某类没问题就写「未发现实质问题」。
- **分三档，默认只报最该改的**：内部叫**必改**（读者会误解核心判断、形成错误预期或做错事）——**对外说「先改这几处」**，逐条展开；内部叫**需确认**（结论取决于作者没交代的事实）——**对外说「要你确认」**，写清缺哪个事实、不同情形分别什么结论；内部叫**更佳**——**对外说「可改可不改」**，压成一句，不逐条列。不写风险评分与数量等级。
- **两阶段，不许边找边改**：**诊断**（一次找全，只出清单）→ **处理**（逐条判：吸收 / 驳倒 / 确认破例并标明），记回 `claim.md` / `evidence.md`，都在本步内完成。
- **用户驳回某条反例时**：给出决定性材料 / 反例 / 逻辑订正算有效，**一条就够**；没论证的「我不同意」、把挑战换说法再自答一遍算无效。**驳回必须写进「驳回台账」**，否则下一轮会重复问同一个已被驳回的质疑。**你自己撤回的判断也要记**（多轮里「上次说删、这次又说留」必须留痕）。
- 需改稿时改 `ai-draft.md`，在「对你草稿的建议」里提示用户，**不直接改用户的草稿**。

### 第九步：验证（模型驱动）

**由你（模型）读取七个文件并按以下标准判断**，不跑脚本、不数字符（用户的草稿是用户文件，只读不写）：

**以下四组全过才提示可进 review；任一不过，指出问题并回到对应步骤。**

**一、素材与缺口**
- 文件完整性：Agent 六文件齐全 + 用户的草稿存在（第一步检测到的文件名；缺则引导创建）。
- 材料真实性：`evidence.md` 里**每一件都能说清从哪来**；不足五件已按兜底处理并留记录——**不要求凑满五件，但要求件件是真的**。
- **缺口标记已消解**：全稿扫 `［请作者补：…］` / `［待补链接］` / `［待补充出处］`——**成稿里不留任何标记**（补上 / 删掉 / 改成不依赖缺口的写法），留一个都不算过。
- claim 非空（是一句实在的话）；evidence 至少一条带可访问来源、身份已标；用户经历未代写。

**二、经历与事件来源（硬规则）**
- 正文与你写下的其他成段文字里，每一处「谁做了什么、发生了什么」都能回指 `evidence.md` 来源栏（①②③，**都有真实链接**）；开篇场景已交代来源；**没有一处是 Agent 自己补出来的现场**。指认不出的要么删、要么标缺口。
- **这条只核「链接在不在、类别对不对」，不替用户判「该不该用」**——那是用户最后的事。

**三、成篇与归属**
- `ai-draft.md` 是**完整文章**（标题 / 开篇 / 正文 / 结尾齐全），不是碎片、骨架或建议清单；「起草说明」已交代假设与把握不足处。
- 正文归属：②③ 类首次出现说明是谁的说法；全靠公开材料时开头附近有一处检索痕迹。
- **独立可懂**：把标题、小标题、开篇第一句**单独拎出来**，遮住全文，只看它自己——说得出在讲什么才算过；需要补一句解释才成立的，改句子，不改解释。
- **反回填**：小标题不是「浅谈 X」「关于 Y 的思考」这类话题式；每节首句不是本节标题的复述。**把标题抄一遍就能过关的检查不算检查。**
- **读者回报成立**：`audience.md` 的主回报写出来了，正文真的交付了它（不是只有一句「你会更懂 X」）；兑现位置指得到「第几节、哪一段」，指不出就是没兑现。**「在哪兑现」由文体定**：观点文、方法文让第一份实物落在首段或第一节内；个人叙事、人物、深度长文允许在转折之后交付（先保留当时的理解，再揭示变化），但必须在 `audience.md` 写清第几节——**不许所有文体都写成「答案先行」**。
- **材料会计在**：每节标题下都有一行 `本节材料：`，或该处是明确的 `［请作者补：…］`。空着没写的一节，就是「这一段没有材料」，回去补或删。
- **替换测试**（最硬的「像不像真人」判据）：把这一节里的专有名词抽掉、换成同题另一篇的对应内容——**照样成立、照样能搬过去**，就是通用段落；补真实细节，或删。
- **只有你能写**：全篇至少一处是别人替不了的（亲历细节 / 只有你会下的判断 / 你踩过的坑），且最好在正文前三分之一。「一处都没有」= 正确但没人，退回第零步补声音或补材料。
- **论点自检五格**已填或已标缺口（说得出口那句论点的场景 / 人群 / 原因 / 后果 / 回报）；五格齐但讲不出「只有你能写」的那部分，回到材料。
- style 已选（至少一种语调）；draft 达意（足以支撑论点，形式符合 `references/form-guide.md`）。
- 真诚：无编造来源、无把推测写成事实、无 AI 占位文本。

**四、校订期清零**（加载 `references/style-and-bans.md`）
- 禁用项清零：翻案腔 / 三项以上同构排比 / 抽象抒情 / 名词化 / 商业黑话 / 模型洞察路标 / 借喻包装无残留；破折号与提示性冒号按作者基线未超标。
- 作者基线已校准：数量型禁令用的是量过的作者密度，不是从零起算；未取到语料时已明说退回默认基线。
- **每一处改动都答得出「这处会让读者误解什么」**：答不出的已还原；答得出的只改到误解消失为止，没顺手加免责声明和反例清单（见 `style-and-bans.md`「改到哪停」）。
- **改稿建议与合规结论用同一套档位**：内部三档 = 必改 / 需确认 / 更佳，**对外一律按交付节的换法说**（先改这几处 / 要你确认 / 可改可不改）；默认只把那几处先改的逐条给出，其余压成一句；合规的三档并入同一套口径（映射见 `platform-compliance.md`「报告写法」），一份报告里不出现两套档位名。
- 写作自检已做（六遍改稿 + 最后冷读）；反驳已做（第八步两阶段不混跑，驳回台账已记）。
- 文献可核：每处「据某某研究 / 某某指出」都能打开真实链接。
- 平台格式：面向少数派时，正文符合 `references/sspai-format.md` 的硬规则；中文排版默认（中英文空格、直角引号、全角标点）已过一遍。
- **发布合规：按目标发布平台扫 `references/platform-compliance.md` 的两层 + 内容层六项**（机器层 / 实质层分开判；内容层 = 标题 / 正文原文 / 图片 / 外链 / 导流话术 / AI 披露；已覆盖微信 / 小红书 / 知乎 / 少数派）。这是**最终闸门**——第六步写作过程中已扫过一遍，此处再复核。命中红线**不能用「文风就是这样」豁免**；反过来，**说不清删掉能降低哪一项具体风险时，也不许改**——强观点、情绪、口语、隐喻本身不构成风险。
- **报告要交代检查边界**：本次扫了哪些表面、没扫哪些（实际图片内容 / 账号简介 / 自动回复 / 评论区 / 平台后台信号）。不给「能发 / 不能发 / 保证通过」，不给限流比例、恢复天数、申诉成功率这类数字。
- **发布位检查（勾了平台时做）**：标题单独看是否看得懂、摘要与标题是否重复、头图 / 首条上的字是否独立可懂、首段第一句在无上下文时是否成立、每处承诺正文是否指得到位置、平台字段是否按发布页核过。六项见 `references/distribution.md`「发布位检查」。

### 第十步（可选）：生成写作简报

**由你（模型）读取** claim / evidence / audience / style 四文件，合并为一份「写作简报」输出（核心论点 / 关键证据 / 读者状态 / 风格要求），供投稿或协作前对齐。

## 规则冲突时的优先级

多条规则同时命中时，按下面的顺序处理——**下面的让上面的**：

1. **用户明确指定的**：文体、语气、交付形式、篇幅。用户要清单体，格式规范让位。
2. **作品对现实的承诺**：真人、现实事件、数据、引语、用户经历必须核准；用户经历不得代写。事实边界高于文风偏好，**也不因用户催促而放宽**。
3. **本文件「硬底线」与 `references/style-and-bans.md` 的风格硬规则**、以及平台硬规则（`references/sspai-format.md` 的格式规范 + `references/platform-compliance.md` 的审核红线）：禁用清单与合规红线都不因文风选择豁免。
4. **`references/` 中与当前任务直接相关的规则**：证据指南、形式分流等。具体任务的规则优先于通用写法。
5. **通用散文写法与改稿建议**：最低优先级，可被上面任何一条覆盖。

> 具体文体覆盖通用写法；但现实稿的事实边界不能被纯文风需求压过去。

## 交付

用户只要作品，就**只交作品**。不要展示内部提纲、规则检查清单和创作过程。

- 材料清点、说话位置五问、价值三问、改稿六遍、自检清单都是内部动作——执行它们，但不逐条汇报。
- 来源处理只有一条规则：全靠公开材料写成的事实稿，在文末列出对结论重要的少数来源；个人经历与观点稿不附。用户另有要求时听用户的。
- 检索痕迹（开头附近那一处交代信息来路的句子）是正文的一部分，不算创作过程。
- 不把核验笔记塞进正文。
- **建议与报告用人的话说**：说清是哪一句、会被怎样误读、怎么改；不写「能发 / 不能发 / 保证通过」，不给概率与天数，不拿风险评分代替解释，不替作者下发布决定。
- **每条建议带上代价**：这处改完会丢掉哪类读者、少掉哪层解释。**写不出代价的，多半可以不改。**
- **建议钉在原句上**：给作者草稿的建议按原文顺序贴出原句，用 `~~删除~~` / 🆕 新增标明；上一轮自己判错的地方用 ⚠️ 标明还原——不要把改错悄悄抹掉。
- **模型词不进报告**：不写「主回报 / 关系六型 / 断点形态 / 机器层 / 实质层 / 三档 / 必改 / 需确认 / 更佳」，一律换成「读者读完会带走的那句话」「开头有没有露出他熟悉的处境」「读者会在这一句停下」「平台可能卡的位置」；档位也换说法——**必改 → 先改这几处**、**需确认 → 要你确认**、**更佳 → 可改可不改**。

## 硬底线与风格（分工）

**任何阶段都不能破的底线**（起草期也适用）：

- **不编造来源**；不把推测写成事实；不把 AI 猜测写成事实。**区分两类「占」**：`［请作者补：…］` 是**缺口标记**（起草期允许，校订期必须消解）；「根据知识库中的相关笔记…」这类是 **AI 占位文本**（任何阶段都不许）。
- **不编造经历与事件**：不许写出一件没有来源的「发生过的事」——包括开篇场景、朋友对话、亲历片段、「上周我遇到」。**编一个像真的场景，和编一篇像真的文献是同一件事**。**没有来源就用缺口标记替代内容**（不是写出编造的细节再标注）；起草期可留着，校订期消解（见第四步）。
- **不修改用户的草稿**——只读不写，无论草稿叫什么名字；你自己的**完整草稿**写 `ai-draft.md`，由用户决定是否采纳。
- **事实**：凡是「据报道」「数据显示」「研究表明」必须能点到一个原始来源；脚注 `[^N]` 溯源；数字对齐到原始出处，不四舍五入、不凭记忆。
- **不编造「同题空白」**：说「没人讲过」「同行只说了一半」之前，必须能说出查过什么（本地语料 / 已发表 / 公开检索）。查过没找到，写「我没有找到同题内容」，**不许写成「没人写过」**；只有摘要、点不开原文的不算盘点到（见 `references/topic-value.md`）。

**形式级禁令与风格规则在校订期加载**：见 `references/style-and-bans.md`（禁用清单、A/B 分档、改到哪停、否定样本、数量型作者基线、适用范围）。**起草期不必读它**——见第七步「起草期许可」。

> 论点深度、声音校准、结构接缝、最小优先、起草期正向清单、六遍改稿见 `references/writing-craft.md`（第七步加载）。
> 证据标准与证据反模式见 `references/evidence-guide.md`。

## 目录约定

文章项目位于环境探测确定的写作根目录下，命名格式为 `YYYY-MM-DD-slug`（Obsidian Vault 默认 `40-Writing/`，其他环境用当前工作目录）。
每篇文章包含七个文件：Agent 读写 `_index.md`、`claim.md`、`evidence.md`、`audience.md`、`style.md`、`ai-draft.md`；用户的草稿由用户自己创建与写作（文件名不限，默认 `draft.md`），Agent 只读不写。**第零步存了作者画像时多一个 `_author-profile.md`**（第八个文件，也在项目文件夹内）。

```
Your Project/
└── 2026-09-20-ai-design-system/
    ├── _index.md          # 文章入口 + 状态 checklist（Agent 写）
    ├── claim.md           # 核心论点（Agent 写）
    ├── evidence.md        # 证据与逻辑（Agent 写）
    ├── audience.md        # 读者认知状态（Agent 写）
    ├── style.md           # 风格与修辞（Agent 写）
    ├── ai-draft.md        # Agent 的完整草稿（Agent 写）
    └── draft.md           # 用户的文章草稿（用户写，Agent 只读；文件名不限）
```
