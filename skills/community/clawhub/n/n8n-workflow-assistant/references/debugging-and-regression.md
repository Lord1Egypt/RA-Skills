# 调试、回归与最小修复

用户说出错时，以执行证据定位，不以“按理应当正常”否定。先固定最新导出、任务与时间，找首个与预期不同的节点，比较输入、参数、原始输出与错误出口。

## 分层定位

1. 是否到达Webhook；未到达先查网络、路径、网关及鉴权。
2. 输入字段是否完整；尤其整批共用字段、逐行备注、false/0和明确参数。
3. HTTP原始响应是否已有数据；再查整理records/facts、权限投影及最终渲染，找哪层丢字段。
4. 嵌套响应先定义父记录与子项关系，不把命中子项当整条主记录；字段关联与来源路径保留。
5. 判断条件覆盖范围是否正确；例如证据在备注却只匹配标题。修复前写出反例，不通过改测试期望掩盖真实问题。
6. 最终写入参数是否被后置推断覆盖；显式值优先应在所有实际写入分支成立。

## 离线检查器的边界

本包validate_workflow.mjs检查JSON图、常见连线/引用、Code语法及部分高价值规则。它不加载n8n完整节点schema、不执行表达式、不运行Code、不访问服务。真实模板解析器只解析表达式语法，不证明值可用、item linking正确或节点实际执行。

--parser-root可指定包含node_modules/@n8n/tournament的可信本地运行目录。未安装解析器时报告expression_status=not_checked；--require-expression-parser会对未完成的真实解析失败退出。不要把启发式提示称为完整解析通过。

比较脚本按节点ID和连线端口给出结构差异，不输出原始参数正文，避免泄露业务资料。它是审查辅助，不能自动判断每个差异是否合理。

## 回归矩阵

覆盖成功、明确空结果、非法输入、接口超时、错误、部分失败、重复触发、整批多行及上下文切换。精确断言最终payload、记录主键集合、字段优先级、期限/空值语义和错误原因；业务规则由测试项目提供。

先复现用户报告，再最小修改；同时运行相关旧用例。未改节点和凭据配置应保持，固定输入中的真实请求头及人员资料不应进入分发包。没有新变更或未解决疑点时不反复扩大测试。
