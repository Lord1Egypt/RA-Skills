# 营养与生长规则

## 营养素与单位

| key | 名称 | 单位 |
|---|---|---|
| `kcal` | 热量 | kcal |
| `protein` | 蛋白质 | g |
| `iron` | 铁 | mg |
| `calcium` | 钙 | mg |
| `vitaminA` | 维生素A | μg |
| `vitaminC` | 维生素C | mg |

食材营养值均为**每 100g 可食部**近似值。某餐某项摄入 = Σ(每 100g 含量 × 克重 / 100) + 对应补充剂。补充剂只计入维生素A / 维生素C，不参与其它 4 项。

## 每日推荐量

基础值（全天总量，近似参考《中国居民膳食营养素参考摄入量》）：

| 月龄 | kcal | 蛋白质 g | 铁 mg | 钙 mg | 维A μg | 维C mg |
|---|---:|---:|---:|---:|---:|---:|
| 小于 24 月 | 1100 | 35 | 10 | 600 | 400 | 40 |
| 24 月及以上 | 1250 | 40 | 12 | 600 | 400 | 45 |

定制微调（按顺序相乘，只作用于指定项）：

| 条件 | 影响 |
|---|---|
| `sizeStatus = small` | 热量 ×1.10、蛋白质 ×1.10 |
| `sizeStatus = large` | 热量 ×0.95 |
| 体重小于 10kg | 热量 ×1.05 |
| 体重大于 16kg | 热量 ×0.95 |
| `ironRisk = 1` | 铁 ×1.20 |
| 钙、维生素A、维生素C | 恒为基准值，不微调 |

**过敏不参与数值计算**，只按逗号/顿号/空格切分生成「已标记过敏：X，制作辅食时请避开」提醒；**性别不影响推荐量**，只用于选择 WHO 曲线。

## 达成率与建议

`ratio = 摄入 / 推荐量`：

- `ratio < 0.6` → 偏低，`{名称}偏少（摄入/目标单位），{食物建议}`
- `ratio > 1.3` → 偏高，`注意别过量`
- 其余 → 达标（**60%~130% 都算达标**，不是必须到 100%）
- `ratio > 1` 时额外显示「超出 X%」

进度显示时强调目标为**全天目标**：早午餐累计未到 100% 但已过 60% 属正常，避免被误读为「已经吃够」。

6 条食物建议文案：

| 营养素 | 建议 |
|---|---|
| 热量 | 可适当增加主食（米饭/面条）或红薯 |
| 蛋白质 | 建议加个鸡蛋或一点瘦肉、鱼 |
| 铁 | 建议搭配瘦肉、猪肝（每周1-2次）或菠菜 |
| 钙 | 建议增加牛奶、酸奶、豆腐 |
| 维生素A | 建议吃胡萝卜、南瓜、西兰花 |
| 维生素C | 建议吃橙子、猕猴桃、草莓 |

过敏提醒排在最前；当天无任何餐次时加一条「今天还没有记录，先记一餐再来看建议吧」。

## 今日食物来源

只统计**当天实际吃过的食物**（不是内置库全部食物）：按 `foodId` 跨餐累加克重，`提供量 = 每100g含量 × 克重 / 100`，按提供量降序，显示「吃了 Xg / 提供量 / 占今日该营养摄入的百分比」。维生素A/C 补充剂作为「维生素补充剂」单列，标注「额外补充（非食物）」。今日无相关记录时显示空状态。

## 报告口径

`report --days 7|30`：

- 逐日调用摄入计算，「有记录天数」只按热量/蛋白质/铁/钙任一大于 0 判断（与 App 一致，**不含维生素A/C**）。
- 日均 = 各项总和 / 有记录天数（为 0 时分母取 1）。
- 输出 Markdown：日均达成率表 + 每日热量、蛋白质、铁、钙明细。
- 目标按报告生成当天的月龄计算，不按历史每天的月龄回溯。

## WHO 生长标准

`assets/growth_standards.json` 含 8 组数组，每组 37 个点，下标即月龄 0-36：`boyHeightP3`、`boyHeightP97`、`girlHeightP3`、`girlHeightP97`、`boyWeightP3`、`boyWeightP97`、`girlWeightP3`、`girlWeightP97`。

- 来源：WHO Child Growth Standards 简化百分位表。0-2 岁为躺着量的「身长」表，2-5 岁为站立「身高」表，24 月处约 0.7cm 断层属正常（不是数据错误）。
- 月龄超出 0-36 时钳制到端点值。
- 单项判定：小于 P3 记 -1，大于 P97 记 1，其余 0。综合判定：身高或体重任一小于 P3 → `small`；任一 大于 P97 → `large`；否则 `normal`。
- `add-growth` 在 `sizeStatusManual = 0` 时把判定结果写回档案；手动锁定则不覆盖。

## 免责声明（必须随建议保留）

> 数据为常见食材近似值，建议由本地规则生成，仅供参考，不构成医疗诊断；特殊情况请咨询医生或营养师。

WHO 标准适用于足月儿，早产儿需按矫正月龄并咨询医生；曲线仅供观察趋势，不是医学诊断。对外表述避免「诊断 / 治疗 / 必须补充」等医疗化措辞。

## 数据出处与再生成

`assets/food_table.json`（30 种、6 分类）与原 Flutter 项目 `lib/data/food_database.dart` 一一对应；`assets/growth_standards.json` 与 `lib/data/growth_standards.dart` 一一对应。若将来需要更新：

- 食材：逐行解析 `Food(id: '...', name: '...', category: '...', kcal: ..., ...)` 的键值对。
- WHO：匹配 `static const List<double> <名称> = [ ... ];`，**先去掉 `//` 注释**再提取小数，每组必须恰好 37 个值，否则说明解析出错。

Skill 运行时不读取任何 Dart 文件；这两份 JSON 是唯一数据源，更新后无需改动 `scripts/baby.py`。
