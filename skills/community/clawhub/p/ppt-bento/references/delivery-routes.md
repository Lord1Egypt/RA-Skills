# 交付路线与编辑需求

在需求确认及选择生成方式时读取。用户的文件要求、编辑范围与运行环境优先，路线名称只是说明实现方式，不能代替这些约定。

## 路线选择

| 路线 | 适用需求 | 实现与默认交付 | 编辑边界 |
| --- | --- | --- | --- |
| SVG/PPTX | 静态演示、矢量源稿、PowerPoint 放映 | 共用策划与数据；生成逐页 SVG 与真实 PPTX。接受整页图形时可嵌入 SVG；要求编辑时从同一内容模型生成原生 PPTX | 整页 SVG 是图形对象，不保证文字、图表数据或各部件原生可编辑 |
| HTML/PPTX | 浏览器展示、响应式阅读或用户要求的交互，同时需要 PowerPoint 版本 | 共用策划与数据，生成 HTML 与真实 PPTX；PPTX 是适合放映的静态版本。只有接受整页图像时才可用截图方式 | HTML 动画、悬停和筛选不自动转入 PPTX；要求编辑时用原生对象生成静态 PPTX |
| 仅 PPTX | 用户只需要 PowerPoint，尤其需要继续改稿 | 直接生成原生 PPTX 及必要生成源文件，不强制增加 HTML 或 SVG | 按确认范围生成原生文字、形状、表格和图表 |

用户只要 SVG、HTML、策划稿或其他组合时，交付其所需格式即可，不为执行表格而增加无关文件。用户没有指定路线时，给出与用途匹配的推荐选项并等待回复；已授权自行决定时，普通静态汇报优先选择原生 PPTX，需矢量源稿再选 SVG/PPTX，明确需要网页体验再选 HTML/PPTX。不要因为文章示例使用 HTML 就自动改用网页。

## 编辑性契约

在策划稿开头记录交付格式、路线、需要编辑的对象，以及允许作为图片/矢量整体保留的部分。避免笼统承诺“全部可编辑”：

- 原生文字：可修改文本与字号；转曲文字、截图文字不满足。
- 原生表格：可修改单元格；整张表格图片不满足。
- 原生图表：若要求编辑数据，应有可修改的数据系列或工作簿；用形状画出的柱形仅能改外观，不等于可编辑数据的图表。
- 原生形状：主要结构与标签可独立调整；复杂插画、照片可保留为图像并说明范围。
- 局部编辑：逐项记录哪些对象可改，其余的源文件在哪里修改。

SVG“转换为形状”的效果随应用、版本和特性而异，不作为原生编辑的保证。HTML 源代码可编辑也不等于 PPTX 内对象可编辑。

先检查可用工具是否支持约定路线与对象类型。若无法满足，说明具体不支持的部分和可行替代；改变已确认的格式或编辑范围前向用户澄清，不悄悄降级为截图。不要仅改扩展名生成 PPTX。

## HTML/PPTX 的实现边界

- 放映页面默认 16:9；响应式阅读可另设布局，但不能使交付 PPTX 缺失关键信息。
- 交互须有静态表达：关键结论、默认/选定场景、图例和限定条件在 PPTX 中可见。多个状态无法在约定页数内表达时，澄清取舍，不擅自扩页或隐去证据。
- 动画用于辅助表达；导出模式关闭动画，展开需打印的内容，避免截图捕获透明、加载中或滚动未出现的元素。截图前完成字体、图片和图表加载。
- 离线使用时将依赖内嵌或本地化；单个 HTML 引用 CDN 不等于离线自包含。联网版需说明外部依赖，不向外部服务发送原始用户资料。
- 网页适配不依赖固定的 3–5 列。投影页面按可读性组织，不能照搬网页的小字与高密度卡片。

## 验证与交付说明

两种格式分别打开或渲染，核对实际页数、比例、标题、核心数值、单位、来源和限制。原生 PPTX 核查代表性对象类型；图表数据可编辑需求还需检查数据结构。只有代码结构检查时明确检查范围，不称为已在 PowerPoint 实测。

最终简述：交付路线、文件清单、页数、PPTX 哪些部分可编辑、HTML 是否离线可用，以及实际验证情况。保留对应源文件，不强制所有路线都附带 SVG。
