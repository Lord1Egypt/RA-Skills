> **版本**：v2.6.3（2026-09-06）

## 一、设计哲学

论衡从 v2.3.13 的「AI 使用披露」（透明）+「G13 AI 使用披露」（审计）演进到 v2.4.0 的「G14 中文 AI 痕迹深度检测」——**不是检测器（GPTZero 类），是论衡自己的「中文学术话语风格指南」+ 检测算法**。

**核心承诺**：
- **风格净化，非隐瞒**：G14 的目标是「去 AI 腔 + 提升中文学术话语可读性 + 贴近主人个人风格」，**不是「让 AI 痕迹不被检测到」**——G13 AI 使用披露照常在交付说明声明「本文由 AI 辅助生成」，**不隐瞒 AI 身份**
- **诚实透明**：G13 AI 使用披露照常在交付说明声明（不试图隐瞒 AI 痕迹）；G14 与 G13 互补不重叠（前者声明 + 后者净化）
- **中文特化**：所有检测维度针对**中文学术话语**，不是英文模式直接套用
- **适用规则（按 Phase 0「目标语言」字段客观适用，非可选 —— 本修订起定案）**：G14 **不再是可选功能**（原「Phase 0 显式勾选启用」与 `g14_opt_in` 已删除）。是否适用由任务简报「目标语言」字段**客观决定**：
  - **必跑**（`enabled`）：目标语言**含中文**（中文 / 中英混）→ 必跑（`condition: target_language_includes_zh`）
  - **客观不适用**（`n/a`）：目标语言为**纯外语**（English / 其他非中文）→ 不跑 G14（**客观不适用，非「关闭」**，无需披露）
  - **降级自检**（`selfcheck`）：适用且属轻量档（**2000-3000 字**，口径真源 = `字数判定表.md`）走内置「G14 自检」（不 spawn 独立 checker）
  - **主人豁免（窄口）**（`exempted_by_owner`）：主人**显式要求**关闭 → 全项目不跑，且**必须在 `final/交付说明.md` 披露**

## 二、检测维度（9 类）

| 类别 | 检测点 | 阈值 | 借鉴来源 |
|------|-------|-----|---------|
| **G14-A 学术模板语** | 「综上所述/笔者认为/本文认为/值得关注的是/不容忽视/在新时代背景下/具有重要的理论与现实意义」 | 任一模板出现 ≥3 次 | chinese-writing 7.4 |
| **G14-B 句式同质化** | 连续 3 段同句式起头（如「首先...其次...最后...」「不仅...而且...」） | 同模板 ≥2 次连续段 | 论衡自有 |
| **G14-C 学术套话高频** | 「赋能/抓手/底层逻辑/范式/迭代/路径」每段 ≥1 次 | 全文 ≥5 处 | humanizer-zh |
| **G14-D 破折号滥用** | **全文 >8 处**，或每段破折号 ≥2 处且 ≥5 段，或破折号总字数占比 >3% | 全文 ≥5 段 | humanizer-zh |
| **G14-E 三项排比** | 全文 ≥3 处「A/B/C」式排比 | 全文 ≥3 处 | humanizer-zh |
| **G14-F 人称错位** | 学术论文滥用第一人称「我」超过全文1% | 「我」字频 > 1% | 论衡自有（中文规范）|
| **G14-G 个人辨识度缺失** | LLM 判定：本文与10 篇同主题论文风格相似度 >80% | LLM 自评判定 | 论衡自有 |
| **G14-H 党报话语堆砌** | 政治学科特化：「重要讲话精神/重要指示/根本遵循」过多 | 全文 ≥3 处 | 论衡自有 |
| **G14-I 防御性写作** | 理由前置「为防止X我们采用Y」/ 元话语「值得注意的是」/ 自我辩护「本文并非要证明」/ 过度免责「本研究存在一定局限性」 | 任一模式 ≥3 处 | writing-guard STYLE |

> 🔍 **G14-B 口径固定（v2.12.32 新增，回应实测 P1——口径分叉）**：实测中**同一稿**因「连续段」读法不同得到 **Warning（3 类）** 与 **Pass（0 类）** 两个结论，末轮争议全落在口径上。**口径须在 Phase 0 固定并写入任务简报**（`G14口径: 严格|宽松`）：
> - **严格（默认）**：命中口径 = ① **相邻正文段**（不含标题行）连续 ≥3 段同句式起头，**或** ② **小节开门段同构**（连续 ≥2 个小节的首段用同一句式起头）——二者任一即算 B 类命中。
> - **宽松（主人显式选择）**：仅计 ①，**不计**小节开门段同构。
> - 未在 Phase 0 固定 ⇒ **按严格口径判定**；G14/T7 报告头部须写明所用口径（`g14_scope: strict|lax`），避免末轮再争议。

## 三、判定规则

**单条命中**：每类单独计算，每类内部阈值独立判定。

**整体判定**（v2.12.49 M-4 修）：**取 `max(类数档判定, 单类严重度档判定)`，二者取严**：
- 命中 0-2 类 + 任一类实测 < 阈值 3 倍 → ✅ Pass（轻微 AI 味，可接受）
- 命中 3-4 类 / 或任一类实测 ≥ 阈值 **3 倍** → ⚠️ Warning（**不自动修订**：主控暂停 → 呈报 3 选 1；选 B 才触发 `t5_style_revision` 风格修订 1 次）
- 命中 5+ 类 / 或任一类实测 ≥ 阈值 **5 倍** → ❌ Fail（触发 `t5_style_revision` —— T5 最后一次**仅风格层**修订；**G14 不重跑**）

**单类严重度档（v2.12.49 M-4 新增）**：

| 单类实测 / 阈值 | 档位 | 判定 |
|---|---|---|
| < 1x | 正常 | 不计入严重度 |
| 1x-3x | 偏高 | 类数档覆盖 |
| **3x-5x** | **超阈** | **Warning**（主控必须列在 `severe_single_class` 报告字段） |
| **> 5x** | **严重** | **Fail**（即数即判，无论类数） |

**报告头必填字段**（v2.12.49 M-4 必填，防「超阈 11.5 倍被类数 0 洗成 Pass」同型漏检）：
```yaml
g14_report_header:
  hit_class_count: <N>          # 命中类数
  hit_class_names: [G14-A, ...]  # 命中类名列表
  severe_single_class:           # 严重度单类（可选，多于命中；未命中则为空列表）
    - {name: G14-D, measured: <N>, threshold: <M>, ratio: <R>}
  final_verdict: <pass|warning|fail>   # max(类数档, 严重度档)
  max_band_basis: <class_count|single_severity>  # 哪个档起决定作用
```

**反面实例**（修 M-4）：**超阈 11.5 倍但类数 0 → 旧口径判 Pass**（实测见个体化命题报告）。**新口径下 = max(类数档=Pass, 严重度档=11.5x>5x=Fail) ⇒ Fail**。

## 二.5、段落级密度热力图（v2.14.0 新增）

**目的**：把"全文 9 类总判定"细化为"段落级密度"，让 T5 / T8 能精准定位 Top 5 高密度段做定向修订，避免 G14 全文修订浪费时间。

**输出格式**（v2.14.0 起在 `audits/G14-检测报告-vN.md` § 段落密度段必填）：

```markdown
## 段落级密度热力图

**扫描方式**：段落分隔 = 双换行（`\n\n`）；每段分别计数 9 类命中数；密度 = 段内命中数 / 段字数 × 10000（万字比）。

| 段号 | 段首预览（≤30 字） | 段字数 | 9 类命中数 | 密度（命中/万字） | 命中类名 |
|------|-------------------|-------|-----------|------------------|---------|
| §1.1 | 本文聚焦于 XX 主题 | 850 | 3 | 35.3 | A, C, D |
| §2.3 | 研究方法方面 | 620 | 2 | 32.3 | A, D |
| §3.1 | ... | 1100 | 0 | 0 | — |
| ... | ... | ... | ... | ... | ... |

**Top 5 高密度段列表**（按密度降序）：
1. §1.1（密度 35.3）：「本文认为 X...赋能...破折号...」
2. §2.3（密度 32.3）：「研究方法...本文认为...」

**全文加权总分** = Σ(段密度 × 段字数) / 总字数 = 全文平均密度
```

**判定阈值（段落级）**：
- 单段密度 ≥ 50 命中/万字 → 🔴 高密度段（重点修订对象）
- 单段密度 20-50 → 🟠 中密度（关注）
- 单段密度 < 20 → 🟡 低密度（可接受）

**与传统 9 类判定的关系**：
- 段落级密度是**定位工具**，不替代 9 类总判定
- 9 类总判定仍决定 Pass / Warning / Fail
- 段落级密度仅供 T5 定向修订 / T8 仲裁 / 主人快速查阅

**例外豁免**（主人可显式要求关闭）：
- 「本文认为」/「笔者认为」等学术模板语在**引言/结论**段可豁免（学术规范要求）
- **结构必写段豁免**：「本文认为/本文提出」在先行者文献「本文差异化」段 / AI 使用声明段 / 摘要限定语 / 主人洞察理论贡献段可豁免（论衡模板强制要求书写；豁免清单同源见写手卡「元叙事清理清单」§ 自指式豁免段）
- 破折号在**正文叙述**段豁免（仅检查论点段）

### 二.6、声音保留反查（R-56，并入 G14，不新增门号）

去 AI 化不是把文章磨成无菌的中性说明。完成 G14 风格修订后，T8/T7 必须对最终候选稿做一次反查，记录：

1. **观点强度仍在**：核心论点、判断句和结论没有被统一改成「可能、一定程度上、值得进一步研究」等无承诺 hedge；
2. **个人判断仍在**：主人已授权的洞察、理论贡献或边界判断没有被删除或改写成无主体的套话；
3. **独特论证仍在**：至少抽查 3 个高密度/关键段，确认论据—论点连接、反方回应和本文差异化没有因风格修订消失。

**反查结果字段**（写入 G14 报告或 T8 交付说明）：`voice_preservation: pass|warning|fail`、`checked_sections: <段落/章节>`、`neutralization_signals: <逐条列出或 n/a>`、`owner_insight_preserved: yes|no|n/a`。出现「无立场句 / 全部 hedge / 观点消失」任一信号 → 至少 Warning；核心判断或主人洞察被抹除 → Fail，回到 `t5_style_revision`，但修订边界仍仅为恢复声音，不得借机改论证与数据。

## 四、触发流程

**适用性**：G14 是**客观适用**、非可选的闸（详见 §一）。适用/不适用由 Phase 0「目标语言」字段决定 —— **含中文 → 必跑**；**纯外语 → `n/a`**（客观不适用，非「关闭」）。报告头须绑定 `draft_id` / `draft_version`。

**触发次数与位置**：**首审全流程只一次；风格修订后全文复检 ≤2 轮**（v2.13.0 P0-2）。位置 = `t7_5_integrity → g14_style_gate → phase4_4_figures`（别名「Phase 4.4 前置（G14 风格闸）」）—— **定稿前的最后一道闸**。`rerun_after_report: false` 仅表示报告落盘后不自动重复首审；若进入 `t5_style_revision`，只按本节规定执行风格复检。

**风格修订后复检（v2.12.70 收口 P1-3；v2.13.0 P0-2 严格度升级）**：`t5_style_revision` 完成风格修订后，必须**重跑轻量 G14 风格复检**（`rerun_g14_style_recheck`：仅风格维度判定、主控亲为 read 判定、不 spawn）—— 保证 G14 审计的是**最终定稿前版本**，指纹对齐，不回落到风格修订前的旧稿。复检不过 → 回 `t5_style_revision` 重改；复检过 → 才进 `phase4_4_figures`。

**复检严格度档（v2.13.0 P0-2，ECS 实战反馈：旧轻量复检只扫修订片段，实测「路径」残留 11 处）**：`rerun_g14_style_recheck` 必须按**全文词表计数**执行——
1. **扫描对象 = 修订后全文**（`current_draft_sync` 后的 `drafts/current_draft.md`），**禁止只扫修订片段**；
2. **计数方式 = 按本文件 §二 9 类词表逐类全文计数**（含未修订段落），命中数与阈值一并写入复检报告头部（字段同 `g14_report_header` + 追加 `recheck_round: <N>`）；
3. **指令残留扫描并入复检词表（v2.15.13 反哺 FB-07/FB-02a）**：任务书指令残留模式（`须[^。；]{0,12}：` / `本节须` / `应修改` / `需补充` / `给写手的话`，同源 = 审计速查 G16⑤）**命中即 P1**，不依赖 LLM 判断；**whitelist 豁免**：直接引语（引号内）/ 法条·文献原文引述 / G14 结构必写段 / 「主体边界·外部效度」段中「须加 / 须预先 / 须显式」类合法约束句（实测 2026-10-06：v3 残留 4 处全部属此类，但自报「全部清除」与实测不符——复检须列命中清单与豁免判定，不得笼统报 0）；
4. **收敛判据 = 命中类数较上一轮下降且无单类 ≥ 3x 阈值**；未收敛 → 回 `t5_style_revision` 重改；
5. **回环上限 ≤ 2 轮**（`t5_style_revision.style_recheck_rounds_max: 2`，真源 = `phase-order.yaml`）；轮次耗尽仍有 Fail / 单类 ≥ 5x 残留 → 主控暂停 + **主人三选一**（接受残留 + `final/交付说明.md` 披露 / 破例追加 1 轮 / 主人手工润色，**无默认**，写法同 `audit_revision` M-6）。

**执行前提**：`precondition: 已可定稿（前置修订已收敛）` —— 前置修订尚未收敛（`audit_revision` 未退出 / 仍有未决 P0·P1 修订项 / 尚不能定稿）时**不执行本闸**，先完成修订；进入「可定稿」状态才开闸（业主原话：「T5 之前若有修订但还不能定稿，则 G14 还是不执行」）。

> ⚠️ 原「复检收敛判据」已由本节的全文词表、下降判据和 ≤2 轮上限替代；不得再使用 `g14_rerun: skipped_no_new_prose`。

**降级与豁免**：轻量档（**2000-3000 字**）走内置自检（`selfcheck`），不 spawn 独立 checker；主人**显式要求关闭**（`exempted_by_owner`）→ 全项目不跑 + 必须在 `final/交付说明.md` 披露。

## 五、报告输出

- 适用性与执行前提（目标语言判定 → 必跑 / `n/a`；是否已达「可定稿」）
- **时点有效性诚实边界（v2.12.67 审计 P2-5；v2.13.0 P0-2 收口）**：G14 首审结论作用于**判定时点的文本**；其后若触发 `t5_style_revision`（Fail 出口 / Warning 主人选 B），风格层修订后的文本**必须按「复检严格度档」全文复检**（≤2 轮，见上节）——旧口径「修订后不再复检、风险静默披露」（v2.12.67）**已废**；复检轮耗尽仍有残留的，按主人三选一处置并在交付说明披露，不以 G14 结论背书。
- `draft_id` / `draft_version` 绑定
- 9 类检测项逐项判定（命中数 + 阈值 + 原文示例）
- 整体判定（Pass / Warning / Fail）
- 详细命中位置（章节 + 段落 + 行号）
- 修订建议（按类别给出改写示例）
- T5 风格修订处理状态（已修订 / 未修订）

## 六、与其他闸门的关系

- **M-Form**：形式合规（字数/格式/标注），G14 是「风格合规」，互补不重叠
- **G11 时效告警**：数据时效，G14 是「文本风格」，不重叠
- **G12 数据信任**：数据可信度，G14 是「话语风格」，不重叠
- **G13 AI 使用披露**：诚实声明，G14 是「风格净化」，互补（前者声明 + 后者净化）
