# 05 · 故障排查

## 1. 登录/认证

| 现象 | 原因 | 处理 |
|---|---|---|
| `401` / `AiotAuthError` | token 过期、密码错、账号禁用 | 重新 `login()`；检查账号状态 |
| 登录成功但设备列表为空 | 用了 API Key，且它绑定到空集成租户 | 改用 JWT/账号密码；先用 `/open/account` 确认 |
| `403` | 无权限（非 owner/admin） | 换有权限的账号；检查设备分享权限 |
| `404` | 设备/指令不存在，或环境不对 | 确认设备 ID、测试/生产环境 |
| `429` | 触发频率限制 | 退避 10s；降低轮询频率/设备数 |
| `AiotProtocolError` | 返回 HTML/非 JSON（网关、登录页） | 检查 Base URL、代理、是否被重定向 |

---

## 2. API Key 的特殊情况

平台文档说 `X-API-Key` 长期有效，但本账号实测：

- 只带 `X-API-Key` 调 `/open/account`、`/open/device/list` → `code=0` 但数据为空；
- 同时带 `Authorization: Bearer <JWT>` → 正常返回。

SDK 同时发送 `X-API-Key` 和 `YZL-AIoT-KEY`，但不会替代 JWT。若你必须用 API Key：

1. 调 `/open/account` 看 `deviceCount` 是否 >0；
2. 若为 0，联系平台确认 API Key 绑定/租户；
3. 生产环境优先用服务账号登录拿 JWT，并在 401 时自动重登。

---

## 3. 设备列表包含密码

`/open/device/list` 对 owner/admin 返回 `password`、`bindCode`。SDK 默认脱敏：

```python
client.devices.list()                          # password=None
client.devices.list(include_secrets=True)      # 明文
```

```js
await client.devices.list();                              // password=null
await client.devices.list({ includeSecrets: true });      // 明文
```

不要为了省事全局打开；日志、异常上报、前端响应都可能泄露。

## 4. 实时值/历史

| 现象 | 说明 |
|---|---|
| `values` 里是字符串 `"25.5"` | 平台原值就是字符串；SDK 的 `normalize_telemetry` 会尝试转数字 |
| `/telemetry` 里的 `value` 返回 `null` | 该时刻无有效数据；历史序列保留点位但 `value=null` |
| `ts` 不变 | 设备没有新数据；不要把它当成请求时间 |
| 历史为空 | 时间范围/keys 不对；设备可能刚上线；检查 `start/end` 本地时间格式 |
| 聚合为空 | 时间范围太大/太小、bucket 不支持；先用 `1h` |
| 告警返回几千条 | `pageSize` 可能被忽略；业务侧 `items[:limit]` |

时间参数格式：`YYYY-MM-DD HH:mm:ss`（平台本地时间，Asia/Shanghai）。Python 可传 `datetime`，JS 可传 `Date`，SDK 转成本地字符串。

## 5. 指令

| 现象 | 处理 |
|---|---|
| `400` 设施不可写 | 型号里该测点 `access` 必须是 `rw` |
| 指令一直 `pending` | 设备离线/协议不匹配；UDP 设备需 `get_order` |
| `timeout` | 设备没回 `order_conf`/`facs_reply`；检查南向日志 |
| `commandId` 拿不到 | 下发响应里才有；历史用 `/open/command/list` |
| `/open/command/{id}` 404 | 部分环境不开放单条查询；用列表过滤 |

## 6. Bridge

| 现象 | 处理 |
|---|---|
| `/health` 的 `errorCount` 增长 | 看 `errorLast`；登录过期/设备不存在/限流 |
| `/latest` 404 | 设备未配置或还没完成第一次轮询 |
| `/events` 为空 | 第一次轮询未完成；或值没有变化（事件按变化触发） |
| 事件重复 | 检查 `ts`/`values` 是否真的变化；平台可能高频上报 |
| Webhook 收不到 | URL 不可达、返回非 2xx、签名校验失败；看 Bridge 日志 |
| 内存增长 | `retainEvents` 默认 1000；多设备可调小 |
| 重启后事件从 seq=1 | 内存态，正常；重要数据落库 |

### Webhook 签名失败

- 必须对**原始请求体**计算 HMAC，不能重新序列化 JSON；
- 检查 `X-AIoT-Signature` 前缀 `sha256=`；
- 检查 secret 是否一致（环境变量/启动参数）；
- 使用常量时间比较，但先比较长度。

### 端口/CORS

- Bridge 默认 `0.0.0.0:8080`；云主机安全组放行。
- 前端跨域：Bridge 返回 `Access-Control-Allow-Origin: *`；生产建议在 Nginx 限制来源。
- 浏览器不要直连平台 API（JWT 泄露）；让浏览器访问你的后端/Bridge。

## 7. MQTT

| 现象 | 处理 |
|---|---|
| `Not authorized` | 北向独立凭证未分配；用户 JWT/API Key/设备密码都不行 |
| 连上但收不到 | 订阅 `north/+/+/data`；确认设备在对应环境、有实时上报 |
| 收到历史补传 | 北向 topic 不推 `facs_his`，只推实时帧 |
| TLS 失败 | 平台 1883 明文，没有 8883；不要强行 `mqtts` |
| 重复/断线 | 设置 `clean=true`、重连 5s；业务按 `(deviceId,ts)` 去重 |

没有 MQTT 凭证时，用 Bridge REST 轮询；或让平台把 topic 转发到你的 MQTT/HTTP。

## 8. Node/Python 环境

| 现象 | 处理 |
|---|---|
| JS `fetch is not available` | Node < 18；升级，或注入 `fetchImpl` |
| JS `Cannot find package 'mqtt'` | `npm install mqtt`，或不用 MQTT |
| Python `ModuleNotFoundError: aiot_north` | `pip install -e python` 或 `PYTHONPATH=python/src` |
| Python `ModuleNotFoundError: paho` | `pip install "aiot-north[mqtt]"` |
| 中文乱码 | Windows 终端编码；业务 JSON 是 UTF-8，不影响数据 |
| 代理/自签证书 | Python 用 `HTTPS_PROXY`；自签证书需把 CA 加入系统信任，不要关闭校验 |

---

## 9. 诊断顺序

1. `whoami` 能否成功？→ 认证问题
2. `devices --limit 1` 是否有数据？→ 数据范围/API Key 问题
3. `telemetry <id>` 是否有值？→ 设备/环境问题
4. `history` 是否有时间序列？→ 时间范围/keys 问题
5. Bridge `/health` 的 `lastPoll`/`errorLast` → 轮询问题
6. `curl` Webhook 地址 → 网络/签名问题
7. 最后才怀疑 SDK：用 `--token` 直接调 `curl` 对比响应。
