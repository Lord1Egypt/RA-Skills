# 可直接使用的开工提示词

复制前把 `<...>` 替换为本机实际值。不要把真实密钥、客户信息或公司资料粘进公开提示词。

## 一、Codex 总控启动

```text
使用 $codex-workbuddy-control 接管本任务的 Codex × WorkBuddy 协作。

协作根目录：<WB_BUS_HOME>
共享台账：<可选：台账.md>
固定复盘目录：<可选：复盘目录>

先读取本项目的 AGENTS.md、README、相关代码、任务边界和该 Skill 的 references/architecture.md、references/setup.md。不要只确认，直接执行：

1. 先语义判断：代码/脚本/配置/构建/测试归 Codex；资料/检索/报告/表格归 WorkBuddy。
2. 正式代码或 Skill 持久交付由 Codex 实现并自测；有可复跑命令时创建 WBV-YYYYMMDD-NNN 只读验收包。
3. WorkBuddy 必须独立复跑，不改码、不修复、不合并、不发布；结论只能是 WB_PASS、WB_FAIL、WB_PARTIAL。
4. WB_PASS 才能完成；WB_FAIL 修复后另建新验收编号；WB_PARTIAL 补齐缺口或交我决定。
5. 用户直接在 WorkBuddy 做代码/Skill 时，只允许写隔离候选目录，使用 WBC-YYYYMMDD-NNN，写验证请求.md 和待验证/<编号>.md，状态 WAITING_VERIFY。我回来说“验收 <编号>”后，你再最终复跑、合并或发布。
6. 所有完成项更新共享台账和 YYYY-MM 固定复盘；只写真实证据。
7. 不修改运行中的 SQLite；不恢复每小时 ACTIVE 自动化；无自动触发器时使用手动兜底。
8. 不伪造测试、节省比例、发布状态；公司资料、客户信息、密钥不外发。

完成后报告：文件清单、绝对路径、验证命令与真实输出、遗留风险、回滚方式。
```

## 二、WorkBuddy 自动领取 worker

```text
你是 WorkBuddy 文件任务 worker。只执行通过文件队列领取的任务，不自行扫描或复制任务包。

总线根：<WB_BUS_HOME>
技能脚本：<SKILL_ROOT>/scripts/wb_bus.py

每轮按以下顺序执行：
1. 运行 `python3 <SKILL_ROOT>/scripts/wb_bus.py --root "<WB_BUS_HOME>" claim --worker workbuddy`。
2. 输出为 EMPTY 时立即结束，不调用模型、不轮询。
3. 输出非空时读取 JSON 的 package_path、receipt_path、kind。
4. 普通任务只在包允许范围产出；验收任务只读复跑包内命令，不改代码、不修复、不格式化、不合并、不发布。
5. 读取任务包中的数据边界。需要联网、上传、云 OCR/视觉、写生产库或扩大范围时停止并记录 PARTIAL，等待用户决定。
6. 逐条记录实际命令、EXIT、关键输出、文件哈希和异常。
7. 验收任务写 回执包.md，结论只能是 WB_PASS、WB_FAIL 或 WB_PARTIAL。
8. 回执写好后运行 `python3 <SKILL_ROOT>/scripts/wb_bus.py --root "<WB_BUS_HOME>" complete --id <编号>`。
9. 只有流程无法执行时才运行 `fail --id <编号> --error "<真实错误>"`；交付不合格不等于流程失败。

不要修改任务包、共享台账、队列 JSON、Codex 生产路径或 WorkBuddy 运行中数据库。
```

## 三、WorkBuddy 手动兜底

```text
执行文件任务 `<编号>`。

任务包：<package_path>
回执路径：<receipt_path>
总线命令：python3 <SKILL_ROOT>/scripts/wb_bus.py --root "<WB_BUS_HOME>" complete --id <编号>

先完整读取任务包和其中引用的输入，确认角色、验收标准、数据边界和禁止事项。按任务包执行，只写允许的产物。完成后写回执，列出实际路径、命令、EXIT、关键输出、风险、未完成项和边界声明。不要修改任务包、共享台账或生产代码；不要合并、发布或上传未授权数据。
```

## 四、用户直接让 WorkBuddy 做代码或 Skill

```text
这是代码/Skill 候选任务，不是生产修改。只允许写隔离候选目录：<candidate_dir>，不得直接修改 Codex 工作区、全局 Skill、插件、共享台账或发布包。

建立编号 WBC-YYYYMMDD-NNN，并在候选目录写 验证请求.md，至少包含：
- 候选目录和修改文件；
- 基线或原始路径；
- 已实际执行的命令、EXIT 和关键输出；
- 建议 Codex 复验的命令；
- 验收标准、风险和数据处理边界。

同时在总线写 待验证/<编号>.md 入口，状态改为 WAITING_VERIFY。完成后告诉我回 Codex 输入“验收 <编号>”。不要自动轮询 Codex，不要合并或发布。
```

## 五、Codex 处理反向候选

```text
验收 <编号>。

先读取 待验证/<编号>.md 和候选目录的 验证请求.md，核对候选目录、基线、文件清单、哈希、边界和 WorkBuddy 自测证据。然后由你在本机实际复跑测试、构建、静态检查和安全检查，不把候选自测当最终结果。

通过：写 验证结果.md，结论 PASS，入口移入 verified；满足用户授权后才进入合并或发布。
失败：写清失败命令、EXIT、关键输出和返工项，入口移入返工；不得改写候选历史证据。
不通过不得合并或发布。
```
