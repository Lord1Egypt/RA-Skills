# ADR-0011：随包 sealed 测试子集

日期：2026-11-15 ｜ 状态: Accepted ｜ 修订：ADR-0010 的「tests 不随包」边界

## 背景

ADR-0010 确立模块化分层时沿用 ADR-0001 时代的分工：tests/ 全量回归矩阵（43
个历史版本文件，约 337KB）留在开发侧，包内验证交给 tools/selfcheck.py（安装
完整性四查）。2026-11-13 的建设性反馈指出「部分关键测试未随包分发」——
收包方只能跑 selfcheck 的四条探针，无法复验判定语义级行为（五态判定、忠实度
标签、审计包、布局锁）。

## 决策

随包分发一个 **sealed 测试子集**，以 `tests/shipped_manifest.json` 为唯一来源：

1. **清单制**：打包器（pkg_dual_lang.sh）读清单复制；`tools/run_tests.sh
   --shipped` 只跑清单内文件——包内部分拷贝损坏（清单文件缺失）直接 FAIL；
   `tools/selfcheck.py --tests` 联动执行。
2. **准入判据**（三条全过）：① sealed 默认档零网络（在线用例组自带
   skipUnless 自跳过）；② 包态自足——仓库独有文件缺席时自洽降级（如
   SKILL_ZH.md 包内不存在，F53 枚举锁回退单 SKILL.md）；③ 无硬编码版本数
   （随扩容漂移的断言一律动态化）。
3. **边界不变的部分**：全量矩阵（43 个历史版本回归文件）仍在开发侧——它们
   锁的是版本演进过程中的历史修复点，对收包方是噪音；随包子集锁的是**现行
   判定语义与工程宪法**。

## 后果

- 收包方可复验：布局锁（8 文件 <122,894B 静态阅读线）、五态判定语义、
  忠实度标签注记宪法、wheel 清单门、留出集 offline 口径、工具枚举同步——
  即「这个包是否还是它声称的那个引擎」。
- 包体 +约 142KB（9 文件+清单本体）；泄漏红线闸与重复文件闸自动覆盖新增文件。
- 新增测试文件的准入：改 shipped_manifest.json 一处，打包器与
  run_tests.sh --shipped 自动跟随（单一来源，无第二份白名单）。
