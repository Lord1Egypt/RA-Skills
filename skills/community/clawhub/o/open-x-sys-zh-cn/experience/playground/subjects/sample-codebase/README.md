# orderly

一个很小的订单处理服务。

## 它怎样工作

订单进入队列，再由 **4 个并行工作的处理线程**领取，因此吞吐量会随线程数增加。

每张订单会依次：

1. 预留库存；
2. 通知客户；
3. 标记订单完成。

某一步失败时，处理线程会使用指数退避重试，最多尝试 3 次。这样通知服务短暂中断时不会被重试压垮。

## 配置

| 设置 | 默认值 | 含义 |
| --- | --- | --- |
| `WORKERS` | 4 | 并行处理线程数量 |
| `MAX_ATTEMPTS` | 3 | 每张订单最多尝试次数 |
| `BACKOFF_BASE_SECONDS` | 0.5 | 指数退避的基础等待时间 |
| `NOTIFY_SECONDS` | 0.05 | 模拟通知服务的延迟 |

## 运行测试
