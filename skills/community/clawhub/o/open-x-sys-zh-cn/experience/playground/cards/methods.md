# 方法卡

> **给“组一组”用。** 三十张卡：23 个核心方法和 7 个视角。这个人挑一个对象，叠两到五张。按给出的顺序运行这一叠，每张卡之后说出它增加了什么。每张卡在运行时里都有一页（`capabilities/methods/<阶段>/<函数>.md`）；深入使用一张卡之前，先读那一页。

按阶段分组展示。新手可以从标 ★ 的七张开始。

## 阶段一 · 看懂：它是什么？怎么运转的？

| 卡 | 这样说 | 它显示什么 |
|---|---|---|
| **开启** `open(x)` | “给 ___ 开启一个系统。” | 整体：组成、关系、边界、真正重要的东西 |
| ★ **透视** `xray(x)` | “帮我看透 ___ 背后真正起作用的结构。” | 反复发生的事件之下的结构 |
| **流动** `flow(x)` | “跟着钱走一遍 ___。” | 什么在积累，什么在流动，在哪里堆积 |
| **回路** `loops(x)` | “是什么让 ___ 一直这样运转，或者一直卡住？” | 反馈回路，以及正在上演的已知模式 |
| **估算** `estimate(x)` | “___ 大概有多大？” | 一个站得住的量级 |

## 阶段二 · 解释：它为什么会这样？

| 卡 | 这样说 | 它显示什么 |
|---|---|---|
| ★ **第一性原理** `first_principles(x)` | “把 ___ 拆到一定成立的东西，再重新构建。” | 事实，对上习惯和假设 |
| **溯源** `trace(x)` | “___ 是怎么一步步变成今天这样的？” | 转折点，以及哪些东西被锁定了下来 |
| **瓶颈** `bottleneck(x)` | “真正限制 ___ 的是什么？” | 限制整体的那一个约束 |
| **激励** `incentives(x)` | “谁能从 ___ 保持现状中得到什么？” | 谁想要什么，谁付出代价 |
| **换视角** `shift(x, as)` | “站在 ___ 的位置看 ___。” | 每个位置看到什么、看不到什么 |

## 阶段三 · 预见：接下来会怎样？

| 卡 | 这样说 | 它显示什么 |
|---|---|---|
| **推演** `whatif(x, if)` | “如果 ___，___ 会怎样？” | 后果、延迟、几种未来 |
| **二阶思考** `second_order(x, action)` | “如果我们 ___，然后呢？” | 后果的后果 |
| ★ **反过来想** `invert(x, goal)` | “什么会让 ___ 失败？” | 它可能出错的方式，以及怎样避开 |
| **连接** `connect(a, b)` | “___ 会怎样影响 ___？” | 系统之间真实的关系 |

## 阶段四 · 找准：在哪里用力最有效？

| 卡 | 这样说 | 它显示什么 |
|---|---|---|
| ★ **杠杆** `leverage(x, goal)` | “在 ___ 里，哪个小改变最重要？” | 少数几个值得用力的地方 |
| **关键少数** `vital_few(x)` | “___ 里哪 20% 决定了 80% 的结果？” | 造成大部分结果的那一小部分原因 |

## 阶段五 · 选择：对我们来说，最好的做法是什么？

| 卡 | 这样说 | 它给出什么 |
|---|---|---|
| ★ **最佳实践** `practice(system, goal)` | “以我现在的条件，___ 最好的做法是什么？” | 一项适合的实践，和一个低成本的第一步验证 |
| **权衡** `weigh(options)` | “我该 ___ 还是 ___？” | 选项并排比较，包括可逆性 |

## 阶段六 · 创造：把它做出来

| 卡 | 这样说 | 它给出什么 |
|---|---|---|
| ★ **做成作品** `make(x, form)` | “把它做成一个 ___。” | 一份完成的成果；需要传播时继续长出传播物 |
| **设计** `design(goal)` | “帮我设计一个能 ___ 的 ___。” | 一个新的系统、流程或产品 |
| **搭建能力** `build(capability)` | “帮我搭建做 ___ 的能力。” | 一项能工作的能力，在真实工作上验证过 |

## 阶段七 · 改进：有效吗？接下来呢？

| 卡 | 这样说 | 它给出什么 |
|---|---|---|
| ★ **复盘** `review(x)` | “我们来复盘一下 ___：发生了什么，应该改什么？” | 意图与结果的对照，以及要改什么 |
| **盯住** `watch(x, signal)` | “帮我盯着 ___，一旦 ___ 就告诉我。” | 回来时要检查的信号和阈值 |

## 视角

| 卡 | 这样说 | 它显示什么 |
|---|---|---|
| **问题类型** `problem_type(x)` | “___ 是哪一类问题？” | 该去分析，还是该去试探 |
| **边界** `bound(x)` | “看 ___ 的时候，我们漏掉了谁、漏掉了什么？” | 选定的边界遮住了什么 |
| **尺度** `scale(x)` | “把 ___ 放大十倍，会变成什么？” | 什么取决于规模 |
| **存续** `viable(x)` | “___ 靠什么活下去？缺了哪一块？” | 没有人在履行的那项职能 |
| **应变** `variety(x)` | “___ 应付得了它面对的复杂局面吗？” | 情况与应对之间的错配 |
| **涌现** `emerge(x)` | “___ 是怎么在没人设计的情况下自己长出来的？” | 用局部规则解释出来的一个模式 |
| **矛盾** `contradiction(x)` | “是什么矛盾卡住了 ___？” | 让两种需要都被满足的办法 |

## 适合先试的几叠

| 这一叠 | 用在 | 你会注意到什么 |
|---|---|---|
| 透视 → 反过来想 | 为什么路越宽越堵 | 先是结构，然后是一种好心的修补怎样失败 |
| 流动 → 瓶颈 → 杠杆 | 一个小型订单服务 | 活儿在哪里等着，什么在限制它，往哪里推 |
| 溯源 → 连接 | 集装箱 | 它是怎么来的，然后它在别处改变了什么 |
| 回路 → 激励 → 杠杆 | 啤酒游戏 | 那个回路，讲道理的人为什么在喂养它，什么能打断它 |
| 关键少数 → 最佳实践 | 一份周更的通讯 | 时间到底花在了哪里，然后是一项适合的实践 |

这个人开启过自己的东西之后，一叠卡可以保存为个人路线。
