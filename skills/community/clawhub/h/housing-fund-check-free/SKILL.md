# 住房公积金汇缴与基数核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：财务、出纳、人事在**每月发薪与公积金汇缴那几天**，
必须把这张汇缴明细表核一遍，才能往上报、往工资表里带、往下做账。

**这张表会逐项核对什么**：住房公积金每月汇缴明细 —— 逐人复算
`单位月缴存额 = 缴存基数 × 单位比例`、`个人月缴存额 = 缴存基数 × 个人比例`、
`缴存合计 = 单位月缴存额 + 个人月缴存额`；核合计行逐列与各明细行之和；
查同一期间重复人员、关键字段空缺与负数、缴存基数是否超出表内给定的上下限。

每条结论都带**原文行号与出处**，并写出可被第三方复算的算式；
材料不足时**不给结论**，会明确列出还缺什么，也**不会**输出「未发现问题」。

## 这个免费版查什么（7 项）

1. 单位月缴存额复算（缴存基数 × 单位比例）
2. 个人月缴存额复算（缴存基数 × 个人比例）
3. 缴存合计复算（单位月缴存额 + 个人月缴存额）
4. 合计行勾稽（合计行逐列与各明细行之和不符）
5. 同一期间重复人员检测
6. 关键字段空缺与负数检测
7. 缴存基数超出表内上下限

**这个免费版没有执行**（引擎的 `CHECKS_WITHHELD` 会如实列出）：
基数低于表内下限的判定与应调整基数、比例是否落在允许档、
新增与离职人员的缴存月份是否对得上、区间内断缴月份、
单位与个人比例是否一致、与工资表应缴口径的差异、
以及**按金额排序的补退处理清单**。

## 怎么用

```bash
node scripts/run.mjs --sample                 # 先看内置样例
node scripts/run.mjs --input 你的材料.json     # 跑自己的材料
node scripts/run.mjs --input 你的材料.json --json
```

入参就是把**表头和明细行一起**从公积金系统或工资表复制成文本贴进 `{"text": "…"}`
（Tab 分隔最稳）。至少要能认出「期间」「姓名」「缴存基数」「单位比例」
「个人比例」「单位月缴存额」「个人月缴存额」「缴存合计」这几列，否则不出结论。

## 需要完整档时（可选）

本免费版是**完整可用的核心产出**，本版本**不包含**下面这些项：

- 缴存基数低于表内下限检测（并给出应调整基数与月差额）
- 缴存比例不在允许的整数档（给出最接近的合法档）
- 新增 / 离职人员的缴存月份与在职区间不符（应缴未缴或多缴）
- 同一职工在缴存区间内出现断缴月份（影响连续性）
- 单位与个人缴存比例不一致检测
- 与工资表应缴口径差异（工资个人缴存 vs 公积金个人缴存额）
- 按金额排序的补退处理清单（每条带原文行号与建议动作）

同名工具的**完整档**是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别**就是上面这些，没有别的**。

## 边界（请务必知道）

- 本工具**不给法律或合规意见**，也不判断当地当年真实的基数上下限与比例是否用对；
  它只核**表内可算的算术关系**与**你填进表内的**上下限、比例档位是否自洽。
- 本工具**只核住房公积金**。社保（养老 / 医疗 / 失业 / 工伤 / 生育）与公积金是
  **两套独立系统**，基数上下限与比例各自定 —— 社保请用 `social-insurance-check`，
  本工具不看社保任何一个险种。
- 不计算滞纳金、利息、罚款，也不做跨年度的基数调整追溯；不读取 .xlsx。
- 材料不足时**不给结论**，也不会输出「未发现问题」。

## 常见错法（这张表里真的会有人这么填）

1. **基数与工资混用**：把「应发工资」直接当「缴存基数」填，上下限两列又空着 ——
   免费档这时只能报「缴存基数超出表内上下限」这一类；完整档才会给出
   "应压回上限、月差额多少"的补退结论。基数请按当地口径取，
   **并把上下限两列一起填进来**，判据才有依据。
2. **比例写成别的东西**：`12%` 写成 `0.12` 本工具能认（归一成 12%），
   写成 `12`（漏百分号）只是碰巧对，写成 `1.2%` 或「十二」就认不出来了 ——
   认不出来时这一行**不参与比例类判定**，别把它当成"通过了"。统一写 `12%` 最稳。
3. **新增与离职月份留空**：新增人员只写进明细、不填「新增月份」，
   离职人员当月照缴但「离职月份」空着 —— 免费档不报错（它不做这项检查），
   完整档也无从判断该不该缴。人员增减月份是这一项的唯一依据，务必填。
4. **离职当月与离职后混在一行**：离职当月应缴、次月停缴，但表里把两个月合并成一行
   写一个金额；这时「缴存合计」与「单位 + 个人」对不上，断缴月份也会被误判。
   **一人一月一行**，停缴的月份就是没有行。
5. **合计行手改过却没重算**：明细里加了一个人，合计行还是上月那一版；
   或者只更新了「缴存合计」列，忘了「单位月缴存额」「个人月缴存额」两列。
   本工具**按列**复核，三列会分别报出来，别只改一列。
6. **把补缴并进当月**：补缴月份和当月汇缴写成同一行、同一个金额，
   个人月缴存额就与「基数 × 比例」对不上（补缴是按历史基数算的）。
   补缴请单独成行并注明月份，不要并进本期。
7. **同一个人因为分档缴存拆成两行却没写依据**：按政策分档分行是正常的，
   但两行都写同样的期间与证件号，会被判成「同一期间重复人员」，
   还会让单位与个人合计都翻倍 —— 分档行请在备注列写明依据。
