# 纪要蒸馏 · 四栏收口法

## 何时用
- 多人群聊/多方会议后需要一份"能执行"的纪要
- 长对话（几十上百轮）要压缩成不丢关键的状态文档
- 周报从流水记录收口

## 第一步：四栏框架
所有信息只进四个篮子，进不出去的标"杂项"直接弃：

| 栏 | 收录标准 | 必带字段 |
|---|---|---|
| **决议** | 有明确"定了"信号的结论 | 决策人、时间戳、原话出处 |
| **待办** | 可指派、可验收的动作 | 责任人、验收标准、期限 |
| **在途** | 已发起未闭环的事 | 发起凭证（编号/链接）、候谁回应 |
| **分歧** | 未达成一致的两种以上口径 | 各方观点一行式、卡点是什么 |

## 第二步：三条过滤纪律

### 1. 引用回查
纪要里每一条关键事实，落笔前回原始对话**查一次出处**；
转述新文件/新数据必须带原文可定位的凭证（编号、文档ID、
消息号），**禁止凭印象写纪要**。

### 2. 回声不记账
互相确认的客套（"收到""好的""晚安"连发）属回声件，
不计入决议也不计待办；只记**改变状态的那一条**。

### 3. 滞后件标注
若 A 结论发出时 B 结论已在途（两人在交叉发消息），
纪要按**时间戳排序**并在滞后件上标"（已被 X 时点更新）"，
防止过期结论被当现行。

## 第三步：收口三问
1. 有没有"应该发生但没记录"的事？（漏账排查）
2. 每条待办是否都可验收？（写"持续跟进"的打回重写）
3. 分歧栏是否如实？（**不许为了纪要好看而删分歧**——
   不掩盖执行偏差是纪要的底线）

## 输出模板
```
【纪要】场合____ 时间____ 记录人____
一、决议（n条）  [决策人|时间|出处] ...
二、待办（n条）  [责任人|验收标准|期限] ...
三、在途（n条）  [凭证编号|候谁回应] ...
四、分歧（n条）  [甲口径/乙口径/卡点] ...
脚注：漏账排查结果__；回声过滤__条；滞后件__条
```
