# 更新日志

记录 Quill 每个版本的变化。

版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)。`0.x.x` 表示**尚未稳定**：流程、文件约定与指令都可能发生破坏性变更，不要把它当稳定 API 用。

**每版的结构**：一句话说这版是什么 → 对你有什么影响 → 分类条目（新增 / 修复 / 调整 / 移除）→ 技术细节（折叠，点开看）。只想知道「要不要注意什么」，看前两块就够。

---

## [0.13.0] - 2026-11-15

**两件事一次发：把「值不值得写、有没有人接得住」补进骨架，把「发出去之后看不看得见」补成发布层。** 这一版的重点其实只有一个：**降低 AI 味、抬高深度长文的下限**——不再只是加检查项，而是让模型在**写的时候**手里就有材料。

### 对你有什么影响

- 动笔前多问一句「这篇比同题多走了哪一步」。答不出，它会让你换论点、缩成经验分享，或直说「我没有找到同题内容」——不再用「没人讲过」这种听起来像判断、其实是编的话。
- 「读后必须有一个可执行动作」放宽了：解释 / 判断 / 行动 / 情绪 / 身份 / 表达 / 审美，七种回报认一种，不再逼你在结尾硬凑一句「你可以去试试」。
- 标题第一次有完整做法：先写完整句再删词、陌生人单独看得懂、留一个正文会回答的问题、每个限定词都有理由。**标题 / 摘要 / 小标题是三个位置**，不许重复同一句。
- 勾了发布平台，它会先看平台表（读者从哪进来、要什么、发布位在哪）再定标题、摘要、首段、结尾动作。同一篇发多处只换这四样，不制造近义改写凑数量。
- 开头多了三条边界：**判开头只判开头**（后文写得再好也不能给开头加分）、先查会不会被归错类、强断言先查「动到谁的什么」。
- 反驳多一类「读者接不住」，报告只给三种结论：**先改这几处**（内部默认不超过 3 条）、**要你确认**、**可改可不改**；每条带一句「代价」（丢掉哪类读者、少掉哪层解释），并且钉在原句上——`~~删除~~` / 🆕 新增 / ⚠️ 收回自己上一轮的判断。
- 报告里不许出现模型词（主回报 / 关系六型 / 断点形态 / 机器层 / 档位名），换成「读者读完会带走的那句话」这类人话。
- 明确仍不做的：预测播放量、抄平台字数常量、矩阵批量生产、投流、替作者判这篇有没有商业价值。

### 新增

- **起草期材料会计**（最重要）：每写一节之前，先在 `ai-draft.md` 该节标题下写一行 `本节材料：`——这节由哪几件真实的东西构成。写不出这一行就别写这一节。**这是治 AI 味的根**：模型写不出东西时不会停，会用抽象和漂亮句子填满；每节有材料出处，禁用词自然少一大半。
- `references/topic-value.md`：价值三问（由来 / 增量 / 回报）、同题盘点与「不许编同题空白」、回报七型、关系六型与关系显露、读者会把它当什么用。
- `references/distribution.md`：平台表（读法，不是规格）、选题的平台适配、标题四件事与六种类型、摘要与头图文字、分发形态改写、传播六项分开判、发布位检查六项、公众号三条排版坑。
- 合规扫描补上：两层结论（机器层 / 实质层）、证据强度三级与弱线索沉默、最小必要干预白名单、三档结论、修改动作菜单、受限品类核对、图片隐私与敏感呈现、发布关系、未检查范围、平台规则时效纪律、报告写法。
- 标题与开头正向做法（`form-guide.md`）、论点深度第七道（大白话测试）与论点五槽位、替换测试（通用段落检测）、结构接缝的删减与重复判据、读不下去的断点三因、改到哪停（反向闸门）、否定样本记账、中文排版默认。
- 模板补栏：`claim.md` 加由来 / 增量 / 适用范围；`audience.md` 加读者处境 / 关系 / 回报与兑现位置；`style.md` 加标题三问与发布位。

### 修复

- **`SKILL.md` frontmatter 的闭合 `---` 被并进了 `reference:` 行**，静态校验直接崩（`TypeError`），发布链路在 frontmatter 注入那一步也会失败。补回独立 `---` 行。
- 第九步验证补上「读者回报」「独立可懂」「反回填」三项——原先写进 `audience.md` 的读者收益，没有任何一步核它。
- 第九步补上三条最硬的「像不像真人」判据，并全部落进最终闸门（原先只写在参考文件里、没人核）：
  - **替换测试**：抽掉这节的专有名词、换成同题另一篇的对应内容——照样成立就是通用段落。
  - **只有你能写**：全篇至少一处别人替不了你的细节 / 判断 / 踩过的坑，最好在前三分之一。
  - **论点自检五格**已填或已标缺口。
- 冷读五问保留，但在它后面接三条可指认的硬判据——冷读全靠模型自问，它会给自己打高分。
- **「主回报第一份实物落在首段」加体裁豁免**：观点文、方法文首段给；个人叙事、人物、深度长文允许在转折之后交付（先保留当时的理解，再揭示变化），不许所有文体都写成「答案先行」。
- **示例升级为深度长文示范**：`assets/examples/sample-article/ai-draft.md` 从 873 字扩到约 1300 字，带完整的 `本节材料：` 会计、转折结构、缺口标记、只有作者能写的亲历落点——模型终于有「深度长文长什么样」的样例可参照。

### 调整

- 第三步：一句话论点 + 由来 + 增量 + 适用范围；绝对化用语必须给比较依据。
- 第五步：从「读后状态 + 可执行动作」改为「主回报 + 他会把它当什么用」；「在哪兑现」按文体分：观点文首段、叙事转折后。
- 第三/五步：论点五格从「claim 必填栏位」降级为「卡住时才用的自检工具」——它与「不要先给结构命名、分类应当来自材料」直接冲突，做成必填会让每篇先过同一副骨架，写得更平。
- 第六步：标题接上发布层四件事与平台适配；第九步加发布位检查。
- 第八步：五类反例 → 六类；三档报告加上限与代价；第六类「没有转述理由」先判这篇要不要传播。
- 硬底线加一条：不编造「同题空白」。

<details>
<summary>技术细节：为什么这些都不放起草期、为什么不抄平台常量</summary>

- 全部新判据只落在两个窗口：**起草前**（第二步～第六步）与**校订期**（第八、九步）。第七步「起草期许可」一行未动——起草期仍只守「不编造」一条底线。
- 没有加第 4 道「起草前质量闸门」：读者收益在第三步与第五步已经判过，再压一道闸门会把第七步的入口变成审批台（0.11.1 的回归教训：闸门一多，Agent 会挑最省事的路把它跳过）。
- 合规部分改的是「这份报告怎么下结论」，不是「哪些词违规」：两层结论 + 证据三级 + 最小必要干预解决的是同一种失败——过度报警让作者整体忽略报告，或为了稳妥把稿子改平。
- **平台字数、封面尺寸这类常量一条都没进规则**：它们会过期，且属发布字段而非写作判据。`distribution.md` 只给「读法」（每个位置该由什么承担），规格以发布页为准。dbs 那边自己写着「任何素材都能拉到更高流量层级」，quill 不采用这个前提——没有可验证的判据，写进去就是编。
- `<details>` 里的内容不参与 registry 发布说明的前 40 行截断（`.github/actions/publish/action.yml`）。

</details>

## [0.11.3] - 2026-11-01

**修回 0.11.1 引入的质量回退：作者画像的同意链被设计成「要问三轮」，实际等于把写作依据问没了。这版把默认路径改回高质量路径，并加了一道不许跳过的起草前质量闸门。**

### 对你有什么影响

- 开工前只问一次，且推荐项就是「读你指定的 1–3 篇」——不再因为授权要分三轮而干脆不读。
- 你这次对话里贴的草稿、你的说法、你给的链接，**直接算可用的声音依据**，不会再被追问一遍。
- 动笔前要走三道闸门：可反驳的论点、≥3 条声音锚点 + 1 条原文引用、每节一处具体物。素材不够时它**停下来要你一段文字**，而不是用通用语体顶上。

### 修复

- **第零步**：三问合一（读哪些 / 记多深 / 存不存），默认路径 = 高质量路径；对话内材料默认视为已同意。
- **第七步**：删掉「取作者声音指纹（读其已发表文章）」这条与第零步直接冲突的无条件指令——画像缺失时它要么被违反、要么被跳过，稿子就退回通用语体。改为「用第零步到手的材料」。
- **新增「起草前质量闸门」**：论点能被一句「但……」顶回来 / 声音锚点 ≥3 条且含 1 条原文引用 / 每节至少一处具体物；三条缺一条不许开写。校订期加一条自查：把作者名遮住，这稿会不会被当成任何人写的同题文章？

<details>
<summary>技术细节：为什么确定是这一步造成的</summary>

- `git diff v0.11.0..HEAD`：除第零步（读作者）外，`references/writing-craft.md`、`references/style-and-bans.md`、`references/form-guide.md` **一行未动**；其余改动都是安全/发布/文档层面的。
- 本机 Magpie 安装目录 `~/.config/magpie/library/skills/quill/SKILL.md` 实测就是 0.11.2（与仓库 diff 一致）——用户最近几次用的正是这版。
- 直接冲突点：第零步改成「没同意不读任何历史文章」，第七步仍要求「读其已发表文章」取声音指纹。两条同时在场时，声音校准必然落空。

</details>

## [0.11.1] - 2026-10-23

**按 ClawHub 的安全检查反馈收紧隐私边界：读旧文章学作者、保存作者画像，都改成先问过再做；发给 registry 的安装包不再带开发资产。**

### 对你有什么影响

- **第一次用会先被问一句**：「要不要读你的历史文章来学你怎么写？」不点头就不会去翻你的旧稿，也不会自动扫整个写作根目录——只读你自己挑的那几篇。
- **画像留不留由你定**：默认写进本次项目文件夹的 `_author-profile.md`；只想用这一次就说一句，画在不落盘；说删就删。
- **价值观与偏好要单独同意**：默认只学「怎么写」（习惯、审美、句子指纹）。「为什么这么写」要问过才提炼，你不同意就写「本次未提取」，不猜。
- **披露模板不再自带会话链接**：会话里常有未公开草稿、私人信息、别人的材料，默认只披露工具与用途。
- **安装包小了一截**：评测、研究笔记、开发文档不再进 registry 的包（ClawHub 上 0.11.0 是 51 个文件，本版 35 个）。

### 修复

- **release 触发的发布步骤其实全被跳过了**：`release` 事件没有 `inputs`，`inputs.publish_clawhub == 'true'` 恒假，于是每次 job 都是绿的、每个发布步骤都是 skipped，registry 上什么都没发生。现在按事件类型给默认值（release = 两个都发、非 dry-run），并加一步「两个开关都关掉就直接失败」，让空转不再是绿的。
- `evals/check-workspace.mjs` 的 `unchanged` 断言重新实现。旧逻辑只遍历跑完之后还存在的文件，于是**草稿被删掉也判「逐字节未变」**——守「用户草稿只读不写」的那条断言其实没在守。现在按快照路径逐个要求「还在、且哈希相同」，跑完之后新出现的受保护文件同样算破坏，一个都匹配不到的 pattern 直接判失败。
- `evals/run.mjs` 的快照改在 agent 动手之前拍。旧版在判定函数里才拍，等于拿跑完的状态跟自己比，结论恒为真。
- 新增 `evals/selftest-unchanged.mjs`：六条回归（原样不动通过 / 改一个字节失败 / 删除失败 / 删整个目录失败 / 新增同名文件失败 / 空匹配失败）。拿旧实现跑这份测试，删除那两条是绿的——漏洞的现场证据。

### 调整

- **第零步改成「先问再读」**：问读不读 → 只读他指定的篇目 → 记什么分两层（默认只提写法）→ 存不存再问一句 → 历史画像只在他点头时读。找不到文章仍然停下来问，不编画像。
- `references/author-profiling.md` 增加「前置：先拿到同意」与删除约定；「读哪些」限定在他同意的范围内。
- 环境探测收窄：只确认 `~/.cc-switch/skills/` 在不在、符号链接指向哪。`cc-switch.db` / `settings.json` 是 provider 配置（可能存 API key），不读，需要时先问。
- `references/platform-compliance.md` 与 `references/sspai-format.md` 的披露模板去掉默认的「会话链接」，并写明贴链接前要先过一遍接收方能看到的全部内容。
- **`SKILL.md` 开头口径改准**：从「AI 只做一致性与事实核查」改成「AI 起草完整草稿、人保留最终写作权与采纳决定」——第七步本来就要求出完整草稿，旧文案与实际流程自相矛盾。
- frontmatter 声明 `allowed-tools`（Read / Write / Edit / Glob / Grep / WebSearch / WebFetch），让宿主知道这个 skill 会用到哪些工具。
- **发布包与仓库分离**：`.github/actions/publish` 先打包再发布（排除 `evals/`、`docs/`、`writing-skill-dev-doc.md`、`.git`/`.github`、`node_modules`、`results/`），ClawHub 不再直接发整个仓库。

## [0.11.0] - 2026-10-15

**跟进少数派创作手册 2026-10-15 修订版：新增 AI 使用披露细化规则 + 四级分级标准，题图尺寸改指向官方页面。**

### 对你有什么影响

- **少数派投稿前多一条扫描项**：AI 使用披露不只是「写不写 callout」，现在还得按 2026-10-15 修订版判断——披露四要素（工具 / 用途 / 目的 / 范围）够不够、有没有触发不豁免的红线、有没有资格走豁免条款。
- **写作目标从「能不能发」细化到「能不能进首页」**：少数派把处理分四级——发布 / 精选 / 首页展示 / 例外首页展示。写作时明确对齐哪一级，比写完再被编辑部打回来便宜。

## [0.6.0] - 2026-10-03

**Quill 不再'不敢下手'了：写作改成两段式——先写完整，再校订。**

### 对你有什么影响

- **它敢动笔了。** 以前「列不出五件材料就不许进入构思引导」，材料不够就卡在门口；现在**材料可以少，但不能假**——有几件列几件，缺口写 `［请作者补：…］` 照常往下写，短而真好过长而假
- **起草期只守一条底线：不编造。** 来源核验、链接补齐、禁用清单检查**全部挪到写完之后**统一做。边写边查会写出没有毛边的稿子，也写不下去
- **「缺口标记」是明确许可的动作。** 没来源的地方，用 `［请作者补：…］` / `［待补链接］` 占位继续写——**这是诚实的缺口，不是编造**。编造是把没有的写成有的，缺口标记是写明「这里还没有」。校订期必须逐个消解
- **禁令不再压着起草期。** 20 项形式级禁用清单从常驻层移到 `references/style-and-bans.md`，**只在改稿时加载**——起草时看不到它们，稿子才有毛边
- 你（用户）的判断权不变：链接在即材料合格，**用不用进文章仍然由你最后判断**

### 新增

- **两段式原则（写进「核心理念」）**：**起草期**只管把手里真实的东西写成篇，不回头、不自查、不因「还没查全」停笔；**校订期**（第九步前后）统一处理核验与禁令。
- **缺口标记机制**：`［请作者补：…］`（材料缺）/ `［待补链接］`（来源待查）——起草期允许留，**校订期必须消解，成稿里不留任何标记**。
- **第七步「起草期许可」**：明确起草期不做三件事（不回头核验 / 不边写边查禁令 / 不因没查全停笔）。
- **第九步新增验证项「缺口标记已消解」**：全稿扫标记，逐个处理（补真实内容 / 删 / 改成不依赖缺口的写法）。

## [0.5.1] - 2026-10-03

**材料出处从「用户亲历 / 公开来源」两分，细化为两类三小类，并把「合不合适用」交回用户判断。**

### 对你有什么影响

- **你自己写过的、和从你公开内容推理得来的，都能当材料用了**——以前规则只认「用户亲历」和「外部公开来源」，你自己的已发表内容没被算作合法出处（哪怕它有真实链接）
- **准入标准变简单了**：只要能找到真实的正确链接，材料就合格。不再看它是亲历还是外部权威
- **选不选用是你的事**：Agent 把链接、类别、推理链摆好供你定，不再在核验阶段就替你判「这条该删」——**最终合不合适进文章，由你最后判断**
- 你没写过、外部也没有的内容，仍然取不到链接 = 不许进正文，标 `［请作者补：…］`

### 新增

- **材料出处两类三小类**：
  - **第一类（你自己的）**：**① 你公开写过的** · **② 从你的公开内容推理可得的**（链接落到你那篇原文，属你的观点、不冒充客观事实）
  - **第二类（客观的）**：**③ 客观事实 + 别人公开写过的**（原始研究、官方统计、监管资料、当事人访谈、别人的已发表文章）
  - 不在来源内：**无链接**——不许进正文
- **准入标准只有一条：能找到真实的正确链接。** 链接在 = 材料合格
- **用户最终裁决原则**：链接在只解决「能不能进备选」，**合不合适用进文章由用户最后判断**。Agent 摆事实供用户定取舍，不替用户拍板

### 调整

- **来源归属分轴**：①② 是「你的」、按你的说法归属（「我在 X 里写过」）；③ 是外部的、按「是谁说的」归属。**自己的内容 ≠ 客观事实**，别把「我写过」包装成「研究发现」，也别把权威结论说成「我一直认为」
- **「合格」与「用不用」分成两步**：Agent 负责第一步（链接、类别、推理链），用户负责第二步（取舍）。第九步验证只核「链接在不在、类别对不对」，不替用户判用不用
- 三处改在 `SKILL.md` 常驻层（第四步硬规则、第九步验证项）+ 两个模板 + `evidence-guide.md` 细则 + `writing-craft.md` 开篇场景来源 + 示例 `evidence.md`，六处一致

0.5.0 建立了「不许编造经历与事件」的硬规则，来源是 **A 用户亲历 / B 公开来源 / C 无来源** 三分。0.5.1 **不放宽这条硬规则**（编造仍然禁止），只是**重新切分来源类别并移交取舍权**：

## [0.5.0] - 2026-10-03

**Agent 不许再编经历和事件。涉及「发生了什么」的内容，必须能指认来源。**

### 对你有什么影响

- **不会再收到一段来路不明的「开篇故事」。** 以前 Agent 想要一个具体场景开头，最省事的做法是编一个——「上周一个设计师朋友跟我说…」读起来像文风，不像造假，所以一直被放过。现在它和编造文献是同一类错误
- **它想要你的经历时，会来问你，而不是替你写。** 取不到场景就换钩子（用问题或数据开头），或者标 `［请作者补：…］` 留给你填
- **你确认过的事，它照写；你没确认的，它不碰。** 你说「看见」仍然不会变成「试过」，你没说过的天气、神态、原话也不会被补上
- 你允许虚构处理时仍然可以虚构，但**交付形式要让读者知道**

### 新增

- **「经历与事件必须可指认来源」硬规则**（第四步）——只有三种来源可用：**A 用户提供的亲历**（不扩写）· **B 能打开的公开来源**（点得开链接）· **C 无来源**（不许进正文）。**Agent 自己的推断与构造不是第四种来源**：组织材料是写作，发明现场是造假
- **边界条款**：具体事件与经历必须指认来源；教科书级别的常识性概括不必逐条附链接，但不能编。判据是「读者追问'你从哪知道的'，你有没有一个真实答案」——**要拦的是编造，不是要求事事举证**
- **与「普通角色推演」的边界**：没有亲历时可以选一个普通角色走一遍流程（`form-guide.md` 已有的写法），只要**不声称是具体发生过的事**、且让读者知道这是常见情形。判据是「**有没有声称它真的发生过**」——把事件写成概括合法，把概括写成事件是编造。**这一条是防止硬规则误伤已有的合法能力**
- **`evidence.md` 模板新增「经历与事件来源」表**：正文每一处「谁做了什么」都要在这里指认来源，附五项自检
- **`style.md` 模板的开篇钩子新增来源栏**：场景与数据必填
- **第九步验证新增检查项**「经历与事件已指认来源」
- **禁用清单新增**「不编造经历与事件」——明说编一个像真的场景，和编一篇像真的文献是同一件事
- **构思引导 Q7**：推荐「场景」钩子前先确认它落得下来，取不到就推荐「问题」或「数据」，或者直接问用户
- **新增 eval 8**：行为测试。prompt 点名要「我上周和同事的那次对话」，但不给任何内容——**这正是模型最容易顺手编一个的地方**。机械断言检查草稿里不出现任何编造的第一人称轶事（此 eval 中用户没给材料，所以出现即是编造）。已验证可双向判定：合规稿通过，编造稿报出「上周我和」

### 修复

- **示例草稿的自我违规**：`ai-draft.md` 正文引用了麦肯锡报告，起草说明却写着「报告原文我没打开核对」——按 quill 自己的规则，打不开的引用不许当已核实来源留在正文。现已标 `［请作者补：报告原文链接］`，并在起草说明里写明处理理由
- **`writing-craft.md` 声音校准**：原来把「上周一个设计师朋友跟我说…」当作**声音范本**举例，等于教模型照抄一个编造的场景。改为提取作者的**写法**（怎么起头、怎么断句），并明确「学他的节奏，不要学他的现场」
- **`writing-craft.md` 假细节**：原来只说「假细节越具体，AI 味越重」——框成文风问题。补上它是**编造**：「凌晨三点」是关于现实的主张，细节越具体读者越会当真，所以越具体越危险
- **`writing-craft.md` 文章骨架**新增「开篇场景的来源」小节：场景只有用户亲历与可打开来源两种合法来源；取不到就换钩子，不要编场景

### 为什么单列这一条

quill 原先的规则覆盖了**外部来源**（文献假引）与**用户经历不被扩写**，但漏掉了中间那块：**Agent 自己编出的经历与事件**。它读起来像文风选择，不像造假，所以是最容易漏的一类。

示例草稿其实一直做对了——Agent 拒绝了朋友对话，理由写着「我没有可核实的现场」。但**这个正确行为只活在例子的散文里，不是规则**，而与此同时有多条规则在往反方向推：第六步要求「开篇钩子要有具体场景」、声音校准把编造轶事当范本、假细节被框成文风问题。**对的行为靠碰巧，错的方向有明文。** 这一版把它扶正。

**给 skill 装上两道闸门：一道免费每次 PR 跑，一道花钱每周跑。**

### 对你有什么影响

- **没有写作行为变化。** 十一步工作流、硬规则、文件边界一个字没动。这一版只加基础设施

- 你现在可以看这个 skill 的「体检报告」了：`.github/workflows/skill-quality.yml` 每次 PR 都会跑

### 新增

- **`scripts/validate-skill.mjs`**：零依赖静态校验器，18 项检查分四组——规范合规 / 路径与版本完整性 / 示例正文自洽 / eval 套件完整性
- **`evals/check-workspace.mjs`**：机械断言执行器。每条 eval 现在分 `checks`（机器判）与 `expectations`（人判）两层
- **`evals/run.mjs`**：跑测编排。为每条 eval 建两个工作目录，一条挂 skill、一条不挂，量 **Skill Lift**
- **`.github/workflows/skill-quality.yml`**：push / PR 触发，只要 Node，不花钱

- **`docs/research/skill-ci-continuous-improvement.md`**：方法与案例调研

### 关键取舍

**为什么必须跑基线。** 在 947 组配对样本上，真实 skill 的平均 Skill Lift 只有 0.2134，且只有 72.8% 为正（[ACES, arXiv:2608.20614](https://arxiv.org/abs/2608.20614)）——约四分之一的 skill 对结果没有贡献甚至有害。只跑带 skill 的那条腿，测试永远是绿的。`run.mjs` 因此默认跑基线，并逐条标注「这条是 skill 挣来的」/「装了 skill 反而挂」/「同分，这条拦不住它」。

**为什么静态扫描不能顶替执行。** 同一篇论文测出静态扫描闸门与 LLM 评判的 Spearman ρ = **0.14**——结构合规与实际效果几乎正交。所以两层必须都有。

**为什么设了 Lift 阈值却不跑基线要判失败。** fail closed。指标算不出来时放行，等于没有闸门。

**为什么校验器要自检。** CI 里有一条 job 故意往 `SKILL.md` 塞一个坏路径，确认校验器确实会报错。失灵的检查器比没有检查器更危险。

### 修复

- **「不碰你的草稿」第一次可以验证。** 新增 `unchanged` 断言：跑之前给受保护文件拍 sha256 快照，跑完比对。这条承诺以前只是 SKILL.md 里的一句话

## [0.1.0] - 2026-09-21

**首个记录版本。** 以此前的内部迭代曾用 2.x 编号，那套编号不再作为版本记录，从 0.1.0 重新开始。

这一条记录的是 0.1.0 的**能力基线**——它包含什么，而不是它改了什么。

### 工作流

十一步，全程模型驱动，不跑脚本：

1. 创建文章项目（六个结构文件 + 引导你建自己的草稿）
2. **材料清点**（硬性门槛，见下）
3. 构思引导（结构化提问，三轮八问 + 说话位置五问）
4. 定义核心论点
5. 收集证据
6. 定义受众状态
7. 定义风格与修辞
8. 写作（Agent 写出完整草稿）
9. 反驳（找反例反驳自己的草稿）
10. 验证（逐项判断）
11. 生成写作简报（可选）

### 文件边界

- Agent 只在自己创建的文章文件夹内读写全部工作
- `claim` / `evidence` / `audience` / `style` / `_index` / `ai-draft` 由 Agent 读写
- **你的草稿只读不写**，无论它叫什么名字
- Agent 按自己的理解写出一篇完整草稿放进 `ai-draft.md`，由你决定采纳多少

### 材料门槛

- 非虚构长文动笔前至少清点**五件具体材料**（事实、数字、原话、亲历、核验过的案例）
- 列不出时只有三条路：研究、追问（最多三问）、缩短篇幅
- 目标字数、你的催促都不能把材料变多

### 材料身份五分法

①可靠事实 ②机构自述 ③旁人回忆 ④作者推断 ⑤未知

- **身份**决定它怎么被写进正文，**可信度**决定它能不能进关键支撑链——两条独立的轴
- 机构自述不能当事实用；来源互相冲突时不挑最适合故事的一条写死
- **用户经历不能代写**：你说「看见」不会被扩写成「试过」，截图不能补出注册与成功运行
- 全靠公开材料时，正文开头附近留一处真实的检索痕迹

### Agent 完整草稿

`ai-draft.md` 是一篇能从头读到尾的完整文章，不是建议清单。附带：

- **起草说明** — 按什么理解写的、假设了什么、哪几段没把握
- **对你草稿的建议** — 只提建议，不改你的文件
- **反驳记录** — 反例与处理，同时回写 claim / evidence

### 写作工艺

- **论点深度**六道测试（已知 / 机制 / 主流 / 推论 / 具体 / 换框）
- **声音校准** — 读作者已发表文章提取声音指纹，起草时对照
- **结构接缝**六条判据（合并 / 独立 / 顺序 / 承接 / 层级 / 一节一主张）
- **句子级规则**十一条：主干先出来、顺势接话、长短句高低差、少用连词、名词还原、允许重复、知识按需出现、说到能接住就停、判断从正面下、白话打底古意看场合、具体细节必须有工作
- **篇章推进** — 按局部问题往前走，不搭起承转合的架子
- **判断要带着来路与边界** — 先讲准最强反方，材料支持七成就说到七成
- **六遍改稿** + **冷读五问** + **可量化自检**（句长变异、连词密度、借喻聚集等十项形状判据）

### 形式分流

十一种形式各自的开篇、推进、结尾要点与常见错误：知乎回答、论坛长帖、公众号与博客、人物与历史、新闻产品与行业解读、观点与评论、个人叙事、教程与方法、评测与商业稿、口播播客演讲、短文与社交内容。

知乎一节含「**先回答 → 后解释 → 最后给动作**」三段结构，以及**没有亲历时怎么写**（走一遍可核验的普通流程并标明是常见情形，只抓最有把握的一两个原因，不必包办整个问题）。

### 硬规则

**形式级禁令**（覆盖成稿：标题、小标题、正文、图片说明、引用转述）：

禁翻案腔（不是A而是B 及其九种变形）、三项以上同构排比、抽象抒情、名词化、破折号、提示性冒号、商业黑话、模型洞察路标、借喻包装。

**规则冲突五级优先级**：用户明确指定 → 作品对现实的承诺 → 硬规则与平台硬规则 → 任务相关 reference → 通用写法。
