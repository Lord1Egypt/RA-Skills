# 设施（测点）属性修改接口说明

**版本**：v1.0 · 2026-11-21
**适用**：YZL-AIoT 平台北向接口（主服 `47.111.84.144:3005` / 测服 `43.139.12.195:3005`）

---

## 一、问题背景

### 之前的问题

1. **设备自动添加的设施无法区分**
   - 设备上报型号未定义的测点 → 平台自动加入型号设施列表
   - 但属性被硬编码：`dataType='decimal'`（或 `text`）、`access='none'`（仅上报）
   - 前端保存型号时 `sanitizeMetrics` 会剥掉 `autoAdd` 标记 → 无法识别哪些是自动加的

2. **改设施属性只能整表覆盖**
   - 唯一接口 `PUT /open/product/:id` 要求传完整的 `metrics` 数组
   - 漏传一项就会丢失该设施 → 风险高

### 本次修复（2026-11-21）

| 问题 | 修复 |
|---|---|
| `autoAdd` 标记被丢弃 | `sanitizeMetrics` 保留 `autoAdd` / `addedAt` |
| 无法单独改一个设施 | 新增 `PATCH /open/product/:id/metric/:key` |
| 前端无法识别自动添加的设施 | 型号编辑弹窗对 `autoAdd` 设施显示「自动」标签（悬停显示添加时间） |

## 二、新接口：修改单个设施属性

### 请求

```
PATCH /open/product/{型号ID}/metric/{设施key}
Authorization: Bearer <token>
Content-Type: application/json
```

### Body（只传要改的字段，全部可选）

| 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|
| `dataType` | string | `int` \| `decimal` \| `text` \| `enum` | 数据类型 |
| `access` | string | `rw` \| `r` \| `none` | 指令可用性 |
| `label` | string | 任意 | 显示名称 |
| `unit` | string | 任意 | 单位 |
| `visible` | boolean | `true` \| `false` | 前端是否显示 |

### `dataType` 选择规则

| 值 | 含义 | 典型用途 |
|---|---|---|
| `int` | 整数 | 信号强度、开度、限位、浮球 0/1 |
| `decimal` | 小数 | 电流、电压、流量、温度 |
| `text` | 文本 | 固件版本、ICCID、位置、时段配置 |
| `enum` | 开关/枚举 | 继电器状态、故障码、工作模式 |

### `access` 选择规则

| 值 | 含义 | 前端表现 |
|---|---|---|
| `rw` | 可查询 + 可下发指令 | 设备详情页出现可操作控件（开关/输入框/按钮） |
| `r` | 仅查询 | 只读展示，不可下发指令 |
| `none` | 仅上报 | 只展示数值，不可查询也不可控制 |

**注意**：`access` 决定设备详情页「数据交互」区是否出现控制控件。想让设施可控制必须设为 `rw`。

### 响应（200）

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "product": "RSTICQ",
    "key": "in1",
    "before": { "dataType": "int", "access": "none", "visible": true, "label": "输入1(浮球1)", "unit": "" },
    "after":  { "dataType": "enum", "access": "r",   "visible": true, "label": "输入1(浮球1)", "unit": "" }
  }
}
```

### 错误码

| HTTP | 场景 |
|---|---|
| 400 | `dataType` 或 `access` 取值非法；无权修改（非创建者且非管理员） |
| 404 | 型号不存在；设施 key 不存在于该型号 |

## 三、调用示例

### 1. 把浮球输入改成开关类型（可画阶梯曲线）

```bash
curl -X PATCH 'http://47.111.84.144:3005/open/product/RSTICQ/metric/in1' \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"dataType":"enum","label":"浮球1(高/低)"}'
```

### 2. 把自动添加的设施改成可查询

```bash
curl -X PATCH 'http://47.111.84.144:3005/open/product/RSTICQ/metric/newSensor' \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"dataType":"decimal","access":"r","label":"新增传感器","unit":"m"}'
```

### 3. 把设施改成可控制（能下发指令）

```bash
curl -X PATCH 'http://47.111.84.144:3005/open/product/RSTICQ/metric/kk1' \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"access":"rw"}'
```

### 4. 隐藏某个设施（不删数据）

```bash
curl -X PATCH 'http://47.111.84.144:3005/open/product/RSTICQ/metric/k6s' \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"visible":false}'
```

## 四、批量修改多个设施

接口是单设施的。要批量改，循环调用即可（每次一个 key）：

```python
import requests

def patch_metric(base, token, product, key, **fields):
    r = requests.patch(
        f"{base}/open/product/{product}/metric/{key}",
        headers={"Authorization": f"Bearer {token}"},
        json=fields, timeout=20,
    )
    return r.status_code, r.json()

# 把浮球三路都改成 enum
for k in ["in1", "in2", "in3", "in4"]:
    code, body = patch_metric("http://47.111.84.144:3005", TOKEN, "RSTICQ", k,
                              dataType="enum", label=f"浮球{k[-1]}")
    print(k, code, body.get("data", {}).get("after"))
```

## 五、自动添加设施的标识

设备上报型号未定义测点时，平台会自动加入型号设施列表，该设施的 JSON 里带：

```json
{
  "key": "new_sensor",
  "label": "new_sensor",
  "unit": "",
  "dataType": "decimal",
  "access": "none",
  "visible": true,
  "autoAdd": true,
  "addedAt": "2026-11-21 00:15:00"
}
```

| 字段 | 说明 |
|---|---|
| `autoAdd: true` | 设备上报自动添加（非人工定义） |
| `addedAt` | 首次出现时间 |

**前端表现**：型号编辑弹窗中，这类设施左侧显示黄色「自动」标签，悬停可看到添加时间。

**用 PATCH 改过任一属性后，`autoAdd` 标记会自动清除**（表示已人工确认）。

## 六、查询现有设施

### 查单个型号

```bash
curl 'http://47.111.84.144:3005/open/product/RSTICQ' \
  -H "Authorization: Bearer $TOKEN"
```

返回的 `metrics` 数组包含所有设施的 `key/label/unit/dataType/access/visible`（自动添加的额外带 `autoAdd`/`addedAt`）。

### 查型号列表

```bash
curl 'http://47.111.84.144:3005/open/product/list' \
  -H "Authorization: Bearer $TOKEN"
```

`metrics` 字段同样完整返回。

## 七、相关接口对照

| 接口 | 用途 | 何时用 |
|---|---|---|
| `PATCH /open/product/:id/metric/:key` | **改单个设施属性** | 推荐，最安全 |
| `PUT /open/product/:id` | 更新整个型号（含全量 metrics） | 改多个设施 + 其他型号字段 |
| `PUT /open/product/:id/metrics-config` | 设施语义配置（control / compare） | 配置对比参数、控制参数分组 |
| `POST /open/product/:id/clean-metrics` | 清理设备多余设施 | 清理自动添加的垃圾设施 |

## 八、注意事项

1. **`access` 改 `rw` 不等于设备支持**
   - 平台会显示控制控件，但设备固件必须真的支持该指令
   - 农污设备控制走 `A3H`，模组设备走 JSON 指令

2. **`dataType` 改错会影响 IoTDB 存储**
   - IoTDB 序列类型首次写入即定死
   - `text` 类型的序列不能写数字，反之亦然
   - 改 `dataType` 只影响平台解析和前端显示，不改变 IoTDB 已存数据

3. **`visible=false` 不删数据**
   - 只是前端不显示，IoTDB 数据仍正常采集

4. **改完立即生效**
   - 接口内部会调用 `clearProductMetricCache()` 清缓存
   - 无需重启服务

## 九、验证记录（2026-11-21）

```
① PATCH /open/product/RSTICM/metric/tui  {"access":"r"}
   → HTTP 200
   before: {dataType:int, access:rw}
   after:  {dataType:int, access:r}

② PATCH /open/product/RSTICM/metric/tui  {"access":"rw"}
   → HTTP 200，恢复

③ PATCH {"dataType":"foobar"}
   → HTTP 400 "dataType 必须是 int / decimal / text / enum 之一"

④ PATCH /open/product/RSTICM/metric/__nope
   → HTTP 404 "设施 __nope 不存在于型号 RSTICM"

⑤ GET /open/device/RSTICM-0000000858
   → tui: dataType=int access=rw  （状态正确）
```
