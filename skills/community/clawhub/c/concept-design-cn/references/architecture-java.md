# Java/Spring 约定

[工程架构](architecture.md)在 Java/Spring 项目中的落实方式，按需采用。职责与依赖边界以工程架构为准；其他语言采用原生等价形式。

## 命名与装配

- Java 包名复合词连写。
- 按需显式装配：模块根放 `<Business>Configuration`，用例组的 `<BusinessScope>Configuration` 只绑定组内组件与端口，`bootstrap/` 放最终装配。跨角色与跨适配器分支装配归 `bootstrap`。
- 在使用方边界用 `<Capability>Properties` 绑定配置。

## 可选：集中管理定时与事件入口

采用 `adapters/inbound/jobs` 集中管理定时与模块事件入口时，在项目约定中声明适用源码与例外，并启用以下架构检查：

- `@Scheduled`、`@ApplicationModuleListener` 仅出现在该包及子包。
- `jobs` 不依赖 `inbound` 的其他子包，如 `web`。

检查实际入口方法、组合注解及重复注解，用正例与违规夹具验证匹配和两项约束。业务任务经用例执行；纯存储生命周期维护可按具体类或方法登记例外，保留在存储层。若由 `jobs` 集中触发，须通过声明的纯技术维护端口，在项目依赖表登记并由 `bootstrap` 装配；禁止直访存储内部或为此增加空转发业务用例。未启用本约定时，不强制建立 `jobs` 或检查注解位置。

## 监听器迁移

按[迁移与兼容](architecture-execution.md#兼容)处理模块事件入口移动：

- 核对显式或默认监听器 ID 及待处理发布记录；默认 ID 可能包含声明方法的全限定名，模型规则身份不等于框架监听器身份。
- 按存量保留稳定 ID 或迁移记录，验证旧记录能在重启后恢复，不会漏执行或额外重复。
- 注解位置约定不要求替换监听注解或改变事务与异步语义；验证实际效果及适用的恢复行为。
