# 公众号文章拆解

把一篇中文深度长文拆成两套可复用能力：作者的**思考路径**（怎么想）和**举证手法**（怎么证）。

产出不是内容摘要，也不是"这篇文章讲了好在哪"的感想，而是一份结构化的写作机理拆解，让用户能把作者的思考骨架和举证手法迁移到自己的选题上。

## 核心原则（不可违反）

1. **引原文作证**：每一条判断都必须有原文依据。禁止脱离文本的空泛总结。判断后面要能跟上"文中怎么写的"。
2. **数字标待核实**：文中所有具体数字（薪资、金额、家数、日期）都视为待核实素材，在报告里明确标注，不当作统计结论引用。
3. **分析机理，不分析传播**：聚焦"怎么想、怎么证"，不要滑向"为什么火、阅读量多少、怎么涨粉"。
4. **先摆事实，判断只多走一步**：这是所拆解文章的共同特征，本 skill 的输出也要克制，不替作者脑补动机。

## 工作流

### 第 1 步：拿到正文

- 用户给了链接 → 用 WebFetch 抓取全文，prompt 要求逐段保留原文、小标题、数字、案例，不要总结。
- 用户直接贴了正文 → 直接使用。
- 抓取失败或正文不全 → 告知用户，请其粘贴文本，不要基于标题臆测。

### 第 2 步：双维度拆解

按下面两个维度分析。详细判据见 `references/framework.md`，此处给出必须回答的核心问题。

**维度 A · 思考路径**

回答"作者怎么把现象凿成判断"，逐条列出推理链，每条要用文中的实际内容佐证：

1. 切入点：从什么现象开场？是共识还是反常识的矛盾？
2. 拆词：把哪个模糊概念拆成了两个指向相反的东西？
3. 中间层：追问了什么被忽略的"消失的那一段"？（这通常是题眼）
4. 换维度：是否在某个点横向切到另一个维度交叉验证？
5. 收口：最后落在情绪上还是结构上？用政策/数据还是金句收尾？

同时提炼作者的**判断标准**（他用什么判据下结论，例如"谁担责""看不看得出来"），这类标准往往比结论本身更可迁移。

**维度 B · 举证材料与引用手法**

分两部分：

1. 材料清单：按类型归纳，每类写清「具体材料 / 引用方式 / 在论证中顶什么用」三列。常见类型：招聘或行业信息、薪资或业务数字、人物案例、司法判例、政策条文、行业历史基准。
2. 引用手法：识别作者用了哪些手法。重点找这七种：
   - 精确数字制造现场感
   - 并置而不下判断（把两样东西摆一起，让读者自己得出差距）
   - 转述为主、引号只给金句
   - 跨行业材料靠接口句合法接入
   - 具名撑可信度、化名撑故事感
   - 用案例但划边界（主动说明可比性限制）
   - 材料严格对应结构，每类只顶一个环节

用 Toulmin 模型还原主干论证：主张 / 证据 / 推理 / 限定 / 反驳。

### 第 3 步：证据质量评估

明确回答三个问题：来源是否给出处？是否有跨行业拼接？结论是统计事实还是观察性判断？给出"哪些能拿走、哪些要核实"的诚实提醒。

### 第 4 步：产出报告

按 `references/output-template.md` 的结构输出。默认输出结构化 Markdown；用户要求文档文件时，再另行排版。

## 使用注意

- **N 步而非固定五步**：思考路径的五步是常见形态，不是硬模板。文章只有四步或六步时如实反映，不为凑数硬套。
- **不要替作者美化**：如果作者论证有漏洞（来源模糊、以偏概全），在证据质量评估里如实指出，这本身就是分析价值。
- **区分"分析文章"和"复刻文章"**：本 skill 产出拆解报告。用户若要求照着写一篇新文章，那是另一轮创作任务，不在这里直接生成。
