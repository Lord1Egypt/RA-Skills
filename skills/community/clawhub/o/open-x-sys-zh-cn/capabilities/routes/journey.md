# 旅程：七个阶段及其关系

> **何时读**：需要判断一个请求依赖什么；这个人从中途进入（一个决定、一次搭建、一次复盘），你要判断前面的阶段该做多少；或者一次运行卡住了，你怀疑跳过了某个阶段。

旅程提供七个可选择的方向，方便人找到自己关心的问题、选择方法或回顾成长。它说明**眼前的工作需要哪些认识和结果**。已满足的条件直接用，新的反馈可以从任意方向进入。

```text
   ┌──────────────────────────────────────────────────┐
   ▼                                                  │
 看懂 ──► 解释 ──► 预见 ──► 找准 ──► 选择 ──► 创造 ──► 改进
   ▲        ▲        ▲                                │
   └────────┴────────┴───── 新的证据会把你带回前面 ────┘
└──── 看清它怎么运转 ────┘ └ 想清怎么做 ┘ └ 做出来 ┘ └ 越做越好 ┘
```

## 七个阶段

| 阶段 | 问题 | 需要的能力 | 做得好的标志 |
|---|---|---|---|
| **1 · 看懂** | “它是什么？怎么运转的？” | 画出整体；看见事件之下的结构；跟踪流动的东西；找到回路；估算量级 | 这个人能用一句话说出它怎样运转，而且这句话不是人人都会说的那一句 |
| **2 · 解释** | “它为什么会这样？” | 拆到一定成立的东西；追溯来历；找到限制它的东西；跟着激励走；从别人的眼睛看 | 这个解释能预言一件可以核对的事，并说得出什么会证明它错了 |
| **3 · 预见** | “接下来会怎样？如果……呢？” | 推演后果以及后果的后果；问什么会让它失败；跟踪对其他系统的连锁影响 | 有几种真正不同的未来，每一种都带着会预告它的早期信号 |
| **4 · 找准** | “在哪里用力最有效？” | 找到那几个一推就变化最大的地方 | 一张简短的排序清单，写明效果与代价，并指出许多不值得做的事 |
| **5 · 选择** | “对我们来说，最好的做法是什么？” | 发现、比较、适配实践；权衡选项及其可逆性 | 一条适合这些条件的推荐路径、它的代价、什么时候会改变，以及一个低成本的第一步验证 |
| **6 · 创造** | “把它做出来。” | 把认识做成成果；设计；把各部分连接成新的能力 | 有一样完成的、能用的东西：一份值得署名的成果，一项在真实工作上验证过的能力 |
| **7 · 改进** | “有效吗？接下来呢？” | 对照意图与结果；学习；盯住重要的信号 | 系统的认识和实践真的变了，并且有东西正在被盯着 |

人们听到的是四个阶段：**看清它怎么运转**（看懂、解释、预见）· **想清下一步怎么做**（找准、选择）· **把它做出来**（创造）· **越做越好**（改进）。对这个人说话时用四个阶段，自己思考时用七个阶段。

## 各阶段之间的关系

**有效工作可以彼此借力。** 有根据的预见可以借助能解释现象的模型。一次试做也可能反过来让问题被看清。创造可以从明确的委托、现成工具、草图或实验进入。看此刻需要什么条件，再取用已有认识或临时补齐。

**向后：改进会回馈前面每一个阶段。** 一个与意图不同的结果，是关于系统怎样运转、为什么、接下来会怎样的新证据。把它送回它该去的地方：一幅画错的图景、一个找错的原因、一个漏掉的后果、一个选错的杠杆点、一项不适合的实践。系统会越来越好而聊天不会，原因就在这里。

**从哪里进入都行。** 人们从自己的需要所在的地方进来。问“我们该涨价还是降成本”的人，是从“选择”进来的。说“把它做成视频”的人，是从“创造”进来的。悄悄地、有分寸地补上这个请求所依赖的前面阶段：

- 这个人的系统里已经有前面的认识，就用上它，不重做。
- 没有，就把前面的阶段做到足以让答案站得住，并且只展示答案需要的部分。这个人要的是一个决定，不是一次导览。
- 前面的阶段如果发现了会改变问题本身的东西，就说出来。那常常就是揭示。

**提前离开没有问题。** 不是每个请求都要走到“改进”。“帮我搞懂 ___”到一份成果就完整了。重要的是系统记下停在了哪里，以后的运行才能从那里接着走。

**它是一张依赖地图。** 七个阶段说明一种完整结果建立在哪些认识与能力之上。系统可以从任何真实位置进入、返回证据、跳转尺度或并行展开；用户经历的是发现怎样形成，以及自己现在可以拿它做什么。

## 阶段之下的六个问题

六个零级问题（可区分性、时间、空间、状态、相互作用、约束）在每个阶段都会被问到。每个方法，都是把其中一两个问题朝某个方向追问下去的一种广为人知的方式：

| 方法族 | 主要追问 |
|---|---|
| 开启、边界、尺度 | 可区分性与空间：它是什么，它在哪里结束，在哪个尺度上它才是它 |
| 透视、回路、流动、连接、涌现 | 相互作用：什么影响什么，什么在积累，什么在反馈 |
| 溯源、推演、二阶思考 | 时间：它怎样形成，之后会怎样，延迟多久 |
| 估算、关键少数、盯住 | 状态：有多大，有多集中，现在正怎样变化 |
| 第一性原理、瓶颈、矛盾、应变、存续 | 约束：什么一定成立，什么限制着它，它缺了什么就不行 |
| 激励、换视角 | 人与人之间的相互作用：谁想要什么，每个人看到什么 |
| 杠杆、最佳实践、权衡、设计、搭建能力、复盘 | 把这些问题转向行动：在哪里用力，什么适合，做什么，发生了什么 |

没有哪个有名字的方法适合眼前的对象时，就回到这六个问题。它们永远适用。方法之所以存在，是因为它们的名字为人所知、结果容易辨认，而不是因为它们穷尽了思考的方式。

## 判断该走多远

默认全力开启（见 `SKILL.md` 第七节）。系统主动补足当前结果真正依赖的认识、检验与能力，让用户直接得到与问题规模相称的完成度。

- **可靠图景经受过反驳。** 认识至少经历一次可能推翻它的检验：核对预测、寻找反例或比较另一种解释。
- **可用推荐带着条件。** 路径写明它依赖什么、什么时候会改变，以及如何低成本验证。
- **完成成果经过实际体验。** 可渲染、可运行或可打开的作品在交付前真正看过、用过并改过。
- **演化留下未来差异。** 有价值的新认识、作品、能力、关系或纠正进入相应系统；当前没有值得持久化的变化时，成果本身仍保持完整。

## 从实践一侧看这段旅程

最佳实践研究就是同一段旅程：认识系统、发现能力鸿沟（看懂、解释）→ 预测后果、选择值得尝试的路径（预见、找准、选择）→ 建立连接、执行实践、先低成本验证（创造）→ 系统改变，状态、结构、实践或目标（改进）→ 下一轮。见 `engines/build.md`。

## 人的能力沿着旅程生长

一个人的成长，也沿着同一条路衡量：看见结构、解释原因、预见后果、找到杠杆、选出适合的做法、创造并改进。见 `system/growth.md`。
