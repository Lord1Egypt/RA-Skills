# 户型尺寸与动线校验引擎（renovation-143m）

> 空间校验的完整规则与分级标准。设计类任务必读；验房/风格/预算类问题可跳过。
> Full rules for geometry/circulation validation. (Reference module — read before any layout/design/render task.)

## 1. 核心原则

装修方案必须先满足真实空间约束，才能进入效果图生成阶段。

能力边界声明（强制）：
- 具备可编程几何模型时 → 执行真实的几何交集/净空计算。
- 只能通过图片视觉检查时 → 结果标记「视觉推测」，禁止标记「精确几何验证通过」。
- 任何情况下不得把视觉猜测包装成精确尺寸验证；不能把纯文字检查伪装成几何计算。
- 不支持精确计算时，必须明确说明能力边界；不得因工具不支持就跳过必要验证并宣称成功。

## 2. 户型几何数据模型（唯一数据源）

数据文件：`references/house-geometry.json`（mm 为统一单位）。

### 2.1 房屋级字段
建筑面积、套内面积（如有可靠资料）、坐标系与原点、实际朝向、室内层高、各区域地面标高、图纸比例、单位（mm）、数据来源、测量精度、最后核验时间。

### 2.2 空间节点（room_id 命名规范）

| ID | 名称 | 说明 |
|----|------|------|
| bedroom_master | 主卧 | 东南侧 |
| bedroom_secondary_1 | 次卧一 | 西南侧 |
| bedroom_secondary_2 | 次卧二 | 东北侧，保留卧室属性 |
| living_room | 客厅 | 中部 |
| dining_room | 餐厅 | 北侧 |
| kitchen | 厨房 | 北侧 |
| bathroom_dining | 卫生间A | 餐厅旁公卫，唯一可装小便池 |
| bathroom_former_master | 卫生间B | 原主卫，规划公共入口 |
| balcony_south | 南向阳台 | |
| platform_north | 北侧设备平台 | 已获准打通意向 |
| office_gaming | 办公电竞区 | 客厅内功能分区，不计为独立房间/第四卧室 |

每个空间记录：唯一 ID、名称、原始功能、目标功能、长宽面积、多边形边界（坐标点）、门窗位置、相邻房间、主要家具、通行区域、是否可改造、关联需求（REQ-…）、数据可信度（measured / estimated / unknown）。

### 2.3 墙体与建筑构件
区分：承重墙、非承重隔墙、剪力墙、梁、柱、烟道、管井、外墙、门窗、设备设施、**结构性质未确认的墙体**。未经证实的墙体不得自动归类为可拆墙；每一处墙体变更记录依据。

### 2.4 图纸读取规则
优先读取可解析的 CAD/DXF/DWG 等几何数据；不能直接解析时用合适的转换工具。只有图片时：
1. 先根据指北针统一方向（不得把屏幕上下左右当真实方位）；
2. 按图纸标注识别尺寸；
3. 建立近似几何模型，无法确认的数据标注 unknown；
4. 每项尺寸保留来源；
5. 严格区分「图纸标注尺寸」与「图像估计尺寸」；
6. 严禁用图片像素比例推断所有墙厚和门洞尺寸后声称已精确测量。

## 3. 家具真实占用模型

家具不能只存长宽高，必须记录使用所需空间，区分**静态占用面积**与**实际使用占用面积**：

- **电脑桌**：桌面宽深、显示器支架空间、主机位置、椅子常规占用区、椅子后退距离、人起身活动区、线材插座位置。
- **餐桌**：桌体尺寸、餐椅尺寸、餐椅拉出距离、落座后空间、餐椅背后通道。
- **衣柜**：柜体深度、柜门类型、柜门开启空间、取物站立空间。
- **床**：床体尺寸、床头柜占用、上下床空间、衣柜与床相对位置。

家具放得进去 ≠ 家具能正常使用。

## 4. 空间冲突检测清单

### 4.1 几何碰撞
家具与墙体重叠 / 家具与家具重叠 / 门扇与家具、其他门碰撞 / 玻璃移门与橱柜碰撞 / 橱柜与水槽位置冲突 / 家具遮挡门窗洞 / 卫生间洁具互相挤占 / 新建隔断阻断通行区。

### 4.2 使用空间冲突
电竞椅后退挡走廊 / 餐椅拉出挡厨房入口 / 衣柜门开时碰床 / 卫生间门开时碰马桶 / 冰箱门开影响过道 / 洗碗机拉出后无法站人 / 书桌椅占用进卧室必经路线。

### 4.3 建筑条件冲突
新门洞位于未确认可开洞墙体 / 家具遮挡管井检修口 / 设备移位缺少依据 / 改造破坏必要建筑构件。

## 5. 通行动线校验

将空间入口、门洞、关键功能区转换为节点，生成动线网络。固定路径：
入户门→客厅 / 入户门→餐厅 / 客厅→主卧 / 客厅→次卧一 / 客厅→次卧二 / 客厅→卫生间A / 公共区→卫生间B / 客厅→阳台 / 餐厅→厨房。

每条路径检查：真实连通；是否穿越他人私密房间；家具阻挡；最窄处净宽；门开启后实际通行空间；明显绕行；与家务动线冲突。

**两条硬性路径验证：**
1. 卫生间B：必须存在从公共区域不经过主卧的有效路径——门画在墙边 ≠ 公共入口已实现。
2. 电竞区：电脑椅实际使用状态下，进入主卧和卫生间的主要路径仍畅通。

## 6. 净宽设计目标（初步设计参数，非统一法定标准，阈值可配置）

| 场景 | 初步设计目标 |
|------|-------------|
| 主要公共通道 | 尽量 ≥1000mm |
| 局部次要通道 | 尽量 ≥900mm |
| 电竞椅后方兼通道区 | 优先预留约 1000–1100mm |
| 餐桌椅后方通行区 | 按椅子实际拉出状态计算 |
| 卫生间门洞 | 按实际门型、净宽及相关要求确定 |
| 床边活动空间 | 按床型、家具和使用习惯确定 |

不满足时：明确指出 + 展示实际计算值 + 解释影响 + 给修改建议。尺寸未知时：标记「无法验证」，禁止编造净宽，禁止标注合格。**未经验证的净宽不允许在图上随意标注「≥1.0m」。**

## 7. 校验结果分级

| 级别 | 含义 | 处理 |
|------|------|------|
| PASS | 有足够尺寸与几何证据，满足校验条件 | 可作为已验证部分 |
| FAIL | 发现明确冲突（门扇与柜体重叠、通道被完全阻断等） | **阻断进入「已验证」状态，必须修改后重验** |
| UNKNOWN | 缺少真实尺寸/构件信息等数据 | 不得伪装成 PASS；可继续生成条件性概念方案，但必须显著披露 |
| NOT_APPLICABLE | 当前设计不涉及该项目 | 跳过并注明 |

## 8. 本户型固定回归测试

每次方案变更后必须重跑：

1. 餐厅旁公卫是否放得下小便池（结合 REQ-BATH-004 取舍规则）
2. 原主卫是否真的从公共过道进入（不穿主卧）
3. 原衣帽间是否已取消且未变成新房间
4. 三间卧室保持完整（东北间未被改成书房）
5. 厨房玻璃门不与水槽/橱柜冲突
6. 北侧设备平台连通方案合理（范围与边界待核实项已标注）
7. 电竞椅后退不挡主卧入口
8. 餐椅拉出不挡公卫门
9. 阳台中间无凭空新增门
10. 主卫门、次卧门互不干扰

测试通过标准 = 规则正确执行 + 结果如实分级。**「规则执行成功」不得解释为「实际住宅方案合格」**——依赖现场尺寸的测试在数据缺失时输出 UNKNOWN。
