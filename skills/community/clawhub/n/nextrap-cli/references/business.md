# 理解线索并选择调查路径
<!-- reference-type: common -->

> **范围**：解释 Nextrap 公共请求数据能回答什么，以及如何从 IP、URL、产品名称选动作；不扩展 CLI 能力、不制定后台权限，也不执行漏洞验证。
<!-- slot: 范围 -->

## 先把用户的话落到数据对象

| 线索 | 能直接回答的问题 | 不应混淆的概念 |
|---|---|---|
| 来源 IP | 基础归属；指定窗口内出现的请求、活跃日期、类型和产品分布 | 来源地址可能是代理或共享出口，归属地、ASN 不等于行为人的真实身份；基础归属不代表恶意评分。 |
| URL 或接口路径 | 哪些请求包含该线索、来源有哪些、主要方法与类型、某条前后的动作 | 完整 URL 和路径片段不同；平台记录里的请求地址不自动成为已验证的真实受害站点。 |
| 产品名称 | 该名称对应公共产品范围内的请求、不同来源、路径和类型分布 | 按名字检索日志不需要产品管理命令；同名可能对应多个产品编号，不能把名称当稳定唯一 ID。 |
| 已有日志定位信息 | 当前权限可读全文，或同一边界记录前后的请求 | 日志 ID、真实日期、产品编号来自同条结果；产品编号不是 IP，也不是产品名称检索条件。 |

条件写法只维护在 [query.md](query.md)。用户给的是品牌、产品系列或模糊简称时，按其原意使用包含匹配并说明范围；只有无法区分其意图时才问具体产品，不能自行补版本、CVE 或产品编号。用户只给产品编号而没有可用名称或已有日志时，当前名称字段不能替代编号检索，先补所需输入，不伪造 `product_id` 检索字段。

## 按问题选择证据，避免把命令跑满

- **要看发生了什么**：取少量原始日志，保留来源、时间、方法、URL、产品及打码/截断标记。除非用户明确要路径去重，否则保留重复请求，因为重复次数也是观察的一部分。
- **要看规模**：不同 IP、国家或产品数量用对应去重计数；请求集中在哪里用对应维度分布。不要抓多页日志后用本地条数冒充总量，也不要为一项统计请求所有维度。
- **要调查一个 IP**：窗口内活动给出请求数和时间，再决定是否需要日志样例。用户只问归属时，基础信息已足够；用户问具体行为时，仅归属信息不足以回答。
- **要看先后动作**：从已选日志进入上下文，不把相同 IP 的任意两条记录拼成同一攻击链。上下文还约束同产品和蜜罐，且只返回有限邻居；可按真实时间排序展示，但保留边界和方向。
- **要看完整载荷**：按下一节区分截断和打码；检索到摘要不代表已经读到全文。结果已回答问题时停止，不把可继续查询当成必须继续。

从分布到日志、从 IP 活动到上下文的数据传递分别见 [分布下钻](workflow-distribution-drilldown.md) 和 [IP 调查](workflow-ip-investigation.md)。

## 全文、打码和解密如何选

| 看到的情况 | 业务判断与下一步 |
|---|---|
| 现有预览已足够回答 | 直接分析可见证据，不因存在全文命令就再取一次。 |
| `req_body_truncated=true`，需要后半段且未打码 | 使用同条 ID 与日期调用 `log show`；这是加载已存储全文，不是解密，不消耗解密次数。成功后仍检查返回标记，不能凭命令名承诺完全未过滤。 |
| `mask_reason_code` / `mask_reason` 提示受限，或 `show` 被拒绝 | 说明可见边界，保留已取得证据。截断和打码可以并存；`show` 不能绕过打码。 |
| 用户要求读取受限内容 | 按 [log.md](log.md) 的解密条件、[status.md](status.md) 的余额说明处理；只有已授权的单条解密才执行。不能把“分析这个 IP”自动扩成解密所有样例。 |
| 解密或上下文超时 | 这次调用可能已经消费，不能把未收到结果写成未扣次或自动重复；按主文件错误处理保留不确定性。 |

成功读取的是平台存储的请求，仍可能经过敏感信息过滤；不要恢复被遮蔽的字符、据空字段补造载荷或承诺再次解密不消费。

## 权限、数量和时间共同限定结论

字段目录说明哪些条件可用，不等于能读取正文。`current_account_allowed=null` 是未知，不是明确拒绝：用户已授权且语法明确的公共查询可以交由后台判定，不能据此承诺有权限，也不能切账号或环境绕过拒绝。

记录总量、去重对象数、分布桶种类数和桶内请求数是不同量；近似聚合不是精确盘点。样例代表本次返回，不能从几个样例推断全部流量的占比。产品名、攻击类型标签和 IP 归属是平台提供的上下文，不是独立取证结论。

请求窗口可能被后台按账号进一步裁切。IP 首末活动是有效窗口内的观察；上下文窗口来自边界日志真实时间，不能把所有时间都改成查询当天。没有结果只说明本次条件、窗口和身份下没有返回，不能据此判断目标安全或此前没有发生过行为。

## 自检

- [ ] 回答的是用户的 IP、URL 或产品问题，未凭名称补出 ID、版本或漏洞结论。
- [ ] 取样、计数、分布、全文和上下文各有用途；没有为完整感执行无关调用。
- [ ] 结论与事实分开，清楚区分请求尝试、攻击成功和未知结果。
