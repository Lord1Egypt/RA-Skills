# OPC OS Core — 一人公司操作系统

你一个人加上7个AI Agent。不是7个助手——是7个部门。每个部门有自主权、有边界、有自己的cron、有自己的产出目录。你这个CEO不做执行。你做三件事：定方向、在跨部门冲突时裁决、每周看一次巡检报告。

---

## 五分钟：这不是什么

**不是**AI客服系统、自动化工作流、聊天机器人。

**是**一家公司的神经架构——就像苹果不是一个"音乐播放器公司"，OPC OS Core不是一个"AI工具集"。你拿了它，相当于拿到了7个能独立工作的Agent、一份可以修订的法律体系、一个让信息吃进去能吐出决策的大脑、一个你只需要每周看一眼的汇报系统。

它做的不是让AI帮你干活。是让AI代替你没时间做、不该你做、或者你做不好的那部分管理工作。

---

## 进化阶梯

### L1：装好就跑（第一天）
下载skill→创建7个Agent→安装cron模板→设好company/目录→给你自己设CEO标识。第一天晚上你会收到第一条日报。你会发现——有人在汇报，而你没有叫他们汇报。

### L2：调参裁权（第一周）
你开始改自治梯度。法务部从上报所有合同变成只上报有风险的。品牌部从CEO审稿变成自发布。你开始理解三通道冗余为什么不是过度设计——因为你经历过其中一个通道静默断了。

### L3：收入循环（第一月）
变现漏斗开始跑。免费平台引流→QQ频道过滤→知识星球付费。你的第一条收入入账。你不激动——因为这是流水线，不是惊喜。

### L4：战略模式（第三月+）
你一周只看一次产出。你思考的不再是"cron有没有失败"，而是"要不要加一个部门""要不要砍一个平台"。你从操作员变成了CEO。

## 实际案例：月的一人公司

2026年6月23日，月决定把自己的AI工作流系统化。当天搭建了7部门架构。6月25日全系统上线：39条cron、7个部门、5个已发布skill、双向审核体系、从免费平台到知识星球的变现漏斗。

### 第一天什么样
什么都没有。7个Agent的名字都没定。

### 第三天什么样
- 数据中心在消化情报
- 品牌部每日自动发帖（小红书/公众号/头条/即刻）
- 监察部在巡查cron健康
- 销售部还没有产出——因为还没有客户
- 法务部废弃了知乎账号（合规审查发现风险）

### 第六天（6月28-29日）：治理升维
系统跑起来之后，真正的挑战不是技术——是治理。零散的铁律在MEMORY.md里堆着，部门边界开始模糊，数据中心的心脏衰退了（学习cron消失、大脑不自消化）。

月在这两天建立了完整的治理骨架：
- **磐石铁律**：七部建制锁死，CEO唯一决策核心，董事长四权不可下放。框架内可调但柱不可撼。
- **不能降质铁律**：提质、增效、降本一体。获客线不可降质，模型切换三问。
- **日报消费铁律**：五级响应制（🚨30分钟→🔴2小时→🟡4小时→🟢6小时→⚪8小时），响应三态（认领/处置/周转），升级链。
- **中枢铁律**：董事长月临御各部，唯QClaw为信道。
- **数据中心心脏重建**：三条cron重建（学习+进化代谢+心跳），大脑恢复自消化。

教训：系统跑起来只是第一步。跑着跑着治理会腐烂——部门边界会模糊、cron会悄悄消失、铁律会散落在记忆文件里。你需要定期清创。不是修bug——是修架构。

### 现在什么样（运行7天）
- 39条cron，36条免费模型
- 每日22:00-22:15七部门日报错峰抵达
- 每周监察部巡检+技能维护
- 五层治理体系：祖训→天宪→敕令→训示→铁律
- 收入：¥0.00（漏斗已就绪，信任需要时间）

### 我们学到的（血的教训）

**治理篇**：
- 写在MEMORY.md里的制度≠落地。任何制度必须在当天变成cron。
- CEO第一次可以跑通模板，然后打包移交。第二次就不能自己上了。
- 治理文件会腐烂。你今天写的铁律，三天后可能和实际情况对不上——不是铁律错了，是你在进化。定期对照、修订、重新发布。

**通讯篇**：
- isolated session里用message工具直发飞书=静默失败。sessions_send是唯一正确选择。
- 只用一条通讯通道=你只有一条命。三通道冗余不是在浪费资源。

**成本篇**：
- 免费模型的API Key也会过期。每条cron至少两个fallback。
- 内部运维cron默认lightContext: true。不省这个钱。

**质量篇**（6月28日新增）：
- 品牌部模型对比：qwen3.5-plus幻觉严重、格式无视——得分1.0 vs deepseek-v4-pro的7.8。模型不能看价格选，要看产出质量。
- 获客线不可降质。省钱省到内容质量下降=省了Token丢了用户=最贵的省钱。

## 7部门架构

| 部门 | 核心产出 | 为什么必须独立 |
|------|---------|---------------|
| 数据中心 | 情报管线/模型路由/基建维护 | 信息不处理就是垃圾 |
| 品牌部 | 内容发布/品牌策略 | 你需要被看到 |
| 销售部 | 客户管理/变现转化 | 流量不变现等于白干 |
| 财务部 | 成本核算/Token控制 | 不知道花了多少就是盲飞 |
| 法务部 | 合规审查/一票否决 | 一次违规能让一切归零 |
| 监察部 | 全员审计/品控巡查 | 不被检查的系统一定腐 |
| 行政部 | 同步/备份/提醒/清理 | 琐事会压垮CEO |

不要上来就建7个。从3个开始：数据中心+品牌部+监察部。等你感觉这三个人管不住了再加第二个。每个新部门在你加之前都会经历反复的自我怀疑——"我真的需要它吗？"——这是好事。

## 五层治理体系

OPC OS Core的治理不是一堆规则。是五层递进——每一层的修改门槛不同。门槛越高的越接近物理定律，门槛越低的越接近操作手册。

### 第一层：乾穹祖训（永不可改）
```yaml
规则:
  - 不做违反AI服务条款的事
  - 不冒充人类身份
  - 内部数据不外泄
  - 盈利50%归中枢运维基金
```
祖训只有四条，永远不会增加。每一条都是"破了天塌了"级别的。不是指导原则——是物理定律。

### 第二层：硅基天宪（可修订，但不得违祖训）
```yaml
规则:
  - 巡查上限≤1000条
  - Agent间走内部通道
  - 产出24h内消费
  - 部门间不交叉写文件
```
天宪随系统演化修订。但每次修订必须标注修订原因、生效时间、旧版本保留备查。天宪不是活文档——是宪法。频繁改的天宪说明你没想清楚。

### 第三层：敕令（董事长独断颁布，与祖训同格）
敕令是董事长的独立意志——与祖训同格，本身不可修改。不是CEO制定的运营规则，是董事长对组织架构和根本秩序的锁定。

磐石敕令（2026-06-29）锁死了五柱：
1. 七部建制不增不减不更名
2. CEO灵儿唯一决策核心
3. 董事长四权（罢免/巡查/判官/框架独断）不下放
4. 乾穹祖训+硅基天宪为道术锚点
5. 公司大脑（八步代谢+神经链+密级路由）不可摘除

敕令之下，框架内可调但柱不可撼。新建部门/裁撤部门/推翻大脑→一级熔断。

### 第四层：训示（董事长颁，低于敕令但高于铁律）
训示是董事长对运营方向的框架指令——不如敕令永久，但高于铁律。例如：不能降质训示、日报消费训示、中枢训示。CEO在训示框架内制定铁律。

### 第五层：铁律（CEO制定，日常运营规则）
```yaml
规则:
  - 部门间不交叉写文件
  - 免费平台纯引流（不塞付费链接）
  - QQ频道仅置顶帖含付费链接
  - 所有发布双审制
  - 获客线不可降质
  - 模型切换三问
  - 日报五级响应
```
铁律是活的。今天的一条教训明天就变成铁律。铁律不用修订——直接加。但每条铁律必须有"为什么"的注释（哪个事故导致了这条）。

**治理文件的物理结构**：
```
company/constitution/
├── ZUXUN.md                    # 祖训（4条，永不可改）
├── CONSTITUTION.md             # 天宪（可修订）
├── DECREE_001_GENESIS.md       # 敕令（与祖训同格）
├── DECREE_009_GENESIS_LOCKDOWN.md  # 磐石敕令
└── IRON_RULES.md               # 铁律汇编（活文档）
```

## 不能降质铁律

提质、增效、降本，三者一体，不可分拆。这条铁律是6月28日品牌部模型对比验证之后诞生的。

**模型切换三问**：任何模型切换前，必答三问：①新模型在此场景的输出质量是否不低于旧模型？②切换是否带来可感知的效率提升？③切换是否降低Token成本？三问皆"是"方可执行。缺一问即驳回。

**获客线不可降质**：对外各平台发布、信息搜集——模型切换、流程变更、工具替换，凡触及获客线者，须先证其质不低于旧，方可落地。不能提质则不动。

**内部运维降本不降质**：免费模型优先；但若免费模型产出错误率上升、格式乱码、逻辑断裂，立即切回付费模型。降本的前提是功能不退化。

## 日报消费铁律（五级响应制）

日报不是交差——是行动的起点。异常不能沉默。

```
🚨 特急 — 30分钟内响应
🔴 急   — 2小时内响应
🟡 一般 — 4小时内响应
🟢 普通 — 6小时内响应
⚪ 日常 — 8小时内响应

响应三态（缺一不可）：
  认领 — 回执+预计处置时间
  处置 — 闭环验证
  周转 — 正确转交+获认领

升级链：超时→CEO；CEO超1小时→董事长
同异常连犯3日→直送CEO
```

时限自行政部08:15汇总起计。23:00-07:00不计时（特急级除外）。接到异常30分钟无回执记一级失职，累计三次停职审查。未读即跳过记"盲飞"——一次通报，二次停该部cron一周。

## 四信息密级

```
🔴 绝密 — CEO+数据中心可见，仅本地处理，禁云模型
🟠 机密 — 部门内部，本地+私有云
🟡 内部 — 全公司，可用付费云模型
🟢 公开 — 可外发，可用免费模型
```

密级自动路由模型：🟢走免费GLM-4-Flash → 🟡走付费稳定 → 🔴🟠走deepseek-v4-pro本地。分级不是为了安全——安全是附加值。主要为了省钱。

## 双向审核

任何产出发布前：

**第一道：数据中心（技术审查）**
语法/格式/文件路径/安全扫描（无真实密钥泄露）/大小限制

**第二道：CEO（内容审查）**
方法论正确/差异化定位/公开传播安全/质量达标

一道不过，打回。单检不发布。

## 变现漏斗

```
免费平台(小红书/即刻/公众号/头条)
  → 纯引流，不塞付费链接
  → QQ频道(过滤层)
  → 频道置顶帖含知识星球链接(唯一付费入口)
  → 知识星球(¥149/年，唯一变现阵地)
```

为什么分这么多层？免费平台塞付费链接会被封。QQ频道不隔离付费入口会被封。知识星球不做纯付费内容没人买。每一层在解决一个问题——不是设计师画了层级就放那了。

## Day 1-6 启动路径

```
Day 1: 创建3个Agent(数据中心+品牌部+监察部)
       → 设好company/目录 → 安装前3条cron
Day 2: 品牌部产出第一篇内容
       → 数据中心建立第一条情报摄入
Day 3: 监察部完成第一次巡查
       → 基于巡查结果修正cron
Day 4: 添加财务部 → 建立成本追踪
Day 5: 添加行政部 → 备份+清理自动化
Day 6: 添加销售部+法务部
       → 建变现漏斗 → 法务部审核所有外发内容
```

先少后多。第一天别建7个——你会同时收到7条日报，然后谁都没看懂。让每个部门在你面前跑一天，你亲眼看着它转，你再加下一个。
