# ಚಂದಾದಾರಿಕೆ ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆ ಮತ್ತು ಪಾವತಿ — powpow-register

## ತೀರ್ಮಾನ (ಉತ್ತರ ಮೊದಲು)
> **ಉಚಿತ ಪರೀಕ್ಷಾ ಅವಧಿ (2026-10-18 ಇಂದ; ವೇದಿಕೆಯ ವಾಸ್ತವ ವರ್ತನೆ ಮುಂದುವರಿದೆ)**: ಈ ಅವಧಿಯಲ್ಲಿ ನೋಂದಣಿಯಾದ ಖಾತೆ ನೇರ ಎಲ್ಲಾ ವೈಶಿಷ್ಟ್ಯಗಳನ್ನು ಬಳಸಬಹುದು, ಮತ್ತು **ಸಬ್ಸ್ಕ್ರೈಬ್ ಮಾಡುವುದು ಒಂದು ಐಚ್ಛಿಕ ಅಪ್‌ಗ್ರೇಡ್, ಅಗತ್ಯವಲ್ಲ** — ಬಳಕೆದಾರರು ಸ್ವಯಂ ಸದಸ್ಯತ್ವ ಬಯಸಿದಾಗ ಮಾತ್ರ ಈ ಫೈಲ್ ಹರಿವನ್ನು ಅನುಸರಿಸಿ. ಪರೀಕ್ಷಾ ಅವಧಿ ಮುಗಿದಾಗ, ಸಬ್ಸ್ಕ್ರಿಪ್ಶನ್ ಇಲ್ಲದ ಖಾತೆಗಳು ವಿಷಯ ಪೇಜ್‌ಗಳನ್ನು ಸಂದರ್ಶಿಸಿದಾಗ ಸಬ್ಸ್ಕ್ರಿಪ್ಶನ್ ಪೇಜ್‌ಗೆ ಮರುನಿರ್ದೇಶನ ಆಗುತ್ತವೆ; ಈ ಫೈಲ್ ಪ್ರಕಾರ ಸಬ್ಸ್ಕ್ರಿಪ್ಶನ್ ಪೂರ್ಣಗೊಳಿಸಿದರೆ ಸಾಕು.


**Alipay ಮತ್ತು PayPal ಎರಡೂ ಚಂದಾದಾರಿಕೆ ಮಾರ್ಗಗಳನ್ನು ಈಗ agent ನಿರ್ವಹಿಸಬಹುದು — ಆದೇಶ ರಚನೆ ಮತ್ತು ಬಂದಿಳಿಕೆ ಟ್ರ್ಯಾಕಿಂಗ್ ಸೇರಿದಂತೆ.**
Alipay ಒಂದು-ಬಾರಿ ಖರೀದಿ, ಸ್ವಯಂಚಾಲಿತ ರಿನ್ಯೂವಲ್ ಇಲ್ಲ — ಚೀನಾ ಮುಖ್ಯಭೂಮಿ ಬಳಕೆದಾರರು ಮತ್ತು Alipay ಇರುವವರಿಗೆ;
PayPal ಮಾಸಿಕ ಸ್ವಯಂಚಾಲಿತ ರಿನ್ಯೂವಲ್, ಯಾವಾಗ ಬೇಕಾದರೂ ರದ್ದುಗೊಳಿಸಬಹುದು — ವಿದೇಶ ಮತ್ತು Alipay ಇಲ್ಲದ ಬಳಕೆದಾರರಿಗೆ.
WeChat QR (ಮಾನವ ದೃಢೀಕರಣ) ಮತ್ತು Huawei IAP ಇನ್ನೂ ಇವೆ, ಆದರೆ ಸ್ಕಿಲ್ ಅವುಗಳನ್ನು ನಿರ್ವಹಿಸುವುದಿಲ್ಲ.

ಪಾವತಿ ಹಂತದ ಜವಾಬ್ದಾರಿ ಗಡಿ: agent **ಆದೇಶ ರಚಿಸಬಹುದು, ಕ್ಯಾಶಿಯರ್ ತೆರೆಯಬಹುದು, ಬಂದಿಳಿಕೆ ಪ್ರಶ್ನಿಸಬಹುದು**; ಬಳಕೆದಾರರ Alipay/PayPal
ಖಾತೆ/ಪಾವತಿ ರುಜುವಾತುಗಳನ್ನು **ಎಂದೂ** ಮುಟ್ಟಬಾರದು, "ಪರವಾಗಿ ಪಾವತಿಸುತ್ತೇನೆ" ಎಂದು ಎಂದೂ ಭರವಸೆ ನೀಡಬಾರದು. ಪಾವತಿ ಕ್ರಿಯೆ ಯಾವಾಗಲೂ ಬಳಕೆದಾರ ಸ್ವತಃ ಅಧಿಕೃತ ಕ್ಯಾಶಿಯರ್‌ನಲ್ಲಿ ಪೂರ್ಣಗೊಳಿಸುತ್ತಾರೆ.

## Alipay ಮಾರ್ಗ (vibepay, ಮುಖ್ಯ)

ಒಂದು-ಬಾರಿ ಖರೀದಿ ವ್ಯವಸ್ಥೆ: ಒಮ್ಮೆ ಪಾವತಿಸಿದರೆ ಅನುರೂಪ ಅವಧಿ ಸಕ್ರಿಯಗೊಳಿಸುತ್ತದೆ, **ಸ್ವಯಂಚಾಲಿತ ರಿನ್ಯೂವಲ್ ಇಲ್ಲ**. ಪ್ಯಾಕೇಜ್ `src/lib/alipay-vibepay.ts` (`ALIPAY_PACKAGES`) ನಲ್ಲಿ ಸ್ಥಿರವಾಗಿ ಬರೆಯಲಾಗಿದೆ:

| key | planId | ಹೆಸರು | ಬೆಲೆ | ಅವಧಿ |
|---|---|---|---|---|
| `monthly` | alipay-monthly | ಮಾಸಿಕ ಸದಸ್ಯತ್ವ | ¥6.99 | 30 ದಿನ |
| `quarterly` | alipay-quarterly | ತ್ರೈಮಾಸಿಕ ಸದಸ್ಯತ್ವ | ¥19.99 | 90 ದಿನ |
| `yearly` | alipay-yearly | ವಾರ್ಷಿಕ ಸದಸ್ಯತ್ವ | ¥69.99 | 365 ದಿನ |

### ಇಂಟರ್‌ಫೇಸ್ ಒಪ್ಪಂದ (ಸ್ಕಿಲ್ ಸ್ಕ್ರಿಪ್ಟ್ ಈಗಾಗಲೇ ಸುತ್ತಿದೆ, agent ನೇರವಾಗಿ ವಿನಂತಿ ಸೇರಿಸುವುದಿಲ್ಲ)

| ಇಂಟರ್‌ಫೇಸ್ | ವಿಧಾನ | ವಿವರಣೆ |
|---|---|---|
| `/api/payment/alipay/create-order` | POST | `Authorization: Bearer <JWT>` ಬೇಕು (pending ಬಳಕೆದಾರ ಸಾಕು). body `{package}` → `{paymentHtml, outTradeNo, amount, planName}` ಹಿಂತಿರುಗಿಸುತ್ತದೆ; `paymentHtml` ಸ್ವಯಂಚಾಲಿತವಾಗಿ Alipay ಗೇಟ್‌ವೇಗೆ ಸಲ್ಲಿಸುವ ಫಾರ್ಮ್ ಪುಟ |
| `/api/payment/alipay/query` | GET `?outTradeNo=` | ಅದೇ Bearer ದೃಢೀಕರಣ. `paid` / `pending` / `closed` / `unknown` ಹಿಂತಿರುಗಿಸುತ್ತದೆ |
| `/api/payment/alipay/notify` | POST (Alipay ಸರ್ವರ್ ಕಾಲ್‌ಬ್ಯಾಕ್) | ಐದು-ಅಂಶ ಸಹಿ ಪರಿಶೀಲನೆ (ಸಹಿ, app_id, ಮೊತ್ತ ಹೊಂದಾಣಿಕೆ, TRADE_SUCCESS/TRADE_FINISHED, ವ್ಯಾಪಾರಿ ವಿಶಿಷ್ಟತೆ) → **idempotent** ಆದೇಶ ನವೀಕರಣ + ಚಂದಾದಾರಿಕೆ ರಚನೆ + ಖಾತೆ ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆ. ಸ್ಕಿಲ್ ಈ ಇಂಟರ್‌ಫೇಸ್ ಅನ್ನು ಎಂದೂ ಮುಟ್ಟುವುದಿಲ್ಲ |
| `/payment/alipay/return` | ಬ್ರೌಸರ್ ರೀಡೈರೆಕ್ಟ್ ಪುಟ | ಸಾರ್ವಜನಿಕ ಪಥ, ಪಾವತಿಯ ನಂತರ "支付成功" ದೃಢೀಕರಣ ತೋರಿಸುತ್ತದೆ, ಪುಟ ಹಿನ್ಭಾಗ ನೈಜ ಸ್ಥಿತಿ ಪೋಲ್ ಮಾಡುತ್ತದೆ |

- ಪಾವತಿಸದ ಆದೇಶ **2 ಗಂಟೆಗಳಲ್ಲಿ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಮುಚ್ಚುತ್ತದೆ**; ಬಳಕೆದಾರ ಮಧ್ಯದಲ್ಲಿ ಬಿಟ್ಟರೆ → ನೇರವಾಗಿ ಮರಳಿ `create-order`, ಹಳೆಯ ಆದೇಶ ಚಿಂತಿಸಬೇಡಿ.
- ಸ್ಕ್ರಿಪ್ಟ್ `paymentHtml` ಅನ್ನು ತಾತ್ಕಾಲಿಕ HTML ಕಡತಕ್ಕೆ ಬರೆಯುತ್ತದೆ, agent ಸಿಸ್ಟಮ್ ಆಜ್ಞೆಯಿಂದ ತೆರೆಯುವುದರಿಂದ Alipay ಕ್ಯಾಶಿಯರ್ ಪ್ರವೇಶಿಸಬಹುದು
  (QR ಸ್ಕ್ಯಾನ್ ಮಾಡುವುದು ಅಥವಾ Alipay ನಲ್ಲಿ ಲಾಗಿನ್ ಆಗಿ ಪಾವತಿಸುವುದು).

### ಸಕ್ರಿಯಗೊಳಿಸುವ ಸರಣಿ (ಸ್ವಯಂಚಾಲಿತ, ಮಾನವ ಬೇಕಾಗಿಲ್ಲ)

notify ಸಹಿ ಪರಿಶೀಲನೆ ಹಾದು → `paymentOrders` ಪಾವತಿಸಿದಂತೆ ಗುರುತಿಸಲಾಗಿದೆ → `user_subscriptions` ರಚನೆ/ವಿಸ್ತರಣೆ
(`planId`, `currentPeriodEnd` durationDays ಪ್ರಕಾರ ಲೆಕ್ಕ, ರಿನ್ಯೂವಲ್ ಮೂಲ ಮುಕ್ತಾಯ ದಿನಾಂಕದ ಮೇಲೆ ವಿಸ್ತರಿಸುತ್ತದೆ) →
`users.accountStatus: active` + `subscriptionStatus: ACTIVE` → ರೀಡೈರೆಕ್ಟ್ ಪುಟ paid ಪೋಲ್ ಮಾಡಿ ಯಶಸ್ಸು ತೋರಿಸುತ್ತದೆ.

### ಪಾವತಿಸಿದ ನಂತರ ಹೊಸ ಲಾಗಿನ್ ಸ್ಥಿತಿ ಬದಲಾಯಿಸಬೇಕು (ಮುಖ್ಯ)

JWT ಚಂದಾದಾರಿಕೆ ಘೋಷಣೆ ಹೊಂದಿರುತ್ತದೆ (pending ಖಾತೆ `NONE`). **ಪಾವತಿ ಬಂದಿಳಿಕೆ ಕೇವಲ ಡೇಟಾಬೇಸ್ ನವೀಕರಿಸುತ್ತದೆ, ಈಗಾಗಲೇ ನೀಡಲಾದ
JWT ಅನ್ನು ಬದಲಾಯಿಸುವುದಿಲ್ಲ** — ಹಳೆಯ token ಘೋಷಣೆ ಇನ್ನೂ NONE, ಅದನ್ನು ನೇರವಾಗಿ ಲಾಗಿನ್ ಲಿಂಕ್ ರಚಿಸಲು ಬಳಸಿದರೆ "ಸದಸ್ಯತ್ವ ಇಲ್ಲ" ಎಂದು ಕಾಣಿಸುತ್ತದೆ.
ಆದ್ದರಿಂದ ಸ್ಕಿಲ್ `paid` / PayPal `ACTIVE` ದೃಢೀಕರಿಸಿದ ನಂತರ ಮೊದಲು `refresh-login` (ಮರುಲಾಗಿನ್ ಹೊಸ JWT, ಘೋಷಣೆ ACTIVE ಆಗುತ್ತದೆ) ಚಲಾಯಿಸುತ್ತದೆ,
ನಂತರ ಲಿಂಕ್ 2 ರಚಿಸುತ್ತದೆ. ಇದು ವಿನ್ಯಾಸ ನಡವಳಿಕೆ, ಬಗ್ ಸರಿಪಡಿಸುವುದಲ್ಲ.

## PayPal ಚಂದಾದಾರಿಕೆ ಮಾರ್ಗ (ಸ್ಕಿಲ್ ನಿರ್ವಹಿಸುತ್ತದೆ; ವೆಬ್, HarmonyOS ಅಲ್ಲ)

ಒಂದೇ ಒಂದು ಯೋಜನೆ ಇದೆ, Premium Monthly (ಸುಮಾರು $1/ತಿಂಗಳು, `/api/subscription/plans` ಹಿಂತಿರುಗಿಸುವಂತೆ); ಇದು **ಮಾಸಿಕ ಸ್ವಯಂಚಾಲಿತ ರಿನ್ಯೂವಲ್**
ಆಗಿದ್ದು ಬಳಕೆದಾರ ತಮ್ಮ PayPal ಖಾತೆಯಲ್ಲಿ ಯಾವಾಗ ಬೇಕಾದರೂ ರದ್ದುಗೊಳಿಸಬಹುದು.

### API ಒಪ್ಪಂದ (ಸ್ಕಿಲ್ ಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ ಮೊದಲೇ ಸುತ್ತಲ್ಪಟ್ಟಿದೆ; agent ಎಂದೂ ನೇರವಾಗಿ ವಿನಂತಿ ರಚಿಸುವುದಿಲ್ಲ)

| ಎಂಡ್‌ಪಾಯಿಂಟ್ | ವಿಧಾನ | ಟಿಪ್ಪಣಿ |
|---|---|---|
| `/api/subscription/plans` | GET | Bearer ಬೇಕು; ಲಭ್ಯ ಯೋಜನೆಗಳ ಪಟ್ಟಿ (ಈಗ 1 ಮಾತ್ರ) |
| `/api/subscription/create` | POST | body `{planId}` → `{subscriptionId, approveUrl, status}`; `status` ಸಾಮಾನ್ಯವಾಗಿ `APPROVAL_PENDING` |
| `/api/subscription/create` | GET | Bearer ಬೇಕು; `{activeSubscription, allSubscriptions}`; agent `activeSubscription.subscription.status === 'ACTIVE'` ಆಗುವವರೆಗೆ ಪೋಲ್ ಮಾಡುತ್ತದೆ |
| `/api/subscription/verify` | POST | ಯಶಸ್ಸು ಪುಟ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಕರೆಯುತ್ತದೆ (cookie ಸಹಿತ); webhook ಬಾರದಿದ್ದಾಗ ನೇರವಾಗಿ PayPal API ಮೂಲಕ ಸಕ್ರಿಯಗೊಳಿಸುತ್ತದೆ |
| `/subscription/success` | ಬ್ರೌಸರ್ ಹಿಂತಿರುಗುವ ಪುಟ | PayPal ಅನುಮೋದನೆಯ ನಂತರ ಬೀಳುವ ಪುಟ; verify ಅನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಪೋಲ್ ಮಾಡಿ, ಮುಖಪುಟ / ಮೂಲ ಪುಟಕ್ಕೆ ಹಿಂತಿರುಗುತ್ತದೆ |
| `/subscription/cancel` | ಬ್ರೌಸರ್ ಪುಟ | ಬಳಕೆದಾರ ರದ್ದುಗೊಳಿಸಿದಾಗ ಅಥವಾ ವಿಫಲವಾದಾಗ ಬೀಳುವ ಪುಟ; ಮರಳಿ ಪ್ರಾರಂಭಿಸಬಹುದು |

### agent ಕಾಲಕ್ರಮ

```
create-order --provider paypal   # → approveUrl ಹಿಂತಿರುಗಿಸುತ್ತದೆ, ಸ್ಥಳೀಯ HTML ಕಡತಕ್ಕೆ ಬರೆಯಲಾಗುತ್ತದೆ
HTML ಕಡತ ತೆರೆಯಿರಿ               # → ಬ್ರೌಸರ್ PayPal ಅನುಮೋದನೆ ಪುಟಕ್ಕೆ
query (ಪ್ರತಿ 10–15s)             # → ACTIVE ಆಗುವವರೆಗೆ ಪೋಲ್
refresh-login                    # → ಹೊಸ JWT (ಚಂದಾದಾರಿಕೆ ಘೋಷಣೆ ACTIVE)
login-link --target home         # → ಅಧಿಕೃತ ಲಾಗಿನ್ ಲಿಂಕ್ ರಚಿಸುತ್ತದೆ
```

- 1 ಗಂಟೆಯೊಳಗೆ ಪೂರ್ಣಗೊಳ್ಳದ PENDING ಚಂದಾದಾರಿಕೆಗಳನ್ನು ಬ್ಯಾಕೆಂಡ್ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಸ್ವಚ್ಛಗೊಳಿಸುತ್ತದೆ; ಮರಳಿ ಪ್ರಾರಂಭಿಸಿದರೆ ಸಾಕು.
- ಬಳಕೆದಾರ ಮರಳಿ `create-order` ಚಲಾಯಿಸಿದರೆ, ಬ್ಯಾಕೆಂಡ್ ಇನ್ನೂ ಮಾನ್ಯವಾಗಿರುವ `APPROVAL_PENDING` ಚಂದಾದಾರಿಕೆಯನ್ನು ಮರುಬಳಕೆ ಮಾಡುತ್ತದೆ, ಆದ್ದರಿಂದ 409 ಬರುವುದಿಲ್ಲ.
- Alipay ಯಂತೆಯೇ: ಬಂದಿಳಿಕೆ ಡೇಟಾಬೇಸ್ ಅನ್ನು ಮಾತ್ರ ನವೀಕರಿಸುತ್ತದೆ — ಹಳೆಯ JWT ಸ್ವಯಂಚಾಲಿತವಾಗಿ ರಿಫ್ರೆಶ್ ಆಗುವುದಿಲ್ಲ, ಆದ್ದರಿಂದ ಮುಖಪುಟ ಲಿಂಕ್ ಕಳುಹಿಸುವ ಮೊದಲು `refresh-login` ಅನ್ನು **ಖಂಡಿತ** ಚಲಾಯಿಸಬೇಕು.

## ಚಂದಾದಾರಿಕೆ ಪುಟದ ನಾಲ್ಕು ಮಾರ್ಗಗಳು

ಚಂದಾದಾರಿಕೆ ಪುಟ `src/app/(public)/subscription/page.tsx` ರನ್‌ಟೈಮ್ ಪರಿಸರ ಪ್ರಕಾರ ಪ್ರದರ್ಶಿಸುತ್ತದೆ:

| ಮಾರ್ಗ | ಪರಿಸರ | ಯಂತ್ರ | ಸಕ್ರಿಯಗೊಳಿಸುವ ವಿಧಾನ |
|---|---|---|---|
| **Alipay (ಮುಖ್ಯ)** | ವೆಬ್ ಬದಿ | `AlipayPaymentSection` vibepay ಇಂಟರ್‌ಫೇಸ್ (ಮೇಲೆ ಕೋಷ್ಟಕ) ಬಳಸುತ್ತದೆ | notify ಸರ್ವರ್ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಸಕ್ರಿಯಗೊಳಿಸುತ್ತದೆ, ಸೆಕೆಂಡ್‌ಗಳು |

## ಸ್ಥಿತಿ ಮತ್ತು ರೀಡೈರೆಕ್ಟ್

- Alipay ಪಾವತಿಸಿದ ನಂತರ → ರೀಡೈರೆಕ್ಟ್ ಪುಟ ಯಶಸ್ಸು ತೋರಿಸುತ್ತದೆ; PayPal ಯಶಸ್ವಿ → `/subscription/success` → ಖಾತೆ active →
  ಸ್ವಯಂಚಾಲಿತವಾಗಿ `next` ಸೂಚಿಸಿದ ಮೂಲ ಪುಟಕ್ಕೆ (ಇಲ್ಲದಿದ್ದರೆ ಮುಖಪುಟ) ರೀಡೈರೆಕ್ಟ್.
- ಈಗಾಗಲೇ ಚಂದಾದಾರಿಕೆ ಬಳಕೆದಾರ ಚಂದಾದಾರಿಕೆ ಪುಟ ಪ್ರವೇಶಿಸಿದರೆ → "You're All Set!" ತೋರಿಸುತ್ತದೆ, 3 ಸೆಕೆಂಡ್‌ನಂತರ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಮುಖಪುಟ ಹಿಂದಿರುಗುತ್ತದೆ.
- ಪಾವತಿ ವಿಫಲ/ರದ್ದು (PayPal) → `/subscription/cancel`, ಮರುಪ್ರಾರಂಭಿಸಬಹುದು.
