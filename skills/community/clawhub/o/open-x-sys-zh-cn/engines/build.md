# 实践：从认识到能力

> **何时读**：有人需要知道在自己的条件下做一件事最好的办法；出现了能力鸿沟；你要推荐、组合或创造一项实践；你在搭建一项能力；或者一项正在使用的实践该重新看一看了。
> 这个引擎在最佳实践、权衡、设计、搭建能力、复盘和盯住之下运行。

这个引擎针对任何真实系统，持续研究、发现、比较、选择、组合、创造和改进适合它的实践。它让 OpenXSys 成为能够为具体对象生成能力的系统级 Skill。

## 从最佳实践到系统能力的调用链

这条链说明依赖怎样被逐层调用，不规定用户必须经历的步骤：

1. 从当前系统和人的真实条件中说准**能力鸿沟**；需要方法入口时读[最佳实践](../capabilities/methods/5-decide/practice.md)。
2. 通过[文件](../adapters/files.md)、[Web](../adapters/web.md)、[工具](../adapters/tools.md)和人的经验研究真实候选、机制与适用条件。
3. 用[权衡](../capabilities/methods/5-decide/weigh.md)比较关键差异；没有现成实践适合时，进入[设计](../capabilities/methods/6-create/design.md)或[搭建能力](../capabilities/methods/6-create/build.md)。
4. 在真实任务中产生作用，由[验证](../runtime/verify.md)区分执行、状态改变与目标效果。
5. 用[复盘](../capabilities/methods/7-improve/review.md)和[盯住](../capabilities/methods/7-improve/watch.md)接收后续结果，由[演化](evolve.md)把有效实践写成能力，让失败改变下一次运行。

当前现场可以从链上任一点进入，也可以并行研究多个候选。最重要的是每次调用都有去处、有返回：选择回到行动，行动回到证据，证据回到系统。

## 什么是最佳实践

**最佳实践，是在特定系统的状态、结构、时间、空间、相互作用与约束条件下，为实现当前及未来有价值的目标，经过研究、比较、适配和实践检验，而值得采用的方法、结构或行动方式。**

由此而来的五个性质：

- **有条件。** 它在写明的条件下才是最好的。没有条件，它只是建议。
- **可以是复合的。** 它可以把 Skill、工具、模型、人员、知识、流程和组织结构组合起来，连同它们的连接方式、执行顺序、适用边界与触发条件。
- **可以被创造。** 现成的都不合适时，可以拼出或设计出一项更合适的实践。
- **会演化。** 系统、目标或可用的手段变了，什么是最好的也会变。
- **由结果评价。** 最终算数的证据，是在这个系统里发生了什么。

## 四种研究能力

| 能力 | 做什么 | 好是什么样 |
|---|---|---|
| **发现** | 找到已有的实践：科学研究、成熟产品、开源项目、专业社区、真实案例 | 几个来自不同类型来源的真实候选，包括行内人实际的做法，以及别人失败的地方 |
| **研究适用条件** | 弄清每个候选的机制、前提、成本、边界和副作用 | 你说得出它为什么有效，以及它要有效必须满足什么 |
| **组合和创造** | 把不同领域的方法接起来，或者设计一个新的 | 这个组合有解释：为什么是这些部分，为什么这样连接 |
| **持续改善** | 改进正在使用的实践，以及选择实践的方法 | 结果或条件变化时，实践记录跟着改 |

第一个要看的地方，是这个人自己的系统：已经为这个人验证过的实践、已有的连接、已经拥有的工具。第二个才是世界。去研究以此为生的人实际怎样做，而不只是文章推荐什么。

## 循环

```text
认识系统，发现能力鸿沟
        → 研究实践
        → 预测后果，选择值得尝试的路径
        → 建立连接，执行实践，先低成本验证
        → 系统改变：状态、结构、实践、目标
        → 下一轮
```

这就是那段旅程，从实践的一侧来看。能力鸿沟，是系统现在能做到的与目标所要求的之间的差距。把鸿沟说准，就是一半的工作：“我不会做视频”不是鸿沟；“我一个晚上能写出一份好脚本，但每一分钟成片要花我四个小时”才是。

## 判断哪种实践更适合的七个维度

| 维度 | 问题 |
|---|---|
| **适用性** | 为什么它适合这个系统目前的实际条件？ |
| **价值** | 对当前和未来的目标能产生什么改善？ |
| **成本** | 时间、算力、资金、人员和维护投入？ |
| **证据** | 它在什么条件下得到过验证？ |
| **系统影响** | 它会改变哪些组成、连接和运行方式？ |
| **后续发展** | 它会产生哪些新瓶颈，又带来哪些新机会？ |
| **切换条件** | 什么时候应该坚持、调整或换用另一种方法？ |

这些维度是你做比较的方式，不是要填的表。在候选之间真正有差别的维度上，把比较展示给这个人；某个维度不清楚，就说不清楚。

**适用性优先。** 目标相同的不同的人，应当得到不同的实践。同样是“我想用 AI 做视频”，预算有限的独立创作者要避开昂贵的返工、可以接受朴素一些的画面，走的是一条路；能承担返工、需要统一品牌的团队，走的是另一条。每条建议都写明它依赖的条件，以及什么时候会改变。如果你的推荐对任何人都一样，你就还没有用上对这个人的了解。

**证据分层。** 说明你手里的是哪一种：在这个系统里测到的；在一个可比的系统里测到的；行内人的报告；从机制推出来的；系统自己的推理。每一层使用与其证据力度相称的语言。

## 一条推荐包含什么

- **推荐的路径**，以及它为什么适合这些条件。
- **它的代价**，用这个人真实在乎的东西来计：小时、钱、注意力、维护。
- **考虑过的替代方案**，以及什么条件下其中一个会更好。
- **一个低成本的第一步验证**：在付出大部分代价之前，能显示这条路径在这里是否走得通的最小真实尝试。它有可以观察的结果，也有一个会见分晓的时间。
- **切换条件**：说明该坚持、调整还是更换的信号。

一条没法低成本验证的推荐，值得更多的谨慎，而且这一点应该让这个人知道。

## 创造能力

系统能力不是各部分能力的简单相加。只有建立适当的连接、反馈与控制，一个模型、一个工具和一个数据源才会形成新的整体能力：

**发现鸿沟 → 研究实践 → 建立新的连接和结构 → 产生能力 → 在真实工作上验证。**

- **先用已有的东西来搭。** 优先使用这个人自己的工具、Skill、资料与工作方式，再使用宿主已经提供的能力。只有现有组合补不上的鸿沟，才值得提出一个新部件或新连接（见[工具适配器](../adapters/tools.md)）。
- **加上反馈，而不只是一条流水线。** 一项分不清自己的产出好不好的能力，会在没人察觉的时候变差。决定它检查什么，以及检查不通过时怎么办。
- **在真实工作上验证。** 一项能力算是存在，是它已经完成过这个人工作里的一件真实任务，而且结果是这个人认可的。在那之前，它是一份设计。
- **把它记下来**，让另一个 AI 也能运行它：它做什么，有哪些部分、怎样连接，怎样启动，需要什么，在什么上验证过，在哪里失效。

改变可以发生在不同的深度：一个参数、一个局部方法、一条反馈路径、一次结构调整、一次边界移动、一项新能力、一个被修正的目标。越深的改变通常越重要，代价也越高（梅多斯）。说明你提议的是哪一层。一个来要“更好的提示词”的人，可能需要的是不同的结构，而这应该作为一个选择让这个人听到。

搭建可能涉及代码、安装、账号和定时运行。花钱、发布、删除、联系他人、安排定期运行和安装新组件，依据真实所有权与授权发生。代码在相应授权中运行，作用范围和结果始终可以检查。

## 实践记录

实践记录属于系统的核心。每一份都用朴素的语言回答：

- 这项实践是什么：组成、连接、顺序、触发条件；
- 它服务于哪个目标；
- 为什么适合这个系统；
- 证据，以及证据的种类；
- 成本；
- 它改变了什么；
- 目前的结果；
- 切换条件；
- 下一次审视。

这些是读者应该能从记录里得知的东西。它们不是标题。一项小实践只有三句话。一项复合的实践，可能带着一张图、一段脚本和一张结果表。把它写成这个人能从中认出自己工作方式的样子。

## 重新审视

出现下面的情况时，把一项实践重新看一遍：

- **结果变差**：它本该改善的那个指标不再改善；
- **条件变化**：系统、工具、预算或目标，已经不是这项实践当初假设的样子；
- **出现更好的东西**：一个新工具或新方法改变了比较的结果；
- **这个人超出了它**：关于这个人的技能或规模的某个假设不再成立。

系统回来时，说出哪些实践需要注意，并拿出证据。持续有效的实践成为用户系统的**能力**（见[成长](../system/growth.md)）。分享出去的实践带着条件、证据和接续方式，让接收者能够适配与验证。

## 这个引擎容易在哪里出错

- **把通用建议说成最佳实践。** 没有条件，没有成本，对谁都一样。
- **一张清单代替一个判断。** 十个选项而没有推荐，是把工作交了回去。
- **推荐厉害的，而不是适合的。** 能力最强的工具，往往不适合这份预算、这份技能和这个节奏。
- **跳过低成本验证。** 这个人付了全价，才知道一次小试验本可以告诉自己的事。
- **把实践写成脚本。** 停在原则，和决定成败的那几个决策上。把每一步都写死的实践，会成为以后更强的 AI 的天花板。
- **与结果失去连接。** 推荐需要回到实际结果，才能教会系统怎样改进。

## 这个引擎在这个人的系统里读写什么

- **读**：对相关系统的认识，包括是什么限制着它；根系统（这个人的资源、约束、目标、技能）；已有的实践记录与能力；连接。
- **写**：实践记录；陆续到来的结果；能力；它建立的连接；审视日期与盯住的条件。怎样写见[演化](evolve.md)，系统的组成部分见[部件](../system/parts.md)。
