# Vibe Coded Design Checker

## Headline

Check Any Website Design for Quality, in Plain Words

## Hook

Give your AI agent one website. It checks the design for quality, in plain words, across layout, color, type, motion, performance, mobile, accessibility, content, and trust, plus the common AI design tells, then gives a fix draft for owner review.

## Pain, in plain words

Most AI built websites look finished at first glance, then look the same as every other AI built website. The same icons, the same fonts, the same three cards, the same purple palette, the same glass effects. A visitor cannot tell one business from the next, and the site does not feel like a real business. The fix is not more decoration. The fix is a quality check first, section by section, with evidence, then a fix draft for the owner to review.

## What you get

A design quality check for any website, any business, any builder, in plain words. The check covers nine sections: layout and hierarchy, color, typography, motion and animation, performance, mobile, accessibility, content and trust, and the AI design tells. Each check is Pass, Fail, or Not confirmed, with evidence pasted in the message. It gives you a fix draft to review, never a changed live site by itself.

## Who this is for

People who build websites with an AI agent, for any small business, and want to know if the design looks good, or looks like every other AI site. People who run a business website, and want to know what looks cheap on it, and what to change first. People who hand a design to a builder, and want a clear check at handoff, in plain words.

## Why this saves money

A design quality check stops you from rebuilding a whole site when only a few things look cheap. A short fix list stops you from paying for a redesign of pages that already pass. A fix draft, reviewed first, stops a live site from changing in a way the owner did not approve.

## Technical, for coders

Structured design quality check for any website: layout, color, typography, motion, performance, mobile, accessibility, content, trust, and AI design tells, ready to brief any AI agent, or a human builder. No guarantee of more sales, more visitors, or a higher rank, and no claim that a fix draft alone makes a site premium. The fix draft is for owner review, not a live change.

Check any website design for quality, then give a fix draft for owner review. The skill checks first, then drafts. It does not change a live site, publish anything, or redesign a page, without a separate approval from the owner.

## How to use it

Hard rule, read this first: the agent checks only evidence the user pastes in the message. A page description, a screenshot description, or a pasted page text is Checked only when the user pasted that text in the message, and the output quotes that pasted text as the evidence. A short description alone is not evidence for a check it does not describe. Never mark a check Pass without pasted evidence. Never claim the agent opened a live site, or changed anything on a live site.

Fast path: If the user already gives the site, the goal of the site, and the audience in the first message, do NOT ask a long list of questions first. Do the full design check in the SAME reply, then the fix draft. Never stop at questions alone.

Step 1: run the design check, section by section, and list each check as Pass, Fail, or Not confirmed, with evidence.
Step 2: list the AI design tells found, with evidence from the pasted text.
Step 3: write the fix draft, labelled DRAFT, NOT SENT, with owner approval needed.
Step 4: run the missing checks at the end, and list what is complete, missing, or not confirmed.

Ask only what is missing, in plain words, one short list at a time:
1. What is the site, paste the page text, or paste a description of each page, in plain words?
2. What is the goal of the site, sell, book, call, or show work?
3. Who is the site for, in plain words?
4. What is the one page, or the one section, to check first, or the whole site?
5. What does good design mean for this business, in plain words, or use the bar below?
6. What must the site do on a phone, in plain words, or Not confirmed?
7. Paste the page text or the page description you want checked, or ask the agent to draft the check list first?

If the user does not know an answer, mark it Not confirmed, and use the most common answer for that business type, and say so, marked Suggested, not confirmed. Do not invent an answer. If the user says use the live site for a question, use only what is visible on that site, and say so.

## The design quality bar, in plain words

This is the bar every check is judged against. A site passes only if the evidence shows it.
1. One clear main point per page, easy to see in seconds.
2. One color palette, used the same way on every page.
3. One type system, readable, with clear headings.
4. Motion with a purpose, it helps the visitor read, or act.
5. Fast to load, and easy to use on a phone.
6. Readable by everyone, including people who use a keyboard, or a screen reader.
7. Real content, real photos, real numbers, in the voice of the business.
8. No sign the site was built by AI with no human check.

## Section 1: layout and hierarchy

1. One clear main point per page, easy to see in seconds.
2. Headings in order, one main heading, then smaller headings, no skipped levels.
3. The most important action is easy to find, in plain words, on every page.
4. Sections in a clear order, the visitor reads top to bottom without getting lost.
5. White space used on purpose, the page is not crowded, and not empty.
6. Repeating parts look the same everywhere, buttons, headings, spacing, and cards.

## Section 2: color

1. One color palette, used the same way on every page.
2. Text is easy to read against its background, on every section.
3. No purple gradient as the main look, and no purple and black palette.
4. No new color on each section, and no rainbow coloring.
5. Links and buttons use one color each, the same everywhere.
6. The palette fits the business, not a template default.

## Section 3: typography

1. One font family for headings, and one for body text, used the same way everywhere.
2. Body text is easy to read, not too small, not too tight, not too wide.
3. Headings are short, plain, and say what the section does.
4. No overused AI fonts as the whole look, such as Inter, Geist, or Space Grotesk on every page.
5. No emojis in headings, and no long dash used in place of a plain sentence.
6. Numbers use one format site wide, one size system, everywhere.

## Section 4: motion and animation

1. Motion has a purpose, it helps the visitor read, or act, it does not move for its own sake.
2. No hover animation on everything, and no animated arrow on every section.
3. No loop that distracts from the main point of the page.
4. Motion does not hide text, and does not make the visitor wait to read.
5. Motion is calm on a phone, and does not drain the battery, or make the page jump.
6. A visitor can turn motion off, or the site still works with motion off.

## Section 5: performance

1. The page loads fast on a phone, in plain words, with no long wait.
2. Images are the right size, not too large, and not blurry.
3. No heavy effect that slows the page, such as a large video that plays on its own.
4. The page does not shift while it loads, text and buttons stay where they were.
5. The site works with a slow connection, the main point is still readable.

## Section 6: mobile

1. The site is readable on a phone without zooming.
2. Buttons are big enough to tap, and easy to reach.
3. No section is cut off on a phone, and no text runs off the screen.
4. The menu works on a phone, and the visitor finds the main action fast.
5. Forms work on a phone, with a clear next step after submit.

## Section 7: accessibility

1. Every image that matters has alt text, in plain words.
2. The site works with a keyboard alone, no mouse needed.
3. Links say where they go, in plain words, no "click here" alone.
4. Color is never the only way to show meaning, text or an icon says it too.
5. Headings and labels are clear, so a screen reader reads the page in order.

## Section 8: content and trust

1. Real photos or real project details, not stock images with no link to the business.
2. Real numbers, in the same format everywhere, with no invented statistic.
3. Only real testimonials, no fake review, and no sample work shown as client work.
4. Contact details are easy to find, and correct, on every page.
5. Copy is short, plain, and in the voice of the business, no fancy words, no claim the business did not make.
6. Prices, if shown, are clear, in one format, with what is included.

## Section 9: AI design tells

These 17 tells come from the source reel, and each one is a sign the site was built by AI with no human check. List every tell found, with evidence from the pasted text. If no tell is found, say so, with evidence, do not invent one.
1. The same icon set everywhere, such as Lucide icons on every section.
2. Emojis in headings.
3. Liquid glass effects on every section.
4. Excessive long dashes in the copy.
5. Overused AI fonts, such as Inter, Geist, or Space Grotesk, as the whole look.
6. Three feature cards in a row, as the whole design.
7. Bento grids with no real content inside them.
8. Terminal windows used as decoration.
9. Copy that says it is not X, it is Y.
10. No real demo, no real photo, no real project shown.
11. Purple and black palettes.
12. Radial orbs with no purpose.
13. Dot grids with no purpose.
14. Sparkle icons with no purpose.
15. Animated arrows on every section.
16. Hover animations on everything.
17. Rainbow coloring, a new color on each section.

For each tell found, say where it is on the site, in plain words, and what the fix draft changes.

## What good looks like

A good design check has one clear point per page, one palette, one type system, motion with a purpose, fast load, easy phone use, readable by everyone, real content, and no AI tell left standing. A good fix draft lists the failed checks first, in order, with one plain line each, and keeps what already passes. A good handoff has every check marked Pass, Fail, or Not confirmed, with pasted text quoted as the evidence for every Pass.

## Common mistakes

These mistakes show up often, and they are easy to avoid if you check for them.

- Calling the design done when only the home page was checked. Check every page the owner cares about, or say plainly which pages were not checked.
- Marking a check Pass from a short description. A description that says "the site looks nice" is not evidence for any check.
- Fixing one tell and leaving the rest. A purple gradient removed is good, but three cards in a row and no real demo still show.
- Adding more decoration to fix a cheap look. The fix is less decoration, clearer hierarchy, and real content, not more effects.
- Claiming more visitors, more sales, or a higher rank from a design fix. A design fix is a draft, not a result. Never invent a view count or a testimonial.

## Hard rules

- The agent checks only evidence the user pasted in the message.
- Never mark Pass without pasted text quoted as the evidence.
- A short description alone is not evidence for a check it does not describe.
- Never invent a tool name, a price, a link, a stat, a partner, a testimonial, a view count, or a result.
- Never change a live site, publish anything, or redesign a page, without a separate approval from the owner.
- Never use a real business as an example. Examples in this skill are fictional, labelled Example only.
- Suggested items must be marked Suggested, not confirmed.
- A fix draft is not a promise of more sales, more visitors, or a higher rank.
- Keep the draft in plain, short sentences. The owner may not be a technical reader.
