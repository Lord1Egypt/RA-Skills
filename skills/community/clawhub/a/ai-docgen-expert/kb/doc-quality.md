# doc-quality：文档质量工程

## 定位与心智模型

技术文档质量工程：管「一篇文档如何写好」——写作基本功、结构化组织、示例代码质量、图表使用、可读性工程、AI 腔治理。

核心思想：

- 文档使命官方定性：**write for humans first, computers second**（先为人写，再为机器写）——一切质量判据以此为总纲 [官方文档](https://google.github.io/styleguide/docguide/best_practices.html)
- 文档叙事观：**documentation is the story of your code**——文档是代码的故事，质量缺陷即叙事断裂 [官方文档](https://google.github.io/styleguide/docguide/best_practices.html)
- 哲学基调：**no perfect document, only proven methods and prudent guidelines**——没有完美文档，只有被验证的方法与审慎的指南；一切质量度量是手段而非目标 [官方文档](https://google.github.io/styleguide/docguide/best_practices.html)
- 质量四维模型：可发现性 / 可理解性 / 可操作性 / 时效性（判据与检查手段见 API 速查表）[模型经验]
- 读者行为假设：扫读不细读、中途着陆、目标驱动——文档为扫读设计而非为通读设计 [模型经验]

适用边界：本域管单篇文档的写作质量。文档类型判断与结构选型 → doc-taxonomy；质量维度的自动化验证落地 → ai-doc-verification；行内注释质量 → code-comment；风格指南/术语表/度量治理 → doc-governance。

## 法则

编号与 elicited/07-laws.md 完全一致（DQ-1 ~ DQ-10），无新造、无改号。

**DQ-1** **MUST**: 清晰性三支柱：具体名词、强动词、短句。抽象词（灵活/强大）零信息；名词化（「进行校验」→「校验」）是动词逃避；被动语态隐藏主体；一句一信息，从句超两层拆句；代词与先行词隔句即重述名词。
- 违反后果: 读者无法在扫读中获取动作与主体，误解率与弃读率上升；抽象名词堆砌使文档零信息。
- 溯源: [模型经验]（01-writing-fundamentals，置信度高）。「为读者而写」原则层官方锚定（write for humans first, computers second）[官方文档](https://google.github.io/styleguide/docguide/best_practices.html)；Google style 语态/人称/标点细则未获取——原则已锚定（best_practices），细则以官方指南为准，未经文档验证。

**DQ-2** **MUST**: 直呼读者：第二人称、主动语态、直接开始。填充词（「需要注意的是」）、元话语（「在本节中我们将」）、服务性结尾（「希望有帮助」）零信息删除；被动仅当受动者是焦点。
- 违反后果: 防御性填充稀释信息密度，读者在废话中消耗耐心后放弃；被动语态让动作主体不可追责。
- 溯源: [模型经验]（01，置信度高）。人优先原则官方锚定 [官方文档](https://google.github.io/styleguide/docguide/best_practices.html)；Google 第二人称/主动语态逐条细则未获取——原则已锚定（best_practices），细则以官方指南为准，未经文档验证。

**DQ-3** **[GLOBAL] MUST**: 渐进披露三层：TL;DR ≤3 行 → 主体 → 深水区。每长页有第一层；先结论后论证（BLUF），无悬念结构；边缘情况独立小节不污染主流程；标题串能独立还原文档结构（标题测试）。
- 违反后果: 无 TL;DR 的长页迫使读者通读全文才能定位，扫读者直接离开；悬念结构使读者无法中途着陆。
- 溯源: [模型经验]（02-structured-writing，置信度高；渐进披露为业界共识，权威出处未获取）。GLOBAL 理由：渐进披露是信息呈现的通用结构（API 响应设计/错误信息设计同构）。

**DQ-4** **MUST**: 示例五性：可运行、最小化、真实、渐进复杂度、版本明确。复制即跑（import 完整无省略号）；一示例一概念；数据形态真实（foo/bar 玩具化是隐性文档缺失）；错误处理按类型分寸（reference 不展示/how-to 展示相关/tutorial 一处教学点）；示例对应版本显式。
- 违反后果: 伪代码/玩具示例复制即报错，读者对文档失去信任且无法映射自身场景；死示例长期误导。
- 溯源: 示例排序纪律官方锚定——Class/Module API documentation 要求示例先行、**simplest use case first** [官方文档](https://google.github.io/styleguide/docguide/best_practices.html)；示例五性细则为 [模型经验]（03-example-code-quality，置信度高）。

**DQ-5** **[GLOBAL] MUST**: 图优于文四判据：空间关系/拓扑结构/时序交互/对比矩阵；不满足不画图。文本可 diff 图（Mermaid 类）优先于二进制图；图是事实的投影（架构变更触发图更新——图腐烂比无图更糟）；分层展示（总览 ≤10 元素+子域详图）；图内术语与正文一致；简单线性流程画图是过度设计。
- 违反后果: 不满足判据的图是纯维护负担；二进制图不进 diff，图腐烂比无图更糟（主动误导）。
- 溯源: [模型经验]（04-diagrams-visualization，置信度高）。GLOBAL 理由：可视化选择判据跨域适用（UI 信息设计同构）。

**DQ-6** **MUST**: 认知负荷工程：外在负荷最小化、相关负荷合理投入、内在负荷诚实保留。「简单来说」不降低复杂度（伪简单）——分解/类比/渐进披露才降低负荷；主流程内联（跳转迷宫防御——教程关键步骤必须本页）；嵌套列表 ≤2 层；粗体一屏 ≤3 处。
- 违反后果: 伪简单与跳转迷宫推高外在负荷，读者认知超载弃读；措辞降难度让读者误以为懂了。
- 溯源: [模型经验]（05-readability-engineering，置信度高；认知负荷框架为教育心理学成熟理论，文档应用为迁移）。

**DQ-7** **MUST**: 为扫读设计：读者扫不细读。关键词前置（段首句/列表首词）；短段落（屏读 ≤6 行）；5 秒测试（答不出「这页讲什么」即首屏失败）；可读性公式度量只做粗筛极端值报警不做质量判断（Goodhart 防御）。
- 违反后果: 关键信息埋中段扫读者扫不到；公式度量当 KPI 触发 Goodhart 失真（短句化改写割断逻辑连接）。
- 溯源: [模型经验]（05；扫读行为为 web 可用性研究共识，细节降级）。Goodhart 防御与官方基调同向——no perfect document, only proven methods and prudent guidelines [官方文档](https://google.github.io/styleguide/docguide/best_practices.html)。

**DQ-8** **[GLOBAL] MUST**: AI 腔的判据是信息密度：低信息密度的高完成感即腔，删除测试（删掉信息量不变=删）。十特征清单（总结癖/对称癖/免责癖/空洞强调/元话语/形容词堆砌/均匀节奏/假对话/闭环强迫/虚化收尾）；消除策略：删（首选）/换实/破对称/节奏注入；腔在骨架（结构对称/每节总结）不止在词汇。
- 违反后果: AI 腔文档「看起来完整」实则无信息，读者时间被浪费；只去词汇层留骨架则治理无效。
- 溯源: [模型经验]（06-ai-style-issues，自我内省+观察，置信度高；清单非穷尽、模型代际敏感）。GLOBAL 理由：信息密度判据适用于一切生成内容审查（不止文档）。

**DQ-9** **MUST**: 风格样例化不描述化：展示目标风格，不描述目标风格。「简洁专业」无效，2-3 篇认可样例有效（风格样例锚）；AI 腔词典可 lint（免责词/元话语/强调词扫描自动化）；团队全员 AI 工具后防整体 AI 腔化（组织声音）。
- 违反后果: 描述化风格指导落不了地；无 lint 兜底则人审遗漏持续累积，团队文档整体 AI 腔化。
- 溯源: [模型经验]（06，置信度高）。

**DQ-10** **MUST**: 去腔不跨类型一刀切：tutorial 的引导句是功能不是腔。判型先于文风治理：reference 零叙事零引导，tutorial 引导与「让我们」是教学功能（只走一条路的陪伴语态）；治理边界：治理低密度（腔），不治理风格偏好——过治产生无菌无味文档。
- 违反后果: 一刀切去腔删掉 tutorial 的教学功能（引导语）；无害风格差异被过度治理，产生「无菌无味」文档。
- 溯源: [模型经验]（06、01，置信度高）。

## 核心概念速览

| 概念 | 一句话定义 |
|---|---|
| 清晰性三支柱 | 具体名词 / 强动词 / 短句（DQ-1） |
| BLUF | bottom line up front——结论在首段，不设悬念 |
| 渐进披露 | TL;DR（≤3 行）→ 主体 → 深水区的三层信息结构 |
| 标题测试 | 只读标题串能还原文档结构即通过（结构完整性测试） |
| 示例五性 | 可运行 / 最小化 / 真实 / 渐进复杂度 / 版本明确（DQ-4） |
| simplest use case first | 官方示例排序纪律：系列示例从最简用例开始 [官方文档](https://google.github.io/styleguide/docguide/best_practices.html) |
| 错误处理分寸 | reference 不展示 / how-to 展示主题相关 / tutorial 一处「出错时」教学点 |
| 图腐烂 | 图与现实脱节且因 diff 盲区不被发现——比无图更糟 |
| 认知负荷三分类 | 内在（内容复杂度，不可消除）/ 外在（表述引入，可消除）/ 相关（心智模型构建，教学投入） |
| 伪简单 | 「简单来说」类措辞不降低内在负荷——分解/类比才降低 |
| 5 秒测试 | 读者看页面 5 秒答不出「这页讲什么」即首屏失败 |
| 扫读优化 | 关键词前置、短段落、粗体克制——为扫不细读的读者设计 |
| 删除测试 | 删掉后信息量不变即为腔/废话——AI 腔核心判据 |
| AI 腔 | 低信息密度的高完成感（十特征见 DQ-8，非穷尽） |
| 风格样例锚 | 以 2-3 篇认可样例 few-shot 定风格，不描述风格 |
| 警示三级 | Note=补充信息 / Warning=数据丢失风险 / Danger=不可逆损坏或安全风险 |
| Goodhart 防御 | 可读性公式等度量只做粗筛报警，不做质量判断 |

## 最佳实践

### 场景 1：写一篇能被扫读的长文档

本实践源于 [DQ-3]、[DQ-7]。

推荐路径：
1. 先写 TL;DR（≤3 行，结论前置，BLUF）——第一层是长页的礼节，无第一层即失礼。
2. 标题先行搭骨架：只抄标题串连读，能还原结构才动笔正文（标题测试）。
3. 主体按 80% 读者的目标组织；边缘情况移入独立小节或独立 how-to，主线处一行链接。
4. 关键词前置：段首句、列表项首词承载定位词——读者扫首词决定读不读。
5. 深水区（原理/权衡/边缘）折叠、分页或外链，篇幅预算倒置：第一层 ≤3 行、第二层为主体、第三层不限。

do/don't：

```text
✗ 「在本节中，我们将深入探讨缓存策略的方方面面。首先，让我们回顾一下背景……」
   （元话语开场 + 铺垫先行 + 结论埋在第三段）

✓ 「缓存策略：默认 5 分钟 TTL，登录态请求绕过缓存。原因与配置如下。」
   （TL;DR 先行 + 关键词前置 + 读者 5 秒内可决策要不要读）
```

边界条件：reference 型一页一词条可免三层（标题即结论）；短通知类文档免 TL;DR。渐进披露为业界共识，权威出处未获取 [模型经验]。

### 场景 2：为 API / 功能写示例代码

本实践源于 [DQ-4]，示例排序纪律官方锚定（simplest use case first）。

推荐路径：
1. 最简用例先行：第一个示例是目标概念的最小可运行形态 [官方文档](https://google.github.io/styleguide/docguide/best_practices.html)。
2. 一示例一概念；数据形态真实——字段形态本身是隐性文档。
3. import 完整、依赖已声明、无省略号伪代码——复制即跑是信任基础。
4. 错误处理按文档类型分寸：reference 不展示（或一行 catch 占位）、how-to 展示与主题相关的错误路径、tutorial happy path 为主 + 一处「出错时怎么办」教学点。
5. 版本显式声明（示例对应版本；假设最新版需说明）。
6. 默认最小聚焦；完整性需求用配套完整项目仓库补——两需求分治而非互相妥协 [模型经验]。

do/don't：

```ts
// ✗ don't：玩具化 + 伪代码 + 版本沉默
const data = getUser('foo'); // 返回 { bar: 1 }
// ... 其余配置

// ✓ do：真实数据形态 + import 完整 + 版本显式
import { getUser } from '@acme/users';

// @acme/users v3.2+；v2 语法见迁移指南
const user = await getUser('u_8f3a2');
// → { id: 'u_8f3a2', name: '张三', plan: 'pro' }
```

边界条件：真实 ≠ 冗长——数据形态真实、代码量最小；系列文档内示例保持命名/导入/错误处理风格一致（示例风格规范可进团队风格指南）。

### 场景 3：决定要不要画图、怎么画

本实践源于 [DQ-5]。

推荐路径：
1. 判据先行：空间关系（架构分层）/ 拓扑结构（数据流、状态机）/ 时序交互（协议）/ 对比矩阵——四判据不满足不画图。
2. 文本可 diff 图（Mermaid 类）优先于二进制图——进 VCS 可 review 可合并；二进制图仅当文本图表达不了，且源文件入库。
3. 分层展示：L1 总览图 ≤10 元素 + L2 每子域详图（渐进披露的图版）。
4. 图更新进触发链：架构变更 PR 模板勾「架构图已更新？」；图与正文术语对照术语表保持一致。
5. 图内文字不可搜索——关键信息需正文补偿。

do/don't：

```text
✗ 三步线性流程画泳道图；全系统一张图 40 节点 60 边。
✓ 主线读代码即可理解时不画；画则 L1 总览 ≤10 元素 + 子域详图分层。
```

边界条件：复杂布局文本图表达吃力时改用专业工具（但源文件必须入库）；无真实架构源（代码结构/依赖图）时不画架构图——凭想象画的架构图是编造 [模型经验]。

### 场景 4：治理 AI 腔

本实践源于 [DQ-8]、[DQ-9]、[DQ-10]。

推荐路径：
1. 删除测试定位：删掉这段/这句信息量变化吗？不变即腔，删。
2. 查骨架不止查词汇：审大纲对称性——每节等长、每列表恰三点、每节末尾有总结段即警觉（腔在结构层）。
3. 消除四策略：删（首选）/ 换实（「非常重要」→ 为什么重要、错了会怎样）/ 破对称（硬凑的第三点删）/ 节奏注入（信息密度驱动段落长短）。
4. 词典 lint 自动化：免责词/元话语/强调词扫描进 CI（人审兜不住词典化机会）。
5. 风格样例锚：2-3 篇认可样例 few-shot——展示风格，不描述风格。
6. 判型先于去腔：reference 零叙事零引导；tutorial 的引导句是教学功能，保留。

do/don't：

```text
✗ 逐句删「总之」「需要注意的是」，但每节总结段 + 万物三点式的骨架原样保留。
✓ 大纲级检查：删掉全部节末总结段——信息量不变则整层删除；
  生成模板骨架词（「在本节中」「综上所述」）词典扫描清除。
```

边界条件：治理低密度（腔），不治理风格偏好（句式/用词习惯）——过治产生无菌无味文档；tutorial 引导句是功能不是腔 [模型经验]。

### 场景 5：讲清一个复杂概念

本实践源于 [DQ-6]。

推荐路径：
1. 识别三类负荷：内在（内容复杂度，不可消除）、外在（表述引入，可消除）、相关（心智模型构建，教学投入）。
2. 伪简单禁止：「简单来说」不降低复杂度——用分解、类比、渐进披露降低负荷。
3. 主流程内联：教程关键步骤必须本页（判型内主流程不跳转）；深入细节、API 全量外链。
4. 结构纪律：嵌套列表 ≤2 层（第三层出现即重组为表格或小节）；粗体一屏 ≤3 处。

do/don't：

```text
✗ 「简单来说，它就是一个分布式一致性协调服务。」（措辞不降低内在负荷）

✓ 「类比：像停车场的车位协调员。功能三件事：a/b/c。
   先不管分布式——单机版是这样……」（类比 + 分解 + 渐进披露）
```

边界条件：内在负荷诚实保留——API 复杂就是复杂，不假装简单；认知负荷框架为教育心理学成熟理论，文档应用为迁移 [模型经验]。

## 高频坑点（速查）

### 深度展开 1：示例复制即报错（P0，信任级失效）

- 症状：读者复制文档示例运行即报错——`// ... 其余配置` 省略号、import 缺失（类型/函数来源不明）、示例用 v3 语法而读者在 v2 环境。
- 根因：作者以「读者能脑补」为假设写示例；示例从未被运行验证（死示例）；版本假设沉默。
- 代码对照：

```ts
// ✗ 复制即报错
const cfg = loadConfig(); // Config 类型从哪来？loadConfig 哪个包？
// ... 其余配置

// ✓ 复制即跑
```

### 深度展开 2：图腐烂（静默失效类，diff 盲区）

- 症状：架构图停留在旧架构，现实已重构两次；PR 里二进制图变更无人知道变成了什么。图比无图更糟——主动误导。
- 根因：二进制图不进 diff（或文本图进 diff 但被跳过）；架构变更无「图更新」触发；图源文件丢失无法修改。
- 修复：文本可 diff 图（Mermaid 类）优先；架构变更 PR 模板勾「架构图已更新？」；图与代码定期盘点核对（时效维度）；二进制图源文件入库。→ [DQ-5]

### 深度展开 3：结构性 AI 腔（治理失效类）

- 症状：逐句去腔（删「总之」改结尾）后，三点式骨架、每节末总结段、均匀节奏原样保留——审校者以为已治理，读者仍读出满页腔。
- 根因：腔的可见层（词汇）比结构层（段落组织、大纲对称）易识别；逐句审校不看大纲。
- 修复：审校看大纲——每节等长、每列表恰三点即警觉；对大纲层跑删除测试（删全部节末总结段，信息量不变则整层删）；lint 加结构信号（段落长度分布均匀性报警）。→ [DQ-8]、[DQ-9]

## API 速查表

本域「API」为质量评估工具集：四维质量评估表 + 示例代码规范检查清单 + 文档测试手段表。

### 四维质量评估表

| 维度 | 判据 | 检查手段 |
|---|---|---|
| 可发现性 | 标题串可导航（标题测试通过）；关键词前置（段首句/列表首词）；图内文字不可搜索需正文补偿 | 标题串连读测试；以读者目标关键词全文检索能否命中 |
| 可理解性 | 清晰性三支柱达标；术语先定义后使用；外在负荷最小化；5 秒测试可过 | 新读者试读 + 5 秒测试；术语首现位置先于使用处检查 |
| 可操作性 | 示例复制即跑；步骤完整内联本页；前提条件前置且独立成清单 | 干净环境粘贴实测；前提清单与步骤流分离核对 |
| 时效性 | 示例/图与当前版本一致；版本声明显式；图未腐烂 | doctest/示例编译；图与代码定期盘点核对；版本声明抽查 |

### 示例代码规范检查清单

| 检查项 | 判据 | 不合格症状 |
|---|---|---|
| import 完整 | 类型/函数来源可追 | 「这个类型从哪 import？」 |
| 无伪代码 | 无 `// ...` 省略号、无「其余配置」 | 复制即报错 |
| 一示例一概念 | 删掉非目标概念示例仍成立 | 多概念混演，重点淹没 |
| 数据形态真实 | 字段/取值贴近读者场景 | foo/bar 玩具化 |
| 错误处理分寸 | reference 不展示 / how-to 相关 / tutorial 一处 | try-catch 全家桶或全无 |
| 版本显式 | 示例对应版本有声明 | 沉默假设最新版 |
| 系列一致 | 命名/导入/错误处理与同系列一致 | 同文档内风格漂移 |
| 示例正文一致 | 示例行为与正文断言一致 | 正文说返回列表，示例用单对象 |

### 文档测试手段表

| 手段 | 验证什么 | 做法 |
|---|---|---|
| doctest | 示例输出断言非编造 | 提取文档代码块与输出断言，CI 自动运行比对 |
| 示例编译 | 代码块语法/类型可编译 | CI 编译全部文档代码块 |
| 可复制性检查 | 复制粘贴即跑 | 干净环境（新容器/沙箱）执行关键示例 |
| lint | AI 腔词典与结构骨架 | 免责词/元话语/强调词词典扫描；段落长度分布与对称性报警 |
| 可读性公式 | 仅粗筛极端值 | 句长/段长分布异常报警；**不做质量判断**（Goodhart 防御） |
