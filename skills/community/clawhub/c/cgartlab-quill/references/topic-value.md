# 选题价值（这篇凭什么值得读）

> 本文件在**第二步定下主题之后、第三步精修论点之前**加载；第五步定读者回报时再取一次。
> 它回答四个问题：**为什么是现在 / 比同题多走了哪一步 / 读者能带走什么 / 他凭什么觉得和自己有关。**
> 与 `conception-guide.md` 的分工：那边管**怎么问**（核心疑问 + 三轮提问），这边管**答成什么样才算过关**。别在两处定义同一条判据。

## 一、价值三问

一句话各答一次，答完就往下走，不要展开成报告（交付纪律见 SKILL.md「交付」）。

| 问 | 答不成的信号 | 答成了写进哪 |
|---|---|---|
| 为什么是现在 | 触发点只是「我想写」「该更新了」 | `claim.md` 的「由来」 |
| 比同题多走了哪一步 | 只能答「我的角度更好」「写得更好懂」 | `claim.md` 的「增量」 |
| 读者能带走什么 | 只能答「知道这件事很重要」 | `audience.md` 的「读后状态」 |

三问里**哪一条答不出来，就说明这篇文章现在缺什么**——缺的那条，要么补材料，要么改选题，要么缩短篇幅只交能交的那部分。不要用形容词把空白盖住。

## 二、由来：问「上次卡在哪一步」

「为什么是现在写这个」很容易答成动机（想写、憋了很久、被朋友问了）。动机不是材料，写不进正文。换成具体失败现场：

> **你上一次试图解决这件事时，卡在了哪一步？**

这个问题答出来天然带时间、卡点、代价，直接就是 `evidence.md` 里的材料。答不出，说明这个题还没有被真正碰过——要么先去做一次，要么承认这篇是二手转述。

> 同一件事还有一个变体问法：「你想推进到哪一步，而不只是重复哪一步动作？」把「整理访谈」写成「把混乱的访谈整理成能做决策的判断」，选题才立得起来。

## 三、增量：同题盘点

三问，按顺序答：

1. **同行把这件事讲到哪一步了？**（具体到篇目，不是「网上很多」）
2. **你在哪一步多走了一层？**（多出的那一层要能被一句话说出来，说成「更全面」不算）
3. **读者看完会不会说「这个我知道」？**（会 → 增量不足）

### 怎么盘点（模型驱动，不跑脚本）

按 `refutation.md`「反例优先级」走：① 本地语料（Obsidian / 本地仓库）→ ② 作者已发表内容 → ③ 他的公开仓库 → ④ 联网检索。**只认能点开的页面**，搜索摘要与模型记忆不算盘点（与 `evidence-guide.md`「什么不算核实」同一条标准）。

**没有联网检索工具时**：只做 ①②③ 的本地盘点，并在「增量」里写明「本次只盘了本地语料，没有联网查」。**不许把「没查」写成「没找到」**——那正是这一节要拦的编造。

盘点结果记成一张三栏表，**写进 `claim.md` 的「增量」栏**（不新建文件、不建索引——quill 的基本单位是一次写作，不是内容库）：

| 谁写过 | 讲到哪一步 | 备注 |
|---|---|---|
| <篇名 / 链接> | <它停在了哪个结论> | <你没看到谁继续往下讲> |

能当论据引用的同题篇目，另按 ③ 类外部来源进 `evidence.md` 的「证据清单」；盘点表与证据清单是两件事，前者记「别人讲到哪」，后者记「我要用哪一条」。

### 硬约束：不许编「空白」

**说「没人讲过」「同行只说了一半」之前，必须能说出你查过什么。** 这是编造的一个入口——「目前还没有人系统讨论过 X」读起来像判断，其实是一句关于现实的主张（`evidence-guide.md`「经历与事件的核实」同源）。

- 查过但没找到 → 写「我没有找到同题内容」，**不许写成「没人写过」**。
- 只查到摘要、点不开原文 → 不算盘点到这一篇。
- 盘点不完整的，就把话说小：「我看到的几篇都停在 A」，而不是「所有人都停在 A」。

### 三档判定与出口

| 落差 | 判据 | 出口 |
|---|---|---|
| **明显** | 能说出同题停在哪、你从哪继续 | 直接进第三步 |
| **较小** | 多走的那一层要靠读者自己发现 | 把增量写进论点句本身（别只放在正文中段） |
| **无** | 读者看完标题就能说完你要说的 | 换论点（写别人没答的那一问）／降级为经验分享（不承诺普遍结论）／放弃这个题 |

> 与「论点深度」七道测试的分工：那道测试管**这个判断够不够深**（`writing-craft.md`），同题盘点管**这个判断在市面上够不够新**。两件事都会让读者决定读不读，缺哪条补哪条。

## 四、读者回报七型

`audience.md` 的「读后状态」从下面七型里选**一个主回报**，不要七项都填：

| 型 | 读者拿走的东西 |
|---|---|
| 解释 | 一个简单、能复述的原因 |
| 判断 | 一套区分或选择的依据 |
| 行动 | 一个现在就能开始的动作 |
| 情绪 | 一种被说中的感受（必须由事实与处境撑住，不靠情绪词） |
| 身份 | 「原来这种人也存在 / 我也算这一类」 |
| 表达 | 「原来这件事可以这样说」 |
| 审美与娱乐 | 读得舒服、看得过瘾 |

**只认一个主回报。** 两个并列时，先问哪一个才是这篇非给不可的，另一个降级成手段。

> 写不出动作不等于失败。观点文与经验文的读者常要的是「解释」或「判断」，不是动作——硬加一句「你可以去试试」反而是空动作。要求的是**有一种写出来的明确回报**，不是必须有可执行步骤。

## 五、读者凭什么觉得和自己有关

读者承认你说得对、却不觉得这事跟自己有关，是长文最常见的失败。定回报之后再定**关系**，六型里挑 1–2 个：

| 型 | 读者的内心话 |
|---|---|
| 当前处境 | 「我正在经历这个」 |
| 利益后果 | 「这会影响我的钱、机会或风险」 |
| 未命名经验 | 「原来这种感觉可以这样说」 |
| 身份与立场 | 「这说的是我们 / 他们」 |
| 好奇与窥探 | 「我想知道别人是怎么做的」 |
| 社交用途 | 「这个可以拿去跟人讲」 |

选完补一句判据：**这个关系在开头露出来了吗？**（开头出现读者熟悉的处境、后果或身份才算露出来；只在结尾点一句不算）

范围别打分，只写一句话：这一篇是说给「一小群正卡在这件事上的人」，还是「跨群体的共同处境」。人群称呼越宽（「大家」「普通人」「创业者」），读者越认不出自己。

> 这一栏的目的不是做用户画像，是防止正文里那句「我们每个人都……」——它让所有读者同时不属于被描述的人。

## 六、读者会把它当什么用（他会不会转）

如果这篇要面向公开平台（**个人站、博客、公众号、论坛都算**；只有明确不公开的稿子不算），再答一句：读者会把它当什么用？

**身份表达 / 备忘工具 / 社交谈资 / 情绪出口**——四选一，答不出就不写。这一条不预测流量（quill 不预测播放量），只用来检查一件事：**这篇有没有一个可转述的用处**。答出来的用处，往往就是标题和结尾该落的地方。

> 它与「主回报」不是同一栏：**主回报是读者带走什么**（解释 / 判断 / 行动 / 情绪 / 身份 / 表达 / 审美），**用途是他拿它去干什么**（发出去 / 存起来 / 下次自查）。回报是「判断」时，用途常见的是「备忘工具」——两栏答案接近是正常的，不矛盾；用途答不出就空着，不许为了填满编一个。

## 七、自检四条

输出前各自问一次，答不上就回去改，别写进正文：

1. 这三问里，哪一条是我编的（不是查到的）？
2. 「增量」那一句，能不能被同行用一句「这个我们早写过」顶回来？
3. 「读后状态」有没有被我写成了一句「你会更懂 X」？
4. 「和我有关」这一层，开头三行里有没有？

## 什么时候可以跳过

- **内部备忘、纯资料整理、给一个人看的说明**：价值三问答完就够，不做同题盘点，也不做关系六型。
- **短答**（几百字、不必建项目，见 `form-guide.md`）：只需要「由来 + 回报」两句。
- 用户明确说「这篇不打算发」→ 增量与传播两项跳过，别拿平台标准要求一篇私人记录。
