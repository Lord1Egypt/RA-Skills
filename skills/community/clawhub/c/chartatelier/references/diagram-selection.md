# 图种决策表

> 用途：把一句需求稳定映射到一个图种，避免“先画再说”。判定顺序固定为信号词 → 主关系 → 元素规模；任一步冲突时，以主关系为准。

## 一、三步判定

1. **读信号词**：从需求句里找“分层”“先再”“怎么连”“谁在何时”“第一阶段”“三个数字”“差在哪”这类词。
2. **定主关系**：层级、顺序、连接、角色协同、时序推进、数量对比、方案取舍——七种主关系各自对应唯一图种。
3. **量元素规模**：数节点与连线。超过该图种上限时先拆图，不缩字号。

冲突处理：信号词命中两个以上图种时，取需求句主语所属的那一层。例如“微服务怎么连、调用顺序如何”，主语是服务之间的连接，判拓扑，把调用顺序降为连线上的序号标注。

## 二、八种图种

### 1. 分层架构图（architecture）

- 判断信号：分层、上层、底层、接入层、支撑层、平台层。
- 骨架：横向分层带，带内并列卡片，层名置于每带左上角。
- 最小可用：3 层 × 每层 2–4 张卡片。
- 上限：单层 ≤5 张卡，总量 ≤18 张卡，层数 ≤5。
- 常见误用：用架构图表达先后顺序；把“数据库”与“查询服务”并列成同级。
- 验收要点：同层卡片等宽等高、层间垂直间距一致、跨层连线只连相邻两层。

### 2. 流程图（flow）

- 判断信号：先…再…然后、如果…就、卡在哪、审批、回退。
- 骨架：纵向主干居中，判定菱形向右分叉，回边从左侧外圈绕回。
- 最小可用：3 步主干 + 1 个判定。
- 上限：主干 ≤8 步，判定 ≤3 处，回边 ≤2 条。
- 常见误用：主干超过 10 步仍不折行；判定出口不标“是 / 否”。
- 验收要点：主干 x 坐标统一、判定两个出口都有箭头、回边不穿过任何矩形。

### 3. 拓扑图（topology）

- 判断信号：怎么连、链路、组网、走哪条线、机房、区域。
- 骨架：分区虚线框 + 框内节点 + 正交连线；跨区连线走框间空隙。
- 最小可用：2 个分区、5 个节点。
- 上限：节点 ≤14，跨区连线 ≤8，分区 ≤4。
- 常见误用：把拓扑画成架构分层；同一条链路画成两条线。
- 验收要点：连线不穿框、不自交；同一对节点之间只保留一条线；图例说明线的类型（实线 / 虚线 / 颜色）。

### 4. 泳道图（swimlane）

- 判断信号：谁做什么、跨部门、交接、责任边界。
- 骨架：纵向泳道（每个角色一条）× 横向阶段列。
- 最小可用：3 条泳道 × 4 个阶段。
- 上限：泳道 ≤5，阶段 ≤6。
- 常见误用：一条泳道塞进两个角色；阶段列宽不等导致箭头错位。
- 验收要点：同一阶段的活动顶部对齐；跨泳道箭头只上下走，不斜穿。

### 5. 时序图（sequence）

- 判断信号：谁先发、响应、回调、超时、交互几次。
- 骨架：顶部参与者列 + 生命线 + 水平消息箭头。
- 最小可用：3 个参与者、4 条消息。
- 上限：参与者 ≤6，消息 ≤12。
- 常见误用：把异步消息画成同步；消息文字压在生命线上。
- 验收要点：消息自上而下按时间递增；返回消息用虚线，与请求区分。

### 6. 时间轴（timeline）

- 判断信号：第一阶段、里程碑、从 X 到 Y、上线节奏。
- 骨架：单条水平轴 + 上下交错标签，避免相邻标签碰撞。
- 最小可用：4 个节点。
- 上限：8 个节点；超过 8 个改两行时间轴或改泳道。
- 常见误用：等距与等比分不清；标签竖排后撑出画布。
- 验收要点：节点等距或按真实时长成比例（二选一，并在图注写明）；标签到轴线的垂直距离一致。

### 7. 信息图（infographic）

- 判断信号：一页讲清、三个数字、占比、增长。
- 骨架：主视觉（一个大数字或一张简图）+ 3–5 个数据块 + 一句结论。
- 最小可用：1 个主数字 + 2 个支撑块。
- 上限：数据块 ≤5，每块文字 ≤2 行。
- 常见误用：把所有数字都做成环形图；单位与时间口径缺失。
- 验收要点：每个数字都带单位与统计口径；同类数字使用同一量纲。

### 8. 对比矩阵（matrix）

- 判断信号：A 和 B 差在哪、怎么选、打分、优劣势。
- 骨架：行 = 选项，列 = 维度；单元格用符号（● / ○ / —）或两字以内的短词。
- 最小可用：2 个选项 × 3 个维度。
- 上限：维度 ≤6，选项 ≤4。
- 常见误用：单元格里写整句；符号含义不在图例说明。
- 验收要点：符号种类 ≤3 且配图例；列宽一致；表头底色区别于数据行。

## 三、拆图阈值

| 情况 | 阈值 | 拆法 |
|---|---|---|
| 架构图卡片数 | >18 | 按层拆：接入与核心一张，数据与支撑一张 |
| 流程图步数 | >8 | 按阶段拆，跨图处标“接续①” |
| 拓扑节点数 | >14 | 按分区拆，边界节点两侧都出现并注“跨区” |
| 时间轴节点数 | >8 | 拆上下两行，或改泳道按角色分列 |
| 矩阵维度数 | >6 | 只留决策相关维度，其余进备注 |

拆图后每张仍需独立通过五项自检，且同一份交付内的语义色不得改变含义。

## 四、反例清单

- 用一张图同时表达“层级 + 时序 + 数量”：必然有一项被牺牲，改为一张主图加一句注释。
- 需求句只有名词没有关系（“做个系统架构图”，却未给系统名与层数）：先问清三层结构，不得凭空生成模块名。
- 用户指定图种但与其目的冲突（要“流程”，实际在比较方案）：按目的选型，并在交付说明写明偏离原因。
- 把图例当注释用：图例只解释颜色与线型，业务说明走编号注释。
