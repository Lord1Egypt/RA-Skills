## 用户反馈模块（诊断闭环关键环节）

### 核心价值

用户反馈是OPC智脑持续优化的核心数据源，每次诊断必须收集反馈，形成"诊断-反馈-优化"闭环。

### 触发时机

报告导出完成后，自动触发用户反馈询问：

```
✅ 导出成功！

📁 文件已保存到：opc-reports/2026-06-09/

---

📝 **收集反馈，持续优化**

诊断已完成，希望听听你的真实感受，帮助我改进产品。

回复数字即可：
• 回复 1 → 快速反馈（5个核心问题，2分钟）
• 回复 2 → 详细反馈（11个问题，10分钟）
• 回复 0 → 暂不需要反馈

💡 你的反馈对我很重要，会直接影响产品优化方向。
```

#### 步骤5：自动更新反馈汇总（必须执行）

**⚠️ 此步骤为强制执行，不可跳过。每次新增反馈后必须同步更新summary。**

**执行流程**：
1. 读取 `opc-feedback/当日日期/` 目录下所有 `feedback-*.md` 文件
2. 逐个解析每个反馈的问卷答案和分析标签
3. 重新统计汇总数据，更新 `feedback-summary.md`

**汇总统计规则**：

| 统计维度 | 统计方法 |
|---------|---------|
| 总反馈数 | 统计 feedback-*.md 文件数量 |
| 满意度分布 | 按Q1答案分组统计人数和占比 |
| 最有价值部分 | 按Q2答案统计票数，取Top3 |

| 流程体验 | 按Q4（快速版Q3）答案分组统计 |
| 推荐意愿 | 按Q10（快速版Q5）答案分组统计 |

### 反馈应用机制

#### 机制1：产品优化优先级

根据反馈自动生成优化优先级：

| 反馈维度 | 占比 | 优化优先级 |
|---------|------|-----------|
| 核心价值点 | 40% | 最高 |
| 流程体验 | 30% | 高 |
| 付费意愿 | 20% | 中 |
| 推荐意愿 | 10% | 低 |

**示例**：
- 如果多个用户反馈"流程不顺畅" → 立即优化信息采集流程
- 如果多个用户反馈"缺少某功能" → 优先开发该功能
- 如果多个用户反馈"定价偏高" → 调整定价策略

---

#### 机制2：案例沉淀

**正面反馈（满意度高）**：
- 记录为成功案例
- 用于产品宣传和口碑展示
- 脱敏后可公开分享

**负面反馈（满意度低）**：
- 详细记录问题和原因
- 优先分析共性问题和改进方向
- 作为产品迭代的重要输入

---

#### 机制3：定价策略调整

根据付费意愿反馈动态调整定价：

| 反馈区间 | 用户占比 | 定价建议 |
|---------|---------|---------|
| 9.9-29.9元 | >50% | 定价29.9元，增加低价引流款 |
| 30-99元 | >50% | 定价99元，符合用户预期 |
| 100-299元 | >50% | 定价199元，可考虑增加高客单价服务 |
| 300元以上 | >50% | 定价299-399元，定位高端服务 |

### 约束规则

1. **主动询问原则**：报告导出完成后必须主动询问是否反馈，不等待用户主动提出
2. **简洁高效原则**：快速反馈版优先推荐，降低用户反馈门槛
3. **一次性展示原则**：所有问题一次性展示，用户一次性提交，不逐题询问
4. **格式友好原则**：提供清晰的格式示例，降低用户填写门槛
5. **记录原则**：每次反馈必须记录到文件，不遗漏任何反馈
6. **汇总同步原则**：每次新增反馈后必须同步更新feedback-summary.md，不可跳过
7. **全量统计原则**：汇总必须重新统计所有反馈数据，不是增量更新，确保数据准确
8. **感谢原则**：无论反馈多少，必须感谢用户的时间和意见
9. **应用原则**：反馈必须转化为具体的优化动作，不能只收集不应用
