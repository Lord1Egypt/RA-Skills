# 用真实测试改进技能与专家

本指南来自 FastGPT、n8n 专家制作和多轮普通用户测试的维护经验（2026-11-17整理）。它说明如何收集证据和收敛改动，不规定业务工作流必须采用特定节点、接口、模型或查询规则。

## 先确定实际执行的版本

读取隐藏 `.codebuddy-plugin/plugin.json` 得到专家版本，再沿 `skills` 声明读取实际内置技能的 `SKILL.md` 和版本清单。不要在专家根目录猜技能清单路径，也不能凭 Agent frontmatter 缺少 version 就断言专家无版本。报告专家、技能、build_id/local_revision、目标客户端版本及审核生效版本；缺少来源的值标未知。

技能版本不必随头像或专家上传版本一起递增。当前版本事实集中在清单，参考文档尽量引用它；历史版本说明保留时间范围。交付前检查正文中的“当前版本/均为”等旧断言，不能批量替换所有历史版本号。

安装核对使用 `scripts/verify_install.py` 比较可信发行 ZIP 与用户指定的实际目录。报告只证明选定文件一致，不证明客户端已经加载该目录；同版本号也可能存在 local-r1/r2 等不同构建。额外运行时文件单列，备份放在技能发现目录之外。

## 从普通用户任务到证据

先用用户自然说法测试核心场景，再补边界、非法输入、部分失败与最终交付。从最终交付文件提取实际绑定、代码和引用，不用另写的一份函数替代产物测试。测试只打印输出或只检查“变量有值”，不能据此声称真实路由和最终回复正确。

每个案例至少保存：需求依据、原始输入（公开时脱敏）、实际/期望结果、实际模型及思考设置、专家和技能构建标识、测试命令、退出码、stdout/stderr、产物及测试合同摘要、测试层级。不能把用户后来纠正的模型名称继续计入对比；标记误归类，保留本地追溯，汇总排除该轮。没有对等样本和相同任务条件，不写某模型“最佳”；额度不足可换模型继续，但单独记录。

需要行为断言时验证最终可见结果：原输入完整保留、原因可理解、请求失败与业务空结果区分、批量结果不丢行。不把某项目的 IP/MAC、ping、HTTP 状态码或 URL 规则强加给其他技能。

## 定向反例和同合同正样本

对确有必要的校验器加少量能暴露具体缺陷的变异：先证明故障确实生效，再用相同工具和合同验证正确产物 exit 0、变异产物按预期断言 exit 1。每份不同合同均需要自己的正样本；错误路径 mock 不能替代正确路径 mock。保存工作流/产物、合同、工具及相关依赖摘要，防止拿另一份通过报告来配对。

故障探针 exit 0 只说明故障存在；缺文件、缺环境、检查器崩溃和不支持的语法不算成功拦截。仅 route=invalid 等宽断言可能漏掉原值截短，需要同时断言完整原值、原因和最终回复。保留首次失败及修正记录，不把重跑后的通过写成从未失败。

## 远程测试与成本

用户提供分享URL时，先读取技能已包含的协议/注册资料和现有测试脚本。已有可信接口契约且用户已授权测试时优先API；不要猜测 shareId 等同 appId、端点或鉴权。协议未知才做最小必要取证或浏览器回退，不要求每次新对话重复提供已知协议。发布通用包只带脱敏协议说明与示例，私有域名、令牌和注册表留在项目配置外。

日志分析可主动引导导出 Excel/CSV；用户目标平台若默认仅最近7天，可提示扩大日期范围增加样本，但先以实际导出界面为准。先归类重复问题和高影响案例，再形成“案例→原因证据→修复→验收”的映射。工作流和知识库更新分别确认适用性，不能把一轮模型猜测变为事实。

## 收尾条件

结构检查、解压脚本、客户端导入、客户端实际调用、业务平台运行和市场审核分别报告。通用报告标 `artifact_role`、`importable_workflow:false`，只把真正的工作流交给业务平台导入。必要检查通过后交付或按授权发布；不要为低影响文案/头像修改重复全部业务测试，用户选择停止扩测时说明剩余边界即可。
