# 拆解报告输出模板

分析完成后按此结构输出。所有标题用标准 Markdown，一份报告只有一个 H1。

```markdown
# 《文章标题》文章拆解分析报告

**分析对象**：作者、标题、发布日期
**原文链接**：URL
**分析目标**：拆解作者的思考路径与举证手法

---

## 一、概览与核心判断

一句话概括全文方法（例如：抓矛盾、拆概念、追中间层、换维度、结构化收口）。
说明本报告回答什么，以及证据的总体特征。

## 二、作者的思考路径

### 2.1 N 步推理链
每步一个小标题，格式：
**第 N 步，动作名。** 这一步做了什么 + 原文依据 + 为什么关键。

（步数按文章实际，不强求五步。题眼那一步要标注。）

### 2.2 判断标准（如有）
提炼作者下结论用的判据，每条给原文例句。

## 三、举证材料拆解

### 3.1 材料清单
表格：材料类型 / 具体材料 / 引用方式 / 论证作用。

### 3.2 材料的组织原则
说明材料如何对应论证结构。

## 四、引用手法拆解

### 4.1 手法清单
逐条列出识别到的手法，每条给原文例句。

### 4.2 论证结构还原
Toulmin：主张 / 证据 / 推理 / 限定 / 反驳。

## 五、证据质量评估与使用提醒

来源是否有出处、是否跨行业拼接、结论是统计还是观察。
给出"哪些能拿走、哪些要核实"。

## 六、可迁移的写法模板

把方法抽象成 5-7 条动作清单，供用户套用到新选题。

## 七、结语

点明这篇文章真正值得学的是什么。
```

## 输出纪律

- 章节可按需增删，但 A/B 两个维度与证据质量评估必须有。
- 每条判断后跟原文依据，用引号或转述标明。
- 数字后面标注"（待核实）"或在第五章统一声明。
- 不输出阅读量、传播路径等爆文数据，除非用户明确要求。
- 语气保持克制，不用"惊艳""绝了""封神"这类形容词。
