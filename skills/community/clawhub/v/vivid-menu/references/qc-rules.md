# 质检规则

`inspectMenu()` 把「看起来对不对」翻译成可计算的检查。这是整条链路里最值得学的部分：**生成 → 测量 → 修复**。

`error` 表示版面已破损，必须改；`warn` 表示能看但不够好，建议改。

## 规则全表

### 数据层

| code | 级别 | 触发条件 | 后果 | 谁来修 |
|---|---|---|---|---|
| `empty` | warn | 没有任何菜品 | 空白菜单 | 人（补菜品） |
| `no-name` | error | 某道菜 `name` 为空 | 渲染出一行空白，像 bug | 人 |
| `dup-id` | error | 两道菜 `id` 相同 | 点击编辑会改错菜 | 人（重新生成 id） |
| `dup-name` | error | 同名菜名出现多次 | 顾客以为重复计价 | **人**（合并或改名，机器猜不出来） |
| `no-price` | warn | `price` 为空 | 顾客不敢点 | **人**（绝不编造价格） |
| `sig-no-evidence` | warn | 标了招牌但 `signature_note` 为空 | 无法追溯为什么推荐它 | 自动（补一句说明） |
| `no-blurb` | warn | `blurb` 为空 | 该行留下突兀空白 | 自动（查词典补） |
| `price-format` | warn | 部分价格带 `¥`、部分不带 | 排版参差 | 自动（统一补符号） |
| `price-unit` | warn | 部分带「/份」「/位」、部分不带 | 计价方式不清 | 人（判断该不该带单位） |
| `mixed-section` | warn | 有的菜归了类、有的没有 | 出现无名分节 | 自动（未分类统一归「热菜」） |

### 插图层

| code | 级别 | 触发条件 | 后果 | 谁来修 |
|---|---|---|---|---|
| `art-thin` | error | 图元 < 4 个 | 缩小后认不出是什么 | 自动（丢掉外部图，交回引擎重画） |
| `art-tiny` | warn | 插图内容 < 120 字节 | 可能是空图形 | 自动（同上） |
| `art-busy` | warn | 图元 > 70 个 | 小尺寸糊成一团 | 人（换简单类别或外部图） |

### 排版层

| code | 级别 | 触发条件 | 后果 | 谁来修 |
|---|---|---|---|---|
| `name-overflow` | error | 菜名换行超过 2 行 | 被截断，字消失 | **人**（删字或改短名） |
| `blurb-truncate` | warn | 描述换行超过 2 行 | 尾部被吃掉 | 自动/人（压到 60 字内） |
| `price-wide` | warn | 价格文字宽 > 86 单位 | 挤压左侧文字区 | 人（去掉多余字符） |
| `too-long` | warn | 总高 > 4200 | 打印会分页 | 人（拆菜单或删描述） |
| `too-few` | warn | 少于 4 道菜 | 版面空旷 | 人 |
| `multi-signature` | warn | 招牌 > 1 道 | 只有第一道放大，其余名不副实 | 自动（只留第一道） |

### 主题层

| code | 级别 | 触发条件 | 后果 | 谁来修 |
|---|---|---|---|---|
| `contrast-low` | warn | 纸墨对比度 < 7:1 | 远看发灰、打印糊 | 人（换主题或改色） |
| `accent-close` | warn | 点缀色与墨色色距 < 28 | 招牌菜没层次 | 人（拉开色距） |

## 自动修复的边界

`autoFix()` 最多跑 3 轮，只修**机器能确定对错**的问题：补描述、补招牌依据、重画插图、统一价格写法、归并分节、收敛招牌数量。

**明确不修的四类**，因为它们需要人做价值判断：

1. **价格缺失** — 不知道就留空，编一个数字是最严重的错误
2. **菜名重复** — 「大份」「小份」还是「删一道」，机器猜不出来
3. **菜名过长** — 删哪两个字会改变语义
4. **菜单过长** — 拆不拆、按什么拆，是经营决策

这条边界的意义：**自动修复只让菜单变正确，不让它变得不是用户的那张菜单。**

## 怎么读质检结果

`error` 为 0 才叫可用。`warn` 要逐条判断：

- `no-blurb` 连着出现五六条 → 不是缺陷，是你给的菜品太冷门，词典没覆盖。手动补比让机器猜好
- `too-long` + `too-few` 同时出现是不可能的，出现说明数据有问题
- `contrast-low` 一定是主题选错了，不要试图微调，直接换主题

## 二次校验

改完菜单必须重新 `inspectMenu`。`autoFix` 可能引入新问题（比如把价格统一加了 `¥` 后撑破价格列宽变成 `price-wide`），一轮修复后要复检。
