# 示例系统

> **给“逛一逛”用。** 可以打开阅读的完整示例系统：一个维护得好的系统，在几周之后是什么样子。
> **示例身份：构造样本。** 其中的人、数字和对象细节为试验场创作，用来展示系统形态与接续习惯。研究与作品中的现实判断继续从真实对象和来源中产生。

| 示例 | 它展示什么 | 它有哪些部分 |
|---|---|---|
| `creator-weekly-video/` | 一个为了行动而存在的系统：一项实践、它五周里的结果、一个盯住的条件 | 核心、一份实践记录、数据、一段小脚本 |
| `concept-for-a-beginner/` | 一个只有一个短文件的系统，其中第二份认识记录占了一半的分量 | 只有核心 |

每个示例只有一个中文 `SYSTEM.md` 入口。

## 怎样展示一个示例

1. 先读它的入口。在讲解之前，先问这个人注意到它是怎样写的。
2. 展示各部分之间的关系：入口描述了其他每个文件，并说明它是做什么用的。
3. 指出那些习惯：本质放在最前；论断带着日期和证据；实践记录大部分是结果；“现在最值得做的事”是一个选择；第二份记录说明下一次从哪里讲起。
4. 把两个示例并排放。一个里面的任何东西，放进另一个里都说不通。这个差别就是要学的东西（见运行时里的 `system/shapes.md`）。
5. 把两个检验说出来。**接续检验**：一个新的 AI，只凭这些文件能接着做吗？**起点检验**：下一次运行，会从这个人已经理解的地方开始吗？

## 怎样使用这些示例

观察每个示例怎样让结构贴合对象、使用者和目的，再为真实系统生成自己的文件、顺序和语言。

真实示例只有在所有者明确同意公开、隐私已处理、来源与权限清楚时才进入试验场。
