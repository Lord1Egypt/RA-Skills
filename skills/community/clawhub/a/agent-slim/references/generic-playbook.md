# 通用瘦身手记

不依赖具体 Agent 的文件名。先按"这段内容什么时候进上下文"判断归属，再选手法。只看名字容易漏（比如叫 `NOTES.md` 的文件可能每轮都注入）。

## 0. 三条前提

1. **先量再动。** 没有基线就没有"省了多少"，只能算"我改动了什么"。
2. **一次一块。** 同时改三处，回归失败时说不清是谁的错。
3. **触发词是不可压缩件。** 描述可以砍到一句话，触发词砍掉一个就等于砍掉一条路由。

## 1. 规则（每轮都在的指令）

**怎么找**：每次对话都会出现在系统提示里的那段文字；或者被它引用进来的规则文件。判断方法不是看目录名，而是问"我开一个无关的新话题，它还在吗？"

**症状**：同一条约束在三个地方各写一遍；历史遗留的"当前阶段"说明；大段解释"为什么要这么做"。

**手法**
- 合并重复：同一约束只留一处，其他处改为指针。
- 删过程留结论：把"为什么"移出常驻，只留"必须/禁止"。
- 删时效性内容：已经过期的阶段说明、临时开关说明。
- 压缩措辞：长句改短句，例子只留一个最典型的。

**红线**：安全边界、禁止项、身份约束不能因为"读起来啰嗦"而删。它们的字数就是成本，但删掉是事故。

## 2. 记忆（摘要、画像、注入块）

**怎么找**：开头那段"关于用户的背景"；或者 `memory` / `MEMORY` / `summary` 类文件。有些 Agent 在服务端注入一段，本地找不到对应文件——那种只能去设置里清。

**症状**：记忆文件从几十行涨到几千行；同一事实在不同段落重复；大量"待确认""unknown"空条目；把整段排查过程写进常驻。

**手法（最有效的一条）**
- **结论常驻 + 过程外移 + 指针可达。** 常驻文件只留可执行结论（口径、命令、判定规则），把完整过程逐字存到不注入的归档文件，并在常驻里留一行"详见 `<path>`"。
- 空条目清空：`[unknown]`、占位符、TODO 不产生信息，只产生 Token。
- 去重：同一事实在"身份""偏好""项目"三处各写一遍，只留一处。

**红线**：事实不能丢。外移的是叙述和过程，不是结论。外移后要能一键找回（归档路径写进常驻）。

## 3. 技能（清单描述 + 正文 + 参考）

**怎么找**：每轮注入的技能清单（名称 + 描述 + 触发词）；被调用时才加载的正文；正文引用的参考文件与子项。

**症状**：描述长到一段话；同一技能装了两份（名称相同）；参考目录里躺着从没被路由过的大文件；一个技能拆出几十个子项全部列在清单里。

**手法（按性价比排序）**
1. **去重名**：同 `name` 的两个目录会让清单重复、让路由指错。留一份（能真正跑通的那份），另一份打包隔离。
2. **压描述**：只压最长的几个，压到"一句话说清干什么 + 全触发词"。描述是路由依据，压缩时逐条比对触发词。
3. **清单瘦身**：子项只在需要时列，不要在清单里平铺几十条。
4. **正文外移**：正文只留"何时用 / 流程 / 边界 / 路由"，细则移到按需文件。这叫"留入口不留全文"。
5. **大文件拆分**：单个参考文件超过 ~20 KB 就该按主题拆，并给出读取条件。

**红线**：正文外移后必须仍可达（路由表里要能查到），否则下次就真的调不出来。外移不等于删除。

## 4. 工具（MCP / 插件暴露的工具）

**怎么找**：每轮注入的 tool schema 清单。很多 Agent 会把所有已连接 server 的工具名全列进去。

**症状**：工具名上百个；一个月没调用过的 server 仍在列表里；同一个能力被两个 server 重复提供。

**手法**
1. **先分清真注入与缓存**：本地可能缓存了几百个工具，但只有已连接的才进上下文。按 server 数工具、按调用记录定去留。
2. **裁剪暴露面**：能用服务端 header / 配置限制工具集就用（例如只暴露 `repos,users` 这类工具集，再加白名单单工具）；不能限制就去掉整个 server。
3. **按真实调用定去留**：扫最近 30 天的调用记录，零调用的 server 优先关。
4. **关掉要走对入口**：内置连接器往往不在普通配置里，改配置文件无效，得在 UI 设置里关。写报告时要标"待人工"，不能写"已优化"。

**红线**：裁剪后必须对端点做一次真实列举验证（`initialize` + `tools/list`），不能只看配置文件改没改。子代理/自动触发类工具（如表格代理、支付卡片）关之前要确认没有流程依赖。

## 5. 文档（固定注入的模板与参考）

**怎么找**：不由用户触发就被带进上下文的模板、示例、检查清单。

**手法**：外移 + 补读取条件；模板只留骨架，示例留一个；把"使用说明"和"内容"分开，说明按需读。

**红线**：模板被外移后，生成结果的结构不能变。改完拿一个真实产出对比一次。

## 6. 冷数据（会话、备份、日志、缓存）

**怎么找**：不进上下文、只占磁盘的东西。典型是旧会话、重复备份、日志、插件旧版本、blobs。

**手法**
- 旧会话：确认已结束再归档，保留可读性。
- 重复备份：只有逐字节相同的才能免确认隔离；不同的一律人工看。
- 日志：交给宿主的轮转机制，不要手动删正在写的文件。
- 插件旧版本：被新版本替代的可以清，但必须同步清注册表，否则市场自动更新会拉回来。

**红线**：这一层**不产生 Token 收益**。把它写成"省了 token"是口径造假。清理前留删除清单（路径、字节、依据）。

## 7. 五类手法速查

| 手法 | 适用 | 是否可能省 Token | 风险 |
| --- | --- | --- | --- |
| 压缩 | 规则、描述、结论 | 是（直接） | 压掉触发词或边界 |
| 外移留指针 | 记忆过程、技能正文、大参考 | 是（如果确实不再加载） | 指针断了等于丢失 |
| 去重 | 同源技能、重复约束、重复子项 | 是 | 删错保留副本 |
| 裁剪暴露面 | 工具清单、子项清单 | 是（直接） | 裁掉在用能力 |
| 归档 | 会话、备份、日志、缓存 | 否，只省磁盘 | 删了没留回滚 |

## 8. 常见反模式

- **只压最长的那个文件**：最长的往往不是每轮都加载的，压了也不省 Token。
- **把 Warm 的收益算成每轮收益**：Warm 只有"确实不再被加载"的那部分才算。
- **用磁盘节省冒充 Token 节省**：两本账，不能相加。
- **一次改十个文件**：回归失败无法定位，也没法只回滚一处。
- **报告里只写"优化完成"**：没有 before/after 数字，用户感受不到，下次也不会再找你。
- **为了消 warning 造假文件**：布局差异导致的告警应逐条说明，不该造一个空文件糊过去。
