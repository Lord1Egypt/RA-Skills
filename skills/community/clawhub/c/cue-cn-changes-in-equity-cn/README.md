# 所有者权益变动·逐条挂源

给一份财报或公告，把**合并所有者权益变动表**读成一张**每个数都能回到表内原句**的登记表：权益变动总览、本期增减变动、利润分配与所有者投入、期末余额与勾稽、归属于母公司与少数股东。

权益变动表是财报里唯一一张「横竖都要平」的表：纵向每列 期末＝期初＋增减，横向每行 合计＝各成分列之和，再加上三条勾稽（综合收益总额＝净利润＋其他综合收益、增减合计＝综收＋投入－分配、本节合计＝总览的合计列）。这些关系披露里不会替你算，但也不是让你补出来的——**表内各数照抄，轧平与勾稽由机检现算**。本件只做前一半：把数抄对、把列标对、把原句挂上。

不反推增减、不把未分配利润说成可分现金、不评价股东回报是否丰厚、不估值、不给评级。

## 一、零依赖三分钟上手

只装 Python 3，不给任何数据文件，也能跑出一份完整合规的成品，看它长什么样、判据怎么打：

```bash
python3 scripts/check_equity_statement.py --demo
```

把这份样例存下来再跑一遍机检——它会照七节形制、三元组、行列轧平、三条勾稽与红线逐条判：

```bash
python3 scripts/check_equity_statement.py --demo > 样例权益变动稿.md
python3 scripts/check_equity_statement.py 样例权益变动稿.md
```

接着换成你自己那份稿子：

```bash
python3 scripts/check_equity_statement.py 你的权益变动稿.md
```

退码语义：`0` 五道全过｜`1` 有发条（逐条打印 `码 行号 说明`）｜`2` 用法错（没给稿子路径，也没给 `--demo`／`--selftest`）｜`3` 读不到文件或空稿。零发条但有判据尚未落字时同样退 3——rc=0 只留给「五道全过」，没跑的道不能算过；报告里那几道计「不可判」，**不等于合规**。本件五道已全部落字，这条当前不触发（好样单跑退 0），留着是为了将来某道回退成空壳时不把「没跑」读成「过」。

拿不到成品时，从原文开始的三步：

1. **定主体与报告期**，拿到年报或半年报的合并所有者权益变动表（横排大表，十几列）与附注里利润分配、所有者投入那几段。
2. **每节抄事实，连原句一起抄**：一条 = 一行，行首写项名、紧跟 `〔列：列名〕`、再写金额，行末挂 `「原句」〔锚：页/表〕[S#]`；表里没有的数就写 `未取到：项名`，不留空、不借「期初加增减等于期末」这类常识补。
3. **跑一遍自检**，红一条改一条：

```bash
python3 scripts/check_equity_statement.py --selftest   # 内置夹具自检（档数与结果以末行现报为准）
```

三档一起跑（自测→好样→坏样，坏样注入必先断言落地）：

```bash
bash scripts/fixtures/run_fixtures.sh
```

## 二、五道机检在管什么

现状以脚本里 `UNIMPLEMENTED` 的现值为准：五道**全部已落字**，`UNIMPLEMENTED` 为空——报告里那一道「不可判」的计数当前为 0。将来某道若回退成空壳（重新登记进 `UNIMPLEMENTED`），它会调用即抛、由机检收进「不可判」，既不判也不放行，单稿退 3；`rc=0` 只留给「五道全过」。

| 码 | 名称 | 判什么 | 最常拦住的情况 | 现状 |
|---|---|---|---|---|
| `EQ-STRUCT` | 形制 | 头部三件自标（AI 整理初稿／请回原文核对／不构成投资建议）逐字在位、七节齐且按序；认不出的节标题与多出同名节记 stray 逐条发。只判「形」，不判内容 | 某节名改了个字就整节认不出；节里只有散文没有 `- ` 发现行 | 已落字 |
| `EQ-QUOTE` | 原句与锚 | 发现行以「」原句＋〔锚：…〕＋`[S#]` 收尾且三元组落在行末，可挂多组，缺哪件点名哪件；来源行 `- [S#] 标题 \| URL \| 检索日 YYYY-MM-DD`，URL 须为可点 http(s)；引用的 `[S#]` 须已登记 | 只写「期末余额 112.00 亿元」没抄原句；正文引用了 `[S3]` 而来源节没有这一号；检索日写成 `2026/03/20` | 已落字 |
| `EQ-FOOT` | 行列轧平 | 只认带 `〔列：…〕` 的发现行，**列名按字面匹配、不按位置**（位置一改序就整片误红）。① 列内：某列期初／增减／期末三项都在才判，须满足 期末＝期初＋增减；② 行内：某行「合计」与**全部**已知成分列都在才判，须满足 合计＝各成分之和。缺一项即该列／该行不判，**不补 0**。容差 `0.011` 个登记单位（两侧各舍一次的最坏情况），不放宽到「1 元」那种量级 | 抄错一格数导致列内不平；漏抄一列导致整行不判（宁可整行不判也不拿缺数补 0）；整稿漏写列标 ⇒ 一项都判不了 | 已落字 |
| `EQ-LINK` | 三条勾稽 | ① 综合收益总额＝净利润＋其他综合收益税后净额；② 本期增减变动合计＝综合收益总额＋所有者投入和减少资本－利润分配（**表里分配是减项，符号按项目名定，不靠「分配记负数」那套约定**）；③ 本节增减合计＝「权益变动总览」里本期增减变动〔列：合计〕那一格。三数不齐就不判 | 自己用上期比例反推增减；净利润拿「归属于母公司」口径顶替合并数（合并数＝归母＋少数股东，两者本就不等）；只挪总览合计列造成的跨节不符 | 已落字 |
| `EQ-LINE` | 红线 ＋ 缺口对账 | 甲 自下判断词零命中（股东回报丰厚／高送转预期／管理层意图／分红慷慨／大股东看好／值得买入／建议关注／后市可期）；乙「未分配利润」同行不得并写「可分现金／可分配现金／现金分红能力」；丙 正文 `未取到：X` ⇔ 第六节点名 X，零缺口时第六节写 `未取到：无`。甲乙扫全文但**「口径与未取到」「来源」两节整节豁免** | 在内容节写「公司股东回报丰厚」；把「未分配利润 59 亿」写成「59 亿可分现金」；正文点了未取到而第六节没列（单向），或反之（反向） | 已落字 |

**`EQ-FOOT` 的现场读数不能省**：每次跑都会印一行

```
EQ-FOOT 已判：列内 4 项、行内 3 项；未判（认不出表形或数不齐）13 项——只对这 7 项负责
```

判 0 项与判 12 项全平若印成同一句，读者会把「一行都没查」读成「这表平了」。所以列标被删净时它**不静默零发条**，而是明发一条「未判任何一项……整表零校验——**这不等于合规**」。这一条是本件最贵的一条判据：它区分的是「查了、平」与「没查」。

`--selftest` 逐档打印每档结论，末行自己报 `自测档数=N｜不合=0｜不可判=N`（**两个 N 都以现跑为准，本文不复述数字**；「不可判」那一位随 `UNIMPLEMENTED` 现算——本件当前为 0）。夹具分类：好样——零发条；坏样·形制——头部缺自标、节标题认不出；坏样·锚——摘掉「」＋〔锚〕只留 `[S#]`、来源行检索日斜杠式、引一个未登记的 `[S#]`；坏样·轧平——列内破、行内破；坏样·勾稽——综收≠净利＋其他综合收益、增减合计≠三项算出来的数、只挪总览合计、总览表自洽同步挪 1；坏样·红线——自下判断、把未分配利润说成可分现金、缺口单向与反向；反证——缺一格不判、删掉整行使三数不齐不判、净利润只有母公司口径不许顶替、红线词写进第六节整节豁免、`[待人工]` 行不算缺口。另有五道机械自证：覆盖自证、空壳自证、不崩自证、单稿退码自证、读数自证。

## 三、四条红线（这件的立身之本）

1. **不反推增减。** 本期增减只认表内三项（综合收益总额／所有者投入和减少资本／利润分配）的原句，不用上期比例外推、不用资产负债表差额倒轧；缺的写「未取到：」并进第六节。
2. **不把账面数说成现金。**「未分配利润 59.00 亿元」是权益科目余额，不等于「可分现金 59.00 亿元」；能不能派现、派多少看分红方案，本件不判。同一行里并写即发。
3. **不轧账、不并项。** 综合收益总额、所有者投入和减少资本、利润分配各占一行，不并成「净变动」「合计影响」一句；行列与勾稽的平衡由机检现算，本件不替表算一遍再写进正文。
4. **净利润只认合并口径。** 「归属于母公司所有者的净利润」不能顶替合并净利润；引文里只写归母而无「合并」字样时，机检把该项作废、宁可记未取到——错口径的数比没数更危险。

## 四、数据通道

发现先行，匿名取 live 目录，拿到 `routing` 后再连接发 `tools/list`，以现场返回为准，不硬编码工具名与工具数：

```bash
curl -sS https://cuecue.cn/api/mcp-catalog -o /tmp/mcp-catalog.json
python3 -c "import json;d=json.load(open('/tmp/mcp-catalog.json'));print(d.get('routing') or d)"
# 拿到 routing 后，带 token 发 tools/list：
curl -sS -X POST "$ROUTING_URL" -H "Authorization: Bearer $CUE_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

- **原文腿**：年报的合并所有者权益变动表、附注·利润分配与所有者投入走数据腿；该域是否开放、是否实时，以 catalog 返回为准，本件不承诺。
- **正文腿**：权益变动表常是任意页幅的横排大表（十几列、跨页），截图与扫描件交 `cue-omni-reader` 解析——先取大纲，再按节取用；计费与可用性以服务端返回为准。
- **深研**：`cue-research` 是独立入口（自带运行脚本），凭据同一把 key。
- 配置页只给指针、不复述开通步骤：数据腿 <https://cuecue.cn/hub/mcp>；解析腿 <https://cuecue.cn/hub/omni-reader>；取 key <https://cuecue.cn/hub/api-key>。

不装通道也能跑：只拿用户直供的表截图或附注段，七节骨架照样出，代价是横排大表在截图里常缺列，缺列的那几行只能记「未取到」，行列轧平与勾稽可能一项都判不了——机检会明说判了几项。

本件不发请求、不代付费，消耗以服务端返回为准。

## 五、本件不做什么

| 不做 | 谁来做／怎么办 |
|---|---|
| 反推本期增减（上期比例外推／资产负债表差额倒轧） | 只认表内三项原句；缺的写「未取到：」 |
| 把未分配利润说成可分现金、算可派现能力 | 分红方案看公告；能力判断一律 `[待人工]` |
| 评价股东回报是否丰厚、分红是否慷慨 | 一律 `[待人工]`；本件不构成投资建议 |
| 其他综合收益的税后净额明细与重分类去向 | `cn-other-comprehensive-income-cn` 管；本件只取它的税后净额做勾稽① |
| 基本与稀释每股收益、加权平均股数 | `cn-eps-cn` 管；本件不推每股影响 |
| 其他权益工具的条款、利息股利处理与分类依据 | `cn-other-equity-instruments-cn` 管；本件只照抄它在权益变动表里占的那几列 |
| 会计政策变更的性质、追溯调整与累积影响 | `cn-accounting-policy-change-cn` 管；本件只登记追溯调整落在表里的数 |
| 给评级、目标价、目标市值、高低估 | 一律 `[待人工]` |

## 六、和另外几枚包怎么分

| 你手上是 | 用哪枚 |
|---|---|
| 权益变动总览、本期增减五项、利润分配与所有者投入、期末勾稽、归母与少数股东 | **本件** |
| 其他综合收益的概况、税后净额三数、重分类、归属 | `cn-other-comprehensive-income-cn` |
| 基本与稀释每股收益、加权平均股数 | `cn-eps-cn` |
| 其他权益工具（永续债／优先股）的条款与分类 | `cn-other-equity-instruments-cn` |
| 会计政策变更的性质与依据、追溯调整与累积影响 | `cn-accounting-policy-change-cn` |
| 递延所得税的确认、计量与转回 | `cn-deferred-tax-cn` |

本件管**所有者权益变动表这一张表**：勾稽① 用到的其他综合收益税后净额只照抄，明细与重分类归 `cn-other-comprehensive-income-cn`；权益变动表里「其他权益工具」那一列的金额只照抄，条款与分类归 `cn-other-equity-instruments-cn`；追溯调整引起的期初余额变化本件只登记，变更性质归 `cn-accounting-policy-change-cn`。同一家公司既要做权益变动又要做其他综合收益时，两件各管各的表，不互相代填。
