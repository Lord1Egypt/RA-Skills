# 怎么量、怎么让用户看见

用户不会因为"我优化了配置"而满意，只会因为"同样的活儿，账单变少了"而满意。所以瘦身必须留下三个可复算的数：**每轮常驻、单次加载、磁盘**，并且前后用同一口径。

## 1. 三个数，三本账

| 数 | 含义 | 怎么来 | 能不能说"省了" |
| --- | --- | --- | --- |
| 每轮常驻 | 每开一次对话就发出的固定部分 | 逐块字符数 × 系数，或用量面板的同类任务基线 | 能，但要说清是估算还是实测 |
| 单次加载 | 触发某技能/文档时才发出的部分 | 该文件字符数 × 触发频率 | 只有确实不再加载才算 |
| 磁盘 | 会话、备份、缓存、日志 | `du`、文件计数 | 只算磁盘，永不算 Token |

三本账不能相加。把"清了 600 MB 日志"写成"省了 token"是最常见的口径事故。

## 2. 测常驻：不依赖宿主也能做

按块统计字符数，同一口径算两遍：

```sh
# 逐块统计（换成你自己的常驻文件）
for f in <rule-file> <memory-file> <identity-files...>; do
  printf "%-40s %s\n" "$f" "$(wc -m < "$f" | tr -d ' ')"
done
```

系数约定：中英混排约 `0.6 token/字符`，纯英文约 `0.25`，纯中文约 `0.7`。**同一份报告只能用一个系数**，否则前后不可比。写清楚：`估算值，非账单实测`。

技能清单也要算：所有技能的 `name + description + 触发词` 加起来，往往比规则文件还大。

## 3. 测真实收益：同类任务对比

有账单或用量面板时，这是最有说服力的证据：

1. 选 3 个**同类**任务（复杂度相近，别拿"改个错字"对比"重构一个模块"）。
2. 改动前各跑一次，记录 input tokens。
3. 改动后同样任务再跑一次，记录 input tokens。
4. 取三次均值做差，而不是拿单次峰值对比单次谷值。

差异应接近"每轮常驻的减少量"，如果差得远，说明还有别的变量（上下文长度、工具返回体积）在影响，如实写出来。

## 4. 换算成用户能感知的量

只写"省了 5,824 token/轮"没人有感觉。补一层换算，但**公式给出来，数字让用户自己代入**，不要替他假设单价：

```
每月节省 ≈ 每轮节省 × 每天轮次 × 30
每月费用节省 ≈ 每月节省 ÷ 1,000,000 × 你的输入单价
```

示例写法（数字仅为示例，须替换成实测）：

> 每轮常驻从 11,699 降到 5,875（-50%）。按每天 40 轮计，每天少发约 23 万 token，
> 一个月约 700 万。按你的输入单价折算即可得金额；此处不代填单价。

## 5. 报告模板

一次瘦身结束，用户至少要看到这张表（示意：只取四块，不是全量）：

| 块 | 改前 | 改后 | 省 | 手法 |
| --- | ---: | ---: | ---: | --- |
| 常驻规则 | 1,075 | 284 | 791 | 压缩 |
| 记忆文件 | 4,834 | 1,327 | 3,507 | 外移留指针 |
| 技能清单 | 3,334 | 2,872 | 462 | 压描述 + 去重名 |
| 工具清单 | 2,741 | 2,255 | 486 | 裁剪暴露面 |
| **合计** | **11,984** | **6,738** | **5,246** | — |

下面必须跟三行口径声明：

- 单位与算法：`字符数 × 0.6`，静态估算，非账单实测
- 时点：改动前后的具体日期
- 未计入：哪些块没测、哪些收益不确定（如 Warm 层）

磁盘另起一张表，别混进这张。

## 6. 证明"体验没变"的四项

省 Token 不能用能力换。四项证据缺一不可：

1. **触发词全量核对**：改前导出所有技能的触发词，改后逐条检查仍在。丢一个就是一条路由断掉。
2. **引用可解析**：被移动的文件在新位置仍能被引用到，路由表里有入口。
3. **结构可解析**：frontmatter 闭合、必填字段齐全、JSON 可解析。
4. **抽样任务可用**：挑 3–5 个最常用的真实任务跑一遍，输出结构不变。

再加一条兜底：**每项改动的回滚位置**。用户不信"不会出问题"，只信"出问题能一键回去"。

## 7. 口径纪律

- `measured` 只能用现有计量工具或日志读数，注明时间窗口。
- `estimated` 必须写算法；不能和 `measured` 相加成一个"实测值"。
- `unknown` 单独列出，不并入总收益。
- 门槛不过就写"未达成"，不写"基本达成"。
- 复跑同一命令应得到同一个数；对不上就说明有变量没控制住，先查再报。

已验证的完整算例（含逐块数字与复算命令）见 `references/case-workbuddy.md` 第 3 节。
