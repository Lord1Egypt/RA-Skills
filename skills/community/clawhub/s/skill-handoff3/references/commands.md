# 命令与触发词规范

五个动作的**调用形式、触发词与触发边界**的权威定义，供 SKILL.md 的 `description` 指针引用。行为细节与副作用见 [SKILL.md](../SKILL.md) §3；更新记忆流程见 §3.3；自检六步见 [selfcheck.md](selfcheck.md)。

## 1. 触发总原则

1. 每轮记忆**常驻、不需触发**（写在 SKILL.md 的 `description` 里，模型每轮都做）。`$LIB/handoff_patches.md` 的判据句对所有五个动作与每轮记忆都生效（存在才读、无则跳过；判据句本身不是独立动作）。
2. 五个动作**命中才额外执行**；未命中任何动作 = 纯记忆轮，只碰自己会话的 `mem_` 文件。
3. 裸调用 `/handoff3`（不带触发词）= **交接**，是唯一写报告的动作。
4. 「基于记忆」**必须带 `/handoff3` 前缀**；裸说不触发。
5. `/handoff3 <触发词>` 以触发词为准，不走完整交接。
6. 宽泛词「生成 / 报告 / 文档」按字面也算交接（用户已接受误触发）。

## 2. 规范命令表

| 动作 | 调用形式 | 触发词（中） | 触发词（英） | `/handoff3` 前缀 | 行为一句话 | 详规 |
|---|---|---|---|---|---|---|
| ① 交接 | `/handoff3`（裸） | 交接 / 生成 / 报告 / 文档 / 归档 / 上下文接不上 / 重建视图 / 重建记忆汇总 / 刷新全量记忆 / handoff | handoff / handover / wrap up / report / archive / lost context / rebuild | 否（裸即交接） | **含自检六步** → 补缺口 → 重建视图 → 出报告，唯一写报告的动作 | SKILL.md §5 |
| ② 更新记忆 | `更新记忆` 或 `/handoff3 更新记忆` | 更新记忆 / 刷新本会话记忆 / 补全记忆 / 同步记忆 / 修复落款 | update memory / refresh memory / sync memory | 否 | **只读写当前会话自己那一个 `mem_` 文件**：缺失则建、漏记则补、结构问题就地修；不读别的文件、不跑自检六步、不重建视图、不出报告。用于落款失效、怀疑本会话文件有问题或缺失 | SKILL.md §3.3 |
| ③ 自检 | `自检` 或 `/handoff3 自检` | 自检 / 检查记忆 / 记忆体检 / 修复记忆文件 | self-check / check memory / memory check / memory repair | 否 | 六步体检并修复自己会话的 `mem_` 文件，只体检不出报告（交接已含，日常不必单独发） | selfcheck.md |
| ④ 基于记忆 | `/handoff3 基于记忆 [想说的话]` | 基于记忆 / 按记忆 / 根据记忆 | from memory / based on memory | **是** | 刷新视图后读它作答，不写报告 | SKILL.md §3 |
| ⑤ 帮助 | `帮助` 或 `/handoff3 帮助` | 帮助 | help | 否 | 按固定文本列用法，不读写文件 | SKILL.md §3.1 |

> 表中为**精确词表**；宽泛词（生成 / 报告 / 文档）的误触发见 §1 第 6 条。帮助文本按用户该条消息语言输出，命令清单不含「帮助」本身。

## 3. 纯记忆轮边界

未命中 §2 任何动作时：只碰自己会话的 `mem_` 文件，绝不读写 `handoff_report.md`、不重建 `handoff_memory.md`；不因「换了窗口」「发了个继续」「视图落后于报告」自作主张刷产物。
