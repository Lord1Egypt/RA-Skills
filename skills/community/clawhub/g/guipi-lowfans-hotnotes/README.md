# 小红书低粉爆款数据获取

## 目录定位

本仓库是「小红书低粉爆款数据获取」技能的发布副本，与 WorkBuddy 技能目录
（`.workbuddy/skills/` 下的同名技能）保持同步。通用客户端形态：不绑定任何
自有服务品牌，任何兼容 liuchuan-data 协议的服务均可作为数据源。

## 文件清单

| 文件 | 定位 |
|---|---|
| `SKILL.md` | 技能定义：一次性问卷（6 问一轮抛完）的强制流程、31 个官方一级分类、参数与配额说明、调用方式、已知边界、故障处理 |
| `fetch_notes.py` | 执行脚本：单文件，仅依赖 requests；一次性问卷（`--menu`）、定位候选（`--position --plan`）、服务端类目/正文过滤、增量缓存、单文件 HTML 看板（标签可点筛） |
| `README.md` | 本文件，目录定位与机制说明 |

## 核心机制

领域检索不再用自造词库，全部走**灰豚官方笔记分类树**：

- `--category`：服务端 SQL 按 cidP 过滤，父类自动覆盖全部子树，支持逗号分隔多类目 OR
- `--position` + `--plan`：把「穿搭 / 搞钱 / 带娃」这类定位词映射到官方类目，输出编号候选（零配额）
- `--body-keyword`：服务端正文 desc_text 包含匹配，逗号分隔多词 OR，字面匹配
- 组合语义：`(category OR domain) AND keyword`，三层可叠加

采集侧已按官方树 31 个一级分类补采，12h 类目覆盖率约 74%，
补采维度覆盖 12h / yesterday / 3d / 7d（24h 上游异常，不补）。

## 准入档位与配额

| 档位 | 单次 | 每天 | 限速 | 不可用 |
|---|---|---|---|---|
| 匿名体验（不传 Key，按 IP + X-Client-Id 双轨） | 5 条 | 10 条 | 1 请求/3 分钟 | trend / authors；**脚本 UA 一律 429** |
| 试用 Key | 20 条 | 1000 条 | 1 请求/分钟 | — |
| 永久 Key | 200 条 | 不限 | 1 请求/分钟 | — |

**无 Key 取不到数**：服务端匿名档对脚本 UA 一律 429（风控设计，不是故障）。
本技能无 Key 时直接退出并给配 Key 指引，不发那次注定失败的请求。

配额按**接口实际返回的条数**扣费：服务端类目/正文过滤后返回几条扣几条，零命中零扣费；
配额不足时按剩余额度做**部分交付**（返回 N 条，而不是整请求 429）。
响应头 `X-Quota-Remaining-Notes` 每次回报当日剩余条数，终端汇总行显示 `剩余=N条`。
单次请求上限 20 条，所以 40 条 = 2 次请求，1000 条 = 50 次请求（约 52 分钟，页间隔 62 秒）。

## 交互方式：一次性问卷（6 问一轮答完）

`--menu` 零配额打印完整问卷，agent 原样贴给用户，**所有问题一次列完**，
用户一轮回齐编号（`1-19 2-1 3-1 4-2 5-1 6-1`），agent 提炼成参数后直接取数：

- 问题 1 类别：1-31 + 32 其他（编号 = 官方一级分类树序，从 `TOP_CATEGORIES`
  常量输出，与 `--list-categories` 完全对齐）；选「其他」→ `--position --plan`
  零配额出候选，确认后再 `--category`
- 问题 2 时间维度 1-5（无其他）：12h 默认 / 24h（上游异常）/ yesterday / 3d / 7d
- 问题 3 采样方式 1-4（无其他）：点赞+收藏（扣 40）/ 只点赞（扣 20）/
  只收藏（扣 20）/ 三榜（扣 60）
- 问题 4 取数规模 1-3 + 4 其他（自定义条数，≤1000）：20 / 40 / 1000
- 问题 5 附加过滤 1-4 + 5 其他（自定义阈值）：不过滤 / 点赞≥1000 / 粉丝≤1000 / 两者
- 问题 6 内容类型 1-3（无其他）：全部 / 只要视频 / 只要图文

带「其他」的项**先追问补齐再取数**，补齐前不发 `/notes` 请求（零扣配额）。
类别编号 → 类目名由 agent 换算（`--category` 认名称或 ID），时间编号 → 维度由脚本直接认
（`--time-range 3`）；问卷与脚本同源，不会串号。

**每题都有推荐项**：`--menu` 会给每题标一个 `← ★ 推荐（来源）`，用户回
「推荐 / 默认」就按星号走。推荐来源按优先级取「已固定人设 → 上次成功取数
（`last_run.json`，自动记录）→ 脚本默认」；冷启动没有类目数据时，第 1 题推荐
「32 其他」，提示用户描述方向。

## 固定人设

第一次交付完，agent 用 `interaction_ask` 只问一题「要不要把这次的人设定位固定
下来？」——固定后下次做低粉爆款只需回「沿用」，不必再描述定位。

- `--save-profile --category … --position …`：把本次的类目、定位词、正文词、
 时间维度、采样、规模、过滤阈值、类型整套写进 `profile.json`（配置目录）
  （零配额、不取数）
- `--show-profile` 查看当前人设，`--forget-profile` 取消固定
- 固定后 `--menu` 顶部打印人设，问题 1 多出 `0. 沿用已固定人设`，各题 ★ 也按
  人设参数标；用户回 `0`/「沿用/老样子」就直接按人设取数
- 换定位：按新参数取数后再 `--save-profile` 覆盖；不想要了就 `--forget-profile`

## HTML 看板的实现方式

`render_html()` 在脚本内渲染单文件页面：内联 CSS、无外部 JS；
头部元信息 + 4 个 KPI（命中条数/平均点赞/粉丝中位数/最高点赞）+ 标签热度 Top 8
条形图 + 卡片墙（封面 3:4、名次角标、标题、作者粉丝、赞藏评转、类目徽标、
`打开笔记 ↗`）。封面直连小红书 CDN，失败由渐变底色兜底；空结果出空态页。
默认输出 `低粉爆款_<类目>_<维度>.html`，可用 `--html` 指定、`--no-html` 关闭。
封面用 `loading="eager" decoding="async"`。
卡片可点开站内预览浮层，底栏与浮层都有「复制」按钮。
视频条目有 `video_url`（mp4 直链）时，浮层左侧直接换成 `<video controls>` 播放器
（poster 用 720 宽封面），关闭浮层即 `pause` + 清 `src`；播不了自动退回封面，
右侧「播放视频 ↗」仍可手动打开。视频卡封面正中带 ▶ 圆标，定位解析卡会写
「视频直链 N/M 条可站内播放」——直链随采集持续回填。

**排序条**：卡片墙上方有 `默认顺序 ｜ 点赞 ｜ 收藏 ｜ 评论 ｜ 转发 ｜ 降序 ↓/升序 ↑`。
卡片带 `data-like/collect/comment/share/rank/seq` 读数，点指标按该指标降序重排、点方向按钮
切升序、点「默认顺序」回到榜单原序；只重排 DOM 不重新取数（零配额），与内容类型、
标签筛选叠加生效，当前排序会写进筛选状态行。

**主题筛选**：选项不写死
——先跑 `--tag-report` 看本期样本（标签频次 + 逐条「标题｜标签｜正文前 70 字」，零配额），
agent 从标题、正文、标签三处提炼主题组，有几个算几个（不限组数），再用
`--tag-groups "主题=词a,词b;…"` 重渲染（缓存命中、零配额）；组内词会同时比对该条
的标签、标题、正文。

每次真实取数都会把主题组和原始标签**增量并进** `theme_cache.json`（缓存目录）
（按类目分 scope；组内词只增不减、老组永不丢、同一批重渲染不重复计数）。看板因此
会列出该类目**累计的全部主题组**，加上「未被任何主题覆盖且本批出现 ≥2 次」的高频
单标签（最多 60 个），按**本批命中 → 历史累计**排序；本批 0 命中的主题仍保留但暗显。
看板上标签热度条、主题胶囊、卡片/浮层里的标签都点一下即可加入多选，默认「任一命中」，
可切「匹配：全部」；样本里没 tags 的条目有独立「无标签」胶囊。类型与主题双向分面计数。
胶囊**超过 3 行**时默认只露 3 行（底部渐隐），旁边出现「展开全部（共 N 行）」，点开
铺满、「收起主题」折回；行数按实际排版量（`offsetTop`），窗口变化会重新量。
`--clear-cache` 会把主题缓存一起清掉，下次重新积累。

**筛选时间 + 获取时间**：卡片右上/底栏带「获取 HH:MM」
小徽标（本期写「本次 …」），看板顶部时间条为
`今天 ｜ 昨天 ｜ 近1周 ｜ 近1个月 ｜ 近3个月 ｜ 自定义时间`，每枚带实时条数；点
「自定义时间」用旁边两个日期框指定起止（起止颠倒自动对调）。每次真实取数都会往
`history/`（缓存目录下）落一份快照（`notes_...__YYMMDD_HHMM.json`），
这些窗口能筛出本地缓存过的历史批次。默认看「今天」，隔天才打开且今天
为空时自动退到覆盖全部批次的自定义区间；历史条目只做参照——结论块与 KPI 仍只算当期，
避免命中率被撑爆；`--no-history` 可关历史池。要清掉本地样本：
`python fetch_notes.py --clear-cache`（删 `notes_*.json`、历史快照与主题缓存，保留额度快照与
预览服务状态）。

## 缓存和配置位置

缓存不放在技能目录里，而是放在**用户级目录**，同一台机器上任意对话、任意技能副本
（工作区 / D 盘同步副本）共用同一份；升级技能不会丢，也不会把数据打包分发出去。

- **数据缓存**（可丢、量大）：`%LOCALAPPDATA%\liuchuan-data\cache`
  （mac/Linux `~/.cache/liuchuan-data/cache`）——`notes_*.json`、`history/`、
  `theme_cache.json`、`quota.json`、`serve.json`
- **配置 / 人设**（该留、量小）：`%APPDATA%\liuchuan-data\config`
  （mac/Linux `~/.config/liuchuan-data/config`）——`profile.json`、`last_run.json`

**默认 + 可改**：默认路径开箱即用，不弹选择；想换就 `--set-cache-dir "<目录>"`
（把现有缓存复制过去 + 写指针，永久生效），`--show-paths` 随时看当前路径和文件数
（两者都零配额）。优先级：`--cache-dir` / `--config-dir`（本次）> 环境变量
`LIUCHUAN_CACHE_DIR` / `LIUCHUAN_CONFIG_DIR` > 指针文件 > 平台默认。

**默认全量保留**：不做按时间/体积的自动淘汰，跑过的批次都留着；只复制不删除。
要清必须显式 `--clear-cache`（清 notes + history + theme，保留 quota / serve / profile）。

## 预览地址（http 直开）

出完 HTML 后脚本自动在文件所在目录起一个 `python -m http.server`（只绑
`127.0.0.1`，端口 8777 起挑空闲，同目录复用，状态存
`serve.json`（缓存目录）），`【结论】` 末尾打印
`预览地址：http://127.0.0.1:8777/低粉爆款_情感_12h.html`，可直接点开或粘进浏览器。

- 该服务只是把本地文件用 http 发出来，**HTML 仍只在本机，没有上传到服务器**
- `--serve-port 8899` 换端口；`--no-serve` 不起服务；`--stop-serve` 停掉已起的服务

## 数据来源

本地采集器按官方分类补采灰豚低粉爆文榜（12h/24h/昨日/3d/7d 五维度）推送至服务器，
经公网只读 API 输出——端点为环境变量 `LIUCHUAN_BASE_URL`（未配置时脚本保持占位符
且不发请求）。通用客户端形态：任何兼容 liuchuan-data 协议的服务（自建或第三方）
均可作为数据源。缓存默认目录与 Key 变量见上一节。

## 使用前提

**必须有 Key**：服务端匿名档会被 UA 闸门拦（脚本必 429），本技能无 Key 时直接退出并给指引。
Key 由运营方发放（支持 `key|YYYY-MM-DD` 时效格式），配置见 SKILL.md 第 4 节，
建议写用户级环境变量 `LIUCHUAN_API_KEY`。

只读能力仍免 Key：`--menu` / `--list-categories` / `--plan`（纯本地或公开端点，零配额）。
取数前会打公开 `/meta` 探活；入库超过 15 分钟会在 stderr 提醒「数据可能不是最新的」
（采集端停摆时能第一时间发现，而不是把旧榜当新榜）。
