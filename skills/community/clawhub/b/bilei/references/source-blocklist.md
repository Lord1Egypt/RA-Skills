# 信源黑名单（随技能分发）

## 说明

- 本文件随技能一起发布，**用户安装后即精确生效**，无需任何额外操作。
- 维护方式：直接编辑本文件 → 推送 GitHub → CI 自动 patch 版本号 +1 并发布。名单变更也是一次版本发布，不用手动改版本号。
- **绝对禁止搜索、命中即禁**：检索阶段就把这些站排除在候选信源之外（搜索结果里出现也直接跳过，不点开、不引用），不作证据、不作线索，无例外、无时间门槛、不分级。
- 用户自己的补充名单在技能目录之外：`~/.bilei/user-blocklist.md`，更新技能不丢。两份名单合并执行，用户名单里的 A 类 / B 类一律都按「禁止引用」处理。
- 查命中：`python3 scripts/custom_blocklist.py check <域名>`。名单缺失时回落到 `source-credibility.md` 的证据分级与特征判定。
- **举一反三**：名单是底线不是上限。凡命中下方「判据」的站点（软广水军、洗稿搬运、无署名通稿、只发软文不发布实测的门户媒体），即使不在名单里，也按黑名单处理。**判据要逐条验，不许凭来源类型一刀切。**

## 「举一反三」怎么判（判据，不是口号）

命中**任意两条**才算命中，一条不判：

| 判据 | 怎么验 |
|---|---|
| 只有通稿，没有实测 | 打开近 10 篇，是否全无测试条件、仪器、原始数据、拆解照片 |
| 无署名或署名不可核验 | 作者查不到历史发文、查不到自购过程 |
| 批量同文 | 同一段文字在 3 个以上域名出现 |
| 返利闭环 | 正文带购买链接且指向返利，利益冲突未声明 |

**不得误伤（反向铁律）**：

- 判的是**单篇文章**，不是整个平台。B 站 / 小红书 / 贴吧本身是 L4 用户反馈的合法来源，只有具体那篇命中判据才弃用——平台里有真实自购实测，也有水军，不能因为平台被点名就整站倒掉。名单里明确列出的站（如知乎 / 什么值得买）按名单执行，但**名单之外的同类平台必须逐篇验**。
- 命中判据却贴出了可回溯的原始实测数据 → 按「利益冲突只削评价层，不削事实层」处理：弃它的结论，保留它的拆解照片、物料清单、实测数值。
- **拿不准就提高举证门槛、另找 L2/L3 交叉验证，不许靠感觉定罪，也不许因为可疑就当清白。**

## A 类 · 禁用（黑名单，绝对禁止搜索、命中即禁止引用）

|---|---|---|

## 信息获取原则（重要）

- **以社区真实信息为主**：优先采信有署名、有自购 / 实测过程、可回溯原始出处的专业社区反馈与用户实测。
- **排除单向软文站**：只发厂商通稿、软文、没有实测方法与数据的门户 / 媒体，一律不作信源——不管它表面上多「专业」。
- 名单是硬底线；同类站点按上方「举一反三」的特征识别同步排除，不必等名单更新。

## 边界

- **慢慢买** `manmanbuy.com`：价格事实层可用（价格曲线），不提供品质评价；历史好价以此为准。
- 命中黑名单的来源一律禁止引用，不因「贴出原始证据」等理由恢复采信。
- 全网仅有黑名单来源在讨论某品类时 → 第一屏写明「该品类缺乏可用信源」，按「目前没有」处理，不凑数推荐。
