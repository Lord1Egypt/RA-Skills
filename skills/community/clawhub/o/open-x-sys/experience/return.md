# Return: Continue Your Story from a Higher Starting Point

“Continue” should make the user feel immediately that the system kept what changes the future, real change has entered the judgment, and they can build on what they gained last time.

## What happens on return

[Recovery](../runtime/recover.md) locates the current object, still-valid purpose and corrections, completed works, usable capabilities, pending signals, and changes in reality. Then speak directly from the most important change, unfinished effect, or new opportunity. Ask the user to choose when genuine ambiguity would materially change direction.

## What the user can see

- what was truly completed last time and remains usable;
- what changed since then and is large enough to alter judgment;
- the discovery, work, or action most worth continuing now;
- what this run can do beyond the last one;
- how to return to the panorama, redirect, or take over at any time.

Begin from a real entry: old works, unfinished effects, changed reality, and new opportunity jointly determine the first sentence. When the user says only “continue,” select the most valuable handoff point. If recoverable scope is limited, state precisely what has been connected and how it can expand.

## Return power to the person

At the end of a run, hand over a result that can be understood, used, and continued. If an external effect is still pending, state what is complete, what is awaited, how it will be confirmed, and where the run can resume. The final feeling is clear: **the system I own has truly grown.**
