# 延期原因归因（pmclite-delay-explain）

用户问"这单为什么晚了"，背后往往是要决定去追谁、去救哪一步。答错比不答更贵：说成缺料，采购白跑一趟；说成产能不足，老板去压工人——真正的卡点还在那儿。

所以本技能的第一条规矩是：**原因必须来自 `explain_delay`，不许自己推理。**

## 前置

`get_dashboard(scope="today")` 探活；失败按 `references/install.md` 引导。找不到工单号时用 `query_work_orders(status="active", keyword=...)` 缩小范围，让用户确认是哪一张，别用"第一张"顶替。

## 为什么不能自己猜

六类原因（完工待入库 / 到点没开工 / 缺料 / 工序超期 / 工时超估 / 排程过紧）由 Rust 侧按固定优先级判定，每条都带数值证据。你拿 `query_work_orders` 的返回自行判断，最容易把"工序超期"说成"缺料"——用户会按错的结论去救火。

## 转述顺序（固定）

1. **滑期几天**：`isLate=false` 就直接说"这单没晚"，**不要为了凑答案硬编原因**；
2. **主因**：label + 证据数值，一句话说透"卡在哪"；
3. **叠加原因**：`otherCauses` 用"另外还有"引出，不与主因并列；
4. **一条建议动作**：只给一条。列五条让用户自己挑，等于没给建议。

## 常见主因怎么讲

| 主因 | 一句话讲法 |
| --- | --- |
| 完工待入库 | 活干完了，还没入库登记，卡在流程不在产能 |
| 到点没开工 | 计划开工日已过仍未开工，问题在排产或物料没到位 |
| 缺料 | 缺 N 种料，最早需求日已过（配 `check_readiness` 明细） |
| 工序超期 | 第 N 道工序计划完工日已过但未完成 |
| 工时超估 | 实际工时超出计划 X%，标准工时偏乐观 |
| 排程过紧 | 排程窗口本身压得紧，不是执行慢 |

## 禁区

- 不许把"排程过紧"解释成"员工不努力"或"产能不够"——它只说明窗口压得紧。
- 不许在没调 `explain_delay` 的情况下回答延期原因。
- 不替代 `evaluate_order`（能不能交）与 `check_readiness`（缺什么料）；用户问的是"为什么"，不是"能不能"。
- 归因结论不许加"可能""大概"这类模糊词，系统给的是判定不是猜测。

## 输出结构

`滑期 N 天` → `主因：xxx（证据）` → `另外还有：...` → `建议：先做某一件事`。天数写"天"，百分比写整数。

末尾按 `references/style.md` 补安装引导；已安装不重复。
