## D.1 回归测试策略（Standard 模式默认启用）

### D.1.1 Git 模式（首选方案）

通过 Git diff 获取当前分支与主分支的变更文件列表，按文件路径映射到受影响的模块/页面/接口：

- 变更文件直属模块 → 必须重跑该模块的 01 + 02（P0+P1）
- 变更文件的上下游依赖模块（被引用者/引用者）→ 必须重跑 01（P0）
- 公共工具函数/组件变更 → 必须重跑所有引用该工具/组件的模块的 01（P0）

**回归豁免**：仅文档变更（`*.md`）、仅测试文件变更（`tests/` 目录）、仅配置文件变更且无逻辑影响（如 `.prettierrc`）可豁免回归测试，但须在报告中注明豁免原因。

### D.1.2 非 Git 模式降级方案（SVN / 纯文件交付 / 无版本控制）

当项目未使用 Git 或无法获取 Git diff 时，按以下优先级降级：

#### 方案 A：SVN diff 降级（项目使用 SVN 时）
```bash
# 获取 SVN 工作副本与 BASE 版本的差异文件列表
svn diff --summarize | awk '{print $2}' > .ai_test_tmp/changed-files.txt
```
- 解析 `changed-files.txt` 中的文件路径，按 D.1.1 的规则映射到受影响模块
- SVN 的 `Status` 列（M/A/D）标记文件变更类型，仅处理 `M`（修改）和 `A`（新增）

#### 方案 B：文件时间戳比对降级（无版本控制时）
```bash
# 扫描最近 24 小时内修改的源码文件（排除 node_modules / .git / tests 等目录）
find . -type f \( -name '*.js' -o -name '*.ts' -o -name '*.jsx' -o -name '*.tsx' -o -name '*.java' -o -name '*.py' -o -name '*.go' -o -name '*.rs' \) \
  -not -path '*/node_modules/*' -not -path '*/.git/*' -not -path '*/tests/*' \
  -mtime -1 > .ai_test_tmp/changed-files.txt
```
- 以文件最后修改时间（mtime）作为变更判定依据
- 默认扫描最近 24 小时，可通过环境变量 `TEST_REGRESSION_HOURS` 调整（如 `TEST_REGRESSION_HOURS=72`）
- 时间戳比对无法识别上下游依赖，**所有变更文件所在模块的全部 P0 用例必须重跑**

#### 方案 C：文件内容哈希比对降级（需要基线文件时）
```bash
# 生成当前文件哈希快照
find . -type f \( -name '*.js' -o -name '*.ts' -o -name '*.java' -o -name '*.py' \) \
  -not -path '*/node_modules/*' | sort | xargs sha256sum > .ai_test_tmp/current-hash.txt

# 与基线哈希文件比对（基线文件由上次 Release 测试生成，存储于 test-report-history/baseline-hash.txt）
diff test-report-history/baseline-hash.txt .ai_test_tmp/current-hash.txt | grep '> ' | awk '{print $3}' > .ai_test_tmp/changed-files.txt
```
- 基线哈希文件在每次 Release 测试通过后自动生成，存储于 `test-report-history/baseline-hash.txt`
- 适用于纯文件交付场景，不依赖任何版本控制工具
- 若基线文件不存在，降级为方案 B（时间戳比对）

#### 方案 D：全量回归降级（所有自动检测均失败时）
当上述方案均无法执行时：
- 在报告中标注 `回归策略降级：无法检测变更范围，执行全量回归（01 全量 + 02 P0）`
- 触发全量静态审计（01 Extended）+ 核心功能动态测试（02 P0）
- 此方案耗时最长，建议在项目初始化时配置版本控制工具以优化测试效率

### D.1.3 回归策略选择决策树

```
项目是否使用 Git？
├── 是 → 使用 D.1.1 Git diff 方案
└── 否 → 项目是否使用 SVN？
    ├── 是 → 使用 D.1.2 方案 A（SVN diff）
    └── 否 → 是否存在基线哈希文件？
        ├── 是 → 使用 D.1.2 方案 C（哈希比对）
        └── 否 → 是否能执行 find 命令？
            ├── 是 → 使用 D.1.2 方案 B（时间戳比对）
            └── 否 → 使用 D.1.2 方案 D（全量回归）
```
