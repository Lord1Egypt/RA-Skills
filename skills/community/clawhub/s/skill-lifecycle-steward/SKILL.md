# Skill Lifecycle Steward · 技能生命周期管家

## Overview

把"选技能"与"管技能"合并到一处处理，形成从发现到安装再到维护的闭环。所有路径共用一套安全铁律，在任何工具间切换前先完成现状收集与影响面确认。

## 意图路由（先读这里）

根据用户说法选择路径；一次请求可串联多条，按 A → B → C 顺序推进。

| 用户意图 | 典型说法 | 路径 |
|---|---|---|
| 只有需求，不知用哪个技能 | "有没有能干 X 的 skill""推荐一个" | A 发现与评估 |
| 已选定，需要装上 | "装上它""启用 X" | B 安装与启用 |
| 查看现状 | "我装了哪些""X 有更新吗" | C1 查看状态 |
| 升级 | "升级 X" | C2 升级 |
| 卸载/清理 | "卸掉 X""清理不用的" | C3 卸载与清理 |
| 改已装技能 | "把 X 改成…" | C4 编辑 |

命中路径后先确认前置条件是否就绪，再进入具体步骤。

## 铁律（所有路径通用）

1. 按"只读收集现状 → 列出影响面 → 取得确认 → 执行 → 输出变更清单"推进。写操作前必须确认。
2. 不可逆操作（卸载、删除、覆盖）先做备份或快照，并明确告知回滚方式。
3. 绝不擅自覆盖已有技能目录。安装前确认技能名称、来源与目标路径。
4. 凭据通过环境变量或密钥管理器注入，不落盘、不进版本控制。依赖缺失时停下报告，不索取明文凭据。
5. 候选命中危险信号时标注 ⚠️ 或降级，不静默推荐。只操作声明范围内的目标，不越权。
6. 命中率优先于省 token：先自有后外部、先本地后外网；外网单源加超时，卡死即跳过；命中私有技能直接置顶，省去后续评分。

---

## 路径 A：发现与评估

### A0. 理解需求

厘清三件事：领域、具体任务、该任务是否常见到大概率已有现成 skill。提取核心功能词，中英互译各试一次，并判断类别（开发工具 / 办公效率 / AI·ML / 系统 / 创意 / 数据 / 商业营销）。

### A1. 优先查自有技能（最高优先级）

在检索任何外部来源之前，先按需求关键词匹配用户已拥有或上传的技能，命中即置顶并标注「⭐ 你的私有技能（已拥有）」：

- 用户级：`~/.workbuddy/skills/*/SKILL.md`
- 项目级：`{workspace}/.workbuddy/skills/*/SKILL.md`（若有工作区）

匹配 `name` / `description` / `triggers` / 正文，中英关键词都试。只有未命中或不合适时才继续 A2。

### A2. 检索（先原生，外网仅补充）

**WorkBuddy 原生来源（主）：**
- `search_and_install_skills`——一句话搜索并安装，首选。
- 当前可用技能索引（Skill 工具提供的列表）——直接筛选，零网络依赖。
- 需求指向外部 App/服务或专家角色时，转连接器推荐 / 专家推荐。

**外网补充（可超时跳过）：**
- skills.sh 排行榜——看该领域是否已有高安装量头部技能。
- awesome-skills 列表——用 WebSearch/WebFetch 抓结构化目录。
- GitHub——搜 `<需求> skill`、`<需求> agent skill`，优先官方源。
- 单条外网请求加超时（如 `curl -m 10`），卡死即跳过，不阻塞整体。

### A3. 去重与合并

不同来源搜出同一 skill 时，按优先级保留最优记录：

| 优先级 | 来源 |
|---|---|
| 最高 | 用户自有/已上传技能 |
| 高 | WorkBuddy 官方内置精选 / 官方源 |
| 中 | 高安装量社区技能 |
| 低 | 其他列表 / 低星仓库 |

名称完全相同、名称高度相似、或同一作者多版本时，保留高优先级 / 最新版。

### A4. 质量与安全评估

按 `references/evaluation-guide.md` 的维度评级（🟢 强烈推荐 / 🟡 可用需核实 / 🔴 不推荐）。评级达到可推荐门槛后，按 `references/security-scan.md` 读取候选 `SKILL.md` 及将被执行的脚本做安全扫描；命中危险信号即降级或标注 ⚠️。

### A5. 输出推荐

按评级排序输出结构化列表（见「输出模板」）。每条含技能名、一句话用途、来源/安装量、评级、触发词、安装方式。自有技能命中时提示"已拥有，直接说需求即可触发"。

---

## 路径 B：安装与启用

1. 确认候选技能的名称与来源已获用户认可，并检查目标路径是否已有同名技能。
2. 若同名技能已存在，停下询问是覆盖、跳过还是换名，绝不擅自覆盖。
3. 安装方式：
   - 新技能用 `search_and_install_skills` 安装；或把 `SKILL.md` 写入用户级 `~/.workbuddy/skills/<name>/` 或项目级 `{workspace}/.workbuddy/skills/<name>/`。
   - 连接器/专家走对应建议卡，由用户授权。
4. 来自第三方市场的技能，执行前确认依赖就绪（账号已授权 / CLI 已安装 / 环境变量已设置）。
5. 安装后给出变更清单与验证方式（如何触发、如何确认生效），并提醒重开会话以刷新技能索引。

---

## 路径 C：管理与维护

### C1. 查看状态

以只读方式收集：已装技能列表、版本、更新状态。涉及第三方市场时可浏览市场检索可用技能。输出简洁清单，不改动任何内容。

### C2. 升级

列出将被升级的技能及其当前/目标版本，取得确认后执行。跨版本升级先做快照。

### C3. 卸载与清理

1. 列出将被卸载/删除的具体技能，说明影响面。
2. 备份或快照，明确告知回滚方式。
3. 取得用户明确确认后执行。
4. 输出变更清单。

### C4. 编辑已装技能

先读取现有 `SKILL.md` 及相关文件再改。若技能来自市场，保存编辑后在技能目录的市场元文件（`_skillhub_meta.json` 或 `_knot_meta.json`）中写入 `"userModified": true`，防止后续自动更新静默覆盖。本地新建的技能跳过此步。

## 串联示例

> 用户："帮我找个能处理 PDF 拆分的，装上，再看看有没有更新。"

1. 路由：A → B → C1/C2。
2. 执行 A：理解需求 → 查自有技能（无命中）→ 检索 → 评估 → 输出候选并请用户确认。
3. 确认后执行 B：检查同名 → 安装 → 给出触发方式与验证方法。
4. 执行 C1：查看已装状态与更新信息；若有可用更新，列出版本差异并在取得确认后走 C2。

## 找不到时怎么办

1. 明说"没找到现成技能"，不硬塞假阳性结果。
2. 按类型拆分现有方案（如 A 做文档、B 做网页、C 做视频）给出组合建议。
3. 明确标注能力缺口，并主动提议用技能创建能力（`skill-creator` / `skill-maker`）从零定制。

## 边界与降级

- 用户已知确切技能名与安装命令 → 直接执行，不绕路检索。
- 通用能力即可完成、不值得专门找 skill → 直接完成，不启动本流程。
- 需求是 MCP 服务器/连接器 → 转连接器推荐，不按 skill 包处理。
- `search_and_install_skills` 不可用 → 用可用技能索引筛选，并按 B3 手动写入 `SKILL.md` 到用户级/项目级。
- 外网不可达 → 忽略外网补充，仅用本地与内置结果照常输出，并说明检索范围受限。
