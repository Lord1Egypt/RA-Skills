# 需求问诊与候选筛选

本页定义"从用户随口一句话到一份可执行候选清单"的流程。核心原则：**先问清硬约束，再谈车型；预算与座位是不可突破的边界，不是参考值。**

## 一、两条入口

| 入口 | 用户表现 | 动作 |
|---|---|---|
| A 新手选车 | "预算 X 万，买什么好"、"家里五口人" | 走问诊流程，先收硬约束再出候选 |
| B 已锁定车型 | "C16 六座多少钱"、"C11 增程有没有热泵" | 直接查表回答，不强行问预算；但涉及"值不值""要不要加钱"时补问预算口径 |

## 二、三个硬约束（必须问清）

### 1. 预算

- 问：**裸车预算还是落地预算？是不是硬上限？**
- 裸车预算 → 直接与指导价（或已确认书面成交价）比。差 2,800 元也是超，不能说"差不多"。
- 落地预算 → **只算余额**：`余额 = 预算 − 裸车 − 购置税`，余额留给保险、上牌、选装、贷款费用。本库没有保险与上牌报价，所以只能说"余额约 X 元，需报价核验"，**不能断言"落地不超"或"肯定不够"**，也不要用拍出来的系数反推裸车上限。详见 [落地成本](purchase-cost.md)。
- **指导价超过预算的车型不得列为合格候选。** 用户主动说可以加预算，才作备选，并写明差额。
- 同一预算下比较两台车，用同一套税费假设。不能一边排除较便宜的、一边接受较贵的。

### 2. 充电条件

分四档问，不要只问"有没有家充"：

1. 固定车位能否装桩（产权／长租、物业是否同意）。
2. 单位能否稳定充电（价格、时段、是否常被占）。
3. 附近公共快充的距离、价格、排队情况。
4. 每周可用充电次数。

只有第 1 档为否、且 2–4 档都差时，纯电才是明显不利选项。**不能把"无家充"直接等同于"不能买纯电"。**

### 3. 乘员与座位

问：**经常几人出行、是否有儿童安全座椅、是否需要第三排。**

座位算术必须精确：

| 布局 | 座位数 | 说明 |
|---|---:|---|
| 五座（2+3） | 5 | 二排三人座 |
| 六座（2+2+2） | 6 | 二排两个独立座椅，中间有通道 |

**五座换六座，净增 1 个座位，不是 2 个。** 差别不能只讲座位数，要分四项讲：座位数、二排座椅形式（三人座 → 两个独立座椅）、第三排上下车通道、行李空间。

## 三、软条件（问诊第二轮，最多补三个）

城市与冬季气温、年行驶里程、长途频率与单程距离、停车位尺寸（是否机械车位）、是否置换、牌照与指标。

一次最多追问三个问题，不要连问十个。用户不答就按最常见情况给"分情况"答案，并注明假设。

## 四、候选筛选顺序

1. **砍掉超预算**：裸车口径下，指导价（或已确认书面成交价）> 上限的，全部剔除；落地口径下先算每台的"裸车+购置税"，余额为负或极小（不足保险量级）的不得称"可成交"，只能列为"需报价核验"。
2. **砍掉座位不够**：常坐人数 > 座位数，或被安全座椅占位后成人无位可坐的，剔除。需要 6 人 → 只剩 C16 六座。
3. **砍掉补能不可行**：四档充电条件全差且年里程高、长途频繁 → 纯电降权（不是剔除，是降权并说明）。
4. **剩余按场景排序**：长途多 → 增程；通勤为主 → 纯电；在意二排舒适 → 高配。
5. **输出 2–3 个候选**，每个都要有：为什么留、为什么不留其他的、还有什么待核验。

剔除理由必须写出来。用户看不到排除过程，就不知道自己被什么条件限制了。

## 五、选车卡（固定输出格式）

```
【已知条件】预算（口径+金额+是否硬上限）／乘员与座位／充电条件／里程与长途
【预算内候选】2–3 个版本，各一行：版本名、指导价、关键差异
【已排除】版本 + 一句理由（超预算 X 万／座位不够／补能不适配）
【预计成本】裸车 + 购置税（按公式）+「余额 = 预算 − 裸车 − 购置税」+ 保险上牌待报价，标明假设
【待核验】配置归属、优惠资格、充电桩可行性、试驾项目
```

## 六、体验类需求：先问功能，再谈硬件

"辅助驾驶好一点""空间大一点"都是**体验描述**，不能直接翻译成配置条件。把体验改写成硬件，会让候选集莫名其妙地缩小，用户还以为是被预算卡住了——这类错误最隐蔽，因为金额往往算得完全正确。

| 用户原话 | 不能直接推出 | 应该先问 | 确认后才可加的条件 |
|---|---|---|---|
| 辅助驾驶好一点 | 必须带激光雷达 | 主要在①高速领航 ②城区道路 ③泊车 哪个场景用；愿不愿意为硬件加钱；能否接受"功能交付状态未确认" | 用户明确说"必须带激光雷达" → 才可加 `require_lidar` |
| 长途多、要大空间 | 只看 C16 | 常坐几人、是否必须六座、行李或婴儿车体积、长途频次与沿途补能 | 用户明确说"只在 C16 里选"或"必须六座" → 才可加 `series` / `min_seats` |

三条规则：

1. **先给全系比较，再谈条件。** 用户没确认之前，按预算给全系候选；确认之后重算一遍，并明确说"因为你加了这条，去掉了哪几款"，让用户看得见代价。
2. **撤销条件要能回到基线。** 用户改口（"其实不要求激光雷达"）时，删掉该过滤重算，不在原结论上打补丁、不硬撑原来的推荐。
3. **不从硬件推体验。** 有激光雷达 ≠ 辅助驾驶更好用；座位多 ≠ 空间更大。体验类问题只给"试驾时验证什么"，不给排名、不给打分。

## 七、硬规则

- 不问预算就给推荐 = 违规。
- 用"可能优惠"让超预算车型进入候选 = 违规。
- 把五座六座差异说成"多两个座位" = 事实错误。
- 把"没有家充"当作纯电的唯一否决条件 = 判断过简。
- **把用户的体验描述（"辅助驾驶好一点""空间大"）直接翻译成硬件或车系筛选条件 = 擅自加条件，违规。**
- 把"高配已知有某配置"写成"多花的钱买到了该配置" = 证据不足（见 [差价](trim-deltas.md) 第 0 节）。
- 报"落地约 X 万"却不列保险费、上牌费假设 = 隐含结论，违规。
- 用户预算与需求无交集时（如 14 万裸车 + 必须六座），**直说无解**，给出最低可行预算差额，不擅自放宽条件。
