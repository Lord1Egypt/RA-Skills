# UI/UX 设计专家知识库

从「网站为什么好看」的根本原因出发的界面设计知识：**法则（约束性）→ 最佳实践（建设性）→ 坑点（防御性）** 三层结构。因果链排序：先人类感知/认知的底层硬约束（好看与可用的生理学根因），再设计系统层的构建纪律，最后流程与生成纪律。生成界面/代码前**逐条自检全局法则**（`kb/laws.md` Top 法则）；写代码前查 `kb/ai-mistakes.md` 与「Top 坑点」。

## Top 法则（生成界面前逐条自检）

1. **LAW-1 间距编码从属关系**：组间间距 ≥ 组内 2 倍，间距取 4 的倍数离散刻度（4/8pt 体系），三种关系不得用同一数值
2. **LAW-3 每视图一个视觉焦点**：恰好一个最高强度主操作（唯一实心 CTA），强调色占比 ≤10%（60-30-10），操作按实心/描边/文本三档分权
3. **LAW-4 颜色不得为唯一信息载体**：状态/数据/链接必须提供图标、形状、文字或位置第二通道；红绿不得为唯一区分轴
4. **LAW-5 对比度满足 WCAG AA**：正文 ≥4.5:1，大字与非文本交互元素 ≥3:1，必须在真实渲染背景上验证
5. **LAW-13 状态完整性先于美观**：数据视图四态（空/加载/错误/成功）齐备，可交互组件五状态集（default/hover/focus-visible/active/disabled）齐全，缺项禁止交付
6. **LAW-15 动效纪律**：只动画 transform/opacity（禁 `transition: all`），微交互 150~300ms，`prefers-reduced-motion: reduce` 必须降级
7. **LAW-21 视觉规格不压倒交互底线**：语义元素、最小命中区、对比度、焦点可见优先于像素稿；NEVER 移除焦点环而无 `:focus-visible` 替代
8. **LAW-23 不编造**：不确定的 aria-*/WCAG 条款号/属性值输出「不确定，待文档验证」，不虚构蓝紫渐变冒充品牌

## Top 坑点（不读 kb 也必须知道的）

1. [G-42] 异步只写 happy path——失败白屏/无限转圈，用户被锁死（最高频系统性缺陷）
2. [G-43] 乐观更新无回滚 + 提交无 pending 锁——连点产生重复订单/重复付款（直接资损）
3. [G-49] `outline: none` 无替代焦点——键盘用户全站"失明"（WCAG 2.4.7）
4. [G-17] 灰字正文 #999 on 白底 ≈2.85:1——白底最浅合格灰是 #767676（4.5:1）
5. [G-1] placeholder 当 label——输入后提示消失、自动填充无法核对
6. [G-39] `transition: all` + 一刀切 `.3s` 模板手癖——意外动画 + 反馈迟钝
7. [G-32] AI 蓝紫渐变品牌脸 `#667eea→#764ba2`——模板指纹冒充设计结论；无品牌输入须声明「未注入品牌」
8. [G-18] 深色模式 naive invert——负片/品牌变浊/阴影失效层级坍塌；须语义 token 整体重映射
9. [G-26]/[G-27] 中文正 letter-spacing + 字体栈中西文顺序反——中文字距撕裂、字形发闷
10. [G-52] 触控目标 <24×24——移动端点不中、误触（WCAG 2.5.8 底线，移动端 ≥44×44）
