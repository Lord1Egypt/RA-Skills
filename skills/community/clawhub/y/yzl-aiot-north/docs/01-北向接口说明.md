# 01 · 北向接口说明

本文是 Python / JS SDK 的实现依据。内容来自平台“开放接口/API 文档”，并在 2026-11-04 用真实账号与设备做过调用验证。

---

## 1. 地址与认证

| 项 | 值 |
|---|---|
| REST Base | `https://aiot.yzlkj.com` |
| 南向设备服务器 | `ciot.yzlkj.com`（测试）/ `siot.yzlkj.com`（生产） |
| MQTT Broker | `ciot.yzlkj.com:1883`（明文，无 TLS） |
| 北向实时 Topic | `north/{product}/{device}/data` |

### 1.1 JWT（推荐）

```http
POST /auth/login
Content-Type: application/json

{"account":"用户名或手机号","password":"密码"}
```

```json
{
  "code": 0,
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "expiresIn": 604800,
    "user": {"id":"u_...","username":"...","role":"user","appkey":"ak_..."}
  }
}
```

后续请求：

```http
Authorization: Bearer <JWT>
```

文档写有效期 24 小时，实测登录响应的 `expiresIn=604800`（7 天）。以服务端返回为准；401 时重新登录。

### 1.2 API Key

平台文档：

```http
X-API-Key: ak_...
```

Web 控制台还会发送：

```http
YZL-AIoT-KEY: ak_...
```

SDK 同时发送两个头。

> 实测：本账号只带 API Key 调用 `/open/account`、`/open/device/list` 返回空数据，而带 JWT 返回 42 台设备。API Key 可能是独立集成租户或未绑定设备。**生产建议优先 JWT/账号密码**；用 API Key 时先调用 `/open/account` 确认数据范围。

## 2. 统一响应信封

```json
{
  "code": 0,
  "msg": "success",
  "data": { ... },
  "extra": ""
}
```

| code | 含义 |
|---:|---|
| 0 | 成功 |
| 400 | 参数错误 |
| 401 | 未认证 / token 过期 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 429 | 限流 |
| 500+ | 服务端错误 |

SDK 把非 0 `code` 转成异常：

- Python：`AiotAuthError`、`AiotRateLimitError`、`AiotAPIError`
- JS：`AiotAuthError`、`AiotRateLimitError`、`AiotAPIError`

## 3. 端点

### 3.1 账号

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/auth/login` | 登录 |
| GET | `/auth/profile` | 当前用户（含 `appkey`） |
| GET | `/open/account` | 账号概览（设备数/在线/告警/配额） |

### 3.2 设备

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/open/device/list` | 列表；`Filter`、`GroupId`、`Online`、`MaxResultCount`、`Offset` |
| GET | `/open/device/{id}` | 详情；owner/admin 可见 `password`、`bindCode` |
| GET | `/open/device/stats` | 在线/休眠/离线统计 |
| GET | `/open/device/{id}/telemetry` | 最新值 |
| GET | `/open/device/{id}/history` | 历史；`keys`、`start`、`end`、`limit` |
| GET | `/open/device/{id}/aggregate` | 降采样；`keys`、`start`、`end`、`bucket`（1m/5m/1h/1d） |
| GET | `/open/device/{id}/backfill-logs` | 补传记录 |

设备列表项：

```json
{
  "id": "WANCD2-0000001008",
  "product": "WANCD2",
  "name": "温室控制器",
  "protocol": "TCP",
  "online": true,
  "status": "online",
  "lastSeen": "2026-11-04 01:27:06",
  "env": "prod",
  "password": "******",
  "bindCode": "******"
}
```

> `password`/`bindCode` 是设备凭证。SDK 默认脱敏；需要明文时显式传 `include_secrets=True` / `includeSecrets: true`。

### 3.3 实时值

```json
{
  "deviceId": "AIOTSDK-0001",
  "online": true,
  "status": "online",
  "ts": "2026-11-04 01:30:16",
  "lastSeen": "2026-11-04 01:30:16",
  "data": {
    "temp": {"value": "25.5", "ts": "2026-11-04 01:30:16", "label": "Temperature(C)", "abnormal": ""}
  }
}
```

SDK 归一化为：

```json
{
  "deviceId": "AIOTSDK-0001",
  "device_id": "AIOTSDK-0001",
  "online": true,
  "ts": "2026-11-04 01:30:16",
  "values": {"temp": 25.5},
  "meta": {"temp": {"label": "Temperature(C)", "ts": "...", "abnormal": ""}},
  "raw": {}
}
```

- 数值字符串会尽量转成 int/float；`"abc"` 保留字符串。
- `abnormal` 非空表示平台判定异常。
- `ts` 是“该设备最新数据时间”，在没有新数据时保持不变；可用于去重。

### 3.4 历史

```json
{
  "deviceId": "AIOTSDK-0001",
  "points": 6,
  "series": {
    "temp": [
      {"ts": "2023-11-15 06:13:20", "value": 11.1},
      {"ts": "2026-11-04 00:36:20", "value": null}
    ]
  }
}
```

- `series` 按测点分组，按 `ts` 升序。
- `value` 可能是 `null`（该时刻无有效值）。
- 时间参数用本地时间字符串 `YYYY-MM-DD HH:mm:ss`。

### 3.5 聚合

```json
{
  "deviceId": "AIOTSDK-0001",
  "bucket": "1d",
  "series": {
    "temp": [{"bucket": "2026-11-03 08:00:00", "min": 23.5, "max": 26.5, "avg": 25.52, "count": 10}]
  }
}
```

### 3.6 指令

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/open/device/{id}/command` | 下发 `set`/`get` |
| GET | `/open/command/list` | 历史指令 |
| GET | `/open/command/{id}` | 单条状态（部分环境 404，以列表为准） |

请求：

```json
{"cmd":"set","args":["DEVICE-ID","sw","1"]}
```

响应：

```json
{
  "commandId": "2fe0f09bc55bc47c",
  "tra": "82d30ba9fcbfd9e7",
  "status": "pending",
  "channel": "TCP"
}
```

状态：`pending` / `sent` / `succeeded` / `failed` / `queued` / `timeout`。

- `args` 必须包含设备 ID 作为第一个元素；SDK 的 `send_command`/`sendCommand` 会自动补。
- `set` 的设施 `access` 必须是 `rw`，否则 400。
- UDP 设备离线时指令进队列，等设备 `get_order`。

### 3.7 告警

`GET /open/alarm/list?status=active&pageSize=20`

```json
{
  "active": 13,
  "total": 5109,
  "items": [
    {
      "id": 35708,
      "deviceId": "WANCD2-0000001008",
      "type": "offline",
      "level": "warning",
      "msg": "设备离线",
      "metric": "online",
      "value": 0,
      "ts": "2026-11-04 01:27:40",
      "status": "active",
      "env": "prod"
    }
  ]
}
```

实测 `pageSize` 可能被忽略，一次返回很多条；应用侧应做 `items[:limit]`。

### 3.8 型号 / 测点

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/open/product/list` | 型号列表，含 `metrics[]` 测点定义 |
| GET | `/open/product/{id}` | 单型号详情；**本环境实测 404（2026-11-24）**，改用 `/open/product/list` 按 id 过滤 |
| PUT | `/open/product/{id}` | **整表更新**；`metrics` 必须全量，漏项即丢测点 |
| PATCH | `/open/product/{id}/metric/{key}` | **改单个测点属性**（2026-11-21 新增，见 3.9） |
| PUT | `/open/product/{id}/metrics-config` | 测点语义配置（`control` / `compare` 分组） |
| POST | `/open/product/{id}/clean-metrics` | 清理设备自动添加的多余测点 |
| GET | `/open/gateway/ports` | 南向端口监听状态 |

测点（metric，旧称"设施"）字段：`key`、`label`、`unit`、`dataType`、`access`、`visible`；设备上报自动添加的额外带 `autoAdd: true`、`addedAt`。

### 3.9 改单个测点属性（PATCH）

```http
PATCH /open/product/{型号ID}/metric/{测点key}
Authorization: Bearer <token>
Content-Type: application/json

{"dataType":"enum","access":"r","label":"浮球1(高/低)","unit":"","visible":true}
```

Body 全部可选，只传要改的字段：

| 字段 | 取值 | 作用 |
|---|---|---|
| `dataType` | `int` / `decimal` / `text` / `enum` | 数据类型（影响解析、控件、曲线） |
| `access` | `rw` / `r` / `none` | `rw`=可查询+可下发指令；`r`=仅查询；`none`=仅上报 |
| `label` | string | 显示名 |
| `unit` | string | 单位 |
| `visible` | boolean | 前端是否显示（不删数据） |

响应：

```json
{"code":0,"msg":"ok","data":{"product":"RSTICQ","key":"in1",
 "before":{"dataType":"int","access":"none","visible":true,"label":"输入1(浮球1)","unit":""},
 "after":{"dataType":"enum","access":"r","visible":true,"label":"输入1(浮球1)","unit":""}}}
```

错误：`400` 取值非法或无权修改（非创建者且非管理员）；`404` 型号或 key 不存在。

注意：

- PATCH 改过任一属性后，该测点的 `autoAdd` 标记会被清除（视为人工确认）。
- `access=rw` 只让平台放控件，固件不支持该指令仍会失败。
- `dataType` 与 IoTDB 序列类型绑定，改类型不影响已存数据；`text` 序列不能写数字。
- 改完立即生效（服务端清型号缓存），无需重启。
- 平台文档给的 `47.111.84.144:3005`（主服）/ `43.139.12.195:3005`（测服）是直连地址；对外仍用 `https://aiot.yzlkj.com`。
- 改完可 `GET /open/device/{id}` 复核：设备详情里的 `metrics` 是合并型号配置后的生效属性。

## 4. 北向 MQTT

平台文档：

| 项 | 值 |
|---|---|
| Broker | `ciot.yzlkj.com:1883`（测试）/ `siot.yzlkj.com:1883`（生产） |
| Topic | `north/{product}/{device}/data` |
| 通配 | `north/+/+/data`（订阅全部） |
| 方向 | 平台 → 应用（只读） |
| 内容 | 设备上报的原始 JSON，历史补传不会出现 |

Payload 示例：

```json
{
  "ter": "WANCD2-0000001008",
  "data": [
    {"func": "facs", "args": ["kk1", "1", "vot", "221.5"], "fid": "F1"}
  ]
}
```

SDK 归一化：

```json
{
  "product": "WANCD2",
  "deviceId": "WANCD2-0000001008",
  "values": {"kk1": 1, "vot": 221.5},
  "frames": [],
  "raw": {}
}
```

### 4.1 认证现状（重要）

平台文档写：“设备连接 EMQX 需账号密码；**北向应用订阅用独立凭证或 JWT**；EMQX 已启用密码认证。”

实测本账号：

- 匿名 → `Not authorized`
- 用户 JWT / 用户 ID / 用户名 / API Key 作为 username 或 password → 全部 `Not authorized`
- 设备 ID + 设备密码（南向凭证）→ `Not authorized`
- 1883 是唯一开放的 MQTT 端口；8883/8083/8084/1884 未开放

结论：**北向 MQTT 凭证需要平台管理员单独分配**，本账号未暴露。没有凭证时请使用：

- `NorthBridge` 默认 REST 轮询（已验证）；
- 或让平台在网关侧把 `north/.../data` 转发到你的 HTTP/Webhook。

如果拿到凭证，Python/JS 的 `NorthMQTT` 直接填 username/password 即可，topic/payload 解析已实现。

## 5. 频率限制与分页

- 账号页面显示 API 配额约 **10 次/10 秒**（以实际账号为准）。
- `MaxResultCount` 上限 5000；设备列表默认 50。
- `alarm/list` 的 `pageSize` 实测可能不生效，返回全量；应用侧截断。
- `command/list` 的 `pageSize` 也可能返回超过请求条数；以 `items` 实际为准。
- Bridge 轮询 N 台设备，每轮 N 次请求；请把 `interval` 设为至少 `N` 秒，或使用 MQTT。

---

## 6. 时间与时区

- REST 返回的时间字符串没有时区后缀，按平台本地时间（Asia/Shanghai）理解。
- Bridge 的 `receivedAt` 使用 UTC ISO 8601；`ts` 保留平台原值。
- 历史查询的 `start/end` 使用平台本地时间字符串；Python 可传 `datetime`，JS 可传 `Date`，SDK 转成本地格式。

---

## 7. 安全清单

- 不要把 JWT/API Key 放进前端 bundle；前端通过自己的后端访问 Bridge。
- Bridge 暴露在公网时加反向代理鉴权、IP 白名单、TLS。
- Webhook 校验 `X-AIoT-Signature`，使用 `hmac.compare_digest` / `crypto.timingSafeEqual`。
- 设备 `password`/`bindCode` 默认脱敏；不要全局打开明文。
- 日志里不要打印 `Authorization`、`X-API-Key`、设备密码。
