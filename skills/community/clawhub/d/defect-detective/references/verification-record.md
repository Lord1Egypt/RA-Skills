## 场景与结果

### 场景 1：查重命中（主路径）

- 输入：真实后端缺陷描述（含异常类型与错误码）
- 执行：归一化指纹 → 第一级全指纹术语搜索 → 命中
- 结果：命中一张 open 工单（工单号脱敏），相似度评为「高」——指纹所含核心项全部命中；输出含证据链与建票建议，未做任何写操作
- 通过标准：✓ 命中，且相似度判定与 FAQ 口径一致

### 场景 2：无匹配（诚实降级）

- 输入：全新前端样式缺陷（可达工单系统不覆盖该域）
- 执行：三级降级阶梯全部执行
- 结果：三级均无命中，结论为「否」，如实标注「可达的工单系统不覆盖此域」——未编造匹配
- 通过标准：✓ 铁律 1（不搜索不说已知）与诚实降级成立

### 场景 3：变更关联（git blame）

- 输入：涉及层已知的后端缺陷
- 执行：只读 `git log` / `git blame` 查看失败区域近期合并与作者
- 结果：列出近期变更与作者作为归属推断证据；纯前端场景正确跳过步骤 3
- 通过标准：✓ 铁律 2（无证据不说归属）成立

## 如何复跑

1. 在配置了工单查询工具的环境中说「缺陷分诊」并贴一段已知工单的缺陷描述 → 应命中该工单（验证查重）
2. 再贴一个全新问题 → 应三级降级后报「否」（验证诚实降级）
3. 对一个后端缺陷问归属 → 输出应含 git 证据链（验证归属推断）
