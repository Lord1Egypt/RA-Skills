## 🔁 前期待办回看（第 0 节，必须最先执行）

> ⚠️ **v0.1.30 新增，强制执行**：本节是简报的第 0 节，**先于主题关联图**。没有本节，简报就是流水账。
> **背景**：10-31 首提「固定加一节前期待办回看」，至 11-05 已悬置 5 天（11-02 / 11-03 连续两天在「明日关注」里写「需补上回看动作」却仍未做）。**建议写进简报不等于被采纳**——所以它必须成为模板的强制结构，而不是每日的自觉动作。

**执行方法**：
1. **先读持久台账**：`~/.openclaw/workspace/日志管理/待办台账.md`（**唯一数据源**，2026-11-05 建立）
   > ⚠️ **台账只落本地 + 飞书，不再进 Get笔记**（张公子 2026-11-20 明确：Get笔记 里不需要待办事项）—— **不要**把台账同步到 Get笔记，也 **不要**在简报里报「Get笔记 台账 id」作为回读坐标；台账坐标写「本地路径 + 飞书主档 doc token」即可。
2. 再读取最近 3 天的简报：`~/.openclaw/workspace/日志管理/{D-3, D-2, D-1}-日志简报.md`，提取其「📅 明日关注」和「🔧 改进建议」两节，与台账合并（台账有则更新台账，无则新增）
3. 对台账中每条逐条判定状态，**写回台账**（回写是闭环的一部分，不是可选项）
3. 对每一条判定状态，四选一：

| 状态 | 含义 | 写法 |
|------|------|------|
| ✅ 已落地 | 已实际完成 | 注明完成时间与证据（文件路径 / 链接 / 工具名） |
| 🔄 进行中 | 正在做 | 注明当前进度与下一步 |
| ⛔ 已放弃 | 决定不做 | **必须写明放弃原因**——不写原因 = 悬置 |
| ⏸️ 待你决定 | 需要张公子裁定 | 注明需要他回答什么 |

4. 无条目的日子跳过；连续缺跑导致某天无简报时，在本节注明「该日简报缺失，已由哨兵补做」
5. 若某条目已连续 3 次出现且状态仍为「待你决定」或「⏸️」，标注 **⚠️ 悬置超时**——这类条目应主动升级为「向张公子当面提出」

**输出模板**：

```
## 🔁 前期待办回看

**回看窗口**：{D-3} / {D-2} / {D-1}

| 来源 | 待办 | 状态 | 证据 / 原因 |
|------|------|------|-------------|
| {D-3} | {待办原文摘要} | ✅ 已落地 | {完成时间与证据} |
| {D-2} | {待办原文摘要} | ⏸️ 待你决定 | {需要你回答什么} |
| {D-1} | {待办原文摘要} | 🔄 进行中 | {当前进度} |

**本节新增待办**：{本日新提出的一条，回流到下次回看}
```

> ℹ️ 「本节新增待办」是闭环的关键：本日新提出的待办必须**同时**写进 `待办台账.md` 并在本节显式登记，否则会重复 10-31 以来「提了没人管」的老问题。
> ⚠️ **只写简报不回写台账 = 闭环断裂。** 台账是跨日持久状态，简报是每日快照；下一次的回看靠台账，不靠简报。

>
> ```bash
> cd ~/.openclawer/.openclaw/workspace/日志管理 2>/dev/null || cd ~/.openclaw/workspace/日志管理
> python3 tag_merge.py --new "#你要用的标签"
> ```
> 处置：语义等价 → 复用已有标签｜细化关系 → 两者都留，主标签指向细分｜确为不同概念 → 才新开。
> 先分清**概念型标签**（可做检索入口）与**事件型标签**（一次性事件，不占检索面）。判断标准：**三个月后还可能再出现吗？**
>
> ⚠️ **v0.1.33 补充**：脚本会读取 `日志管理/标签归并判定.json`（唯一判定依据）。输出里标「⛔ 已排除」的组是**已判定为不同概念，禁止合并**——不要再被相似度误导。若某组与新标签高度相似但判定文件里没有，请逐条人工判定并把结论写进该文件（键 `A|B`，不要求书写顺序），下次脚本就会记住。
