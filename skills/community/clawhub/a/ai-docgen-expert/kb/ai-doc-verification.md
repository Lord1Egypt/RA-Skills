# ai-doc-verification — AI 文档验证（六维质量 / doc-tests / 链接健康 / 覆盖率度量 / 反馈闭环 / AI 验收协议）

## 定位与心智模型

本子域覆盖 AI 生成（及人工）文档的验证层：质量六维评审、doc-tests（示例执行/快照/走查）、链接与引用完整性、覆盖率度量、读者反馈闭环、AI 批量生成内容的验收协议。

核心思想：**文档不是写完即真**。AI 生成放大了幻觉风险——编造内容与事实内容输出形态相同，使用者无法靠肉眼分流；验证是发布前的必经层，且「行为文档化即测试义务」（Google docguide：any behavior documented here should have a test verifying it）。验证分两层：机器能拦的全拦（结构层自动化），机器拦不了的按风险分级人审（语义层抽样）——语义准确性自动化不了，「全靠脚本」与「全靠感觉」是同构失败。

**证据层级声明（降级域）**：本子域种子 docs.anthropic.com 区域封锁 BLOCKED（见 ingest-notes），降级为纯模型模式——证据层级为「降级域（内源实践锚 + Google 借道锚）」：主体为 [模型经验]；AV-2 官方背书借道 Google docguide；AV-3 三态分类为本库内源实践锚（spot_check 实践）。**本文件不含、也不得引用任何「Anthropic 官方验证协议」——该协议未经证实存在，不得虚构。**

适用边界：面向文档资产的验证与验收（六维/doc-tests/链接/度量/反馈/抽样）；生成流程本身的人机分工见 ai-docgen-workflow；CI 门禁与债治理见 doc-governance；签名比对的对象（类型导出/TSDoc）见 api-doc-gen。

## 法则

编号与 elicited/07-laws.md 一致，AV-1 ~ AV-10。

**AV-1** **MUST**（[GLOBAL] 候选）: 文档质量六维缺一不可评：准确/完整/一致/时效/可发现/可读。每维至少一句结论；优先级：准确 > 时效 > 完整 > 一致 > 可发现 > 可读（错误负价值 > 缺失 > 难读）。
- 违反后果: 评审被可读性（最易评维度）劫持而漏准确性（最重要维度）——「错而美」的文档通过评审，误导读者。
- 溯源: [模型经验]（elicited/01-six-quality-dimensions）

**AV-2** **MUST**: doc-tests 分层：示例编译每 CI、示例运行断言覆盖 reference、tutorial 快照关键输出、全流程走查每版本发布前。预期输出断言用关键行/归一化比对（全量 stdout 匹配必脆断）；快照更新必须出现在 PR diff 中被审（快照变化 = 行为变更信号）。
- 违反后果: 示例烂掉靠读者报告；快照三步死亡（红→update→skip）；tutorial 早就走不通，新用户首日流失。
- 溯源: [官方文档](https://google.github.io/styleguide/docguide/best_practices.html)（借道锚：any behavior documented here should have a test verifying it）+ [模型经验]（elicited/02-doc-tests）

**AV-3** **MUST**: 链接检查三态：OK / BLOCKED（401/403/405/429/503/超时——反爬族，不计失败）/ BROKEN（404/持续 5xx，退出码 1）。内链 blocking、外链分层+缓存；豁免须登记原因并定期复核；历史记录中的链接保持历史准确（历史路径进豁免清单）。
- 违反后果: 403 反爬全报 BROKEN——真断链淹没在误报里，或团队因误报关闭整个检查；历史 changelog 被「修复」失去历史真实。
- 溯源: [模型经验]（elicited/03-link-integrity；内源实践锚：本库 spot_check 实践——npmjs.com/w3.org 403 族常年 BLOCKED 非 BROKEN）

**AV-4** **MUST**: 引用分类验证：文件/锚点/API 符号/issue/版本/规范条款各有验证方法，不能混同。`{@link}` 死链静默是重灾区；规范章节级引用（RFC 条款）只能人工抽查；每个未验证引用按未验证对待。
- 违反后果: `{@link}` 渲染死链静默；锚点烂（文件在但跳过去落页顶）；RFC 章节号记忆可靠性极低却无人抽查。
- 溯源: [模型经验]（elicited/03）

**AV-5** **MUST**（[GLOBAL] 候选）: 覆盖率度量配对：量度量必配质抽查，度量做 warning 不做 KPI。注释覆盖率/API 覆盖矩阵自动遍历，配随机质量抽查（Goodhart 防御）；分母必须来自代码侧（类型导出）而非文档侧（幸存者偏差）；分级阈值：新增 blocking + 存量基线渐进。
- 违反后果: 覆盖率 100% 全是 `// the x` 垃圾凑数（Goodhart 全额发作）；50 个从未被文档提及的公共 API 不在分子分母里。
- 溯源: [模型经验]（elicited/04-coverage-metrics）

**AV-6** **MUST**: 反馈信号三源分层：行为信号（搜索日志/停留）> 轻反馈（一键组件）> 重反馈（issue）。搜索零结果词是内容缺口地图（最沉默最贵）；反馈周期汇帐进 triage；修复必复验（负反馈率复测——修复不复验等于没修）。
- 违反后果: 「没人提意见」错觉（重反馈是冰山尖）；最贵的缺口数据（搜索零结果）白白丢弃；修复后宣布胜利但负反馈率没变。
- 溯源: [模型经验]（elicited/05-feedback-loop）

**AV-7** **MUST**: AI 生成内容验收按风险分级抽样：低风险（结构化改写/格式化/翻译）5% / 有源中风险（类型在手/既有文档改写）15% / 无源高风险（事实密集/发布类）全量或拒生成。抽样按幻觉高发位加权（数字/链接/名称 > 断言 > 常识）；抽样发现率超阈值触发整批复检（批次内错误自相关）；风险分级按 diff 实质不按任务名义。
- 违反后果: 「只是格式化 PR」夹带内容改写漏审；高风险无源生成全按 5% 抽——幻觉漏网；发现 2 篇幻觉仍放行同批 90 篇。
- 溯源: [模型经验]（elicited/06-ai-acceptance-protocol；5%/15% 为经验设计，可调参数）

**AV-8** **MUST**: 验收必须外部：AI 不做最终放行人。AI 可自查结构（格式/链接/清单完备），不可自查事实（自查的「已核实」不可信）；验收人不能是生成人；AI 参与度元数据记录在案。
- 违反后果: AI 起草 + AI 自评 = 双重幻觉风险无外部交叉；后续问题无法归因分析（参与度缺失）。
- 溯源: [模型经验]（elicited/06）

**AV-9** **MUST**（[GLOBAL] 候选）: 验收发现按错误模式归类回流（AW-10 的验收层落地）。验收不只是放行把关，是校准数据：发现归类→生成规则更新→下一批错误率下降；不回流的验收是纯成本。
- 违反后果: 错一批修一批、生成规则不变——同类幻觉每批重犯。
- 溯源: [模型经验]（elicited/06、05；与 ai-docgen-workflow 的 AW-10 同根，蒸馏阶段合并候选）

**AV-10** **MUST**: 六维验收可重复化：验收标准固化清单化，每次验收同一标准。抽样密度/分级判据/判据映射表（六维→手段）文档化。
- 违反后果: 验收标准漂移——质量不可比、改进不可测，「上次好像没查这条」成为常态。
- 溯源: [模型经验]（elicited/06）

## 核心概念速览

| 概念 | 一句话定义 |
|---|---|
| 六维 | 准确/完整/一致/时效/可发现/可读——缺一不可评，准确性优先（AV-1） |
| 自动化分层 | 全自动（链接/术语/版本一致）/ 半自动（过时扫描、示例运行）/ 纯人工（语义准确、误导性） |
| doc-tests | 文档内示例代码提取→编译/运行→断言输出；行为文档化即测试义务（AV-2） |
| 快照腐烂 | 预期输出无人审查地 update，最终常年 skip——红→update→再红→skip 三步死亡 |
| 维度冲突取舍 | 一致性与历史准确打架时（ADR 旧术语），历史条目显式豁免一致性检查（豁免清单即治理资产）；活文档执行一致性 |
| Goodhart 风险 | 度量成为目标后，为度量优化的行为取代为质量优化的行为——配对防御 |
| 任务测试 | 给读者任务看其能否找到文档——可发现性维度的真实验证法 |
| 关键行断言 | 只断言关键输出行（可配正则提取），优于全量 stdout 匹配 |
| 输出归一化 | 时间戳/随机 ID/绝对路径替换为占位符后比对——断言稳化手段 |
| 三态链接 | OK / BLOCKED（反爬族不计失败）/ BROKEN（真断链，退出码 1）（AV-3） |
| 豁免清单 | 每条豁免含原因与过期复核的检查例外登记——豁免是资产不是暗门 |
| 度量配对 | 量度量必配质抽查——Goodhart 防御（AV-5） |
| 代码侧分母 | 覆盖率分母来自代码侧类型导出而非文档出现——防幸存者偏差 |
| 分级阈值 | 新增违例 blocking、存量基线冻结渐进清偿（「童子军军规」） |
| 搜索零结果词 | 读者反复搜而不可得的内容缺口地图——最沉默最贵的信号（AV-6） |
| 修复复验 | 修复挂信号基线、下周期复测——文档修复的「回归测试」 |
| 风险分级抽样 | 低 5% / 中 15% / 高全量或拒生成；按 diff 实质分级（AV-7） |
| 批次自相关 | AI 错误在批次内同模式——发现一处幻觉即整批扩抽信号 |
| 验收外部性 | AI 可自查结构不可自查事实；不做最终放行人（AV-8） |
| 验收回流 | 验收发现按错误模式归类→更新生成规则（AV-9） |
| AI 参与度标记 | 文档元数据记录 AI 起草比例与人工审校记录（内部透明度） |

## 最佳实践

### 场景 1：搭建文档验证流水线（自动化门先行）

推荐路径：
1. 盘点文档资产类型（reference / tutorial / how-to / changelog / README），每类确定验证手段（见 API 速查表·验证手段分层表）。
2. 机器能拦的全拦进 CI：lint（格式/术语）→ 示例编译 → 签名比对 → 链接检查（内链 blocking、外链分层）。
3. 语义层（准确性/误导性）不入自动化——按 AV-7 风险分级进人工抽样。
4. 每项检查失败必须可操作：报告含位置与建议动作，不产出一堆无人修的 warning（warning 泛滥 = 检查死亡）。

do:
```
CI 门禁：lint + 示例编译 + 签名比对（全 blocking）
        链接检查（内链 blocking，外链 warning + 缓存 + 豁免）
        语义准确性 → 人工抽样（按 AV-7 分级）
```
don't:
```
六维全靠脚本（语义层自动化不了，脚本通过 ≠ 准确）
检查全 blocking 含外链（一次外站抽风全线红灯 → 团队关闭检查）
```
边界条件：一次性项目文档可裁剪到「示例编译 + 内链检查」两项；长生命周期文档库必须全套。本场景源于 [AV-1][AV-2][AV-3][AV-5]。[模型经验]（elicited/01、02、03）

### 场景 2：doc-tests 落地与长期维护

推荐路径：
1. 代码块标记约定：区分可执行块与展示块（```` ```ts ```` meta 信息），「这段别跑」不靠口头。
2. 分层落地（AV-2）：示例编译每 CI（全部可执行块）→ 示例运行+断言每 CI（reference 示例）→ tutorial 快照每 CI 或每夜（关键输出点）→ 全流程走查每版本发布前。
3. 断言设计：关键行断言或输出归一化（时间戳/随机 ID/绝对路径占位符替换）后比对；禁全量 stdout 匹配。
4. 快照纪律：快照 diff 必须出现在 PR 里被审——「为什么输出变了」是行为变更信号，联动 changelog 检查。
5. 环境维护预算：示例依赖的 fixture/环境是 doc-tests 最大长期成本，立项时即承认这笔持续支出。

do:
```
expect(output).toMatch(/server listening on :(\d+)/)   // 关键行断言
```
don't:
```
expect(output).toBe(`Server started at 2026-11-17T10:00:00Z\n...`)  // 时间戳必红 → skip
```
边界条件：工具生态以类指称书写（doc-test 类 runner），选型时按语言生态现查——具体工具未在本库验证；版本敏感示例需版本矩阵，只测最新版对多版本库不够。本场景源于 [AV-2]。[模型经验]（elicited/02）

### 场景 3：链接检查器设计与豁免治理

推荐路径：
1. 引用分型（AV-4）：文件内链（路径存在，本地快）/ 锚点（标题渲染后匹配）/ 站间链接（HTTP 可达，慢+反爬）/ API 引用（`{@link}` 对类型导出检查）/ issue 引用（平台 API）/ 版本引用（对账发布记录）/ 规范引用（人工抽查）。
2. 三态分类（AV-3）：BLOCKED（401/403/405/429/503/超时）单独归类不计失败、退出码仍 0；BROKEN（404/持续 5xx）退出码 1。
3. 外链结果缓存（TTL 数天）——每次 CI 全量外链检查又慢又易被限流。
4. 豁免治理：每条豁免含原因（反爬/已知搬迁/历史引用）+ 定期复核；反爬族可状态码驱动自动豁免，非状态码豁免人工登记。
5. 断链修复走决策树：目标搬家（同内容新地址→更新）/ 目标消亡（删引用或换活源）/ 引用本身过时（这段话该删）——修复必须看上下文语义。

边界条件：锚点 slug 生成规则（大小写/标点/中文处理）因平台而异——实现时查证，对中文文档锚点影响大（本库警示，未经文档验证）；历史 changelog 中的链接进豁免清单，保持历史准确不回改。本场景源于 [AV-3][AV-4]。[模型经验]（elicited/03）

### 场景 4：覆盖率度量体系

推荐路径：
1. 选度量：注释覆盖率（导出符号有 TSDoc 摘要比例，全自动）/ API 覆盖矩阵（公共 API × 文档位置）/ 读者-时刻格子覆盖（战略层，低频盘点）。
2. 分母来自代码侧（AV-5）：类型导出/AST 解析出公共接口清单——文档侧只提供分子。
3. 度量配对：覆盖率 90% 配随机抽 10 条质量分；度量做 warning 不做 KPI。
4. 分级阈值：新增违例 blocking（diff 中新导出无注释即拒）；存量基线冻结 + 触碰时顺手补（渐进清偿）。
5. 频率配对：注释覆盖（新增）每 PR / 注释覆盖（存量）每周 / 链接健康每夜 / API 矩阵每月 / 格子覆盖每季。
6. 报告可操作：每条未覆盖项可点（哪个符号/哪个格子/建议动作），报告 issue 化挂钩修复。

do:
```
分母 = 类型导出清单（AST 解析公共接口）
报告 = 未覆盖符号清单 + 每项建议动作 + 配对质量抽查分
```
don't:
```
分母 = 文档里出现过的 API（幸存者偏差）
报告 = 「覆盖率 87%」一个数字（无可操作项）
```
边界条件：度量频率为经验值可调；有意无文档的高层 API 走显式豁免（决策记录在案），不混入「未覆盖」误报。本场景源于 [AV-5]。[模型经验]（elicited/04）

### 场景 5：反馈闭环运转

推荐路径：
1. 三源接入：行为信号（搜索日志、页面停留/跳出、任务失败线索）→ 轻反馈（页面级「这个页面有帮助吗？」一键组件）→ 重反馈（文档 issue/PR）。
2. 周期汇帐：搜索零结果词 top N → 内容缺口判断（该写新文档？还是改命名让现有文档可搜到？——零结果词同时是「不存在」与「存在但不可发现」两类问题的信号，需人工分辨）；轻反馈负分页清单 → 文档债 triage（与 doc-governance 的 AW-2 触达度加权衔接）。
3. 修复排期后挂信号基线：改前负反馈率 X%，下周期复验收敛到 Y%——修复不复验等于没修（AV-6）。
4. 重反馈逐条处理（量少），但不直接进 todo——先过 triage 防个别用户偏好劫持文档方向。

do:
```
修复项挂信号基线：改前负反馈率 X% → 修复 → 下周期复验 Y%（收敛才关闭）
周期汇帐：搜索零结果词 top N + 轻反馈负分页清单 → triage 输入
```
don't:
```
改完即宣布「已优化」，无复验信号（修复不复验等于没修）
反馈直接进 todo，不过 triage（读者偏好劫持文档方向）
```
边界条件：反反馈组件本身可能是噪音源（误点/恶意），负分页清单看趋势不看单点；匿名反馈缺追问通道是已知局限。本场景源于 [AV-6]。[模型经验]（elicited/05）

### 场景 6：AI 批量生成文档的验收执行

推荐路径：
1. 风险分级按 diff 实质（AV-7）：纯格式 diff（whitespace-only 判定可自动化）→ 低风险 5%；有源生成（类型在手/既有文档改写）→ 中风险 15%；无源生成/事实密集/发布类 → 高风险全量人工或拒绝生成（输入契约见 ai-docgen-workflow AW-3）。
2. 抽样按幻觉高发位加权：数字/链接/名称 > 断言 > 常识——均匀随机是浪费抽样预算。
3. 发现即扩抽：抽样发现率超阈值（如 >10%）→ 该批全量复检或整批打回重生成（批次内错误自相关）。
4. 验收执行分工（AV-8）：AI 承担结构层自查（格式/清单/链接完备性）+ 验收辅助（列待抽清单与核查项）；人承担事实层核查与最终放行。
5. 验收判据映射六维：准确性抽查核源（高发位加权）/ 完整性五要素·格子比对 / 一致性术语表扫描（自动）+ 风格（人）/ 时效性版本对账 / 可发现性导航登记 / 可读性人读一遍（最后过）。
6. 每项验收发现含位置/严重度/建议；发现按错误模式归类回流生成规则（AV-9）。
7. AI 参与度元数据（起草比例/审校记录）随文档入库。

边界条件：抽样密度（5%/15%）为经验设计、可调参数——幻觉率随模型代际下降则密度可降（复检阈值同理）；验收人不得是生成人；本清单本身须固化（AV-10）——每次验收同一标准。本场景源于 [AV-7][AV-8][AV-9][AV-10]。[模型经验]（elicited/06）

## 高频坑点（速查）

### Top 1：链接检查把 403 反爬当 BROKEN（AV-3）

- 症状: 链接检查器全量报断链，`npmjs.com → 403 Forbidden`、`w3.org → 403` 淹没真 404；或团队因误报常年关闭检查。
- 根因: 二值可达逻辑（可达/断），无 BLOCKED 态——反爬站的 403/429 与真断链的 404 混在同一出口。
- 修复: 三态分类——BLOCKED（401/403/405/429/503/超时）不计失败、退出码 0；BROKEN（404/持续 5xx）退出码 1。本库 spot_check 实践锚定：npmjs.com/w3.org 403 族常年 BLOCKED 非 BROKEN。

### Top 2：覆盖率分母来自文档侧（AV-5）

- 症状: 「文档覆盖率 95%」，但 50 个公共 API 从未被任何文档提及——分子分母都不含它们。
- 根因: API 清单从文档侧收集（容易）而非代码侧（需要 AST/类型解析）——幸存者偏差。
- 修复: 分母必须来自代码侧（类型导出/公共接口清单），文档侧只提供分子。

### Top 3：doc-tests 快照三步死亡（AV-2）

- 症状: 快照红 → 有人 `--update` 一把梭 → 再红 → 常年 skip。预期输出与现实漂移无人知晓。
- 根因: 快照更新无审查纪律——快照变化（行为变更信号）不经 PR 审查。
- 修复: 快照 diff 必须出现在 PR 里被审（「为什么输出变了」联动 changelog 检查）；断言改关键行/归一化比对降低脆断。

## API 速查表

本域无传统 API——本节含义为**验证手段分层表 + 幻觉模式识别特征表 + 人工评审 checklist 模板**。

### 验证手段分层表（按成本升序；成本越高覆盖语义层越深）

| 层 | 手段 | 成本 | 覆盖 | 建议频率 | blocking |
|---|---|---|---|---|---|
| 1 | lint（格式/术语表/风格） | 极低 | 一致性、可读性表层 | 每 CI | blocking |
| 2 | 编译/类型检查（示例块编译、文档内代码 typecheck） | 低 | 准确性表层（API 存在性、类型正确） | 每 CI | blocking |
| 3 | 签名比对（文档签名 vs 代码侧类型导出清单） | 低 | 准确性（签名/参数/默认值/返回） | 每 CI | blocking |
| 4 | 链接检查（三态 + 缓存 + 豁免；含锚点与 `{@link}`） | 中 | 可发现性（引用完整性） | 内链每 CI；外链每夜 | 内链 blocking；外链 warning |
| 5 | doctest/示例执行（提取→运行→断言；快照；走查） | 中高 | 准确性深层（行为承诺在位） | reference 每 CI；走查每版本发布前 | 示例运行 blocking；走查 checklist |
| 6 | 人工评审（六维清单 + 风险分级抽样） | 高 | 全六维含语义层（自动化盲区） | 按 AV-7 分级 | 最终放行层 |

分层原则：机器拦结构层（1~5），人拦语义层（6）；跳层（只做 6 不做 1~5）= 人工耗在机器能拦的问题上；只做 1~5 不做 6 = 语义幻觉漏网。

### 幻觉模式识别特征表

| 幻觉模式 | 识别特征 | 首选验证手段 | 关联 |
|---|---|---|---|
| 编造 API（不存在的导出/方法） | API 名在代码侧导出清单 grep 不到；命名「像真的」（同族命名外推，如同库其他方法风格） | 层 3 签名比对（代码侧分母，AV-5） | AV-7 加权位 |
| 虚构参数（参数名/个数/默认值错） | 参数与签名 diff；默认值无源；可选/必选态与类型不符 | 层 2 编译 + 层 3 签名比对 | AV-7 |
| 过时签名（旧版本形态） | 文档用法与当前类型不兼容；示例调用已 @deprecated/已改名 API | 层 2/5 编译与示例执行 + 废弃扫描 | AV-1 时效性维 |
| 虚构配置项 | 配置键在配置 schema/类型定义中不存在；「看起来合理」的键名风格 | 层 3 签名比对 + grep 配置类型 | AV-7 加权位 |

### 人工评审 checklist 模板

```
评审对象: <文档路径> | 批次: <batch-id> | 风险级: 低/中/高（按 diff 实质） | AI 参与度: <x%>
准确性（先过，最重）:
  [ ] API 名/参数/默认值/返回/错误逐项对照源码（非整体印象）
  [ ] 数字/链接/名称类高发位逐条核源（幻觉加权位）
时效性:
  [ ] 版本标注与当前发布对账；无已废弃 API
完整性:
  [ ] 五要素/格子清单比对无缺项
一致性:
  [ ] 术语表扫描通过；多处描述同一事物无矛盾
可发现性:
  [ ] 导航入链已登记；命名可搜索
可读性（最后过）:
  [ ] 结构清晰、语言适配受众
引用与示例:
  [ ] 每个链接/锚点/{@link}/issue 号已验证，或显式标注「未验证」
  [ ] 可执行块自包含；预期输出经实际运行（未经运行的输出断言 = 编造）
结论:
  [ ] 每维至少一句结论
  [ ] 发现按错误模式归类（回流 AV-9）；发现率超阈值 → 触发整批扩抽（AV-7）
  [ ] 放行人签字（外部验收人，AV-8）
```
