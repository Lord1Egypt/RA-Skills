# 浏览器增强测试标准

本标准用于验证屏幕自动化小助手桌面端的浏览器增强能力及相关流程。
测试只操作小助手创建的独立受管 Profile；不得拿
用户日常 Chrome/Edge Profile、真实账号或敏感页面充当通用测试环境。所有写操作先在本地或专用测试页完成。

## 测试前记录

记录桌面端版本、操作系统与架构、浏览器及版本、组件版本、测试页、测试时间和实际命令。先执行：

```text
cli status
cli capabilities
cli access list
browser status
browser --help
```

只有 `cli capabilities` 列出 `workflow.browser-enhancement@1`，且 `cli access list` 中
`browser_enhancement.status.effective` 为 `true`，才进入真实操作。输出中能力码、凭证、个人路径和页面
隐私必须脱敏；不得为了测试索取、记录、代输或绕过能力码。

## 分层用例

| 层级 | 必测用例 | 通过标准 |
| --- | --- | --- |
| 动作契约 | 检查 `workflow.browser-enhancement@1` 与 `ctx.browser` 方法 | 当前版本明确声明；不能仅凭文档猜测 |
| 访问状态 | 已授权已安装、未授权、未安装、未启用、平台不支持 | 分别报告 `effective`、`reason`、`action`，不混成同一种故障 |
| Probe 边界 | 组件有效、未安装、未授权、未启用，以及纯 OCR/UIA/屏幕任务 | 只在有效受管会话中调用；基础路径不调用、不等待 Probe |
| DOM 路由 | READ/LOCATE/ACT/FILL/SELECT/DOWNLOAD/VERIFY，普通 DOM、暂未加载、连续失败、iframe、Shadow DOM、Canvas、DOM 不稳定 | 返回 `USE_DOM`、`ENHANCE_DOM` 或 `EXIT_DOM`；只退出 DOM，不替 Agent 选择 UIA/OCR/CV/VLM；仅显式携带 Probe `strategy_id` 的 Agent 策略定位受三次/约十秒预算约束，普通定位不受限 |
| Profile | 新域名、高置信旧经验、网页改版连续失败、时间衰减 | Profile 只作弱先验；现场结果覆盖历史；失败可降权并标记失效 |
| Profile 隐私 | URL 含路径/查询、selector、XPath、坐标、具体操作步骤 | 只保存域名级能力信息，不持久化元素和页面级知识 |
| 目标窗口推荐 | 浏览器、非浏览器、能力无效、用户拒绝 | 按任务推荐有效能力；基础屏幕路径可直接完成；不要求关闭日常浏览器 |
| 当前窗口优先 | 当前受管会话、普通已打开浏览器、屏幕能力足够、确需 DOM | 优先复用受管会话；普通窗口用屏幕/UIA；确需 DOM 时打开同一网址，保留日常浏览器 |
| 当前页面交接 | 已知 URL、用户同意读取地址栏、拒绝读取、地址无效、原剪贴板恢复 | 取得目标 URL 后在受管会话打开；临时读取需同意并恢复剪贴板；不记录敏感 URL、不关闭日常窗口 |
| 内容选择 | 单元素、跨滚动长元素、零/多匹配、隐藏元素、过期/跨会话对象、iframe | 选区属于唯一可见目标；只记录字符数；失败不退化为坐标拖拽 |
| 内容复制 | `text`/`value`/`href`、空内容、1 MiB 边界与超限、剪贴板拒绝、敏感日志检查 | 经读取与剪贴板权限写入；正文不进日志；超限停止且不截断 |
| 流程静态校验 | 缺引擎能力、缺读取/操作/下载/会话权限、改变页面却无验证 | 非法流程被拒绝并指出具体缺项 |
| 会话 | Chrome；Windows 再测 Edge；跨 CLI 进程连续执行 open --url→locate→read；重复 open；`--new`；会话过期；任务结束保留、显式关闭 | 独立受管 Profile；同一任务只首次 open，后续进程复用同一会话；Agent 不自动使用 `--new`；只在 `browser_session_expired` 后重开；默认保留；显式关闭后清理对应会话 |
| 登录交接 | 密码框、一次性验证码、用户登录完成、重启后再次打开、站点主动过期 | 检测到登录控件即返回 `waiting_for_user/login_required` 且页面保持不动；用户确认后 `auth-status` 变为 `ready` 才继续；正常关闭和重启后登录 Cookie/站点存储仍在；原始凭据不进入模型上下文、流程文件、运行日志或结果输出 |
| 定位与读取 | 唯一、零匹配、多匹配、含文字过滤、隐藏元素、滚动后元素 | 只返回当前会话可见对象；零个或多个匹配安全停止 |
| 页面操作 | 导航、点击、填写、滚动、按键 | 每项有操作前状态与操作后重新定位/读取或屏幕证据 |
| 下载 | 合法文件名、路径穿越文件名、取消/超时 | 只写入本次运行的 `browser_downloads`；不能指定任意目录 |
| 屏幕交叉验证 | DOM 动作成功但可见页面未变化；颜色或文字验证失败 | 不把协议成功当成业务成功；进入有界恢复或停止 |
| Probe 结果记账 | 各 task kind 的 DOM/增强 DOM 执行成功且验证通过、动作成功但验证失败 | 读取/定位/操作/验证能力分开更新；仅验证通过才记录成功；失败返回结构化 `EXIT_DOM` 和候选理解/操作/验证通道 |
| 停止与故障 | 挂起导航时停止、浏览器被关闭、Sidecar 退出、组件版本/协议不匹配 | 停止可及时中断；故障可解释且不退化为猜坐标或普通 Profile |
| CLI 与定位 | 实际 `browser --help` 参数、无 `--index` 多匹配、显式 `--index`、`verify` | 多匹配明确选择或停止；序号与验证按当前接口正确转发 |
| 高风险交接 | 账号授权、凭据输入、支付确认 | Agent 暂停操作与凭据区域采集，由用户在场完成；验证结果后继续，不由自动恢复或收尾代办 |

## 推荐测试页

使用本地静态页覆盖：标题和正文读取、两个同 selector 元素、隐藏元素、视口外元素、输入框、改变可见状态的
按钮、横纵滚动区和 data URL 下载。另准备一个故意不响应的本地 HTTP 端点验证停止和超时。测试页不得依赖
第三方网站的实时结构；真实业务页面只用于最后一轮用户监督验收。

## 结果分级

- `静态通过`：仅语法、权限、协议和单元测试通过。
- `本机 Sidecar 通过`：真实 Chrome/Edge 受管窗口完成定位、读取、操作、下载、验证和停止。
- `正式组件通过`：从正式清单下载、验签、隔离安装、运行、更新、卸载和重装通过。
- `业务页面通过`：由用户授权并监督，在指定真实页面完成一条安全数据。

报告必须列出每一层的通过、失败和跳过项。未执行正式下载或真实业务页面时，不得写“浏览器增强完整验收通过”。

## 地址与组件传输拒绝

浏览器 open/navigate 仅接受带合法主机的 HTTP(S) URL；其他协议拒绝后不要换工具绕过。
组件目录、平台清单、下载包及其重定向须使用 HTTPS。遇到协议或重定向拒绝应保留原始诊断，
区分下载失败、尚未安装和运行不可用，不降级为 HTTP，也不把下载进度到 100% 当成安装成功。
