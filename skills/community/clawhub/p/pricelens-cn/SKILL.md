# PriceLens 比价智选

把「这个值不值得买」拆成需求约束、价格取证、到手价拆解、渠道评级、参数取舍与买／等／换量化裁决六步，输出一份可复核的决策报告。

## 这是什么

- **解决什么问题**：只看挂牌价就下单，是绝大多数人买贵的直接原因。本技能把价格研究从「搜一圈」变成有证据链的决策——真实到手价落在什么区间、哪个渠道买得到也买得安心、三个关键参数怎么取舍、现在买还是等一等。
- **产出物形态**：一份 Markdown 报告 `pricelens-<品类>-<YYYYMMDD>.md`，固定六个区块——结论卡、到手价区间表、渠道矩阵、参数取舍矩阵、买／等／换裁决、取证清单与待复核项。
- **和直接问大模型的区别**：① 每个价格都带来源类型、检索日期与核实状态，凑不出交叉验证就不给点值；② 强制把挂牌价拆成到手价（券／满减／运费／返利／以旧换新）；③ 强制给出三选一裁决与触发条件，而不是「看个人需求」；④ 证据不足时明确降级为区间或「无法定价」，不补推测数字。
- **适用边界**：适合可标准化描述的实物商品与服务订阅；需要线下验货的单件高价值二手、受准入限制的品类，只给筛选条件与验货清单，不给定价结论。

## 适用场景

- 「我想换一台〔品类〕，预算〔金额〕，现在该买哪台、多少钱算好价？」
- 「同一台机器在不同渠道差好几百，差在哪，便宜的能不能买？」
- 「标价和到手价差太多了，把券、返利、运费、以旧换新全算完到底多少钱？」
- 「两个型号参数互有胜负，我该为哪个参数多花钱？」
- 「现在买还是等到大促？等的话等到多少再出手？」
- 「旧机还能卖多少，以旧换新和自卖哪个更划算？」
- 「这个渠道比官方渠道便宜两成，是正品吗，出了问题谁负责？」
- 「帮我把结论做成一页纸，讲给不懂参数的人听。」

## 何时不要使用

- 要实时价格或自动下单：本技能只做给定快照的比价与判断，实时价格由调用方提供。
- 需要承诺"一定最低价"：只给当前可核实快照下的相对高低，不做全网最低承诺。
- 涉及药品、医疗器械、跨境商品的合规准入判断：只提示风险点，结论交专业方。
- 来源不可核验（无截图、无时间戳）：先补证据链，否则只输出"无法判断"。

## 输入与输出

**输入字段**

| 字段 | 必填 | 说明 |
|---|---|---|
| 品类 | 是 | 必须细化到形态层，如「扫地机器人·自集尘」「台盆龙头·抽拉式」，不接受「家电」「数码」这种粒度 |
| 预算 | 是 | 给上限或区间，明确是到手价口径还是挂牌价口径，默认按到手价理解 |
| 必须在意参数 | 是 | 恰好 3 个并按重要性排序，用于参数取舍矩阵的权重；须可比较（数值或可验证描述） |
| 使用场景与环境 | 否 | 面积、安装条件、人数、使用频率，用于一票否决项与使用价值打分 |
| 已有旧机 | 否 | 型号、购入年份、成色、可否回收，用于以旧换新与「换」分支 |
| 渠道偏好与禁区 | 否 | 如只接受自营、不接受二手、必须开票 |
| 时间窗口 | 否 | 最晚什么时候要，决定「等」是否可行 |
| 输出偏好 | 否 | 只要结论卡／完整报告／含一页纸精简版 |

**输出规格**

- 单个 Markdown 文件，命名 `pricelens-<品类>-<YYYYMMDD>.md`，日期为检索日。
- 六个区块的顺序不可调整：结论卡（≤150 字，放第一屏）→ 到手价区间表（3–6 行）→ 渠道矩阵（4–8 行）→ 参数取舍矩阵（2–4 个候选 × 3 个参数）→ 买／等／换裁决（含触发条件）→ 取证清单与待复核项。
- 全文 900–1800 字（含表格），术语首次出现给英文括注。
- 首行必须写明检索时点，并声明「价格为检索时点抓取，需复核」。

## 工作流

### 第 1 步 · 需求澄清（三问必答）

- **做什么**：把口语需求收敛成可计算的输入——品类细化到形态、预算换算成到手价口径、挑出恰好 3 个「必须在意」的参数并排序。三个参数决定后续所有打分权重，必须由用户确认，不能由技能代填。
- **判据**：三个参数都能写成可比形式（`噪音 ≤ N dB`、`越障 ≥ N mm`、`年耗材成本 ≤ ¥N`），不接受「安静」「耐用」「好看」这类不可比描述；预算口径写明含不含运费与安装。
- **失败怎么办**：用户只给模糊需求时，按「该品类最主流的两种形态 + 主流价位带」给两个候选方向让用户二选一，不自行假设；用户坚持不给参数，则按该品类通用三参数代填，并在报告中标注「参数由默认值代填」。

### 第 2 步 · 价格取证（多源交叉）

- **做什么**：按 `references/price-evidence-chain.md` 的四类来源取证——电商搜索结果片段、垂直零售商站点、品牌官网规格页、内容平台（测评、晒单、历史好价爆料）。每个候选至少覆盖 3 类来源，且同一 SKU 至少 2 个独立来源。
- **判据**：同一 SKU 的两个来源到手价差 ≤15% 视为收敛，可以给点值；差 >15% 必须解释差异来源（不同配置、不同套餐、含不含赠品、是否含税），解释不通就不合并，分别列出。
- **失败怎么办**：来源全部被反爬拦截或需登录时，降级为「区间估计 + 缺口清单」，报告首行标注「未取得可交叉验证的点值」，绝不填推测数字；单源孤证只能进「待复核」，不进结论卡。

### 第 3 步 · 到手价拆解（券／满减／运费／返利／以旧换新）

- **做什么**：把挂牌价按下列顺序逐项加减，每项单独成行：挂牌价 − 商品券 − 平台券与满减 − 店铺返现 + 运费 + 安装与延保 − 返利 − 旧机回收价 − 以旧换新补贴 − 赠品折算价。
- **判据**：每一项都要写清计算基数、到账周期与核实状态（已核实／未核实／按区间）。返利以实付为基数并注明到账周期；以旧换新把「旧机回收价」与「额外补贴」分开列，避免把补贴当成降价。
- **失败怎么办**：任一项规则读不到（券门槛、返利比例、补贴资格），该项标「未核实」并给区间，不计入点值；若未核实项合计可能超过到手价的 5%，结论卡改用区间表述。

### 第 4 步 · 渠道可信度评级

- **做什么**：按 `references/channel-matrix.md` 给每个渠道定级：T1 品牌自营与官方旗舰（开票主体为品牌或平台自营）；T2 授权经销与垂直专业零售商；T3 平台第三方店铺（信用达标、支持七天无理由、有授权声明）；T4 二手、跨境、无票渠道。
- **判据**：定级只能由可观察信号支撑——开票主体、授权声明、退换条款、售后网点、店铺经营年限，不能凭「便宜多少」反推可信度；T3 及以上才可进入「买」的候选池。
- **失败怎么办**：开票主体无法确认时直接降一级并标注；T4 渠道若仍要买，必须在报告中单列风险与验货清单，且不得作为唯一推荐。

### 第 5 步 · 参数取舍矩阵

- **做什么**：以第 1 步的 3 个参数为行、候选为列，按排序赋权（默认 50%／30%／20%，用户可改），每个候选每项打 1–5 分后加权。先跑一票否决项（尺寸放不下、接口不兼容、无售后网点），被否决的候选直接剔除，不参与加权。
- **判据**：最高权重参数上明显落后却总价更高时，必须显式点出，不允许被总分掩盖；再做边际收益检查——把最高权重参数从低分提到满分需要多付多少钱，若多付金额超过预算的 20% 且实际使用差异有限，判为「不值得为该参数加价」。
- **失败怎么办**：某参数缺乏可比数据时，该格标「无数据」并在加权时按该行平均值填充，同时把该行权重下调一半，避免用缺失值制造假精度。

### 第 6 步 · 买／等／换量化裁决

- **做什么**：用 `references/value-scoring.md` 的双线六维评分与净收益模型算出持有价值，再与价格位置合并，落到三选一：
  - **买**：最优到手价 ≤ 目标价（多渠道到手价下四分位），且双线六维综合分 ≥6.5，且时间窗口内无更强替代。
  - **等**：当前价高于目标价但需求可延后，或距可预见的促销窗口 ≤6 周且需求不急。需给出「等到什么价再买」的触发价与复核日期；需求侧本身不成立时也归入「等」，标注为需求等待而非价格等待。
  - **换**：预算内存在替代候选，其综合分高出当前候选 ≥0.5，或以旧换新后的净支出低于继续持有的边际成本。
- **判据**：三选一必须落到单一结论，且每个结论都带触发条件（价格阈值、时间窗口或替代方案）与复核方式；目标价由本技能默认阈值给出，可被用户覆盖并写进报告。
- **失败怎么办**：价格证据不足但又必须给结论时，只给「当前价位相对位置 + 需求紧迫度」的二维判定（高／低 × 急／不急），把量化分数留空并说明缺口。

### 第 7 步 · 决策报告输出

- **做什么**：按 `references/decision-report.md` 的模板落盘六区块，先出结论卡再出表格，最后列取证清单与待复核项；如用户需要，另附一页纸精简版（结论卡 + 三条理由 + 触发价）。
- **判据**：结论卡 ≤150 字且能被单独转发；每个价格都能在取证清单里追到来源、日期与核实状态；报告不含「保证最低价」「全网最便宜」这类承诺。
- **失败怎么办**：用户要求压到一页纸时，删渠道矩阵与参数矩阵的明细行，保留结论、三条理由与触发价，其余移入附录，不删取证清单。

## 输出格式

```
结论：买 / 再等 / 换渠道（一句话 + 置信度）
比价表：渠道 | 标价 | 券后价 | 到手价 | 采集时间 | 证据编号
价差归因：渠道差 / 券门槛 / 版本差 / 时效差
风险与时效：价格有效期、库存风险、退货政策
建议动作：具体到"在哪买、用哪张券、什么时候下手"
```

## 质量门槛

- [ ] 每个价格都带来源类型、检索日期与核实状态；没有来源的数字为零。
- [ ] 每个候选覆盖 ≥3 类来源且同一 SKU ≥2 个独立来源；价差 >15% 已解释。
- [ ] 到手价按第 3 步顺序逐项拆开，券、满减、运费、返利、以旧换新各自单列，标明基数与到账周期。
- [ ] 渠道评级由可观察信号支撑；T3、T4 渠道的风险与验货要求已写明。
- [ ] 3 个必须在意参数在矩阵中都有可比口径，无「安静」「耐用」这类不可比词。
- [ ] 结论为「买／等／换」三选一之一，且附触发条件与复核方式。
- [ ] 报告首行含检索时点，并注明「价格为检索时点抓取，需复核」。
- [ ] 证据不足处写「未核实」或「无法定价」，未用推测数字补齐。
- [ ] 全文 900–1800 字，结论卡 ≤150 字且位于第一屏。
- [ ] 全文无「保证最低价」类承诺，无任何个人身份信息与财务状况信息。

## 能力边界

- **不做实时监控与代下单**：所有价格为检索时点快照，券面与活动规则随时变化，下单前必须由用户复核；本技能不代填订单、不接触支付。
- **不承诺最低价**：只给「相对当前可得渠道的价位判断」与比价依据，不保证买到全网最低，也不保证价格在有效期内不变。
- **不评需线下验货的单件**：珠宝、名表、二手车、孤品收藏只给筛选条件、验货清单与议价话术，不出定价结论与「买／等／换」裁决。
- **不替代合规判断**：药品、医疗器械、金融产品、跨境购的准入、税率与保修范围，只给「需向官方渠道核实」的指引，不给结论。
- **证据不足时降级而非编造**：来源不可达时输出区间与缺口清单；用户拒绝提供第 1 步三项输入时，先补齐再开工。
- **不接收隐私数据**：不索取身份证、手机号、收货地址、账号与支付信息；用户主动提供也只在本次会话内用于计算，不写进报告。

## 常见陷阱

- **拿标价比到手价**：忽略券门槛与运费 → 统一折算到"到手价"再比。
- **忽略版本与容量差异**：同型号不同配置直接比 → 先对齐规格再比价。
- **把历史低价当常态**：等不到就说"还能再降" → 给出历史区间与当前分位。
- **不标采集时间**：价格早就变了 → 每条证据必须带时间戳。

输入（3 行）：
