# 库存、成本、常客与私有使用流程

> ClawHub专用v2.7.3；本文件为独立整理的流程，采用MIT-0，完整许可见 `../LICENSE`。公开默认空业务模板；消费、销售、库存、采购及计算价格字段不是市场行情，不预置真实客户或门店经营记录。本版只读边界与空模板验证待实际执行，旧测试不能作新证明。

## 3.1 智能库存预警

家庭「第一瓶/下一瓶买什么」请用 `home.md` 第十二章，不能拿门店按销量补货算法代替家庭覆盖率决策。

触发：库存预警 / 该补什么 / 采购建议。

```text
输入：酒单(menu) + 销量(sales) + 库存(inventory) + 配方库(recipes)
1. 汇总每款酒总销量 → 按配方拆解 → 每种材料总消耗
2. 日均消耗 = 总消耗 / 有效统计天数
3. 可维持天数 = 当前库存 / 日均消耗
4. 建议目标库存 = 日均消耗 × 采购周期 × 安全系数
5. 建议采购量 = max(0, 建议目标库存 − 可用库存 − 已确认在途量)
输出：紧急(<3天) / 预警(<7天) / 充足(≥7天)
```

库存为空则提示「请先设置库存」；销量为空则提示「暂无销量数据，不能预测日均消耗」。不得编造预警天数、供应商或采购金额。日均消耗为零时不除零、不虚构即将断货；由用户说明是否停卖或需要人工最低库存。

```text
库存预警报告（计算时间：运行当天）
紧急补货：[材料]｜当前库存 [本机输入]｜日均消耗 [运行时计算]｜可维持 [计算值] 天
建议采购：[运行时计算数量]｜供应商 [本机私有选择/待确认]
需要关注：[同上]
库存充足：[同上]
采购清单总计：[运行时按价格口径计算；空数据则不报金额]
```

## 3.2 销量追踪

触发：销量 / 卖出 / 热门排行。

- 仅基于用户在本机私有副本中明确提供的 `sales.json`，支持日/周/月统计、按实际数据生成热门酒款列表、趋势与营收统计。
- 公开 `sales.json` 默认空，不包含旧门店销量、营收排行榜或周末增长结论。没有销量不得生成排行榜或把推荐热度当销量。
- 营收 = Σ(实际成交单价 × 实际销售数量)；价格缺失时说明不能计算，不能用公开合成售价冒充实际营收。

```text
销量报告（区间：[用户指定/有效数据日期]）
数据口径：[本机私有记录/无数据]
酒款：[标准中文名]｜杯数：[运行时汇总]｜营收：[有实际成交价才计算]
趋势：[据有效记录计算；不足则明确无法分析]
总营收：[运行时计算；无数据则暂无]
```

## 3.3 成本计算与跟踪

触发：成本 / 定价 / 毛利率 / 成本变动。

```text
材料单价 = 采购金额 / 对应可用容量（同单位）
单杯成本 cost = Σ(各材料用量 × 材料单价)
建议售价 = cost / (1 - target_margin)
毛利 = 售价 - cost
毛利率 = (售价 - cost) / 售价
```

`target_margin` 为0至1之间且小于1的比例，先询问目标，不默认承诺某个毛利水平。只含材料的计算属于「材料毛利」，不等于扣除人工、租金、损耗、税费后的利润。公开包 `prices.json` 是可计算的**合成价格**，仅测试计算流程；真实使用必须在本机私有副本按实际进价、容量、损耗与计价单位核对。

- `cost_history.json` 默认空：显示「暂无成本历史」；仍可按当前合成价格计算，但必须在结果中明确口径。
- 不在文档硬编码某品牌采购价、售价、涨跌幅或采购预算效率；价格示例一律调用当前数据运行时计算。
- 有真实私有成本历史时才比较价格变化；记录日期与供应商差异，不用公开第三方吧台售价反推原材料采购成本。

## 3.4 供应商管理

触发：供应商 / 进货 / 找谁买 / 比价。

`suppliers.json` 公开默认空。联系方式、合同价、进货记录仅在用户授权的本机私有目录管理；不得上传、作为共创投稿、反馈附件或公开发版内容。

## 九、常客档案

触发：常客 / 这位客人喜欢什么 / 记录客人。

- `customers.json` 公开默认空；示例使用「这位客人」「常客A」等泛化称谓，不保留旧客户姓名、昵称、联系方式、消费历史、偏好或过敏记录。
- 普通对话只在当前会话使用必要偏好。持久化前获得用户明确授权，写入本机私有副本，最小化字段。
- 不上传客户偏好、过敏信息、联系方式或经营记录；去掉姓名也不代表这类业务记录可公开。
- 健康安全提示可以在会话中执行，但不得借此汇总或公开个人健康资料。

## 十、数据看板

| 指标 | 数据来源 | 公开默认响应 |
|------|----------|--------------|
| 销量、日均销量 | `sales.json` | 暂无销量数据 |
| 营收、热销排行 | `sales.json` 实际记录 | 暂无经营数据，不生成数字/排名 |
| 成本趋势 | `cost_history.json` | 暂无成本历史 |
| 可维持天数 | `inventory.json` + `sales.json` | 数据不齐，暂不能预测 |
| 配方、节日、替换覆盖 | 对应知识文件 | 读取文件统计，不与经营业绩混用 |

## 日常使用：先建立私有副本

```text
首次使用
1. 备份旧技能与本机私有业务数据，保留目录分离。
2. 在授权的本机私有目录设置酒单、库存及实际价格，不改公开空模板。
3. 推荐/查询可直接使用；库存预测需要真实有效销量。
4. 打烊记录由用户确认后写入私有副本；脚本只读，不自动写入。

日常使用
开店 → 库存预警（数据不足如实降级）
营业 → 情绪推荐 / 配方查询（不按缺料删除灵感）
打烊 → 用户确认实际销量，按需本机留存
每周 → 有记录才做销量、成本与采购回顾
```

## 公开与本机边界

- 公开更新不覆盖本机私有目录；更新先备份，再比较差异，知识文件与业务文件分开合并。
- 明确区分用户授权本机写入、维护者编辑公开模板、用户手动提交已脱敏反馈；静态技能不负责自动同步或上报。
- 公开包内的价格、消费、销售、库存与采购模板不代表真实业务或市场行情；第三方公开吧台历史酒单价格仅是带日期的来源知识，见 `bars.md`。
