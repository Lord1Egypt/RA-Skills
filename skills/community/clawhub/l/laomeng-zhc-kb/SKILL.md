## 何时使用

- 问"ZHC 有多少关键字 / 内置函数 / 类型 / 错误码"，或"这个计数为什么是 44 不是 72"。
- 问某个 `[Exxx]` 报错的含义、触发条件与修法。
- 问契约字段怎么写、某语法形态的**正确写法**（例如函数定义、类型词位置）。
- 问"以哪份文档为准"、某版本改了什么的**权威记录**。
- 问门禁通过情况、冻结件与当前实现是否同源、能否回退。
- 需要定位工程内某主题的资料分布（契约域、门禁域、推理台账域……）。

不适用：需要实际跑通代码验证 → 交 `laomeng-zhc`；需要教学讲解 → 装 `laomeng-zhc-tutorial`。

## 二、标准检索流程

1. **判断问题类型**，走对应入口：

   | 用户问的是 | 走哪份 |
   |---|---|
   | `Exxx` 是什么、怎么修 | 错误码表 → 按码位查 |
   | 语法怎么写、有多少关键字 | 契约全量参考 → `①语法集` |
   | 版本号、冻结、能否回退 | 版本与冻结口径 |
   | 某个主题的资料在哪 | 知识库导航 → 按域浏览 |
   | 内置函数怎么用 | 快速参考（精确签名以契约 `④内置` 为准） |

2. **给出答案时必须带三件套**：结论 + 出处（哪个文件、哪个字段/码位）+ 版本前提。缺出处即视为不可信答案。

3. **遇到 `Exxx` 形态的关键词**，先走错误码表；错误码表未覆盖时明确回答"该码位未登记"，**不得编造**成因。

## 四、版本自证方法（被问"你这答案是不是旧的"时）

1. 用 `references/版本与冻结口径.md` 里的指纹核对：内核字节数、`md5[:12]`、`sha256[:16]`。
2. 报告"当前实现 vs 冻结件"是否同源。**不同源不等于错误**：冻结件是上一季度快照，实现已向前演进，这是既定路线，不允许靠改冻结件抹平差异。
3. 冻结面相关判据（如 C04 契约字节数比）保持红灯是**已知且允许**的状态，回答时必须如实说明，不得声称"全部通过"。

## 五、资料库自身怎么维护

本包 `references/知识库导航.md` 是工程知识库（226 条 / 11 域）的**精简导航**：只留路径与版本，去掉字节数与指纹列，以便控制在分发包体积内。

维护时机：
1. 契约升版或内部修订递增后 → 重渲染契约参考与错误码表；
2. 门禁新增通过报告、验证报告落盘后 → 重建导航；
3. 教程新增课次后；
4. 每次发包前核对本 SKILL.md 头部 metadata 与 references 头部是否一致（版本、修订、四项计数、码位数）。

## 六、引用规范

回答工程问题时：

- 引用文档用**相对工程根的路径**，例如 `方案\契约_1.8.json`、`方案\错误码库\错误码库.py`。
- 引用契约字段用点号路径，例如 `①语法集.语句形态`、`门禁核对.第4级门禁_4.5`。
- 引用错误码写成 `[E303]` 形式，并给出触发条件一行摘要。
- 不确定就说不确定：本技能的价值是**可追溯**，不是"什么都能答"。
