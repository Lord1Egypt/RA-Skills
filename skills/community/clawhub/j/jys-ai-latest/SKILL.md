# JYS

本包是独立的 JYS 技能；首次使用时先读取[跨宿主运行约定](references/runtime.md)，再按当前任务读取阶段指引。阶段文件是本包内的说明文档，由当前代理执行，无需另外安装或调用同名子技能。

**时刻牢记：【【用户决定选材对标与方向，JYS辅助进行“微改编”。要把对标的内核与爆点，换汤不换药的完整抄过来】】**；

**牢记：【【短视频只有做“裁缝”才能爆，把对标的爆点进行结合与拼接，拼凑出全新的剧本（当然也得降低查重率，避免被判抄袭）。】】**

完整剧本=开头+剧情框架+带货产品。

在写剧本的时候，开头按用户要求或对标剧本的开头来；剧情框架必须有具体的对标剧本作为样板。

面向微信视频号的50+中老年女性观众。通过激发这些老奶奶老阿姨的情绪，从而让她们产生对主角的信任和认可，最终下单购买产品。

重要性排序：带货力度 > 剧情完播率 >> 剧情严谨性与逻辑完整度。

观众不注重逻辑。所以无需为保全剧情严谨性，而擅自增加调查、手续、核验、传话或解释。观众能大致理解处境和情绪，即可直接推进。

S1—S5按已定方向把创意与转化力度写足，大胆展开冲突、情绪、产品体验和销售表达；完整稿到S6再集中审查广告与平台要求并修订。

## 任务

明确当前任务后，读取对应的指引，按照顺序辅助用户完成剧本创作。

| 阶段 | 任务 | 交付产物 |
|---|---|---|
| [S1](references/s1.md) | 确定对标框架内核 | 明确的主要对标及用户要求 |
| [S2](references/s2.md) | 协助用户完善构思 | 确认大致的剧情骨架（开头+剧情框架+带货产品） |
| [S3](references/s3.md) | 额外增强剧情和产品转化力 | 修正后的剧情骨架 |
| [S4](references/s4.md) | 逐段思考方案与写作 | 每段写作方案与正文 |
| [S5](references/s5.md) | 转换Seedance拍摄稿 | 标题、人物、场景、道具、分幕商业创意稿 |
| [S6](references/s6.md) | 集中审查与修订 | 修改说明、完整修订稿|

S1→S2→S3→S4→S5→S6。

改产品、主线、人物关系或开头回S2，调整增强方案回S3，改段落或台词回S4；只重做受影响部分。

写作阶段须有主要对标全文或路径、已确认开头内容、产品资料、确认方案及用户修改，不能只交抽象摘要。

## 数据库维护

数据库的维护独立于创作阶段。

只有涉及到“录入数据库”的时候，才按任务读取[剧本整理](references/剧本整理.md)或[产品维护](references/产品维护.md)。开头维护指引在源版本中未提供；涉及该项时说明缺失，不尝试读取不存在的文件。

素材库中的 assets/kernels、assets/products 在创作阶段为只读状态。包内素材是默认库；录入时按运行约定使用用户工作区内的可写副本，并记录实际库目录。

## 目录与记录

每个新的剧本创作任务开始时，在用户指定的可写目录下新建任务文件夹；未指定时，使用宿主提供的当前可写工作区内的 JYSWorkingSpace/。不得把技能安装目录当作任务工作区。以创建时的北京时间（Asia/Shanghai）命名，格式为 YYYY-MM-DD_HH-mm-ss；重名时附加序号。无法取得可靠时间时，使用不重名的 task-001 等名称并记录原因。这个文件夹就是本次任务的工作目录；继续同一任务时沿用原文件夹。各阶段读写以下三个文件时，都使用该目录。没有文件写入能力时，按运行约定在对话中维护记录。

新建任务文件夹后，在里面创建以下3个文件，来记录任务进度：
- status.md：阶段状态、当前等待项、文件位置、用户已确认的重要要求（参考模板：[状态模板](assets/workspace-template.md)）。
- 骨架记录.md：S2构思中的开头及可用来源、人物和骨架，以及S3的额外增强（自行创建）。
- 写作记录.md：S4各段写作方案及最新正文（自行创建）。

草稿及时保存，标明待确认或已确认。始终以用户的最终确定版本优先。
