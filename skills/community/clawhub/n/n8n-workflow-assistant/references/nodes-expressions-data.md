# 节点、表达式与数据语义

## 单项与多项

大多数节点会处理多个输入项；确认具体节点行为后再增加循环。Code的Run Once for All Items与节点Execute Once不同：后者可能在代码看到数据前只保留首项。聚合代码读取$input.all()时须回归多项输入。

$json表示当前输入；链路明确、字段直接来自上一节点时可以使用。$('Name').item依赖item linking；聚合、分支、重复记录及多对多关系后可能不唯一。first()只应在契约确为单项或整批共用信息时使用；不能用它压掉真实逐行差异。需要时携带稳定主键并显式关联，保留pairedItem或建立正确合流。

HTTP、文件提取、Aggregate及Code可能替换输入。为必需上下文定义字段清单，比较每个中间节点的入出数据；避免全量复制任意上游内容，也不要无声丢字段。

## 表达式

完整表达式模板与其中JavaScript是两层语法。复杂对象、嵌套花括号和字符串可能影响模板边界；语法编译通过不代表n8n解析通过。优先简化表达式并在目标实例预览/运行；离线工具可按目标版本配置真实解析器。

检查所有节点参数及错误返回分支，不只成功分支。引用的节点未执行时，用明确的分支结果协议或已验证的isExecuted惰性分支处理；不要取未运行节点后再catch吞错。

日期使用明确单位与时区。存储时间戳、用户显示时间和业务期限分别处理，避免宿主时区再次加偏移。创建、更新、事件发生及查询时间不可互相替代。

## Code与Merge

简单参数变化优先表达式，常见集合操作优先原生节点。复杂Code使用目标沙箱已支持的库；不能假设URL、URLSearchParams、任意require、网络和磁盘权限可用。离线VM不应额外注入线上没有的全局来掩盖故障。

Merge的输入数量、选择输入参数和输出端口索引以版本schema为准；参数值与connections数组索引未必同为零基。所有来源都必须连到正确输入，不应通过.first()掩盖未合流数据。

节点connections按源节点名和端口定位；rename节点后同步更新表达式与连线。错误出口必须接到能处理错误的后续路径。对最终请求体做断言，检查显式参数是否被后面的旧规则覆盖。
