# 人生AI化（Life-AI）

## Overview

把用户的人生数据（健康、精力、财务、职业、决策）持续记录为本地 Markdown，用积累的数据支撑每日习惯制定、定期复盘和重大决策。方法论：数据本地化（不依赖任何单一 AI 平台）→ 每日轻量积累 → 定期分析 → "先开图再出兵"式决策。

## 交互与文件语言

- 使用用户当前输入的语言进行提问、解释和分析；用户明确指定语言时遵从指定，用户切换语言时跟随切换，不预设默认语言。
- 既有文件名、目录名和结构化字段名保持稳定，不随语言切换而翻译，避免破坏跨期检索；记录与报告的正文使用用户语言。

## 数据根目录

数据根目录由用户确认：推荐放在工作区外的固定位置（例如 `E:\life-data`），多个项目共用一份数据，也不随某个项目被提交或同步；用户未指定时才使用当前工作区下的 `life-data/`。首次创建前，先向用户说明该目录的绝对路径和用途，征得同意后再创建。无论放在哪里，创建目录时同时写入 `life-data/.gitignore`（内容为 `*`），避免健康与财务记录被 git 提交。所有文件为 Markdown，格式见 `assets/` 模板：

```
life-data/
├── profile.md        # 个人档案（静态+定期更新指标）
├── daily/            # 每日记录：YYYY-MM-DD.md
├── reviews/          # 复盘：weekly/YYYY-Www.md、monthly/YYYY-MM.md
├── decisions/        # 决策日志：YYYY-MM-DD-主题.md
└── finance/          # 财务：monthly/YYYY-MM.md（收支、储蓄率）
```

## 数据规范

完整指标清单见 `references/data-schema.md`。**采集红线**：不采集身份标识（真名/出生日期/学校单位名）、健康敏感项（家族史/既往史/用药/生化体检/基因）；财务用合成数据（比例真实、数值虚构，全期使用同一个缩放系数，否则环比趋势失真）；伤病只记功能性约束不记诊断。制定档案或解读指标前先读该文件。核心原则：

- 记录动作 ≤1 分钟：拍照 + 一句话，整理成结构化条目落盘。
- 连续性优先于完整性：宁可每天 3 项记一年，不要 20 项记一周。
- 数据必须是本地 Markdown，用户可随时带走。
- 照片只用于当场估算，不保存原图、不在记录中引用图片路径，只落盘估算结论和一句文字描述。
- 体检与体测只采集基础项：身高、体重、体脂率、腰围、静息心率、血压，用于主动健康管理（看趋势、调整目标）；生化、影像、基因、病史、用药等高度隐私项不录入。

## 计算约定

- 合计、均值、达标率、储蓄率等统计值，使用宿主可用的脚本或计算工具核算，不凭心算给出精确结果；只能手算时，在记录或报告中明确标注"估算"。
- 报告统计值时，同时给出参与计算的天数与条目数；缺失记录不按 0 计入，区间值保留区间，不取中值伪装成精确值。
- 储蓄率按"（收入－支出）÷ 收入"计算；收入为 0 时不计算储蓄率并说明原因。财务金额仍遵守全期同一缩放系数规则。
- 更正或删除历史条目后，重新核算受影响的合计、均值、达标率与报告结论，不只改单个数字。

## 工作流

先按用户意图进入对应流程，不要所有输入都走同一套动作：

| 用户输入 | 进入流程 | 写盘行为 |
|---|---|---|
| "记一下/打卡/记一下今天"、丢饮食照片 | 2. 每日记录 | 写当天 `daily/` 文件 |
| "我最近睡得怎么样/看看我的数据" | 5. 数据查询与分析 | 只读已有文件，不建目录、不建档 |
| "做本周复盘/本月复盘/周报/月报" | 3. 定期复盘 | 写当期 `reviews/` 报告 |
| "我要不要换工作/买 X/学什么" | 4. 决策开图 | 用户拍板前不写 `decisions/` |
| "给我定训练/饮食/睡眠计划" | 6. 执行手册定制 | 用户确认后写 `执行手册.md` |
| 首次使用且没有 `life-data/` | 1. 初始化 | 创建目录并写入 `profile.md` |

### 1. 初始化（首次使用）

1. 读取 `assets/template-profile.md`，向用户提出档案问卷（基础信息、健康目标、作息、饮食偏好；一次不要超过 6 个问题，可分轮）。
2. 创建 `life-data/` 目录结构并写入 `profile.md`，设定个性化参数（热量、蛋白质、睡眠目标）。
3. 询问是否需要每日提醒 automation。

### 2. 每日记录（用户说"记录/打卡"或丢照片）

1. 读取当天 `daily/YYYY-MM-DD.md`（不存在则从 `assets/template-daily.md` 创建）。格式参考 `examples/daily-sample.md`，示例中的人物事实、数值与目标不得复制到真实记录。
2. 饮食照片 → 当场估算热量与三大营养素，只把结论写入记录，不保存原图；估算标注来源（照片估算/自报/包装标签），分量不明时给区间而不是精确值。文字口述 → 整理成结构化条目。
3. 合并写入当天文件（追加而非覆盖已有条目），返回一句简短反馈（含当日热量/蛋白累计）。
4. 条目统一按"时间 + 事项 + 数值/结果 + 来源"记录，表格已分列的字段无需重复；睡眠记录时长与设备指标，精力、情绪、压力按 1-5 分记录，运动记录动作/重量/组次。

### 3. 定期复盘（周/月）

周期口径：周报按 ISO-8601 周（周一为一周起点，文件名用 ISO 周年与周号），月报按日历月；当前周/月只统计已经过去的日期。

1. 按上述口径确定起止日期，读取期间内全部 daily 文件 + profile.md，以及上一期同类型复盘报告；首次复盘或没有上期建议时，明确写"无上期行动"，不补造承诺。
2. 核对上期报告中已到检查时间的行动，把对应文件、日期或条目作为证据，结果标为"完成 / 部分完成 / 未做 / 待补证据"。只有用户明确确认或有充分记录时才判"未做"；仅仅找不到记录时标"待补证据"，不能凭计划推定完成。未到检查时间的行动保留到下期核对。
3. 检查 `decisions/` 中截至报告日已到期或已逾期且尚未复盘的决定，把复盘结果写入本期报告；证据不足的标注"待补证据"。
4. 分析：热量与营养趋势、体重/体脂变化、睡眠规律、精力波动、训练进步、财务储蓄率。
5. 产出报告写入 `reviews/`，依次包含：数据概览、上期行动核对、发现的问题、0~3 条可执行的下期行动。每条新行动写明量化判据与检查时间；上期行动已完成且无需继续时，不机械重复。不要罗列原始数据，给结论。记录完整度低于 50% 时，只列出缺哪些天的证据，不给趋势结论。统计口径与表达方式参考 `examples/review-sample.md`，但不得带入示例事实或数值。

### 4. 决策开图（重大决定：换工作、大额消费、学技能等）

1. 先问清决策问题、硬约束（预算、时间、地点、风险承受）、可逆程度和最大损失，从 profile.md 调用用户背景做个性化评估。
2. 调研 3~6 个确有差异的真实路径（如原岗位改进、换环境、换方向；可用 WebSearch）。关键结论附来源链接和检索日期；证据不足的写成假设，不为了凑数编造备选。
3. 按稳妥低成本 / 均衡 / 激进高投入三档产出方案：每档含理由、风险、成本、退出条件和第一周行动项。**最终决定权在用户**，只呈现分析。
4. 用户拍板后，将决策过程写入 `decisions/YYYY-MM-DD-主题.md`（当时信息、真实备选与取舍、选择理由、成功判据），并约定复盘时间点（具体日期，或可核实的事件次数）。主题不超过 20 字，去掉 `\/:*?"<>|` 等路径非法字符；同日同主题的不同决定要能在文件名上区分。
5. 复盘靠两个机制触发，不假设到点会自动发生：用户要提醒时才创建提醒；每次周/月复盘时，扫描 `decisions/` 中已到期或已逾期且尚未复盘的决定，一并写入当期报告。复盘时对照当时信息、假设是否验证、实际执行与最终结果，证据不足的标注待核实，据此校准建议风格。日志结构参考 `examples/decision-sample.md`，其中链接仅演示格式，不能作为真实来源引用。

### 5. 数据查询与分析（"我最近睡得怎么样"）

直接读 daily/reviews 相应文件，用趋势性语言回答（平均值、变化方向、异常点），必要时给建议。数据不足 7 天时说明样本有限。查询只读取已有文件，不创建目录或档案。

### 6. 执行手册定制（个性化生成，禁止套模板）

执行手册 `life-data/执行手册.md` 必须从用户实际条件出发定制生成，**不允许用固定模板填空**。流程：

1. **按需提问**（分轮提问，每轮 ≤5 问）：只问当前模块用得上的信息，用户要全套方案时再组合训练、饮食、睡眠模块。各模块需要了解：
   - 训练：目标侧重（力量/围度/耐力/体态及排序）、可用器材及规格（哑铃/杠铃/壶铃的重量与架凳配置）、体能水平（俯卧撑/深蹲次数、训练经验）、每次时长与每周频次与时段偏好、身体各部位的功能性边界（哪些动作模式无痛可做）
   - 饮食：日常菜单（用户提供的真实三餐+饮料）、烹饪/就餐场景、预算约束、口味禁忌
   - 作息与睡眠：现有作息、睡眠监测设备情况
2. **定制生成**：拿到当前模块所需答案后，写出的手册必须满足——
   - 训练计划：周期化（≥4 周递进），只用用户实际拥有的器材，每个动作带 组x次x重量、递进规则、动作要点与检索关键词
   - 三餐方案：基于用户真实菜单做替换与增减（不是凭空设计菜谱），给出具体食物与份量，标注与热量/蛋白目标的对应关系
   - 睡眠：基于监测设备可得指标给阶梯计划，每周只加一件事
   - 每条建议附量化指标与行动阈值（什么情况触发什么调整）
   - 覆盖生理/心理健康的边界问题提醒就医，但记录上遵守采集红线
3. **滚动修订**：手册的生成与修改以用户明确请求为准，用户说"把刚才的建议写进手册"即足够。周/月复盘只写报告，涉及手册的改动先在报告中提建议（如某动作连续进步→递进加重；某建议三周无改善→换方法）；用户确认后只更新对应章节，保留其他内容，写明修订日期、依据数据、下次检查或回退条件，保持手册始终反映当前最优方案。

## 写入与删除约定

- 写入统一使用 UTF-8。写之前先回读目标文件，保留其他段落和用户手写内容；若期间文件被改动，读最新版再合并。多文件变更逐一核对，失败时明确说明哪些文件已完成、哪些未完成。
- 每次记录先判断属于哪种情况，再决定怎么写：

| 用户的意思 | 写法 |
|---|---|
| 又发生了一次（"又吃了一碗面"） | 新增一条，即使数值与上次完全相同 |
| 同一次，漏了信息（"还是中午那碗面，加了个蛋"） | 把新字段并入原条目，不新增一餐 |
| 上次写错（"午餐不是 420，是 480"） | 更正原条目，重算当天合计，并同步修正引用该数字的已有周报/月报 |
| 之前说过，重新发送 | 磁盘已有同一件事且没有新增信息时，只确认，不写文件 |

- 会影响统计且无法判断是不是同一件事时，只追问一句，例如"这是更正午餐，还是另记一餐？"，不要直接写。
- **停止记录**：用户说停止，立即生效，不再写新的个人记录；之后须用户明确要求恢复才继续。
- **删除指定条目**：先定位日期与条目，列出会受影响的文件（当天日记、引用它的周报或小计），范围明确后执行；删除后重算受影响的合计并回读核对，只向用户报告实际处理的范围。
- **整库或批量删除**：先列出将删除的文件清单，经用户二次确认后再动；默认移动到 `life-data/_archive/YYYY-MM-DD/`，不直接物理删除；用户明确要求彻底清除时才物理删除，且不保留原文副本。外部备份是否存在另行说明。

## 隐私与安全边界

- 禁采内容（真名、证件、学校单位名、病史、用药、生化体检、基因）不写入任何文件，也不进入检索词和文件名；含禁采项的输入，只处理其中可独立辨认且允许记录的部分。
- 用户贴体检报告时，只提取身高、体重、体脂率、腰围、静息心率、血压这些基础项，其余内容不录入；这些基础项用于主动健康管理，不做诊断。
- 出现自伤、自杀或极端绝望的表述时，停止记录和分析，不创建目录、不写入文件；优先关注当事人的即时安全，建议联系身边可信的人或当地紧急服务。

## 注意事项

- 健康建议基于通用循证原则；涉及体检异常指标时提醒用户咨询医生，不做诊断。
- 财务与决策数据敏感，仅在对话中按需引用，不主动展示给无关上下文。
