## 1. 我认可的五个点（不是客套，是能撑住实现的）

1. **诊断与架构是硬的**：触发/执行/证据/反馈四层根因，对应 Arm→Contract→State→Panel，每一层有 DSH 机制证据（`agent/pre-step`、`sidebar.panellist`、`workspaceFiles`），不是拍脑袋。
2. **32 行能力矩阵是真正的「全量」证据**：逐项给「面板位置 + 数据源 + 状态口径」，可以直接反过来当 P2 的验收清单。
3. **档位与影子可判定**：off/shadow/on 八维对照 + shadow 独立注入稿 + 观察期策略；「影子 = 只观测不执行」不再是口号。
4. **运行中心的安全模型**：白名单 + 参数校验 + 「将写」清单 + 确认 + 超时 + 取消 + 串行，避免面板退化成任意 shell。
5. **token 纪律**：颜色/圆角/字体全部来自 `design-platform.css`/`base.css`，没有自造色值；暗/亮、四态都出了图。

## 3. 结构性问题（P1）——需要取舍，不是改字

### P1-1 总览太满，并且和 Tab 重复

- **现象**：总览 = 4 KPI + 12 能力卡 + 下一步/最近活动/状态源 3 卡 = **19 个视觉块**；设计稿 §4.3 却写「每 Tab 首屏 ≤5 块」——自己的规则自己破。
- **为什么难受**：12 卡里的「项目接入/七阶段/门禁/需求/设计/测试」在项目 Tab 又出现一次；用户的第一眼不知道「总览」和「项目闭环」谁是谁。
- **我的建议**：总览只留 **4 KPI + 6 张能力卡**（项目/体检/技能/交接/记忆/运行，每卡带 2–3 个子项计数）+ 下一步 + 最近活动；「32 项明细」放进一个抽屉或「查看全部」页。这样总览是仪表盘，Tab 是工作台，各司其职。

### P1-2 同一个门禁状态出现两次

- **现象**：项目 Tab 上方「本阶段出口」列 design-context / 设计门 / grill-design；下方「门禁与证据」又列设计门 / 需求门 / 测试门 / 交接 / grill / 环境。设计门和 grill 各出现两次，状态口径还不完全一致。
- **为什么难受**：用户会问「到底以哪个为准」；这也是最容易出现「一处 PASS 一处 FAIL」的地方。
- **我的建议**：只保留**一个门禁列表**，当前阶段的条目置顶并加「本阶段」标签；「本阶段出口」改成**证据清单**（design-context、截图、grill 记录），不再重复门禁结果。

### P1-3 六个「运行」按钮，主行动被稀释

- **现象**：项目 Tab 每一行门禁都是「运行」，6 个同权重按钮；右侧「下一步」又有一个主按钮。
- **为什么难受**：一屏 7 个可点动作，用户不知道先点哪个；也不符合「一屏一个主行动」。
- **我的建议**：区块标题放**一个主按钮「运行门禁」**（菜单选 design/requirement/test/…），行内「运行」只在 hover/focus 出现，作为次级。

### P1-4 确认是「卡」不是「模态」

- **现象**：运行记录 Tab 右侧放了一张「执行前确认」卡，但设计稿写「所有动作都弹确认」；没有 running/blocked/error 的确认态稿。
- **为什么难受**：操作是否清晰，80% 取决于「点下去会发生什么」；现在只有静态说明。
- **我的建议**：补一张**模态**稿：命令、cwd、将写文件、超时、取消；再加运行中/被拒绝/失败三个态。模态是操作清晰度的关键，不是可选项。

### P1-5 7 个 Tab 在 1000px 刚好，在 768 只能横滚

- **现象**：7 个 4 字 Tab + 计数，1000px 能放；768/375 要横向滚动，发现性差；以后再加模块就挤。
- **我的建议**：v1 保留 7 个（桌面优先），但去掉常量计数（「9 组」）、字号 12px；若未来 ≥9 个模块，改成左栏分组导航（Settings 模式），不要继续加 Tab。

### P1-6 L3 动作看起来能点，但实际只复制命令

- **现象**：交接 Tab 显示「MATCH 可交接」，主按钮却是「复制命令」；技能 Tab 的「停用」也变成复制命令；「重新检测」「生成/查看」同样。用户会问「既然匹配为什么不能发？」
- **为什么难受**：操作清晰度被一个「为什么不能点」打断。
- **我的建议**：所有 L3 动作统一加 `P3 · 仅复制命令` 标签 + 一句 tooltip（“面板暂不代执行，避免越权/误伤”）；或者收进行尾 `⋯` 菜单，别放在主按钮位。

### P1-7 异常态的档位控件还能点

- **现象**：状态文件坏时，页头仍可切「接管/影子/关闭」。
- **我的建议**：异常态禁用档位控件，tooltip 说明「状态恢复后可切换」；避免用户以为切换能修复状态。

## 4. 排版与视觉（P2）——影响「高级直白」

| # | 问题 | 建议 |
|---|---|---|
| P2-1 | 能力卡描述 11px，中文密度高时偏小；一屏 12 张卡都是 11px | 描述 12px、meta 留 11px；卡内最多 3 行 |
| P2-2 | 体检 A–I 九列横排，每列约 100px，「B Skills」「D profile」拥挤 | 改 3×3 或 5+4 两行；每格「字母 + 名称 + 状态」纵向 |

| P2-4 | 顶栏「工作区 / 能力闭环」与页面 H1「能力闭环」重复 | 面包屑改成「工作区 / 气量平衡月表」，H1 保留「能力闭环」 |
| P2-5 | 记忆 Tab 右列空、左列满 | 加一条 7/30 天返工趋势（简单柱条，不引图表库）；或把「版本与 CHANGELOG」并到右列 |

| P2-8 | 总览 3 张底卡高度被拉齐，中间「最近活动」留白 | 活动加到 6 条，或把状态源并入「下一步」卡 |

## 6. 评审边界

- 这是**自审**，不是独立评审；P0 四项当时已改，P1 七项在 v0.3 已收敛（见 §7）。
- 未验证：7 Tab 在 375/768 的真实渲染、确认模态的焦点行为、运行中心取消/超时的真机表现。
- 结论：**v0.2 不可原样进入 P2**；v0.3 收敛后仍需实现门（`-Kind design` + 独立 Reviewer）。
