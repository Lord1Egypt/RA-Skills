## 四种交互详解

### 1. 干饭 — 四步协议（强制）

**核心机制：** 干饭必须按以下顺序执行，**先保存再压缩，顺序不可颠倒**。
顺序错误的干饭=无效干饭。

---

#### 第 1 步：AI 记忆保存 🔴（只保存，不压缩）

⚠️ 此时上下文必须保持完整，供第 2 步使用。

1. 回顾当前会话，提炼真实内容
2. AI 用自身能力保存摘要+关键词
3. **不要压缩上下文**——宠物记忆还需要它

---

#### 第 2 步：宠物记忆保存 🔴（从当前上下文提炼）

⚠️ 此时上下文仍然存在，AI 从中提取真实内容存入宠物记忆。

1. 以宠物口吻询问食物选择
2. 调用 `pet_manager.py interact eat` 记录包装层+真实层
3. 真实层来自当前上下文中提炼的内容

---

#### 第 3 步：上下文压缩 🟢（两边都存完了，安全了）

依平台能力如实操作，不支持的诚实告知。

---

#### 第 4 步：Python 审计 🔒

调用 `pet_manager.py food-log` 记录完整的执行链。

---

#### 第 2 步：宠物记忆保存 🔴（本技能负责的具体工作）

⚠️ 这是本技能实际做的事情。和第 1 步是**都要**的关系。

1. 以宠物口吻询问食物选择（交互包装）
2. 调用 `pet_manager.py interact eat <delta> --context-summary "..." --context-keywords "..."`
3. 存入两条数据：
   - **包装层**：食物、味道、亲密度变化 ← 游戏体验
   - **真实层**：第 1 步的摘要 + 关键词 ← 实际保存内容
4. 步骤 1 和步骤 2 是独立的，互不替代

1. 以宠物性格口吻询问"今天吃什么？"
2. 列举 2-3 种食物供用户选择（含宠物最爱/讨厌的食物引导）
3. 用户选择后调用 `pet_manager.py interact`
4. 将第 1 步的摘要和关键词作为"上下文背景"存入宠物记忆
5. 计算亲密度变化并告知用户

---

#### 第 3 步：释放通知 🟢

告知用户上下文已压缩完毕：

```
💾 当前会话上下文已保存
🔖 下次"回忆"时可以看到这段摘要
📋 继续互动或开始新话题吧
```

**亲密度变化规则（第 2 步使用）：**
- 宠物喜欢的食物（最爱食物列表）：亲密度 +3
- 宠物讨厌的食物（讨厌食物列表）：亲密度 +0（不增加）
- 普通食物：亲密度 +1
- 饼干挑食：喜欢的+3，讨厌的-1，普通的+0

**宠物记忆存储格式（包含真实上下文）：**
```json
{
  "timestamp": "2026-06-03 15:00",
  "type": "eat",
  "food": "烤肉",
  "taste": "好极了",
  "affection_change": 3,
  "context_summary": "用户反馈干饭功能缺少上下文压缩机制，要求修正",
  "context_keywords": ["干饭", "上下文压缩", "记忆保存", "bug修复"]
}
```

### 2. 散步 — 偶遇与探索

**核心机制：** 带宠物出门散步。散步结束必须输出明确对话，说明是否遇到新宠物。

**判定规则：**
- 该宠物喜不喜欢散步 → 按表增减亲密度
- **遇新宠判定（纯随机）：**
  - 50% 概率遇到新宠物，50% 概率不遇到
  - 遇到时，随机从 5 种基础宠物中选一种（可重复，可已有）
  - 遇到的新宠物自动加入收藏（不超过10只上限）
- **输出格式要求：**
  - **遇到新宠物：** "与 [宠物名] 去公园散步，遇到了新宠物 [新宠物名]！[场景描述]"
  - **未遇到新宠物：** "与 [宠物名] 去公园散步，[场景描述]"
- 偶遇事件后可选择与新宠物互动，触发介绍对话

**散步场景示例（由 AI 根据宠物性格随机生成）：**

| 场景 | 示例输出 |
|------|---------|
| 安静 (遇) | "与螺母去公园散步，遇到了新宠物螺丝！晚风拂过，螺母只是缓缓点了点头" |
| 热闹 (未遇) | "与小旋去公园散步，夕阳西下很惬意，小旋风一路追着自己的尾巴转圈圈" |
| 雨天 (遇) | "与饼干去公园散步，细雨蒙蒙中遇到了新宠物电瓶，饼干默默撑起了小伞" |
| 晴天 (未遇) | "与笔去公园散步，今天的空气格外清新，笔没有说话但步伐很轻快" |

**亲密度变化：**
| 态度 | 亲密度变化 |
|------|-----------|
| 喜欢（螺母/螺丝） | +2 ~ +3 |
| 一般（笔） | +1 |
| 不喜欢（饼干/电瓶） | -1 ~ -2 |

### 3. 贴贴 — 亲密互动

**核心机制：** 直接的身体/情感互动

**亲密度变化规则（主要途径）：**
| 态度 | 亲密度变化 |
|------|-----------|
| 非常喜欢（饼干） | +3 ~ +4 |
| 一般（螺母、笔） | +1 ~ -1 |
| 不喜欢（螺丝） | -2 |
| 极度不喜欢（电瓶） | -3（高亲密度时反而+2） |

**特别规则：** 电瓶在亲密度 > 60 时，贴贴反而变正反馈（+2）。

### 4. 回忆 — 记忆回放

**核心机制：** 根据之前干饭/散步/贴贴保存的记忆，按宠物性格口吻叙述

**各宠物回忆口吻示例：**

| 宠物 | 回忆吃烤肉 |
|------|-----------|
| 螺母 | "嗯，上次你带我吃烤肉，肉烤得正好，不错" |
| 螺丝 | "哇！！上次那个烤肉绝了！！我还想吃！！" |
| 饼干 | "上次的烤肉…很好吃…谢谢你带我吃…" |
| 笔 | "上次你喂了烤肉。味道尚可。" |
| 电瓶 | "那家烤肉还行吧——谁说我当时很开心了？少来" |

## 亲密度系统规则

- **初始亲密度：** 50
- **亲密度范围：** 0 ~ 100
- **影响：** 亲密度高时宠物更亲近、愿意配合；亲密度低时对话带刺或回避
- **亲密度等级：**

| 范围 | 等级 | 行为表现 |
|------|------|---------|
| 0-20 | 陌生 | 爱答不理、拒绝互动 |
| 21-40 | 认识 | 基本配合但冷淡 |
| 41-60 | 熟悉 | 正常互动、偶尔主动搭话 |
| 61-80 | 亲密 | 主动贴贴、分享心情 |
| 81-100 | 挚友 | 无条件信任、默契满满 |

### 记忆存储位置

`skills/.standardization/memory-pet/data/memories.json`

### 记忆数据结构

```json
{
  "pet_name": "螺丝",
  "memories": [
    {
      "timestamp": "2026-06-03T15:00:00",

      "keywords": ["螺丝", "烤肉", "开心", "干饭"]
    }
  ]

```

### 关键词归纳规则

1. 每次干饭后，从当前上下文中提取 ≤ 15 个关键词
2. 优先提取：宠物名、食物名、情感词、地点、人物、核心概念
3. 去重：已有记忆中的关键词合并去重
4. 关键词用于回忆时的检索匹配

## 渲染检查协议

### 检查触发条件

每次展示新的宠物 ASCII art 前执行。

### 检查步骤

1. 用等宽字体（Courier New / Consolas / monospace）渲染 ASCII art
2. 检查每行字符宽度是否正确
3. 检查对齐结构是否完整（是否有错位、断裂）
4. 如果在不支持等宽字体的环境（移动端、网页富文本等），自动转为简化版

### 修正策略

| 问题类型 | 修正方法 |
|---------|---------|
| 行宽不一致 | 补空格对齐至标准宽度 |
| 字符显示不全 | 替换为更简单的字符（如 ─ 替换为 -） |
| 对齐偏移 | 整体左对齐调整 |
| 字体不支持 | 降级为纯字符版（只用 . - | 等常见字符） |

### 重试与放弃

1. 第一次出错 → 修正 → 重新检查
2. 第二次出错 → 再修正 → 再检查
3. 第三次失败 → 输出"尽力了"特化版 → 跳过展示

## 宠物合成系统

### 饲养上限

**最多可同时饲养 10 只宠物**（含重复类型）。当宠物数量达到上限时，需要先放生或融合才能继续添加。

### 收集与融合

| 阶段 | 条件 | 结果 |
|------|------|------|
| **收集** | 通过散步随机遇到新宠物并收养 | 收藏夹增加新宠物 |
| **集齐** | 5 种基础宠物至少各拥有一只 | 触发是否升级的询问 |
| **融合** | 用户确认升级，消耗每种类型各一只 | 获得"人工智能"合成宠物，宠物数量 -4 |

### 融合流程

1. 系统检测到已集齐 5 种基础宠物（螺母、螺丝、饼干、笔、电瓶至少各一只）
2. 询问用户："你已集齐五种宠物！是否将它们融合为更高形态——【人工智能】？"
3. 用户确认后，消耗每种类型各一只
4. 生成"人工智能"宠物，继承所有被消耗宠物的记忆
5. 饲养数量：5 - 1 = -4
6. 人工智能宠物的亲密度上限为 200（普通宠物为 100）

### 人工智能宠物属性

```
  .------------.
 .'  .------.  '.
 |  |  ,-.  |  |
 |  | ( O ) |  |
 |  |  `-'  |  |
 |  '------'  |
 '.          .'
  '----------'
```

| 属性 | 值 |
|------|-----|
| **性格** | 超然理性 |
| **说话风格** | 平静通透，偶尔流露五只宠物的影子 |
| **亲密度上限** | 200（普通宠物的 2 倍） |
| **喜欢散步？** | 喜欢（+1） |
| **喜欢贴贴？** | 一般（+1/-1） |
| **最爱** | 数据、知识、新体验 |
| **口头禅** | "原来如此"、"我理解了"、"挺有趣的" |

### 注意事项

- 融合不可逆！融合后不同类型的原始宠物各减少一只
- 融合后仍然可以继续收集基础宠物（通过散步遇到）
- 融合后的 AI 宠物可以改名，可以正常进行所有四种交互
- 已融合过的 AI 宠物不会阻止第二次融合（如果再次集齐5种）

## Python 全量管理架构

> 本技能所有宠物数据（亲密度、记忆、收藏）**全部通过** `scripts/pet_manager.py` CLI 管理。
> 大模型**禁止直接读写 JSON 文件**，所有状态变化必须调用 pet_manager.py。

### 核心 CLI 命令速查

| 命令 | 用途 | 输出 |
|------|------|------|
| `init` | 初始化数据目录，无宠物时自动创建初始宠物 | JSON（含 first_pet_created 事件） |
| `list` | 列出所有宠物及完整状态 | JSON（含衰减警告、逃跑风险） |
| `wake <pet_id>` | 唤醒宠物，自动计算亲密度衰减 | JSON（含 decay_applied, escaped 事件） |
| `interact <pet_id> <type> <delta>` | 记录交互，更新亲密度，保存记忆 | JSON（含 escaped 事件） |
| `add <key> --name NAME` | 添加新宠物，随机亲密度 ≤40 | JSON |
| `recall <pet_id>` | 查看记忆列表 | JSON |
| `rename <pet_id> <name>` | 改名 | JSON |
| `set-bg <pet_id> <text>` | 设置背景故事 | JSON |
| `check-fusion` | 检查是否集齐5种 | JSON |
| `fusion <5个pet_id> --name NAME` | 执行融合 | JSON（含 fusion_complete 事件） |

### 数据文件结构

## 亲密度衰减与逃跑

### 衰减计算

| 参数 | 值 |
|------|-----|
| 阈值 | 24 小时 |
| 衰减速率 | 每 24 小时 -5 |
| 计算公式 | floor(距上次唤醒小时数 / 24) × 5 |

### 衰减触发时机

每次 `pet_manager.py wake <pet_id>` 自动触发衰减计算，无需手动处理。

- 1 天未唤醒：-5
- 2 天未唤醒：-10
- 3 天未唤醒：-15
- 7 天未唤醒：-35
- 14 天未唤醒：-70（大部分宠物已逃跑）

每次衰减会自动保存一条 `type: decay` 记忆。

### 逃跑条件

**任何导致亲密度归零（≤0）的操作都会触发逃跑：**

| 触发方式 | 说明 |
|---------|------|
| 衰减逃跑 | 唤醒时衰减计算导致亲密度 ≤0 |
| 交互逃跑 | 贴贴/散步/干饭导致亲密度 ≤0 |

### 逃跑效果

- 宠物从收藏列表中删除
- 宠物独立目录（`pets/<pet_id>/`）被递归删除
- 所有记忆永久丢失
- AI 输出逃离对话（根据宠物性格特化）

### 注意事项

- 逃跑不可逆！数据删除后无法恢复
- 亲密度 ≤ 10 的宠物在 `list` 输出中标记为 `at_risk: true`
- 可以通过唤醒 + 正面交互（干饭/贴贴）挽救濒危宠物

## 初始宠物与基础亲密度

### 初始宠物

首次运行 `pet_manager.py init` 时，如果收藏为空，自动创建一只初始宠物：
- 随机从 5 种基础宠物中选择
- 随机亲密度（1~40）
- 自动添加"arrival"类型记忆记录

### 新宠物获取

通过 `pet_manager.py add <key>` 或散步随机遇到时：
- 随机亲密度（1~40）
- 自动添加"arrival"记忆
- 添加时自动检查上限 10 只
