# 架构、模式与证据

## 选择模式

| 模式 | 核心链路 | 首要核验 |
|---|---|---|
| Webhook | 接收→校验→处理→响应 | 谁返回HTTP、哪些分支会响应、超时预算 |
| API同步 | 触发→读取→映射→写入→回读 | 分页、目标主键、增量游标与重试幂等 |
| 定时 | 调度→拉取→处理→汇总 | 时区、重复触发、上次状态与告警 |
| 批量 | 输入账本→处理→逐项结果→汇总 | 来源位置、全部记录、失败项与速率限制 |
| 异步任务 | 保存并回读→派发→处理→轮询 | 真正持久化、身份/任务隔离、游标和恢复 |
| AI编排 | 确定性路由或Agent→有限工具→结果 | 模型/工具绑定、状态边界和副作用 |

不默认使用Agent。步骤明确的工作交给普通工作流；只有依赖文档的答案才引入RAG，动态工具选择确有收益时才用Agent。异步架构应由实际耗时与交互需求决定，不为简单任务无故新增任务表。

## 证据优先级

目标实例的最新导出、实际节点schema及运行记录优先；文档应匹配部署版本。没有MCP时使用已见过的typeVersion做最小修改，未知节点不猜schema。新建流程可给可配置候选，并标明尚未验证的映射。

MCP存在时先发现能力，再查询节点、操作和动态选项；不假定工具名称、连接凭据或项目/文件夹相同。多实例操作先固定目标实例，不能因一个工具会话存在就猜当前环境。新建、修改后重新读取工作流并比较节点和连线。

## 复用与可读性

只有复用、隔离、测试或独立工具边界确有价值时才抽子工作流；仅为了画布整齐可用命名与分组。子流程定义输入输出，不把内部存储字符串外泄成不透明壳。保留工作流名称、说明和人类可读节点名，注明业务原因及外部资源。

性能先量测瓶颈。多个分支不保证并发；每次真实并发都要检查版本执行语义、速率限制和数据竞争。不得把异步派发当作完成，或把批量大小当业务总量上限。
