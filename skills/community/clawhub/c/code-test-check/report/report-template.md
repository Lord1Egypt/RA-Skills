## 五、验证说明与局限性

- **验证范围**：仅对 `{{后端源码根目录}}` 与 `{{前端源码根目录}}` 当前代码版本进行静态分析。
- **无法覆盖**：
  - 运行时动态行为（配置开关、权限控制、异步任务）
  - 数据库数据依赖的逻辑分支
  - 第三方服务交互
- **建议**：本报告作为测试设计的参考输入，未实现/偏离的功能点应作为测试重点，但不能替代实际运行时测试。

## 报告生成要点

1. **代码证据必须可点击**：使用 `file:///` 绝对路径 + `#L行号` 锚点，方便跳转
2. **代码片段要精炼**：只贴与功能点直接相关的关键行，删除无关代码
3. **状态标记要一致**：全程使用 ✅⚠️❌🔀 四种标记，不混用其他符号
4. **客观陈述**：说明部分基于代码事实，不加入主观推测
5. **遗漏优先**：未实现和偏离的功能点要醒目突出，这是报告的核心价值
