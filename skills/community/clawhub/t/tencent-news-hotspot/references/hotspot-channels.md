## 2. 领域词到频道的映射

用户通常说领域而不是频道名，按以下规则解析：

- 直接命中频道名、别名或 `pool_tag_id` → 直接传入 `--channel`。
- 一个领域对应多个频道时逐频道取数后合并去重，例如「财经股票」→ 财经 + 股票。
- 同义/上下位词按最贴近的已知频道解析，并在回复中说明实际查询的频道；无法确定的先说明候选频道，不猜 id。
- 用户给的领域不在上表内时，回复「热点精选当前支持的频道中没有该领域」，并列出已知频道供选择。

## 3. 时间范围

CLI 只提供 `--today`，没有日期区间参数：

| 用户表述 | 执行方式 | 回复要求 |
|---|---|---|
| 今天 / 今日 | `hotspot premium <频道> --today` | 当日无数据时说明当日暂无精选，不去掉 `--today` 后仍称「今天」 |
| 本周 | 取数后按 `timestamp` 截取本自然周 | 写明起止日期 |
| 近期 | 取数后按 `timestamp` 截取（默认近 7 天） | **必须写明实际采用的天数**，不使用含糊表述 |

条目不足时按 `has_more` 与 `--page` 翻页补充，翻到没有更多或达到目标区间为止。

## 4. 输出整理

- 每条固定输出五项：标题（`title`）、发布时间（`timestamp` 转北京时间 `YYYY-MM-DD HH:mm`）、来源（`user_info.nick`）、文章链接（`url`，写成 `[标题](url)` 的 Markdown 超链接，不输出裸 URL）、摘要（`abstract`，较长时取开头约 60–80 字并加 `…`）。
- 字段缺失时写「接口未返回发布时间」/「接口未返回来源」/「接口未返回摘要」，不猜测、不用标题或正文补足。
- 多频道合并后按 `id` 去重、`timestamp` 倒序；同一篇出现在多个频道时保留一条并注明所属频道。
- 只整理接口实际返回的内容，不用模型记忆或其他数据源补齐条目。
- 结尾「查看更多」：统一引导腾讯网，写成 `[查看更多](https://www.qq.com)`。接口当前未下发频道 id，不拼造频道地址；**这个原因不写进给用户的回复**。

## 5. 边界与已知限制

- 频道清单随运营调整；发现 CLI 返回了未知频道时以 CLI 值为准，并可在回复中标注该频道不在本表副本中。
- 各频道精选更新频率不同，「今日」可能为空；此时如实说明，不用其他频道内容填充。
- 精选内容是编辑运营产物，不代表事件全貌；不做事实核查（事实核查使用 `jiaozhen-factcheck` 等专门能力）。
