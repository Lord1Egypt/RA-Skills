## 二、梯队详解

### ⭐ opt-in（Phase 0 勾选启用）：真开放、无需申请、直接用

#### OpenAlex（强烈推荐）
- **性质**：全球最大免费学术元数据平台（[openalex.org](https://openalex.org)），标引 4.7 亿+ 成果
- **API**：完全免费、**无需 API Key**、REST 接口
- **中文文献覆盖**：收录大量中文学术期刊/学位论文（通过 Crossref/DOI 及中文出版商数据源）
- **能力**：按标题/作者/机构/主题/引用检索，支持全文搜索、过滤、分页
- **用法**：`GET https://api.openalex.org/works?search=人工智能&per-page=20`
- **适合**：文献计量、开题调研、引用分析

#### Crossref（强烈推荐）
- **性质**：DOI 注册机构（[api.crossref.org](https://api.crossref.org)），全球文献元数据
- **API**：免费、无 Key、REST 接口
- **能力**：按 DOI/标题/作者检索论文元数据
- **用法**：`GET https://api.crossref.org/works?query=深度学习&rows=20`
- **适合**：查 DOI、找英文文献元数据、引用格式

> **以上两者默认关闭**，须主人在 Phase 0 **显式勾选**才调用；未勾选或选「④全部拒绝」则不调用。

### 🔧 仍为可选（默认关闭）：抓取层

#### 中国科技论文在线（paper.edu.cn）
- 教育部主办，**开放存取（OA）** 平台，[paper.edu.cn](https://www.paper.edu.cn)，110 万+ 首发/期刊论文
- **没有公开 REST API** —— 可走网页抓取（Firecrawl）
- **默认关闭**；需主人 Phase 0 显式勾选 + 自配 `firecrawl_api_key`（宿主侧）
- **适合**：中文论文全文获取（检索摘要可抓，全文 PDF 直链）

## 三、启用条件（Phase 0）

- **默认层**：默认启用；**中文层（OpenAlex / Crossref）**：**默认关闭，Phase 0 显式勾选才用**。主人在 Phase 0「外部服务同意 4 选 1」中若选 **④全部拒绝** → 本次运行**不调用任何检索工具**（含 OpenAlex/Crossref）。
- **抓取层（paper.edu.cn / Firecrawl）**：可选、默认关闭。凭据由主人**在论衡运行环境之外**为相应客户端自行配置；**论衡 agent 不读取、不存储、不传递任何凭据值**，只消费主人投喂的**不含凭据**的抓取结果。

## 四、合并策略（去重）

| 字段 | 匹配规则 |
|------|---------|
| URL | 完全相同 |
| DOI | 完全相同（OpenAlex/Crossref/学术插件都有 DOI） |
| Semantic Scholar paperId | 完全相同（同一论文跨来源的稳定身份键） |
| 标题 | 编辑距离 < 10%（防止不同来源抓的同一论文略有差异） |
| 作者+年份+期刊 | 三元组相同 |

```

- 来源：web_search + Crossref（合并去重，opt-in 已勾选）

```

## 六、化弊为利

- **弊端**：「证据底座局限于中文」→ **不存在**，因为中文层是「并行补充」不是「替代」
- **利好**：中文文献更全（OpenAlex/Crossref 覆盖 4.7 亿+ 元数据），且**零配置门槛**（无需 Key）+ 多语言证据不受影响
- **关键**：中文层（OpenAlex/Crossref）**默认关**（Phase 0 勾选启用），主人若要「纯静态材料 + 本地推理」不勾选即可（或选 ④全部拒绝 / ②脱敏方案）

## 八、限制与数据流说明

- **中文层（OpenAlex/Crossref，opt-in）= 只读公开 API，无需 Key**：通过 `web_fetch` 拉取学术元数据 JSON，**仅发送检索关键词**（主题/作者/DOI），不发送个人信息/机密数据；不要求、不存储任何 API key。
- **抓取层（Firecrawl）= 可选、默认关闭**：需主人 Phase 0 显式勾选启用；凭据由主人在宿主环境为相应外部客户端自行配置与调用，**论衡运行时不读取、不存储、不传递任何凭据值**（含宿主环境变量），未启用/未授权时对该服务零调用、零外发。
- **凭据边界**：主人自管 API key（当前仅抓取层 Firecrawl 一项需要）；论衡**不读取、不持久化、不落盘、不进 prompt、不进会话记录、不进日志、不上传第三方** —— key 仅供主人自用的宿主侧客户端读取，论衡只消费主人投喂的**不含 key** 的结果。任何角色卡的指令都不得要求把 key 值写入 prompt、卡片、状态文件或交接报告。
- **去重质量**：依赖 DOI/标题匹配，少数情况下可能误去重。

## 九、关闭可选层的代价（v2.14.1 明示）

> **背景**：实战复盘指出「关闭可选层」的代价未明示。关闭是主人权利（fail-closed 不强制），但主人应知悉下列代价；主控在 Phase 0 呈现可选层时须一并告知。

| 关闭的层 | 代价 |
|---|---|
| **学术检索与元数据层**（AI4Scholar 工具族 + OpenAlex / Crossref） | 本次运行**学术核验 0 自动化**：文献元数据靠搜索引擎摘要推测（作者/DOI/年份错漏风险显著上升），**引文存在性核验（T1b）退化为网页搜索比对**（高假阳/假阴），无法做引文图谱滚雪球（前向/后向）、无法批量拉取元数据、无法读取全文原文片段（E1 `SnippetRecord` 只能落 `abstract_only`），中文文献元数据完整性约 95%→80%（v2.5.5 实测口径）|
| **抓取层**（Firecrawl） | 付费墙 / 无公开 API 页面全文不可得，只能用摘要 |

> **口径**：以上代价须在 Phase 0 告知主人；主人显式关闭 → 主控在任务简报「外部服务同意记录」段记明关闭项 + 已知代价，不改判定门。
