# 踩坑与铁律（本项目 10 部视频沉淀）

把白板动画流水线跑顺之前，踩过的坑都记在这里。**新做视频前通读一遍可省数小时。**

## 1. annotation 的 startMs 必须是「幕内相对时间」

- ❌ 写成成片绝对时间（如 105000ms）→ 这一幕被拉长到几十秒，合并后成片虚高、音画错位。
- ✅ 写成幕内从 0 起算的相对时间；合并总时长 = 各幕 `sceneDurationMs` 之和。
- 自检：写完 annotation 后断言「末元素 end < sceneDurationMs」。
- 用 `make_annotation.py` 自动生成可规避此坑。

## 2. ImageGen 并行生成会「同名覆盖」

- 一次并行生成多张线稿时，若 prompt 触发相同文件名，后发的会覆盖先发的（本项目 V06、V09 都中招）。
- ✅ 每张分别生成、生成后立即 `mv` 成唯一名（如 `scene-01-xxx.png`、`scene-02-yyy.png`）。

## 3. 配音时长要用「实测」，别用估

- 云希（zh-CN-YunxiNeural）常速约 **5.2 字/秒**。手写 `durations.json` 估算会系统性偏短（本项目 V09 每段短约 1.06s，22 段累计差 24s），导致段间重叠、配音塞不进画面。
- ✅ 用 `prepare_narration.py`：先 edge-tts 合成每段 → 裁静音 → 测真实时长 → 段间留 0.4s 间隙算锚点 → 写 `narration_plan.json`。再交给 `narrate_edge_tts.py`。
- 若实测配音 > 无声成片时长：**延长各幕 `sceneDurationMs` 并重渲**，或给慢段加正 rate（微加速），不要事后硬拉音频（会吞字）。

## 4. 字幕遮挡画布正文

- libass 实际渲染位置：video_y = canvas_y × 0.6944。字幕默认落在 y≈717–780，会盖住画布下半部正文。
- ✅ 用推荐烧录样式（FontSize=21，MarginV=28，白字黑描边），并把画布正文控制在上方 2/3 区域；线稿下半部留白给字幕。

## 5. 增强图元必须落在揭示区内

- `render_stream_whiteboard.py` 只在标注 `region` 内揭示墨迹（_allowed_mask）。PIL 用 `enhance_toolkit.py` 画的标题/标签/便签，如果画在区域框外，渲染时**不会显示**。
- ✅ 增强图上的每个文字块，都要在对应 `region` 框内；多块内容用多个 region 分别揭示。

## 6. 手部素材要显式传入

- 渲染命令必须带 `assets/drawing-hand-clean.png`，否则用内置 `drawing-hand.png`（可能不存在）或退化成程序化笔尖。自包含版已把素材放进 `assets/`，默认即指向它。

## 7. 环境：缺 soundfile / edge-tts 会中途崩

- `narrate_edge_tts.py` 与 `build_subtitles.py` 依赖 soundfile；`prepare_narration.py` 依赖 edge_tts。先跑 `prepare_env.py` 建好 venv（已把这两个加进依赖清单）。

## 8. 抽帧质检不可省

- 每部成片至少抽 5–7 帧（开头/各幕交界/结尾），核对：标题是否完整、主体是否揭示完毕、字幕是否压正文、音峰是否 < 0dB。本项目 V04 因字幕压住第五层文字返工过一次。

## 9. 字幕烧录的 PlayRes 缩放坑（最隐蔽，项目2 三片全中招）

- **现象**：`force_style` 里设了 `FontSize=32`，成片里字幕却巨大无比，左右被裁、超出画面。
- **根因**：ffmpeg `subtitles=` 滤镜对 **SRT 输入**走 libass 默认脚本分辨率 `PlayResX=384 / PlayResY=288`。
  Style 的 FontSize 是"脚本分辨率单位"，渲染时按 `frame_height / PlayResY` 放大：
  1080×600 画面 → 600/288 ≈ **2.08×**，`FontSize=32` 实际 ≈ **73px**。
  一条 28 字中文 ≈ 1850px，直接撑爆 1080 宽。
- **实测证据**：1080×600 白底 + `FontSize=32` 的 33 字符测试串 → 暗像素 bbox `x[0,1079]`（贴满左右）、文本高 73px。
- ✅ **解法**：`srt_to_ass.py` 显式写 `PlayResX/PlayResY = 画面宽高`，FontSize 即为画面像素（1080×600 用 **26**），
  再用 ffmpeg `ass=` 滤镜烧录。同参数实测 → 文本高 29px、宽 445px 居中，四边余量充足。
- ⚠️ **不要用 `subtitles=` + `force_style` 调小字号去"凑"**：那依赖 ffmpeg 版本的默认 PlayRes，换个版本/分辨率又会错。

## 10. 图元坐标超画布会被静默裁掉

- 项目2 V02 第三幕把 4 张口诀卡按 `xs=[110,490,870,1250]`、宽 300 排布 → 末卡右边缘 1550 > 画布宽 1536，
  右边缘被裁，直到抽帧量 bbox 才发现（`x_max` 贴到 1079）。
- ✅ `enhance_toolkit.py` 已内置 `_check_bounds()`，`draw_label_card` / `draw_note` / `sketch_rect` 越界即打印 `[bounds!] box=(...) 超出画布 WxH`。
- ✅ 成片后务必量**无声版末帧**的暗像素 bbox：四边都应有正余量。
  注意区分"字幕触边"和"持笔手素材自然延伸到底边"——后者无声版同样到底边，属正常。

## 11. 底部便签不能画进字幕区（项目3 十二片质检发现）

- **现象**：底部结论便签画在画布 y 700–830（1536×864），成片里被硬字幕压住一半。
- **根因**：1080×600 画面上字幕 Alignment=2 + MarginV=36 + FontSize=26 → 字幕块约占画面
  y 529–567（含描边）。按 864/600 折算回画布坐标，**画布 y ≥ 762 就是字幕区**。
- ✅ **规则**：所有图元（尤其 `draw_note` 结论便签）的 `y1` 必须 ≤ **756**（1536×864 画布）。
  内容若放不下就整体上移或压缩行距，不要往底部挤。
- ✅ 量化验证法：`ffmpeg` 抽"无声版"与"成片"同时刻帧做像素差，差异 bbox 的 y 范围应只在
  字幕带（约 529–599 画面坐标）内；若差异延伸到 y<529 说明字幕与画面内容重叠。

## 12. 音画必须同步（世校赛讲座视频重大返工教训）

- **现象**：成片里"讲 A 主题时画面还是 B 主题的图"，结尾约 30s 静默空画，观众出戏。
- **根因**：配音时间轴（连续、按段实测，约 70s）与各幕固定 34s×N=102s 的绘画时间轴是**两套独立时钟**，互不锚定。
- ✅ **解法（让两轴用同一只钟）**：
  1. 把 SRT 段按主题分组为「幕」写进 `scenes.json`（`[{"lines":[1,5],"bodyBeats":2}, ...]`）；
  2. `prepare_narration.py` 后，用 **`build_sync_spec.py --srt --plan narration/narration_plan.json --scenes scenes.json`** 生成每幕 spec；
  3. 该脚本令**每幕时长 = 该幕配音时长之和 + gaze** → 合并成片 ≈ 配音总时长，幕切换对齐主题切换；幕内拆「标题→左主体→右主体→结论」节拍，**每拍揭示时长 = 对应口播句实测时长之和** → 讲到哪画到哪。
- ✅ 自检：合并后 `ffprobe` 成片总时长应与 `prepare_narration` 打印的「配音总时长」接近（差值为各幕 gaze 之和，约 N×0.6s）；抽帧核对"第 N 句口播时刻的画面"是否正是该句对应的图。

## 13. 题材要与参赛专业强相关（世校赛讲座视频返工教训）

- **现象**：初版线稿用工厂/医院/公文等泛化意象，与生物/化工/环境/材料/轻工等参赛专业脱节，辅导价值低。
- ✅ **规则**：理工农医类竞赛视频，ImageGen prompt、`draw_note` 结论条、口播举例三处都围绕上述专业取材（无菌操作、反应釜、污水处理厂、材料表征、食品感官评定等），按视频主题轮换，杜绝泛化意象。详见 SKILL.md「题材专业相关性」一节。

## 14. ImageGen 返回尺寸不确定，crop 前必须过 fit_canvas（世校赛重制黑块教训）

- **现象**：重制世校赛 4 部视频时，ImageGen 整批返回 **1024x1024 方图**（而非预期的
  1536x1024），流水线按 (0,55,1536,919) 裁剪，右侧 512px 越界被 PIL 填**纯黑**，
  成片右上角出现大块黑色矩形，且抽帧质检前未被发现。
- **根因**：PIL `crop` 越界区域自动填黑；流水线对输入尺寸没有任何断言。
- ✅ **规则**：`remove_watermark.py` 之后、`homogenize_paper.py` 之前，必须先跑
  `fit_canvas.py scene-01-*.png`：宽度不足 1536 时居中 pad 到 1536 宽
  （底色取左缘纸张均值，homogenize 会进一步统一）。脚本会打印每张图的实际尺寸，
  顺便充当尺寸自检日志。
- ✅ **量化验证**：crop 后逐图检查四角 20x20 区域均值，若出现接近纯黑
  (<40) 而线稿纸底应为 (>180) 的角，说明仍有越界，立即中止而不是继续渲染。

## 15. 混流音轨必须加 -shortest（配音版被旧音轨拉长教训）

- **现象**：重制后画面 81.78s，但 `narration-track.wav` 是上一版按 102s 成片生成的
  （88~103s），`ffmpeg -i 无声.mp4 -i track.wav -c:v copy -c:a aac` 未加 `-shortest`，
  输出时长 = max(视频, 音频)，成片被拉长 6~21s，末尾出现静音静帧，且字幕轴
  （按 81.78s 生成）与画面错位。
- ✅ **规则**：混流命令**永远带 `-shortest`**：
  `ffmpeg -y -i XX-无声.mp4 -i narration/narration-track.wav -c:v copy -c:a aac -b:a 192k -shortest XX-配音版.mp4`
  让画面时长主导输出，多余音轨自动截断（末尾本就是 gaze 留白静音，无损失）。
- ✅ **配对校验**：混流后 `ffprobe` 检查配音版时长 == 无声版时长；`build_subtitles --total`
  传**无声版实际时长**（用 ffprobe 现取，不要沿用 plan 里的 --total）。

## 16. 动画必须是「笔画出来的」，不能有擦写/填充感（世校赛二次返工教训）

**现象（用户反馈）**：①绘画与文字部分重叠、看不见文字；②绘画顺序不协调，
「感觉是擦写出来的，不是画出来的」。

**根因（三个叠加）**：
1. **渲染参数**：`--ink-path grid --color-fill contour-wipe` = 墨迹按网格**逐块填充** +
   上色**自上而下幕帘扫描**——前者像打字机糊块、后者像橡皮擦扫过，正是「擦写感」来源。
2. **文字碰撞**：ImageGen 线稿自带英文/中文标题（SCORECARD、Hands-on Operations、
   金项目三角…）与增强中文标题画在同一天顶部中央 → 字叠字；`draw_note` 旧版
   alpha=70 半透明底让线稿透过便签压住文字。
3. **增强内容跨区**：标签卡横跨 body(y180-600)/note(y600-742) 两带 → 同一排卡被拆成
   两段揭示，笔「跳来跳去再回头」，顺序失调。

✅ **修正（已固化进脚本默认值）**：
1. **渲染默认 `--ink-path skeleton --color-fill brush`**：骨架细化 + 8 邻接追踪出真实笔画，
   笔尖沿笔画滑行逐段落墨（起笔），添彩沿同一路径刷（同轨迹）→ 观感即「随笔画出来」。
   同时 `_lay_ink` 改为**整帧批量揭墨**（一条 polyline 一次布尔运算），速度提升约 10 倍。
   凝视帧改 **0.4s 交叉淡入**（旧版硬切，未揭墨残余会瞬间蹦出）。
2. **`enhance_toolkit` 新增两件武器**：
   - `clear_area(im, box, feather)`：高斯羽化软边清除线稿自带字样（底色四角采样，
     深色背景图同样适用）；清除框要**盖住目标的全部笔画含下延部**，并延伸到 y=0。
   - `draw_title(..., panel=True)`：标题铺实心纸底圆角面板+手绘边，用于「顶部有插画
     不能清」的场景（人物头部/深色底纹）。`draw_note`/`draw_label_card` 底改**实心纸色**
     （原 alpha 70 会透线稿）。
3. **布局对齐标注带**：标题 y40-170、主体 y180-600、结论便签 y600-742（y1≤756 避字幕区）。
   增强内容**不得跨带**，一排标签卡整体放进一个带；与口播节拍一一对应。
4. **每场景三选一策略**：顶部带空 → 直接写；顶部有自带字样 → `clear_area` 后写；
   顶部有不可清插画/深底 → `panel=True`。逐场景决策前先出标题带对照图（crop y0-210）。

✅ **量化验证**：渲染后抽帧（每幕 5 帧），核对①笔尖位置=最新笔画前端；②任意帧无
「字叠字」；③文字底色为实心纸色。

## 17. 逐句节拍 + 真实语音计时 + 链式笔顺（「讲到哪画到哪」v3）

**现象（用户反馈）**：①绘画顺序不协调、「感觉是无序画出来的」，要求「有逻辑性、
局部和整体大协调」；②「讲到哪画到哪，讲话和绘画协调统一」。

**根因（三层）**：
1. **节拍太粗**：v2 每幕只切「标题→左主体→右主体→结论」四拍，一拍覆盖五六句口播
   （最长 20s），整块内容在一次窗口里按位置硬画 → 必然「讲到哪画不到哪」。
2. **假时长**：narration_plan 的末段按 80s 目标补齐（假值最长 17.6s），且每幕各自
   +0.6s 凝视漂移，成片被拉到 81.8s，尾部十几秒静音空画。
3. **笔顺无序**：`_order_skeleton_strokes` 按「包围盒左上角字典序」排笔画——同一行的
   多个部件（如三个小人的头/身/腿）被按 x 打散，笔在部件间跳来跳去。

✅ **修正（三层对应，已固化）**：
1. **scenes.json v2 beats 格式**：每幕显式声明节拍数组——
   `{"lines":[口播段号...], "rects":[[x,y,w,h]...或{"rect":..,"dur":ms}], "point":[[x,y]...]}`。
   `lines` 管「讲到哪」，`rects` 管「画到哪」，一句一画/多句一画由作者按画面语义映射；
   `point` 拍只移动笔尖不落墨（总结/过渡句，如「用这五条逻辑重新审视你的项目」时
   笔尖沿已画好的三角描一遍）。
   **拍序 = 口播顺序**，这就是「顺序有逻辑性」的第一来源；块间动线再按
   「从上到下、从左到右、相邻优先」规划（局部协调），整体形成阅读动线（整体协调）。
2. **真实语音计时**：`build_sync_spec.py --narration-dir narration` 直接测每个
   `segNN.wav` 的真实语音长度（20ms 窗、峰值 4% 阈值、去首尾静音）；每拍窗口 =
   [本拍首句起始, min(本拍末句语音结束+tail, 下一拍首句起始-0.05)]；幕时长 =
   下一幕首句起始（零漂移）；全片 = 最后一句语音结束 + 结尾凝视。
   实测成片从 81.8s 收紧到 66-78s（=真实语音），尾部空白与每幕漂移全消。
3. **链式笔顺**：`_order_skeleton_strokes` 重写为「从最左上笔画起笔的**最近邻链式
   排序**」——行带优先（y 带内按 x 推进），下一笔取上一笔终点最近的候选，方向连续；
   彻底消灭同图元部件间的跳笔。
4. **拍间留白、拍内紧接**：spec 里拍间空隙放本拍第一块的 `lead`（口播停顿时画面静止），
   拍内多块 `lead=0` 紧接画（渲染器抬笔衔接）。
   ⚠️ `lead` 与 `make_annotation` 的全局 cursor 是**相加关系**——拍内块若再设递增 lead
   会双重累加导致末元素超出 sceneDuration（本轮实测翻车点：三块卡溢出 1.9s）。
5. **内容多的幕果断拆幕**：V02 29 句拆 5 幕（原 3 幕），第 4/5 幕用 ImageGen 补画
   对应意象线稿（闭环+红线 / 调研数据）。**一句画不超过 2-3 个空间块**，否则观众
   来不及看。

✅ **量化验证**：渲染后按口播时刻抽帧（每句中段 1 帧），核对「当前口播句 ↔ 当前
最新笔画内容」逐句对应；另测成片总长 ≈ 真实语音总长 + 1s 凝视。

## 18. 改了文案/拆了幕，必须重建 narration-track.wav（否则声音与画面各走一只钟）

**现象**：画面与字幕完全对得上（都按 plan 走），但**听感对不上**——观众听到的
某句比画面早/晚；本轮更严重：V03 的 `seg29` 在旧音轨里**完全没有声音**，
而画面老老实实为它画了 3 秒（= 最后一段讲解凭空消失）。

**根因**：`narrate_edge_tts.py` 生成音轨后**直接混流进成片**，此后音轨就固定了。
再改 SRT / 拆幕 / 加句时，`narration_plan.json` 的 `start` 会变（甚至段数变多），
但磁盘上的 `narration-track.wav` 还是旧的：
- 画面、字幕 → 按新 plan（一致）；
- 声音 → 按旧音轨（失配）。

**排查特征**：plan 最后一段 `start` 之后**测不到任何音频能量**；或
「成片总长 ≈ 真实语音结束 + 1s」这条等式不成立（本轮 V03 spec 合计 76.98s，
而旧音轨语音在 73.00s 就结束，相差 3.98s），即说明音轨与 plan 已脱钩。

✅ **规则**：凡是**动过 SRT / 分段 / plan**，合成前先跑
`scripts/rebuild_track.py` 重排音轨（复用已有 segNN.wav，秒级、不重调 TTS）：

```bash
$VENV $SK/rebuild_track.py --plan $d/narration/narration_plan.json \
    --work $d/narration --out $d/narration/narration-track.wav
# 输出核对：成片无声时长 ≈ speech_end + 结尾凝视(1.0~1.5s)
```

✅ **两条 plan 分工别搞混**：
- `narration_plan.json`（**字典** `{segments,total}`）→ 给 `build_sync_spec.py` / `prepare_narration.py` 用；
- `subtitle_plan.json`（**列表** `[{idx,start,file}]`）→ 给 `build_subtitles.py` 用，
  由 `make_subtitle_plan.py --plan narration_plan.json` 现生成。
  直接把前者喂给 `build_subtitles.py` 会报 `KeyError: 0`（本轮踩到）。

✅ **四者同钟自检**（合成完必做）：静帧/语音/字幕/画面四路时间轴要满足
`成片时长 ≈ 语音结束 + 凝视`、`每句字幕起点 ≈ 该句 seg 的 plan.start`。

## 19. 卡片底色 = 本图纸色（不是固定的"纸白"），同带并列元素必须留缝

**现象（用户反馈「绘画与文字重叠」的残留形态）**：
- 便签/卡片呈现为一块**明显偏白的补丁**，与匀纸后的米色页面有色差，观感像贴了便利贴；
- 更糟的是半透明底（alpha 70~235）会让底下线稿透上来，压在文字上；
- V02-s5 的结论便签横跨 x120-1416，**直接穿过剪贴板插画**；
- V03-s3 的便签（116-616）与「人机料法环」第一张卡（520-688）**重叠 96px**，
  把「讲得清」压掉一半——增强脚本自己画的两个元素打架。

✅ **规则**：
1. 一切填充用 `_page_rgb(im)`（`enhance_toolkit` 内，四角采样中位数）+ **alpha 255**。
   既完全盖住线稿，又与页面同色、看不出补丁边界。深色底稿同样适用。
2. 同一标注带（尤其 y600-742 结论带）内并列的元素，**先把所有盒子的 x 区间排开再写代码**，
   留 ≥20px 缝；便签与卡片不得相交。
3. 便签/卡片尽量避开线稿主体（插画、人物、剪贴板）：宁可缩短或挪到空白带，
   也不要把插画拦腰截断（人物"半个身子在便签后"很廉价）。
4. 自检：`enhance_scenes.py` 跑完后看 `_sheet_enh_all.png` 缩略图对照板
   （14 张一屏），肉眼扫一遍重叠/截断，再进渲染——比成片抽帧便宜得多。

## 20. 笔顺三代演进：行带 + 带内严格左→右（别再用"最近邻接龙"）

用户两轮反馈都指向「绘画顺序」：先是"感觉是擦写出来的"，再是"无序、要局部与整体协调"。

**三代算法与实测结果**：

| 版本 | 做法 | 结果 |
|---|---|---|
| v1 包围盒字典序 | `(min_y//12, min_x, min_y, -len)` 排序 | 同一行的多个部件被按 x 打散，笔在部件间来回跳 → 用户："无序乱画" |
| v2 最近邻接龙 | 最左上起笔，之后每笔接**离笔尖最近**的一笔 | 单块图形（人物/设备）连贯了，但**便签折角画在右上**，接龙从折角滑到文字右端，"零失误·肌肉记忆"被**倒着写成"记忆…零失误"** —— 一眼看出不是人在写 |
| v3 行带 + 左→右 | 按竖直重叠（>较矮者 45%）分「行带」，带间从上到下，**带内严格按 x 升序** | 稳定呈现"先框线 → 从左到右写字 → 补右边框/折角"，与真人板书一致 |

**v3 细节**：
- 竖边（如便签左右边框）高度大，会把上下内容并进同一带；带内按 x 排序后，
  天然得到「左边框 → 文字 → 右边框」的顺序，不需要特殊规则。
- x 分桶容差 6px（同一竖列的两个笔画再按 y），避免抖动。
- 每笔方向用 `_orient_stroke(k, cur)` 取"近端起笔"，笔尖仍连续滑行，不瞬移。

**教训**：**"最近邻"只解决"局部连贯"，解决不了"书写方向"**。文字类内容必须有
明确的行/列扫描方向，否则光标会顺着几何最近点倒着写。判断依据很直观——
抽连续的 5~6 帧看文字是从哪一端开始成形的。

## 12. 文字贴边 / 被遮罩整块吃掉（项目3 用户反馈「显示不全」）

1. **胶带越过 region 上边界 12px**：`draw_note` 的胶带画在 `(x0+30, y0-12, x0+110, y0+10)`，

3. **长句冲出框/画布**：定死字号 + 定死框宽，一句 14 字以上的标签必然溢出牌外。

**修法（v1.3 已固化）**：

- `draw_note` 胶带/折角改为画在框内（y0+2 起）；`draw_label_card`/`draw_note`/`draw_title`/`safe_text`
  统一走 `fit_font` 按可用宽度反算字号，超宽打印 `[fit] 字号 34→29`，缩到 13px 仍超宽打印
  `[text-overflow!]` 要求改文案。
- `_check_bounds` 增加 margin 维度：出画布报 `[bounds!]`，距边 <8px 报 `[edge!]`。
- 新增 `check_layout.py`：拿「region 并集」比对墨迹，直接列出**永远不会被揭示的墨迹**，

## 24. v1.4 版式安全复核：项目1 十片返工的四个新坑

用户第二次反馈「文字贴近画面边缘、显示不全」，对象是**项目1 已交付的十片**。复查 31 幕发现
22 幕有问题：**99 处贴边、28 处压进字幕带、3 处整块永不显示**。修完沉淀出四条新教训。

### 24.1 有底稿时必须走「底图对比」，否则报告不可用

项目1 的增强图是 `ImageGen 线稿 + PIL 叠字`，线稿本身就画满整张纸，边缘全是墨。
第一版 `check_layout.py` 直接量整图墨迹 → 每幕报几十条"贴边"，全是纸上的线条，
真正的文字问题被淹没。

正确做法是拿 `<stem>-base.png`（同一张裁剪图、未叠字）做差：

```python
diff  = |enh - base|.max(axis=2)
added = (diff > 30) & ink_mask(enh, 55)
```

只量 `added` 的包围盒与连通块，才是"新画上去的东西"的边界。`--base auto` 自动配对，
命中时打印 `[mode] 底图对比：…`。

> **推论**：`-base.png` 不是垃圾中间产物，是体检的必需品，必须随片子一起留着。

### 24.2 `maskPaddingPx` 必须参与归属判断，否则一堆假阳性

渲染器揭示 region 时会把矩形外扩 `maskPaddingPx`（老标注默认 22px）。
体检若只按纯 region 矩形判断归属，落在 padding 环带里的墨迹会被判成"永不显示"。
V07 第一版报告 6 处"永不揭示"，实际全是 padding 覆盖到的正常内容。

`check_layout.py` 的 `load_regions()` 现在返回 `[{"region": r, "pad": pad}]`，
归属测试前先 `r.expand(pad)`。

### 24.3 钳制必须按「真实墨迹矩形」，不能按文字原点（16px 偏差）

PIL 的 `textbbox((0,0), txt, font)` 是**相对原点**的，且字体 ascender 留白让真实墨迹
比原点低 10–18px。第一版 `clamp_box` 钳的是 `(x, y, x+w, y+h)` 这种原点框，日志写
"已钳到 756"，实测像素却在 772 —— 差 16px，仍然压进字幕带。

修法：新增 `draw_text_center(d, cx, cy, text, font, ...)`，内部先画一次量 `bb`，
再钳 `(ox+bb[0], oy+bb[1], ox+bb[2], oy+bb[3])` 这个**墨迹矩形**，最后按差值回推原点重画。
`safe_text` 同样把边界测试改成 `bb_abs = (px+bb[0], py+bb[1], px+bb[2], py+bb[3])`。

> 任何"量文字占多大地方"的代码，都必须用 `bb` 偏移，不能用原点。

### 24.4 安全边距要按「成片像素」倒推，不能按画布直觉取整

画布 1536×864 → 成片 1080×600，缩放比 **0.703**。想要成片留 24px，画布侧就得 34px。
第一版取 `MARGIN=24`（照搬 `fit_font` 的框内边距），成片只剩 17px，肉眼仍觉得贴边。

最终常量（`enhance_toolkit.py` 顶部，改一处全流程生效）：

| 常量 | 值 | 折算成片 |
|---|---|---|
| `SAFE_MARGIN` | 34 | ≈24px（左/右/下） |
| `SAFE_TOP` | 36 | ≈25px（上，标题带下压） |
| `SUB_BAND_TOP` | 756 | 字幕带 y1 上限（762 再留 6px 缓冲） |

配套 `clamp_box` / `clamp_center` / `draw_text_center` 已接进 `draw_title`、`draw_label_card`、
`draw_note`、`safe_text`、`draw_stamp`、`draw_star`，**只平移不缩放**（图元本身比安全区还大才缩）。

### 24.5 新增 `check_render.py`：content coverage 是终局判据

`check_layout.py` 判的是「源图 vs region」，它管不到**烧完字幕之后**的事。
用户看到的"显示不全"有一半发生在后半程：字幕盖住底部便签、libass 静默失败、
合流少一幕、编码器丢帧。

`check_render.py` 解成片**最后一帧**，与 `*-enh.png` 对齐，算墨迹交集比例 = **内容覆盖率**；
低于阈值时按连通块列出缺失区域，并输出成片四边实际留白。判据 ≥ 0.99，exit 0/1。

| 脚本 | 时机 | 能抓 | 抓不到 |
|---|---|---|---|
| `check_layout.py` | 渲染前 | 贴边、入字幕带、region 漂移 | 烧字后遮挡/丢帧 |
| `make_annotation.py` 自检 | 标注后 | 末元素超 sceneDuration | 版式 |
| `check_render.py` | 成片后 | 覆盖率、真实四边留白 | 覆盖率合格但位置偏（需人眼） |

三关缺一不可，且顺序不能颠倒：前两关便宜（秒级），最后一关贵（要解视频）但最接近"用户实际看到的东西"。

### 24.6 ffmpeg `ass=` 吃不了中文绝对路径

重新烧字幕时踩到：`Could not create a libass track when reading file '/e/……/narration/subs.ass'`，
文件存在、权限正常、路径正确，依然失败。libass 的路径解析在 Windows 上不认 UTF-8 绝对路径。

**唯一可靠解法**：`cd` 进目录，只传相对文件名。

```bash
cd "$d" && ffmpeg -y -i "配音版.mp4" -vf "ass=narration/subs.ass" ... "完整版.mp4"
```

不要试图用 `subtitles=` 替、也不要加引号/转义/短路径——都是白费。

### 24.7 批量返工的工程化：先备份、再脚本化、单片验证后放量

十片返工手工做必然出错，正确顺序：

1. **先备份成片** → `成片交付_备份_YYYYMMDD/`，出问题能立刻回退。
2. **写 `rebuild_p1.sh`**：对每片 ①逐幕用 `annotation.json` 重渲染 ②`merge_scenes.py` 合并
   ③**复用原旁白轨**（`-map 0:v:0 -map 1:a:0 -c:v copy -c:a copy`，不重跑 TTS）
   ④转 ASS 烧录 ⑤烤到 `成片交付/`。
3. **先跑单片（V07）验证**：确认渲染观感、时长、音轨都对，再放量跑剩下九片。
4. 放量后用 `check_render.py --dir` 逐片复核覆盖率。

复用旁白轨这一步很关键：它把返工从"重做配音+字幕+计时"降级成"只重渲画面"，
单片几分钟，且保证**声音与旧版逐字节一致**，不会引入新的音画不同步。

### 24.8 标题的红色波浪线会顶到副标题：间距要按「下划线下沿」算

`draw_title` 除了写字，还会在标题下方画一条红色手绘波浪线做下划线。原实现是
`y + size + 16 ± 6`，也就是**向下探 22px**。而各片副标题的 `center_text(..., cy, ...)`
是按自己的版面定的，常见值 `cy=120`、字号 22 → 墨迹从 `cy-11=109` 起。

两相对照：

| 场景 | 标题 y/size | 波浪线下沿 | 副标题墨迹上沿 | 结果 |
|---|---|---|---|---|
| V04-s1 | 40/44 | 106 | 100 | **重叠 6px** |
| V04-s2 | 40/40 | 102 | 96 | **重叠 6px** |
| V02-s2 | 40/48 | 110 | 111 | 仅差 1px |
| V09-s3 | 40/44 | 106 | 109 | 仅差 3px |

1–3px 在 1536 宽画布上缩放后只剩不到 2px，成片里看起来就是**红线把小字划掉了**，
典型「文字显示不全」。V04 更是直接压字。

修法：把波浪线改为 `y + size + 7 ± 5`（只下探 12px），紧贴标题底部，让出 10px 给副标题。
同时 `LAYOUT.add` 的高度从 `size + 24` 收到 `size + 14`，region 也跟着收紧。

> **教训**：「标题 + 装饰线」是一个整体图元，它的**下沿**才是与下方文字的间距基准，
> 不是标题字号的下沿。凡是"在文字周围加装饰（下划线/胶带/边框）"的绘制函数，
> 都要在文档里写明它向下探多少，否则调用方算间距一定踩坑。
