# SCHEMA.md 写法指南

> 本文档在 LLM 配置 / 修改 SCHEMA.md 前必读。模板见 `assets/schema-template.md`。

## 1. SCHEMA.md 的地位

- `wiki/SCHEMA.md` 是知识库的**约束配置**，**用户可编辑**，LLM **不擅自修改**。
- LLM 在每次编译前必须先读 SCHEMA.md，按其约束建页。
- `schema_version` 字段变更会触发全量重编译（diff.py 检测）。

## 2. 必含字段

### 2.1 `schema_version`（frontmatter）

每次结构变更（新增实体类型、修改主题边界）递增版本号，如 `v1` → `v2`。**主题清单的增删也属于结构变更**，必须递增版本号。

### 2.2 主题边界

明确"覆盖什么、不覆盖什么"。例：

```markdown
## 主题边界

覆盖：人工智能、分布式系统、编程语言、软件工程。
不覆盖：与上述无关的领域（如纯数学基础理论、生物医学）。
```

边界外的内容即使出现在 raw 文件中也**不建页**，必要时在编译报告中提示用户。

### 2.3 主题清单（关键）

表格形式，每行一个主题：

```markdown
## 主题清单

| slug | 名称 | 简述 |
|------|------|------|
| deep-learning | 深度学习 | 神经网络与表示学习的理论、模型、训练方法 |
| distributed-systems | 分布式系统 | 分布式一致性、容错、调度与存储 |
```

约束：
- **slug** 一律 kebab-case 英文，唯一，与 `pages/<slug>/` 目录名一致。
- 名称可用中文。
- 简述 1-2 句，供 index.md 抓取。
- 主题**永不合并**；仅当某主题页面数 > 1000 时由 lint 建议拆分。

### 2.4 实体类型清单

枚举所有允许的 `entity_type`，建页时必须命中其中之一：

```markdown
## 实体类型清单

- 概念
- 方法
- 模型
- 人物
- 机构
- 论文
- 数据集
- 事件
```

build_index.py 按 entity_type 在主题索引中分组、排序，顺序见脚本中的 `ENTITY_ORDER`。

### 2.5 成页规则

明确"何时新建独立页 vs 并入已有页"。示例：

```markdown
## 成页规则

1. 核心概念、重要方法、知名模型独立成页。
2. 子概念内容不足 200 字时，并入父概念页的子节，不单独建页。
3. 人物仅当在主题内有显著贡献时建页；否则在相关概念页以引用形式出现。
4. 论文仅当本身是里程碑（被反复引用、催生分支）时建页；其余作为来源出现在概念页的 `## 证据 / 来源`。
5. 同一实体有多个名称时，选最通用的作 slug，其余写入 `aliases`，不重复建页。
```

### 2.6 页面模板

指向 `assets/page-template.md`，详见 `page-authoring.md`。

### 2.7 写作风格

约定语言、语气、引用格式、长度上限：

```markdown
## 写作风格

- 语言：中文为主，专有名词保留英文原文（如 Transformer、Raft）。
- 语气：客观陈述，不用第一人称，不用营销口吻。
- 引用格式：`## 证据 / 来源` 中每条形如「出自 [[相关概念]]；原文见 raw/<文件名> §<章节>」。
- 长度：单页目标 < 1500 字。
```

## 3. 主题的生成与维护流程

### 3.1 首次创建

1. LLM 通读所有 raw 文件（用 `parse_raw.py` 解析）。
2. 归纳主题清单，写入 SCHEMA.md 草稿。
3. **交用户确认 / 编辑**（主题边界、主题清单、实体类型、风格）。
4. 用户确认后才能进入建页阶段。

### 3.2 增量更新

- 新资料若涉及现有主题，归入对应 topic，无需改 SCHEMA。
- 若催生新主题，LLM 在编译报告中提出"建议新增主题 X"。
- **用户确认后**，LLM 才在 SCHEMA.md 主题清单中追加新行，并**递增 schema_version**。
- 然后编译相关页。

### 3.3 主题拆分（仅 lint 触发）

- 仅当某主题页面数 > 1000 时，lint 报告建议拆分。
- 由用户决策后更新 SCHEMA.md：把原主题拆成多个新主题，递增 schema_version，触发全量重编译。
- 主题**永不合并**。

## 4. 常见错误

| 错误 | 后果 | 修正 |
|---|---|---|
| LLM 擅自添加主题 | 违反范式红线 | 必须先在报告中建议，等用户确认 |
| 主题清单 slug 大小写不一致 | build_index 主题分裂 | 一律 kebab-case 小写 |
| 主题清单与 pages/ 目录不一致 | lint 报 topic_orphans | 修改 frontmatter 的 topic 或更新 SCHEMA |
| 忘记递增 schema_version | 增量编译不触发全量 | 任何结构变更都必须递增 |
