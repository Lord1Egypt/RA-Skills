#### C. 领域坐标定义（多域判据：KLS1 判层、定位与盘点，KLS2 燃料匹配，KLS0 术语守护）

**领域可验证性分层**（白话版：越靠前的领域，"对错"越容易用明确规则判定；越靠后的领域，越依赖共识和个人手感——分层决定同一套循环在各领域能跑多远）：

| 层 | 定义 | 三态上限 |
|----|------|---------|
| 形式层 | 判断标准可完全形式化为规则、证明检查或模拟，裁决不依赖现实观测 | 已裁决 |
| 实证层 | 判断标准依赖经验证据与现实观测条件 | 已校验（证据充分时） |
| 规范层 | 判断标准本身是社会共识建构，随共同体协商更新 | 已校验（附共识判据来源） |
| 默会层 | 核心知识以"知道但难以言说"的方式存在于个体，只能示范传递 | 待裁决为主 |

判定问题序列（按序判定，命中即停）：①裁决点能否全部编码为可核验规则且裁决无需现实观测？能 → 形式层；②对错是否由经验证据与现实观测决定？是 → 实证层；③对错标准是否由共同体约定而非客观事实决定？是 → 规范层；④核心判断是否无法完整言传、只能示范传递？是 → 默会层。

分层与分档的关系：分层刻画裁决标准的性质，分档（自主/协作/人类主导）刻画 AI 在循环中的自主程度——形式层常出自主档候选，实证层多落协作档，规范层与默会层通常人类主导档。分层是分档判定的相容性约束，不是替代。

分层使用规则：KLS1 环节定位时先判层并记录；分档结论须与分层结论相容；时钟评估按层校准节奏假设——默会层与规范层须区分"工具普及节奏"与"裁决权普及节奏"，工具可快速普及，裁决权的普及不随工具自动发生。KLS3 三态预期与覆盖边界按层校准（见 KLS3 域级说明）。硬边界一：待裁决含两种成因——依据不足（可补充证据推进）与观测不可及（受现实手段限制，须附注成因，不得视作可短期推进）。硬边界二：默会部分无法编码，只能传递，不得强行清单化。

**五层阶梯**（主体与知识创造循环的关系位置，自下游向上下游）：

| 层 | 定义 | 判定依据示例 |
|----|------|-------------|
| 执行层 | 用模型跑循环做事：写作/编码/分析/批量生成 | 产出物是直接交付的执行结果 |
| 设计层 | 造循环：把工作流重构为可复用管线、技能包、基元链 | 产出物是可复用的工作流资产 |
| 验证层 | 装裁决门：把领域判断标准编码为可核验规则与清单 | 产出物是评估清单/校验脚本/形式化规则 |
| 问题层 | 定方向：决定循环往哪递归，构建问题清单与纲领 | 产出物是经过筛选的问题清单与研究纲领 |
| 品味层 | 定价值标准：判断什么问题值得进入循环、什么结果算重要 | 产出物是判断履历与共同体公认的取舍记录 |

**四稀缺环节**（循环内部尚未被普及、价值集中的功能位）：

| 环节 | 定义 |
|------|------|
| 问题选择 | 决定提什么值得解，构建并维护经过筛选的问题清单 |
| 验证器构建 | 把领域判断标准编码为可核验规则、清单或形式化系统 |
| 消化整合 | 把机器批量产出重构为可读、可教学、可入库的知识资产 |
| 实验裁决 | 通过物理实验/现实场景对候选做最终判定 |

**层与环节的关系**：四环节是循环内的功能位，五层是主体的占位坐标——验证层对应验证器构建，问题层对应问题选择，品味层收编消化整合与价值终审，实验裁决是验证层在物理世界的延伸。

**上移燃料**（从下层环节向上层环节移动时携带的资产）：

| 燃料 | 定义 |
|------|------|
| 数据 | 独家积累的数据与素材，孕育问题嗅觉 |
| 社区 | 共同体信任与协作网络，支撑协作与分发 |

#### D. 三态标注与白话注纪律（全包硬门禁）

所有裁决类输出必须三态标注：已裁决（规则/清单明确判定）/ 已校验（经验证据支撑方向）/ 待裁决（无充分依据，或观测不可及——受现实手段限制无法裁决，须附注成因）。禁止以"已校验"冒充"已裁决"。三态预期按领域可验证性分层校准（定义见总览 C 节）：形式层可推进至已裁决；实证层上限多为已校验；规范层条目不得标已裁决，应标已校验并附共识判据来源；默会层仅可言说边缘可编码入清单。验证器必须显式声明覆盖边界（哪些情形清单覆盖不了），覆盖边界不得为空；默会层覆盖边界必须显式声明核心默会部分不在覆盖范围内。

白话注规则：产出物中框架术语（可验证性分层/需求轨道/阶梯层级/环节/档位/三态/时钟阶段）首次出现时，括号附一句白话解释；诊断报告与路线图的结论必须附三句话白话版，比喻随使用者领域走。

#### E. 脱敏与保密条款（全包硬门禁）

脱敏（输出端）：不引用具体新闻事件、真实猜想名、真实人名、机构名、外部技能名；范本与示例一律使用假设领域与占位符；产出物引用文献须真实存在，不确定标注"待验证"；技能包自身不内置文献列表。

保密（输入端与检索端）：涉及使用者商业主体的材料，未经使用者明确授权不得联网检索、不得在产出物之外留存或转发；输入默认提示匿名化选项（以代号替换敏感名称）；落盘仅限使用者指定路径，会话结束提示清理；授权范围须记录在产物头部；对外分享或商业化交付前须复核脱敏与授权记录。

生活轨隐私与安全边界：涉及使用者或家庭成员个人隐私（健康/位置/财务/身份）的材料按保密条款同等纪律处理（匿名化、最小化采集、授权后检索）；生活轨产出涉及健康、食品安全、照护、法律与财务等专业领域时，须附"不替代专业意见"提示与适用边界，此类裁决点标"待裁决"，裁决权归专业者。

#### F. 模型能力分工防线与领域事实来源分级

生成/重组/结构化填充交给执行模型；技能规范与领域框架事实一律读 references/；裁决一律走 scripts/ 或评估清单；禁止凭模型参数记忆输出结构与事实；发现具体事件或人名引用即守护 FAIL。

领域事实来源三级（裁决依据适用，逐条标注来源级别）：①使用者提供资料——可直接作已校验依据；②授权检索的公开文献——标注真实来源后可作已校验依据；③模型参数记忆——一律标"待验证"，禁止作为裁决依据。三级均不足以支撑的表述标"待裁决"。

#### G. 执行框架概念定义（多域共用，禁止仅以名称引用）

**三轴正交**：执行轴（How，必选）——决定"怎么做"，任何任务必须走；内容轴（What，按需）——决定"产出的构成"，按任务需要启用；创新轴（Why Different，按需）——决定"与默认做法有何不同"，仅在需要差异化时启用。正交 = 三轴独立启用、互不依赖、可任意组合。

**六大元操作**：

| 操作 | 定义 | 本技能典型动作 |
|------|------|---------------|
| S 感知 | 从环境获取信息 | 采集需求、读取规范与数据目录 |
| C 认知 | 对信息加工与推理 | 环节判定、档位判定、方案规划 |
| A 行动 | 产生可观测产出 | 生成报告/清单/路线图/验证器包 |
| O 组织 | 结构化管理资源 | 知识入库、目录沉淀、归档 |
| I 交互 | 与外部主体建立关系 | 现状确认、路线确认、澄清问答 |
| G 守护 | 确保安全、合规、质量 | 三态检查、脱敏检查、脚本校验 |

**六种编排模式**：

| 模式 | 定义 |
|------|------|
| 顺序 | 前序任务输出作为后序输入，逐级执行 |
| 并行 | 无依赖的任务同时执行，结果汇聚 |
| 条件 | 按判定结果选择分支（如路由到不同域） |
| 循环 | 满足迭代条件时回到前序任务（如 KLS3⇄KLS4） |
| 扇出 | 一个输入分发给多个任务（如四模式各自产题） |
| 扇入 | 多个任务输出汇聚为一个结果（如整合交付） |

**清单法**：成品 = 组件组合。步骤：确认成品目标 → 构建组件清单 → 按清单逐项填充 → 组装成品 → 一致性核对。本技能中的形态：结构类产物（诊断报告/路线图/验证器清单/问题资产卡）一律按 templates/ 模板字段逐项填充。

**样本法**：成品 = 对样本的模仿产出。步骤：获取样本（references/KLS00~KLS05 中的标准输出样例）→ 分析样本的结构与风格（不分析内容）→ 以目标内容替换样本内容 → 自检与样例结构一致。纪律：仅借鉴结构与风格，不复制样本内容。

### KLS1 循环诊断域

#### 域级说明

在 KLS1-01 环节定位时先判定使用者领域所处可验证性层并记录；分层结论作为 KLS1-02 分档判定的相容性约束与 KLS1-03 时钟评估的节奏校准依据。默会层与规范层领域评估时钟时，须区分"工具普及节奏"与"裁决权普及节奏"。

**分档决策表（KLS1-02 判据，逐条核对）**

| 判据 | ①自主档 | ②协作档 | ③人类主导档 |
|------|---------|---------|-------------|

**普及时钟信号清单与区间规则（KLS1-03 判据）**

四类信号（至少覆盖两类方可给出阶段结论）：替代工具出现 / 平台商品化 / 成本曲线下降 / "不会做的人"存量。
阶段枚举：已普及 / 普及中 / 稀缺。

### KLS3 验证器构建域

#### 域级说明

**三态预期按层校准（KLS3-03 判据，四层定义见总览 C 节）**

| 层 | 验证器预期 | 覆盖边界要求 |
|----|-----------|-------------|
| 形式层 | 裁决点可完全形式化，条目可推进至已裁决 | 常规声明即可 |
| 实证层 | 条目上限多为已校验；待裁决须附注成因（依据不足/观测不可及） | 声明观测不可及的情形 |
| 规范层 | 判据即共识，条目不得标已裁决，应标已校验并附共识判据来源；清单更新即共识更新 | 声明共识未收敛的争点 |
| 默会层 | 仅编码可言说边缘，核心判断保留共同体裁决 | 必须显式声明核心默会部分不在覆盖范围内 |

**裁决台账协议（实证层 KLS3-05 必读；协议模式与 KLS4 数据路径协议同构）**

1. 用途：追踪假设的裁决状态推进（待裁决→已校验/已裁决），是实证层新知识创造的载体——无台账则实验结果回流断链；
2. 路径：使用者随时指定（本次会话指定 > 上次沿用 > 未指定时询问一次），支持多册并存，禁止指向技能包内部；
3. 懒创建：文件不存在时按骨架创建（标题+使用说明+表头：假设ID/领域/裁决点/最小裁决判据/当前状态/成因/实验安排/结果/更新日期，零数据行）；
4. 状态推进：只更新状态列与结果列并刷新更新日期，不改写历史行；状态变化须附证据来源（使用者回报/文献/实验报告，按来源分级标注）；
5. 回流联动：状态推进后评估是否触发时钟重估（KLS0-04）与清单迭代（KLS3-06）。

**分层运行校准（KLS3-01/04/05 按层执行，与需求轨道正交）**

| 层 | 裁决点处理（KLS3-01/02） | 验证器形态（KLS3-04） | 闭环机制（KLS3-05） |
|----|------------------------|----------------------|---------------------|
| 形式层 | 全部归入可形式化组；归约失败即回退复查直觉图景 | 默认脚本化/形式化（可执行规则、证明检查清单），裁决由脚本自动执行 | 脚本运行即闭环；异常输入转人工 |
| 实证层 | 可形式化组+需实验裁决组 | 清单+最小裁决判据，脚本仅做预筛 | 裁决台账（见上方裁决台账协议） |
| 规范层 | 可形式化组+共同体裁决组 | 共识判据清单，每条目附判据来源（权威文本/共同体决议） | 共识更新程序：评议周期/异议登记/版本记录，清单更新即共识更新 |
| 默会层 | 直觉图景为主载体，清单仅编码可言说边缘 | 直觉图景+示范案例集为主，清单为辅 | 传递方案：示范者/练习安排/反馈回路，传递效果回访记录 |

### KLS4 问题资产域

#### 域级说明

**四模式定义表（KLS4-01 判据与操作）**

| 模式 | 定义 | 操作步骤 | 创新路径标注格式 |
|------|------|---------|-----------------|
| 直用 | 将已验证的方法范式原样应用于本领域的新对象或新场景 | 枚举已验证范式 → 逐一试套 → 标注适配改动 | 已验证范式 → 新对象/场景 |
| 改进 | 对领域默认假设或现有方案施加系统化变形，从变形空间提取问题 | 列出默认假设 → 逐条反转/极端化/加约束 → 筛选可行项 | 默认假设反转/极端化 |
| 迁移 | 将源领域底层结构提取为抽象模式后投射到本领域 | 选异质源领域（结构可提取且与本领域异质）→ 抽象化 → 投射 → 提炼问题 | 源领域 → 抽象模式 → 目标领域 |
| 构建 | 将两个不相关概念解构为维度后强制连接，产出反常识组合 | 各解构 3~5 个维度 → 建立维度矩阵 → 强制连接 → 可能性集群 → 提炼问题 | 概念甲维度 × 概念乙维度 |

**十种创新元框架（KLS4-01 改进模式算子，可单用或组合）**

| 框架 | 操作要点 | 适用领域特征 |
|------|---------|-------------|
| 第一性原理 | 分解到不可再分的基本事实，区分假设后仅从事实重建 | 理论根基厚但需重构 |
| 逆向思维 | 列核心假设逐一反转并推到逻辑极端，重建可行方案 | 共识太强缺乏批判 |
| 辩证综合 | 正反双方全力构建最强论证，识别各自局限，创造包含并超越双方的新立场 | 存在对立学派/范式 |
| 随机性驱动 | 引入无关概念强制组合，保留看似荒谬但有趣的连接发展为方案 | 需要跨界灵感 |
| 涌现生成 | 定义基本单位与简单规则，让系统运行足够步数，记录涌现模式提取方案 | 复杂系统/社会现象 |
| 演化迭代 | 随机生成多方案 → 评估筛选 → 交叉变异 → 循环至最优 | 有多个候选方向 |
| 系统动力学 | 识别存量/流量/反馈/延迟，找高杠杆干预点 | 有反馈回路的动态机制 |
| 约束驱动 | 强化现有约束或添加新约束，在边界内穷尽可能性 | 约束反而激发创新 |
| 故事叙述 | 用叙事框架（主角/欲望/障碍/转变）重构，映射回现实 | 人文叙事/意义建构 |
| 游戏化 | 转化为游戏机制（挑战/选择/反馈），输出可立即使用的方案 | 行为激励/参与设计 |

**迁移类型与源领域质量检验（KLS4-01 迁移模式前置判据）**

迁移四类型：机制迁移（核心机制）/ 结构迁移（结构关系）/ 方法迁移（方法论）/ 概念迁移（核心概念重新定义后迁移）。

源领域质量检验（不通过时更换源领域并说明理由）：

| 检验维度 | 检验内容 | 不通过标志 |
|---------|---------|-----------|
| 结构可提取性 | 源领域有清晰可描述的底层结构 | 无法形式化描述输入→处理→输出 |
| 抽象层级匹配 | 抽象模式在目标领域有对应物 | 过于领域特异无法映射 |
| 异质充分性 | 与目标领域差异度足以产生新视角 | 源与目标过于同质 |
| 可验证性 | 迁移方案可在目标领域操作化验证 | 无法在目标领域落地检验 |

**基元运用深度选择（KLS4-01 执行方式）**

| 方式 | 特征 | 输出量 | 适用 |
|------|------|--------|------|
| 基元嵌入（快速通道） | 在基元执行框架内调用某策略，单步处理 | 每方式 2~3 个选题 | 快速多角度扫描 |
| 独立模式（完整流程） | 完全进入策略角色，按完整流程多步递进 | 框架级 2~5 个选题 | 某策略深度挖掘 |

基元重组：基元（输入→处理→输出）本身可重组为创新链路——串联（A 输出→B 输入）/ 并联（同一输入送多基元→汇总）/ 嵌套（基元内嵌子基元）/ 递归（输出回流自身迭代），链路结构本身即创新方式。

**约束**：除非使用者指定模式子集，四模式至少各生成 1 条候选；改进模式必须声明所用元框架；迁移模式必须先通过源领域质量检验；每题标注来源模式与创新路径（按四模式定义表格式）；生成前先走数据路径协议查重。

| 维度 | 判定内容 | 不通过标志 |
|------|---------|-----------|
| 机制明确性 | 假设有可检验的因果或作用机制 | 只有效果断言、说不出为何成立 |
| 证据可得性 | 所需数据、文献或检测方法可获得 | 关键证据全部无来源（来源分级见总览 F 节） |
| 实验成本适度 | 验证成本与预期收益匹配 | 验证代价明显超过收益上限 |
| 收益非平凡性 | 优化收益值得投入验证 | 收益可忽略或与现有方案无差异 |

**分层分轨评估与标注规则（KLS4-01/02 判据；层与轨正交：层定裁决与证据形态，轨定价值标准与交付形态）**

1. 评估维度：学术轨用学术四维，实证层工程优化用工程型校准表；商业轨其余候选（如规范层市场/策略类问题）以"价值依据"维度替换"理论传统"（可论证的商业价值来源：成本数据/市场需求/合规要求），其余维度沿用；生活轨以"生活依据"维度替换"理论传统"（可观察的生活痛点/使用频率/改善可感知性），宽窄适度以个人或家庭可执行为参照；筛选表须注明判据版本；
2. 商业轨标注：候选附价值标注（预期收益类型：降本/增效/合规/新品；适用对象/场景）；
3. 保密与隐私标注：涉商业主体的候选以代号入册，保密级别与授权状态按 E 节保密条款记录；涉个人与家庭隐私的生活轨候选以代号处理；标注写入"问题表述"列尾部（【价值：…】【保密：…】），不新增列，保持与既有册表头兼容。
4. 分层校准：形式层候选以命题形式表述（猜想/反例/推广），"预期非平庸结论"列写命题与证明路径；规范层候选以规范脉络（法条/判例/伦理框架/行业惯例）充实理论传统列；默会层候选多为"默会判断显性化"类，以实践脉络（师承流派/成熟范式案例）替换理论传统，示范案例即证据形态。

**数据路径协议（KLS4-01 / KLS4-04 必读）**

1. 路径优先级：本次会话使用者指定 > 上次沿用 > 未指定且无历史时询问一次；
2. 多册并存：按研究方向可建多册，切换即换当前生效册，历史册不删除、不自动合并；查重默认当前册，跨册查重为深化可选项；
3. 路径格式：绝对路径或相对路径（以当前工作目录为基准）；禁止指向技能包内部；
4. 懒创建：文件不存在时按 templates/KLS-question-asset-template.md 的骨架创建（标题+使用说明+表头，零数据行）；
5. 幂等追加：只增数据行，永不改写骨架与已有行；手动编辑与程序追加同权；
6. 发布分离：打包或分享技能时不包含数据文件。

### 项目包构建（跨域交付形态，不属于单一域）

方法产出之后，若要落到多人多轮协作中运行，把它打成一个可独立复制的项目包。项目包跨 KLS3（验证器）、KLS5（交付）与治理条款，故单列，不并入任何一域。

#### 适配性自检（四条前提，缺一条不得构建）

| # | 前提 | 判断问题 | 不满足说明什么 |
|---|------|---------|---------------|
| 1 | 多轮次 | 要跑几轮才能逼近答案 | 一轮够 → 是任务，不是项目 |
| 2 | 多方协作 | 是否至少两方，各握对方没有的东西 | 一人可完成 → 不需要契约 |
| 3 | 有裁决点 | 能否用实测/试点/审核判定成没成 | 判不了 → 只能说服，不是验证 |
| 4 | 要沉淀判据 | 本轮结论能否用于下一轮 | 不能 → 无累积价值 |

四条全过方可构建；三条以下改用普通文档。硬套只会得到八份填不满的表，三方花两周讨论"格子填什么"而不是干活。

#### 五位置翻译（构建前置动作）

**不得先填表。** 先答三问：①"改一个变量→看结果→算值不值"的循环具体长什么样；②一轮多长、多少成本；③谁能裁决"成了/没成/测不出来"。

三答对应五位置：输入变量集（动什么）、目标量（看什么，只能一个）、约束量（不能变差的部分）、裁决手段（怎么看＋谁能判）、实施边界（成本与周期所限范围）。

#### 八件套迁移要点

| 件 | 迁移改什么 | 常见错法 |
|----|-----------|---------|
| 作业包说明 | 包名、角色名、开工步骤 | 正文残留"产品/配方/实测"字样 |
| 项目信息 | 项目名、领域、参与人 | 只改项目名，开包清单条目未换 |
| 归属与许可 | 产出物类型（数据/报告/模型/名单） | 沿用"配对数据归甲方、实测数据归乙方" |
| 作业契约 | 五位置、P1～P9 实例化、六步、表 A～F 列 | **只改名词不改判据**（最大坑） |
| 轮次页 | 表单字段、实测条件四项 | 保留"温度/湿度/设备代号" |
| 配对数据册 | "配对"在本场景的定义、A/B/C 分级标准 | 沿用三词定义而不重新界定 |
| 判据台账 | 槽位名称 | — |
| 四道锁 | 各方各自的"原料"是什么 | 照搬"配方归甲方、设备归乙方" |

#### 判据实例化自检（最易走样处）

把领域词硬换而保留原因果逻辑，即失效。逐条自问"**这句话在这行里具体指什么**"，答不出即未实例化。以 P7 为例：

| 场景 | P7 所指 |
|------|--------|
| 产品拆解 | 每降 1 单位成本，牺牲多少性能 |
| 市场进入 | 每多投 1 元促销，换多少动销 |
| 招聘渠道 | 每多花 1 元渠道费，换多少入职 |
| 内容投放 | 每多投 1 元，换多少有效留资 |

四个都不一样，结构相同——这就是"槽位"的含义：位置固定，含义填充。

#### 非产品场景示例

| 位置 | 市场进入验证 | 招聘渠道效果验证 |
|------|-------------|-----------------|
| 输入变量集 | 定价档位、渠道组合、首铺 SKU 数、促销力度 | 渠道组合、JD 措辞、薪资区间、面试环节数 |
| 目标量 | 首 90 天单店月均动销 | 投递到入职的转化率 |
| 约束量 | 毛利率下限、品牌价格带、现金流安全线 | 单人招聘成本、offer 接受率、用人部门满意度 |
| 裁决手段 | 3～5 家样板店试销 + POS 数据 | 分渠道小流量投放 + 招聘系统数据 |
| 实施边界 | 现有经销商覆盖、合规准入 | 预算上限、合规要求（不得歧视性筛选） |

三方分工同构：业务方/用人部门（握客户与预算，否"值不值得做"）、执行方（握渠道与落地，否"做不了"）、分析方（握判据与跨案例，否"不可信"）。轮次序列同构：探边→收口→外推→校准。P9 在两例中均归约失败（真实支付意愿 / 候选人长期质量），只能问不能算。

#### 验收（三条，缺一退回）

1. 五位置每格为**具体内容**（非"待定""视情况"）；
2. P1～P9 每条有**本领域判定标准**（非照抄通用描述）；
3. 覆盖边界写出**本领域三类排除**（非"暂不适用"）。

第三条最易糊弄也最易出事——边界不写清，一轮跑完就会把它当成通用结论。

#### 格式

`templates/KLS-package-*` 八件套；复制与改名见 `templates/KLS-README.md`；初始化脚本 `scripts/KLS_package_init.py`。

生成式构建（非复制）时，**契约的 html 版不会自动出现**——内容换了，版式须重排。做法：拿现成包内 html 作版式底板，替换内容，不从零编写。仅求能开工时可暂缺（html 属次要件），但对外共读或打印前须补齐。
