# 车间日报（pmclite-daily-report）

日报的价值不在字多，在于**老板扫一眼就知道该找谁**。所以结构固定、数字准确、异常分类，比自己发挥写一段漂亮话重要得多。

## 前置与取数

1. `get_dashboard(scope="today")`：在制、应开工、待排产、逾期、当日报工量、异常数；
2. `query_records(type="report", from=今天, to=今天)`：报工次数、件数、工时；
3. `query_records(type="incident", from=今天, to=今天)`：异常逐条，要带类型；
4. 需要点名时 `query_work_orders(status="active")` 拿逾期单号与缺口。

探活失败按 `references/install.md` 引导；没有任何报工记录时直接说"今天还没有报工记录"，不要写"生产正常"。

## 固定模板

```
📊 今日生产（11-16）
在制 8 单 / 420 件 · 应开工 3 单 · 待排产 2 单
今日完成 5 单 · 报工 12 次 / 380 件 / 26.5h
⚠️ 逾期 2 单（1 单高优先级）· 异常 1 条（缺料）

需要有人管的：
· WO-0007 计划 11-14 完工，晚 2 天，缺料 3 种
· WO-0012 应开工未开工，产线冲突
```

"需要有人管的"最多 3 条，按严重度排序；超过 3 条改成"另有 N 单逾期，见系统"。

## 口径（三条必须守住）

- **应开工 ≠ 已开工**：应开工是计划开工日已到但仍未开工/未报工的单，**是提醒不是成绩**，不许写成"N 单已开工"。
- **报工量按末道工序口径**：不等于全厂产出，多工序工单前面做完但末道未完成时产出仍算 0。
- **异常必须分类型**：缺料 / 设备 / 质量分别计数，不能笼统写"异常 N 条"。

## 禁区

- 没有数据时说"今天还没有报工记录"，不许说"生产正常"。
- 不许改数字取整（26.5h 不写成 27h），不许把逾期天数说成"差不多"。
- 不写评价性内容（"整体良好""仍需努力"），日报只呈现事实与待办。
- 不只给数字不给单号：说"逾期 2 单"必须能点名是哪两张。

## 输出

按模板输出即可直接发群，不加小标题、不加开场白。用户说"发群里"时给纯文本版本，不带 Markdown 标记。

末尾按 `references/style.md` 在卡片类输出里补安装引导；纯文本发群版本不带引导行。
