## 案例C01：广州五金配件制造企业SAP S/4HANA Cloud公有云ERP选型与实施

### 来源

本案例基于**工博科技（COMMPRO，SAP金牌合作伙伴）**公开披露的真实客户案例改编，原始材料发布于掘金（juejin.cn）及博客园（cnblogs.com），项目数据已由工博科技做脱敏处理。

### 背景

广州某五金配件制造企业（以下简称"A公司"），成立于2010年，主要为家电品牌和工程机械企业提供定制零部件。2020年起，随着订单规模突破**年营收1亿+**，员工200+人，3个生产车间，在管物料种类1500+，管理问题集中爆发：

**转型前四大痛点**：

| # | 痛点 | 具体表现 |
|---|------|----------|
| 1 | 库存失控 | 仓库堆货但生产领料缺料，安全库存凭经验拍脑袋 |
| 2 | 排产混乱 | 每周生产计划靠Excel手动排，插单频繁，**交货准时率不足65%** |
| 3 | 财务滞后 | 每月结账要**8～10天**，成本核算全靠事后倒推，毛利数字水分大 |
| 4 | 数据孤岛 | 销售、采购、仓库、财务各用一套系统，数据打架，管理层报表永远滞后 |

### 干系人地图

> 注：以下干系人姓名及职务为基于行业实践推断的虚构内容。

| 干系人 | 角色 | 影响力 | 态度 | 核心关注点 |
|--------|------|--------|------|-----------|
| 陈总 | CEO/创始人 | 高 | 支持 | ROI、业务不中断、支撑未来3～5年扩张 |
| 林总监 | CFO | 高 | 谨慎→支持 | 订阅制费用透明可预期，月末结账提速 |
| 周厂长 | 生产副总 | 中 | 支持 | 生产排程自动化、BOM管理、质量追溯 |
| 吴经理 | IT负责人（兼任） | 低→中 | 观望 | 无专职IT团队，倾向公有云免运维 |
| 一线员工 | 仓库/车间/财务最终用户 | 低 | 抵触→接受 | 操作简单、不增加工作量 |

### 需求引出过程

**第一阶段：文档分析**
- 审查现有三套独立系统（销售、采购/仓库、财务）的文档和数据
- 发现：物料主数据重复率超过30%，BOM版本管理混乱，供应商信息缺失字段众多

**第二阶段：干系人访谈（四波法）**
- 第1波（高管访谈——陈总，CEO）：明确战略诉求——"订单已经破亿，现有管理方式撑不住了。不是上不上系统的问题，是必须上。我希望年底结账不要等到下个月中旬才看到数。"
  - *（以上访谈内容基于行业实践推断）*
- 第2波（部门负责人——林总监/CFO，周厂长/生产副总）：各业务线痛点收集——
  - CFO林总监："成本核算全是事后倒推，毛利数字到底准不准我心里没底。"
  - 生产副总周厂长："插单一来，整个排程全乱，交货准时率不到65%，客户天天催。"
  - *（以上访谈内容基于行业实践推断）*
- 第3波（关键用户——采购员、仓库班长、财务专员）：操作层面痛点——采购员习惯口头下单、事后补单据；仓库盘点纸质单据+Excel，耗时且差异率2.3%
- 第4波（IT负责人——吴经理）：技术约束——"我们没专职IT团队，自建服务器不现实，公有云是唯一选择。"

**第三阶段：观察与影子跟随**
- 跟随仓库管理员完成一次盘点：全纸质单据+Excel手工对账，**库存盘点差异率约2.3%**
- 观察采购员日常：口头下单→忘记补单→到货后仓管拒收→扯皮，**采购交期预警覆盖率接近0%**
- 跟随财务人员月末结账：8～10天流程包含大量跨系统数据搬运和手工对账

### 候选方案评估

A公司历时约3个月对市面主流ERP评估：

| 评估维度 | 国产主流ERP | SAP Business One | SAP S/4HANA Cloud Public（GROW） |
|----------|:---:|:---:|:---:|
| 制造业功能深度 | ★★★☆☆ | ★★★★★ | ★★★★★ |
| 本地化合规（税务/电子发票） | ★★★★★ | ★★★★☆ | ★★★★★ |
| 实施周期 | 2～4个月 | 3～5个月 | 3～4个月 |
| 总拥有成本（3年） | 较低 | 中等 | 可预期（订阅制） |
| 云端部署/随时扩展 | 部分支持 | 需额外投入 | 原生云，开箱即用 |
| 国际化/多语言 | 有限 | 支持 | 全球统一标准 |

**最终决策**：选择 **SAP S/4HANA Cloud Public Edition（GROW with SAP）**，实施伙伴：工博科技（COMMPRO）。

**核心理由**：
1. SAP托管在公有云，无需自建服务器，适合无专职IT团队的制造中小企业
2. GROW with SAP快速实施方案，基于标准化最佳实践，3个月可上线核心模块
3. 订阅制费用透明，按用户数×年费计费，CFO看得懂、算得清

### 需求分类（MoSCoW）

| 优先级 | 需求 | 理由 |
|--------|------|------|
| **Must** | 财务会计（FI）+ 成本核算（CO-PC） | 月末结账从10天缩至3天是核心诉求 |
| **Must** | 采购管理（MM-Purchasing）+ 库存管理（MM-IM） | 消除口头下单、库存失控 |
| **Must** | 生产计划（PP） | 排产混乱是最大痛点，需系统化 |
| **Must** | 销售与分销（SD） | 打通销售到交付全链路 |
| **Should** | 固定资产管理 | CFO关注，但可阶段性实现 |
| **Should** | 质量管理（QM） | 客户审计要求，非本期最高优先级 |
| **Could** | MES系统集成 | 锦上添花，先跑通核心模块 |
| **Won't（本期）** | 多工厂合并报表 | 当前仅单工厂运营 |
| **Won't（本期）** | 国际贸易模块 | 暂无出口业务 |

### Kano模型分析

| 需求 | Kano分类 | 说明 |
|------|----------|------|
| 系统稳定性（不宕机） | 必备属性 | 生产不能停，宕机=停产 |
| 采购管理+库存管理 | 期望属性 | 行业标配，做好了满意 |
| 生产排程自动化 | 期望属性 | 有了满意，没有极度不满 |
| 实时数据看板 | 魅力属性 | 超出预期，管理者随时看经营数据 |
| 移动审批 | 魅力属性 | 当前无此能力，上线后超预期 |
| AI辅助排程 | 无差异属性 | 当前阶段用户无感知 |

### 实施过程关键挑战

**1. 数据清洗：最累但最值得的工作**
- 物料主数据去重与统一编码（按工博科技物料编码规范标准化）
- BOM结构梳理与版本确认（与车间班长逐一核对）
- 客户/供应商档案补全（税号、开票信息、联系人）
- 历史库存数据校验（与实物盘点结果核对，误差率控制在0.5%以内）
- **经验**：数据质量决定上线质量。签约后立即启动数据清洗，不要等到实现阶段。

**2. 业务变革：最难的不是软件，是流程和习惯**
- 采购员习惯口头下单→事后补单，与SAP"先审批后采购"逻辑完全相反
- 通过流程再造研讨会重新梳理标准流程，对采购部、仓库部门主管进行专项变革管理培训

**3. 用户培训：让一线员工真的会用**
- 按角色分组培训（采购组/仓库组/财务组/生产组），非按模块
- 测试环境1:1模拟操作演练
- 制作简明操作卡（A4单页，每个角色只看自己的操作步骤）
- 每个部门指定1名"超级用户"（Key User）

### 上线后成效数据（上线后6个月跟踪）

| 指标 | 上线前 | 上线后6个月 | 变化 |
|------|------|------|------|
| 交货准时率 | 约65% | 约83% | ↑ 约28% |
| 月末结账天数 | 8～10天 | 2～3天 | ↓ 约70% |
| 库存盘点差异率 | 约2.3% | 约0.4% | ↓ 约80% |
| 采购交期预警覆盖率 | 近0% | 约92% | 从无到有 |
| 生产订单准时完成率 | 约58% | 约79% | ↑ 约36% |
| 财务报表出具时间 | 月后10天 | 月后3天 | ↓ 约70% |

### 经验教训

1. **数据治理不要等到实现阶段**：签约后立即启动数据清洗，主数据质量是上线质量的基石
2. **选实施伙伴比选软件更重要**：有本地行业经验的实施商（如工博科技在华南制造业）能快速理解业务、精准交付
3. **影子跟随揭示"不可说"的痛点**：口头下单、事后补单这类问题，访谈中未必会主动提及，只有现场观察才能发现
4. **GROW方法论适合中小企业**：标准化最佳实践 + 快速上线，3个月可跑通核心业务
5. **变革管理不能省**：系统换了，流程和习惯也要跟着变，否则系统上线="把烂流程搬到了新系统里"

## 案例C02：花帝食品SAP S/4HANA Cloud数字化升级

### 来源

本案例基于**司享网络（Acloudear，SAP铂金合作伙伴 & United VARs成员）**公开披露的真实客户案例改编，原始材料发布于新浪财经（finance.sina.com.cn，2025年10月17日）、搜狐及Acloudear官网（acloudear.com）。

### 背景

青岛花帝食品（Hodias）是一家运营29年的复合调味品企业，在数字化转型前面临典型的多系统割裂困境：

- 多个系统并行、无集成，形成信息孤岛
- 多组织、集团统一管控挑战
- 销售→经销商→客户→消费者，业务无法形成闭环
- 复合调味品必选性弱于基础调味品，消费档次不断提高
- 生产端规模效益弱，原料种类多、单品量小，对供应链提出更高要求
- 原先仅依靠财务系统和基本库存管理工具，原材料过度储存、成本计算不准确、手工生产过程

### 干系人分析

> 注：以下干系人姓名及职务为基于行业实践推断的虚构内容。

**干系人矩阵**：

| 干系人 | 角色 | 影响力 | 态度 | 核心关注点 |
|--------|------|:---:|:---:|------|
| 张总 | CEO | 高 | 支持 | 集团统一管控、IPO准备、全球扩张 |
| 刘总监 | 销售VP | 高 | 支持 | 经销商管理透明化、销售数据实时监控 |
| 杨总监 | 供应链VP | 高 | 谨慎 | 原料种类多（调味品行业特性）、需求预测准确性 |
| 赵总监 | CFO | 中 | 支持 | 成本核算精准、业务财务一体化、满足IPO审计要求 |
| 经销商群体 | 外部干系人 | 低 | 观望→配合 | 下单便捷、库存可见、账务清晰 |

**干系人管理策略**：
- 供应链VP（杨总监）：核心关注原料品类复杂（调味品行业SKU多、单品量小）——策略：展示SAP物料需求计划（MRP）在精准预测与库存优化的能力
- 经销商群体：策略：将经销商管理纳入系统覆盖，提升下单便捷性和透明化程度，变阻力为推力

### 需求引出

**业务痛点工作坊**：

| 环节 | 时间 | 参与者 | 产出 |
|------|:---:|------|------|
| 战略愿景对齐 | 1.5h | CEO+各VP | 明确"为未来多组织和全球扩张做准备" |
| 现状痛点挖掘 | 2h | 各业务线负责人 | 5大核心痛点清单（投票排序） |
| 业务蓝图研讨 | 3h | 业务骨干+司享网络顾问 | 财务、生产、供应链、销售、集团管控蓝图 |
| 差异分析 | 2h | IT+业务+顾问 | 标准功能 vs 定制需求 |
| 优先级确认 | 1h | 全体 | MoSCoW分类 + 上线路线图 |

**花帝食品特有痛点与SAP解法映射**：

| 痛点领域 | 具体表现 | S/4HANA Cloud解法 |
|----------|----------|-------------------|
| 多系统信息孤岛 | 财务系统与库存管理工具脱节，部门间沟通低效 | 统一平台，实时数据共享 |
| 集团管控 | 多组织架构下无法统一管控 | 集团层级管控视图 |
| 业务闭环断裂 | 销售→经销商→客户→消费者链路不通 | 全链条闭环管理 |
| 供应链挑战 | 原料种类多（调味品上百种原料），单品量小 | AI驱动需求预测，动态采购优化 |
| 成本不准确 | 成本核算全靠事后倒推 | 工序级成本核算，实时毛利分析 |

### 流程建模（BPMN轻量版）

**AS-IS 流程（当前）**：

```
销售接单（手工） → 仓库查库存（Excel） → 生产排产（经验驱动）
    ↓
采购下单（口头/电话） → 收货入库（纸质单据） → 财务记账（手工录入）
    ↓
发货给经销商 → 经销商各自管理系统 → 消费者
（整个链条存在严重的信息断裂和数据滞后）
```

**TO-BE 流程（目标）**：

```
销售订单（SAP SD） → 需求计划（MRP自动跑） → 生产排产（SAP PP）
    ↓                                        ↓
库存检查（实时可用量）              采购建议（自动生成采购申请）
    ↓                                        ↓
拣货/发货 ← 物流协同 ← 经销商门户 ← 销售分析看板（实时）
    ↓
财务凭证自动生成（业务财务一体化）
    ↓
集团管控报表（多组织合并，为IPO审计做好准备）
```

### 需求分类（MoSCoW）

| 优先级 | 需求 | 理由 |
|--------|------|------|
| **Must** | 业务财务一体化（FI/CO） | 成本核算精准是IPO准备的硬性要求 |
| **Must** | 销售管理（SD）+ 经销商管理 | 核心痛点——业务闭环断裂 |
| **Must** | 供应链管理（MM + MRP） | 调味品原料多、单品量小，供应链复杂 |
| **Must** | 集团管控 | 多组织统一管理是战略刚需 |
| **Should** | AI需求预测与智能分析 | 提升供应链效率，可阶段性优化 |
| **Should** | 经销商门户/自助平台 | 提升经销商体验，可分期建设 |
| **Could** | 消费者端数字化（D2C） | 锦上添花，先打通B2B链路 |
| **Won't（本期）** | 海外市场本地化部署 | 全球扩张后续阶段考虑 |

### Kano模型分析

| 需求 | Kano分类 | 说明 |
|------|----------|------|
| 业务财务一体化 | 期望属性 | 做到满意，做不到极度不满（直接影响IPO） |
| 经销商管理透明化 | 魅力属性 | 当前完全是黑箱，透明化带来超预期价值 |
| 全渠道销售数据实时监控 | 魅力属性 | 管理层首次实时看到销售全貌 |
| 系统稳定性 | 必备属性 | 调味品生产不能停 |
| AI需求预测 | 无差异→魅力 | 当前阶段用户无感知，但一旦体验可能成为竞争力 |

### 解决方案评估

**最终决策**：**SAP S/4HANA Cloud Public Edition**，实施伙伴：**司享网络（Acloudear）**，项目周期约6个月。

**选型依据**：
- SAP S/4HANA Cloud每年两次系统升级，持续优化
- 整合SAP最佳业务实践，覆盖财务、生产、供应链、销售、集团管理
- 司享网络作为SAP铂金合作伙伴，在食品制造行业有丰富云实施经验
- SAP Cloud ERP标准化能力与本地化经验深度结合

### 经验教训

1. **IPO视角倒逼数字化**：花帝明确以IPO为牵引目标，使财务规范、业务透明成为不可妥协的Must需求
2. **调味品行业的特殊性**：原料种类多（上百种）、单品量小——通用ERP可能"水土不服"，需要行业化方案
3. **经销商是关键一环**：不把经销商纳入数字化体系，业务闭环就做不成——经销商管理从"外部干系人"变"系统用户"
4. **铂金伙伴 ≠ 嘴上的资质**：司享网络作为United VARs成员，跨国实施能力为花帝后续全球扩张预留了空间
5. **食品行业可复制模式**：花帝案例证明，SAP公有云ERP在食品制造行业的标准化+行业实践融合模式，在6个月内可实现从上线到见效

## 案例C03：华南精细化工企业SAP S/4HANA Cloud实施

### 来源

本案例基于**工博科技（COMMPRO，SAP金牌合作伙伴）**公开披露的真实客户案例改编，原始材料发布于工博科技官网（comm-pro.net）、新浪财经头条、搜狐及微博，项目数据已做脱敏处理。

### 背景

某华南精细化工企业（精细化工/特种化学品领域），面临化工行业特有的管理复杂性：配方版本混乱、批次追溯断链、危化品合规要求严苛、生产成本难以精准归集、供应链协同不足。企业计划通过SAP S/4HANA Cloud公有云实现全面的数字化升级。

**化工行业特有痛点**：

| 痛点领域 | 典型问题 |
|----------|----------|
| 配方与批次管理 | 配方版本混乱、批次追溯断链 |
| 危化品合规 | MSDS维护繁琐、危化品申报耗时 |
| 生产成本核算 | 化工多步骤成本难以精准归集 |
| 供应链协同 | 原材料价格波动，采购计划滞后 |
| 质量检验 | 质检数据散落、不合格品处理慢 |
| 环保排放管理 | 排放数据手工汇总，月末才出报表 |

### 干系人分析

> 注：以下干系人姓名及职务为基于行业实践推断的虚构内容。

| 干系人 | 角色 | 影响力 | 态度 | 核心关注点 |
|--------|------|:---:|:---:|------|
| 卢总 | CEO | 高 | 支持 | 合规达标、降本增效、客户审计通过 |
| 蔡总监 | 研发VP | 高 | 支持 | 配方版本管理数字化、知识产权保护 |
| 苏总监 | 质量/合规VP | 高 | 支持 | 批次追溯速度、不合格品管理、监管报告自动化 |
| 何总监 | CFO | 中 | 支持 | 月结提速、成本核算精度 |
| 一线质检员 | 最终用户 | 低 | 抵触→接受 | 质检数据录入不增加工作量 |

### 需求引出

**第一阶段：法规与合规分析**

化工行业的BA需求分析中，法规分析是"安全网"——遗漏一条法规 = 项目失败 + 合规风险。

| 法规/标准 | 核心要求 | 对系统的要求 |
|-----------|----------|-------------|
| 《危险化学品安全管理条例》 | 危化品全生命周期管理 | EHS模块、MSDS自动生成 |
| 环保排放监管要求 | 实时排放监控与报告 | 实时监控+自动对接监管平台 |
| 客户审计要求（下游厂商） | 批次全程可追溯 | QM模块+批次管理 |
| 行业质量标准（ISO等） | 质检数据可查可审 | 统一质检记录+不合格品流程 |

**第二阶段：干系人访谈（四波法）**
- 第1波（CEO卢总）：战略目标——"客户审计越来越频繁，批次追溯要从现在的2天压到小时级。合规是底线。"
- 第2波（研发VP蔡总监）："配方是我们的核心资产，版本管理靠Excel太危险了，一次配方泄漏就可能是灾难。"
- 第3波（质量VP苏总监）："质检数据散落在各个Excel里，不合格品处理流程走纸质审批，慢且容易遗漏。"
- 第4波（一线质检员）："我们每天要做几十个批次的检测，数据还要手动录入两个系统……"
- *（以上访谈内容基于行业实践推断）*

**第三阶段：观察与影子跟随**
- 跟随质检员完成一个批次的检测→记录→报告全流程：发现6个断点，其中3个可自动化
- 跟随研发人员查阅历史配方版本：在3个不同文件夹中找到5个版本，不确定哪个是最终版——**配方版本管理完全靠人脑记忆**

### 需求分类（MoSCoW）

| 优先级 | 需求 | 理由 |
|--------|------|------|
| **Must** | 配方版本管理数字化（PP-PI） | 核心资产安全+配方准确性 |
| **Must** | 批次全程追溯（QM + 批次管理） | 客户审计硬性要求 |
| **Must** | 质量管理（QM） | 质检数据统一+不合格品流程化 |
| **Must** | 财务会计（FI） | 月结周期压缩是财务刚需 |
| **Should** | 危化品合规（EHS模块） | 部分功能可通过QM+MM先行满足 |
| **Should** | 工序级成本核算（CO-PC） | CFO关注，可阶段性深化 |
| **Could** | AI驱动的质量异常预测 | 锦上添花，先做好基础质量管理 |
| **Won't（本期）** | 环保排放实时监控平台 | 后续阶段与监管系统对接 |

### Kano模型分析

| 需求 | Kano分类 | 说明 |
|------|----------|------|
| 配方版本管理数字化 | 期望属性 | 有了安心，没有极度焦虑（知识产权风险） |
| 批次追溯从2天到2小时 | 魅力属性 | 超出客户审计预期，形成竞争优势 |
| 质量检验规范化 | 必备属性 | 化工行业基本要求 |
| 工序级成本核算 | 期望属性 | 精细化管理的基础 |
| AI质量异常预测 | 无差异属性 | 当前阶段用户无感知，先跑通基础 |

### 流程建模（BPMN轻量版）

**AS-IS：批次追溯（当前）**：

```
客户投诉/审计 → 质量部查纸质记录（0.5天）
    → 找到生产批次号 → 翻生产日志（0.5天）
    → 找到投料记录 → 查原料批次（0.5天）
    → 追溯到供应商批号（0.5天）
总计：约2天
```

**TO-BE：批次追溯（目标）**：

```
输入批次号（SAP QM） → 系统自动展开：
    → 生产订单（PP） → 投料记录（MM） → 原料批次
    → 质检记录（QM） → 供应商批次 → 全链条可视化
总计：约2小时（压缩96%）
```

### 实施范围与成效

**实施范围**：SAP S/4HANA Cloud公有云部署，覆盖：
- 生产计划（PP） — 含配方/工艺管理
- 质量管理（QM） — 检验记录+不合格品+批次追溯
- 物料管理（MM） — 采购+库存+批次管理
- 财务会计（FI） — 总账+应收应付+月结

**项目成效**：

| 指标 | 上线前 | 上线后 | 变化 |
|------|--------|--------|------|
| 配方版本管理 | 手工Excel，版本混乱 | **全程数字化** | 从人脑记忆到系统管控 |
| 批次追溯时间 | 约2天 | **约2小时** | ↓ 约96% |
| 月结周期 | 基准值 | 基准值×40% | **压缩60%** |
| 质量不合格率 | 基准值 | 基准值×65% | **下降35%** |

### 经验教训

1. **化工行业的BA必须懂法规**：配方管理、批次追溯、危化品合规不是"需求"，是"生存条件"——客户审计不过关 = 丢客户
2. **配方版本管理是化工企业的"核心命门"**：这不仅是一个IT需求，更是知识产权保护问题——BA必须理解其敏感性
3. **MoSCoW在化工行业的分量不同**：客户审计相关的"Should"往往会被客户审计压力升级为"Must"，优先级是动态的
4. **影子跟随在化工行业特别重要**：实验室和车间的实际工作流，往往和文件上写的SOP差别很大
5. **从"2天到2小时"的叙事力量**：不是"实施了QM模块"，而是"批次追溯从2天缩到2小时"——用业务语言讲技术价值
