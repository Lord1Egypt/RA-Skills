## Description:

Creates a standardized AI model project structure covering data, tokenization, model training, experiment tracking, health checks, lineage tracing, run comparison, checkpoint management, and documentation linting.

This skill is ready for commercial/non-commercial use.

## Use Case:

Developers and AI engineers use this skill to scaffold and maintain model-development projects with consistent folders, concise documentation rules, provenance records, quality logs, experiment comparison, and checkpoint utilities.

### Deployment Geography for Use:

Global

## Known Risks and Mitigations:

Risk: Unsafe project names or output paths can cause scripts to create, copy, rewrite, archive, or delete files outside the intended project.

Mitigation: Use trusted project names, avoid path separators and .. components, and review the resolved target paths printed by the scripts before allowing changes.

Risk: Checkpoint cleanup can delete checkpoint files.

Mitigation: Run checkpoint cleanup with --dry-run first, keep backups, and confirm the keep count and project path before running a non-dry cleanup.

Risk: Documentation lint fixes can rewrite markdown files by adding review markers.

Mitigation: Review lint output before using --fix and keep version-control or backup copies for files that may be changed.
