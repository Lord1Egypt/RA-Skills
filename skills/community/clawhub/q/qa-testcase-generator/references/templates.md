# 测试用例模板

## 用例结构模板

```yaml
用例编号: TC-NNN
业务域: 业务域名称
优先级: P0|P1|P2|P3
测试维度: 功能|可靠性|效率|安全性|易用性|可维护性|兼容性
用例类型: 冒烟测试|回归测试|探索性测试|验收测试
设计方法: 边界分析+等价类|状态迁移|判定表|场景法|Pairwise
测试场景: 测试场景描述
测试点: 具体验证点
操作步骤:
  - 步骤: 1
    操作: 操作描述
    预期: 预期结果
测试数据: 测试数据说明
前置条件: 执行前环境或数据准备
需求来源: 需求来源引用
标签: [设计方法, 流程类型, 优先级]
```

> **说明**：`预期` 字段嵌在 `操作步骤` 数组内部（非顶层字段）。Excel 输出时会提取 `操作步骤[].预期` 单独渲染为「预期结果」列。`序号` 和 `测试结果` 是 Excel 专属列，不在 JSON 中定义。

## 优先级定义

| 优先级 | 含义 | 分配规则 | 建议占比 |
|--------|------|----------|----------|
| P0 | 冒烟级 | 核心层主流程+阻塞性异常 | 10-15% |
| P1 | 核心级 | 核心层分支+重要层主流程+关键边界 | 30-40% |
| P2 | 一般级 | 核心层非关键+重要层异常+辅助层 | 30-40% |
| P3 | 低优先级 | 极端边界+低频场景+探索性 | 10-20% |

## 设计方法适用场景

### 边界分析

适用：输入有明确范围、长度、数量限制

用例结构：
- 有效边界值（最小值、最大值）
- 无效边界值（最小值-1、最大值+1）
- 特殊值（0、空、null）

示例：
```
需求：密码长度8-20位
用例：
- TC-001: 输入8位密码（有效边界）
- TC-002: 输入20位密码（有效边界）
- TC-003: 输入7位密码（无效边界）
- TC-004: 输入21位密码（无效边界）
```

### 状态迁移法

适用：实体有明确的状态流转

用例结构：
- 所有合法状态转换
- 非法状态转换（逆向、跳跃）
- 状态回退和循环

示例：
```
订单状态：待支付→已支付→已发货→已完成
用例：
- TC-001: 待支付→已支付（合法转换）
- TC-002: 已支付→已发货（合法转换）
- TC-003: 已发货→待支付（非法逆向）
- TC-004: 已支付→已完成（非法跳跃）
```

### 判定表法

适用：多个条件组合决定结果

用例结构：
- 条件桩（所有条件）
- 动作桩（所有可能结果）
- 规则列（条件组合→动作映射）

示例：
```
条件：会员等级、购买金额
动作：折扣比例
规则：
- 普通会员+<100元 → 无折扣
- 普通会员+≥100元 → 95折
- VIP会员+<100元 → 95折
- VIP会员+≥100元 → 9折
```

### 场景法

适用：有明确的业务流程

用例结构：
- 主流程（正向路径）
- 分支流程（备选路径）
- 异常流程（错误处理）

示例：
```
下单流程：
- TC-001: 主流程 - 选商品→加购物车→下单→支付→完成
- TC-002: 分支 - 库存不足时提示
- TC-003: 异常 - 支付失败时回滚库存
```

### Pairwise法

适用：多个可选参数组合

用例结构：
- 参数对组合（不是全组合）
- 确保每对参数值至少组合一次

示例：
```
参数：浏览器(Chrome/Firefox)、操作系统(Windows/Mac)、用户角色(管理员/普通)
Pairwise组合：
- Chrome+Windows+管理员
- Chrome+Mac+普通
- Firefox+Windows+普通
- Firefox+Mac+管理员
```
