# Scroll Animation Workflow

## Headline

Turn Two Still Frames Into Scroll Animation Code for a Website, in Plain Words

## Hook

Give your AI agent one website section. It drafts the workflow, in plain words. You make a start frame and an end frame in Whisk. You upload both to Flow and generate an 8 second animation video. You extract the frames with EZGIF at 30 frames per second, about 240 images. Then your AI agent drafts the prompt that turns those images into interactive scroll animation code for your site. The agent drafts, you run the tools, the agent only checks the text you paste back.

## Pain, in plain words

A plain website section does nothing when a visitor scrolls past it. A scroll animation makes the section move as the visitor scrolls, and the site feels alive. Most small business owners do not know how to start. They have no frames, no video, no extracted images, and no prompt to give an AI coding tool. The fix is a short workflow first, frames, then video, then extracted images, then a prompt, with a check at each step, so nothing is called done until the evidence is pasted in the message.

## How to use it

Hard rule, read this first: the agent does not make frames, does not generate a video, does not extract frames, and does not write the scroll animation code itself. The agent drafts the workflow and the prompt, and only checks evidence the user pastes in the message. A short description alone is not evidence. A frame list, a prompt, or a code snippet is Checked only when the user pasted that text in the message, and the output quotes that pasted text as the evidence.

Fast path: If the user already gives the business, the goal of the section, and the audience in the first message, do NOT ask a long list of questions first. Draft the full workflow and the handoff check in the SAME reply, then the fix draft. Never stop at questions alone.

Step 1: create the start frame and the end frame in Whisk. The agent drafts what each frame must show, in plain words, one line per frame. The user makes both frames in Whisk. The start frame shows the section at the top of the scroll. The end frame shows the section at the end of the scroll. Keep both frames in the same style, same colors, same text, so the animation looks like one section moving, not two different sections.
Step 2: upload both frames to Flow and generate an 8 second animation video. The agent tells the user how to do this step. The user uploads the start frame and the end frame to Flow, and generates an 8 second animation video. The video runs from the start frame to the end frame, in 8 seconds. The user pastes back what Flow reported, how long the video is, and what it shows.
Step 3: extract the frames with EZGIF at 30 frames per second, about 240 images. The agent tells the user how to do this step. The user gives the 8 second video to EZGIF, and extracts the frames at 30 frames per second. An 8 second video at 30 frames per second gives about 240 images. The user pastes back how many images were extracted, and the first and last image names, in plain words.
Step 4: feed the images to an AI coding tool with a prompt to generate interactive scroll animation code. The agent drafts the prompt, in plain words. The prompt says what the section is for, what the start frame shows, what the end frame shows, and that the animation must follow the scroll, in plain words. The user gives the images and the prompt to an AI coding tool, and pastes back the code it returned, or a short snippet of that code, plus what the tool reported.
Step 5: run the handoff check, frames, video, extracted images, and code, all checked with evidence pasted in the message. List each item as Checked, Missing, or Not confirmed, with the pasted text quoted as the evidence.
Step 6: write the fix draft, labelled DRAFT, NOT SENT, with owner approval needed.

Ask only what is missing, in plain words, one short list at a time:
1. What is the business, in plain words?
2. What is the goal of this section, teach, show work, or get calls?
3. Who is the section for, in plain words?
4. What must the start frame show, in plain words?
5. What must the end frame show, in plain words?
6. What is the one point of this animation, in one line?
7. Paste the frame list and the prompt you want checked, or ask the agent to draft them first?

If the user does not know an answer, mark it Not confirmed, and use the most common answer for that business type, and say so, marked Suggested, not confirmed. Do not invent an answer.

## Frame prep checklist

Use this checklist before Step 2, so the video matches the site.
- Start frame shows the section at the top of the scroll, in plain words.
- End frame shows the section at the end of the scroll, in plain words.
- Both frames use the same colors, the same text style, and the same business name.
- Both frames show one point only, not three points.
- Both frames are readable on a phone, short words, no tiny text.
- The frame list is pasted in the message, so it can be checked.

## The handoff prompt structure

Use this structure when the agent drafts the prompt for Step 4, in plain words.
- Section: what the section is, and where it sits on the page.
- Start frame: what the start frame shows, pasted in the message.
- End frame: what the end frame shows, pasted in the message.
- Motion: the animation must follow the scroll, smooth, one section, in plain words.
- Images: about 240 images, extracted at 30 frames per second, from an 8 second video.
- Result: interactive scroll animation code for this section only, no other page changed.
- Check: the code must match the start frame at the top of the scroll, and the end frame at the end of the scroll.

## The handoff check

Run this check on every item, and show each one to the user with evidence:
- Item: [start frame, end frame, 8 second video, extracted images, scroll code prompt, or scroll code, in plain words]
- Result: [Checked, Missing, or Not confirmed]
- Evidence: [the text the user pasted in the message, quoted, or Not confirmed]
- Fix draft: [one line, in plain words, or None]

Use Checked only with pasted text quoted as the evidence. If no text was pasted for an item, mark it Missing, and say what is needed. Never mark Checked without pasted text. Never claim a video is generated, or code is done, if you only saw a frame list or a prompt.

## What good looks like

A good frame list has one start frame and one end frame, in the same style, with one point. A good video is 8 seconds, from the start frame to the end frame. A good extraction is about 240 images at 30 frames per second. A good prompt says the section, the start frame, the end frame, and that the animation must follow the scroll. A good handoff has every item marked Checked, Missing, or Not confirmed, with pasted text quoted as the evidence for every Checked item. A good fix draft lists the missing items first, in order, with one plain line each.

## Common mistakes

These mistakes show up often, and they are easy to avoid if you check for them at handoff.

- Making two frames in different styles. The start and end frames must match, same colors, same text, same business name.
- Making a video that is not 8 seconds. The workflow uses an 8 second video, so the extraction gives about 240 images at 30 frames per second.
- Extracting at the wrong rate. The workflow uses 30 frames per second, so say the rate plainly when you paste the result back.
- Feeding the images to a coding tool with no prompt. Draft the prompt first, with the section, the start frame, and the end frame.
- Calling the code done when only the prompt exists. A prompt is not code. Checked needs pasted text, and code needs a pasted snippet.
- Claiming views, followers, or sales from an animation. An animation is a draft, not a result. Never invent a view count or a testimonial.
