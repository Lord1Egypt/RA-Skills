# 商业点子体检官（壳包 · ClawHub版）

**一句话**：填 1-10 个点子，拿一份带八步评分卡、三情景经济账和 Go/Pivot/Kill 判定的体检报告——点子靠不靠谱，看这份能对照、能复跑、依据可溯源的判定工具，不是成功学。免费写出来的是通用分析，¥4.90 买的是按你自己的竞品与算账输入算出来的判定。

## 一、使用条件

1. 你有具体点子（单个或 1-10 个批量），能给出一句话描述（≥10 字，含目标人群与变现方式）和你的算账四数值（客单价/转化率/月触达/月固定成本，0 可以）。
2. 本机 node ≥ 18；提交脚本仅用 node 内置 http/fs/path，零第三方包。
3. 端点已开放；若偶发不可达＝服务器维护窗口，照实等待重试即可，非技能故障（端点开放口径见 §五.3）。
4. 你接受「即用即删」：服务端原始点子文本不落盘（只存参数哈希），无历史找回，改问卷需重新提交。

## 二、步骤

### 第 0 步 · 前置条件与支付路径
本技能的产品（体检报告）在 linkkhub 服务器端生成，按次收费走 HTTP 402 协议（支付宝 AI 按量付费）。两条付款路径，任选其一：
**A 路径 · 人类扫码（最简单）**：无需在本机安装任何支付宝技能。发起下单后系统返回账单，账单自带支付链接/二维码，您本人用支付宝 App 扫码付款即可，付讫后智能体继续取回报告。
**B 路径 · 智能体自动付**：需要您的智能体本机具备官方支付宝支付技能（alipay-payment-skill 类，通过官方渠道获取）并已完成支付宝侧授权。检测法：智能体自查该技能在位与授权状态（官方技能自带状态检查，apply-wallet/bind-wallet 阶段不可互换）；缺技能则引导经官方渠道获取，缺授权则引导完成官方授权流程（提交开通口令/授权码，以支付宝侧结果确认为准）。未配置 B 路径不影响 A 路径。
提交脚本只访问唯一端点 https://linkkhub.top/idea/generate；自动预备（第 0.5 步）阶段的联网搜索是用户侧智能体在用户授权下的本机行为，非本技能脚本发起；页面、账单与该端点之外无任何外呼。

### 第 0.5 步 · 自动预备（选填，用户侧智能体具备联网搜索时可用）

用户侧智能体先联网搜索该点子的行业、竞品与价格带，产出草案三件：

1. **competitors 草案清单**：每条 name/price/billing_model/source/checked_at（source＝检索来源、checked_at＝检索日期）；
2. **scores 五维草案**（pain/moat/willingness/delivery/acquisition，各 0-10）；
3. **econ.price 参考值**（对标竞品价格带）。

三件草案一律标注「智能体估算·附来源」，以草案表呈现，经用户确认或修改后方可写入 `my_questionnaire.json`。**用户私有事实边界**：econ 的 pay_rate/reach/fixed_monthly（转化率/月触达/月固定成本）系用户私有事实——智能体只可建议值，须经草案表呈现用户确认或修改后方可进入第 2 步下单，禁猜值直提。**兼容与边界**：用户侧无搜索能力则跳过本节照第 1 步（全兼容）；本节纯可选、纯文档，不改计费与支付边界，本技能包脚本仍只访问第 0 步所述唯一端点。

### 第 1 步 · 填问卷
复制 `scripts/questionnaire.json` 为 `my_questionnaire.json`，按 `_fields` 说明填 ideas 数组（1-10 条；每条 idea 文本＋econ 四数值必填；scores/competitors 选填）。壳包不猜值：缺项或非法值在提交时原样退回（`QUESTIONNAIRE_*` 错误码、不发单），请补齐后重试。证据类备注（pain_evidence 需求真伪/channel_note 渠道/compliance_note 合规/market_size_note 市场规模）留在本地，据此填 scores 与 econ，不进请求体。

### 第 2 步 · 提交生成（端点已开放）
```bash
node scripts/submit_report.js --in my_questionnaire.json
```
- 返回 **402**：账单在 `Payment-Needed` 响应头（base64url JSON），响应 body 含订单要素（out_trade_no/amount/goods_name；同参重复建单命中已有订单不重出，order_reused 标注）。按账单完成支付宝 402 支付后，携 `--proof <Payment-Proof>` 重试即出报告（A 路径扫码/B 路径智能体自动付）。
- 返回 **200**：报告 markdown 全文落 `./点子体检报告.md`，stdout 附判定摘要（verdict/total_score/sku/条数）；已履约单携原凭证重试→复用既有结果直接返回（already_fulfilled=true，不重复交付、不二次计费）。
- 端点已开放（2026-11-14 起）；真实网络故障按 NETWORK_ERROR（退出码 1）退回、不发单不扣费——偶发不可达＝服务器维护窗口，照实等待重试即可，不是故障。

### 第 3 步 · 报告本地编辑（不二次计费）
生产契约只消费 idea/scores/econ/competitors 四类字段，不消费增删参数。脚本保留 `--remove 12,31` / `--add "自定义措辞"` 参数，但**不随请求提交服务端**，仅打印 `OPTIONS_LOCAL_ONLY` 提示（不影响提交与计费）；自定义措辞以生成后报告 `点子体检报告.md` 的本地编辑为准（手动增删自标注〔USER〕）。改问卷本身：改 `my_questionnaire.json` 后重新提交（无历史找回；同一已付凭证对同一参数重试属防重复交付，非新计费）。

## 四、失败处理

| 现象 | 含义 | 处置 |
|---|---|---|
| 退出码 2 + `ENDPOINT_NOT_OPEN`（保留码） | 保留码：脚本内该判定为占位分支、正常提交不会触发（端点已于 2026-11-14 开放，见 §五.3） | 该码不会在正常流程出现；若出现即端点常量被改动，停止提交并联系发布方 |
| 402 + `Payment-Needed` 头 | 计费闸门未放行 | 按账单走支付宝 402 支付，携 `Payment-Proof` 重试即出报告；同参重复下单命中已有订单不重出 |
| 401 验付失败 | Payment-Proof 校验失败（验付失败语义：明确失败、不发单、不建新订单行、不发账单） | 重新支付获取新凭证后重试 |
| 400 `BATCH_TOO_LARGE` | 点子条数 >10（上限拒单，message「一次最多 10 个点子，更多请分批购买」） | 分批购买（壳侧先闸 `QUESTIONNAIRE_BATCH_LIMIT` 退回、不发单） |
| 422 `INVALID_INPUT` | 点子太短（<10 字）/缺必填/参数契约不符（不发账单） | 按 message 补齐重提，服务端不代填 |
| 502 `FULFILLMENT_CONFIRM_FAILED` / 500 `FULFILLMENT_PERSIST_FAILED` | 履约确认失败 / 落库失败 | 勿重复支付：稍后携同一 `Payment-Proof` 重试（服务端响应防重，重提交不重生成资源） |
| 网络超时（客户端侧 20s） | 服务器维护窗口或网络故障（端点已开放，见 §五.3） | 勿立即重复支付，先核账单状态；维护窗口照实等待重试 |
