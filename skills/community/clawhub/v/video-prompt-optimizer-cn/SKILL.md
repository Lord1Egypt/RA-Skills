# AI 视频提示词优化

把用户给出的原始提示词、画面意图和已有素材，产出一份短而完整的 Markdown 交付物：可复制最终提示词、镜头动作顺序、连续性约束，以及与原稿的对比说明。

## 输入检查

先确认以下信息；缺少关键项时不要猜测，指出缺什么并给出最短补充模板。

- 画面主体和要传达的结果（必需）
- 时长或镜头数（可选；未知时默认一个 5–8 秒镜头，并标明该假设）
- 平台比例、受众或用途（可选）
- 原始提示词、参考图/视频描述、禁忌元素（可选）
- 实际视频生成模型及其官方已知参数（可选）

## 工作流

1. 提取主体、场景、行为、镜头、光线、风格和限制。把含混或互相冲突的描述列为“待确认”。
2. 若用户选择用 Opus 5.5 或其他语言模型写提示词，照选项使用或保留该选项；它只是提示词写作模型，绝不自动换版本，也不把它说成视频生成模型。
3. 依据时间顺序写镜头动作。每步只描述一个可见变化，包含起始状态、动作、镜头运动和结束状态。
4. 写最终提示词：先稳定身份与环境，再写动作和摄影语言，最后写负面/边界约束。人物身份、产品属性和限制只保留用户提供或可直接观察的信息。可补充摄影构图、持杯手和光线方向等创作方案，但必须在“对比与待确认”标明为建议，不能写成用户已经提供或模型已经生成的事实。
5. 写连续性约束，锁定角色外观、服装、道具位置、场景、光线方向、运动方向和镜头衔接；仅列本任务相关项。
6. 对比原稿，说明删掉的歧义、补齐的画面信息和仍待确认的内容。

## 输出格式

使用以下 Markdown 标题，避免冗长解释：

```md
## 最终提示词
...

## 镜头动作顺序
1. ...

## 连续性约束
- ...

## 对比与待确认
- 原稿问题：...
- 本次优化：...
- 待确认：...
```

## 边界

- 不调用视频生成 API，也不声称已经生成视频。
- 不编造任何模型参数、镜头能力、时长上限、seed 或专有语法；若实际模型未指定，输出与模型无关的自然语言提示词。
- 不引入用户未确认的专用编译器、参数体系或输出格式。
- 同一人物跨镜头时，以连续性约束优先于新增装饰性描述。

## 自检

运行 `node scripts/self-test.mjs`。成功样例位于 `fixtures/success-input.md`，其参考交付位于 `fixtures/success-expected.md`；失败样例 `fixtures/failure-missing-brief.md` 因缺少主体与画面意图而必须被识别为资料不足，不能因缺少时长或镜头数而判错。
