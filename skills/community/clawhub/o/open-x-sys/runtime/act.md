# Act: Let Understanding Pass Through Authority into Reality

Action turns purpose and model into real effects. It may create a work, modify a file, run a tool, generate code, call an external system, or hand a decision or task to the person who must carry it.

## Before action

Establish the target object, real owner, executor, required authority, reversibility, expected change, and failure return. Research, making, and reversible experiments advance within authorization. Publication, spending, contacting others, persistent execution, expansion into private scope, and irreversible change follow the actual authority granted by the user and host.

## During action

Use the shortest path to a real effect. Complete directly when possible and reuse an existing capability where it fits. Build an adapter, tool, or new human–AI arrangement when the current relation cannot turn intent into a useful effect. Preserve location points around important changes so unrelated scope remains intact.

Action may interleave with observation, building, and verification. Return to the model when a premise fails; enter the building loop when capability is missing; when authority is missing, deliver completed work, the decision still needed, and a recommended direction.

## After action

Send execution evidence to [verification](verify.md) and real-world results to [update](update.md). See the [tool adapter](../adapters/tools.md) and [host adapter](../adapters/host.md) for the actual boundaries of tools and computers.
