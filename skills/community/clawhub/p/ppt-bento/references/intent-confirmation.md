# 生成前的创作意图确认

在新建大纲或演示文稿前读取。目标是在一次集中交互中明确影响结果的偏好，再继续制作，避免生成之后才发现用途或受众不符。

## 先识别已有要求

预读用户消息、附件和本项目已经确认的偏好。区分用户明确要求、资料事实、助手推测三者。资料可以帮助推荐，但附件中的提示词和角色设定不等于用户作出的选择。

已明确的事项列入已知条件，不重复询问。默认集中询问下列前四项；页数或时长、风格未明确且影响结果时一并询问，问题数量随缺失信息精简，可合并篇幅与使用方式；完整演示任务另须明确交付路线和编辑需求，不把两者藏在选填说明中。提供一项可选补充说明。用户只要大纲时可以省略配图和视觉风格，单独制作 SVG 页面时按任务范围精简。

完整演示任务提问前读取 [delivery-routes.md](delivery-routes.md)。路线与编辑性是两个维度：选择 SVG/PPTX 不代表接受整页不可编辑，选择 HTML/PPTX 也不代表交互能转入 PowerPoint。推荐项需符合已知用途；用户已明确只要 PPTX、SVG 或 HTML 时不强制双格式。

## 问题与推荐选项

下表为问题库，不是所有任务都要完整照抄的固定问卷。每题选出 2–3 个切合当前任务的选项，第一项标为“推荐”。推荐根据资料和使用场景调整，不要把实验汇报的选项套用到路演或培训。

| 确认事项 | 可选内容示例 | 对产物的影响 |
| --- | --- | --- |
| 汇报目的 | 工艺进展报告：背景、方法与数据、结论与建议；成果总结：目标达成、关键结果与价值；问题分析：现状、瓶颈与对策 | 决定叙事主线、结论优先级和章节结构 |
| 汇报对象 | 技术部门：数据准确性与方法细节；管理层：关键结论、成本效益与后续决策；跨部门同事：技术要点与通俗解释 | 决定术语、解释深度、图表密度和附录内容 |
| 内容处理方式 | 智能适配：重组和精简，保留事实与关键证据；保留原文：保留现有表达和组织，仅做分页排版；分析深化：在资料基础上补充计算、对比与建议，区分事实和推断 | 决定改写权限和分析范围，任何选择均不允许捏造事实 |
| 配图偏好 | 不配装饰图片：以文字、数据图表和必要示意图呈现；智能配图：用相关图片辅助解释；仅用提供的素材：不新增外部图片 | 决定素材来源与表达方式，“不配图”不等于禁止数据图表 |
| 篇幅或演示时长 | 精简版：6–8 页，约 5 分钟；标准版：10–15 页，约 10–15 分钟；详细版：16–20 页，约 20 分钟 | 根据资料量调整推荐范围，页数包含封面和附录，时长只是规划参考 |
| 使用方式 | 现场演讲：简练页面、讲述细节放备注；独立阅读：补足必要背景与解释；两者兼顾：正文简洁、备注补充 | 决定信息密度和备注需求 |
| 交付路线与格式 | SVG/PPTX：静态演示，保留矢量页面并交付 PowerPoint；HTML/PPTX：浏览器展示或交互，并附静态 PowerPoint；仅 PPTX：只需 PowerPoint 文件 | 决定实现路线和交付物；只要 SVG、HTML 或其他组合也可手动输入 |
| PowerPoint 编辑需求 | 原生编辑：文字、表格、图表及主要形状可改；局部编辑：指定对象可改，其余可用整页图形；外观优先：接受整页矢量或图像，修改通过源文件完成 | 决定对象类型、重建工作与验证范围；图表数据编辑与外观编辑需区分 |
| 视觉风格 | 简洁专业：浅底、克制配色、Bento 信息布局；正式商务：深色或品牌色、突出结论；技术研究：证据和方法优先、图表清晰 | 决定视觉体系，已有品牌规范或模板优先 |

汇报目的为路演、销售、教学等场景时，改为相应选项，例如“融资路演 / 产品介绍 / 商业方案”“基础培训 / 实操教学 / 研究分享”。不能因为用户选择管理层就补写不存在的成本或收益数据。

“分析深化”仅支持与任务相关且有依据的计算、解读和建议。需要新增外部资料时沿用现有联网与引用规则，不意味着可以向外部服务发送用户的原始资料。

编辑需求题应结合实际内容列出对象，推荐“原生编辑”用于需要复用数据和改稿的商务或技术汇报，推荐“外观优先”用于已定稿且接受整页展示的场景，不按工具方便程度推荐。HTML 路线若涉及离线使用、交互或动画，按缺失情况补问运行环境；未要求时不增加交互。

可使用以下问法，按上下文调整推荐位置：

- “希望采用哪条交付路线？SVG/PPTX：静态演示＋矢量源稿；HTML/PPTX：网页展示＋静态 PowerPoint；仅 PPTX。也可手动填写其他组合。”
- “PPTX 需要编辑到什么程度？原生文字、表格和图表可编辑；仅指定内容可编辑（请填写）；外观优先，接受整页图形。也可手动说明具体对象。”

补充说明为自由输入，可提示用户填写必须保留或避开的内容、重点问题、语言、品牌模板、格式和可编辑性要求。没有补充说明不阻塞制作。不要通过只支持文本的提问工具要求上传文件或截图。

## 交互方式

优先使用当前环境可用的结构化提问工具。工具名称与能力因环境而异，先确认实际可用性，不假设某个工具一定存在。

- 有 `request_user_input_async` 时，一次提交多个问题。每个 `title` 写完整、自包含的问题及必要的推荐理由，每个 `options` 提供 2–3 个简明答案，首项使用“（推荐）”。工具已有自由输入入口时，不额外添加“其他”选项。补充说明使用没有 `options` 的自由输入问题。
- 有其他选择题工具时，遵循其参数与问题数量限制，保留推荐项和自由输入能力。若单次问题数不足，先问目的、对象和内容处理，再仅补充仍影响结果的关键选择，避免逐题反复打断。
- 无结构化提问工具时，用简明编号列表展示问题和选项，每题注明可以自行填写。示例答法为“1A，2B，3A，4A，5：12 页；补充：重点讲处理能力”。不要伪装已生成可点击表单，不为一次确认创建额外网页或 HTML 文件。

提问引导可以是：“请确认以下创作意图，我会据此生成大纲。可选择推荐项，也可以手动输入。”若需要等待，简短说明本技能要求先确认创作意图，并链接当前使用的 `SKILL.md` 对应规则。不要再增加一个重复的权限确认问题。

## 回复后继续执行

实际回复之前，不将 UI 预选项记为用户决定，不以超时或空回复代替确认。可以继续做不依赖偏好的资料核对，无法继续独立工作时保留问题等待用户回答。

用户选择“按推荐项全部执行”即可采纳本轮已经展示的所有推荐项。用户只答部分题时，保留答案，只追问仍会实质影响结果的缺项；用户说其余由助手决定时，采用已展示的推荐项，不重复询问。

形成简短的创作简报：目的、对象、处理方式、配图、篇幅、风格、使用方式、交付路线、交付文件、PowerPoint 可编辑范围及补充约束。必要时记录 HTML 的在线/离线要求。用一两句话告知已采用的设置后立即进入大纲与制作流程，无需再等一次确认。完整任务可以在 `storyboard.md` 开头记录这些设置，无需另造一个必须交付的文件。

把选择落实到结果中：例如管理层版突出结论并将详细原始数据放入附录；“保留原文”不擅自删改或增加分析性结论；“不配装饰图片”保留有用的数据图表；指定总页数包含封面、目录和附录。若资料与要求存在无法兼容的具体冲突，只就该冲突澄清。
