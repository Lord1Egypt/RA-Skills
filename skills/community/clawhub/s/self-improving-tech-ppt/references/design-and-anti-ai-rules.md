# 技术规划 PPT 设计规范、反 AI 味与防踩坑手册

本手册沉淀自真实多轮高层技术规划 PPT 实战迭代，供智能体在每轮设计与自检中严格执行。

---

## 一、内容与逻辑铁律

1. **必须回答四件事，绝不画业务流程图**
   - 顶栏：**为什么做（问题）→ 达成什么（目标）**；
   - 左侧：**核心技术挑战**（只讲内在技术难点，**绝不出现方案名词**）；若引入核心新概念/缩写（如 `DSL`），左下单独放一张概念卡讲清「缩写全称 + 定位与为何用 + 产出与最终运行形态」；
   - 右侧：**技术解决方案**（严格与左侧挑战 **1 对 1 水平齐平对应**，每条泳道必须露出真实底层技术、数据结构、算法或标准机制，如 `JSON Schema 受限解码`、`ExprAST`、`DAG`、`Kahn 拓扑判环`、`UCUM`，绝不写空洞文字复述目标）。
2. **禁止编造玩具业务例子**
   - 严禁在技术挑战卡里编造具体业务小故事或玩具案例（如某特定消费场景、固定响应时长等）；
   - 左侧挑战卡需要视觉示意图时，使用**纯抽象技术对比示意图**（如「第1次 `[条件][单位][步骤]` ≠ 第2次 `[文本混写][接口未剥离]`」「`格式合规 ✓` ≠ `逻辑正确 ?`」），既专业又有设计感。
3. **禁止跨页硬编码章节号与内部系统黑话**
   - 正文绝不出现「供 3.2 匹配、见第 5 页」这类脆弱章节号，统一写清功能职责（如「供匹配复用计算 · 交运行层编译执行」）；
   - 对外或高层汇报页不出现内部小系统代号（统一写通用标准名称，内部映射仅放配套文字说明稿）。
4. **专业术语逻辑严谨性核查**
   - 易听混缩写主动汉化：如 `URI` 易听成网页 `URL`，页面统一写「标准标识 / 引用」；
   - 概念关系严守边界：如 `is-a` 仅用于「概念同源的父类→子类特化」，绝不能把「同词异义 / 口径互斥」强行挂成 `is-a` 继承（互斥必须分域独立建类隔离）；
   - 外部标准明确边界：如 `UCUM` 适用于物理与工程计量单位，货币（ISO 4217）与离散业务计数需配合扩展枚举兜底，汇报口径要实事求是。

## 二、反 AI 味与文本自检黑名单

### 1. 表达红线
- **零圆括号原则**：PPT 正文框内不使用 `（...）` 或 `(...)`，避免视觉碎裂，改用顿号、中点 `·` 或破折号自然表达。
- **杜绝「AI 味空泛套话」**：禁「赋能、抓手、底座、拉通、闭环、范式、破题载体、鸿沟、断层、锚点、消费」等虚词。
- **杜绝「伪口语 / 网络词」**：禁「撑不住、把不住、写死、脑补、用不起来、兜不住、自由发挥」。
- **杜绝「生僻压缩造词」**：禁「直读/只读（病句）、编检、守恒、反译、核极性、可算可跑、强覆盖伤存量、结构漂移、多维索引（越界）、归一依据（生造）」。
- **杜绝前缀套话**：挑战卡内不加「难点：……」「核心：……」「例：……」。

### 2. 默认程序拦截黑名单（`DEFAULT_BANNED_WORDS`）
已在 `scripts/ppt_engine.py` 内置，各任务可根据用户新增纠偏继续追加。

## 三、可切换主题与克制配色原则（绝不写死风格）

> 实战教训：严禁 AI 味橙黄+浅绿大面积底色，也严禁过亮、过艳的霓虹粗边框和泥泞投影。高级感来自**低饱和度主次色阶 + 纯白卡片对比**。同时风格必须支持按汇报对象与企业 VI 灵活切换，不能写死。

### 内置主题（通过 `Scene(name, theme_name=...)` 一键切换）

| 主题名 | 风格定位 | 主色 / 深锚点色 / 底床色 | 适用场景 |
| --- | --- | --- | --- |
| `executive-blue`（**默认强制**） | 沉稳企业蓝 | `#005EA8` / `#08306B` / `#F5F9FE` | 默认必选：技术规划、企业级架构评审、高层汇报 |
| `slate-minimal` | 极简石墨灰 | `#334155` / `#0F172A` / `#F8FAFC`（配 `#2563EB` 点缀） | 仅用户显式要求极简咨询风时切换 |
| `steel-teal` | 冷钢青蓝 | `#20647A` / `#133B4A` / `#F5FAFB` | 仅用户显式要求青蓝色系时切换（已去绿调防 AI 味） |
| `academic-indigo` | 学术靛蓝 | `#3451B2` / `#19285E` / `#F6F8FE` | 仅用户显式要求学术/大会 Keynote 时切换 |
| 自定义品牌色 | `build_theme(base, overrides)` | 按用户指定主色自动替换 | 严格对齐任意企业 VI 或指定参考图 |

### 通用色彩克制铁律（所有主题共用，代码硬校验）
- **严禁模型擅自换色或拼凑色板**：所有填充与描边必须取自 `scene.theme`；用户未显式换色时锁死 `executive-blue`；
- **边框宁细勿粗**：外框与泳道用 `0.75–0.95pt` 安静边框（`border`），绝不用 `1.4pt+` 粗亮描边抢文字视觉；
- **纯白卡片坐落在极浅底床上**：泳道用极浅色底床（`panel_bg`），流程图核心节点用纯白底（`white`），用深锚点色（`navy_deep`）稳住页面底部重心；
- **语义警示色极度克制（程序强限面积）**：柔和琥珀色（`amber_bg / amber_bdr / amber`）**仅用于**异常虚线分支（未通过/未收录）和极少量对比高亮，单块宽 `≤ 240pt`、全页总面积 `≤ 4.5%`，**严禁画底部整行橙黄横幅**。

## 五、跨模型防退化红线（针对 ChatGPT / 通用对话模型常见退化）

1. **禁止「Gamma 博客风」空壳版式**：严禁顶部「小横线眉标 + 超大 28pt 标题 + 一句话导语 + 一条深色原话栏 + 左右稀疏两栏 + 底部整行橙黄框」。顶部标题栏总高度控制在 `50pt` 以内，把 90% 画布面积留给真正的技术挑战与机理架构图。
2. **禁止「一页只讲一句例句」的稀释拆分**：不要把一套技术架构拆成 10 页低密度散文；核心架构必须优先凝练成高密度全景架构页（单页 `≥ 35` 节点、`≥ 6` 正交连接线、四象限填满且呼吸均匀）。
3. **先套完整蓝图再填内容**：构建新页时直接复用 `ppt_engine.py` 的 `add_arch_header`、`add_problem_goal_band`、`add_swimlane_shell`、`add_chip_module`、`add_header_strip_module` 与 `examples/demo_tech_slide.py` 四区坐标网格，绝不从零随手画两张大白表交差。

## 四、组件精细度与排版防踩坑铁律

1. **彻底消灭「大方块、大圆柱」**
   - **拒绝空洞大方块**：流程节点高度控制在 `24–29pt`；若某节点需要承载 3～4 个技术要点（需要 `32–44pt` 高度），**绝不留大片空白**，必须拆成「标题 + 内部微标签胶囊（`12–13pt` 高度）」或「蓝顶条 + 两条淡蓝核验条」的结构化微模块；
   - **拒绝巨型大蓝圆柱**：数据库圆柱（`MSO_SHAPE.CAN`）一律用**轻巧白底蓝边小圆柱**（宽 `60–64pt`、高 `33–48pt`，`adjustments[0] = 0.20`），绝不拉成 `90pt` 高的蓝色大油桶！若右侧需要承载多层信息，拆成「上方紧凑白卡（口径与版本）+ 下方小巧白底圆柱（对象库）」。
2. **左侧挑战卡采用「左抽象示意图 + 右图标徽章与要点」双栏结构**
   - 彻底消除单栏纯文字列表的大片空洞留白；
   - 徽章带精致白线矢量图标（96×96 透明 PNG），要点文字用 2 行均衡排布，字号清晰不缩成蚂蚁字。
3. **100% 90° 正交折线与像素级对齐**
   - 严禁任何斜线箭头；优先让主链路直线平齐（消除 `2–3pt` 无意义小折弯）；
   - 三条泳道内的流程图区域保持**左边界与右边界像素级齐平**，内部圆柱底边与相邻模块底边齐平。
4. **PowerPoint 原生渲染专属避坑**
   - **不要用重叠矩形遮盖圆角**：会产生接缝伪影，直接用干净的单一圆角矩形或细分割线；
   - **旋转三角形渐变（`wedge_r`）**：PowerPoint `ISOSCELES_TRIANGLE` 顺时针旋转 `90°` 后，本地 `270°`（底→尖）配 `rotWithShape="1"` 才能在 PowerPoint、Keynote 和 macOS QuickLook 下全部稳定呈现从左到右渐变；
   - **圆柱（`CAN`）文本边距**：PowerPoint 原生自动避开圆柱顶盖，设置 `margin_top = 1.0pt` 即可防文本下沉裁切；
   - **菱形（`DIAMOND`）防折行**：宽度给足 `56–62pt`、`pad_x = 0`、字号 `5.7–5.8pt`，保证 `口径一致?` 等短问句单行居中不折行；
   - **东亚字体锁定**：每个 run 必须同时写入 `a:latin`、`a:ea`、`a:cs` 为 `PingFang SC`（或目标系统字体），防止跨端回退成宋体/等线导致字宽暴涨溢出。
