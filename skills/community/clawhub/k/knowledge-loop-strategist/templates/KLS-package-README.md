# 产品拆解优化作业包（README）

**一句话**：三方用同一套规则，把"改一个参数会怎样"这件事，一轮一轮验证清楚。

这套东西不教你怎么优化产品。它管的是——**每一轮要验证什么、谁来填、填成什么样算数、错了往哪儿改**。

> **若你是模型**：跳到第九节「接续协议」，按其中顺序读取并执行。不要从头重跑。

---

## 一、包里有什么

**七个文档，八个文件**（作业契约出了两个格式，一个给模型跑，一个给人看）。

| 文档 | 文件 | 是什么 | 谁主要用 | 频率 |
|---|---|---|---|---|
| — 作业包说明（本文件） | `产品拆解优化作业包（README）.md` | 总览、开工顺序、维护规则、接续协议 | 三方 + 模型 | **先读** |
| ⓪ 项目信息 | `项目信息.md` | 项目状态头：身份、当前轮次、进度、累计指标 | 三方 + 模型 | **每轮更新** |
| ① 归属与许可 | `归属与许可.md` | 文本归属、许可范围、产出物归属、退出处理 | 三方签署 | 定一次 |
| ② 作业契约 | `产品拆解优化作业契约.md` | 规则全文，可编辑、可交给模型执行 | 三方 + 模型 | 定一次 |
| ② 作业契约·阅读版 | `产品拆解优化作业契约.html` | 同一份规则，排版版，可打印共读 | 三方 | 定一次 |
| ③ 轮次页 | `轮次页模板.md` | 每轮一套表单 | 三方各填各节 | **每轮复制一份** |
| ④ 配对数据册 | `配对数据册.md` | 历史配对记录 | 甲方主填 | 持续累积 |
| ⑤ 判据台账 | `判据台账.md` | 判据修正记录 | 丙方维护 | 持续累积 |

**契约定“怎么干活”，归属与许可定“东西归谁”。两份都签了，合作才算成立。**

### 什么算一个完整的包

**判据：八个文件同在一个文件夹里，且下面四份都在。**

| 缺了哪份 | 后果 |
|---|---|
| 作业包说明（README） | 不知道怎么用，接续协议也没了 |
| 项目信息 | 状态丢失，人和模型都接不上 |
| 归属与许可 | 权利没声明，等于默许 |
| 作业契约 | 没有规则，只剩一堆表格 |

其余四份（轮次页模板、配对数据册、判据台账，以及契约的 html 版）缺了能勉强开工，但第一轮就会卡住——表单没有、数据没处落、打印版没有。

**文件夹名不是随便起的。** 八个文件名在包与包之间完全相同（都叫 `项目信息.md`、`判据台账.md`），**父目录名是它们唯一的区分标识。**

**默认名就是 `产品拆解优化作业包`**，和 `项目信息.md` 第一节的项目名保持一致。绑定到具体项目后两个一起改，规则见第七节。

不要用「新建文件夹」「资料」「2026」这类名字——包发出去之后，文件夹名就是它唯一的身份证。收件人打开一看就知道是什么，也不用回头问你是哪一版。

**先把这份说明读完，再打开契约。** 契约二十多页，直接进去容易迷路。

### 使用中会新增的文件（开包时还没有）

| 文件 | 何时产生 | 谁产 | 数量 |
|---|---|---|---|
| `R{n}-{类型}.md` | 每轮开始，**必有** | 三方合填 | 一轮一份，旧页永不覆盖 |
| `实验设计-{轮次}.md` | A 级配对 <6 组时，**按需** | 乙方 + 丙方 | 可能一份都没有 |
| `归档/`（目录） | 项目收尾时收旧页，**可选** | — | 一个 |

举例：一个跑三轮的项目，目录里最终会有 `R1-探边轮.md`、`R2-收口轮.md`、`R3-外推轮.md`，外加包内那七个固定文件。

**清单之外若确需新增，先在本节登记再创建。** 不登记的散落文件会破坏“单一事实来源”——三个月后没人知道哪个版本算数。

**这条清单本身也是边界**：出现一个没人认领的文件，通常说明有人在绕过契约干活。

## 二、它们是什么关系

**作业契约是单一事实来源。** 其余三个都从它派生，不能反过来。

```
作业契约（规则）
   ├── 派生 → 轮次页        （每轮的表单，列结构照契约第 6 节）
   ├── 派生 → 配对数据册    （数据，颗粒度照"受限级"规定）
   └── 派生 → 判据台账      （数据，修正对象是契约第 3 节的槽位）
```

**项目信息是状态指针**，不派生任何东西——它只回答三个问题：现在第几轮、做到哪一步、判据继承自哪里。模型接续全靠它定位。

**数据是这么流的：**

```
轮次页填完 ──→ 配对进数据册 ──→ 回流进台账 ──→ 下一轮判据状态更新
   ↑                                                    │
   └────────────────────────────────────────────────────┘
```

一句话：**每跑一轮，判据准一点，下一轮快一点。** 如果某一轮开始"从零开始"，说明有环节断了。

## 三、这套东西**不**提供什么

有三处是故意留空的，只给判定维度，不给答案：

| 留空处 | 你得自己定 |
|---|---|
| 目标量该选哪个指标 | 在你的领域里，哪个数才算"改好了" |
| 九个槽位的阈值定多少 | 你那行的指标、检测方法、通过线 |
| 覆盖边界划到哪 | 你的产品具体哪些情形不适用 |

**这三处填不出来，整份契约就是空表。** 填出来靠现场判定，不靠照抄。

判断现场这三件事，不是看文档能学会的——文档给的是"该判哪几件事"，不是"该怎么判"。

## 四、第一次开工，四步

**第 1 步 · 读规则**（约 20 分钟）
三方各自读一遍 `产品拆解优化作业契约.html`。重点看第 2 节（三方分工与四道锁）和第 5 节（六步流程）。

**第 2 步 · 定五个位置**
只干一件事：把「目标量」定成**一个**数。定不出来就别开工——两个目标的项目，第一轮必失败。

**第 3 步 · 数配对**
甲方去数据里数 A 级配对有几组。
- ≥6 组 → 直接出假设
- <6 组 → 先做实验设计补点（契约 5.1 第②步）

**第 4 步 · 复制轮次页**
把 `轮次页模板.md` 复制成 `R1-探边轮.md`，勾选类型，开始填。

## 五、每轮怎么跑

| 阶段 | 动作 | 谁 |
|---|---|---|
| 会前 | 读契约、备产品与现状、带一版目标量初稿 | 三方 |
| 会中（第 1 次） | **定五位置**（目标量只能一个）、对口径、签授权 | 三方 |
| 会后 1 周内 | 数配对、填第 2 节；同时**验测量**：重复测 3 次，标准差 < 预期效应 1/3 | 甲方 + 乙方 |
| 第 2 周 | 出候选表 + 失败判据表 | 丙方 |
| 第 4～6 周 | 做实验、填回报表与归因 | 乙方 |
| 轮末 | 填回流记录、算命中率、过第 12 节自查 | 三方 |

**唯一硬止损：测量不可行。** 其余所有不通过都能调整路线，只有这一条是停。测不准的时候，整个流程会照常运转、照常出报告，但每个结论都是噪音。

## 六、维护规则

**只改契约，不改派生文件。** 改完契约后，按这张表同步检查：

| 改了契约的什么 | 要同步检查哪里 |
|---|---|
| 槽位编号（P1～P9） | 轮次页第 4 节 · 判据台账第一节 · 表 E 的"指向槽位" |
| 轮次类型或通过标准 | 轮次页开头那张标准表 |
| 表 A～F 的列定义 | 轮次页第 2、6、7、8、10、11 节（依表 A～F 顺序） |
| 产物清单（六件） | 轮次页第 12 节 |

**两本账只增不改。** 填错了追加一条更正行，不回头改旧行——历史被抹掉，就看不出进步速度了。

**契约升版时，已开项目的包不动。** 每个项目包里放的是开包那天的快照，不受全局更新影响。只有新开的项目才用新版契约。这条不守，三个月后没人说得清某批数据是按哪版规则产的。

## 七、命名约定

### 文件夹

**文件夹名 = 项目名。一个值，两处出现。**

| 情形 | 文件夹名 | `项目信息.md` 第一节 |
|---|---|---|
| 默认（尚未绑定具体项目） | `产品拆解优化作业包` | 产品拆解优化作业包 |
| 绑定具体项目后 | `产品拆解优化-甲产品降本` | 产品拆解优化-甲产品降本 |
| 多个包并存 | `01-产品拆解优化-甲产品` | 产品拆解优化-甲产品（不含序号） |

**默认名就是 `产品拆解优化作业包`。** 一旦这套文件对应到具体项目，把文件夹和信息表里的名字一起改掉——**改名必须同步，一步不能省**：

1. 改文件夹名
2. 改 `项目信息.md` 第一节的项目名
3. 在下一轮轮次页备注一句"项目名变更"

序号的例外：多个包放一起时可以加 `01-`、`02-` 前缀方便排序，但**项目名里不写序号**——序号是文件夹的装饰，不是身份的一部分。

**为什么这么严**：八个文件名在所有包之间完全相同，文件夹名是它们在文件系统里的唯一标识。名字对不上，收件人只能回来问你，而那时候你可能不在旁边。

### 文件

| 文件 | 命名 | 说明 |
|---|---|---|
| 轮次页 | `R{n}-{类型}.md` | 例：`R1-探边轮.md`、`R2-收口轮.md`。**旧页永不覆盖** |
| 实验设计 | `实验设计-{轮次}.md` | 例：`实验设计-R1.md`。只在该轮需要补数据点时才建 |
| 配对数据册 | 固定一个文件 | 不按轮次拆分，跨轮累积 |
| 判据台账 | 固定一个文件 | 同上 |

**连字符只用在「固定前缀 + 可变名」的地方。**

`R1-探边轮.md` 里，`R1` 是编号、`探边轮` 是类型，两者是不同性质的 token，需要分隔。
`项目信息.md` 是单一概念，不写 `项目-信息.md`。

这条分得清，文件名就不会一半带连字符、一半不带。

**标题 = 文件名。** 每个文件第一行的 `# 标题` 必须与文件名一致（去掉扩展名）。改文件名时同步改标题——否则文件列表里一个名、打开又是另一个名，转发出去最容易被问"这是哪一份"。

轮次页按轮次分文件，是因为**三态状态的变化轨迹本身就是资产**——P7 从"待裁决"变成"已校验"用了三轮还是一次，这个速度决定第二年的议价能力。覆盖掉就看不出进步。

### 署名的两种写法，不要混

| 文件类型 | 署什么 | 为什么 |
|---|---|---|
| **正式文档**（作业包说明、契约 md/html、归属与许可） | 作者 + 版本 + 日期 + 邮箱，完整落款 | 会被传阅、会升版，需要能追溯"这是哪一版" |
| **工作文件**（项目信息、轮次页、两本账） | 只留一行出处，不标版本日期 | 每轮复制或持续生长，"版本"会误导；内容是三方共填，标"作者"会认错人 |

**判断标准**：这份文件会不会被单独发出去？

- 会（比如把某一轮结果发给老板看）→ 至少要有出处行，否则脱离包就失去归属
- 不会 → 出处行也够用，不必加版本

**工作文件为什么不该标版本**：轮次页的规则版本由契约决定，它自己升不了版；数据册和台账是持续增长的数据，"版本"这个词对它们没有意义——它们只有"累计到第几条"。

## 八、给不同角色的一句话

- **甲方（配方方）**：你的活是数配对和判断值不值。数据不外流，用相对偏差就够。
- **乙方（验证方）**：你的活是设计并执行测量，外加一句"测不准"。这句话能否决整轮。
- **丙方（建议方）**：你的活是把配方变成可裁决的假设，并维护判据。你的战绩表是命中率。

## 九、接续协议（给模型）

**本包是可接续的。不要从头重做，先重建状态。**

### 9.1　读取顺序（严格按序，读完再动手）

| 序 | 文件 | 提取什么 |
|---|---|---|
| 1 | `项目信息.md` | 当前轮次、进度档位、契约快照版本、判据继承来源 |
| 2 | `产品拆解优化作业契约.md` | 规则：五位置、P1～P9、六步、表结构 |
| 3 | `判据台账.md` → 第一节「当前生效判据」 | **本领域已实例化的判据——这是最关键的输入** |
| 4 | `配对数据册.md` | A 级组数、失败案例数 |
| 5 | 最新一轮 `R{n}-*.md` | 判据状态快照、覆盖边界、命中率、未完成项 |

**不要读 `历史版本/`。** 里面是过程稿，与当前规则不一致。

### 9.2　状态判定（按序检查，命中即停）

| 条件 | 本轮动作 |
|---|---|
| 开包清单未走完 | 回到 `项目信息.md` 第二节补齐，不开工 |
| A 级配对 <6 组 | 不出候选，先做实验设计补点（方案存为 `实验设计-{轮次}.md`） |
| 上一轮进度 ≠ 已判定 | 先补完上一轮（回报表 → 归因 → 回流） |
| 上一轮抽查偏差 >20% | 本轮类型 = **校准轮** |
| 判据继承自其他项目 | 本轮类型 = **外推轮** |
| 上一轮通过，且 P7 已有 ≥5 组数据 | 本轮类型 = **收口轮** |
| 其余 | 本轮类型 = **探边轮** |

### 9.3　写回（顺序不能乱）

| 步 | 写什么 | 写到哪 | 方式 |
|---|---|---|---|
| 1 | 新建轮次页 | `R{n}-{类型}.md` | 从模板复制 |
| 2 | 候选表、失败判据表 | 新轮次页 | 填 |
| 3 | 回报表、归因表 | 新轮次页 | 填 |
| 4 | 回流记录 | 新轮次页 **+** `判据台账.md` 第二节「修正记录」 | **追加行** |
| 5 | 当前生效判据 | `判据台账.md` 第一节 | **覆盖该槽位所在行** |
| 6 | 新增配对 | `配对数据册.md` | **追加行** |
| 7 | 累计统计 | `配对数据册.md` 统计节 | 覆盖 |
| 8 | 当前轮次与进度 | `项目信息.md` 第二节 | 覆盖 |

**只做一步，写回，再进下一步。** 不要一次产出全部轮次——那会跳过判定，把推导当结论。

### 9.4　六条禁止

1. 不覆盖任何已完成的轮次页
2. 不删除失败案例
3. 不把配对数据带到别的项目
4. 不留空覆盖边界
5. 不用"已校验"冒充"已裁决"
6. 不跳过第一节「当前生效判据」凭记忆判定

### 9.5　一句话

**读包 → 判状态 → 只做下一步 → 写回指定位置。** 状态在文件里，不在你的记忆里。
