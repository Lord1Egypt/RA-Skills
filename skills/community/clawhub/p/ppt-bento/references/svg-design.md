# Bento Grid 与 SVG 页面设计

在策划稿进入设计阶段时读取卡片与视觉规则；SVG 专属实现规则仅在生成 SVG 时适用。交付与编辑需求以 [delivery-routes.md](delivery-routes.md) 为准。

页面类型、开放式/卡片式/混合式构图、卡片内部排版与整套节奏见 [layout-composition.md](layout-composition.md)。本文件负责语义拆分、画布、视觉参数和 SVG 实现；使用隐形网格时同样遵守对齐和间距。

## 画布和内容区

原文默认画布为 `viewBox="0 0 1280 720"`，即 16:9。默认卡片间距至少 20 个用户单位；在 1280×720 CSS 像素显示时相当于 20px。若画布等比调整，间距也按比例调整。

可以从四周约 40 单位的外边距起步，再为标题、正文和页脚安排区域。这是实施建议，不是原文规定。原文的 1200×580 大卡片是单一焦点布局示例，须结合标题和页脚检查是否放得下。

## 按内容选择布局

| 关系 | 布局 | 决策要点 |
| --- | --- | --- |
| 一个重点或大图表 | 通栏图表或单一大卡片 | 不为填空间拆成多个卡片，背景干净时无需容器 |
| 两个平行主题 | 50/50 两栏 | 两边保持相似信息密度 |
| 主论点加辅助证据 | 约 2/3 与 1/3 两栏 | 先扣除间距，再分配可用宽度 |
| 三项并列比较 | 三栏 | 使用统一比较维度和单位 |
| 中心论点及两侧支撑 | 中间大卡片加侧卡片 | 中心面积体现信息权重 |
| 总述后分解 | 顶部英雄卡片，下方 2–4 张卡片 | 视线从结论进入细节 |
| 不同层次、多种信息 | 混合网格 | 共用对齐线，避免碎片化 |

卡片数量可为 1、2、3、4、5 或更多，由信息关系决定。信息重要性决定卡片面积，不能简单地按段落数量分配等大方块。内容超载时优先整理或拆页。

## 卡片语义与内容层级

每张卡片表达一个核心观点。独立并列信息可以拆卡；因果、先后、条件与例外须保持关联，必要时用连接线、流程或时间线表达。不要按逗号、段落或固定字数机械拆卡。比较关系优先用统一维度的图表或表格，避免大量孤立数字卡。

- 指标卡：大数值＋单位＋指标名称，再标明期间、实验条件或比较基准；必要限制和来源不可省略。单独的“大数字”不算完整指标。
- 观点卡：简洁且准确的标题＋具体解释或证据；不为短标题强行压缩术语，不强制双语装饰。
- 主卡与辅助卡：主卡建立页面结论，辅助卡提供独立证据或行动，不重复同一句话填充多个卡片。

## 视觉样式

遵循用户品牌和参考风格。未指定时，选用适合受众的简洁专业样式，建立一套有限的色板、标题层级和字号体系。强调色服务于重点和数据语义；不要靠装饰制造不存在的业务结论。

制作前确定背景/正文/强调/辅助色、标题/正文/指标/注释字号、边距/间距和圆角。1280×720 可从页标题 36–44、正文 22–28、指标 48–72、注释 14–18 用户单位起步，按字体和实际投影检查调整；这些是参考范围，不用小字号弥补内容超载。

用户已确认的浅底、深底或品牌体系优先。强调色控制数量，但多系列图表需有可区分的颜色或线型；红绿等业务语义保持一致，不能为了单色风格消除差异。

图表的轴、单位、图例、时间范围和数据来源应清晰。流程、架构和关系图先准确表达结构，再增加样式。对未知数据保留待补充说明，不生成看似真实的图表。

## SVG 实现

- 使用 SVG 命名空间 `http://www.w3.org/2000/svg`，明确 `width`、`height` 和 `viewBox`。
- 优先使用 `rect`、`line`、`path`、`circle`、`text` 和 `tspan` 等基础元素；元素 ID 在同一文档中唯一。
- 为文本显式设置字体、字号、颜色和位置。SVG 普通 `text` 不会自动换行，需按宽度拆行并用 `tspan` 定位，检查中文、英文长词与行距。
- 正确转义 XML 文本中的 `&`、`<`、`>` 等字符；属性值正确引用。
- 避免脚本、事件处理器、外部样式依赖和 `foreignObject`；复杂滤镜、遮罩和字体效果须验证目标应用支持情况。
- 使用有权使用的素材，尽量嵌入图片或一并交付本地资源，避免依赖可能失效的远程链接。
- 优先保留文本为文本。字体转路径可能提高外观稳定性，但会损失文本编辑和检索能力，只在明确需要时选择并说明。

每页生成后渲染检查；优先修复内容溢出、缺字、碰撞和对齐问题，再调整装饰。代码能解析不代表排版正确。

局部着色或字重变化使用 `tspan` 等文本片段，并核对基线、行距和换行；避免把同一句话随意拆成多个独立文本框后失去对齐。PPTX 对应使用原生富文本保留编辑能力。

## PPTX 导出与可编辑性

按 [delivery-routes.md](delivery-routes.md) 选择原生生成或整页图形方式，并验证约定的可编辑范围。SVG 路线保留源稿；HTML 与仅 PPTX 路线不强制补做 SVG。真实生成 PPTX 后才称为 PowerPoint 文件。
