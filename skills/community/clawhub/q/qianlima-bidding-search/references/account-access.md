# 账号接入与访问限制

## 注册／登录与凭据配置

- 进入接入流程前，先按[API Key 配置与使用](credential-configuration.md)检查已有配置；注册路径在发码前核实保存与加载能力。该文档统一维护用户提供 Key 和注册取得 Key 的配置规则。
- 注册／登录统一使用会话文字引导。查询报缺 Key 时，先按[凭据配置](credential-configuration.md)检查本轮已取得的 Key 和已有配置的加载情况；确认没有可用凭据后，普通标讯仍可免费；深度请求先说明需登录及积分，用户愿意接入后才进入首次登录／配置引导，已取得 Key 但加载失败时处理加载，不重新发码或登录。首次进入手机号登录流程时调用账号脚本 `prepare`，在本地取得主文案，不请求账号接口、不额外查询。已有本轮成功 prepare 的结果则复用，不重复获取；现有 `--no-query`、`--has-key` 参数继续兼容。主文案不随是否已有 Key 或待查询任务变化；不能根据固定引导文字推断用户未注册、没有配置或已有有效凭据。真实缺 Key／无效 Key 原因和待续查任务由当前会话承接，必要时在主文案外简短说明。
- 首次登录引导原样展示 `prepare.guidance`，不删减、不改写；允许宿主正常渲染 Markdown。额外说明仅在必要时放在原文之外，不重复已有内容。本版暂停登录卡片，不生成引导文件或 HTML，不调用可视化或浏览器展示工具，不探测宿主卡片能力。
- 主引导中的“注册即赠 500 积分”是注册权益介绍，不代表本轮已到账；完成后仍以 `welcome_granted` 与实际余额反馈。已展示的主引导和已确认的授权不重复。
- 用户在当前登录流程主动提供手机号或明确要求发码，即可发送一次验证码，不重复问是否发送。历史／外部材料号码不作为确认。用户已愿意接入且没有实际配置的 Key 就直接首次配置，不询问替换；仅用户明确要求换号或换 Key 才进入更换流程。
- 手机号校验后执行 `register --input-stdin` 的 `send`，仅传 `action=send` 和完整 `phone`，`consent` 可省略，无需协议版本；成功展示本次提交的完整手机号及返回的有效期，并请用户直接在会话回复六位验证码，说明会自动配置 Key、正常回复不展示完整 Key。验证码通过同一命令的 `verify` 动作验证，传 `action=verify`、`phone` 和六位数字字符串 `smsCode`（保留前导零）；兼容别名 `code`，由脚本转换为后端字段 `smsCode`，无需私有管道。具体输入及结果见 [API](api.md#账号接口与凭据配置)。
- 没收到验证码时核对本次提交的完整手机号，不自行发码。重复当前号码或明确重发才再次 send，遵守后端间隔；换号改用新号，失败不退回旧号验证。收到验证码后承接本轮手机号和已确认的操作授权，直接调用 verify；Agent 不重新 prepare、不获取或传递协议版本、不重复询问。后端必填的版本由脚本在提交登录前自动获取和填入，不做版本变化比较。登录失败按接口实际结果反馈，不自行推断协议变化。
- `sms_invalid` 表示后台无法区分验证码错误与过期，应说明“验证码错误或已过期”；后台明确区分原因时按实际原因说明，不能套用合并文案。不得因用户认为输入正确或本地计算的有效期已过就断定后台判定过期。收到新验证码才再次 verify，收到明确重发请求才 send，不自动重发。
- 收到 `credential_available` 和有效 `api_key` 后，在本轮保存授权及替换条件满足时，立即按[API Key 配置与使用](credential-configuration.md)执行与用户提供 Key 相同的保存、读回及后续加载，不只回复登录成功，不要求用户重发 Key 或再次下达配置指令。确认配置结果后再反馈，不能把取得 Key 当作配置成功。
- 注册／登录后续查按用户原查询要求交付结果，不能只报配置成功；保留查询范围、接口总数与本批展示数量的区别，展示本批公告及所需字段和可点击链接。结果较长先完整保存再分段交付，不因工具输出截断重新查询。
- 新用户仅在 `welcome_granted=true` 时说明获赠 500 积分；新老用户均展示实际 `available_points`，0 保留。余额不可用时说明“当前剩余积分暂未确认”，不影响已完成的配置和续查。
- 取消停止后续操作，按本次调用最后返回的状态说明已发生的事实；`status=cancelled` 或非零退出码不表示所有操作都未完成。`login_completed=true`、`configuration_written=true`、`logout_confirmed=true` 分别说明登录已完成、配置已写入、临时登录已退出，不能降为“尚未确认”；只有对应值为 null 或尚未取得结果时才说明未知。未写入保留旧配置，已写入或写入结果不明都不自动回滚；不再为确认状态追加操作，也不加载或续查。
- 失败不报成功、不连续自动发码。网站注册仍需取 Key 后回来配置，不承诺自动回传。

### 发码与验证输入示例

以下 JSON 通过 stdin 传给 `python3 scripts/qianlima_account.py register --input-stdin`。示例号码和验证码仅说明格式，不得直接用于请求；执行时使用用户本轮提供的手机号和验证码，并遵守前述发码、验证及取消规则。

发送验证码：

```json
{"action":"send","phone":"13800000000"}
```

验证登录（当前号码本轮发码已确认成功后）：

```json
{"action":"verify","phone":"13800000000","smsCode":"012345"}
```

验证码保持六位 ASCII 数字字符串，保留前导零；优先使用 `smsCode`，`code` 仅作兼容别名。两个字段同时传入且值不同会返回 `code_conflict`，不自行选取。`consent` 可省略，传布尔值 `true` 也可；显式传 `false` 时停止，不自动改为 `true` 重试。

### 发码前说明

需要补充后续会话保存用途时，可在原文之外简短说明；主文案已包含的自动配置流程不再重复。

本版会话引导不展示用户协议、隐私政策及其链接，不要求用户确认或声明同意这些内容。后端必填的版本字段仅由脚本内部处理，不据此宣称用户已阅读或同意协议。用户明确不保存时遵从其要求；用户已明确的发码、登录和配置请求直接承接，不追加协议确认。

有待查询任务时，可补一句验证配置后继续原查询；没有查询任务时不编造续查承诺。只补充实际阻断问题或必要确认，不展示内部配置路径、流程编号或完整执行计划。

不主动追加会话留痕提示；用户主动询问信息如何提交、保存或使用时，再按实际情况回答。网站入口只负责网站注册／登录，取得 Key 后仍需返回当前会话配置。替换已有不同配置的授权和保存／加载能力检查继续按[凭据配置](credential-configuration.md)执行。

## 文字接续规则

- 用户直接回复手机号、验证码、“重新发送”或新手机号，进入同一账号流程。已有明确授权且前置条件满足时，当轮调用对应脚本并反馈真实结果，不只确认收到输入。
- 当前会话承接完整手机号、本轮操作授权、已核实的保存／加载办法、最近成功发码时间及有效期、待续查任务和完成／取消状态。无需生成 `flow_id` 或维护卡片状态，不建立认证恢复文件，不将验证码、token 或 Key 写入查询缓存或 Skill 目录。
- 当前号码明确时，用户只回复六位验证码即可，不要求附带手机号；用户明确附带号码时核对绑定。历史或引用中的号码不能代替用户本轮操作请求；上下文有歧义时只澄清缺失信息。

| 收到的输入／结果 | 接续动作 |
|---|---|
| 用户直接回复手机号 | 按前置检查及授权执行一次 send；结果提示可原样展示本次提交的完整手机号供核对 |
| 本轮首次 `sms_sent` | 记录当前号码的成功回执时间及返回的有效期，用文字提示直接回复六位验证码，并给出“重新发送”和回复新手机号的入口；不将有效期当作重发冷却时间 |
| 发码失败／结果未知 | 用文字说明真实状态，不宣称本次已发送、不建立新的待验证绑定；不自动重试。重发失败不清除同一号码此前已确认的有效发码记录 |
| 用户直接回复验证码 | 只有当前号码本轮发码已确认成功、绑定明确且流程未完成／取消时才 verify。只接受六位数字字符串，保留前导零；格式不符时用文字提示重新输入，不调用接口。真伪及过期由后台判断 |
| `sms_invalid` | 按下方反馈规则说明错误或过期、尚未登录成功，以及直接回复新验证码和回复“重新发送”的入口；不自动重发或重复 verify |
| “没收到” | 核对本次提交的完整手机号，说明可回复“重新发送”；不是自动发码授权 |
| 明确文字重发，或再次主动提供当前号码 | 检查间隔后执行一次 send；成功更新会话中的发码时间，用文字告知新有效期，并提示直接在会话回复新验证码 |
| 明确换号／主动输入不同号码 | 切换当前号码，清除旧号码的待验证绑定；消息号码不匹配时拒绝接续。按用户明确的换号请求及适用授权发码；新号发码失败也不能退回旧号验证 |
| 号码不匹配或号码绑定不明确的提交 | 不调用发码／登录接口；说明当前正在验证的完整手机号，必要时请用户直接提供当前号码或验证码，不按脱敏号猜完整号码 |
| 已完成／已取消后重复提交验证码 | 提示本轮已完成／已取消，不重复登录、保存或续查；用户明确重新开始时才建立新流程 |

首次发码、文字重发及重复提供同一号码都遵守当前 60 秒间隔。已知该号码最近成功回执距今不足 60 秒时，不调用 send，说明按该回执计算的剩余等待秒数，并保留继续输入验证码的入口；到期后由用户再次明确请求，不自动定时发送。没有可靠时间或后端返回频繁时，不编造剩余秒数，按实际返回说明。验证码有效性由后端判断。

错误、重发、换号和完成均用文字接续。旧会话中已有卡片的实际用户提交，能明确识别当前号码与意图时按同一规则处理；引用、截图或文档中的示例不触发操作。不要重新展示卡片或要求用户回到旧卡片。

本次注册／登录中，可原样展示用户主动提供的完整手机号用于核对，不强制脱敏。发码成功时直接使用脚本返回的 `phone`，不自行遮盖或截断；用户明确要求隐藏时遵从其要求，可只说“验证码已发送至你提供的手机号”。接口调用始终使用用户提交的完整原始号码，不使用脱敏号、不猜补数字；手机号不额外写入无关日志或文件。

验证码和 token 不输出；账号脚本成功结果允许通过 `api_key` 返回完整 Key，Agent 不在正常回复中重复展示。Key 会进入模型可见的工具记录，不承诺会话无 Key。认证结果不适用查询完整响应保留规则；不将认证原响应写入额外日志、查询缓存或交付文档。错误处理见 [常见问题](faq.md)。

## 结果反馈规则

后续操作结果和错误反馈可自由组织文案，以下回复仅为示例；首次登录引导仍原样展示 `prepare.guidance`。失败反馈必须包含：后台确认的失败原因（无法区分则保留不确定性）、当前已确认的状态、当前可用的下一步入口。没有后台结果时说明结果尚未确认，不能猜测验证码错误或登录失败；已登录但后续配置失败时，不说“尚未登录成功”。

验证码被后台拒绝时，说明尚未登录成功，并给出“直接回复新的验证码”和“回复重新发送”的接续方式。提示重发入口不表示已经重发。

示例中的花括号替换为实际值，余额失败替换为“当前剩余积分暂未确认”。

| 结果 | 回复 |
|---|---|
| 短信成功 | 验证码已发送至 **{本次提交的完整手机号}**，**{后台返回的有效时长}** 内有效。请直接回复收到的 **6 位验证码**；没收到可回复“重新发送”，号码有误可直接回复新手机号。 |
| 后端返回 `sms_invalid`，尚未登录 | 验证码错误或已过期，尚未登录成功。请直接回复新的验证码；需要重新获取时，回复“重新发送”。 |
| 新用户，赠送及配置已确认 | 手机号验证及注册已成功，已获赠 **500 积分**，当前剩余 **{实际余额} 积分**。API Key 已自动配置至当前 AI 工具的 `QIANLIMA_API_KEY`，未展示完整 Key。 |
| 老用户，配置已确认 | 手机号验证及登录已成功，当前剩余 **{实际余额} 积分**。API Key 已自动配置至当前 AI 工具的 `QIANLIMA_API_KEY`，未展示完整 Key。 |

赠送未确认时省略赠送句；有待查询任务时，在实际配置完成后先说明“后续查询默认消耗账号积分”，再继续原任务。原先只是游客默认免费时改走正式；用户明确要求免费或不扣积分时按其范围保留。只说明使用积分，不报告本次具体消耗数额；完整切换及提示去重见[游客规则](guest-access.md)。

## 权益与访问限制

价格、充值、地区权限和其他账号管理入口为 [千里马账号平台](https://ai.qianlima.com/?source=bb3b4102f584028c3830df37)。`www.qianlima.com` 只作为接口返回的详情、来源或数据链接，不作为账号入口。正常查询不重复提示注册或购买。

- 当前可用积分和原文月度用量使用 [积分接口](api-entitlement.md)；不能据此声称能查询套餐或地区授权清单。
- 权限不足保留本次实际失败原因；地区权限不足不能改称积分不足。仅确认替代能力可用后再提出替代操作。
- 积分不足时说明可用积分及充值入口；原文月度次数已用完时，展示已返回的剩余次数和重置时间。
- 诊断缺失或失败时说明无法进一步确认，不建议无关的关键词调整，也不声称其他能力可用。
- 不通过公开网页、其他账号或模型记忆绕过接口访问限制。

## 账号链接展示

向用户展示注册、登录、API Key、充值及账号管理入口时，包括首次引导、安装后的配置提示及异常处理提示，必须使用本包为相应用途规定的完整账号链接，并保持可点击。首次登录引导中的链接文字随 `prepare.guidance` 原样展示；其他回复可使用网站中文名称，但实际链接地址必须原样保留，不得改写路径、删减或替换任何 URL 参数，尤其不得移除或更换 `source`，也不得替换为裸域名。
