# 游客查询与积分查询

本页用于决定免费查询的选路、结果说明、权益引导及后续任务衔接。先按用户身份和费用意愿确定执行方式，再按对应能力文档组织查询；结果返回或用户追问时，使用本页对应场景的规则。

搜索条件见[普通项目](capabilities/project-search.md)，请求和响应契约见[免费搜索接口](api-free-search.md)。本页决定何时进入账号流程；具体登录和配置操作复用[账号接入](account-access.md)及[凭据配置](credential-configuration.md)，不另建登录流程。

## 一、身份与选路

### 1. 先判断身份

按既有凭据配置规则检查，不要求用户重复提供已配置的 Key。

| 状态 | 判断与处理 |
| --- | --- |
| 游客 | 确认没有个人 API Key，可匿名查询普通标讯 |
| 已配置 Key | 个人 Key 能够加载用于请求，按账号能力执行 |
| 配置异常 | 已有配置但读取或加载失败，先处理配置问题，不直接判定为游客 |

“游客”是身份，“免费”是查询方式。已有 Key 的用户也可以免费查列表，携带 Key 不代表该请求收费。

### 2. 按需求选路

| 用户状态 | 本次需求 | 执行方式 |
| --- | --- | --- |
| 游客 | 普通招标、中标等标讯列表，或对应的翻页、修改条件 | 使用免费接口，匿名返回基础结果，不先要求注册 |
| 游客 | 详情、正文、附件、联系方式、进展、来源原文，或采购意向、临期项目、企业情报等正式能力 | 先按第三节说明所需权益；愿意注册／登录后再进入账号流程 |
| 已配置 Key | 普通标讯列表，没有任何适用的免费要求（含会话偏好和当前列表主动选择） | 默认使用正式接口，沿用现有权益和计费规则 |
| 已配置 Key | 明确要求免费查询普通标讯列表 | 使用免费接口并携带已配置的真实个人 Key；列表不扣积分，仍受免费字段和额度限制 |
| 已配置 Key | 主动请求深度信息或其他正式能力 | 使用个人 Key 调用对应正式接口；列表免费偏好不阻止此操作 |

上表始终服从用户明确的费用限制。游客混合需求先完成可独立执行的免费部分，再说明尚未提供深度内容所需权益，按第三节组合提示；不因一项受限阻塞整个查询，也不能因其中一项免费就把其他能力当作免费。已配置 Key 且已明确确认积分不足时，按第四节“积分不足”优先免费完成可满足部分，不将已有账号判为游客。

### 3. 分清免费要求的范围

| 用户意愿 | 作用范围 |
| --- | --- |
| “这批列表免费查” | 当前列表及其翻页、修改条件和恢复；不扩大到其他列表，不限制主动请求的深度查询 |
| “本会话后续列表都免费查” | 本会话后续普通标讯列表；深度查询仍按账号权益执行 |
| “全程免费”“任何操作都不扣积分” | 所有操作；需要收费时先说明并取得对应范围的同意 |

已配置 Key 的用户首次主动要求免费列表时，若尚未明确会话后续偏好，实际查询成功后，在结果列表前说明免费范围并询问一次后续普通列表是否也都免费；同轮直接展示结果，不等待回答。“这次免费”只确定当前列表，不代表后续偏好已确定；询问不阻塞本次结果，未回复不扩大范围。当前操作遇请求频率限制时仅按限频处理；明确次数额度耗尽或分页触顶且正式通道可承接时，才按第四节处理积分续查，不同时询问后续免费偏好。已明确后续选择则不再问，具体链接说明见[主动选择免费列表](#2-主动选择免费列表)。

用户后来改变意愿，按最新指令及其范围执行。明确同意本会话后续使用积分，可以覆盖旧列表的免费选择；仅同意本次收费，不能扩大为后续收费授权：本次传 `authenticated`，后续仍受原免费限制时显式传 `guest`，不能因缓存记录上次为正式模式而继续收费。脚本保存的是执行模式，费用授权范围仍由 Agent 承接。范围不清且影响是否收费时，只澄清必要的费用意愿。

游客因无 Key 而默认免费，不等于主动选择了后续免费。登录并完成 Key 配置后，默认使用积分继续原任务；用户明确提出的免费或不扣积分要求仍须遵守，具体见第五节。

## 二、免费范围与限制

### 1. 能查什么、返回什么

免费开放普通标讯搜索、翻页和修改条件。筛选项、匹配逻辑、排序及时间边界沿用正式搜索，不额外缩减筛选项，也不静默删除或放宽用户条件。

基础结果包括：标题、招标／采购单位、中标单位、地区、阶段、预算金额、中标金额、发布时间和相应链接。公告 ID 留作后续定位，不直接展示；金额由元换算为万元，空值说明未公示，0／false 保留原意。

允许按正文、附件、标的物等条件筛选，不代表免费返回相应内容。附件筛选保留，但免费列表不返回 `hasAnnex`；需要标的物明细、正文、附件或联系人等深度信息时，按正式能力处理。

已有基础信息足以回答时直接回答，不为解释这些信息再查详情或引导注册。不猜中标方，不用 WebSearch 补全免费未开放的电话或正文；不通过隐藏展示代替服务端字段裁剪。

### 2. 数量与频率限制

以下限制同时适用于匿名免费请求和携带个人 Key 的免费请求。

| 项目 | 规则 |
| --- | --- |
| 每页数量 | 固定 30 条；末页或不足 30 条时按实际返回数量展示 |
| 免费翻页上限 | 同一组有效查询条件最多前 10 页，共最多 300 条 |
| 每分钟请求频率 | 20 次；服务端仍保留并发、过载及全局成本保护 |
| 每小时额度 | 150 次 |
| 每日额度 | 300 次 |
| 累计方式 | 分钟频率限制与小时、日次数额度同时生效；翻页计次，正常修改条件不重置累计额度 |
| 总数展示 | 真实命中总数与免费可访问数量分开说明，不能把命中总数截成 300 |

额度和访问上限由服务端控制。本地可以根据已知分页上限避免请求第 11 页，但不能代替服务端限制。不自行计算剩余额度或恢复时间，不连续重试、不拆分条件绕过限制。计量身份及窗口以接口契约为准，不自行查询或填报用户 IP；按 IP 计量时不能宣称每个用户独享额度。

### 3. 链接如何展示

**列表链接展示：** 返回官网首页入口时，公告标题使用纯文本，不附该 URL，不另设“查看详情”或表外官网替代入口，也不追加官网链接说明。返回对应公告详情链接时，标题附该条实际返回的完整 URL，保留路径和参数；不能仅凭是否配置 Key 判断。表格、纯标题列表、翻页、修改条件及缓存交付均适用；用户明确不要链接时遵从。原始响应和查询状态中的 URL 保留，不伪造详情链接。

| 身份 | 免费列表链接 | 展示说明 |
| --- | --- | --- |
| 无 Key 或无效 Key | 千里马AI数据平台官网入口 | 标题为纯文本，不展示该官网 URL，不追加列表下方的官网链接说明 |
| 有效 Key | 对应公告的详情入口 | 说明列表免费，点击查看详情使用账号积分 |

单独提及平台时称“千里马AI数据平台”。既有注册／登录流程的官网入口保留，不因取消游客标题链接而删除；不在结果列表中另加官网入口或链接用途说明。用户主动询问时按实际返回类型解释。

无效 Key 的免费请求由服务端按匿名模式成功返回基础结果和官网链接，正常交付，不报鉴权异常，不额外查权益或去掉 Key 重试。正式接口实际返回的鉴权错误仍按正式规则处理。

来源由脚本在免费请求体的 `sourceCode` 中固定传入，后端据此生成链接，Agent 按链接类型展示，保留的详情 URL 原样使用；不在回复时补拼来源参数。传参细节见[免费接口](api-free-search.md#来源传递)。

历史响应及缓存中的官网 URL 保留，重新展示列表时按纯文本标题处理，不因登录而改写为详情链接。旧对话不修改；登录后新返回的真实详情链接可以点击。

列表请求、链接生成／展示及自动预览不应触发详情扣费，用户实际查看详情时由后端校验账号权益并按正式规则计费。Agent 不为生成链接逐条调用收费详情，也不自动打开或预取收费详情。个人 Key 不拼入 URL，不交给页面脚本，不写入查询状态或回复。详情鉴权和计费由后端与页面负责，不能仅凭链接存在就承诺可访问。

### 4. 未完整提供的信息如何标注

因未登录或已明确确认积分不足而未查询的深度内容，分别标注“登录后查询”或“充值后查询”，不笼统写“待查”。已有信息直接展示，部分已知时仅对未提供部分标注。表格内使用上述短标注，表格上方按适用场景统一说明权益及操作方式，不在每个单元格重复长篇引导。其他缺失或失败情况沿用原有规则，不套用上述提示。标注不承诺登录或充值后一定有该信息，不改变拒绝注册、提示去重或费用授权规则。

## 三、游客的引导规则

### 文案执行与场景选择

固定回复模板在触发条件满足时必须原样使用；仅允许替换明确列出的变量，或按已列明的例外规则省略相应内容。不得自行缩写、同义改写或省略信息。业务分析、结果摘要及查询建议不受固定模板限制，不能用建议替代固定提示。文案描述的是能力与费用规则，不保证某条公告一定存在正文、附件或联系方式。

本页直接给出的面向用户固定文案，输出时整段使用 Markdown 加粗（`**文案**`），包括按例外删减或替换变量后的文案；拼接多个模板片段时合并加粗范围，不嵌套加粗。业务结果及自由分析不因此整段加粗。账号流程的 `prepare.guidance` 仍按工具原样展示，不额外改写其格式。

有结果时的展示顺序为：查询条件及数量摘要 → 加粗的适用固定提示 → 结果列表 → 业务分析与下一步建议。免费范围、登录入口、费用说明、免费偏好确认及适用的上限说明／续查邀请放在列表之前；提示位置前移不改变触发条件、去重或授权范围。先取得查询结果再判断成功提示，不能在请求成功前预告成功。有偏好问句时，同轮直接展示结果，不等待用户回答。没有新结果时直接说明限制及适用选项，不重复旧列表。深入建议仍在结果后，权益短句紧跟具体建议；登录完成后的费用告知仍在实际收费调用之前。

每轮根据可见对话选择适用场景，不把模板逐段堆叠：

1. 用户当前明确的取消、拒绝注册、费用限制及授权范围优先；用户后来主动登录或改变费用意愿时按新指令承接。
2. 用户已明确愿意登录时进入第五节账号流程，不再追加询问登录意愿的过渡；已完成配置时用第五节承接文案。
3. 当前查询失败或遇限时先解释实际原因。请求频率限制只按限频处理；明确次数额度耗尽或分页触顶才按对应分支处理续查，不能同时询问后续免费偏好；失败不触发首次成功提示。
4. 游客同时请求免费基础信息与深度内容时，先执行免费可独立完成的部分，成功后用深度场景的组合模板，不叠加首次免费提示；纯深度需求没有免费可交付部分时直接过渡，不为凑列表额外搜索。免费接口不能满足的必要筛选条件不得静默删除。已配置 Key 且确认积分不足时按第四节独立场景承接。
5. 其余成功结果按身份选择游客首次提示或已有账号免费提示；同轮有深入建议时不重复另一段权益说明。普通免费续查和可直接回答的基础信息不新增推广。

业务回复只解释当前业务限制、费用范围和下一步，不引用内部规则原文或本地 Skill 路径。技术排查请求可说明依据；账号流程原样展示 `prepare.guidance` 的要求保留。提示是否已展示按实际发出的回复判断，不把读取文档或失败请求算作已提示。

正常业务回复使用“免费查询”“登录后使用积分”等用户可理解的表达，不用“无 Key”“游客模式”“测试环境”或内部参数解释查询限制。仅在用户主动询问配置、环境或进行技术排查时，说明必要技术信息。

### 游客模式登录邀请

首次免费结果、实际深度需求及适用的次数额度／分页上限场景统一使用下列说明，不再判断入口或赠分是否已介绍。每轮最多一次；深入推荐仍仅使用权益短句，不主动附本段。“我要登录”是便捷回应示例，其他明确注册／登录意愿同样有效。

> **新用户注册可获赠500积分，如需登录或注册，直接说“我要登录”即可。**

普通翻页、修改条件和继续免费查询不单独触发本段；拒绝注册后不主动追加，短时间重复遇限不重复邀请。已明确愿意登录时直接进入第五节，不再询问意愿。

### 1. 首次返回免费结果（实际执行免费查询）

**触发条件：** 游客在当前会话实际执行免费查询并首次成功取得结果，包括正常零结果；首次失败不消耗此触发机会。无效 Key 被服务端按匿名成功返回时按游客实际结果处理。

**固定回复模板：** 实际免费查询成功后，在查询条件及数量摘要之后、结果列表之前展示。未拒绝注册时使用完整模板，不因此前介绍过入口或赠分而删减：

> **以下为免费查询结果，登录后可使用积分查询完整公告、附件及联系方式。**\
> **新用户注册可获赠500积分，如需登录或注册，直接说“我要登录”即可。**

本模板按上述两行展示，每行加粗；保留这里的标点，不拼回一段。

**允许替换项：** 正常零结果时将“以下为免费查询结果。”替换为“本次免费查询未找到符合条件的结果。”，其余按适用分支展示；不把失败当零结果。

**去重与例外：** 已拒绝注册时仅用“**以下为免费查询结果。**”；后续翻页、修改条件、继续免费搜索或交付本页缓存不重复本段。同轮还有未提供的深度需求时改用下一场景的组合模板，不叠加本段。

**后续动作：** 免费任务正常继续，不要求注册，不自动发短信或调用正式能力。

### 2. 用户请求游客无法获取的深度信息

结果中的深度内容标注遵循[未完整提供的信息如何标注](#4-未完整提供的信息如何标注)。

**触发条件：** 游客请求正文、附件、联系方式、其他未开放字段、进展／来源原文，或采购意向、临期项目、企业情报等正式能力；包括同次请求还含可免费完成部分的混合需求。

**执行规则：** 混合需求先执行免费可独立完成的部分，取得结果后在列表上方使用组合提示，不因部分内容受限阻塞整个查询。不得静默删除影响结果的必要筛选条件，把放宽条件的列表当作满足原需求的结果。已有基础信息足以回答时直接回答，不重复查询；纯深度需求没有免费可完成部分时直接说明权益，不为凑列表发起无关搜索。此处是在回答业务访问条件，不是请求执行权限审批；普通回复不附“暂停依据”、内部规则引文或本地文件路径。

**固定回复模板：** 纯深度需求：

> **免费查询仅提供招投标项目基础信息，{所需内容}需登录后使用积分查询。新用户注册可获赠500积分，如需登录或注册，直接说“我要登录”即可。**

混合需求实际免费查询成功时，在结果列表之前使用：

> **以下为免费查询结果。{所需内容}需登录后使用积分查询。新用户注册可获赠500积分，如需登录或注册，直接说“我要登录”即可。**

**允许替换项：** `{所需内容}`使用用户本次明确需要、尚未提供的深度内容的简短名称，如“采购意向”“采购方联系方式”“车辆要求和投标截止时间”；不复述地区、时间、关键词等查询条件，不增加用户未提出的需求。完整查询条件保留用于后续查询；正常零结果将“以下为免费查询结果。”替换为“本次免费查询未找到符合条件的结果。”。免费失败不使用成功模板，按实际原因说明。已有基础信息直接回答、没有新列表时不使用“以下为免费查询结果”，交付已有信息，仅说明未提供内容的权益及适用登录说明。

**去重与例外：** 组合提示优先于首次免费模板，每轮只出现一次登录说明，不按入口或赠分是否曾介绍分支；免费范围内已经能够回答的部分不引导登录。已明确愿意登录转第五节；已拒绝注册仍交付免费部分，对未提供深度内容仅用“**{所需内容}需要登录后使用积分查询。**”，不补赠分或邀请。

**后续动作：** 保留当前对象、条件、进度和未完成任务，用户愿意登录后由现有账号流程承接；未同意不执行受限请求。

### 3. 推荐用户深入查询

**触发条件：** 沿用现有推荐逻辑或用户询问下一步，提出联系人、截止时间、正文等深入建议；不因游客模式固定新增推荐段落。

**固定回复模板：** 需要在该轮建议处说明权益时，使用“**（登录后可查询）**”。

**允许替换项：** 权益短句不改写；建议的内容、对象与格式由实际业务决定。

**去重与例外：** 不要求每条建议、每轮建议都附短句；本轮首次免费提示或深度过渡已说明权益时不重复附加。免费筛选、翻页、基础信息整理不附此句；拒绝注册后不主动推荐登录或赠分。

**后续动作：** 选择建议只表示深度需求，转上一场景；不等于同意登录、发短信或收费。明确愿意登录的直接承接。

### 4. 请求频率、免费次数额度与分页上限

先依据明确的限制原因分流，不仅凭 `429` 推断额度类型。请求频率限制、累计免费次数额度、本组结果访问上限分别处理；身份状态不解释服务失败。

仅下述 4.2／4.3 满足各自追加条件时，在限制说明后使用对应的登录邀请。请求频率限制不使用这些文案。

不区分入口或赠分是否已介绍，统一使用：

> **如需继续本次查询，需登录后使用账号积分。新用户注册可获赠500积分，如需登录或注册，直接说“我要登录”即可。**


#### 4.1 请求频率达到上限

**触发条件：** 返回请求过频、请求频率达到上限或明确的每分钟限频；只有通用 `429`、未说明额度类型时，不推断小时／日次数额度耗尽。

**固定回复模板：** 明确为每分钟20次时使用“**免费查询已达到每分钟 20 次上限，请稍后继续查询。**”；其他信息不足时忠实说明实际返回，不猜具体档位。

**允许替换项：** 仅在接口明确给出可适用的等待时间时补充等待信息，不自行计算恢复时间。

**去重与例外：** 游客和已有账号均按限频处理，不追加注册／登录邀请、赠分、积分续查问句或后续免费偏好问句；不把限频解释为积分不足。已有账号也不能因限频自动切换积分通道。用户后来独立、明确提出登录或改变模式时，再按其实际意愿处理，不承诺切换能解除限频。

**后续动作：** 保留条件及已有结果，停止本次请求；不自动重试、不轮询、不拆条件绕限。后续用户要求再查时按当时身份和授权执行，成功提示按实际首次成功及拒绝状态判断；不把登录或拒绝登录说成查询恢复的原因。

#### 4.2 累计免费次数额度耗尽

**触发条件：** 服务端明确确认小时或日的累计免费查询次数额度耗尽；不能由泛化的请求频率消息推导。

**固定回复模板：** 小时额度使用“**本小时免费查询已达 150 次上限。免费额度为每小时 150 次、每天 300 次，预计于 {恢复时间} 可继续免费查询。**”；日额度使用“**今日免费查询已达 300 次上限，预计于 {恢复时间} 可继续免费查询。**”。

**允许替换项：** 同时耗尽多个窗口时逐项说明实际已确认的窗口；`{恢复时间}` 仅替换为接口明确提供且适用于全部已耗尽窗口的恢复时间。未知或不适用时，省略“，预计于 {恢复时间} 可继续免费查询”并以句号结束，不自行推算。固定数字不自行替换；响应冲突时如实说明，不宣称新规则生效。

**去重与例外：** 首次次数额度耗尽、正式通道可承接且未拒绝注册时，才在限制说明后使用本节对应的登录邀请；短时间重复或已拒绝注册只说明额度，不重复邀请。没有依据确认正式通道可承接时不提供该选项，不叠加首次成功或后续免费偏好提示。

**后续动作：** 同意登录转第五节；未同意不收费，不自动重试或拆条件绕限。次数额度不等于积分余额；Key无效按鉴权原因处理，不解释为积分不足。

#### 4.3 本组免费分页达到上限

**触发条件：** 本组有效查询条件已达到前10页／最多300条访问上限，仍需继续本组后续结果；不因正常末页或少于300条就误判触顶。

**固定回复模板：** 本轮有结果时，在结果列表之前使用“**免费查询最多查看本组查询 300 条结果，可以按原条件重新查询最新结果。**”；已确认仍有更多命中时附“**仍有更多匹配结果。**”。

**允许替换项：** 总数未知时不声称还有或没有更多；300条是结果访问数量，不是每日300次请求额度。

**去重与例外：** 首次分页触顶、正式通道可承接且未拒绝注册时，在限制说明后使用本节对应的登录邀请；短时间重复或已拒绝注册只说明分页限制，不重复邀请，不叠加首次成功或后续免费偏好提示。

**后续动作：** 同意登录转第五节，保留原条件和交付进度；不能自动收费或通过修改条件绕限。按原条件重新查询最新结果仍受前10页及累计次数额度限制，不自动重查，不把重查当后续300条。

### 5. 用户拒绝注册

**触发条件：** 用户明确不注册、不登录或取消登录。

**固定回复模板：** 同时提出可执行免费任务时直接交付，不新增固定提示；仅拒绝且无其他任务时用“**好的，继续使用免费查询。**”；再次请求受限内容时用“**{所需内容}需要登录后使用积分查询。**”。

**允许替换项：** 仅替换实际请求的 `{所需内容}`。

**去重与例外：** 不因新列表、翻页或再次遇限重启注册或赠分推广；用户主动询问权益时正常完整回答，不视为已同意登录。之后明确主动登录时承接新意愿。

**后续动作：** 不执行登录或收费，保留待办，继续适用的免费能力。

## 四、已配置 Key 用户的处理规则

### 1. 日常正式查询

**触发条件：** 普通列表无适用免费要求，或主动请求已授权正式能力。

**固定回复模板：** 不新增游客说明、注册提示或固定费用确认；直接交付业务结果。积分不足转本节第五场景。

**允许替换项：** 业务回答依实际数据组织，不报告本次具体消耗积分。

**去重与例外：** 整体不扣积分限制优先；已有配置加载失败不能判为游客。已说明费用范围的正常查询不逐次提醒。

**后续动作：** 按个人 Key 权益执行；明确确认积分不足时按本节第五场景完成免费可满足的部分并说明模式，不把其他错误当成积分不足。

### 2. 主动选择免费列表

**触发条件：** 已配置 Key 用户主动要求免费普通列表，本次成功且尚需首次说明或确认新的会话偏好。

**固定回复模板：** 返回详情入口且后续列表偏好未明确时：

> **本次列表免费查询，仅返回基础信息；点击详情或查询其他深度信息需使用积分。本会话后续的招中标列表也都免费查询吗？**

已明确后续列表都免费时：

> **当前会话后续的普通招中标列表将免费查询，仅返回基础信息；点击详情或查询其他深度信息仍使用账号积分。**

**允许替换项：** 实际返回官网入口时分别将分号后、问句前的费用句替换为“**查询其他深度信息需使用有效账号及相应积分权益。**”或“**查询其他深度信息仍需使用有效账号及相应积分权益。**”，不说点击官网扣费；只确认当前列表免费时保留首句及费用说明，去掉后续偏好问句。不外加官网辨析或统一查看入口。

**去重与例外：** “这次免费”尚未决定会话偏好，查询成功后在结果列表前询问一次，同轮直接展示结果，不等待答复。未回复不扩大范围，不在后续翻页、筛选中重复问；用户已明确后续偏好不再询问。全程不扣积分已明确后续免费偏好，不再询问；列表结果仅确认免费选择，不说深度信息会自动收费。之后实际请求受限内容时才按深度场景取得授权。请求频率限制按限频处理；次数额度或分页上限按第四场景处理，不同时询问后续免费偏好。无效 Key 匿名成功遵守游客提示，不额外鉴权探测。

用户在后续一轮确认“本会话后续列表都免费”，即使同轮还请求正文等深度内容，在该轮结果之前也必须使用上面的会话免费确认文案一次；不能用“已记住”等自拟摘要替代。这是确认新的偏好，不算重复首次免费说明；不再叠加另一段费用说明。

用户首次明确“仅当前列表免费，其他按默认”时，即使同轮要求翻页，也在结果之前使用“**本次列表免费查询，仅返回基础信息；点击详情或查询其他深度信息需使用积分。**”确认一次（官网入口按上面的规定替换费用句）；这是首次确认范围，优先于普通翻页去重。此后沿用该范围的翻页、筛选不重复确认；不再追加会话偏好问句。

**后续动作：** 携带真实 Key 免费查询，标题按实际返回类型展示：官网入口用纯文本，真实详情链接原样保留。未确认后续免费只保留当前列表及续查免费；确认后新列表也免费。新意愿按其范围更新。

### 3. 免费列表后请求深度信息及整体费用限制

**触发条件：** 已有 Key 用户实际请求正式能力，或明确免费次数额度耗尽／分页触顶后正式通道可承接，但存在全程不扣积分等整体限制。

**固定回复模板：** 已说明积分范围且无整体限制时不追加固定提醒，直接执行。受整体限制、尚无相应授权时：

> **{待办任务}需要使用账号积分，超出你要求的免费范围。是否仅本次使用积分{待办任务}？**

尚未说明费用范围但无整体限制时，调用前用“**{待办任务}会使用账号积分。**”，不增加确认步骤。

**允许替换项：** `{待办任务}` 仅替换为当前对象及操作，前后相同。

**去重与例外：** 已有足够授权直接按其范围执行；一次授权不扩展到后续。次数额度耗尽或分页触顶时，用户没有整体限制的使用下一场景；有整体限制的本次授权问句优先，不并列询问会话偏好。

**后续动作：** 深度查询不改变原列表免费选择；回列表仍免费。仅本次授权完成后原费用限制恢复，不能因缓存上次正式而续费。用户主动给出更广或更窄授权按其实际范围处理。

### 4. 免费次数额度耗尽或分页上限

**触发条件：** 已有 Key 的免费查询明确发生累计免费次数额度耗尽，或本组免费分页触顶；正式通道可承接且尚无足够授权。请求频率限制不触发本场景，按游客规则中的限频分支处理，不自动切积分或追加积分续查问句。

**固定回复模板：**

> **{限制说明}是否从现在起，本会话后续查询都使用当前账号积分？同意后，我会{续查操作}。**

**允许替换项：** `{限制说明}` 使用第三节对应限制文案及已确认的剩余结果说明；`{续查操作}` 替换为保留实际条件和进度的本次操作，例如“继续查询第11页”。费用范围及问句不改成含糊的“继续吗”。

**去重与例外：** 优先解决当前续查，不同时询问后续免费偏好，不介绍注册或赠分。短时间重复遇限不重复问；已有授权直接承接。全程不扣积分按上一场景；正式通道不能承接时仅解释实际限制，不提供无效选项。

**后续动作：** 上轮只有这一项且范围明确，“好，继续”等肯定答复即可承接，不再确认；多选或范围不明才澄清。未同意不收费；只同意本次就只执行本次。明确本会话后续积分授权覆盖当前任务、新搜索和旧免费列表续查。免费额度恢复不自动切回、不轮询；再次要求免费按新指令范围切换，保留进度和前10页限制。会话偏好不写入账号默认配置，旧缓存不覆盖新意愿。

### 5. 积分不足

结果中的深度内容标注遵循[未完整提供的信息如何标注](#4-未完整提供的信息如何标注)。

**触发条件：** 已配置 Key 用户查询时，由实际权益信息或接口响应明确确认积分耗尽／不足（如 `10030`）；不根据通用失败推断余额。无效 Key、配置失败、限频、超时及服务繁忙不触发本场景。

**执行规则：** 免费能力可以满足全部或部分需求时，直接完成免费可执行部分，无需再次确认是否免费查询；携带当前个人 Key，不转匿名身份。Agent 依据能力显式传 `--access-mode guest`，不重试已失败的收费请求。纯深度需求没有可免费完成的部分时直接提示；已有基础信息能回答就直接回答，不重复调用或发起无关搜索，不静默删除必要筛选条件。

**固定回复模板：** 免费查询成功后，在查询条件及数量摘要之后、列表之前加粗展示：

> **当前账号积分不足，本次已使用免费查询，以下为项目基础信息。如需查看完整公告、附件及联系方式，请前往[千里马账号平台](https://ai.qianlima.com/?source=bb3b4102f584028c3830df37)查看积分或充值。**

没有可免费交付的内容时：

> **当前账号积分不足，暂时无法查询{所需内容}。请前往[千里马账号平台](https://ai.qianlima.com/?source=bb3b4102f584028c3830df37)查看积分或充值。**

**允许替换项：** 确认余额为零才将“当前账号积分不足”替换为“当前账号积分已耗尽”，不能仅凭不足错误推断耗尽。`{所需内容}`替换为实际深度需求；混合需求也将第一段“完整公告、附件及联系方式”替换为本次未提供的深度内容。正常零结果将“以下为项目基础信息”替换为“未找到符合条件的基础结果”。已有诊断返回可用积分时补充实际值，否则省略；充值入口保留完整来源参数。

**去重与例外：** 转免费当轮说明一次，普通连续翻页不重复充值提示；再次请求受限深度内容时按实际状态提示。不追加注册、赠分或全会话免费偏好问句。免费失败不能使用成功模板；已有基础信息直接回答而无新免费调用时，不声称执行了免费查询，对未完成深度内容用第二段。

**后续动作：** 当前列表及其连续翻页保持免费，保存原条件、公告对象和失败前实际交付进度，按第五节换算分页且遵守免费上限；不记为全会话免费偏好，不改账号默认配置。积分恢复后不静默将当前免费列表切回收费，按明确查询意图及费用授权衔接。免费查询也受限时如实说明，不自动切回收费。

## 五、登录与任务承接

### 用户愿意注册／登录

**触发条件：** 用户明确愿意注册／登录，或直接提供手机号且操作意图明确。

**固定回复模板：** 使用现有账号流程，首次主引导原样展示 `prepare.guidance`。

**允许替换项：** 不改写工具返回的主引导；工具失败按实际原因解释，不自行编造主引导。

**去重与例外：** 不重复询问登录意愿、不堆叠权益过渡；现有主引导保持工具原文。已提供的信息复用，不要求固定口令。

**后续动作：** 按账号及配置文档执行，保留对象、条件、进度和待办；未完成配置不声称已能收费续查。

### 登录及 Key 配置完成

**触发条件：** 本会话由游客接入，个人 Key 已配置并可加载；只取得 Key 不满足此条件。

**固定回复模板：** 默认积分续查时：

> **登录及 Key 配置已完成，后续查询默认使用账号积分。现在继续{待办任务}。**

原列表有明确免费要求时：

> **登录及 Key 配置已完成，原列表继续免费查询。现在继续{待办任务}。**

**允许替换项：** `{待办任务}` 为实际对象及操作，无待办时删除最后一句。直接提供 Key 接入时将“**登录及 Key 配置已完成**”替换为“**Key 配置已完成**”，不冒充短信登录。按工具事实另补余额及已确认到账的新用户赠分，老用户不称再次获赠。

**去重与例外：** 全程不扣积分等整体限制仍有效，受限任务先按第四节取得授权，不说整体已转积分。配置失败不能用成功文案。正常后续收费不逐次提示，不输出实际本次消耗数额，不为计算消耗查流水、比较余额或重放请求。

**后续动作：** 按实际授权续查原任务，不要求重述；默认游客免费不延续为登录后偏好，主动免费要求继续保留。

### 分页、限制与续查

沿用[连续追问](capabilities/follow-up-and-results.md)恢复原条件和对象。已知公告 ID 直接获取所需信息，不重新搜索或重放成功调用。修改筛选按既有规则形成新列表，不沿用旧条件下的位置偏移。

同条件切换免费／正式模式时，保留实际浏览进度，不能直接沿用不同页大小下的页码：

- 正式请求因积分不足失败不增加已交付位置；转免费从失败前实际交付位置继续，不跳过未成功交付结果。
- 免费转正式续查，继续每页 30 条，承接原进度；正式独立查询沿用原分页规则。
- 正式转免费，按已交付位置换算 30 条分页并跳过重叠记录。例如已连续交付前 100 条，从免费第 4 页跳过前 10 条接续。已取回但未展示的记录不算已交付，按目标模式字段规则继续处理。
- 切换后仍遵守免费前 10 页／300 条限制，不重置进度绕限。动态更新或排序差异使衔接不可靠时，说明结果变化，不承诺无遗漏，不自动重放历史页。

### 将意愿传给脚本

Agent 根据上述规则为本次操作选择 `--access-mode`，不让用户填写参数：`guest` 表示免费普通标讯请求，`authenticated` 表示正式请求，`auto` 按凭据和适用的列表状态选路。免费模式不适用于未开放能力，正式模式仍须加载 Key 并由服务端校验权益。

积分不足后的当前列表免费不代表用户主动选择全会话免费；`access_mode_source=explicit` 仅表示调用显式传入模式，不代表用户授权范围。会话偏好由 Agent 从可见对话承接并传入显式模式，不期待脚本自行推断用户授权。确认本会话后续列表免费时，新列表传 `guest`；确认后续使用积分时，当前任务、新搜索和旧列表续查均传 `authenticated`，覆盖旧免费选择。模式参数和保存的列表状态不扩大授权；仅同意本次收费后，后续仍按原费用要求执行。

请求字段、实际页大小及访问边界的处理见 API 文档。免费请求不能发送 `numPerPage`，总页数不能代替免费可访问页数；模式或分页响应不符合契约时按响应异常处理，不据此改收费或放宽限制。

### 失败与取消

**触发条件：** 请求失败、登录取消、配置未完成，或当前操作未获费用授权。

**固定回复模板：** 取消按第三节拒绝场景处理；失败依服务端或工具实际原因解释，没有通用成功／赠分文案。费用授权未满足按第四节对应场景说明，不新增平行问句。

**允许替换项：** 失败原因、已完成部分和仍待完成事项按实际返回组织，不推断账号无权益或免费额度耗尽。

**去重与例外：** 免费首次失败不触发成功提示，之后首次成功仍按第三节执行；失败、取消或配置未完成不能声称登录成功。正式鉴权错误与无效 Key 免费匿名成功区分，后者正常交付。

**后续动作：** 不继续未授权收费；已明确积分不足按第四节第五场景免费承接并说明；其他正式失败不自动转免费，免费鉴权失败不去掉 Key 重试或切收费。限流不查个人积分解释，网络或结算不明不自动重放收费请求；保留待办及已有成功结果。

提示去重、拒绝推广、待办、会话偏好和授权范围由 Agent 承接可见上下文，不为提示额外调用接口或建立引导状态文件。权益可用不保证某条公告一定有正文、附件或联系方式。

## 命令与复杂操作

模式由 Agent 选择并放在 `search/next/refine` 的 `--access-mode` 参数，不能放进 `query-json`。`preflight-complex --access-mode` 覆盖旧计划操作的 `access_mode`；逐项执行批准操作时同步该字段到 CLI，预检不代表费用授权。混合数据源按各项授权处理，不把 guest 用于采购意向、临期或企业能力。完整恢复字段和部分展示进度见[API 上下文](api.md#完整查询上下文)。
