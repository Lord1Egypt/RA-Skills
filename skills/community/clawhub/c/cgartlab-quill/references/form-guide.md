# 形式分流（不同文体怎样换衣服）

> 本文件在第二步定下文章类型后、第七步动笔前加载。用户明确指定的形式覆盖本文件的默认建议。
>
> 本文件只处理**形式差异**：开篇怎么进、正文怎么推进、结尾落在哪、这种形式最容易犯什么错。说话位置、材料门槛、句子级规则与禁用清单仍由 SKILL.md 与 `references/writing-craft.md` 决定——形式只换衣服，不换骨架。

## 形式由什么决定

第二步 Q1 选的文章类型决定默认形式；用户明确指定则覆盖：

| Q1 类型 | 默认形式 | 备选形式 |
|---------|---------|---------|
| 观点论述 | 观点与评论 | 行业解读、知乎回答 |
| 经验分享 | 个人叙事 | 评测、论坛长帖 |
| 技术解析 | 教程与方法 | 产品解读、知乎回答 |
| 趋势分析 | 新闻 / 产品 / 行业解读 | 观点与评论 |

## 通用原则

- **开篇尽快碰到事情**：无论哪种形式，第一段都要碰到对象、动作或结果。不要预告全文结构。
- **标题最后取**：从文章已经写实的位置里找，不从「文章该写什么」里找。
- **篇幅由材料决定**：材料不够就缩短，不靠形式撑长（见 SKILL.md 第一步半）。
- **形式服从作品对现实的承诺**：评测不能升级成亲历，解读不能伪装成独家洞察。

## 标题与开头（所有形式通用）

标题不是文采测试，是三件事：**读者看不看得懂、想不想点、点进来正文兑不兑现。**

- **先写完整，再压缩**：用正常中文写出这句要说的完整意思（涉及谁、哪件事、什么判断），再从这句话里删词。删完读者说不出在讲什么，就退回完整句重写——**不许先拼一句漂亮的短句，再让正文去圆**。
- **遮住上下文读一遍**：把标题、小标题、开篇第一句单独拎出来，假装没看过全文。陌生人知道对象和判断吗？**需要你补一句解释才成立的，改句子，不改解释。**
- **承诺 = 兑现**：标题里提出的问题、数字、反差，正文必须给出答案；兑现不了就换标题或改正文。
- **数字与反差要有来源**：标题里的数字，正文要能回指 `evidence.md` 的来源栏（第四步）。
- **长度先量作者基线，没语料就按默认上限**：中文标题默认 20 字以内（`style-and-bans.md` 的禁令）；作者旧稿的标题普遍更长时按基线放宽。感叹号、「震惊 / 必看」、「纯悬念式」一律不写；**quill 的标题不卖关子**——让陌生人知道在谈什么，比让人猜更有用。平台对标题字符数的硬要求，以该平台发布时显示的限制为准，本 skill 不内置各平台字数表。

**倒数第二件事：开头怎么进。** 五种入口里选一个（内部选择，不进交付物）：

| 入口 | 第一段写什么 |
|---|---|
| 结果入口 | 先说结果或代价，再回头讲过程 |
| 判断入口 | 先给判断，紧接着给依据 |
| 演示入口 | 先摆一件具体的东西，再说它怎么来 |
| 需求入口 | 先写读者眼下的处境，再给方案 |
| 事件入口 | 交代必要事实，继续讲尚未解决的问题（**不补造当事人动机**） |

- 方法、经验类内容的第一句，先让读者知道你凭什么讲。
- **开头是试用装，不是预告片**：标题负责吸引，开头直接往下讲，不再吊胃口；也永远别假设读者看过标题，开头要自己交代在讲什么。
- **下一句必须带新东西**：事实、步骤、证据或进展任一样。开头承诺了 A 却转去讲 B，或开头说完的铺垫在第二节又讲一遍，都算断。

**留人判据**（定完开头过一遍）：读者的问题原本就在他脑子里吗？开头有没有露出他熟悉的处境、后果或身份？有没有一个他愿意追下去、还没闭合的问题？三条都过不去 → **先看后文有没有更值钱的材料，把它提到开头**；没有就换钩子，**不许编场景**（来源硬规则见 `writing-craft.md`「开篇场景的来源」）。

**三条边界，防自己给自己放水：**

- **判开头只判开头。** 只读到读者做去留决定的位置（标题 + 首段 + 第一处小标题前），**后文一概不读**。后面写得再好，也不能让开头算过关——**后文的价值只能用来改开头，不能用来给开头加分**。判完写一句：如果只读到这里，读者会不会继续？
- **先查「被归成哪一类」。** 写两句话：读者看完标题和首段会以为这是哪类文章（专业讨论 / 个人故事 / 方法清单 / 情绪表达 / 利弊判断）；它实际是哪类。**两句不是同一类，改开头，不改正文**——被归错类的读者，后面写得再好也救不回来。
- **强断言先查对象。** 用尖锐判断开头时，补一句「这句话动到谁的什么」（钱、机会、关系、身份、眼下任务）。写不出对象，那不是好开头，是情绪表演；写得出来，把那个对象写进首段。

## 观点与评论（观点论述）

- 把争议落到具体事实、因果或价值选择，不停在立场表态。
- **先准确处理最强反方**，再给出作者当前相信的判断（见 writing-craft.md「判断要带着来路与边界」）。
- 没有个人经历时，不编「我亲眼见过」。作者怎样挑材料、解释因果、愿意为哪句话负责，本身就能形成声音。
- 忌：面面俱到，把每个方向都照顾一次。

## 个人叙事（经验分享）

- 先找最清楚的动作、物件、场景与一次意外。
- **保留当时的理解，也保留今天回头看的变化**——不要用今天的领悟倒灌成当时早已看透。
- 物件前后出现时，现实作用和后来含义都要成立。不要为了首尾呼应凭空造一只杯子、一张车票、一封旧信。
- 忌：把一次经历写成人生定律。

## 教程与方法（技术解析）

- 尽早说清三件事：做完会得到什么、需要什么条件、最容易卡在哪里。
- **步骤按依赖顺序排列**，每一步写动作和可见结果。
- 原理讲到读者能处理常见变化即可，不必讲全。
- 读者能少走一步弯路，教程就已经有价值——结尾不用谈认知、人生和时代。
- 忌：步骤顺序按作者理解的顺序而非执行顺序。

## 评测与商业稿（经验分享 / 技术解析）

- **亲测材料按真实任务出现**：为什么开始用，做了哪些步骤，哪里失败，结果怎样，适合谁。
- 只有官方资料时，写资料解读或测试计划，**不能升级成亲身体验**。
- 合作信息、公开事实、亲测和作者判断要能分辨。
- **限制写准，往往比一味夸赞更可信。**
- 忌：用官方参数代替真实使用。

## 新闻、产品与行业解读（趋势分析）

- 先写新发生了什么，再解释普通人为什么需要关心。
- **分开记录：已经开放 / 邀请测试 / 宣布即将提供 / 长期愿景 / 行业猜测**。标题只写到当前事实允许的位置——正文承认「尚未开放」，救不回一个已经写大的标题。
- 官方材料解决「发布方想让人怎样理解」；作者还要解决「一名普通读者实际会碰到什么」——补限制、成本、真实流程、受影响的人、发布方没有回答的问题。
- **行业影响落到具体角色**：谁购买，谁部署，谁付钱，谁多做一项工作，谁可能失去订单，出错以后谁负责，旧办法在哪一步最难受。名单列到能证明趋势就停——挑角色不同的两三个例子讲清关系，剩下的一句带过。
- 没有新增材料时，交一篇准确说明稿，不要伪装成独家洞察。
- 忌：把长期愿景写成已发生。

## 人物与历史长文

- 先整理时间线，**再分开检查先后、因果与动机**。资料只证明先后，不能用「于是」「因此」「这让他决定」偷偷补出因果；来源没有人物自述，不能替他写内心独白。
- 资料能证明人物作过选择，才写选择。资料只证明他离开一家公司、去了另一座城市，就写动作、当时条件和后来结果。
- **后来成功不能倒过来证明早年的每一步都有远见。** 毕业、搬家和换工作不会自动成为命运关口。
- 来源没有天气、神态、房间、对白和心理，就不要补。
- 张力来自真实压力：收入突然中断、一项技术始终跑不通、合作关系变化、手里的钱与时间不够、一个确有记录的决定带来后果。
- 忌：把履历当人物——学校、职位、城市都写了，人物仍然没有动作。

## 知乎回答

**先接住题目。** 读者问「为什么」，正文就尽早给出一种解释；问「什么体验」，正文要有经历、观察，或明确说明自己从哪里知道。答案简单就直接说；答案复杂就从最容易被忽略的一处进入。

**动力来自「为什么」和「你怎么知道」**，不是来自标题党悬念。

推荐结构——**先回答，后解释，最后给动作**：

1. 第一句就把判断落地，不要让读者等三段才知道你的答案。
2. 用一段经历或一组材料说明凭什么这么说。
3. 最后给一个能带走的动作或建议。

> 例（结构示范，内容仅供参考）：
>
> 会后悔，而且通常不是买错那一下。
>
> 我在门店待过一阵，见人买相机。进门都说要记录生活，预算咬得很死；试完一圈，最后往往多花三四千。第一个月拍得勤，第二个月嫌沉，半年后只在旅游时背一次。
>
> 真难受的在后头。器材放着不用，卖掉觉得亏，偶尔拿出来拍两张，还要证明自己当初没冲动。钱花完了，账一直没结。
>
> 所以给朋友的建议很简单：先租一周，背着它正常上下班。一周后还愿意带，再买。

**没有亲历时怎么办**——这几乎是知乎回答的常态。可以依靠事实、可核验的常见流程和推理写作，但**不能假装自己见过**。

- 选一个普通角色，把他从开始到结果的动作走一遍，并**明确这是常见情形**，不能配上伪造的精确经历。
- **只抓最有把握的一两个原因。回答不必包办整个问题**——一块讲透，比六类原因各说三句强。
- 一段抽象解释之后，尽快落到一次报价、一份作品、一项支出、一次失败或一个决定。

**其他**

- 不要先感谢邀请，不要预告「我将从三个方面回答」，不要把答案改造成公众号文章以后再贴回来。
- 专业问题讲到读者能使用；个人问题说清经验适用于谁，别把一次经历写成人生定律。
- 忌：先摆一堆结论再补理由（读者要的是答案，不是摘要）。

## 论坛长帖

- 交代为什么开这个帖，随后顺着时间、调查或亲历过程写。
- 允许插话、补充、回头纠正和阶段性停顿。
- 真实经历保留当时不知道的部分。
- 忌：用「有人看我就继续」制造假互动；伪造「更新」「楼主回来填坑」。

## 公众号与博客长文

- 正文可以比论坛帖更紧凑，仍要保留说话者。
- **长文靠材料、解释和过程撑起来。最近一千字只让同一个观点更响 → 删掉或继续研究。**
- 小标题用于定位，不用于给每一段提前写结论。
- 各部分不必等长。
- 忌：把帖子改造成公众号文章时只换排版不换结构。

## 口播、播客与演讲

- **写给耳朵**：新名词第一次说全，代词要能找到对象，数字只留听众必须记住的。
- 一句话一口气说不完就拆开。
- 开头给坐标与眼前问题，中间顺着听众会问的下一句往下说。
- **完整读出声并计时**。纸面上顺、嘴里拗，仍然要改。

## 短答与长文的分流

- 可以先很短，也可以写成长文。**quill 的七文件流程对短回答是过重的**——短答直接用写作规则写，不必建项目文件夹。
- 到了长文规模（材料能支撑多节、需要证据链、还要跑反驳与验证）才值得走完整流程。
- 拿不准时按「删掉这节会不会缺一块」判断，而不是按字数判断。

## 短文与社交内容

- 只留一个主要任务：交代消息、讲一个观察、给一个判断、留一个细节，或让人物完成一次小变化。
- 第一句尽快碰到对象、动作或结果。不必强行反转。
- **把长文改短时重新取材和排序，不沿着原文一路删字。**
