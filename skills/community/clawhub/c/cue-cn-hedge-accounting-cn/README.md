# 套期会计·逐条挂源

给一份财报或公告，把**套期保值与套期会计处理**读成一张**每条都能回到原句**的登记表：套期保值概况、套期关系与指定、套期工具与被套期项目、有效性评价与无效部分、现金流量套期储备。

套期会计是附注里最容易被读反的一块：签了衍生品不等于做了套期，做了套期不等于指定成了某一类，评价了有效性不等于给出了结论。公允价值套期、现金流量套期、境外经营净投资套期三类的会计去向各不相同，套期储备与套期损益更是两条不能互抵的腿。本件逐条登记披露原话，判断留给人。

套期类型只认披露指定的那一类，不按合约形态推断；有效性结论、无效部分的金额与去向照抄原句；储备腿与损益腿分列，不轧净额。

本件不判套保策略是否合理、不估值衍生品、不测算敞口，不给评级与目标价。

## 一、零依赖三分钟上手

只装 Python 3，不给任何数据文件，也能跑出一份完整合规的成品，看它长什么样、判据怎么打：

```bash
python3 scripts/check_hedge_accounting.py --demo
```

把这份样例存下来再跑一遍机检——它会照七节形制、三元组与红线逐条判，应当零发条：

```bash
python3 scripts/check_hedge_accounting.py --demo > 样例套期稿.md
python3 scripts/check_hedge_accounting.py 样例套期稿.md   # 打印「—— 机检：0 条发条」，退 0
```

接着换成你自己那份稿子：

```bash
python3 scripts/check_hedge_accounting.py 你的套期稿.md
```

退码语义：`0` 五道全过｜`1` 有发条（逐条打印 `码 行号 说明`）｜`2` 缺参数（没给稿子路径，也没给 `--demo`／`--selftest`）｜`3` 读不到文件或空稿；另有单独一档：零发条但某道判据跑不出结论时同样退 `3`（当前五道全已落字，正常读数不触发）。

拿不到成品时，从原文开始的三步：

1. **定主体与报告期**，拿到年报或半年报原文（附注「套期会计」「衍生金融工具」「其他综合收益」三处）。
2. **每节抄事实，连原句一起抄**：一条 = 一行，行末挂 `「原句」〔锚：页/表〕[S#]`；披露没写的就写 `未取到：项名`，不留空、不借常识补。
3. **跑一遍自检**，红一条改一条：

```bash
python3 scripts/check_hedge_accounting.py --selftest   # 10 档内置夹具自检
```

## 二、五道机检在管什么

| 码 | 名称 | 判什么 | 最常拦住的情况 | 现状 |
|---|---|---|---|---|
| `HA-STRUCT` | 形制 | 头部四件自标逐字在位、`主体：`／`报告期：` 行在场非空、七节齐且按序、前五节各至少一条发现行、节内只许 `- ` 行 | 把 `主体：` 写成 `- 主体：`；某节只有散文没有发现行；节序被调换 | 已落字 |
| `HA-QUOTE` | 原句与锚 | 发现行以「」原句＋〔锚：…〕＋`[S#]` 收尾且三元组落在行末；来源行带可点 URL 与检索日；引用的编号须已登记 | 只写「利率互换」没抄原句；正文引用了 `[S3]` 而来源节没有这一号 | 已落字 |
| `HA-TYPE` | 类型只认原句 | 登记值写了某类套期而同行「」原句没有该类型词即发；同一行登记两个类型而原句只写一个也发；前五节一条类型都没登记，发一次 | 原句只说「签订利率互换合约」，登记值写成「现金流量套期」 | 已落字 |
| `HA-EFFECT` | 有效性与无效部分只认原句 | 结论词（高度有效／基本有效／无效）、方法名（定性评价／定量评价／回归分析／美元偏移法）、无效部分金额与去向（当期损益／其他综合收益）出现在登记值里而不在原句里即发 | 原句只写「按季评价有效性」，登记值写成「高度有效」；无效部分金额自己按比例算出来的 | 已落字 |
| `HA-LINE` | 红线 | 储备腿与损益腿不得轧成净额（净额／合计／轧差／相抵／抵减）；无效部分不得「暂挂／待摊／递延确认」；正文「未取到 X」与第六节点名两向对账；零缺口须写 `未取到：无`；「不适用」「无此项」「无需披露」一律发 | 把现金流量套期储备与套期损益写成一行「净额」；正文写了未取到而第六节没列 | 已落字 |

五道现读全已落字，`--selftest` 十档内置夹具的末行读数是 `自测档数=10｜不合=0｜不可判=0`（含好样零发条一档，形制／锚／类型／有效性／红线各钉一档，以及类型、有效性、红线三档反证与零缺口一档——反证档专验「词只出现在「」引文里时不该发」）。

## 三、三条红线（这件的立身之本）

1. **类型只认披露指定的那一类。** 签了利率互换不等于现金流量套期。原句没写指定为何类，正确写法是套期类型未取到，而不是按合约形态替披露归类。
2. **有效性结论与无效部分只认原句。** 「高度有效」是披露的结论，不是本件算出来的；无效部分的金额与去向（当期损益／其他综合收益）两样都要原句，原句只说「存在无效部分」没给数的，金额写未取到。
3. **储备腿与损益腿分列，不轧账。** 计入其他综合收益的现金流量套期储备与计入当期损益的套期损益是两条腿，一行一个数、各挂各的原句；写成「净额」「合计」「轧差」「相抵」即发。无效部分不得「暂挂」「待摊」「递延确认」——那是把该确认的挪到以后。

## 四、数据通道

发现先行，匿名取 live 目录，拿到 `routing` 后再连接发 `tools/list`，以现场返回为准，不硬编码工具名与工具数：

```bash
curl -sS https://cuecue.cn/api/mcp-catalog -o /tmp/mcp-catalog.json
python3 -c "import json;d=json.load(open('/tmp/mcp-catalog.json'));print(d.get('routing') or d)"
# 拿到 routing 后，带 token 发 tools/list：
curl -sS -X POST "$ROUTING_URL" -H "Authorization: Bearer $CUE_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

- **原文腿**：年报附注·套期会计、衍生金融工具、套期保值公告与指定文件的原文走数据腿；该域是否开放、是否实时，以 catalog 返回为准，本件不承诺。
- **正文腿**：附注常夹在几百页 PDF 里（套期关系表、有效性评价表、其他综合收益明细），长附件与扫描件交 `cue-omni-reader` 解析——先取大纲，再按节取用；计费与可用性以服务端返回为准。
- **深研**：`cue-research` 是独立入口（自带运行脚本），凭据同一把 key。
- 配置页只给指针、不复述开通步骤：数据腿 <https://cuecue.cn/hub/mcp>；解析腿 <https://cuecue.cn/hub/omni-reader>；取 key <https://cuecue.cn/hub/api-key>。

不装通道也能跑：只拿用户直供的附注截图，五节骨架照样出，代价是看不到交易所原文那一路、套期关系表与储备明细多半缺页，只能登记截图里那几行，证据密度降为单份材料且没有出处可回查。

本件不发请求、不代付费，消耗以服务端返回为准。

## 五、和另外几枚包怎么分

| 你手上是 | 用哪枚 |
|---|---|
| 套期类型与指定、工具与项目、有效性与无效部分、现金流量套期储备 | **本件** |
| 外币报表折算差额、折算汇率与折算方法 | `cn-foreign-currency-translation-cn` |
| 可转债的转股价、赎回与回售条款 | `convertible-bond-terms-cn` |
| 长期股权投资的持股与权益法核算 | `cn-long-term-equity-investment-cn` |
| 债务重组的方式与重组损益 | `cn-debt-restructuring-cn` |
| 会计政策变更的性质、原因与影响金额 | `cn-accounting-policy-change-cn` |

本件只管**套期会计处理这一块**：折算差额怎么来的归 `cn-foreign-currency-translation-cn`，可转债条款归 `convertible-bond-terms-cn`；境外经营净投资套期，本件只挂「指定为该类套期」的原句与储备腿，被投资单位本身归 `cn-long-term-equity-investment-cn`。同一家公司既有可转债又有套期时，两件各管各的节，不互相代填。
