# Машинный запуск и вывод: подробности

## Как узнать команду

Открывайте только команды, нужные для задачи.
**`max commands search messages --json`** описывает одну команду;
**`max commands messages --json`** — всю группу. Оба ответа содержат аргументы, флаги,
глобальные флаги и коды выхода. Для короткой справки — `max <команда> --help`.
Слова после `commands` задают один путь, а не список групп: разные группы смотрите отдельными
вызовами. **`max commands --json`** возвращает всё дерево для общего обзора;
не читайте его целиком перед каждой задачей. `max commands info messages list --json` показывает схемы и эффекты
одной команды. `effects.remote: "write"` обозначает запись в MAX, а один `effects.local: "write"` — запись только
на этой машине. `commands --json` не подключается к аккаунту. Его поле `contract` —
версия общего JSON-контракта; она меняется только при несовместимом изменении полей ответа, а не
при обновлении пакета, поэтому проверяйте это поле, а не весь вывод целиком.

## Флаги для агента

Используйте `--json --no-input` для работы без вопросов; секреты передавайте явно через pipe.
`--json=id,text` оставляет эти поля каждого элемента списка вместе со страницей и полнотой. Для id
достаточно `--json=id`. Точка выбирает вложенное поле: `--json=ref,text,reply_to.text`. `--max-output-bytes` и
`--max-input-bytes` задают byte budgets; одноразовые действия имеют срок 30 секунд, меняемый через `--timeout`.
Перед чувствительной записью `--dry-run` проверяет форму запроса и права до действия;
общий preview не подключается к мессенджеру, не резервирует запись и оставляет цели непроверенными.
Полные правила — [контракт CLI](https://github.com/WireCatLabs/max-cli/blob/main/docs/cli-contract.md).

`-v` и `-vv` добавляют подробности в вывод для человека. Версия — `max -V`. Строки о каждом
запросе к MAX — `--trace`, в stderr.

## Форма ответа

**Любой список — объект**, а не массив: `{ "items": [...], "page": { "limit": 20, "has_more": true }, "meta": {…} }`,
у бота тоже; одна вещь — `{ "item": {…} }`. Ключи — snake_case. Следующую страницу называет шаг `page.next`
в `next` (его `cursor` или `page`), у бота тоже; чего в ответе нет — `missing`. У списка без страниц
`page.has_more` — `false`. Ошибка, завершающая команду, уходит в stderr, stdout при ней пуст.

## Неполные ответы

Частичные чтения и загрузки могут завершиться кодом `0`: проверьте `missing`, `next`, а у загрузок — `complete`,
`batch.failed` и `issue`; JSONL частичной загрузки добавляет `batch_summary`. Успешная часть сохраняется, повторяйте
только незавершённое после указанной паузы.

`--jsonl` — по объекту на строку, удобно для `jq`; последняя строка — `{"type": "end", …}` с `page`. Отчёты `stats`
`--jsonl` не принимают.

## Коды выхода полностью

`0` — успех, `2` — неверный ввод, `4` — нет входа, `5` — профилю это действие не разрешено (`permissions`; ошибка
называет запрещённый ресурс или действие — не обходить), `6` — не найдено, `7` — чата нет в списке разрешённых,
`8` — лимит: отправок за час, или MAX отказал во входе из-за частых попыток (тогда **не повторять**: профиль сам
не входит до времени из ошибки; сказать владельцу; `flood clear` — обслуживание владельца после окончания лимита,
не обход для агента), `14` — **неизвестно, ушло ли сообщение**
([отправка](sending.md#код-14)).

## Имя профиля

Имя профиля — латиница, цифры, точка, дефис и подчёркивание: оно становится именем файла и записью в ключнице.
Имя в другом алфавите отвергается **как имя** (код `2`), и это не то же самое, что профиль, в который никто
не входил (код `4`). Флага `--profile` нет; то же, что первое слово, делает переменная `MAX_PROFILE`.

## `--offline`

`--offline` отвечает из локальной копии и не подключается. Если там ничего нет — ошибка.
Отправка с `--offline` — всегда отказ.
