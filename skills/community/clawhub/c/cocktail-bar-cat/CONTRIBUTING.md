# 一起补全吧台事实摘要 · MIT-0专用版共创说明

> 适用于ClawHub专用v2.7.4。只收贡献者有权以MIT-0授权的原创事实摘要、独立方法分析与原创代码；不收第三方原文、逐句译文、消费者评论、权利不清的照片或本机私有业务。本地副本不代表远端已发布。

## 一、静态副本不会自动更新

`cocktail-bar-cat` 不是在线服务：本地增删只在自己机器上，不自动回传/同步；`bars.py` 只读本地JSON，不联网抓新酒单。

可追溯路径：**显式贡献并确认MIT-0授权 → 维护者核来源与原创边界 → 授权合并专用副本 → 本版门禁与中文说明 → 另行授权发布 → 使用者手动更新**。时效可以运行时变旧，资料只能通过显式补录变新。

本机私有目录不覆盖，更新先备份。公开贡献绝不包含客户偏好、过敏、联系方式、消费、销量、库存、采购合同价或经营记录；仅匿名化姓名不够。

## 二、优先收哪些贡献

| 优先级 | 内容 | 用途 |
|--------|------|------|
| 1 | 带日期的官方酒单来源链接，以及贡献者独立整理的事实摘要 | 新一期 `menu_snapshots` 的事实记录，不分发原酒单作品 |
| 2 | 酒名、风味、公开材料清单的独立事实整理 | 非官方结构分析；未公开比例明确留空 |
| 3 | 自行抽象的主题/功能结构/研发方法 | `menu_concepts`，不复制整套原命名、顺序或叙事 |
| 4 | 有来源的下架、换址、闭店事实纠错 | 对在售判断作提醒；旧快照留事实对照 |

不投稿消费者评论或其改写版；不评分、不排名、不冒充实饮。带日期与出处的**公开消费酒单价格事实**可登记用于核查，不是采购价、合成售价或当前市场行情；无来源不造数字。

## 三、提交模板

投稿需审校和发版，不会自动生效。不确定写不清楚。原页面或照片只给来源链接供核查，**不将第三方文本/照片作为随包附件**；资料独立整理成摘要。自行拍摄的图片也不默认收录，本专用包维持无第三方媒体边界。

```text
【店名】公开店名
【城市】城市文字信息
【酒单日期】来源实际日期；不确定写未知
【日期依据】发布日/有凭据的酒单日期
【出处】可公开来源链接，仅供核查原作
【是否官方/换季】是/否/不清楚
【独立摘要】自行概括材料事实、风味功能及结构，不抄原文或整单顺序
【公开价格】可选，来源实际标价、日期与出处；不是私有业务
【状态】有依据的下架/换季/闭店提醒
【署名】用户确认的昵称或匿名
【授权确认】本次贡献为本人有权授权的原创整理/代码，同意按MIT-0发布；不含第三方原文、译文、评论或媒体
```

### 可选JSON模板

以下为**占位示意**；核日期、唯一来源ID与实际字段后才能合并，不是可直接入库的数据。无公开价格依据就省略价格。标题仅用必要来源识别信息，主题/说明必须独立表达。

```json
{
  "source": {
    "id": "new-source-id",
    "title": "用于定位的来源标题",
    "url": "来源实际公开链接",
    "date": "YYYY-MM-DD",
    "type": "官方酒单来源链接",
    "official": false,
    "contributor": "用户确认的昵称或匿名"
  },
  "menu_snapshot": {
    "as_of": "YYYY-MM-DD",
    "label": "自行拟定的事实快照标识",
    "theme": "自行概括的功能结构",
    "drinks": ["公开酒名A"],
    "source_ids": ["new-source-id"],
    "freshness": "unknown"
  },
  "signatures": [
    {
      "bar": "公开店名",
      "city": "城市",
      "name": "公开酒名A",
      "flavor": "原创风味事实摘要",
      "menu_snapshot": "YYYY-MM-DD",
      "status": "unknown",
      "confidence": "low",
      "verified": false,
      "replica": {"type": "非官方结构试做（独立方案）"}
    }
  ]
}
```

静态 `freshness/status` 仅建档基线，按运行日期重算。占位日期不得通过门禁，未知资料不得作为当前在售推荐；酒名列表仅为事实索引，不复现整张原酒单的命名编排。

## 四、审校八条

1. **日期优先**：无日期为 `unknown`；只有年份按该年1月1日，范围取最大年份1月1日保守估计。
2. **出处可查**：链接/平台/发布日期/是否官方明确，登记 `sources`；署名由用户确认，不强制实名。
3. **比例未公开不伪造**：有材料事实才按经典结构提出独立试做起点，非店家配方；无材料不编。
4. **不冒充官方原方**：`replica` 明确非官方独立方案、`verified=false`；来源有完整配方也不把其文本搬入包内或声称获店家认证。
5. **仅概念**：`concept_only=true` 只给抽象方法，不编材料比例或硬凑锚点。
6. **换季/无酒单**：`menu_status=rotating/no_menu`，只给独立方法与当日核查提醒。
7. **旧期留事实**：新一期追加、旧期归档；旧第三方引文/评论/媒体不因归档而保留。
8. **原创与安全**：不评论评分、不抄叙事；不点火出品、不使用雄黄粉、不写饮酒治病或灌醉话术，不用无证名人引语。

另核隐私、食品安全、来源定位与MIT-0授权：不含客户偏好、过敏、联系方式或经营记录；预处理标安全条件、甜度全路线执行。**事实核查等级与发行表达形式解耦**，已核事实不是复制原作品的许可。

## 五、维护者合并与发版流程

```text
1. 收原创摘要/代码与明确MIT-0授权 → 核日期、来源、原创边界与隐私
2. 先备份，在独立ClawHub副本追加sources与事实快照；不覆盖原版
3. 有公开材料事实才补signatures，写时效/置信度/非官方独立方案
4. 运行python3 scripts/audit.py及相关回归；记真实结果，修复失败

6. 用--as-of选足够远的日期检查变老，不用固定年份保证所有快照过期
7. 以RELEASE_NOTES中文文案同步SKILL/README/LISTING及技术版本记录
8. 核21个JSON、维护manifest、scripts、references、LICENSE与说明齐全；无第三方原文/译文/评论/媒体或本机私有资料
9. 实际验证后打包；只有另行明确授权才发布远端/市场，使用者手动更新
```

投稿不等于生效，打包不等于发布。专用v2.7.4验证结果以实际平台回读为准；旧17/31项测试不作为新结果，不自动上传、上线或承诺审核通过。
