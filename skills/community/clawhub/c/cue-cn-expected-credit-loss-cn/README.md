# 预期信用损失·三阶段与两条计提路径逐条挂源

给一份年报或半年报，把附注里**预期信用损失（金融工具减值准备计提方法）那一段**读成一张**每个数都能回到附注原句**的登记表：预期信用损失概况、三阶段划分、组合计提、单项计提、前瞻性信息与账龄依据。

这一段是财报里最容易被二手转述坏的地方：损失准备提了多少、本期计提转回核销各多少、三阶段怎么分的、组合与单项两条路各提多少、前瞻性信息用了哪几种情形。**数照抄附注原句，计提比例与滚动轧差由机检现算**。本件只做前一半：把数抄对、把阶段与组合标签按附注写对、把原句挂上。

不重算损失率、不判断计提是否充分、不按逾期天数自己推阶段、不给评级目标价。

## 一、零依赖三分钟上手

只装 Python 3，不给任何数据文件，也能跑出一份完整合规的成品，看它长什么样、判据怎么打：

```bash
python3 scripts/check_expected_credit_loss.py --demo
```

把这份样例存下来再跑一遍机检——它会照七节形制、三元组、三阶段、计提比例与滚动轧差、四条红线逐条判：

```bash
python3 scripts/check_expected_credit_loss.py --demo > 样例预期信用损失稿.md
python3 scripts/check_expected_credit_loss.py 样例预期信用损失稿.md
```

接着换成你自己那份稿子：

```bash
python3 scripts/check_expected_credit_loss.py 你的预期信用损失稿.md
```

退码语义：`0` 五道全过｜`1` 有发条（逐条打印 `码 行号 说明`）｜`2` 用法错（没给稿子路径，也没给 `--demo`／`--selftest`）｜`3` 读不到文件或空稿。零发条但有判据尚未落字时同样退 3——rc=0 只留给「五道全过」，没跑的道不能算过；报告里那几道计「不可判」，**不等于合规**。本件五道已全部落字，这条当前不触发（好样单跑退 0），留着是为了将来某道回退成空壳时不把「没跑」读成「过」。

拿不到成品时，从原文开始的三步：

1. **定主体与报告期**，拿到年报或半年报附注里预期信用损失／金融工具减值那一段（概况表、三阶段表、组合计提表、单项计提明细、前瞻性信息说明）。
2. **每节抄事实，连原句一起抄**：一条 = 一行，行首写项名、紧跟 `〔口径：本期末〕`／`〔阶段：第三阶段〕`／`〔组合：账龄组合〕`／`〔对象：甲客户〕`／`〔情形：基准情形〕`，再写数字与单位，行末挂 `「原句」〔锚：页/表〕[S#]`；附注里没有的数就写 `未取到：项名`，不留空、不借「预期信用损失本来就是这么分的」这类常识补。
3. **跑一遍自检**，红一条改一条：

```bash
python3 scripts/check_expected_credit_loss.py --selftest   # 内置夹具自检（档数与结果以末行现报为准）
```

三档一起跑（自测→好样→坏样，坏样注入必先断言落地）：

```bash
bash scripts/fixtures/run_fixtures.sh
```

## 二、五道机检在管什么

现状以脚本里 `UNIMPLEMENTED` 的现值为准：五道**全部已落字**，`UNIMPLEMENTED` 为空——报告里那一道「不可判」的计数当前为 0。将来某道若回退成空壳（重新登记进 `UNIMPLEMENTED`），它会调用即抛、由机检收进「不可判」，既不判也不放行，单稿退 3；`rc=0` 只留给「五道全过」。

| 码 | 名称 | 判什么 | 最常拦住的情况 | 现状 |
|---|---|---|---|---|
| `ECL-STRUCT` | 形制 | 头部三件自标（AI 整理初稿／请回原文核对／不构成投资建议）逐字在位、七节齐且按序；认不出的节标题与多出同名节记 stray 逐条发。只判「形」，不判内容；**不判** `主体：`／`报告期：` | 某节名改了个字就整节认不出；同一节写了两次 | 已落字 |
| `ECL-QUOTE` | 原句与锚 | 五节内容节每个数字行须挂一对 `「」` 原句（≥8 字，不能只有数字／标点）＋〔锚：…〕＋`[S#]`；例外只有三形：`未取到：` 行、`[待人工]` 行、`〔自算〕` 行。来源行须合 `- [S#] 标题 \| http(s) URL \| 检索日 YYYY-MM-DD`，正文引用与来源登记**两向**都要对得上，来源节一条合规行都没有则单独发一条。**不核对引号里的数与行首是否同一**（那是 `ECL-ROLL` 的活——分开判是为了让一支坏样只红一道） | 只写「损失准备 3,456.00 万元」没抄原句；检索日写成 `2026/03/20` | 已落字 |
| `ECL-STAGE` | 三阶段只认原句 | 「三阶段划分」节里行首标了 `〔阶段：第N阶段〕` 的行，原句必须含**同一个**阶段词；缺〔锚〕`[S#]` 也发；同一阶段在同一节里报了损失准备的**两个不同数** ⇒ 发。阶段归属只认行首标签，原句里提到别的阶段词不算归属，**不按逾期天数推、不拿上期结构补** | 行首标第三阶段、抄来的原句写的是第一阶段；第一阶段两行数打架 | 已落字 |
| `ECL-ROLL` | 两条计提路径逐数比对 | 「组合计提」「单项计提」两节，按 `〔组合：…〕`／`〔对象：…〕` 分组：① `损失准备 / 账面余额` 与披露计提比例差 > 0.05 个百分点 ⇒ 发；② 滚动式 `期初 ＋ 本期计提 － 本期转回 － 本期核销 ＝ 期末` 差 > 0.01 万元 ⇒ 发，消息记 `重算=X 披露=Y`。**任一项缺失 ⇒ 整条比对跳过**，不猜、不按 0 算；分组名缺失的行不参与同组比对（归属不明） | 计提比例抄成相邻组合那一行的；期末余额抄错一位 | 已落字 |
| `ECL-LINE` | 红线 | ① 把损失准备说成已发生损失（已确定收不回／坏账损失已发生）② 给出「计提充分／不足」的判断 ③ 用轧净额冒充账面余额 ④ 给评级、目标价、买卖建议。另加：组合计提与单项计提**缺任何一节** ⇒ 发条（两条计提路径必须各占一节）。「口径与未取到」与「来源」两节整节豁免 | 把「预期」写成「已确定收不回」；顺手写一句「计提充分」 | 已落字 |

`--selftest` 末行自报 `自测档数=N｜不合=0｜不可判=N`，**N 以现跑为准，本文件不写死数字**——写死的数字必然落后于代码。夹具覆盖上面五道码，每支坏样只红自己那一道（「删掉单项计提整节」那一档按设计同时红 `ECL-STRUCT` 与 `ECL-LINE`，专门钉住双红不被并成单码）；另有一支**反证档**：往「口径与未取到」里写红线词，期望零发条，证明该节整节豁免真的生效。

## 三、七节各登记什么

| 节 | 登记什么 | 最常犯的错 |
|---|---|---|
| 预期信用损失概况 | 损失准备期末余额、本期计提、本期转回、本期核销；`〔口径：本期末〕`／`〔口径：本期〕` | 只写余额不写本期三件，滚动式就无从核 |
| 三阶段划分 | 三个阶段各自的损失准备 `〔阶段：第N阶段〕`，再加一行阶段划分依据 | 按逾期天数自己推阶段；原句里没有那个阶段词 |
| 组合计提 | 每个组合的损失准备、账面余额、计提比例、期初／本期计提／转回／核销／期末，`〔组合：…〕` | 组合名不写，归属不明，该行不参与比对 |
| 单项计提 | 每个对象的账面余额、损失准备、计提比例、本期计提，`〔对象：…〕` | 只写「单项计提合计」，不按对象分行 |
| 前瞻性信息与账龄依据 | 各情形权重（`〔情形：基准情形〕` 等）、组合划分依据 | 权重不写，只写「考虑了前瞻性信息」 |
| 口径与未取到 | 取法口径 ＋ 缺口逐项点名；零缺口写 `未取到：无` | 正文写了未取到而本节没列，或反之 |
| 来源 | 每条 `[S#]` 一行：`- [S#] 标题 \| URL \| 检索日 YYYY-MM-DD` | 引用了 `[S#]` 却没有登记行；检索日写成斜杠式 |

## 四、四条红线

1. **不把预期损失说成已发生损失**：预期信用损失是按概率加权的前瞻估计，不是「已确定收不回」「坏账损失已发生」。
2. **不判断计提是否充分**：「计提充分」「计提不足」「计提偏低／偏高」一律不出现在内容节，够不够交 `[待人工]`。
3. **不拿轧净额冒充账面余额**：账面余额是总额口径；「按净额列示」「抵减后的余额」不得顶替账面余额。
4. **不给评级、目标价、买卖建议**。

另有三条由机检强制：阶段归属不许脱离原句（`ECL-STAGE`）、计提比例与滚动轧差必须对得上（`ECL-ROLL`）、两条计提路径必须各占一节（`ECL-LINE`）。「口径与未取到」整节豁免——那一节按设计就要写「本件不判断计提是否充分」，不豁免会自己咬自己。

## 五、与相邻件的边界

| 相邻件 | 它管什么 | 本件不做什么 |
|---|---|---|
| `cn-working-capital-quality` | 存货／应收账款／合同资产的余额与账龄、计提与转回，五节、**不分阶段** | 本件只登记减值准备计提方法那一段的三阶段、组合与单项两条路、前瞻性信息；两件读的是同一份财报的不同段落 |

| `cn-key-financial-data-cn` | 第一节主要会计数据与财务指标表的逐行登记 | 本件读的是附注，不是第一节那张表 |

## 六、数据通道

- 发现先行：匿名取 live 域清单与 `routing`，**不硬编码工具名与工具数**；连上之后带 `Authorization: Bearer $CUE_API_KEY` 发 `tools/list`，以现场返回为准：

  ```bash
  # ① 匿名取域清单与 routing
  curl -sS https://cuecue.cn/api/mcp-catalog -o /tmp/mcp-catalog.json
  python3 -c "import json;d=json.load(open('/tmp/mcp-catalog.json'));print(d)"

  # ② 带凭据握手取工具表
  curl -sS -X POST "$MCP_ENDPOINT" \
    -H "Authorization: Bearer $CUE_API_KEY" \
    -H 'Content-Type: application/json' \
    -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | head -c 2000
  ```

- 原文腿：年报附注里预期信用损失／金融工具减值那一段在数据腿上，本件不承诺该域开放，也不承诺实时性；
- 正文腿：这一段常是横排大表，截图与扫描件交 `cue-omni-reader`（大纲→按节取用，计费以服务端返回为准）；
- 通道配置页只给指针：<https://cuecue.cn/hub/mcp> ／ <https://cuecue.cn/hub/omni-reader> ／ <https://cuecue.cn/hub/api-key>。
