# 受限资产·抵押质押冻结逐项登记与可动用资金缺口

产出稿的头部就照下面这几行起（三件自标「AI 整理初稿」「请回原文核对」「不构成投资建议」逐字在位；`主体：`／`报告期：` 是**行首裸行**，不带 `- ` 前缀）。判断位一律写成 `[待人工]`：

```
# 示例材料（600000.SH）受限资产登记稿

AI 整理初稿 ｜ 请回原文核对 ｜ 不构成投资建议
主体：示例材料（600000.SH）
报告期：2025 年年度报告·附注·所有权或使用权受到限制的资产
```

**定位**：给一份年报或半年报，把附注里**「所有权或使用权受到限制的资产」那一张表**读成一张**每个数都能回到附注原句**的登记表——受限资产合计与占总资产比例、货币资金按受限形态分组、非货币资产按资产类别分组、受限原因与期限、与负债的对应，五块逐条挂原句与锚。**合计与分项、受限比例由机检现算**，本件只负责把数抄对、把受限形态与类别按附注写对、把原句挂上。

这张表常被跳过，但它是**资产质量与偿债能力的缺口所在**：账面 100 亿货币资金，其中 60 亿是银行承兑保证金，能动的只有 40 亿。本件把「动不了的那部分」逐项点清，**不替你把受限金额减掉算出可动用资金**——那一步要口径判断，交 `[待人工]`。

切割说清楚：`cn-share-pledge-tracker` 跟踪**股东手里股票**的质押与解押，本件登记的是**公司账上资产**的受限；`cn-contingency-commitment-cn` 管或有事项与承诺（含对外担保），登记的是**担保这件事**，本件登记的是**被担保／被抵押的资产那一侧**；`cn-working-capital-quality` 管存货与应收的余额与账龄，**不问受限**。三件读同一份财报的不同段落。

### 是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 五块逐条登记（受限资产概况／货币资金受限／非货币资产受限／受限原因与期限／与负债的对应），缺项也占一行点名 | 够不够还债、资产质量好不好、明年会不会解押（一律 `[待人工]`） |
| 每个数字带 `〔口径：本期末〕`／`〔形态：…〕`／`〔类别：…〕`／`〔对象：…〕` 标签 | 按表格位置认项（第三行就是固定资产那种） |
| 合计现算：受限资产合计 vs 各分项之和，差 > 0.01 万元即发条 | 拿 0 补一个缺失分项去让合计成立 |
| 比例现算：`受限金额 / 资产总额` 与披露比例差 > 0.05 个百分点即发条；> 100% 单独发 | 自己换分母、自己四舍五入到对得上 |
| 每个数挂「」原句＋〔锚：…〕＋`[S#]` 三元组，来源行两向对应 | 只写数字不抄原句，事后补一句「据年报附注」 |
| 数据通道＝live catalog 现值（见「数据通道」那一节） | 承诺任何未开放域、实时性或固定工具清单 |

### 触发场景

「受限资产一共多少、占总资产几个点」「货币资金里有多少是保证金和冻结存款、能动的有多少」「哪些固定资产和存货被抵押质押了、抵押给谁」「受限到什么时候解除」「这些受限资产对应多少借款」。输入形态＝**年报或半年报附注里「所有权或使用权受到限制的资产」那一段**（截图／PDF／解析回来的表格文本）。

## 七节各登记什么

节名必须逐字照这几个（`## ` 起节，节名后面紧跟字母或数字就认不出，会被记成野节）：

| 节 | 登记什么 | 最常犯的错 |
|---|---|---|
| 受限资产概况 | 受限资产合计账面价值、总资产（做比例的分母）、占总资产比例、受限类别数，`〔口径：本期末〕` | 只写合计不写总资产，比例就无从重算 |
| 货币资金受限 | 按受限形态分组：银行承兑汇票保证金／信用证保证金／保函保证金／质押存款／冻结存款／其他，`〔形态：…〕` | 只写「货币资金受限 1,700 万元」不按形态分，看不出哪笔能解 |
| 非货币资产受限 | 按资产类别分组：应收票据／存货／固定资产／无形资产／投资性房地产／其他，`〔类别：…〕` | 类别名不写，归属不明 |
| 受限原因与期限 | 每项受限的原因原句、受限起止或期限，`〔对象：…〕` | 只写「因借款抵押」不写对象，分不清哪项资产 |
| 与负债的对应 | 该受限资产对应的借款／应付票据／担保债务金额；附注不给就写 `未取到：` | 拿受限金额当对应借款金额填上去 |
| 口径与未取到 | 取法口径 ＋ 缺口逐项点名；零缺口写 `未取到：无` | 正文写了未取到而本节没列，或反之 |
| 来源 | 每条 `[S#]` 一行：`- [S#] 标题 \| URL \| 检索日 YYYY-MM-DD` | 引用了 `[S#]` 却没有登记行；检索日写成斜杠式 |

同一条 = 一行：行首写项名与标签，紧跟金额与「万元」，再挂 `「原句」〔锚：页/表〕[S#]`。附注里没有的数写 `未取到：项名`，不留空、不借常识补。

## 五道机检在管什么

现状以脚本里 `UNIMPLEMENTED` 的现值为准：五道**全部已落字**。将来某道若回退成空壳，它会调用即抛、由机检收进「不可判」，既不判也不放行，单稿退 3；`rc=0` 只留给「五道全过」。

| 码 | 名称 | 判什么 | 最常拦住的情况 | 现状 |
|---|---|---|---|---|
| `RA-STRUCT` | 形制 | 头部三件自标逐字在位、七节齐且按序；认不出的节标题与多出同名节记 stray 逐条发。只判「形」，不判内容；**不判** `主体：`／`报告期：` | 节名改了个字就整节认不出；一节写了两次 | 已落字 |
| `RA-QUOTE` | 原句与锚 | 五个内容节里每个数字行须挂齐「」原句＋〔锚：…〕＋`[S#]` 三元组，原句 ≥8 字且不能只有数字标点；例外只有 `未取到：` 行、`[待人工]` 行、`〔自算〕` 行三形；来源行须合格式，正文与来源**两向**都要对得上，来源节一条合规行都没有则单独发。**不核对引号里的数与行首是否同一**（那是 `RA-SUM`／`RA-RATIO` 的活，分开判只为让一支坏样只红一道） | 数字行只写数没抄原句；来源行检索日写成 `2026/03/20` | 已落字 |
| `RA-SUM` | 合计与分项 | ① 「受限资产概况」里的 `受限资产合计` 与「货币资金受限」＋「非货币资产受限」两节所有金额行之和比对，差 > 0.01 万元 ⇒ 发，消息记 `分项和=X 披露合计=Y`；② 某行同时给了受限金额与「账面总额／资产总额」且受限金额更大 ⇒ 发。**任一侧缺失 ⇒ 整条跳过**，不猜、不按 0 算；缺节不在这里判（那是 `RA-STRUCT`／`RA-LINE` 的活，避免一支注入红三道） | 分项漏抄一行，合计就对不上；某类受限金额抄成大于该类资产总额 | 已落字 |
| `RA-RATIO` | 比例重算 | 只在**同一行**里同时拿到「受限金额」「资产总额（或总资产）」与披露比例时才判：按 `受限金额 / 资产总额` 重算，与披露比例差 > 0.05 个百分点 ⇒ 发，消息记 `重算=X 披露=Y`；> 100% ⇒ 单独发一条（那不是四舍五入能解释的）；分母为 0 ⇒ 如实记一句「比例无从重算」，不静默除零崩。**跨行拼出来的分母归属不明，宁可跳过也不猜** | 比例抄成相邻那一行；分子分母取错行 | 已落字 |
| `RA-LINE` | 红线 | ① 给「资产质量好／差」「偿债能力充足／不足」「偿债压力大」的判断 ② 把受限资产说成「已损失」「已减值」「无法收回」 ③ 拿受限金额当可动用金额（出现「可动用」「可自由支配」「实际可用」）④ 给评级、目标价、买卖建议。**同一行同类只报第一处**，免得一句话刷成一片。另加：「货币资金受限」节缺 ⇒ 发条（这一节是本件存在的理由）。「口径与未取到」与「来源」两节整节豁免 | 顺手写一句「偿债能力充足」；把受限的 6,600 写成「实际可用资金」 | 已落字 |

`--selftest` 末行自报 `自测档数=N｜不合=0｜不可判=N`，**N 以现跑为准，本文件不写死数字**——写死的数字必然落后于代码。

## 退码

| rc | 含义 |
|---|---|
| `0` | 五道全过，零发条 |
| `1` | 有发条（逐条打印 `码 行号 说明`） |
| `2` | 用法错（没给稿子路径，也没给 `--demo`／`--selftest`，或给了未知参数） |
| `3` | 读不到文件或空稿；或零发条但仍有判据未落字 |

零发条但有判据尚未落字时同样退 3——rc=0 只留给「五道全过」，没跑的道不能算过；报告里那几道计「不可判」，**不等于合规**。本件五道已全部落字，这条当前不触发（好样单跑退 0），留着是为了将来某道回退成空壳时不把「没跑」读成「过」。

## 四条红线

1. **不判断资产质量与偿债能力**：「资产质量好」「偿债能力充足」「偿债压力大」都是判断，不在本件范围内，一律 `[待人工]`。
2. **不把受限说成已损失**：抵押质押冻结是**权利受限**，资产还在账上、还有价值，不是「已减值」「已损失」「无法收回」。
3. **不拿受限金额当可动用金额**：受限金额恰恰是**动不了的那部分**；写成「可动用」「可自由支配」「实际可用」是把结论搞反了。要算可动用资金，交 `[待人工]`。
4. **不给评级、目标价、买卖建议**。

另有三条由机检强制：合计必须对得上分项（`RA-SUM`）、比例必须与重算对得上（`RA-RATIO`）、受限资产不得被说成已损失或可动用（`RA-LINE`）。「口径与未取到」整节豁免红线——那一节按设计就要写「本件不判断资产质量与偿债能力、不把受限金额当作可动用金额」，不豁免会自己咬自己。

## 数据通道

- 发现先行：匿名取 live 域清单与 `routing`，**不硬编码工具名与工具数**；连上之后带 `Authorization: Bearer $CUE_API_KEY` 发 `tools/list`，以现场返回为准（可跑的完整两段见 `README.md` 的「数据通道」一节）；
- 原文腿：年报附注里受限资产那一段在数据腿上，本件不承诺该域开放，也不承诺实时性；
- 正文腿：这一段常是「项目／账面价值／受限类型／受限原因」的横排大表，截图与扫描件交 `cue-omni-reader`（大纲→按节取用，计费以服务端返回为准）；
- 通道配置页只给指针：<https://cuecue.cn/hub/mcp> ／ <https://cuecue.cn/hub/omni-reader> ／ <https://cuecue.cn/hub/api-key>。
