# 反馈与演化

系统演化是未来的作用发生变化。它可以由新证据、真实效果、约束改变、人的纠正或发现新的连接开始。看变化发生在哪个尺度，再决定它该改变哪一部分。

## 向上找到反复问题的结构

同类问题第一次出现，可以先处理状态或行动；反复出现时，沿下面的层级向上检查，找到持续生成低层事件的结构，并让高层改变重新进入实际行动：

```text
偶然事件或当前状态
→ 当前行动方式
→ 能力是否缺失、过时或不适用
→ 关系、反馈、接口或权责是否设计错误
→ 更高层的资源结构、边界或目标是否在反复生成问题
```

“高一层”指向变化更慢、更稳定、会持续生成低层事件的关系。用多个时点、多个实例或反事实来确认重复性；证据支持到哪一层，系统就更新到哪一层。

## 高层改变怎样向下发生作用

新的目标、边界或结构必须改变实际能力和行动才算演化：

```text
新的目的、模型或结构
→ 改变能力要求
→ 改变组件、关系与权限
→ 改变实际行动
→ 观察新的状态与效果
```

如果一份复盘只留下结论，却没有改变以后观察什么、怎样分工、用哪项能力或何时行动，它还没有进入系统。

## 依赖传播：只改真正受影响的部分

重要认识、能力和关系应当能说明自己依赖什么。新证据到来时，先找直接依赖，再看哪些作品、决定、工具或下游系统真正使用了它。标出需要重审、可以继续和目前未知的部分。保留用户修改和没有受到影响的工作。

目标改变时重新判断成功条件与能力要求，不把旧计划原样沿用。能力失效时，受影响的是依赖它的作用，不自动否定所有对象认识。关系撤回时，停止后续调用，并说明已发出的副本、已发生动作和仍需负责的结果由谁处理。

| 有了什么 | 可以改变什么 | 下次从哪里看出变化 |
| --- | --- | --- |
| 一条新的观察或反例 | 当前判断、一个模型的适用范围、要补的观察 | 下一次解释采取了新的证据或保留了必要的不确定性 |
| 一次成功的行动 | 可复用工具、用法与确认结果的方式 | 类似的工作再来时能使用，效果仍可检查 |
| 延续一段时间的偏差 | 观察入口、协作时机、责任或工作结构 | 以后少漏一类信号，或反馈比原来更及时 |
| 目标、权利或环境改变 | 系统边界、连接条件、由谁决定 | 系统能采用新的安排，也知道原能力在哪些地方失效 |
| 多个系统发现相同关系 | 可以借用的观察方式、实践或连接约定 | 其他维护者在各自条件下用出实际成果，并能改进 |

## 反馈怎样回到能改变它的地方

先判断看到的是执行回执、现实状态、使用效果还是人的理解。接收层可以不同。一部作品让人真正理解了机制，影响的是认识与后续选择。工具运行成功且结果被使用，才出现可以延续的实践。一次错误来自更高层的权责或输入安排时，应推动那个层次的人和系统调整，而不是把每次修补都归到眼前的任务。

留下真实决策所需的信息，例如结论的依据、对象、使用条件、已有版本与负责人。用自然语言把它跟实际可用的部件连起来。工作重复之后，能说明做法是否仍然有价值，哪些地方可以让 AI 或其他工具继续改善。当几条反馈互相矛盾时，核对来源、尺度、滞后和利益关系，也可以保留多种解释。

## 退出和恢复也是系统能力

观察过时、权限撤回、分析错误或工具失效时，指出哪些后续认识和能力受影响。在真实状态确认前保留未知。恢复到仍然可靠的认识、资料或工具版本。人决定长期改变和对外承诺。例行运行需要实际触发入口、清楚的停止办法和适当权限。
