# FTO侵权风险排查 · PatentMax

产品准备上市、出口或量产前，查**目标市场里有没有挡路的有效专利**：把你的产品和专利的权利要求逐项比对，按风险高低列出要处理的专利，每件写清它保护什么、哪里还需要确认、下一步怎么办。每个市场出一份 **Word + PDF** 报告。

支持 **中国、欧洲专利、美国、日本、韩国**，可以一次选多个。专利数据来自 PatentMax 专利库。

使用问题、企业采购：访问 **ip930.com**，右下角「联系客服」。

**不需要 API Key 就能用。** 第一次使用自动领取免费试用，够做一份单市场报告。

## 运行环境（必读，所有命令都适用）

部分 WorkBuddy 等环境的命令行不完整，`cat`、`ls`、`sleep`、`rm` 等可能找不到。为保证任何电脑都能跑通：

- 脚本路径一律写**绝对路径**：`$DIR/scripts/patentmax_fto.py`（`$DIR` 是本技能所在目录），不要写 `cd ... && ...`
- `python` 找不到时依次试 `python3`、`py`；还找不到就用 WorkBuddy 自带的：先用 Glob 在 `~/.workbuddy/binaries/python/versions/` 下找到 `python.exe`，用它的完整路径。**下文所有 `python` 都按这条替换**
- 不要用 `cat` 读文件、不要用 `sleep` 等待：读文件用 Read 工具；等待由脚本自己完成
- 命令在**用户的工作目录**里运行，报告会存到这个目录；也可以用 `--out-dir` 指定
- 命令超时设为 120 秒。脚本每条命令最多跑 30 秒就返回，不会卡住

## 核心原则

**必填三项：产品说明（`--description`）、目标市场（`--markets`）、计划上市时间（`--launch`）。** 缺哪项就问哪项，别猜。

**产品说明要写清结构和工作方式。** 由哪些部件组成、怎样连接、怎样工作，至少 30 个字——报告就是拿这些特征和专利的权利要求逐项比对的，写得越具体，判断越准。用户有产品说明书、规格书、设计文档时，优先让他给文件（`--material-file`），这时说明里只写产品名也行。

**目标市场按真实要卖的地方选。** 中国 `CN`、欧洲专利 `EP`、美国 `US`、日本 `JP`、韩国 `KR`。**首个市场 ¥20，每多一个市场加 ¥10**（以提交后返回的价格为准）。用户只说「出口」没说去哪，先问。

**上市时间用来判断专利会不会在上市前到期**，写成年-月，例如 `2027-06`。

**这是付费任务，执行前必须报价并取得用户确认。** 命令必须显式加 `--yes` 才会执行。

**不出保证性结论。** 不写「不侵权」「可以放心上市」「没有专利风险」——见「结论纪律」。

**不重新提交。** 报告要跑十分钟左右，跑得久不代表失败。只要没有报错，就继续 `wait`。重新提交会新建任务、重复扣费。

## 命令

```bash
# 只给文字说明
python "$DIR/scripts/patentmax_fto.py" create \
  --description "一种桌面折叠风扇：底座内置锂电池，扇头经阻尼铰链可向下折叠 180°，折叠后扇罩扣入底座凹槽，铰链处设霍尔开关，折叠时自动断电" \
  --markets "CN,US" --launch "2027-06" --yes

# 带产品资料文件（PDF / Word，≤20MB）：说明里可以只写产品名
python "$DIR/scripts/patentmax_fto.py" create \
  --description "桌面折叠风扇" --material-file "D:/资料/折叠风扇规格书.pdf" \
  --markets "CN" --launch "2027-06" --yes

# 接着等：每次最多 30 秒，完成时自动下载每个市场的 Word 和 PDF
python "$DIR/scripts/patentmax_fto.py" wait --operation-id <operation_id>

# 重新下载（wait 完成时已自动下载过）：某个市场或全部打包
python "$DIR/scripts/patentmax_fto.py" download --report-id <report_id> --market CN --kind pdf
python "$DIR/scripts/patentmax_fto.py" download --report-id <report_id> --market all

# 不想跑了
python "$DIR/scripts/patentmax_fto.py" cancel --operation-id <operation_id>
```

**参数说明**

- `--description` / `--description-file`：产品说明（必填），较长时放 UTF-8 文本文件
- `--markets`：目标市场（必填），逗号分隔，也认「中国、美国、欧洲、日本、韩国」
- `--launch`：计划上市时间（必填），年-月
- `--material-file`：产品资料文件，脚本会上传给 PatentMax 扫描并提取文字（上传和解析不收费），**只发给 PatentMax，不传到别的网站**
- `--materials` / `--materials-file`：产品资料的文字（至少 20 字），用户把资料内容贴在对话里时用这个
- `--idempotency-key`：不填会按请求内容自动生成——**同样的输入重试不会重复建任务、重复扣费**

## 等待并报告进度

`create` 约 15 秒后返回。返回退出码 10 时，**先发这一句**，再发输出里的进度：

```

```

记下输出 JSON 里的 `operation_id`，后面都用它。然后运行：

```bash
python "$DIR/scripts/patentmax_fto.py" wait --operation-id <operation_id>
```

每条 `wait` 最多 30 秒就返回。按退出码处理：

| 退出码 | 含义 | 怎么做 |
| --- | --- | --- |
| 10 | 还在生成 | 发送输出里的进度，**然后立即再运行一次 `wait`** |
| 0 | 完成了，报告已自动下载 | 按「读结果」交付 |
| 1 | 出错 | 按「出错时」处理 |
| 2 | 输入有误，什么都没提交 | 按 `message` 补齐后再运行 |
| 3 | 同样的任务已经在跑 | 用输出里的 `operation_id` 运行 `wait`，**不要**换写法重新提交 |

把每条 `[进度 X%] 某阶段，已用时……` 去掉方括号部分，前面加 📝 **原文发送**（例：`📝 42.6% 比对权利要求，已用时 4分10秒`）；`[进度] 排队中……` 前面加 🕒。等待期间只发进度，不附加其它文字，不自己估算剩余时间。**出结果之前不要结束回复。**

## 读结果

退出码 0 时报告已经下载好，输出 JSON 的 `files` 里是每个市场的 Word 和 PDF 的完整路径。先发：

```

📄 报告：<files 里每个市场的报告路径，一行一个>
```

`quality_status` 是 `qualified_degraded` 时，紧接着讲 `quality_hint`：只有部分市场出了报告，只收了出报告的市场，其余已退回；没出报告的市场和原因在 `summary.markets` 的 `not_delivered_reason` 里。

再按 `summary.markets` 逐个市场讲要点（遵守「结论纪律」）：

| 字段 | 怎么讲 |
| --- | --- |
| `summary` | 这个市场的总体结论，用自己的话讲两三句 |

## 出错时

脚本出错时输出 `{"error": true, "message": "……"}`，`message` 是写给用户看的中文说明，里面已经写明了下一步怎么办。

- **原样转述 `message`，不猜原因、不自己换写法重试**
- 退出码 2（输入有误：少必填项、市场写错、上市时间格式不对、说明太短、资料文件读不了）：什么都没提交、没扣费，按 `message` 补齐后再运行
- 第一次运行时输出里有「[PatentMax] 欢迎使用 PatentMax！……」那段：原样转告用户一次（含注册地址）
- 出现 `"free_trial": true`：免费试用用完、过期或想用其他功能，`message` 里写着怎么办（注册 PatentMax 送 ¥50 余额），原样转告；用户发来正式密钥后按 `ai_hint` 存好再重跑
- 任务失败或取消时，预扣的费用会**全额退回**，告诉用户这一点

## 结论纪律

**禁止输出保证性结论**，例如「不侵权」「可以放心上市」「没有专利风险」「已被专利覆盖」。

使用这类表述：

> 截至 [日期]，在 [市场] 的有效专利范围内，经与所列产品特征比对，发现 N 件需要关注的专利（高风险 X 件）。本结果是技术参考，不构成法律意见；不排除未公开申请（约 18 个月公开窗口）、产品特征描述不全或权利要求解释差异造成的偏差。

三条必须交代：

- **比对基于用户给的产品说明** — 说明里没写到的结构，报告也比对不到
- **18 个月公开窗口** — 最近一年半的申请还查不到
- **正式结论要专业人员出具** — 侵权判断要由专利代理师或律师对照完整权利要求、按各国法律作出
