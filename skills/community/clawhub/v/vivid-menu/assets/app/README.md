# 生动菜单 · Vivid Menu

把一段菜单文字（或一张菜单照片）变成一张可以打印、可以发朋友圈的菜单。
每一道菜配一幅线条插画，页面负责排版、质检和导出。

**双击 `index.html` 就能用，不需要装任何东西，不需要服务器，不上传任何数据。**

---

## 怎么用

打开后有三个入口：

| 入口 | 适合什么情况 |
|---|---|
| 粘贴菜单文字 | 最快。一行一道菜，如 `红烧肉 68`、`宫保鸡丁 48 微辣` |
| 上传菜单照片 | 照片只留在本机，用于对照；浏览器读不出图上的字，菜名仍需粘一遍 |
| 看一个示例 | 三张成品（川菜馆 / 日式小馆 / 茶室），打开就能改 |

生成之后：

- 点任意一道菜，可以改名字、价格、说明、标签，切换招牌，或换一幅插图
- 左上角「纸张」换配色（五种纸墨）
- 「菜单合集」里能找回之前存的菜单，也能打开内置示例
- 底部「SVG」导出矢量文件，「图片」复制 PNG 直接粘到微信

快捷键：`Ctrl/Cmd + Enter` 开始绘制，`Ctrl/Cmd + S` 存档，`Esc` 关闭浮层。

## 它和你见过的「菜单生成器」有什么不同

不是让模型一次性吐一张图，而是**人和 Agent 一起往一张纸上逐道落笔**：

- **数据与表现分离**：菜品是结构化数据，SVG 只是渲染结果。改一个价格不会重画整张图。
- **工具驱动的生成**：9 个工具（`add_dish` 一次只加一道菜），每次调用只改变菜单的一部分，页面立即重绘并反馈问题。
- **可执行的质检**：把"看起来对不对"变成能算的东西——图元数量、文字行数、纸墨对比度、点缀色色距、总高度。返回 error / warn 两级。
- **生成 → 测量 → 修复**的闭环：`inspect_menu` 报出的问题，`autoFix` 能修的直接修掉。
- **不编造内容**：价格照抄，读不到就留空；招牌菜必须写判断依据。

## 两条驱动路径，共用一套管道

```
                    ┌──────────────────┐
   内置生成器  ────► │  9 个工具 handler │ ◄──── WebMCP / 外部 Agent
 （规则 + 引擎）     └────────┬─────────┘
                             │
                    ┌────────▼─────────┐
                    │  model → layout   │
                    │    → render       │
                    │    → inspect      │
                    └──────────────────┘
```

关键点：**工具只写一份**。内置生成器和外部 Agent 调的是同一个 `add_dish`、同一个 `inspect_menu`，
所以两条路径不会出现逻辑分叉。

- 没有 Agent 环境时，内置生成器用**规则解析 + 参数化插图引擎**跑完整流程，0 API 成本。
- 检测到 `document.modelContext`（WebMCP）时，9 个工具会自动注册，外部 Agent 可以直接接管。
  顶栏会显示「Agent 已接入 · 9 个工具」。

想自己接一下：

```js
// 控制台里可以直接调
window.vividMenu.toolset.add_dish.handler({ name: '椒盐排条', price: '48', section: '热菜' })
window.vividMenu.toolset.inspect_menu.handler()
```

## 插图引擎

没有调用任何图像模型。22 类食材 × 多种构图 × 种子变体，用 SVG 画出来：

```
猪肉 牛肉 禽类 整鱼 虾 蟹 贝类 青菜 菌菇 豆腐 蛋 凉菜
面 饭 汤 饺子 饼 烤串 锅 甜点 饮品 通配
```

- 视口固定 `0 0 100 100`，线宽 2~2.4，圆头圆角，手绘感线条
- 菜名 → 类别的推断有优先级：形态类（面/饭/汤/饺）先于食材类，避免「牛肉面」被判成牛肉；
  另有精确表处理歧义（「鱼香肉丝」不是鱼）
- 同一个菜名永远画出同一幅图（哈希种子），不同菜名构图不同
- 颜色只走三个 token：`INK` / `ACCENT` / `MUTE`，换主题时自动跟着变

```
├── css/style.css
├── js/
│   ├── art/
│   │   ├── pen.js      笔触与图元（path / 叶 / 蒸汽 / 辣椒 / 印章…）
│   │   ├── kinds.js    22 类食材画法
│   │   └── index.js    菜名推断 + 分发 + SVG 白名单清洗
│   ├── model.js        数据模型、主题预设、纸张尺寸
│   ├── measure.js      文字测量与折行（SVG 没有自动折行）
│   ├── layout.js       排版计算，输出绝对坐标指令表
│   ├── render.js       指令表 → SVG
│   ├── inspect.js      质检规则
│   ├── parse.js        文字菜单解析 + 80 道菜词典
│   ├── protocol.js     9 个工具
│   ├── driver.js       内置生成器 + 自动修复 + WebMCP 挂载
│   ├── photo.js        图片压缩与局部放大
│   ├── export.js       SVG / PNG 导出
│   ├── store.js        localStorage 存档 + 内置示例
│   └── main.js         界面编排
└── tools/
    ├── build.js        打包（改完源码跑一次）
    ├── shot.sh         无头浏览器截图（开发调试用）
    └── preview-*.js    插图 / 排版预览
```

## 改代码

源码是 ES 模块。改完 `js/` 下的文件后，必须重新打包：

```bash
node tools/build.js
```

`.bat` 用户直接双击 `build.bat`。

调试时可以用 `dev.html`（需要本地服务）：

```bash
python -m http.server 8899
# 打开 http://localhost:8899/dev.html
```

打包脚本会检查顶层标识符重名——所有模块共享一个作用域，新增模块时变量名别撞车。

### 快捷参数

```
index.html?demo=0          直接打开第 1 个示例
index.html?text=文字&run=1  带文字自动生成（可做演示链接）
```

## 已知限制

- **照片不做 OCR**。浏览器本地读不出图上的字，AI 识别需要外部 Agent 的视觉能力。
  所以照片是"对照物"，菜名还是要粘一遍——这是刻意的取舍，不假装能识别。
- **字体依赖系统**。菜单用衬线字体栈（Noto Serif SC / Songti SC / SimSun），
  换到没装这些字体的机器上会回落，字形略有差异。导出 SVG 时字体不内嵌。
- **localStorage 约 5MB**。存了原图后大约能放十几张菜单，超限时会自动剥离图片保文字。
- **不做协作编辑、版本历史**。单机单人用。
- 招牌菜只有第一道会放大成顶部大图，其余只留标记。

## 从哪来的

结构上参考了「生动菜单 / Vivid Menu」那套网页与 Agent 双向协作的模型（9 工具、数据与表现分离、
机器可执行质检）。这一版重写了三处：

1. **插图不再依赖模型**：换成参数化 SVG 引擎，瞬时出图、零成本、结果可复现。
2. **无 AI 也能跑通**：加了文字解析通道和内置菜品词典，不接任何服务就能从零做出一张菜单。
3. **工具只写一份**：内置生成器和外部 Agent 走同一个管道，避免两套逻辑逐渐漂移。
