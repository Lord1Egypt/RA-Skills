## 一、通用工作流骨架概述

### 1.1 设计背景

工信部《科技服务业标准体系建设指南》规定了三层标准体系（基础通用层/重点领域层/管理保障层），技术经理人6类标准已上传。为实现「对照标准自评→补缺查漏→信息收集→合规审查→贯标辅导」全链路自动化，需将这5个通用工作流抽象为所有44个Skill的底层骨架。

## 二、WF1: 对照标准自评

### 2.1 工作流定义

| 属性 | 内容 |
|------|------|
| **工作流编号** | WF1 |
| **工作流名称** | 对照标准自评 |
| **英文名称** | Standard Self-Assessment |
| **核心功能** | 将机构/个人信息与目标标准条款进行匹配，自动生成差距清单和优先级排序 |

### 2.2 标准输入格式

```json
{
  "WF1_Input": {
    "subject_type": {
      "type": "enum",
      "enum": ["person", "organization"],
      "required": true,
      "description": "评估主体类型：个人/机构"
    },
    "subject_info": {
      "basic_profile": {
        "name": "string (机构名称/个人姓名)",
        "type": "string (机构类型/人才类型)",
        "location": "string (省市)",
        "established_date": "date (成立时间)",
        "contact": "string (联系方式)"
      },
      "capability_data": {
        "service_records": "array (服务记录列表)",
        "financial_data": "object (财务数据，机构用)",
        "team_composition": "object (团队构成)",
        "facility_equipment": "array (设施设备清单)",
        "certification_records": "array (资质认证记录)"
      },
      "self_assessment": {
        "existing_strengths": "string (现有优势)",
        "existing_weaknesses": "string (现有不足)",
        "target_standards": "array (目标标准列表)"
      }
    },
    "standard_selection": {
      "standard_type": {
        "type": "enum",
        "enum": ["national", "industry", "provincial", "organizational"],
        "required": true
      },
      "standard_code": "string (标准编号，如GB/T 34670-2017)",
      "standard_name": "string (标准名称)",
      "version": "string (版本号)",
      "applicable_scope": "string (适用范围的补充说明)"
    },
    "assessment_config": {
      "scoring_method": {
        "type": "enum",
        "enum": ["full_score", "percentage", "level_based"],
        "default": "level_based"
      },
      "include_optional_items": "boolean (是否包含可选条款，默认true)",
      "priority_focus": "array (重点关注的条款，优先级调整用)"
    }
  }
}
```

### 2.3 处理逻辑

#### Step 1: 标准条款解析与匹配

```
输入: 目标标准代码 + 机构/个人信息
处理:
  1. 解析标准XML/JSON文件，提取全部条款项
  2. 按层级结构组织条款树
  3. 根据subject_type匹配适用条款范围
  4. 过滤不适用的豁免条款
输出: 适用条款清单 + 每条的可评分状态
```

#### Step 2: 条款逐项打分

```
输入: 适用条款清单 + 机构能力数据
处理:
  1. 对每条条款进行条件判断
  2. 根据评分规则计算得分
  3. 分级映射(level_based模式):
     - 完全满足: A级(100分)
     - 部分满足: B级(70分)
     - 初步涉及: C级(40分)
     - 尚未涉及: D级(0分)
  4. 标注数据缺失项(需补充材料)
输出: 条款得分清单 + 数据缺失清单
```

#### Step 3: 差距可视化

```
输入: 条款得分清单
处理:
  1. 按一级/二级指标聚合得分
  2. 计算各维度达成率
  3. 生成雷达图/柱状图数据
  4. 识别关键短板(达成率<60%的维度)
  5. 输出TOP5差距清单
输出: 差距可视化数据 + 关键短板报告
```

#### Step 4: 报告生成

```
输入: 全部评分数据 + 差距分析
处理:
  1. 汇总综合得分
  2. 对标同类型机构/人才排名
  3. 生成结构化报告
  4. 输出PDF/HTML格式
输出: 自评报告 + 差距清单 + 优先级排序
```

### 2.4 分支逻辑与异常处理

| 条件 | 分支路径 | 处理方式 |
|------|---------|---------|
| 标准条款缺失 | 提示补充 | 引导用户提供或从标准库检索 |
| 机构类型不匹配 | 类型重定向 | 识别实际类型，推荐正确标准 |
| 数据不完整 | 分步评估 | 先评估已提供数据，标注缺失项 |
| 多标准同时评估 | 并行处理 | 创建多份独立评估报告后合并 |

| 异常类型 | 异常处理 |
|---------|---------|
| 标准文件解析失败 | 降级为条款关键词匹配，提示人工复核 |
| 评分数据来源不明 | 标注"自报数据"，建议提供佐证材料 |
| 机构类型跨类别 | 触发重新识别流程 |
| 网络超时 | 本地缓存优先，逐步加载 |

### 2.6 与其他工作流的衔接

| 衔接工作流 | 衔接方向 | 传递数据 |
|-----------|---------|---------|
| → WF2 (补缺查漏) | 强依赖 | gap_list + dimension_scores |

| 参数名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|

## 三、WF2: 补缺查漏

### 3.1 工作流定义

| 属性 | 内容 |
|------|------|
| **工作流编号** | WF2 |
| **工作流名称** | 补缺查漏 |
| **英文名称** | Gap Remediation Planning |
| **核心功能** | 基于WF1输出的差距清单，制定整改路线图和资源需求计划 |

### 3.2 标准输入格式

```json
{
  "WF2_Input": {
    "gap_list": {
      "source_report_id": "UUID (WF1输出的报告ID)",
      "critical_gaps": "array (来自WF1的关键差距)",
      "moderate_gaps": "array (中等差距)",
      "minor_gaps": "array (轻微差距)"
    },
    "existing_resources": {
      "financial": {
        "annual_budget": "number (年度预算)",
        "available_for_improvement": "number (可用于整改的资金)",
        "funding_sources": "array (资金来源渠道)"
      },
      "human_resources": {
        "current_staff": "number (现有人员)",
        "skilled_for_gaps": "array (可投入整改的人员)",
        "training_capacity": "string (培训能力)"
      },
      "infrastructure": {
        "existing_facilities": "array (现有设施)",
        "equipment_needs": "array (设备需求)",
        "space_available": "boolean (场地是否可用)"
      },
      "partnerships": {
        "existing_partners": "array (现有合作伙伴)",
        "potential_partners": "array (潜在合作伙伴)"
      }
    },
    "constraints": {
      "timeline": {
        "hard_deadline": "date (硬性截止日期)",
        "soft_target": "date (软性目标日期)"
      },
      "resource_limits": {
        "max_budget": "number (预算上限)",
        "max_staff": "number (人员上限)"
      },
      "regulatory_constraints": "array (法规限制)"
    },
    "configuration": {
      "prioritization_method": {
        "type": "enum",
        "enum": ["urgency", "impact", "cost_effectiveness", "dependency"],
        "default": "cost_effectiveness"
      },
      "include_worst_case": "boolean (是否包含悲观情景)",
      "show_alternatives": "boolean (是否显示替代方案)"
    }
  }
}
```

### 3.3 处理逻辑

#### Step 1: 差距分类

```
输入: gap_list
处理:
  1. 判定硬性差距 vs 软性差距
     - 硬性差距: 法规强制/资质必备/一票否决项
     - 软性差距: 优化提升/加分项/可选
  2. 按影响范围分类
     - 核心业务型: 影响主营业务开展
     - 合规风险型: 存在合规隐患
     - 竞争力型: 影响市场竞争力
  3. 识别依赖关系
     - 建立差距间的前置依赖图
输出: 分类后的差距清单 + 依赖关系图
```

#### Step 2: 整改优先级排序

```
输入: 分类差距 + constraints
处理:
  1. 计算综合优先级得分
     - 紧迫性得分: 距截止日期越近越高
     - 影响度得分: 对业务影响越大越高
     - 成本效益得分: 投入产出比越高越高
     - 依赖度得分: 解锁其他差距越多越高
  2. 综合权重计算
     优先级 = 0.3×紧迫性 + 0.3×影响度 + 0.25×成本效益 + 0.15×依赖度
  3. 排序输出
     P0: 必须优先解决(硬性差距)
     P1: 短期内解决(高优先级)
     P2: 中期规划(中等优先级)
     P3: 长期优化(低优先级)
输出: 优先级排序的差距清单
```

#### Step 3: 资源需求分析

```
输入: 排序后差距 + existing_resources
处理:
  1. 对每个P0/P1差距分析:
     - 所需资金(预算分解)
     - 所需人员(技能要求/数量/时长)
     - 所需设备/设施
     - 所需外部资源/合作伙伴
  2. 识别资源缺口
     - 对比现有资源与需求
     - 计算缺口量
  3. 制定资源获取方案
     - 内部调配方案
     - 外部获取方案(采购/合作/外包)
输出: 资源需求清单 + 获取方案
```

#### Step 4: 时间线规划

```
输入: 排序后差距 + 资源方案
处理:
  1. 估算每个差距的整改工期
  2. 按依赖关系排布甘特图
  3. 识别关键路径
  4. 计算最早完成时间
  5. 若超截止日期，识别需压缩的关键任务
输出: 整改路线图 + 甘特图数据 + 里程碑清单
```

#### Step 5: 风险预案(可选)

```
输入: 整改路线图
处理:
  1. 识别关键路径风险点
  2. 评估每项风险的发生概率和影响
  3. 制定风险应对策略
  4. 设置监控指标和预警阈值
  5. Kill Criteria: 明确不可接受的结果
输出: 风险预案 + 监控方案
```

### 3.4 分支逻辑与异常处理

| 条件 | 分支路径 | 处理方式 |
|------|---------|---------|
| 资源完全充足 | 快速通道 | 并行处理多个差距 |
| 资源严重不足 | 资源协商 | 识别最小可行资源集 |
| 硬性截止不可达 | 延期协商 | 输出压缩方案或建议延期 |
| 存在循环依赖 | 依赖解除 | 识别破环策略 |
| 外部依赖无法获取 | 备选方案 | 切换替代方案或调整目标 |

| 异常类型 | 异常处理 |
|---------|---------|
| 资源数据缺失 | 提示补充，按估算处理并标注 |
| 截止日期冲突 | 输出冲突分析，建议调整 |
| 预算超限 | 触发优先级重新评估 |

### 5.3 处理逻辑

#### Step 1: 材料解析

```
输入: materials
处理:
  1. 文件识别
     - 自动识别文件类型
     - 提取文本内容(OCR识别图片)
  2. 结构化提取
     - 关键字段提取
     - 表格数据提取
     - 签名/印章检测
  3. 完整性检查
     - 必填材料清单对照
     - 材料页数/份数检查
输出: 结构化材料数据 + 完整性报告
```

#### Step 2: 条款匹配

```
输入: 结构化材料 + reference_standards
处理:
  1. 标准条款解析
     - 提取每条合规要求
     - 识别判定条件
  2. 材料-条款映射
     - 建立材料与条款的对应关系
     - 标注材料覆盖的条款
  3. 遗漏识别
     - 识别未提供材料的条款
     - 标注需要补充的材料
输出: 条款匹配矩阵 + 遗漏清单
```

#### Step 3: 合规打分

```
输入: 条款匹配结果
处理:
  1. 逐项合规判定
     - 完全合规: 符合全部条件
     - 基本合规: 符合主要条件，轻微偏差
     - 部分合规: 部分符合，存在差距
     - 不合规: 不符合或违反
  2. 权重计算
     - 法规强制性条款: 权重最高
     - 资质必备条款: 高权重
     - 优化建议条款: 低权重
  3. 综合评分
     综合得分 = Σ(条款得分 × 权重) / Σ权重
输出: 分项得分 + 综合得分 + 评级
```

#### Step 4: 风险识别

```
输入: 合规判定结果
处理:
  1. 风险分类
     - 合规红线风险: 一票否决项
     - 重大风险: 影响资质认定
     - 一般风险: 需要整改
     - 提示风险: 优化建议
  2. 风险量化
     - 发生概率评估
     - 影响程度评估
     - 风险值 = 概率 × 影响
  3. 风险排序
     - 按风险值降序
     - 标注Top5关键风险
输出: 风险清单 + 风险矩阵
```

#### Step 5: 修改建议生成

```
输入: 风险清单 + 缺失清单
处理:
  1. 针对每个问题生成建议
     - 问题描述
     - 整改方向
     - 具体修改建议
     - 参考示例
  2. 优先级排序
     - 按影响程度排序
     - 标注必须修改项
  3. 验收标准
     - 明确修改后的合格标准
     - 提供自检清单
输出: 修改建议清单 + 重检清单
```

```
     - 建设阶段
     - 自评阶段
     - 申报阶段
     - 评审阶段
  2. 甘特图编排
     - 任务分解
     - 工期估算
     - 依赖关系
     - 资源分配
  3. 里程碑设定
     - 关键节点

  4. 风险缓冲
     - 预留应急时间
     - 动态调整机制

```

#### Step 3: 材料清单生成

```
输入: 路径规划 + target_standard
处理:
  1. 申报材料梳理
     - 从标准提取材料清单
     - 补充常见要求
  2. 模板生成
     - 标准格式模板
     - 填写指南
  3. 材料准备计划
     - 责任人分配
     - 完成时间节点
  4. 质量要求
     - 每项材料的标准
     - 自检清单
输出: 材料清单 + 模板包 + 准备计划
```

#### Step 4: 评审模拟

```
输入: 材料清单 + target_standard
处理:
  1. 评审流程还原
     - 标准评审流程
     - 常见评审方式
  2. 问题预设
     - 评审常见问题库
     - 针对本机构的问题
  3. 模拟演练
     - 口头答辩模拟
     - 材料质询模拟
  4. 反馈改进
     - 问题反馈
     - 改进建议
输出: 模拟评审报告 + 问题清单 + 改进建议
```

#### Step 5: 答辩辅导(可选)

```
输入: 评审模拟结果
处理:
  1. 答辩技巧培训
     - 结构化表达
     - 应对质疑技巧
  2. 材料支撑
     - 答辩PPT模板
     - 佐证材料准备
  3. 心理建设
     - 常见紧张应对
     - 关键点强调
  4. 实战演练
     - 模拟答辩
     - 即时反馈
输出: 答辩指南 + PPT模板 + 演练记录
```

#### 8.2.2 补缺优先级排序规则

```
优先级计算公式:
P = 0.4×(知识缺口影响度) + 0.35×(技能提升紧迫性) + 0.25×(实践经验必要性)

排序规则:
- P≥0.7: P0级(必须优先补足)
- 0.5≤P<0.7: P1级(短期补足)
- 0.3≤P<0.5: P2级(中期规划)
- P<0.3: P3级(长期积累)
```

| 优先级 | 补缺领域 | 建议资源投入 |
|--------|---------|-------------|
| P0 | 技术成熟度评估能力、供需匹配流程 | 专项培训+项目实战 |
| P1 | 政策法规深度理解、谈判与交易设计 | 系统学习+案例研讨 |
| P2 | 知识产权布局、跨部门协作 | 专项课程+导师带教 |

#### 8.2.3 贯标路径差异

| 阶段 | 初级→中级 | 中级→高级 |
|------|----------|----------|
| **核心路径** | WF1(自评)→WF3(信息收集)→WF5(贯标) | WF1→WF2(补缺)→WF4(合规)→WF5 |
| **重点补强** | 供需对接实操案例积累 | 复杂交易设计与资源整合能力 |
| **典型时间** | 6-12个月 | 12-24个月 |
| **关键里程碑** | 完成3个以上对接案例 | 主导完成1个千万级项目 |
