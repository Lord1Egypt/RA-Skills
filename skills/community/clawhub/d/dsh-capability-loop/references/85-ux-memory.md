# 85 · 用户偏好记忆与体验进化（UX Memory）

> 目的：让这套协作**越用越顺手**——不是靠模型「更聪明」，而是把用户的偏好、纠正、验收习惯变成可复用资产。
> 两本账：**项目画像**（`project-profile.md`，跟着项目走）与**用户偏好**（`memory/user-profile.md`，跟着人走）。

## 1. 记什么（只记「会影响下次交互」的）

| 维度 | 示例 | 来源 |
|---|---|---|
| 沟通风格 | 结论先行 / 要细节 / 先方案后执行 / 少客套 | 用户反复纠正、明确要求 |
| 文档形态 | 要 `.md` + `.html` 总览；要表格不要长文；要带出处 | 用户说「这个格式好」 |
| 设计偏好 | 密度偏紧/偏松、品牌色、禁用的风格、暗色需求 | 设计评审反馈 |
| 验收偏好 | 要命令+退出码；要截图；要「未实测」清单 | 用户打回时 |
| 节奏与边界 | 先给样例再全量；不要一次问太多；不要自动执行写操作 | 协作中的摩擦点 |
| 行业语境 | 燃气/电网术语、合规红线、客户角色 | 项目画像 + 需求评审 |

## 2. 怎么采集（不靠猜）

1. 用户**纠正/否定/重复要求**时：立刻记一条（事件 → 推断偏好 → 建议动作）；
2. 每轮 retro（`templates/retro.md`）追加「用户反馈」段；
3. 同类偏好 ≥3 次 → 提升为 `memory/rules.md` 规则（≤120 字）；
4. 冲突时以**最近一次明确要求**为准，并在 `user-profile.md` 标注「旧：… / 新：…」；
5. 隐私边界：只存本地工作区、只写工作相关内容；用户可随时删除；不跨项目混用（除非用户明确同意）。
6. **告知与上限（必须遵守）**：首次写入前用一句话告知用户「我会把你说过的交付偏好记到 `memory/user-profile.md`，可随时删除」；只记**用户明确说过**的偏好，不记推断出的身份/健康/财务等敏感信息，不记密码、令牌、证件号、住址；共享或纳入版本控制的工作区默认不写记忆（除非用户明确同意）。
7. **删除与导出**：用户说「忘掉某条」→ 删除对应行并在文件末尾记「已删除（日期）」；说「清空」→ 删除整个文件；删除只影响该文件，不影响技能本体。

## 3. 怎么应用（下次自动生效）

- 每次任务前读 `memory/user-profile.md` + `memory/rules.md`；
- 产出形态默认遵循偏好（如默认同时给 `.md` + 单文件 HTML）；
- 问问题时遵守「≤6 问、一次问完、给默认」；
- 若本次不得不偏离偏好（如用户临时说随便），在交付里写一句「本次未按你以往的 X 偏好，因为 Y」。

## 4. `memory/user-profile.md` 建议结构

```markdown
# 用户偏好（由 dsh-capability-loop 维护）
- 沟通：结论先行；先方案后执行；一次问不超过 6 个问题
- 文档：md + 单文件 html 总览；表格优先；必须带证据路径
- 设计：密度偏紧；沿用现有组件库；不接受自造 token 体系
- 验收：给命令+退出码；不能实测标「未实测+补测方式」
- 边界：不自动写 ~/.dsh；不自动更新 skill；不替实现者写代码
## 变更记录
| 日期 | 偏好 | 来源 | 状态 |
|---|---|---|---|
| 2026-11-12 | 要 html 总览 | 用户明确要求 | 生效 |
```

## 5. 体验度量（判断「是否真的越用越好」）

| 指标 | 怎么量 | 变好意味着 |
|---|---|---|
| 澄清轮数 | 一次接入问完即开工 vs 反复追问 | 下降 |
| 返工次数 | 因格式/口径/设计体系不符被打回 | 下降 |
| 用户纠正次数 | retro 中的「用户反馈」条数 | 下降（但发现新问题不算坏） |
| 门禁一次通过率 | `loop-gate` 首次 PASS 比例 | 上升 |
| 偏好命中率 | 抽样检查产出是否符合 `user-profile` | 上升 |

指标写进 `memory/team-learnings.md` 的月度复盘，不追求漂亮数字，只判断方向。

## 6. 自我升级与更新提示

- 本 skill 自身升级：`scripts/skill-status.ps1` 检查「安装版 vs 源目录」版本/哈希差 → 提示 `SOURCE-NEWER vX → vY` 与更新命令；**不自动更新**（尊重使用方修改权）。
- 用户偏好升级：写入 `memory/`，不是写进 skill（skill 面向所有人，偏好面向你）。
- 月度维护（`80-evolution.md` §7）：抽 1 条偏好验证是否仍生效；失效的打「已过期」。

## 7. 反模式

- ❌ 把「用户夸了一句」当偏好 → 偏好来自**行为与纠正**，不是客套；
- ❌ 把偏好写进 SKILL.md 正文 → 会污染通用流程；只写工作区 `memory/`；
- ❌ 记了不读 → 任务前必须读；
- ❌ 未经告知就写记忆、或把推断的身份/敏感信息写进记忆 → 违反隐私边界；
- ❌ 偷偷自动更新 skill / 推送 → 违反不干预约定。
