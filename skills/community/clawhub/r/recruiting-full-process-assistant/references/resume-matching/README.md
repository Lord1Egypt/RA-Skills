# 简历匹配度评分系统

## 一、系统概述

### 1.1 核心设计理念

**从"主观判断"到"量化匹配"**：
- 传统方式：HR 凭经验看简历 → 主观、不一致、易遗漏
- 量化方式：标签匹配 + 打分卡 → 客观、一致、可追溯

**匹配度 = 标签重合度计算**：
```
给定岗位需求标签集合 R，候选人标签集合 C：
匹配度 = |R ∩ C| / |R| × 100%

示例：
岗位需求标签：[985, 硕士，大厂，RAG, Python, AI, 3-5 年]
候选人 A 标签：[985, 硕士，大厂，RAG, LangChain, AI, 3-5 年]
匹配度 = 6/7 = 85.7% → 推荐面试

候选人 B 标签：[211, 本科，创业公司，Python, 数据分析，1-3 年]
匹配度 = 1/7 = 14.3% → 不匹配
```

### 1.2 标签体系

**7 大标签维度**：

| 维度 | 标签示例 | 权重 | 说明 |
|------|---------|------|------|
| 院校标签 | 985/211/C9/QS 前 100/海外/本科/硕士/博士 | 15% | 教育背景 |
| 公司标签 | 大厂/互联网/OTA/AI 创业/外企/国企 | 25% | 工作背景 |
| 技能标签 | RAG/Agent/招聘管理/数据分析 | 30% | 核心技能 |
| 工具标签 | LangChain/Python/SQL/飞书 | 10% | 工具熟练度 |
| 领域标签 | AI/LLM/HR/BD/产品 | 10% | 行业领域 |
| 语言标签 | 英语工作/日语 N2/CET6 | 5% | 语言能力 |
| 证书标签 | PMP/初级经济师/CET6 | 5% | 专业资质 |

**处理流程**：
1. 使用 `resume-to-tags` skill 的 `extract_tags.py` 脚本

## 三、匹配度计算

### 3.1 基础匹配度算法

```python
def calculate_match_score(job_tags, candidate_tags):
    """
    计算候选人匹配度
    
    job_tags: 岗位需求标签集合
    candidate_tags: 候选人标签集合
    
    返回：匹配度百分比
    """
    # 计算标签交集
    matched_tags = set(job_tags) & set(candidate_tags)
    
    # 匹配度 = 匹配标签数 / 岗位需求标签总数
    match_rate = len(matched_tags) / len(job_tags) * 100
    
    return match_rate, matched_tags
```

**示例计算**：

岗位需求标签（10 个）：
```
[985, 本科，3-5 年，算法工程师，RAG, Agent, LLM 应用，Python, 大厂，LangChain]
```

候选人 A 标签：
```
[985, 本科，3-5 年，算法工程师，RAG, Agent, LLM 应用，Python, 大厂，LangChain, PyTorch]
```

匹配度计算：
```
匹配标签 = [985, 本科，3-5 年，算法工程师，RAG, Agent, LLM 应用，Python, 大厂，LangChain]
匹配度 = 10/10 = 100% → 强烈推荐
```

候选人 B 标签：
```
[211, 本科，1-3 年，算法工程师，Python, 数据分析，机器学习]
```

匹配度计算：
```
匹配标签 = [本科，算法工程师，Python]
匹配度 = 3/10 = 30% → 不匹配
```

### 3.2 加权匹配度算法

**考虑标签权重**：

```python
def calculate_weighted_match_score(job_tags, candidate_tags, tag_weights):
    """
    计算加权匹配度
    
    tag_weights: 每个标签的权重（must-have 权重高，nice-to-have 权重低）
    """
    total_weight = sum(tag_weights[tag] for tag in job_tags)
    matched_weight = sum(tag_weights[tag] for tag in job_tags if tag in candidate_tags)
    
    weighted_match_rate = matched_weight / total_weight * 100
    
    return weighted_match_rate
```

**权重设置示例**：

| 标签类型 | 权重系数 | 说明 |
|---------|---------|------|
| must-have 核心技能 | 2.0 | 不满足直接淘汰 |
| must-have 基础条件 | 1.5 | 学历、年限等 |
| nice-to-have 技能 | 1.0 | 加分项 |
| nice-to-have 背景 | 0.8 | 大厂、名校等 |

### 3.3 风险点识别

**自动识别风险点**：

```python
def identify_risks(job_tags, candidate_tags):
    """
    识别候选人风险点
    """
    risks = []
    
    # 缺失 must-have 标签
    missing_must_have = set(job_tags['must_have']) - set(candidate_tags)
    if missing_must_have:
        risks.append({
            'level': 'high',
            'type': 'missing_must_have',
            'items': list(missing_must_have)
        })
    
    # 年限不匹配
    if '3-5 年' in job_tags and '1-3 年' in candidate_tags:
        risks.append({
            'level': 'medium',
            'type': 'experience_gap',
            'message': '工作年限低于要求'
        })
    
    # 频繁跳槽
    if candidate_tags.get('job_hopping', False):
        risks.append({
            'level': 'medium',
            'type': 'stability',
            'message': '存在频繁跳槽风险'
        })
    
    return risks
```

### 4.3 综合评分计算

```
综合得分 = Σ(维度得分 × 权重)

示例：
候选人 A:
- 教育背景：4 分 × 15% = 0.6
- 工作经验：5 分 × 25% = 1.25
- 技能匹配：5 分 × 30% = 1.5
- 项目经验：4 分 × 20% = 0.8
- 软性素质：4 分 × 10% = 0.4
综合得分 = 4.55 / 5.0 → 推荐面试
```

## 七、使用指南

### 7.1 何时使用

**适用场景**：
- 收到大量简历，需要快速筛选
- 多个 HR 参与筛选，需要统一标准
- 关键岗位，需要精准匹配
- 需要数据驱动招聘决策

**最佳实践**：
- 先定义岗位需求标签，再筛选简历
- 结合匹配度 + 打分卡，双重评估
- 定期回顾匹配度与面试通过率的相关性
- 持续优化标签体系

### 7.2 注意事项

**避免过度依赖**：
- 匹配度是参考，不是绝对标准
- 有些优秀候选人可能标签不全
- 需要结合 HR 的专业判断

**标签体系更新**：
- 每半年回顾标签体系
- 根据业务变化调整标签
- 收集面试官反馈，优化权重
