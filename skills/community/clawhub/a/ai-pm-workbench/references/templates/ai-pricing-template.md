## 2. AI定价6大模式

### 2.1 模式对比

| 模式 | 描述 | AI适用场景 | 优点 | 缺点 | AI产品示例 |
|------|------|-----------|------|------|-----------|
| **订阅制(SaaS)** | 按月/年固定费 | AI-Enhanced产品 | 收入可预测 | 用量差异大 | GitHub Copilot $10/月 |
| **按用量(Usage)** | 按API调用/Token/次数 | AI API/平台 | 公平透明 | 成本不可预测 | GPT-4 API |
| **按结果(Outcome)** | 按AI完成的任务收费 | Agent/自动化 | 价值对齐强 | 计量复杂 | Intercom Fin $0.99/解决 |
| **混合(Hybrid)** | 基础费+用量 | AI-Native SaaS | 兼顾稳定+弹性 | 定价复杂 | Notion AI $10+超额 |
| **按价值(Value)** | 按为客户创造的价值 | 垂直AI | ROI直接可见 | 需量化价值 | 医疗AI/按诊断 |
| **免费+增值(Freemium)** | 免费功能+付费高级AI | 个人→企业转化 | 获客快 | 转化率不确定 | ChatGPT/Cursor |

### 2.2 选型决策树

```
AI功能是产品的核心吗？
├── 是 → AI成本占比高吗(>30%)?
│       ├── 是 → 客户使用量差异大吗？
│       │       ├── 是 → 混合定价（基础+用量）
│       │       └── 否 → 按用量定价
│       └── 否 → 订阅制定价（AI作为增值功能）
└── 否 → AI是辅助功能
          └── 订阅制（含AI配额）+ AI用量超额付费
```

### 3.3 成本优化杠杆

| 优化手段 | 预估节省 | 实现复杂度 | 副作用 |
|---------|---------|-----------|--------|
| Prompt缓存 | 30-50% | 低 | 仅对重复前缀有效 |
| 模型路由（简单→小模型） | 40-60% | 中 | 复杂case可能误判 |
| 语义缓存（相似Query） | 20-40% | 中高 | 时效性要求高不适合 |
| 输出Token限制 | 10-20% | 低 | 可能截断有用输出 |
| 微调小模型替代大模型 | 50-80% | 高 | 需要训练数据+维护 |
| 批处理（非实时场景） | 50% | 中 | 延迟增加 |

### 3.4 AI毛利率计算

```
AI毛利率 = (收入 - AI推理成本 - AI基础设施成本) / 收入 × 100%

示例计算：
- 月费：$30/用户
- 月均Token消耗：500K input + 100K output
- 模型成本（GPT-4o）：$2.5/1M input + $10/1M output
- 月均AI成本：500K/1M × $2.5 + 100K/1M × $10 = $1.25 + $1.00 = $2.25
- AI毛利率：($30 - $2.25 - $3基础设施) / $30 = 82.5% ✅

目标：AI毛利率 > 60%
```

## 6. AI免费层策略

### 6.1 AI免费层设计原则

| 原则 | 说明 |
|------|------|
| 展示AI核心价值 | 免费层要让用户感受到AI的"魔法时刻" |
| 控制免费成本 | 免费用户AI成本 < 获客成本 |
| 自然转化设计 | 在用户刚需时刻触发付费（非生硬限制） |
| 用量限制优先于功能限制 | "今天的免费额度用完了" 好于 "这个功能要付费" |
| 个人→团队转化 | 免费层培养个人用户→付费转化团队 |

### 6.2 免费层成本控制

| 方法 | 说明 |
|------|------|
| 使用更便宜的模型 | Free用GPT-4o-mini, Pro用GPT-4o |
| 更低的Token限额 | 限制上下文长度和输出长度 |
| 延迟降级 | 免费请求队列优先级低 |
| 缓存优先 | 免费请求优先使用缓存结果 |
| 广告/水印 | 非付费用户输出带品牌标识 |

## 7. 按结果定价深入

### 7.1 适用场景判断

```
以下条件满足得越多，越适合按结果定价：
□ AI完成的是完整任务而非辅助
□ 任务结果可清晰定义和验证
□ 任务价值可量化（节省了多少人力/时间）
□ 客户对AI的信任度足够高
□ AI成功率和成本可预测
□ 竞争格局适合差异化定价
```

| 产品类型 | 计费单位 | 结果定义 | 验证方式 |

| AI招聘 | 筛选通过的候选人 | 进入面试阶段 | ATS系统回调 |

| AI代码 | 合并的PR | 代码被合并 | Git webhook |

| 定价锚点 | 展示最贵套餐 | 不展示 | 中间套餐选择率 |

### 10.2 定价敏感度测试

```
Van Westendorp价格敏感度模型：
Q1: 价格多少你觉得太便宜而质疑质量？  → PMC (Point of Marginal Cheapness)
Q2: 价格多少你觉得是划算的？          → PME (Point of Marginal Expensiveness)  
Q3: 价格多少你觉得开始觉得贵了？      → IDP (Indifference Price Point)
Q4: 价格多少你觉得太贵了无法接受？    → OPP (Optimal Price Point)

最优价格区间：IDP ~ OPP
```
