# refine 规程 — 知识回流与自动完善

两条路径：**日常回流**（单条知识即时回写）与**增量重蒸**（`/distill <domain> --refresh` 全量融合）。

## 一、日常回流（使用中发现新知识/错误）

### 触发条件（满足其一）

1. 修复了一个 kb 未覆盖的 bug/坑 → 最高价值回流，标注 `[实战回流]`
2. 发现 kb 中过时或错误的内容
3. 官方发布大版本/破坏性变更
4. 用户明确要求「回写/回流/更新知识库」

### 回写格式

向对应 kb 文件的合适小节**追加**结构化条目（不重写整节）：

```markdown
### <标题> [实战回流] <YYYY-MM-DD>
- 症状：
- 根因：
- 修复：<错误代码 vs 正确代码对照>
- 来源：<修复该问题的会话/PR/工单，或官方文档 URL>
```

### 回写纪律

1. 更新该文件 frontmatter：`version` +1、`updated` 改为当日。
2. 在「来源索引」小节补充新来源。
3. kb 错误时：修正条目并在「冲突消解记录」登记原错误内容与修正依据；**不静默删除**。
4. 涉及 SKILL.md 的 Top 坑点清单且新坑足够高危 → 同步更新 SKILL.md 内联摘要。
5. 回写后运行校验脚本确认未破坏结构。
6. 红线/阈值/命名类规范变更必须**全库 grep 旧值确认清零**后才算完成（防止只改一处漏一片——300KB→2MB 曾漏改 5 处即是教训）。

## 二、增量重蒸（/distill <domain> --refresh）

1. 重跑阶段 1（萃取）与阶段 2（抓取），进入**合并非覆盖**模式：
   - kb 条目按主题/坑点粒度合并；已存在且未变化的条目保留原文、原标注、原 version。
   - 文档版本变化 → 更新「版本注意」小节，在「冲突消解记录」登记。
   - 新坑点/新主题 → 追加。
   - 被新证据证伪的条目 → 移除并记录原因（进「冲突消解记录」，不静默删除）。
   - 扩展子领域（配置 `spin_off_subdomains`）**不参与常规重蒸**；仅当 `corpus_home` 寄居语料更新时手动重蒸对应 kb（合并非覆盖规则同上）。
2. `[实战回流]` 条目在重蒸中**永不覆盖**，除非有明确证据证明其已失效。
3. **横切文件对账（强制，不可静默跳过）**：各 subdomain kb 合并完成后、进入阶段 4/5 前，逐一对账横切产物：
   - `gotchas.md`：新增坑点按「Top 判定标准」（见 prompts/distill.md）筛选——达标则追加条目并续号；不达标在文件尾「对账记录」登记豁免。
   - `ai-mistakes.md`：本轮自我质询轮新增的 AI 典型错误 → 追加；无 → 豁免登记。
   - `laws.md`（全局宪法）：本轮产生/修订 `[GLOBAL]` 候选 → 合并升维；无 → 豁免登记。
   - `SKILL.md` Top 坑点/法则内联摘要：新坑达到 Top 判定标准 P0 级 → 同步更新；否则豁免登记。
   - 对账结果统一记入各横切文件尾「对账记录」表：`| 轮次 | 结果（新增 N 条/豁免） | 日期 |`——**新增与豁免二选一，不允许什么都不写**。
4. 合并完成后正常走阶段 4（SKILL.md 更新）与阶段 5（校验）。

## 三、与首次蒸馏的区别

| | 首次 `/distill` | 日常回流 | `--refresh` |
|---|---|---|---|
| 范围 | 全领域 | 单条知识 | 全领域 |
| 覆盖策略 | 全新产出 | 追加 | 合并非覆盖 |
| 版本更新 | 全量 | 顺带 | 核心目的 |

## 四、深化轮操作约定（空白带选题，成文以消除会话部落知识）

增量重蒸用于「富子域继续深挖空白带」时，遵循以下约定：

1. **选题（语义级去重）**：候选主题对照既有 kb + 全部 elicited 做 grep 关键词计数（命中 0~2 次为空白带候选）+ 实读上下文核验（防误匹配与浅提及）；宁缺毋滥，只打空白带，不重复已覆盖主题。
2. **编号续接**：
   - elicited 文件：`<NN>-<topic>.md` 续接该 subdomain 现有最大号；
   - kb 法则：续接该前缀 audit 基线最大号（合并前先跑编号审计记基线：react 域 `audit_refs_react.py`、ui-ux 域 `audit_refs.py`）；
   - kb 坑点：续接「高频坑点」速查表现有最大行号。
3. **来源索引轮次命名**：新增来源以「### 第 N 轮新增（<主题>）」小节追加，N 续接该 kb 现有最大轮次；官方文档可注明 `lastUpdated`。
4. **audit 基线对齐**：合并后各前缀 `n = max` 连续无缺口、断链 0、孤儿 0；新增法则数 = 基线差值，不符即排查漏改。
5. **验证顺序**：`validate_skill.py` → 编号审计（react 域 `audit_refs_react.py` / ui-ux 域 `audit_refs.py`）→ `spot_check.py`（URL 抽查）→ 横切对账（见二之 3）。校验前先过 validate.md「终稿锁定（前置门槛）」。
6. **风格红线**：hex 小写；禁 emoji；中文正文、API 名/术语/报错保留英文原文；中文 UTF-8 每字符 3 字节计体积。

## 五、附录：容量预案与挂账复核（2026-11-18 项目评审 P0/P2 落地）

### LAW 达顶预案（ai-docgen laws.md 当前 19/20，余 1 位）

- 余位（第 20 位）收录标准，三条全满足才可用：
  1. 跨 ≥3 子域成立，且各成立点为该子域**主干场景**（非边缘提及）；
  2. 有官方锚背书，或 ≥3 子域模型知识交叉验证；
  3. 与既有 LAW-1~19 无语义重叠——重叠即并入既有条款修订、不开新条（G4 关闭先例：与 LAW-18「异常态必须显性」重叠即不收，除非出现独立成立点不再复议）。
- 达顶后：新候选一律走「并入既有 LAW」路径（修订条款 + 溯源登记合并 + 对账记录登记）。
- 域层 subdomain 法则 15 硬顶同理（第六轮 PJ 并入映射为操作先例：可判定表达 ×3 → LAW-17、schema 迁移 → PT-10 等）。

### description 精简规程（ai-docgen SKILL.md description 当前 977/1024，余 47 字符）

1. **触发条件**：新增子域所需触发关键词总字符数 > 当前余量。
2. **精简顺序**（先低损后高损）：同义词合并（保留检索高频词）→ Covers 尾部低频触发词删减 → 长词截短（不损义）→ 重组触发词分组语序。
3. **前置校验**：精简后 MUST 跑 `validate_skill.py --keywords <域配置全量关键词>` 回归，覆盖率不得低于精简前（ai-docgen 现基线 100%）。
4. **登记**：SKILL.md 对账记录登记精简明细（删了什么、为何安全）。
5. description ≤1024 为质量红线，不为塞关键词牺牲第三人称/关键词前置公式。

### 存留挂账项复核排期

- 各 kb「未经文档验证声明」清单中的长期存留项（如 commitlint/husky 工具链用法、NestJS/tsoa/swagger-jsdoc 语法细节、ESDoc 维护状态待考），每次 `--refresh` 轮 MUST 顺带复核：重试可达性一次或确认维持降级，并在该项尾部更新 `（lastReviewed: YYYY-MM-DD）` 标注；已解决项从清单移除并注明去向（第 7 轮 MADR 状态枚举、ApiExtractor 配置细节为先例）。
- 豁免登记同样适用定期复核：豁免是资产不是暗门。
