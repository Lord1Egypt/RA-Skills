## B4 机械任务查询化：先对账、后语义审查

机械对账只负责提取集合、计数和字段差异；它不替代 T7/T8 对理论、证据充分性、反方质量、作者声音和发表适配的语义判断。每次运行先产出结构化结果，再由审计角色解释异常。

```yaml
mechanical_reconciliation:
  citation_reconciliation:
    body_refs: 0
    registered_cards: 0
    matched: 0
    body_without_card: []
    card_without_body: []
    duplicate_identifiers: []
    semantic_review_required: []
  data_reconciliation:
    body_data_refs: 0
    registered_data_cards: 0
    verified: 0
    unresolved: []
    missing_fields: []
  gate_coverage:
    declared: 0
    executed: 0
    skipped: []
    missing_reason: []
    false_green_risk: []
  version_reconciliation:
    expected: ""
    matched: []
    mismatched: []
    generated_views_stale: []
  verdict: pass | fail | path_or_param_error | not_enabled
```

硬规则：

1. `body_without_card`、`card_without_body`、`unresolved`、`mismatched`、`skipped` 不能被计入 matched/verified/executed；
2. 机械计数必须保留异常清单，不能只回传一个总数；零异常也要记录扫描范围和 ``；
3. `gate_coverage.declared != gate_coverage.executed + len(skipped)` 时，判 `path_or_param_error` 或 `fail`，不得绿灯；
4. `false_green_risk` 非空时不得写 `pass`；
5. 机械对账完成后，T7/T8 才做语义审查；机械 `pass` 不等于整项质量通过。

**G15 主张强度校准（借 writing-guard EVIDENCE 层「双轴主张模型」）**：对每个核心论点的谓语动词做**双轴强度标记**，修订/润色后与原稿比对——**只能平移（同强度换词）或变弱（降档），禁止变强（升档）**。
- 轴 1 因果力（0-5）：`0 并列/一致`（与…一致/并存/未发现关联）→ `1 相关`（相关/关联/伴随）→ `2 预示`（预示/预测/提示…可能）→ `3 贡献`（贡献于/促成/参与）→ `4 影响`（影响/作用于/调节/驱动）→ `5 强因果`（导致/造成/引起/决定）
- 轴 2 证据力（1-5）：`1 推测 hedged`（可能/或许/推测/初步提示）→ `2 相关 correlated`（相关性/关联性）→ `3 支持 supportive`（支持/佐证/印证）→ `4 直接 direct`（直接表明/实验证实/数据显示）→ `5 确立 established`（已确立/公认/充分证明）
- 判定：修订后任一核心论点**因果力或证据力升档**（如「与…相关」(1) → 「导致」(5)，或「可能」(hedged) → 「充分证明」(established)）= 门故障（P1）；**平级换词/降档 = 通过**
- 豁免（窄口）：修订说明明确记载「新增证据支撑强度升级」（如 T5 补充新数据卡 Dxx），且经 T7 核验证据真实存在 → 允许升档，但须在修订说明披露

**G16 上下文泄漏反向反查（借 writing-guard DELIVERY 层「Context-to-Artifact Leakage」）**：反向反查「写作过程上下文」是否漏进成品（**G13 只声明 AI 身份，本项反查过程残留**）：
1. **被否决方案残留**：「尝试过 XX 不行」「放弃 XX 方案」「改用 XX」
2. **修订过程残留**：「如审稿人要求」「根据修改意见」「按 T5 修订」
3. **来源 metadata 泄漏**：作者邮箱 / 内部 ID / 工作笔记路径

5. **任务书指令残留（v2.15.13 反哺 FB-07/FB-02a，机械判据）**：T6/T7 修订任务书的祈使句被写手原样粘进正文——模式：`须[^。；]{0,12}：`（冒号结尾的任务指令，如「须明示本文与 XX 的论辩位置：」「须回应治理路径的核心分歧：」「同时须自评局限：」）/ `本节须` / `应修改` / `需补充` / `给写手的话`。**命中 > 0 即 P1，零 LLM 成本机械判**。豁免（whitelist）：直接引语（引号内）/ 法条·文献原文引述 / G14 结构必写段。实测 2026-10-06：v2 内嵌 13 处，T6/T7/G14 三层防御全数漏过；v3 修订后仍残留 4 处且自报「全部清除」与实测不符——自报不替代机械门
- 判定：任一命中 → P1（过程上下文不得漏进成品，与 G14 风格净化、M-Form-4/5 元数据/过程语言互补）
- 触发时机：T7 审计 + T8 终检（两处覆盖，防 CAL 从前一处漏到后一处）

**G17 数据指纹比对（借 writing-guard EVIDENCE 层「Scholarship Lock」）**：对正文所有硬数据点（数字 / 单位 / p 值 / DOI / 统计量）做**修订前后精确比对**——修订 / 润色后数据指纹必须与修订前一致，**不可静默改写**（与 G2 数据溯源互补：G2 看「数字有无来源」真实性，G17 看「数字在修订中变没变」完整性）：
1. **数据指纹清单** = 正文每个 `[Dxx]` 数据卡引用的具体数值 + 单位 + 统计量（p 值 / 效应量 / 百分比）+ DOI / 文献标识符
2. **修订前后比对**：修订稿（vN+1）任一数据指纹与修订前（vN）不一致 → 须在修订说明逐条披露「数据修正 + 回查一手来源依据」（回查一手来源机制见 T5 卡第 13 条）
3. **静默改写判定**：改了数据但修订说明未披露 → **P1**（数据完整性失守，Scholarship Lock）
4. **豁免（窄口）**：修订说明明确记载「数据修正依据」+ T7 核验回查依据真实 → 允许改，但须披露

### 轻量档字数敏感度矩阵

> 分档原则：缺失该门是否可能造成事实错误、证据失真或引用不可追溯？会 → **高**，轻量档全量执行；不会但会影响结构判断 → **中**，执行核心子项并记录豁免；主要属于表达/呈现 → **低**，轻量档可跳过但必须写 `n/a` 与理由。该矩阵只决定轻量档审计深度，不改变全量档覆盖。

| 门/门组 | 敏感度 | 轻量档执行口径 |
|---|---|---|
| G0/G1/G2/G11/G12/G13 | 高 | 全量；事实、引用、时效、信任与披露不得因短文省略 |
| M-Form/M-Exist/M-Integrity | 高 | 全量；路径、证据包、信任级别和阶段完整性全跑 |
| G3/G4/G5/G6/G7/G9/G10 | 中 | 跑核心项：论点—论据、章节顺序、反方回应、术语首现与关键结构；次级呈现项记 n/a |
| G8 字数档位 | 中 | 按唯一真源判定表记录档位；不把轻量档误判为全量篇幅要求 |
| G14 | 中 | 含中文走 selfcheck；仍检查九类核心信号与声音保留反查 |
| G15/G16/G17/G18 | 中 | G15/G16/G17 跑核心项；G18 2000-3000 字只核前 6 项，其余显式 n/a；≤2000 字整段 n/a |
