# The journey: seven stages and how they relate

> **When to read**: you need to decide what a request depends on; the person enters in the middle (a decision, a build, a review) and you must judge how much of the earlier stages to do; or a run stalls and you suspect a stage was skipped.

The journey offers seven selectable directions that help people find the question they care about, choose methods, and see how capability has grown. It describes **the understanding and results the present work depends on**. Conditions already satisfied are used directly; new feedback can enter from any direction.

```text
   ┌────────────────────────────────────────────────────────────────┐
   ▼                                                                │
 See ──► Explain ──► Anticipate ──► Focus ──► Decide ──► Create ──► Improve
   ▲         ▲            ▲                                         │
   └─────────┴────────────┴───── new evidence sends you back ───────┘
└───── see how it really works ─────┘ └ know what to do ┘ └ make it real ┘ └ keep getting better ┘
```

## The seven stages

| Stage | The question | The ability it takes | It is done well when |
|---|---|---|---|
| **1 · See** | "What is it, and how does it work?" | Map the whole; see structure beneath events; follow what flows; find the loops; size it | The person can say in one sentence how it works, and the sentence is not the obvious one |
| **2 · Explain** | "Why is it like this?" | Break it down to what must be true; trace its history; find what limits it; follow the incentives; see it through other eyes | The explanation predicts something that can be checked, and names what would prove it wrong |
| **3 · Anticipate** | "What will happen? What if?" | Follow consequences and their consequences; ask what would make it fail; follow ripples into other systems | There are several distinct futures, each with the early signal that would announce it |
| **4 · Focus** | "Where does effort matter most?" | Find the few places where a push changes the most | A short ranked list, with effect and cost, and the many things not worth doing named as such |
| **5 · Decide** | "What is the best way for us?" | Discover, compare and adapt practices; weigh options and their reversibility | A recommended path that fits these conditions, what it costs, when it would change, and a cheap first test |
| **6 · Create** | "Make it real." | Turn understanding into deliverables; design; connect parts into a new capability | Something finished exists and works: a deliverable someone would sign, a capability validated on real work |
| **7 · Improve** | "Did it work? What now?" | Compare results with intent; learn; watch for the signals that matter | The system's understanding and practices have actually changed, and something is being watched |

People hear four phases: **see how it really works** (See, Explain, Anticipate) · **know what to do** (Focus, Decide) · **make it real** (Create) · **keep getting better** (Improve). Use the four phases when you talk to the person. Use the seven stages when you think.

## How the stages relate

**Effective work lends power across directions.** A grounded projection can draw on a model that explains the phenomenon. A prototype may in turn make the real problem visible. Creation can enter through a clear trust, an existing tool, a sketch, or an experiment. Look at what the present result needs, then use existing understanding or supply what is missing.

**Backward: Improve feeds every earlier stage.** A result that differs from the intent is new evidence about how the system works, why, and what it will do. Send it back to wherever it belongs: a wrong picture, a wrong cause, a missed consequence, a wrong point of leverage, a practice that did not fit. This is why a system gets better and a chat does not.

**Enter anywhere.** People arrive where their need is. Someone asking "should we raise prices or cut costs?" has entered at Decide. Someone saying "turn this into a video" has entered at Create. Do whatever earlier stages the request depends on, quietly and in proportion:

- If the person's system already holds the earlier understanding, use it and do not redo it.
- If it does not, do enough of the earlier stages to make the answer sound, and show only what the answer needs. The person asked for a decision, not for a tour.
- If an earlier stage turns up something that changes the question itself, say so. That is often the reveal.

**Leaving early is fine.** Not every request should travel to Improve. "Help me understand ___" is complete at a deliverable. What matters is that the system records where things stopped, so a later run continues from there.

**It is a dependency map.** The seven directions reveal which understanding and capabilities a complete result rests on. The system can enter from any real position, return to evidence, change scale, or open several directions in parallel. The user experiences how a discovery forms and what they can now do with it.

## The six questions beneath the stages

The six zero-level questions (distinction, time, space, state, interaction, constraint) are asked at every stage. Each method is a well-known way of pressing one or two of them in a particular direction:

| Method family | Presses mainly on |
|---|---|
| Open, Boundary, Scale | Distinction and space: what the thing is, where it ends, at which scale it is this thing |
| X-ray, Loops, Flow, Connect, Emergence | Interaction: what affects what, what accumulates, what feeds back |
| Trace, What-if, And Then What? | Time: how it formed, what follows, with what delay |
| Size It, Vital Few, Watch | State: how large, how concentrated, how it is moving now |
| First Principles, Bottleneck, Contradiction, Variety, Viability | Constraint: what must be true, what limits it, what it cannot do without |
| Incentives, Shift | Interaction among people: who wants what, and what each one sees |
| Leverage, Best Practice, Weigh, Design, Build, Review | The questions turned toward action: where to push, what fits, what to make, what happened |

When no named method fits the subject, go back to the six questions. They always apply. The methods exist because their names are known and their results are recognizable, not because they exhaust the ways of thinking.

## Judging how far to go

Full power is the default (see `../../SKILL.md`). The system actively supplies the understanding, testing, and capability the current result truly depends on, so the user receives completion equal to the problem's scale.

- **A reliable picture has faced contradiction.** Understanding undergoes at least one test that could overturn it: check a prediction, seek a counterexample, or compare another explanation.
- **A usable recommendation carries conditions.** The path states what it depends on, when it would change, and how to validate it at low cost.
- **A finished work has been experienced.** A work that can render, run, or open has actually been viewed, used, and revised before delivery.
- **Evolution leaves a future difference.** Valuable understanding, works, capabilities, relations, or corrections enter the corresponding system. When no change deserves persistence, the work itself still remains complete.

## The journey seen from the side of practice

Best-practice research is the same journey: understand the system and find the capability gulf (See, Explain) → anticipate consequences and choose a path worth trying (Anticipate, Focus, Decide) → build connections, run the practice, test at low cost (Create) → the system changes in state, structure, practices, or goals (Improve) → the next round. See `../../engines/build.md`.

## Human capability grows along the journey

A person's growth follows the same path: seeing structure, explaining causes, anticipating consequences, finding leverage, choosing what fits, creating, and improving. See `../../system/growth.md`.
