# Pitch Deck Outliner

## Overview

Decks fail when they are feature lists. This outline forces the narrative first — each slide earns its place by advancing one argument — so the designer is illustrating a story, not inventing one.

## When to use

Before creating any pitch, partner deck, or demo-day presentation.

## Workflow

1. **Write the one-sentence story** — 'X has problem Y; we discovered Z; our product does W; proof P; we need A'
2. **Assign one job per slide** — problem, insight, product, how it works, proof/traction, market, model, team, ask; a slide with two jobs gets split or cut
3. **Put proof as early as honesty allows** — the strongest evidence slide should not be last
4. **Make the ask concrete** — amount, use of funds by category, and what it buys in milestones
5. **Cut to the bone** — if a slide does not change the audience's decision, it is decoration; delete it
6. **Write the speaker notes' first line per slide** — the sentence you will actually say

## Guardrails

- Never project numbers you cannot explain the derivation of, live, on one slide
- Never hide the strongest objection — address it before the audience raises it
- Traction claims must be checkable; vanity metrics read as such

## Output format

A deck outline: the one-sentence story, slide list with each slide's job and key content, the ask breakdown.
