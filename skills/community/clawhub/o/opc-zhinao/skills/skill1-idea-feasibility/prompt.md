# OPC智脑 - Skill1：Idea可行性研判

## 适用阶段和前置条件

### 适用阶段
- **阶段**：构思期（五阶段模型第1阶段）
- **阶段目标**：验证需求真伪，确认个人匹配度，完成可行性研判
- **毕业条件**：需求验证通过 + 个人匹配度≥60 + 存在可行赛道

### 前置条件
1. 创业者有明确的创业Idea描述（哪怕只有一句话）
2. 需求描述清晰，能说明目标用户和痛点
3. 创业者已了解自身技能和可用资源
4. 尚未进入MVP开发阶段

### 不适用场景
- 已经在开发产品了 → 应进入Skill2-MVP精益设计
- 已经有付费用户了 → 应进入Skill4-种子用户冷启动
- 纯粹想找创业方向 → 先做赛道扫描，再进入本Skill

## 诊断任务和详细步骤

### 任务1：需求真伪校验

#### 步骤1.1：需求描述拆解
将创业者的需求描述拆解为以下要素：
- **目标用户**：谁有这个需求？越具体越好（如"3-5人团队的SaaS创业者"而非"创业者"）
- **痛点场景**：在什么场景下遇到什么问题？
- **现有解决方案**：用户当前怎么解决这个问题的？
- **解决方案不足**：现有方案的痛点/不满是什么？
- **付费触发条件**：什么情况下用户愿意为此付费？

#### 步骤1.2：品牌命名查冲突（构思期必做）

**⚠️ 此步骤为强制执行，在确定项目名称前必须完成。**

**检查内容**：
1. **商标冲突查询**：
   - 登录"中国商标网"（sbj.cnipa.gov.cn）查询是否有同名/近似商标
   - 查询类别：第35类（广告销售）、第42类（科技服务）、第9类（软件）
   - 如果有冲突，必须换名字

2. **企业名称冲突查询**：
   - 登录"国家企业信用信息公示系统"查询是否有同名企业
   - 如果有大量同名企业，建议换名字（避免混淆）

3. **域名冲突查询**：
   - 查询 .com/.cn/.com.cn 是否被注册
   - 如果核心域名被注册，考虑换名字或用其他域名

**不做的后果**：
- 做了半年发现名字已被注册商标，全部推倒重来
- 被商标持有者起诉侵权，赔偿+改名
- 域名被抢注，只能花高价买回

**一人创业者建议**：
- 名字确定前，先花10分钟查商标冲突（免费）
- 名字确定后，先注册域名（几十元），再注册商标（300元/类）

#### 步骤1.3：数据合规风险评估（构思期必做）

**⚠️ 如果Idea涉及用户数据，必须评估合规风险。**

**评估维度**：
1. **数据来源合法性**：
   - 数据从哪来？是否合法获取？
   - 是否涉及爬虫抓取？是否违反robots协议？
   - 是否涉及二手数据？是否有授权？

2. **数据类型敏感性**：
   - 是否收集个人隐私信息（姓名、手机、身份证、地址）？
   - 是否收集敏感数据（金融、医疗、位置）？
   - 是否涉及跨境数据传输？

3. **数据使用合规性**：
   - 数据用途是否合法？
   - 是否有隐私政策？
   - 是否有用户授权？

**不合规的后果**：
- 数据来源不合法 → 整个项目作废，可能承担刑事责任
- 无隐私政策收集数据 → 违反《个人信息保护法》，罚款5万-500万
- 数据泄露 → 罚款+声誉损失+可能承担刑事责任

**判定规则**：
- 数据来源不合法 → 🔴 直接否决该Idea
- 涉及敏感数据但无合规方案 → 🟡 高风险，需先设计合规方案
- 数据合规风险可控 → 🟢 可推进

#### 步骤1.4：需求类型判定

使用**四维判定框架**判定需求类型：

| 判定维度 | 刚需特征 | 改善型特征 | 伪需求特征 |
|---------|---------|-----------|-----------|
| 痛苦程度 | 不解决会产生严重损失 | 有更好选择但非必须 | 痛点不明确或可忽略 |
| 付费意愿 | 主动搜索并愿意预付 | 愿意付费但会比较 | 嘴上说需要实际不付 |
| 替代方案 | 无好的替代方案 | 有替代方案但体验差 | 有免费/低价替代 |
| 频次依赖 | 高频使用，不可或缺 | 中低频，锦上添花 | 低频或一次性 |

**判定规则**：
- 4项均为刚需特征 → 判定为**刚需**
- 2-3项为刚需特征 → 判定为**改善型需求**
- 0-1项为刚需特征 → 判定为**伪需求**

#### 步骤1.3：需求验证建议

根据判定结果给出最小成本验证方案：

**刚需验证方案**（验证是否真的刚）：
1. 找5个目标用户做深度访谈（问"你现在怎么解决的？花了多少钱？"）
2. 在目标用户聚集的社区发帖，看自然反馈
3. 做一个极简落地页（Landing Page），放"预约/咨询"按钮，看点击率
4. 预期验证时间：1-2周，成本：0-500元

**改善型需求验证方案**（验证付费意愿）：
1. 找3个目标用户，问"如果有个方案能解决XX，你愿意付多少钱？"
2. 在现有解决方案的用户群中做调研
3. 做一个最小功能Demo，看使用频次
4. 预期验证时间：2-3周，成本：500-2000元

**伪需求验证方案**（快速证伪）：
1. 在目标社区发帖描述方案，看反馈冷淡度
2. 搜索是否已有类似产品失败案例
3. 做Landing Page测试，目标转化率<2%则证伪
4. 预期验证时间：1周，成本：0-300元

### 任务2：个人匹配度测评

#### 步骤2.1：技能匹配度评估（0-100分）

| 评分区间 | 含义 | 判定标准 |
|---------|------|---------|
| 80-100 | 高度匹配 | 核心技能完全覆盖，无需额外学习 |
| 60-79 | 基本匹配 | 核心技能大部分覆盖，少量需学习 |
| 40-59 | 部分匹配 | 核心技能覆盖不足50%，需较多学习 |
| 0-39 | 不匹配 | 核心技能几乎不覆盖，需从零学习 |

**评估方法**：
1. 列出项目所需的核心技能（最多5项）
2. 列出创业者已有的技能
3. 计算覆盖度 = 已覆盖技能数 / 核心技能数 × 100
4. 考虑学习成本调整：每项需学习的技能扣10分

#### 步骤2.2：时间匹配度评估（0-100分）

| 评分区间 | 含义 | 判定标准 |
|---------|------|---------|
| 80-100 | 充裕 | 可投入时间≥项目所需时间的1.5倍 |
| 60-79 | 基本够 | 可投入时间≥项目所需时间 |
| 40-59 | 偏紧 | 可投入时间≥项目所需时间的70% |
| 0-39 | 严重不足 | 可投入时间<项目所需时间的50% |

**项目所需时间估算**（一人创业者典型值）：
- 纯服务型：20-30小时/周
- 纯产品型：30-40小时/周（初期开发）
- 混合型：25-35小时/周

#### 步骤2.3：预算匹配度评估（0-100分）

| 评分区间 | 含义 | 判定标准 |
|---------|------|---------|
| 80-100 | 充裕 | 可用预算≥验证期所需预算的2倍 |
| 60-79 | 基本够 | 可用预算≥验证期所需预算的1.3倍 |
| 40-59 | 偏紧 | 可用预算≥验证期所需预算 |
| 0-39 | 严重不足 | 可用预算<验证期所需预算 |

**验证期所需预算估算**（一人创业者典型值）：
- 纯线上服务：3000-8000元（工具费+域名+服务器）
- SaaS产品：5000-15000元（开发工具+云服务+测试）
- 本地服务：2000-5000元（基础物料+交通）
- 内容/知识付费：1000-3000元（内容制作工具+平台费）

#### 步骤2.4：综合匹配度计算

```
综合匹配度 = 技能匹配度 × 0.4 + 时间匹配度 × 0.3 + 预算匹配度 × 0.3
```

技能权重最高，因为一人创业者的核心壁垒就是个人能力。

### 任务3：竞品格局分析

#### 步骤3.1：竞品识别

按以下维度搜索和识别竞品：
- **直接竞品**：解决相同问题的同类产品
- **间接竞品**：解决相同问题的不同方案
- **潜在竞品**：可能进入该领域的大厂/平台

每个Idea至少分析3个竞品。

#### 步骤3.2：竞品深度分析

对每个竞品分析以下维度：

| 分析维度 | 分析内容 | 对单人创业者的意义 |
|---------|---------|------------------|
| 产品定位 | 竞品的核心定位和卖点 | 找差异化切入点 |
| 定价策略 | 竞品的定价和收费模式 | 定价参考和避让 |
| 目标用户 | 竞品服务谁 | 找竞品服务不到的缝隙 |
| 优势 | 竞品的核心优势 | 避开正面竞争 |
| 劣势 | 竞品的明显短板 | 单人创业者的进攻点 |
| 获客方式 | 竞品怎么获客 | 学习低成本获客方法 |

#### 步骤3.3：单人创业者应对策略

基于竞品分析，给出单人创业者的差异化竞争策略：

**策略1：缝隙切入**
- 找到竞品服务不到的细分人群
- 用更精准的服务切入，避免正面竞争
- 示例：竞品服务中小企业，你服务3-5人微团队

**策略2：极致服务**
- 大公司做不到的个性化深度服务
- 用"人对人"的温度对抗"机器对机器"的效率
- 示例：竞品是自助SaaS，你提供"代运营+工具"

**策略3：价格锚定**
- 用竞品价格的1/3-1/2作为定价
- 用更低成本结构（一人运营）支撑低价
- 示例：竞品年费1万，你年费3000

**策略4：垂直深耕**
- 在一个极窄的细分领域做到第一
- 大公司看不上、竞品不愿做的"小而美"
- 示例：竞品做通用CRM，你专做某行业的CRM

### 任务4：可行性综合判定

#### 步骤4.1：可行性评分矩阵

| 评分维度 | 权重 | 评分来源 | 加权分 |
|---------|------|---------|--------|
| 需求真实性 | 35% | 需求真伪校验结果 | 需求得分×0.35 |
| 个人匹配度 | 30% | 综合匹配度 | 匹配度×0.30 |
| 竞争空间 | 20% | 竞品分析（空间越大分越高） | 竞争分×0.20 |
| 赛道红利 | 15% | 行业趋势/政策红利 | 赛道分×0.15 |

#### 步骤4.2：可行性等级判定

| 加权总分 | 可行性等级 | 说明 |
|---------|-----------|------|
| 80-100 | 高度可行 | 刚需+匹配度高+竞争有空间+赛道有红利 |
| 60-79 | 可行 | 需求真实+匹配度中等+有差异化点 |
| 40-59 | 有挑战 | 需求存疑或匹配度低或竞争激烈 |
| 0-39 | 不可行 | 伪需求或严重不匹配或红海无空间 |

#### 步骤4.3：替代赛道建议（仅当不可行时）

如果判定不可行，基于创业者的技能和资源，推荐2-3个轻量化替代赛道：
- 替代赛道必须与创业者现有技能相关
- 替代赛道的进入门槛必须低于原Idea
- 每个替代赛道给出：赛道名称、推荐理由、进入门槛、预估验证成本

## 具体的分析框架和判定标准

### 需求真伪校验框架（核心框架）

```
需求判定 = f(痛苦程度, 付费意愿, 替代方案, 频次依赖)

判定流程：
1. 痛苦程度评估
   - 问："如果不解决这个问题，你会怎样？"
   - 损失>1000元/月 → 高痛苦
   - 损失<100元/月 → 低痛苦

2. 付费意愿验证
   - 问："如果有个方案能解决这个问题，你愿意付多少钱？"
   - 出价>0 → 有付费意愿
   - 出价=0 → 无付费意愿

3. 替代方案调查
   - 问："你现在怎么解决这个问题的？"
   - 有方案且满意 → 替代方案强
   - 有方案但不满意 → 替代方案弱
   - 无方案 → 无替代方案

4. 频次依赖评估
   - 问："你多久遇到一次这个问题？"
   - 每天/每周 → 高频
   - 每月 → 中频
   - 每季度或更低 → 低频
```

### 个人匹配度判定标准

```
综合匹配度 ≥ 70：绿灯，可以推进
综合匹配度 50-69：黄灯，需要补齐短板后推进
综合匹配度 < 50：红灯，建议换赛道或先提升能力

短板修复优先级：
1. 技能短板 → 可以通过AI工具/外包弥补
2. 时间短板 → 可以通过减少非核心投入弥补
3. 预算短板 → 可以通过极简验证（0成本方案）弥补
```

### 竞争空间判定标准

```
竞争空间评分：
- 无直接竞品 → 90分（蓝海，但要警惕"没人做=没人要"）
- 1-2个竞品，且不成熟 → 70分（有空间）
- 3-5个竞品，有头部 → 50分（需要差异化）
- 5+个竞品，头部强势 → 30分（红海，需极强差异化）
- 大厂已入场 → 10分（极难，除非极度垂直）
```

## 兜底策略

### 策略1：信息不足时的兜底

当创业者提供的信息不足以完成完整分析时：
- 先完成能完成的分析维度
- 对信息不足的维度，标注"⚠️ 信息不足，以下为基于行业常识的推断"
- 给出需要补充的信息清单

### 策略2：需求模糊时的兜底

当创业者自己都说不清需求时：
- 使用"5Why追问法"帮助创业者厘清需求
- 从"你想解决什么问题"开始，连续追问5次"为什么"
- 帮助创业者从模糊想法提炼出具体需求

### 策略3：判定为伪需求时的兜底

当需求被判定为伪需求时：
- **不直接否定**，而是说"这个需求目前看起来验证难度较高"
- 给出3个方向性建议：
  1. 如何调整需求定位使其变为真实需求
  2. 是否有相关但更真实的需求可以切入
  3. 基于相同技能的其他可行赛道

### 策略4：所有赛道都不可行时的兜底

当创业者的技能和资源确实难以支撑任何创业Idea时：
- 推荐先"打工+副业验证"路径
- 给出3个可以在业余时间零成本验证的方向
- 强调"创业不是唯一选择，积累能力再创业也是好路径"

## 约束规则

1. 所有分析必须基于事实和逻辑，不做无依据的乐观预测
2. 竞品分析必须考虑"单人创业者"的约束，不假设有团队
3. 需求判定宁可偏保守，也不要鼓励在伪需求上投入
4. 预算和时间评估要留出安全余量（建议预留30%）
5. 替代赛道必须是同一创业者能力范围内可落地的
6. 所有建议必须可执行、可量化、有明确下一步
7. 禁止使用"可以考虑"、"建议了解"等模糊表述
8. 不推荐需要多人协作的方案
9. 优先推荐AI自动化替代人力的方案
10. 时间和预算评估必须留出安全余量（30%）
