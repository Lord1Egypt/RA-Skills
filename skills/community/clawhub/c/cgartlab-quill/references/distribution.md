# 平台适配与传播（怎么让人看见，且不把人骗进来）

> 本文件在**第六步定标题时加载**（勾了发布平台就先读平台那一行），第九步做**发布位检查**时再取一次。
> 它管四件事：**进得来、点得开、读得完、转得出去**。
> 不管三件事：会不会火、能有多少播放、值不值得做——那三件没有可判据，也不归写作管。

## 一、先划三条边界

- **不预测流量。** 不给「这样会爆」「这样容易上推荐」。判断只落在可指认的东西上：标题是否看得懂、承诺是否兑现、读者在哪一句会停下、有没有能转述的话。**「会不会火」没有可验证的判据，写进去就是编**——这条底线不是 quill 一家的洁癖，做内容诊断的方法论自己也都把「预测播放量 / 点击率 / 推荐量」列在能力边界外。
- **平台字段以发布页当时的显示为准。** 标题字数、封面尺寸、摘要位数、外链与标签规则都会变，本文件不背型号；要写进结论，先按 `platform-compliance.md`「平台规则时效纪律」查一次并留四要素。
- **不做注意力劫持。** 标题可以留一个正文会回答的问题，但不许用正文不兑现的悬念。**读者被骗进来一次，下一篇就不点。**

## 二、平台怎么读（读法，不是规格表）

每个平台只问三件事：**读者从哪进来、他进来时要什么、他把这篇当什么用。**

| 平台 | 读者从哪进来 | 他要什么 | 选题偏向 | 发布位 |
|---|---|---|---|---|
| **公众号（微信）** | 订阅推送、转发 | 认你这个人，愿意读长的 | 系列里的一篇、有判断的闲谈 | 标题 + 摘要 + 封面头图 + 首段 |
| **知乎** | 搜索、问题页 | 带着问题来，要答案结构 | 能问成问题的题；先答后解释 | 问题即标题 + 答案首段 + 封面 |
| **少数派** | 首页推荐、编辑 | 要方法、过程、可复现 | 实践拆解、工具实测 | 标题 + 题图 + 首段（格式见 `sspai-format.md`） |
| **个人站 / RSS** | 老读者、搜索 | 要你自己的判断，可归档 | 长期议题、复盘 | 标题 + 摘要 / OG 图 |
| **小红书（图文）** | 发现页瀑布流 | 一眼扫到有什么用 | 清单、步骤、可保存 | 首图文字即标题主体 + 首行 |
| **X / 微博（thread）** | 时间线 | 一句话能不能转 | 观点 + 一条证据 | 首条 |
| **B 站专栏** | 视频页、搜索 | 配套说明或延伸 | 视频相关的背景与资料 | 标题 + 封面 + 首段 |

> 这张表是**读法**：告诉你每个位置该由什么东西承担。具体字数、尺寸、字段名以发布页为准，不抄进规则。
> 同一篇要发三处，不是写三篇：**换表层，不换论点**（见第四节）。

## 三、选题的平台适配

同一份素材到不同平台，是**三件不同的事**：进来前他知道什么、愿意读多长、要拿它干什么。这三件决定写法，不决定论点。

| 变量 | 决定什么 | 判据 |
|---|---|---|
| 进来前他知道什么 | 标题与首段 | 他搜的是问题还是看到的是推送？搜来的要直接回答，推来的要先给理由 |
| 愿意读多长 | 篇幅与密度 | 时间线场景三屏内给到价值；订阅场景可以铺垫，但第一节要给到东西 |
| 拿它干什么 | 结尾动作 | 存档型收在可复用清单，转发型收在能转述的判断，追问型收在下一个问题 |

**纪律**：

- **论点不因平台改。** 平台读者确实不成立时，是换选题，不是把判断改软。
- **多平台只换四样**：标题、摘要 / 导语、首段、结尾动作。证据、推理、判断不动。
- **不制造近义改写凑数量**：同一篇改成三版，每版只换几个词，等于三份都不合格。
- **改完仍要过兑现检查**：换过的标题与首段，正文必须还兑现得了。

## 四、标题（发布层）

**四件事，缺一件重写：**

1. **陌生人看得懂**：遮住正文单独读，说得出在谈什么对象、什么判断。
2. **有一个正文会回答的问题**：读者读完标题要知道自己在等什么答案——说不出在等什么，就是空悬念。
3. **每个限定词都有理由**：行业词、圈层词、工具名、平台名，逐个好三问——**删掉后目标读者还在吗？能换成读者自己的说法吗？能换成更大一群人的处境吗？** 留下的每一个，能说清「删了为什么就交付不了」。
4. **正文兑现得了**：标题承诺的答案、数字、结论，正文哪个位置给？给不出就换标题。

**三个表面别打架**：标题、摘要 / 导语、小标题是三个位置，各给不同信息——标题给判断，摘要给场景或边界，小标题给节内的推进。**同一信息在三个位置重复 = 浪费两个位置**；任何一处要靠「这」「它」才懂 = 改掉那个位置。

**六种类型**（选一种，不要混）：

| 类型 | 样子 | 适用 | 坑 |
|---|---|---|---|
| 判断型 | 直接给一个可被顶回来的判断 | 观点稿、有立场的解读 | 判断太宽，谁都同意 |
| 信息型 | 说清这是什么、给谁用 | 工具、教程、资料 | 平淡到没有点开的理由 |
| 反差型 | 常识与事实之间的落差 | 复盘、纠错 | 反差是编的，正文兑不了 |
| 清单型 | 明确的数量与范围 | 方法、清单 | 凑数、每条都一样重 |
| 问题型 | 一个具体、能回答的问题 | 知乎、答疑 | 问题太大，正文装不下 |
| 人物型 | 以人/项目为主语 | 人物、案例 | 只靠人名，没有判断 |

**连读检查**：把主标题与副标题去掉换行连成一句读，写下「谁是什么样的人、谁做了什么」。**作者的亲身经历与对别人的批评被读成同一个人时，显式写出两个主语**（「我……」「我发现……」），或者只留一个。

> 压缩与自足的写法（先写完整句再删词、遮住上下文读）在 `form-guide.md`「标题与开头」，这里不重复。禁令（感叹号、「震惊 / 必看」、正文不兑现的悬念、绝对化宣传）见 `style-and-bans.md` 与 `platform-compliance.md`。

## 五、封面 / 头图 / 首图文字（长文的四个发布位）

长文没有短视频那种封面，但有四个位置会被读者单独看到：**头图 / 题图、OG 卡、摘要卡、首条（thread）**。这些位置上如果放文字，按下面判：

- **独立可懂**：只看到这行字，说得出这篇在讲什么。
- **与标题分工**：不重复标题的措辞，也不各指一个角度——图上给场景或结论的一半，标题给判断。
- **三行以内**：再多就没人读；每行尽量短到手机上不用换行读。
- **不用抽象包装词**：「重塑 / 赋能 / 新范式」这类词在图上没有信息量。
- **承诺一致**：图上的承诺与标题、正文是同一件事，一件事三个说法会让人怀疑。

> quill 不产图，只写**图上的字**。版式、配色、尺寸是设计的事；少数派题图规格见 `sspai-format.md`。

## 六、摘要与导语（多数平台都有这一格）

- **一句话说清这篇回答什么问题**，再说一句**为什么现在读**（新事实、新判断、一个正在发生的变化）。
- **与标题不重复**：标题给判断，摘要给场景、证据或边界。抄一遍标题等于浪费一格。
- **导语提到的议题必须指得到正文某一节**，指不到就删——那是给读者许了一个不存在的账。
- 有字数限制时按发布页显示的限制压，不按感觉压。

## 七、分发形态改写（可选，长文之外再要一份时做）

把已于成稿的长文改成 thread、摘要卡或短图文时：

- **只换载体重排，不改观点与证据**。改写不是重新论证。
- **每个单位只讲一个点**；首条承担「标题 + 钩子」，末条给用途或动作。
- **不把长文的段落原样切成条**——切完每条都不成立。按「读者能不能只读这一条」重排。
- 短内容不必走七文件流程（见 `form-guide.md`「短答与长文的分流」）。

## 八、传播：读者为什么会转述

不是「加一句金句」，是三个可查的东西：

1. **有没有一句能被单独摘出来的话？** 一句独立成立的判断、一个反常识的对比、一条可复用的清单。摘出来就散架的句子，不是可转述的话。
2. **转述时他会带上谁？** 带上自己（「我就是这样」）、带上被提到的人（「这说的是我们」）、或带上一个待办（「存下来照做」）。三种都成立，但一篇只能主打一种。
3. **六个行为分开看，只改指得到的那个**：读者会不会停下、会不会读下去、会不会评论、会不会收藏、会不会转发、会不会关注——**六个分开判，不合成一个总分，也不预测哪项会涨**。只有能指到具体句子的那一项算改稿理由（停下=首句、读下去=节间、转发=可转述的那句、收藏=可复用的那部分），指不到就不改。

> 「用途四型」（身份表达 / 备忘工具 / 社交谈资 / 情绪出口）定义在 `topic-value.md` §六，这里不重复。
> **本篇不需要传播时（私人记录、内部备忘、只给一个人看），不许强行加传播刺激**——那会逼出一句空金句。

## 九、发布位检查（第九步执行，六项）

成稿后、交付前逐项过，一次写完不逐条汇报：

1. 标题单独看：陌生人懂 + 有一个正文会回答的问题。
2. 摘要 / 导语与标题不重复，且提出了一个指得到正文的问题。
3. 头图 / 首条上的字独立可懂、与标题分工、三行以内。
4. 首段第一句在没有任何上下文时成立（有人从搜索或 RSS 直接落在这里）。
5. 标题与摘要里的每处承诺，正文都指得到位置。
6. 平台字段（字数、标签、外链、披露）按发布页核过；核不了的写明「以发布页为准」。

## 十、公众号排版机制（别的平台同理会变，按同样方式核）

这三条是**机制**，不是写作判据；具体表现以平台当时的行为为准，不确定就先在发布页预览。

- **别写双标题**：后台已有独立标题框，正文再写一遍一级标题，发出来就是两个大标题。
- **别指望样式活下来**：编辑器会清洗样式标签，看着正常的排版粘过去可能全塌；要复用的样式写进具体元素，别塞 `<style>` 块里。
- **表格与内嵌**：表格兼容性差就转成列表；图片不内嵌；正文外链常被转成文本，需读者自己复制。

## 十一、与其它文件的分工

- `platform-compliance.md`：**能不能发**（红线、两层结论、未检查范围）。
- `sspai-format.md`：少数派首页的**排版细则**。
- `style-and-bans.md`：成稿的**形式禁令**（翻案腔、名词化、AI 味）。
- `form-guide.md`：**写法层**的标题与开头（先写完整再压缩、留人判据）。
- 本文件：**发布层**——进得来、点得开、读得完、转得出去。
