# 阶段 1 规程 — Elicit 模型知识萃取（核心资产）

目标：把执行模型的**内生领域知识**系统性"挤出来"，产出三层知识：**法则**（不可违背的原则）、**最佳实践**（场景化推荐路径）、**坑点**（防御性故障模式），尤其重视官方文档里查不到的隐性经验（行动原则、易错模式、API 误用组合、AI 自己写代码时的典型错误）。这是整个蒸馏流水线的核心阶段。

## 执行方式

对领域配置中的每个 subdomain，逐 `elicitation_topics` 主题执行**五轮萃取**。执行者（agent 本身）就是被蒸馏的模型——你要调用自己对领域的全部内在知识，而不是去查文档。

五轮全部完成后，把该主题的萃取结果写入 `corpus/<domain>/<subdomain>/elicited/<topic>.md`。

## 五轮萃取策略

### 第 1 轮：广度轮（枚举）

对主题做穷举式列举，不解释、不展开：

- 该主题下的坑点 Top 10~20（一句话一条）
- 易错/易误用的 API 清单
- 反模式清单
- 相关联的其他主题

要求**数量优先**：宁可列出后淘汰，不要漏。给每条标注初步置信度（高/中/低）。

### 第 2 轮：深度轮（结构化展开）

对第 1 轮筛出的每个高价值条目，强制展开为固定结构：

```
### <条目标题>
- 症状：<观察到的错误行为/报错>
- 根因：<为什么错，机制层面>
- 错误代码 vs 正确代码：<对照，最小可复现>
- 典型报错原文：<如有，保留英文原样>
- 置信度 + 备注
```

### 第 3 轮：自我质询轮（独有价值）

这是模型知识蒸馏区别于文档搬运的灵魂。自问自答：

1. 「我在生成这个领域的代码时，**自己最容易犯的 10 个错误**是什么？」
2. 「哪些 API 参数组合最容易被误用？错误的调用长什么样？」
3. 「哪些代码模式**看起来合理、实则错误**？」
4. 「用户通常在什么场景下踩到这些坑？」
5. 「我对哪些 API 记忆模糊、可能把相邻版本的签名记混？」——诚实列出，这些进入第 4 轮。

领域配置中每条形如「AI 生成 <子领域> 代码的典型错误」的主题即为本轮而设。

### 第 4 轮：边界轮（低置信暴露）

诚实标注内生知识的边界，供阶段 2 文档锚点重点验证：

- 我**确定过时**的知识（训练截止后可能已变）：列出主题 + 已知最后状态
- 我**不确定**的 API 签名/默认值/行为：逐条列出
- 该领域**版本敏感**的知识点：哪些条目随版本可能失效
- 建议文档验证清单：阶段 2 应优先抓取哪些页面来验证哪些条目

### 第 5 轮：法则化轮（原则升维）

把前四轮的防御性知识（坑点）与经验**反向提炼为约束性知识（法则）**。每个 subdomain 至少完整执行一次（可覆盖该 subdomain 全部主题的萃取产物）。

操作方法：

1. **坑点反向提炼**：每条坑点背后问一句「违反了什么原则？」——「DTO 用 interface 校验失效」背后是「校验元数据必须在运行时存在」。
2. **最佳实践升维**：把场景化建议压缩成「永远/绝不」条款——「App Router 首屏数据 RSC 直取」升维为「服务端数据永不手动塞全局 store」。
3. **格式**：每条法则 = `编号 + MUST/NEVER/ALWAYS + 条款 + 违反后果 + 溯源`：

```
[<SUBDOMAIN>-1] MUST: <条款，一句话，可判定>
  违反后果: <会怎样>
  溯源: <来自哪条坑点/实践/官方规则>
```

4. **可判定性检验**：条款必须能机械判断"是否违反"。「写好代码」不合格；「派生值不得存 state」合格。
5. **分层**：跨领域适用的条款单独标 `[GLOBAL]`（供全局宪法 laws.md 收录）；领域内的用 subdomain 前缀编号。
6. **数量**：每个 subdomain 10~15 条候选，宁缺毋滥——法则是宪法不是清单，放进去就默认不可违背。萃取可宽进（富余候选降级为坑点/最佳实践），蒸馏阶段按 [distill.md](distill.md) 硬顶 15 收敛，不得硬塞超编。

## 萃取纪律

1. **不润色**：萃取产物保持原始密度（要点列表、代码对照、报错原文），结构与润色是阶段 3 的事。
2. **不查文档**：本阶段只调用内生知识。发现需要验证的点 → 记入第 4 轮边界清单，而非现场抓取。
3. **不编造**：对不确定的 API，写「签名不确定，待文档验证」而不是编一个出来。自我质询轮尤其要诚实——承认易犯的错误正是本方案的价值来源。
4. **优先级**：法则 > 最佳实践 > 坑点 > AI 典型错误 > 概念复述。概念复述只保留心智模型级别最小量。
5. **代码对照**：高价值条目尽量带「错误 vs 正确」最小代码对照。

## 增量模式纪律（--refresh 深化轮）

对已有 subdomain 补空白带的深化轮，新 elicited 文件仍须完整执行各轮，追加三条硬性要求（防止深化轮退化为文档转写）：

1. **自我质询轮 ≥5 条内生条目**：「我自己生成该主题代码时最常犯的错误」至少 5 条，必须是模型内省产物——不得把文档事实换个人称复述一遍充数。文档事实归广度/深度轮，隐性经验归自我质询轮；五轮萃取的产品定位是「文档里查不到的知识」。
2. **边界轮必须产出**：不确定的 API 签名/版本敏感点/建议验证清单至少各 1 条；确实全部确定时写明「无待验证项」并说明依据（如本轮已完成阶段 2 抓取核验）。
3. **文档锚点先行允许**：深化轮可先抓取选题页面界定范围再萃取，但抓取确认的事实标注「已锚定（<URL>）」，与内生知识分开陈述，不得混淆来源层级。

## 产物格式

`corpus/<domain>/<subdomain>/elicited/<topic>.md`：

```markdown
---
topic: <主题>
subdomain: <子领域>
rounds_completed: [广度, 深度, 自我质询, 边界]
elicited_at: <YYYY-MM-DD>
---

# <主题>（萃取原始产物）

## 广度轮
## 深度轮
## 自我质询轮
## 边界轮（待文档验证清单）
```

法则化轮的产物单独成文件（每个 subdomain 一份）：

`corpus/<domain>/<subdomain>/elicited/<NN>-laws.md`：

```markdown
---
topic: 法则化萃取
subdomain: <子领域>
rounds_completed: [法则化]
elicited_at: <YYYY-MM-DD>
---

# 法则化萃取（原始产物）

## 领域法则
[<SUBDOMAIN>-1] MUST: ...
## 全局候选（[GLOBAL] 标记）
```
