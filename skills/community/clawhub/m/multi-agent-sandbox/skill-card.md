## Description:

Sets up sandboxed OpenClaw agents for cross-gateway collaboration using Docker isolation, Discord routing, SSH bridges, and Tailscale networking.

This skill is ready for commercial/non-commercial use.

## Use Case:

Developers and operators use this skill to configure sandboxed OpenClaw agents that can collaborate across gateways through Discord, a shared VPS workspace, SSH forwarding, and Tailscale networking while limiting exposure of private main-agent data.

### Deployment Geography for Use:

Global

## Known Risks and Mitigations:

Risk: Persistent host network bridges and broad agent permissions can weaken sandbox boundaries.

Mitigation: Use a dedicated host or test environment, restrict Docker networking to the intended container, and avoid bridging the gateway unless it is strictly required.

Risk: Remote installer scripts and persistent services can introduce supply-chain and operational risk.

Mitigation: Pin and verify installers where possible, review service definitions before enabling them, and document how to disable and remove the services.

Risk: Root SSH access with disabled host-key checking can expose the shared VPS or allow connection spoofing.

Mitigation: Use a non-root VPS account and keep SSH host-key verification enabled.

Risk: Broad Discord intents and bot routing can expose messages or trigger unintended automation.

Mitigation: Limit Discord permissions to required guilds and users, keep mention gating enabled for shared guilds, and rotate exposed bot tokens immediately.
