# 股份支付登记（权益结算／现金结算／等待期摊销）

产出稿的头部就照下面这几行起（三件自标「AI 整理初稿」「请回原文核对」「不构成投资建议」逐字在位；`主体：`／`报告期：` 是**行首裸行**，不带 `- ` 前缀）。判断位一律写成 `[待人工]`：

```
# 示例材料（600000.SH）股份支付登记稿

AI 整理初稿 ｜ 请回原文核对 ｜ 不构成投资建议
主体：示例材料（600000.SH）
报告期：2025 年年度报告·附注·股份支付
```

**定位**：给一份年报，把附注里**「股份支付」那一段**读成一张**每个数都能回到附注原句**的登记表——两类计量各确认多少费用、授予日公允价值怎么定、等待期摊销与剩余等待期还要确认多少、可行权数量这一年怎么从期初走到期末。**两类费用之和与数量四数恒等由机检现算**，本件只负责把数抄对、把分项抄对、把原句挂上。

这一段最容易被含糊过去：一家公司说「本期确认股份支付费用 1.84 亿」，但其中权益结算 1.56 亿、现金结算 0.28 亿——两类计量模式完全不同，**现金结算那部分每期都要按公允价值重估、直接走损益**，权益结算只影响资本公积。把它们混成一行「股份支付费用」，后面所有关于费用性质的推断都会错。本件把两类分开摆，**不替你说「这套激励方案合理」或「未来费用会下降」**——那一步要口径判断，交 `[待人工]`。

切割说清楚：`equity-incentive-plan-cn` 管**激励计划条款本身**（授予条件、行权安排、业绩指标），**不问会计上确认了多少费用**；`cn-changes-in-equity-cn` 管**所有者权益变动表的行列轧平**（其中「股份支付计入所有者权益的金额」只是其中一格），**不拆两类计量、不问等待期摊销与可行权数量**；本件管**附注里这笔费用的会计登记与数量变动**。三件读同一份财报的不同段落。

### 是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 五块逐条登记（股份支付概况／权益结算／现金结算／等待期摊销／数量变动），缺项也占一行点名 | 激励方案合不合理、有没有激励效果（一律 `[待人工]`） |
| 每个数字带 `〔口径：…〕` 标签（本期／本期发生额／截至本期末／本期末） | 按表格位置认项（第三行就是现金结算那种） |
| 现算：两类本期费用之和 vs 披露合计，差 > 0.01 万元即发条 | 只抄合计数、两类空着，让合计无从复核 |
| 现算：期初 ＋ 新增 − 行权 ＝ 期末（万股），差 > 0.01 即发条 | 拿 0 补一个缺失项去让恒等成立 |
| 每个数挂「」原句＋〔锚：…〕＋`[S#]` 三元组，来源行两向对应 | 只写数字不抄原句，事后补一句「据年报附注」 |
| 数据通道＝用户直供的附注原文（零网络） | 承诺任何实时行情、预测或工具清单 |

### 触发场景

「这家公司股份支付一年确认多少费用」「权益结算和现金结算各多少」「等待期还有多少没摊完」「限制性股票这一年解限了多少」。输入形态＝**年报附注里「股份支付」那一段**（截图／PDF／解析回来的表格文本）。

## 七节各登记什么

节名必须逐字照这几个（`## ` 起节，节名后面紧跟字母或数字就认不出，会被记成野节）：

| 节 | 登记什么 | 最常犯的错 |
|---|---|---|
| 股份支付概况 | 类型（权益结算／现金结算并行或仅其一）、本期确认的费用总额，`〔口径：本期〕`／`〔口径：本期发生额〕` | 只写「本期确认股份支付费用」不给总额，后面的两类之和就没有比对对象 |
| 权益结算的股份支付 | 授予日公允价值确定方法、本期确认费用、累计确认费用，`〔口径：本期〕`／`〔口径：本期发生额〕`／`〔口径：截至本期末〕` | 把「累计确认」当成「本期确认」抄，两个数差好几倍 |
| 现金结算的股份支付 | 负债期末账面价值、本期确认费用、本期费用合计，`〔口径：本期末〕`／`〔口径：本期发生额〕` | 只抄负债余额不抄本期费用——现金结算每期重估，费用才是损益影响 |
| 等待期费用摊销 | 本期摊销额、剩余等待期将确认的费用，`〔口径：本期发生额〕`／`〔口径：本期末〕` | 把「剩余等待期将确认」写成「已确认」 |
| 数量变动 | 期初／本期新增／本期行权／期末，**单位是万股**，`〔口径：本期末（股）〕`／`〔口径：本期（股）〕` | 单位写成万元（机检只认「万股」）；漏掉行权那一行，四数恒等就无从现算 |
| 口径与未取到 | 取法口径 ＋ 缺口逐项点名；零缺口写 `未取到：无` | 正文写了未取到而本节没列，或反之 |
| 来源 | 每条 `[S#]` 一行：`- [S#] 标题 \| URL \| 检索日 YYYY-MM-DD` | 引用了 `[S#]` 却没有登记行；检索日写成斜杠式 |

同一条 = 一行：行首写项名与标签，紧跟金额与「万元」（数量行是「万股」），再挂 `「原句」〔锚：页/表〕[S#]`。附注里没有的数写 `未取到：项名`，不留空、不借常识补。

⚠️ **两类不能混**：权益结算与现金结算必须分节摆，且各自都要有「本期确认的费用」那一行。机检要拿这两行相加去对披露合计；缺一行就报「缺数」，而不是跳过——除非你在 `口径与未取到` 里写明该项未取到。

## 五道机检在管什么

现状以脚本里 `UNIMPLEMENTED` 的现值为准：五道**全部已落字**。将来某道若回退成空壳，它会调用即抛、由机检收进「不可判」，既不判也不放行，单稿退 3；`rc=0` 只留给「五道全过」。

| 码 | 名称 | 判什么 | 最常拦住的情况 | 现状 |
|---|---|---|---|---|
| `SP-STRUCT` | 形制 | 头部三件自标逐字在位、七节齐且按序；认不出的节标题与多出同名节记 stray 逐条发。只判「形」，不判内容；**不判** `主体：`／`报告期：` | 节名改了个字就整节认不出；一节写了两次 | 已落字 |
| `SP-QUOTE` | 原句与锚 | 五个内容节里每个带数字的行须挂齐「」原句＋〔锚：…〕＋`[S#]` 三元组；例外只有 `未取到：` 行、`[待人工]` 行、`〔自算〕` 行三形；**正文与来源节两向**都要对得上（正文引了没登记要发，登记了没引用也要发）。**不核对引号里的数与行首是否同一**（那是 `SP-SUM`／`SP-VEST` 的活，分开判只为让一支坏样只红一道） | 数字行只写数没抄原句；来源行检索日写成 `2026/03/20`；引了 `[S2]` 却没登记；登记了 `[S2]` 却没引用 | 已落字 |
| `SP-SUM` | 两类费用之和 | 权益结算「本期确认的费用」＋ 现金结算「本期确认的费用」，与**两处**披露合计（概况的「费用总额」、现金结算节的「本期费用合计」）逐处比对，差 > 0.01 万元即发。**两处合计互不相等本身也发一条**——那说明稿里自己抄岔了。任一侧缺失 ⇒ 若 `口径与未取到` 已写明未取到则整条跳过，否则发「缺数」，不猜、不按 0 算。同一侧匹配到多行 ⇒ 发「多义，不敢比」 | 两类相加对不上合计；两处合计各抄了一个数；漏抄现金结算那行 | 已落字 |
| `SP-VEST` | 数量四数恒等 | 「数量变动」节里 期初 ＋ 本期新增 − 本期行权 ＝ 期末，容差 0.01（万股）。按标签认行，**认「行权」时排除「可行权」**（否则期初/新增/期末三行都会被误认成行权行）。任一侧缺失 ⇒ 同 `SP-SUM` 的跳过规则 | 四个数少抄一个；单位写成万元；把「期末可行权」抄成「本期可行权」 | 已落字 |
| `SP-LINE` | 红线 | 四组词**只在五个内容节扫**（`口径与未取到` 与 `来源` 整节豁免）：① 投资建议（`买入`／`卖出`／`增持`／`减持`／`目标价`／`推荐`／`建议持有`）② 前瞻预测（`预计`／`预测`／`有望`／`将会`／`看好`／`预期增长`）③ 主观评价（`合理`／`不合理`／`偏高`／`偏低`／`显著低估`／`高估`）④ 越界口径（`经常性损益`／`扣非`／`估值`／`市盈率`／`市值`）。**同一行同一组只报最长命中**（「不合理」不该被记成「合理」＋「不合理」两条） | 自己写了一句「预计明年费用将下降」；把股份支付费用写进「扣非」；抄引文时把评级建议一起抄进来 | 已落字 |

## 退码

| 码 | 含义 |
|---|---|
| `0` | 五道全过，零发条 |
| `1` | 有发条 |
| `2` | 用法错（缺参数或未知参数） |
| `3` | 读不到文件、或空稿、或零发条但仍有判据未落字（此时输出会明写「**这不等于合规**」） |

## 数据通道

零网络、纯标准库、单文件。输入就是用户直供的附注文本，本件不联网取数、不缓存、不上传。
`CUE_API_KEY` 是**可选**的：带上才走 `cue-data-mcp`／`cue-omni-reader` 那条取证腿去取原文，
缺位时只把用户贴进来的附注排版成上面那张登记表——**形状一样，数只能来自用户**。

## 快速开始

```bash
# 看一眼样例（零输入可跑，打印一份七节齐的登记稿）
python3 scripts/check_share_based_payment.py --demo

# 跑包内夹具自检（末行会给「自测档数=N｜不合=0｜不可判=0」）
python3 scripts/check_share_based_payment.py --selftest

# 机检自己的稿子
python3 scripts/check_share_based_payment.py 我的登记稿.md
```

详见 `README.md` 的「怎么接到 agent 上」一节（那里有可直接复制的 `curl` + `tools/list` 片段）。
