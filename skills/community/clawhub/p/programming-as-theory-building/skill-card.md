## Description:

Use when writing, generating, modifying, debugging, reviewing, or refactoring code. Treat code work as rebuilding and preserving the program theory: how real-world affairs map into program behavior, why the current shape exists, which existing facility the new demand resembles, and what observable behavior proves the change belongs.

This skill is ready for commercial/non-commercial use.

## Use Case:

Developers and engineers use this skill to guide coding, debugging, reviewing, and refactoring work by recovering the program theory behind existing code before changing it.

## Known Risks and Mitigations:

Risk: The workflow may slow very small edits because it encourages upfront context gathering.

Mitigation: Apply the full checklist to non-trivial code work and use a lighter pass for clearly trivial edits.

Risk: Methodology guidance can still lead to incorrect code changes if the recovered program theory is incomplete.

Mitigation: Verify changes with tests, runtime behavior, or focused review evidence before relying on the result.
