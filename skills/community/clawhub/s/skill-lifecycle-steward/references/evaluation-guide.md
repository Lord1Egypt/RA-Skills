# 技能评估指南

配合主文件「路径 A · A4」使用。目标：给出可解释、可比较的评级，避免凭感觉推荐。评分只用于排序与分级，不必向用户展示逐项分数明细（除非追问）。

## 评估维度

对候选技能逐项考察，每项按证据充分度判断：

| 维度 | 关注点 |
|---|---|
| 来源声誉 | 来自官方源、高安装量排行榜，还是低星/未知仓库 |
| 维护活跃度 | 最近更新时间、issue 响应、版本迭代情况 |
| 文档质量 | `SKILL.md` 是否写清用途、触发条件、工作流与资源引用 |
| 功能匹配度 | 与用户具体需求的贴合程度，而非泛泛相关 |
| 安装量/背书 | 下载量、Star 数、社区评价等可得信号 |
| 安全性 | 是否通过安全扫描（见 `security-scan.md`），有无危险信号 |

**功能匹配度是最高权重项**：一个来源普通但高度贴合需求的技能，优先于来源权威但只沾边的技能。

## 证据替代

WorkBuddy 生态内未必有安装量/Star 数据。按以下顺序取可得的最佳信号替代，不因缺数据就直接判低：

1. 官方内置精选标记
2. skills.sh 页面数据
3. GitHub API（Star、更新时间、贡献者）
4. 文档质量与来源可追溯性

若所有外部信号都缺失，只能依据 `SKILL.md` 本身判断 → 评级不超过 🟡，并标注"来源待核实"。

## 分级口径

- 🟢 **强烈推荐**：证据充分、匹配度高、来源可靠、通过安全扫描。
- 🟡 **可用，建议人工核实**：大体匹配但有信息缺口，或来源需确认，或存在需留意的信号。
- 🔴 **不推荐**：匹配度低、来源可疑，或存在未排除的安全风险。

## 结果呈现

- 推荐项必须附一句话用途与安装方式。
- 任一候选命中危险信号 → 评级不高于 🟡，并附 ⚠️ 单行说明具体问题。
- 高危信号（见安全扫描）→ 直接 🔴，不推荐。
- 找不到合格候选时如实说明，不为凑数降低标准。
