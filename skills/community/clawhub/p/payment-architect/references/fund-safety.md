# 资金安全工程规范

支付系统不可妥协的工程红线。评审任何支付链路设计/代码时按本文件逐条核对。

## F1 金额规范

- 系统内全链路 **整数最小单位**（人民币=分，long/int64）；禁止 int（溢出）、禁止 float/double/BigDecimal 参与中间运算。
- 唯一允许的换算点在持久层边界（如 DB 存 DECIMAL 元时，换算收敛在仓储实现一处）。
- 零/负金额由 Money 值对象在构造时拦截，不进业务逻辑。
- 费率用整数基率（万分之一 = 1）；比例费计算顺序固定：**比例费 HALF_UP 到分 → 保底 → 封顶 → 叠加固定费**；未命中费率规则返回错误（如 FEE_404），**禁止按 0 费放行**。
- 金额上界保护：桶/余额增量更新带非负与 Long 上界条件写。

## F2 幂等体系（三层纵深）

| 层 | 机制 | 职责 |
|---|---|---|
| 入口防重 | 请求号分布式锁（切面在事务外先抢锁） | 只防在途并发重入；锁服务故障时 fail-closed，不无锁放行 |
| 业务幂等 | 唯一键 `(交易类型, 请求方, 外部单号)` + 请求关键要素指纹（SHA-256） | 快速命中与唯一键冲突都要回读并核验指纹；金额/币种/参与方/业务上下文变更即拒绝 |
| 最终防重 | 数据库唯一约束 | 兜底；冲突后回读首次结果返回，不报错、不重做 |

规则：
- 同号重试返回首次结果（成功回成功，失败终态回失败，**FAILED 不复活**）。
- 同号换参 = 拒绝（参数冲突错误码），不是覆盖。
- 审计/受理记录不清理到允许历史重放。
- 消费侧幂等：事件号/请求号/批次号全局唯一键，重复投递按"已受理"返回。

## F3 状态机与并发控制

- 一切状态迁移走状态机白名单校验 + **version CAS（更新带版本条件，判影响行数）**；影响行数≠1 即并发冲突回滚。
- 终态回退结构性拒绝（数据库/服务层双重校验）。
- 业务终态同事务作废未触发的定时任务（避免到期任务误推进已关闭单）。
- 事件版本防乱序：按步骤/单据维护 `last_event_version`，晚到旧版本事件丢弃；TIMEOUT 类事件允许被晚到真实终态收敛。
- 锁序全局固定并文档化，示例：`原单 → 业务单 → 流程步骤 → 账簿合计 → 余额桶（桶号升序）`。禁止反向加锁、禁止持锁扩锁。

## F4 事务边界（三段式，最重要的一条）

跨系统写（RPC/MQ/外部 HTTP）一律三段式：

```
T1 本地意图短事务：CAS 抢占 + 持久化请求号/意图快照（状态=处理中）
   ── 事务外：调用下游（携带稳定 requestId + 请求摘要）──
T2 结果确认短事务：归并结果 + outbox 同事务写入
```

- **禁止事务内 RPC**（连接占用放大、超时不可控、分布式死锁）。
- T1 异常时独立事务回退登记，不得污染在途代次；T2 必须核对 T1 的领取版本。
- 提交结果未知（超时/连接断）时：不改状态、不换号重发，进入查证流程。
- 入口方法拒绝外层已有事务的同步上下文（避免 ORM 一级缓存陈旧导致的状态误判）。

## F5 UNKNOWN（结果未知）处理

- UNKNOWN 不是失败。只按**原请求号/原交易号**发起查证，按查证结果收敛。
- 超时不能判失败；响应丢失登记 `RESULT_UNKNOWN` 类错误返回上游，不改已成功/处理中状态。
- 恢复任务先查证再执行：持主库行锁核实 CREATED 且无成功明细后，才允许 CAS 关闭并按原快照恢复；仅凭超时重做是 P0 缺陷。
- 退款类：本地在途预占 + 核心已退累计 + 原单行锁防并发超额；累计与在途重叠不能证明时**安全拒绝等待查证**，不承诺立即可退。

## F6 通知语义与传输分离（Outbox 模式）

- 业务表与 outbox 表**同一本地事务**写入；不存在"先发 MQ 再提交 DB"或反之。
- 独立 relay/worker 扫描 outbox 投递，租约+退避+超最大次数转人工；投递成功才标记。
- 业务域不自建 HTTP 重试管道；对外回调的传输（签名/重试/ACK）归网关域。
- 消费者按事件号幂等，重复投递回首次结果。

## F7 定时任务与恢复

- 生产禁止裸 `@Scheduled`：由分布式调度（如 XXL-Job 类）分片触发，本地扫描开关仅单实例联调。
- 任务注册时机挂真实业务事件（如"担保到期确认任务"在支付成功时注册，而非受理时），防止被终态作废逻辑误杀。
- 批次任务支持断点续跑（游标持久化）；同一批次重跑用新触发号，历史批次禁止回退。
- 恢复执行有界（如最多 3 次领取），超限转人工；技术异常立即转人工，不做无限退避。

## F8 依赖与降级（fail-closed）

- 外部依赖（风控/计费/产品/加密）未就绪或契约未冻结：事务前拒绝，**禁止 Stub 假成功进入生产**；Stub/默认实现必须显式开关、默认关闭。
- 资源归属身份由可信接入层断言（验签后注入），禁止把请求参数里的 userId/merchantId 当认证结果。
- 非幂等下游接口禁止自动重试；消费方默认 retries=0，超时按下游 SLA 评审后局部覆盖。
- 配置即代码：规则类配置（记账规则/路由）启动加载不可变快照；空表/非法配置/版本混杂 = 启动失败，不回退默认。

## F9 双人制与人工干预

- 人工资金操作（调账/大额结算/备付金划拨）：DRAFT → 复核 → 生效，**operator ≠ reviewer** 系统强校验。
- 大额阈值（如 ≥5 万）强制人工复核节点。
- 差错/异常工单四类以上分类（长款/短款/状态不一致/未知），批准后系统自动冲正，禁止人工直接改表。

## F10 可观测与审计

- 资金操作日志结构化、无高基数标签（请求号/账号不进 metric label）；正常路径日志条数有上限（防刷盘）。
- 敏感字段（卡号/证件/手机号）落日志前脱敏；错误文案用安全文案，不透出内部堆栈与业务原因。
- 全链路 traceId 贯穿 RPC/MQ/任务；MQ 消息头含 traceId、事件号、契约版本、来源系统。
