# Security & Behavior Declaration

> SKILL.md 保留三行摘要，完整声明在此。承诺可验证：全部行为可在单次运行中
> 用 `strace`/抓包复核。

## 运行形态

- 单次 CLI：启动 → 核验 → 写报告 → 退出。无守护进程、无后台任务、运行时不
  下载或安装任何东西（纯标准库）。
- 无 OS 集成：无子进程、无系统服务、无权限变更；文件访问仅限你传入的输入/
  输出路径、本地缓存（`~/.cache/cite-holmes/`）与报告输出。

## 网络边界（始终 HTTPS，官方学术注册库与用户提交的来源 URL）

`doi.org` · `api.crossref.org` · `eutils.ncbi.nlm.nih.gov` ·
`export.arxiv.org` / `arxiv.org` · `archive.org` · `api.openalex.org` ·
`api.semanticscholar.org` · `pubmed.ncbi.nlm.nih.gov`
- 你提交的来源 URL 也在检查范围内（可达性探测 + 死链 Wayback 对照）——检查器会访问用户提供的链接，不仅是上方注册库。

### URL 防护边界（v6.6.0 如实声明）

**已实施的防护**：
- 入口字面量防护：URL 主机部分为回环/内网/链路本地/保留/多播 IP 字面量
  （`127.0.0.1`、`169.254.169.254` 云元数据端点、`10/8`、`192.168/16` 等）
  或 `localhost`/`*.local`/`*.internal` 主机名时，拒绝外呼并如实标注
  （判定落 unreachable，不冒充任何注册库结论）。
- 重定向逐跳复核（v6.6.0）：自动跟随 30x 的路径上，每一跳目标重新过同一
  防护——「公网 URL 经重定向跳内网」的绕过面已封死（doi.org→出版社的
  正常多跳不受影响）。

**如实声明的边界（本工具不承诺）**：
- **DNS 重绑定**：主机名型 URL 的防护是语法级（不做连接层 IP 钉扎）——
  域名解析交给系统 resolver。刻意不做解析结果判定：污染网络下解析本身
  不可信，按解析结果拦截会把正常域名误判成内网地址（实测教训在案）。
  完全防护需网络层手段（出口防火墙/专用解析器），超出本工具形态。
- **域名型重定向目标**：逐跳复核同样是语法级；解析后仍落内网的域名型
  跳转不在防护范围（同上理由）。

不访问任何其他主机；零遥测、零分析、零数据收集。唯一外呼 payload 是你要求
核验的标识符与标题。

## 密钥与数据

- 可选环境变量 `OPENALEX_API_KEY` / `S2_API_KEY` / `NCBI_API_KEY` 只用于向
  对应官方 API 认证你自己的请求，绝不发往其他任何地方，绝不回显（`--doctor`
  只报「已设置/未设置」）。
- 引用清单与报告全部留在本机；持久缓存只存判定与注册库元数据摘要
  （`--no-cache` 可关闭，`--cache-path` 可改位置）。
