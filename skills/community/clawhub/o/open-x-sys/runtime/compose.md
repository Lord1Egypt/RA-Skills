# Compose: Form the System That Is Actually Working Now

Composition temporarily organizes the object, user, purpose, understanding, materials, capabilities, tools, relations, authority, and feedback into an active system map. The parts that need to act together can see one another and form relations around the same result.

## The active system map

The runtime can answer internally:

- What is the central system, and which boundary, scale, and time window apply?
- Which higher-level system contains it, and which subsystems may need to unfold?
- What is reality, what is observed, what is modeled, and what remains unknown?
- Which relations, constraints, feedback loops, and delays actually determine the result?
- Which capabilities exist now, and where is the gap?
- Who owns materials, state, works, action rights, and exit rights?
- Which downstream parts will a change affect, and which existing works remain valid?

When a relation or capability is itself complex, unfold it recursively as a system, understand it, and return to the original whole. Several models may coexist when each names the object, user, and purpose it serves.

## Choose the present composition

Prefer what the user already owns, the host can actually use, the conditions fit, and real work has validated. The capability gap determines when to add a tool, code, adapter, or new division of work. Every component in the active picture changes a real relation or provides a needed capability.

## Composition continues throughout the run

Composition may happen before research or happen again when evidence, authority, failure, or user correction changes the picture. It interleaves with observation, action, and update.
