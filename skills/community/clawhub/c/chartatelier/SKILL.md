# ChartAtelier 商务图表智造

把一句话需求变成可直接放进汇报、标书与白皮书的商务级图表成品：交付高分辨率 PNG 与可编辑 SVG，浅色专业配色，中文排版不糊不挤。

## 这是什么

- 解决“脑中有结构、手上画不出”的断点：直接给出能贴进文档的图表成品，而不是一段还要你自己排版的文字描述。
- 产出固定为五件套：`diagram.html`（内联 CSS + SVG 渲染源）、`diagram.svg`（可编辑矢量源）、`diagram@2x.png`（长边 ≥3000px）、`qa-report.json`（五项几何与色彩实测值）、交付说明（80–200 字）。
- 覆盖六类商务图：架构图、流程图、拓扑图、时间轴、信息图、对比矩阵；每类都有确定的骨架、节点上限与拆图规则，不靠临场发挥。
- 与“通用大模型直接问”的区别：配色、字号、线宽、留白、导出倍率、验收阈值全部写成可执行参数，并由脚本逐条校验，未通过自检不得交付。
- 默认浅色专业配色：`#f1f5f9` 页底配 `#ffffff` 图卡；中文强制走显式字体栈，避免导出后回退成衬线体、字宽散开或文字糊成一片。

## 适用场景

- “我要把这次系统改造讲清楚，压缩进周会 PPT 的一页。”
- “标书里要一张总体架构图，黑白打印也得看得清层级。”
- “白皮书第三章要一张业务流程，七八个环节，别挤成一团。”
- “领导只给三分钟，我要一张图说明从受理到归档到底走了哪几步。”
- “两个方案要对比，做成矩阵，六个维度、四个选项。”
- “机房这些设备和链路怎么连，出一张拓扑图贴在运维手册里。”
- “项目里程碑要一条横版时间轴，八个节点，标注责任人。”
- “一页信息图，讲清三个数字以及它们之间的关系。”

## 何时不要使用

- 要插画、3D 渲染、品牌 VI 或海报级视觉：本技能只做结构化信息图，不做美术创作。
- 需要真实地理位置的精确地图或等高线：只表达相对位置与逻辑关系，不用作导航。
- 节点超过 40 个还想塞进一张图：先拆图，硬塞必然字压线。
- 没有可信数据来源却要在图上标百分比：只允许留 `XX%` 占位，禁止编数。

## 输入与输出

| 字段 | 必填 | 说明 |
|---|---|---|
| `requirement` | 是 | 一句话需求，须含主体与关系（“谁 → 经过哪些环节 → 到哪去”）。不足 12 字时先回到需求澄清，不得直接开画 |
| `diagram_type` | 否 | `architecture` / `flow` / `topology` / `timeline` / `infographic` / `matrix` / `swimlane` / `sequence`；留空则由结构选型自动判定 |
| `nodes` | 否 | 节点清单，逗号分隔。留空时从 `requirement` 抽取；抽取后少于 3 个即回问，不得自行补造业务名词 |
| `canvas` | 否 | `16:9`（默认，逻辑 1520×856）、`4:3`（1280×960）、`a4p`（1240×1754，A4 竖版） |
| `tokens` | 否 | 品牌主色与禁用色。只允许覆盖语义色的描边与标题色，填充必须保持浅色（明度 ≥92%） |
| `scale` | 否 | 导出倍数，`2`（默认）或 `3`。3 用于印刷、喷绘或大屏投放 |
| `lang` | 否 | `zh`（默认）、`en` 或 `bi`（中英对照，英文置下排、字号比中文小 2px） |

输出规格：

| 文件 | 格式 | 规格 |
|---|---|---|
| `diagram.html` | HTML 单文件 | 内联 CSS + SVG，无外部依赖，双击即可打开 |
| `diagram.svg` | SVG 1.1 | `width` / `height` 为显式像素（等于 viewBox 尺寸），文本保持 `<text>` 可编辑 |
| `diagram@2x.png` | PNG | 16:9 输出 3040×1712；A4 竖版输出 2480×3508（≈300 DPI）；长边 ≥3000px |
| `diagram@3x.png` | PNG | 长边 ≥4500px；仅 `scale=3` 时产出 |
| `qa-report.json` | JSON | 留白、连线交叉、文字溢出、对比度、导出尺寸五项实测值 |
| 交付说明 | Markdown | 80–200 字：图种判定、配色口径、字号阶梯、复现命令 |

最少可执行输入：`requirement` 一句话，外加可选的 `nodes`。其余字段留空时按默认值推进，并在交付说明首行声明所用默认值，避免反复追问错过截稿时间。

输出判定：交付物必须同时满足“能贴”（PNG 尺寸与留白达标）、“能改”（SVG 文本仍可编辑）、“能复核”（`qa-report.json` 五项均有实测数值）三条，缺任意一条视为未完成。

## 工作流

### 第 1 步 · 需求澄清（5 问）

先把 5 个问题一次问完，不要挤牙膏式追问；用户未答的项直接用默认值继续推进，并在交付说明里声明所用默认值。

| 问题 | 用来决定 | 未答时的默认值 |
|---|---|---|
| 这张图放进哪里？（PPT 单页 / Word 标书 / 白皮书整页 / 手机预览） | 画布比例、最小字号 | 16:9 单页，正文 12px |
| 观众是谁、离屏幕多远？（领导 3 米外 / 评审逐条看 / 打印传阅） | 信息密度、字号上限 | 2 米观读，正文 12px、标注 10px |
| 图里必须出现的名词有哪些？（系统名、模块名、指标名） | 节点清单与命名口径 | 从需求句抽取，少于 3 个回问 |
| 主关系是什么？（层级 / 顺序 / 连接 / 数量对比） | 图种 | 按第 2 步规则自动判定 |
| 有哪些必须保持一致的东西？（配色、图例、编号、单位、版本号） | 复用 token 与图例 | 使用本技能默认 token 表 |

追问示例：“这张图最终贴在哪份材料里？观众离屏幕大概多远？图里必须出现的名词帮我列 3–8 个。”

判据：5 问中至少答出“放哪里”“主关系”“名词”三项才进入绘制；三项齐备后不再追问，多余信息并入节点清单。
失败处置：用户连续两轮只回“你看着办”，则按默认值全量执行，并在交付说明首行写明“按默认规格交付”。

### 第 2 步 · 结构选型

按需求句里的信号词落图种，不按个人偏好挑。完整决策表与拆图阈值见 `references/diagram-selection.md`。

| 需求信号（买家怎么说） | 图种 | 骨架 | 元素上限 | 不要用于 |
|---|---|---|---|---|
| 分层、上层、底层、接入层 | 架构图 | 横向分层带 + 层内并列卡片 | 单层 ≤5 张卡，总 ≤18 | 表达先后顺序 |
| 先…再…然后、如果…就、卡在哪 | 流程图 | 纵向主干 + 判定分支 | 主干 ≤8 步，判定 ≤3 处 | 表达并行数据流 |
| 怎么连、链路、组网、走哪条线 | 拓扑图 | 分区框 + 节点 + 正交连线 | 节点 ≤14，跨区连线 ≤8 | 表达审批流程 |
| 谁在什么时候做什么、跨角色 | 泳道图 / 时序图 | 角色列 + 阶段网格 / 消息横线 | 泳道 ≤5，阶段 ≤6；参与者 ≤6，消息 ≤12 | 表达容量对比 |
| 第一阶段、里程碑、从 X 到 Y | 时间轴 | 单轴 + 上下交错标签 | 节点 ≤8 | 表达层级关系 |
| 一页讲清一个概念、三个数字 | 信息图 | 主视觉 + 3–5 个数据块 | 数据块 ≤5 | 承载十个以上概念 |
| A 和 B 差在哪、怎么选 | 对比矩阵 | 行 = 选项，列 = 维度 | 维度 ≤6，选项 ≤4 | 表达流程走向 |

三条硬规则：出现“连接 / 链路 / 组网”判拓扑；出现“先…再…如果”判流程；出现“分层 / 上层 / 底层”判架构。三条同时命中时，取需求句的主语所在层级决定主图种，其余降为图例或注释。

失败处置：节点数超过上限时禁止缩字号硬塞。先拆成主图 + 副图（主图给结论，副图给细节），拆图后每张仍需各自通过自检。

### 第 3 步 · 版式与配色

完整 token 表、间距阶梯与图例规则见 `references/visual-spec.md`，此处只列不可协商项。

- 画布：16:9 逻辑 1520×856，四周安全边距 32px；元素按 8px 基准栅格对齐（4 / 8 / 16 / 24 / 32 / 48）。
- 页底 `#f1f5f9`；图卡 `#ffffff`，描边 1px `#e2e8f0`，圆角 16px。
- 语义色只允许这套，且同一份交付内含义不得漂移（蓝 = 接入 / 渠道，绿 = 业务核心，紫 = 数据 / 对账，玫 = 风控 / 差错，橙 = 日终 / 合约，灰 = 外部 / 监管，黄虚线 = 容器边界）。
- 文字层级：标题 `#0f172a` 600、正文 `#475569`、标注 `#64748b`；正文与标注的对比度对白色底不得低于 4.5∶1。
- 线宽：主连接线 1.2–1.5px，辅助虚线 1.1px；箭头 10×7（`refX=9`、`refY=3.5`）；虚线节拍 5–7px 实 / 4–5px 空。
- 圆角：节点 `rx=10`，容器边界 `rx=14`；网格纹 `#eef2f7`、0.8px、40–50px 格。
- 字号：节点标题 14–15px / 600，正文 12px，标注 10–11px，成品上不得出现小于 10px 的字。行高 1.5–1.6，中文不得加正向字距（`letter-spacing > 0.02em` 会让汉字散架）。
- 图例：横排在画布右下角，置于容器框之外，条目 ≤6 个；色块 10×10px、描边 1px，图例文字 10–11px。
- 编号与注释：编号只用一层（① ② ③ 或 1. 2. 3.），不得两套并用；单位统一写在数值之后、括号内，全图口径一致。

### 第 4 步 · 坐标规划与绘制

先出坐标表，再写 SVG。坐标表至少包含：每个节点的 `x / y / w / h`、每条连接线的起止点与折点、每一行占据的纵向区间（band）。

- 所有箭头与连线先于节点矩形写入，让它们渲染在底层，避免被填充色盖住。
- 正交折线只允许走“行与行之间的空隙”：`M x1 y1 L x1 gapY L x2 gapY L x2 y2`，严禁在节点所在 y 值上横穿。
- 节点文字统一用 `text-anchor="middle"` 加手算纵向居中（`dy="0.35em"`），不要依赖 `dominant-baseline`，后者跨渲染器表现不一致。
- 容器边界框（虚线）包住子节点属预期行为，不参与重叠判定。
- 长文本按语义折行，不按字符数硬切：中文一行 ≤14 个汉字，英文一行 ≤28 个字符，超出即拆行或加宽框体。
- 中英对照时中文在上、英文在下，英文行高 1.3、字号比中文小 2px，且不与中文共用一个 `<text>` 节点，便于单独改词。

判据：坐标表能逐行对上 SVG，不存在“画到哪算哪”的矩形。
失败处置：连线穿框时改折点，不要靠调整 z-order 掩盖；改完重跑第 5 步。

### 第 5 步 · 自检（五项，全部脚本化）

| 检查项 | 判据 | 失败处置 |
|---|---|---|
| 留白 | 内容饱和度外接框覆盖画布 ≥95% 宽、≥93% 高；四边留白 1–3% | 收紧 viewBox 到内容外扩 10–20px；并收掉页面 2.5rem 级的默认内边距 |
| 连线交叉 | 正交折线两两相交数 = 0；必须交叉时加跳线桥并在图例注明 | 改走行间空隙，或把交叉的一侧改成虚线绕行 |
| 文字溢出 | 每个 `<text>` 外接框落在所属矩形内（±2px） | 缩短文案 → 提高框高 → 拆行，禁止压字号 |
| 对比度 | 正文/标注 ≥4.5∶1，大字标题 ≥3∶1 | 换同色系更深一档的标题色，不改填充 |
| 导出尺寸 | PNG 像素宽 = 逻辑宽 × 倍数（误差 ≤2px），长边 ≥3000px | 重设窗口尺寸或 `device_scale_factor`，不要靠事后放大 |

验收脚本与逐条命令见 `references/qa-checklist.md`；五项全绿才允许进入导出。检查顺序固定为几何 → 排版 → 色彩 → 导出，前一项不过不改后一项，否则改了颜色回来还要重测几何。

### 第 6 步 · 渲染导出

先抽出独立 SVG（`width` / `height` 写成显式像素），再截图，否则会得到“内容缩在左上角、四周一片白”的废图。完整参数、降级链与常见失败模式见 `references/render-pipeline.md`。

```bash
# 首选：Playwright，元素级截图，天然贴合内容边界
python scripts/render_diagram.py diagram.html --out diagram@2x.png --scale 2

# 降级：Chrome / Edge 无头截图，窗口尺寸必须等于 SVG 固有尺寸
chrome --headless=new --disable-gpu --hide-scrollbars \
  --window-size=1520,856 --force-device-scale-factor=2 \
  --screenshot=diagram@2x.png file:///ABS/PATH/diagram.html
```

- 字体栈固定为 `'Inter', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', 'Noto Sans SC', sans-serif`；Linux 无苹方与雅黑时回退 Noto Sans SC / 思源黑体，绝不回退到 `monospace`（汉字等宽化后对齐全乱）。
- 截图前等 `document.fonts.ready` 并留 300ms 缓冲；用外部 Web 字体时必须等 `networkidle`，否则会截到回退字体的版本。
- PNG 生成后逐张校验像素尺寸；“文件已写出”不等于“尺寸正确”。
- DPI 换算：`像素 = 毫米 ÷ 25.4 × DPI`。A4 竖版 210mm 宽按 300 DPI 需 2480px，即逻辑 1240 × 2；屏幕汇报 2× 足够，标书与印刷件用 3×。清晰度按像素核对，不靠目测。

### 第 7 步 · 交付

按固定目录与命名交付，文件名只允许小写字母、数字、连字符，带版本号，不出现客户名与项目代号。

```
chartatelier-<主题>/
  diagram.html
  diagram.svg
  diagram@2x.png
  qa-report.json
  交付说明.md
```

交付动作：先给 PNG 预览，再列文件清单（路径 + 尺寸 + 体积），最后附 3–5 行要点（图种、配色口径、字号、复现命令）。SVG 必须与 PNG 同时交付，供用户二次编辑。

| 交付项 | 必须 | 验收动作 |
|---|---|---|
| `diagram@2x.png` | 是 | 打开确认无裁切、无模糊、无大块空白 |
| `diagram.svg` | 是 | 在矢量软件中改一个字，确认文本未转曲 |
| `diagram.html` | 是 | 双击直接打开，控制台无报错 |
| `qa-report.json` | 是 | 五项数值全部落在阈值内 |
| `交付说明.md` | 是 | 含图种、配色、字号、复现命令四项 |

交付前最后一遍：把 PNG 缩到 25% 看整体（判断层级与留白），再放到 100% 看局部（判断文字是否糊、箭头是否断）。两个尺度都过关才发出去。

## 输出格式

```
画布：16:9（1520×856）｜4:3（1280×960）｜A4 竖版
边距：外框 64px，节点间距 ≥ 48px
文字：标题 28–34px，节点 16–18px，注释 12–14px
图例：右上角，≤6 项，色块与节点一一对应
导出：PNG，2× DPI
```

## 质量门槛

- [ ] PNG 长边 ≥3000px，像素宽等于逻辑宽 × 导出倍数（误差 ≤2px）；`scale=3` 时长边 ≥4500px。
- [ ] 内容饱和度外接框覆盖画布 ≥95% 宽、≥93% 高，四边留白均在 1–3% 区间。
- [ ] 文字溢出数 = 0：每个 `<text>` 外接框不超出所属矩形 ±2px。
- [ ] 兄弟节点重叠数 = 0；容器边界框与其子节点的重叠不计入。
- [ ] 正交折线相交数 = 0；若采用跳线处理，图例中已注明。
- [ ] 没有任何元素超出 viewBox（含旋转文本），导出图无裁切。
- [ ] 正文与标注对比度 ≥4.5∶1，大字标题 ≥3∶1。
- [ ] 成品中最小字号 ≥10px（2× 输出即 ≥20 像素高），无小于该值的文字。
- [ ] SVG 文本为真实 `<text>` 节点，`width` / `height` 为显式像素，可直接在矢量软件中改字。
- [ ] 图例、编号、单位、页脚版本号与正文一致，无“共 4 页 / 第 1 页共 5 页”式自相矛盾。

## 能力边界

- 不做照片级插画、3D 渲染、拟物图标与品牌 VI 重设计；只按给定 token 收敛配色。
- 不做需要真实地理坐标的精确地图，只做示意区位块与逻辑连线。
- 节点数超过图种上限时拆图，不接受把字号压到 10px 以下换取“一张塞完”。
- 不代填业务数字：涉及未公开经营数据的图，只给结构与占位符（`XX%`），数值由调用方填入。
- 不承诺“能通过评审”或“一定好看”；只保证尺寸、留白、溢出、对比度等参数可被逐条验收。
- 纯文字需求（无结构关系）不出图，改为输出分层要点清单，并说明为何不适合图形化。

## 常见陷阱

- **文字压线**：节点宽度按内容自适应，但忘了留内边距 → 统一 16px 内边距后再估算宽度。
- **浅色主题对比不足**：灰底浅灰字看不清 → 正文与底色对比度不低于 4.5:1。
- **箭头乱指**：连线穿过其他节点，读者要顺着找 → 连线不得穿过任何节点矩形。
- **图例与节点不一致**：改了颜色没改图例 → 导出前逐项比对图例与节点色值。
