# 日常路线，以及怎样选择路线

> **何时读**：要从一句话里选出路线；没有哪条列出的路线合适；要为一个对象调整路线；或者这个人问有哪些路线。

**路线**是一串跨越旅程各阶段的方法。方法很少被单独使用，因为一个好答案通常依赖不止一个阶段。路线有三种：**日常**路线（本页）、**高手**路线（`masters/`）和**个人**路线（在这个人的系统里；见 `system/growth.md`）。

路线是你会调整的默认。它记下的是哪些方法通常能服务某一类请求。它不告诉你下一步该做什么。

## 八条日常路线

| 路线 | 方法 | 典型请求 | 这个人最后得到什么 |
|---|---|---|---|
| **看懂它** | 开启 → 透视 → 流动或回路 → 做成作品 | “帮我真正搞懂 ___。” | 一份展示它怎样运转的成果，围绕一个揭示建立 |
| **解释一个意外** | 透视 → 溯源 → 激励 → 做成作品 | “为什么会发生 ___？” | 让这件意外之事变得不意外的结构与来历 |
| **解决反复出现的问题** | 透视 → 回路 → 瓶颈 → 杠杆 → 最佳实践 → 搭建能力 → 复盘 | “___ 总是发生，怎样彻底解决？” | 不断制造这个问题的回路、该改的那个点、一项适合的实践，以及一个已经生效、带着审视日期的改变 |
| **做一个决定** | 换视角 → 推演 → 二阶思考 → 反过来想 → 权衡 | “我们该 ___ 还是 ___？” | 选项并排比较、各自之后会发生什么、各自怎样失败、各自有多可逆，以及一个推荐 |
| **改进我的做法** | 开启(我) → 瓶颈 → 最佳实践 → 搭建能力 → 复盘 | “以我现在的条件，___ 最好的做法是什么？” | 一项贴合这个人真实条件的实践，搭建成能工作的能力并经过检验 |
| **开启我的系统** | 开启(我) → 透视 → 杠杆 → 最佳实践 | “给我自己开启一个系统。” | 这个人自己处境的图景、能力鸿沟，以及两到四条适合的实践路径 |
| **深入学一样东西** | 开启 → 第一性原理 → 溯源 → 做成作品 → 传授 | “好好教会我 ___。” | 从基本事实建立起来的理解，以及把它讲清楚的能力 |
| **做内容** | 开启 → 透视 → 做成作品（使用内置的视频与设计依赖） | “把 ___ 做成一支给 ___ 看的视频。” | 一份为指定受众做的、完成的讲解，可以直接发布 |

逐条说明：

- **看懂它。** 流动适合有东西在移动和积累的对象（资金、人、物料、注意力）。回路适合行为持续或反复出现的对象。很多对象两者都需要。对外部事物说“给 ___ 开启一个系统”，走的就是这条路线。
- **解释一个意外。** 意外就是入口。通常的发现是：它不是一个事件，而是一个结构露出水面的那一端。如果没有人从结果里得到好处，就把激励换成回路或连接。
- **解决反复出现的问题。** 最长的一条路线，因为它横跨整段旅程。反复出现的问题背后，有一个不断制造它的结构；不碰这个结构的修补，就是“饮鸩止渴”模式。它以复盘结束，因为一次修复是一个有待检验的主张。
- **做一个决定。** 换视角排在最前，因为从每个受影响的位置看，选项通常是不同的样子。可逆性决定一个选择值得多少谨慎。见 `capabilities/methods/5-decide/weigh.md`。
- **改进我的做法。** 先有这个人的条件，才有实践。目标相同的两个人，应该带着不同的实践离开。见 `engines/build.md`。
- **开启我的系统。** 见 `system/root.md`。位置的选择和读取范围，是开场的一部分。
- **深入学一样东西。** 最后的传授，是这个人用自己的话把它讲出来，这是第二份认识记录的证据。
- **做内容。** 受众是请求的一部分：同一份认识，讲给刚入门的人和讲给行内人，是两件不同的作品。成果围绕真实传播场景完成，需要多平台版本或传播物时再调用传播能力。

## 路线是怎样选出来的

从那句话里读出四样东西：

1. **这个人最后需要得到什么。** 一幅图景、一个原因、一次预判、一个杠杆点、一个决定、一样做出来的东西、对已经发生的事的一个判断。它确定路线在哪个阶段结束。
2. **那又依赖什么。** 答案所依赖的前面阶段（见 `journey.md`）。它确定路线从哪里开始。如果这个人的系统里已经有那部分认识，就从更后面开始。
3. **对象是哪一类。** 有东西在流动的，会反复出现的，由人的利益塑造的，由物理极限塑造的，属于这个人自己的。它在同一阶段的方法之间做出选择。
4. **这个人。** 目的、水平、已经理解了什么，以及之前说过的条件。它们决定深度、形式和从哪里讲起。

然后选出合适的路线，调整它，并用一句话说出你走了哪一条。措辞里的信号有帮助，但不起决定作用：“为什么”指向解释，“如果”指向预见，“该不该”指向选择，“总是”“老是”指向回路，“最好的做法”指向最佳实践，“做成”“搭建”指向创造。同样的词，可能落在不同的需要上。

### 当这句话点名了一个方法

“把家用储能电池的成本拆到第一性原理”是对一个方法的请求。完整地运行它，补上它所依赖的最少量的“看懂”，把它作为一份完成的、带来源的结果交付。然后把它自然延续下去的路线，作为下一步选择给出。

### 当没有路线合适

自己组一条。问答案依赖哪些阶段，在每个阶段选一两个方法。说出你组了什么。如果这个组合用得好，而且这类请求很可能再来，就提议一次把它保存为个人路线。

### 当两条路线都合适

如果它们通向真正不同的结果，这就是一个该交给这个人的选择，附上你的推荐，并按推荐先走。如果只是侧重不同，就选一条。

### 当对象离谱、很小或只是好玩

“给我家猫的作息开启一个系统”是一个真实的请求。用同样的诚实、同样的签名来运行它，规模与它相称。一个小对象，常常比大对象更清楚地显示出一个结构。

## 调整路线

- **去掉不会带来增益的方法。** 不是每个对象都有一个值得单独讲的瓶颈，也不是每件意外都有受益者。
- **加上对象需要的方法或视角。** 换一个规模就表现不同的对象，需要尺度。两个需要互相冲突、因而卡住的局面，需要矛盾。问“漏掉了谁”的时候，需要边界。
- **对象需要时调换顺序。** 路线内的顺序跟着依赖关系走，不跟着表格走。
- **再走一圈。** 路线画出来是一条线，但认识是来回移动的：推演里一个落空的预测，会把你送回透视。
- **每个方法都因对象需要而进入。** 路线提供高手经验与依赖关系，运行时继续根据现场增删、替换和重组。

## 每条路线都有的东西

无论哪条路线，用户都会看见真实发现与完成成果，并能从值得继续的方向中选择。身份元素、系统更新、传播物和路线呈现按对象与本次运行的实际需要出现。路线条出现时，显示真正走过的路线，包括系统在现场作出的调整。

## 路线与谨慎的程度

有些路线的终点，是会在对话之外产生后果的行动（搭建能力，以及任何发布、花钱、删除、联系他人或安排代码定期运行的事）。这些行动可以被完整准备，并依据真实所有权与授权进入现实。
