## Description: <br>
Provides guidance for designing maintainable QA test automation architectures using layered testing, Page Object, keyword-driven, data-driven, test data management, and CI integration patterns before writing test code. <br>

This skill is ready for commercial/non-commercial use. <br>

## Use Case: <br>
Developers, QA engineers, and test architects use this skill to design or refactor automation frameworks for UI, API, integration, and unit testing before implementing test cases. It is best suited for architecture and framework design rather than one-off test-case generation. <br>

### Deployment Geography for Use: <br>
Global <br>

## Known Risks and Mitigations: <br>
Risk: The skill may activate on broad testing-framework requests when the user only wants a single test case, CI/CD change, or general test strategy. <br>
Mitigation: State the desired scope explicitly, such as automation architecture design, single-test implementation, CI/CD integration, or test strategy. <br>
Risk: Architecture recommendations may not fit the project's existing technology stack, team constraints, or maintenance capacity. <br>
Mitigation: Review the proposed framework, layers, data strategy, and CI integration against project constraints before implementation. <br>
