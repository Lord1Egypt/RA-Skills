# 采购缺口与下单建议（pmclite-purchase-suggest）

采购最容易犯的两个错：一是漏算（同一张工单算两次或干脆漏行），二是把"在途"当成"已有"。两个错都会让车间在开工当天才发现没料。

净缺口＝毛需求 − 现存 − 在途，要先把所有未完工工单按 BOM 展开再按物料聚合，手算几乎必错。**这一步必须交给 `suggest_purchase`。**

## 前置

`get_dashboard(scope="today")` 探活，失败按 `references/install.md` 引导。

## 调用

- 默认看未来 14 天：`suggest_purchase(horizon_days=14)`；
- 用户说"下个月"就改成 30，"这周"就改成 7；范围 1~180；
- 要更细的物料信息再用 `query_master_data(entity="material", code=...)`，不要用它自己减库存。

## 口径（转述时必须带上）

- **净缺口** = 毛需求 − 现存 − 在途未到量，大于 0 才列出；
- **毛需求** = 未完工工单剩余量（quantity − actualQty）× BOM 用量，**只展开一层**；半成品不递归，遇到半成品要说明"该半成品需另查其 BOM"；
- **不含供应商提前期与最小起订量**——这句必须说，否则用户会把"建议下单量"当成"今天必须下的单"。

## 输出怎么讲

按物料逐项，一行一料：

```
X 项料不够：
1. M001 螺栓 M6 —— 缺 200 个
   毛需求 500（3 张工单，最早 11-18 要）· 现存 300 · 在途 0
   → 建议下单 200
2. M002 垫片 —— 缺 50
   ⚠ 在途 150 预计 11-25 到，晚于需求日 11-18，这部分赶不上
```

`inTransitLate=true` 必须单独提醒"赶不上"，不能混在"在途 150"里让用户以为够了。

## 禁区

- 不许创建采购单、不许说"已经帮你下单了"。本工具纯只读。
- 不许替用户承诺具体下单日期——没有提前期数据，说"今天必须下单"是编的。
- 不许把"建议量"和"在途量"混着说成"已经够了"。
- 结果为空时说"未来 N 天内按 BOM 展开没有净缺口"，不要补一句"应该没问题"。

## 输出结构

`X 项料不够` → 逐项（编码名称、缺口、毛需求与最早需求日、现存、在途是否赶得上）→ `建议下单量` → 一句口径说明（不含提前期与起订量）。
