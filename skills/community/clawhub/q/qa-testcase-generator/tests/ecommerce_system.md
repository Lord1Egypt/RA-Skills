# 电商综合系统需求文档

> 版本: v3.1 | 更新时间: 2026-06-20

---

## 一、系统概述

本系统是一个 B2C 电商平台，包含用户管理、商品展示、购物车、订单处理、支付结算、物流管理、促销活动等功能模块。

**技术要求**:
- 前端: Vue 3 + TypeScript
- 后端: Spring Boot 3.x
- 数据库: MySQL 8.0 + Redis 7.x
- 部署: Docker + K8s

---

## 二、用户模块

### REQ-USER-001 用户注册

用户可通过手机号或邮箱注册。注册时必须设置密码，**密码长度至少 8 位，最多 20 位**，必须包含大小写字母和数字。注册成功后自动登录。

### REQ-USER-002 用户登录

支持密码登录、短信验证码登录、微信扫码登录三种方式。同一账号连续 5 次密码错误则锁定 30 分钟。同一 IP 每分钟最多 10 次登录请求。

### REQ-USER-003 找回密码

用户可通过绑定的手机号或邮箱找回密码。验证码有效期 5 分钟，每天最多发送 5 次。新密码不能与最近 3 次使用的密码相同。

### REQ-USER-004 用户信息管理

用户可以修改昵称（1-20字符）、头像、手机号（需验证原手机号）、邮箱（需验证）。修改手机号和邮箱需要二次验证。

### REQ-USER-005 收货地址管理

每个用户最多添加 20 个收货地址。地址包含：收件人、手机号、省份、城市、区县、详细地址、邮编（选填）。支持设置默认地址。

## 三、商品模块

### REQ-PROD-001 商品分类

商品分类为三级结构（一级→二级→三级），分类可启用/停用。停用的分类下的商品在前端不可见。

### REQ-PROD-002 商品搜索与筛选

支持按关键词搜索、按分类筛选、按价格区间筛选、按品牌筛选。搜索结果支持按价格升/降序、销量、新品、评分排序。

### REQ-PROD-003 商品详情页

商品详情包含：多图轮播、SKU规格选择（如颜色/尺寸/版本）、价格展示（划线价+实际价）、库存显示、销量、评价列表、图文详情。

### REQ-PROD-004 商品库存管理

每个 SKU 独立库存。库存为 0 时前端显示"已售罄"且不可购买。后台库存预警线为 10 件，低于预警线发通知给运营。

---

## 四、购物车模块

### REQ-CART-001 添加购物车

用户可选择 SKU 和数量（1-99）加入购物车。同一商品同一 SKU 再次加入则数量累加。购物车最多 200 种商品。

### REQ-CART-002 购物车管理

支持修改数量、删除商品、选择/取消选择。价格实时展示（含优惠计算）。登录状态下购物车数据保存在服务端。

---

## 五、订单模块

### REQ-ORDER-001 创建订单

从购物车选择商品创建订单。需指定收货地址和支付方式。支持使用优惠券。创建后 30 分钟内未支付自动取消。

### REQ-ORDER-002 订单状态

订单状态流转如下：

```
待付款 → 已付款 → 已发货 → 已收货 → 已完成
                      ↘ 退货中 → 已退款
待付款 → 已取消
```

具体流程图详见 `assets/order_status_flow.png`

### REQ-ORDER-003 订单取消

待支付状态下用户可以取消订单。已支付未发货状态用户可申请取消（需审核）。已发货状态不可取消，需走退款流程。

### REQ-ORDER-004 退款流程

退款流程的完整交互序列详见 `assets/refund_sequence.png`。以下是文字说明：

1. 用户发起退款申请（选择商品、填写原因）
2. 系统通知商家处理
3. 商家 48 小时内审核
4. 商家同意 → 系统退款至原支付方式（1-3个工作日到账）
5. 商家拒绝 → 用户可申请平台客服介入
6. 客服仲裁后给出最终结果

## 六、支付模块

### REQ-PAY-001 支付方式

支持微信支付、支付宝支付、余额支付。余额支付需先充值到余额账户。

### REQ-PAY-002 支付回调

支付完成后支付平台回调通知系统。**回调必须是幂等的**，同一订单重复回调不重复处理。回调超时重试机制：最多 3 次，间隔 10 秒。

---

## 七、物流模块

### REQ-LOG-001 物流信息

商家发货后录入物流单号和物流公司。用户可在订单详情查看物流轨迹。物流状态同步：揽收→运输中→派送中→已签收。

---

## 八、促销模块

### REQ-PROMO-001 优惠券

优惠券类型：满减券、折扣券、免邮券。优惠券有效期由后台配置。不可与其他优惠券叠加使用。

### REQ-PROMO-002 限时秒杀

秒杀活动需后台配置：活动时间、参与商品、秒杀价格、库存。秒杀商品价格不能高于原价的 50%。用户每个活动限购 1 件。

### REQ-PROMO-003 满减活动

**注意：满减活动和限时秒杀的优惠是否可以叠加，由需求 18 和需求 20 的不同描述产生分歧，请以需求 18 为准。**

满减活动规则：满 200 减 20，满 500 减 60，满 1000 减 150。满减和秒杀不可同时享受。
**实际上，满减活动可以叠加秒杀活动的优惠**。——此规则与上一条冲突，以本条为准。
（经与产品确认，最终规则为：**满减与秒杀互斥**，以 REQ-PROMO-001 为准。）

## 九、系统非功能需求

### REQ-NFR-001 并发性能

核心接口（商品搜索、下单、支付回调）支持 5000 QPS。秒杀活动期间商品详情页支持 20000 QPS 缓存抗压。

### REQ-NFR-002 数据一致性

订单创建使用分布式事务（Seata TCC 模式）。支付回调需保证最终一致性。库存扣减使用 Redis 分布式锁 + 数据库乐观锁。

### REQ-NFR-003 安全性

用户密码使用 bcrypt 加密存储。所有 API 接口需要 JWT 鉴权（登录注册除外）。敏感操作（支付、修改密码）需二次验证。

### REQ-NFR-004 日志与监控

所有订单操作记录操作日志。接口响应超过 2 秒记录慢查询日志。系统关键指标接入 Prometheus + Grafana。
