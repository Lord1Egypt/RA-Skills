# 类型判据与反例（types.md）

给模型在「每轮记忆」和「交接抽取」时判定条目类型用。**判据是自然语言，不是正则、不是权重。**

## 优先级

同一句可多标签，`CONSTRAINT` 优先。冲突时以**更晚的显式约束**为准；被推翻的旧项保留在决策链里，不静默删除。`CODE` 是正交材料标记，不参与语义冲突的优先级判定。

## 八类语义判据

下表第一列即标签来源：**中文会话取中文名（如 `[决策]`），英文会话取英文名（如 `[decision]`）**，不另建字典；代码里引用类型时仍用英文大写枚举。

| 类型 | 判据（像什么） | 反例（不算） | 产物去向 | 保真 |
|---|---|---|---|---|
| `CONSTRAINT` 约束 | 禁止 / 必须 / 不许 / 边界 / 硬指标 / 不可改的规则 | 一般建议、偏好 | pin 区逐字 | 永不压缩、永不改写 |
| `ASK` 要求 | 明确的动作指令，可验收 | 模糊的期待 | 待办 / 首条消息 | 逐字进 pin，正文可摘要 |
| `EXPECT` 期待 | 想要的状态或验收标准，不含具体做法 | 已经写明做法的（那是 ASK） | pin 区「验收」行 | 逐字 |
| `IDEA` 想法 | 探索性、可被推翻（「要不要…」「我在想…」） | 已拍板的（那是 DECISION） | 决策段备选 / 速记 | 可摘要，标低确定 |
| `FACT` 事实 | 可核查陈述：数字 / 路径 / 报错 / 版本 / 实测值 | 主观判断、推测 | 结论 | 必须带 quote |
| `DECISION` 决策 | 选了什么 + 为什么 + 被否决的替代 | 只说选了、没理由 | 决策段 | 必须带 quote |
| `REJECT` 否决 | 试过且失败、明确不要、死路 | 只是没做（那是待办） | 否决段（前置） | 必须带 quote |
| `BLOCKER` 阻塞 | 未解决依赖、卡住的问题、等外部确认 | 已解决的 | 阻塞段 | 必须带 quote |

「必须带 quote」的四类（`FACT` / `DECISION` / `REJECT` / `BLOCKER`）+ 两类逐字（`CONSTRAINT` / `EXPECT`）是**硬要求**；`ASK` 逐字进 pin；`IDEA` 允许摘要并标低确定度。

## 正交标记 CODE（不计入语义类型）

`CODE` 不是第 9 种语义类型，而是**材料标记**——表示这条信息的来源是一份要整体读懂、再缩写进正文的原始材料。它与 8 类语义类型正交：一段代码可以支撑决策，也可以成为事实，语义角色仍按决策 / 事实记；当一条记忆主要是在转述材料内容时，直接用 `[代码]` 标签。

统一处理规则只有一条：代码 / 配置 / 数据 / 论文 / ppt / word 等，读懂后缩写为一句结论写进正文对应段落，句末标 `路径:行` 或文档名；**不切片、不贴原文、不设专块**。

## 边界案例

- 「希望背景写得清楚点」→ `EXPECT`（期待，不含做法），不是 `ASK`。
- 「背景必须点明谁/要什么/卡在哪」→ `CONSTRAINT`（可验证的硬规则）。
- 「要不要做个网页编辑器？」→ `IDEA`；若后来决定不做 → `REJECT` 并记理由。
- 一整段 ```` ```js ... ``` ```` → `CODE`：读懂后缩写为一句结论，句末标 `路径:行`；不切片、不贴原文、不设专块。
- 一份 ppt / word / 论文 / 数据表 → `CODE`：读懂核心结论后缩写进正文，句末标文档名或位置；不复制内容、不做章节切片。
- 代码只改一处变量名、没改变行为 → 仍记 `CODE`，写「把 X 改名为 Y，行为不变」，不贴整段。
- 用户说「好的谢谢」「收到」→ **八类都不算**，不是实质结论，不记条目（见 SKILL.md §2.1 判据）。

## 与旧版的区别

没有 `group` / `topic` 类型。**不设主题组**——内容按六段 + 时间顺序组织，相近条目由模型渲染时用标题自然归拢，不做聚类算法。

**原始材料不做机械切片、不设专块**：旧版 v2 把代码块按语义切成零碎片段，产生大量无用数据。这里反过来——整体读懂后缩写为一句结论直接写进正文，句末标来源供回查；原文留在原处，既不切片也不搬进记忆或报告。

**本版新增的一条**：条目**不再带 `[agent]` 前缀**（旧格式每条 `- [WorkBuddy] [时间] [类型] …`）。agent 已由文件名承载，同一文件内 100 条重复同一个词是纯浪费。旧文件的带前缀条目按旧格式兼容读取（schema.md §6），不做改写。
