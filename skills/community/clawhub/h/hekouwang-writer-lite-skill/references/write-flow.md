# WRITE 五步法 · 操作卡

> 适用：常规档及以上的写作/改文档请求。轻量档（改一句话/一个小表）免流程，直接改+一句说明。

## 五步

| 步 | 问题 | 产出 | 常见错误 |
|---|---|---|---|
| **W**ho 读者 | 写给谁？他拿它做什么？ | 一句话读者画像 + 用途（决策/执行/存档） | 不写读者就动笔，术语深浅全凭感觉 |
| **W**hy 目的 | 希望读者看完做什么？ | 结尾的呼吁动作（去办X、定Y、存Z） | 文档没有行动出口，读完不知道干嘛 |
| **H**ow 结构 | 用什么结构装内容？ | 标题骨架 + **每节一句核心句** | 先写正文后排结构，越写越散 |
| **D**raft 起草 | 填内容 | 表格优先的初稿；一句一事；数字加粗 | 大段 prose；一句话塞三个事实 |
| **P**olish 润色 | 删改 | 过检查清单后的终稿 | 只加不减——好文档是删出来的 |

## 每节核心句怎么写

每节标题下第一句就是结论，加粗。读者只读核心句就能跟上全文逻辑。

**合格**：含对象 + 结果或动作，不读本节正文也能决定「跳过 / 精读 / 去执行」。

- 反例：`## 三、缴费记录`（下面自己看）
- 反例（空壳目录语，不合格）：`**方案分五组。**`、`**下面分别说明。**`、`**本节介绍背景。**`
- 正例：`## 三、缴费记录\n\n**核心句：她的缴费家底已全部核实。12年已缴，仅2025年断缴，个人缴费合计1,600元。**`
- 正例：`## 方案\n\n**全局层先落地；项目层只留指针，按批次执行。**`

## 七种文档原型结构

| 原型 | 结构 |
|---|---|
| 办事指南/家庭文档 | 摘要 →（可选：30秒导航）→ 已确认事实 → 规则 → 测算 → 时间线与行动清单（含失效条件）→ 依据 → 术语表 |
| 方案 | 摘要 →（可选：导航）→ 背景/目标 → 方案 → 排期与资源 → 验收与风险；执行型方案（迁移 / 规范落地 / 开发计划）改「按批执行为主干、明细下沉附录」 |
| 报告 | 结论 → 数据 → 分析 → 建议 |
| 说明 | 是什么 → 怎么做 → 注意事项 |
| 邮件 | 目的 → 背景 → 请求/行动 → 截止时间 |
| 汇报 | 结论 → 理由 → 行动（金字塔） |
| 修订 | 复述原意与改动点 → 出稿（保留事实，只调表达） |

执行型方案（迁移、规范落地、开发计划）另见付费版 `pack-execution-plan.md`；免费版至少遵守上表「方案」行。

## 单一真源（计划、日期、金额只完整写一处）

同一个计划/截止日/金额在多处完整重复，改一处漏一处，文档就自相矛盾。

- 完整版只写在一个地方：办事文档写在"时间线与行动清单"，测算写在测算节。
- 其他地方只写一行要点 + "见第X节"，不重复日期、操作路径、明细。
- 时间线和行动清单**合成一节**（勾选清单按时间分组），不要一节表格、一节清单各写一遍。
- 自检：随便挑一个截止日，全文搜它出现几次；超过 2 处（摘要一行 + 正文一处）就是重复。
- **测算对比**：有公共基数（不论选哪档都有的部分）时，主表或附一行给出「只算增量」指标，并写明口径；完整证据三分与出处卡见付费版 `evidence-and-delivery.md`。
- **多来源限制表**：每个数值注明接口／文件与小节，禁止把 A 接口的限制写成产品级；付费版同见 `evidence-and-delivery.md` 一d 节，免费版按上句自检即可。

## 摘要（最多 3 条）

| 条 | 回答什么 |
|---|---|
| 结论 | 现状 + 最终能得到什么（含"以核定为准"等模态） |
| 现在做什么 | 按时间的步骤，每步一行，细节指向正文 |
| 最大风险 | 出口闸门第二问的失效条件，一行 |

背景解释（"为什么查不到"）、算法、明细一律放正文，不进摘要。

## 30秒导航表（可选）

**只在两种情况下加**：正文超过 7 节；或者摘要回答不了读者最常问的问题。摘要已经写清"要做什么"、标题本身能当目录用时，不加——它会和摘要、标题重复。

要加时放在摘要后：

```markdown
## 我想干什么，去哪一节

| 你的问题 | 去这里 |
|---|---|
| …… | 第X节 |
```

## 措辞四原则

| 原则 | 做法 | 反例 → 正例 |
|---|---|---|
| 具体 | 用数字和事实 | "缴了不少年" → "缴了12年，合计1,600元" |
| 简洁 | 一句一意 | "既…又…而且…" → 拆两句 |
| 主动 | 动词+对象 | "对补缴进行了核定" → "窗口核定补缴档次" |
| 一致 | 全文术语统一 | "社保窗口/政务中心/经办窗口"混用 → 首次定义后只用一种 |

## 体检档 / 检查档与格式档（不启动措辞改写）

**体检档**（触发语「只检查 / 先别改 / 只告诉我问题 / 体检」）：只输出诊断清单——位置 / 原句（或现象）/ 问题 / 建议；**不生成改写、不覆盖文件**。脚本输出照实引用（原样转录，不改其中的数字、不替它下结论），四个检查器既有 `--json` 字段不动。清单默认只在对话内输出；用户明确要求落盘时，另写独立 `diagnosis.md`，先展示将要写入的位置与内容经用户确认，且绝不覆盖用户原文——写报告是 agent 的显式动作，不是脚本行为。

- 只要求检查表达、歧义、错别字 → 逐句或逐项给「原句 + 问题 + 建议改法」；检查请求不授权重写或覆盖文件。
- 只要求排版、格式转换、逐字引用、去掉行末句号 → 只执行指定操作，不改措辞；只对指定一处做这类操作时，先重读文件当前版本，只在点名范围内执行。

## 修订模式（带既有文本：改一下 / 润色 / 不顺 / AI 味重）

**不要默认当新写。**

1. **先问一个目标**：结构乱 / 数字错 / 句子难读 / AI 味 / 太长？用户说「你看着办」才全面改。
2. **复述原意与改动点**：先说「保留 X，准备动 Y」，再出稿。
3. **出稿 + 改动清单**：每处一行（位置 + 改前 → 改后 + 原因），可逐条回退。有 git 靠 git；无 git 时清单即回退依据；大改前备份文件名告知用户。
4. **数字、日期、专有名词原样不动**；有出处证明其错的，单独指出；不擅自增删用户未提及的信息。
5. **跑脚本**：常规档必跑 `sawdust_scan` + `sentence_load` + `doc_lint`；去 AI 味加 `rhythm_scan`。轻量档只改一句不跑脚本。
6. **自己的改动自己核对**：清单与终稿逐条对；清单外改动补进或还原；数字变化逐条说明理由。

### 用户文字保护（冲突时从高到低）

| 级 | 内容 |
| --- | --- |
| 1 | 用户本轮明确指令 |
| 2 | 用户亲自修改并确认的当前版本 |
| 3 | 用户提供的事实、名称和格式 |
| 4 | 权威来源中的事实 |
| 5 | 本 Skill 的默认结构与措辞 |

硬操作：改前必读当前文件（不凭对话记忆还原）；用户声明「我的修改肯定没问题」→ 现有修改硬锁，除非随后点名；不加回用户删掉的内容；范围外零变化。「保留原文」与「整体改写」同时出现时，先确认保留范围。

### 修订档交付前四项

1. 以当前文件为底稿（已重读）？
2. 用户亲自修改的内容原样保留？
3. 改动范围未超出用户点名？
4. 用户删掉的内容未被加回（目标词全文搜索核对）？

### 修订变更闭环（交稿四类联动检查）

改一处，连带核对该处的引用是否同步；四类逐条过：

| 检查项 | 核对什么 |
|---|---|
| 标题改动 | 目录、交叉引用、文内「见第 X 节」是否同步 |
| 数字改动 | 出处卡的「数字 / 来源 / 访问日」是否更新，测算口径是否仍成立 |
| 图表改动 | 图注、表题、单位是否仍与内容匹配 |
| 删除章节 | 其他章节（含摘要与导航表）是否还在引用被删内容 |

守修订铁律：改动可列出、可回退；脚本只报告，不改文件。闭环结果写进回复，不写进用户文档。

## 五轴心（交付前过一遍）

| 轴心 | 问自己 |
|---|---|
| 保真 | 数字、日期、金额、文件名对吗？ |
| 去 AI 味 | 锯末词扫了吗？收束句硬加了吗？ |
| 一致 | 术语、口径、单位全文统一吗？ |
| 可读 | 结论前置了吗？只读摘要知道做什么吗？长句拆了吗？**扫读三问过了吗？**（见下） |
| 场景适配 | 结构与读者匹配吗？ |

### 扫读三问（常规档及以上；任一项否 = 未过可读，按 🔴 阅读硬伤处理）

1. **只读 H2/H3 + 每节核心句**，能否复述目标与下一步？
2. **只读摘要 + 行动/排期清单**（如有），能否开工或做决定？
3. **打开任一对照表或变更表**，能否约 10 秒内找到「与我相关的那一行」？

### 阅读硬伤（与事实硬伤同级：须改信息架构，不可只润色放行）

命中任一条，审稿标 🔴 阅读硬伤（级别名可写「阅读硬伤」，改法必须动结构，不是换词）：

| 硬伤 | 判据 |
|---|---|
| 缺导航却过长 | 正文 ≥8 个 H2（或同级节），且摘要回答不了读者最常问的跳转问题，又无「我想干什么，去哪」类导航 |
| 发现/变更平铺无法按问题定位 | 调研有多个子问题、或方案有多条需求/批次，正文却只有纯序号平铺（3.1…3.10 / A…E），读者无法从标题看出「哪块管哪个问题」 |
| 方法挡扫读 | 方法/依据写得过长却无「怎么读」可跳到结论；**或**为求短把「二」「七」整节改成附录、用别的内容占第二节号（调研体禁止，见付费版 `doc-research-report.md`） |
| 空壳核心句 | 节首加粗句是纯目录语（「分×组」「下面分别说明」「本节介绍…」），不含对象+结果/动作 |
| 双编号无对照 | 同时使用两套编号体系（如设计分组 A–E 与执行批次 0–6），正文无一张对照表，强迫读者心算映射 |

证据齐全、句长合规但触犯上表 → **仍算未通过**，不得因「结构七节齐了」放行。

### 保真三闸（常规档及以上；与扫读并列，答不上不许交付）

1. **「相反 / 颠倒 / 写反 / 与…相反」主张**  
   必须同时写出：被否定方原句（注释、文档、常量名）+ 实际调用点行为（赋值、查询条件）。两边同向 → **禁止**写「相反」，只可写「易混 / 名称误导」。只写一边或凭感觉断言 → 🔴 已证实错误或 🟡 依据不足。

2. **交叉引用自检**  
   凡「见本节」「见第 X 节」「见某某」「去这里」：目标标题必须真实存在。导航表里禁止用「本节」指别的章节。改标题后重扫全文引用。断链 → 🔴 阅读硬伤（改引用或改标题）。

3. **模态与证据级别**  
   - 「已定 / 已确认 / 拍板」须写决策主体或出处；没有 → 改「建议口径」或「待书面确认」。  
   - 「均为 A 级 / 全部已核实」与文内 B/C/未取/推断并存 → 🔴 事实硬伤：改成「以 A 为主，其余标级别」。  
   - 摘要里的「每个 X」若正文是「按 Y 共用」，须在摘要点明维度，避免误读。

### 先业务、后实现（代码/表结构类段落）

现状分析、技术方案、调研发现里出现表名、字段、箭头关系、函数名时：

1. **先写不含表名的业务句**（谁、做什么、结果怎样、举例）。  
2. **再写「实现要点」**：表名、字段、`path:line`、代码块——给要对代码的人。  
3. **禁止**用 `` `表A` ← `键` → `表B` ``、裸字段串、`A → B → C` 符号链当主叙事；箭头只能出现在已用人话解释过的示意图或实现要点里。  
4. 字段首次出现用「业务名（`field`）」；后文可只用字段名。

触犯 → 🔴 阅读硬伤（改写法，不是删证据）。受保护 Token 仍须保留，但不得代替业务说明。

## 出口闸门两问（答不上不许交付）

1. **最强反证**：哪个数字/结论最可能错？核实过了吗？
2. **失效条件**：什么情况下过期？写在行动清单旁与摘要里了吗？（只藏在文末「依据」节不算）

常规档及以上另过**扫读三问**与**保真三闸**；触犯阅读硬伤表或保真三闸任一条 → 先改正文再交。

## 交付与失败

- 正文后附**进度卡**；整改写**级别 + 位置 + 问题 + 怎么改**。禁止只报「合规风险：🔴」不说位置。
- 审稿分级：🔴 已证实错误或**阅读硬伤**（直接给改法；阅读硬伤改的是分组/导航/主干顺序）；🟡 依据不足待核；🟢 可选表达建议（用户只问事实时不给）。范围内没问题就直说，不为凑数。
- **进度卡、脚本结果、改动清单写在回复里，不写进用户文档。**
- 任一步失败：报告哪一步 + 原因 + 用户可执行下一步。不静默失败，不假装完成。

## 自进化：learnings（默认只在会话内）

- **默认不落盘**：用户纠正、自查发现错误、同一坑第二次、发现更好方法，只在本次会话里记住并用上；不创建、不追加任何文件。
- **落盘需确认**：只有用户明确说「记下来」或同意保存时才写。写之前先在回复里给出拟写条目、目标路径和用途，等用户点头；没点头就只在会话内记住。
- **位置**：`~/.hekouwang-writer/learnings/`（用户级，目录权限 700，仅本人可读）。不写技能安装目录（可能多人共享），不写用户项目目录。目录建不了就保持会话内记忆，并说明原因。
- **只存通用规则**：写「哪类句子怎么改」这类可复用的写作规则与错误类型；不存用户正文、姓名、机构、数字、文件路径等材料内容。秘密、令牌、证件号一律不记；案例脱敏。
- **保留与删除**：每条带日期；保留 90 天，到期由用户确认后清理。用户可随时要求列出或删除全部条目。
- **不自动改规则**：learnings 从不写入 `SKILL.md` 或本目录规则。确需晋升时，先给拟改条文与 diff，用户明确同意后按其指令改，并在 `CHANGELOG.md` 记一笔。
