## 2.0.1 等价类划分法（Equivalence Partitioning）

将输入域划分为若干等价类，从每个等价类中选取代表性数据作为测试用例，减少冗余测试用例数量同时保证覆盖度。

#### 划分原则：
| 等价类类型 | 划分规则 | 示例 |
|:---|:---|:---|
| **有效等价类** | 合理、有意义的输入 | 用户名长度 6-20 位 → 取 10 位有效用户名 |
| **无效等价类** | 不合理、无意义的输入 | 用户名长度 6-20 位 → 取 3 位、25 位、空值 |

#### 用例设计步骤：
1. 分析需求规格说明，确定输入域
2. 划分有效等价类（正常场景）
3. 划分无效等价类（异常场景）
4. 为每个等价类设计唯一编号
5. 设计用例覆盖所有有效等价类（尽可能少的用例覆盖尽可能多的有效等价类）
6. 为每个无效等价类单独设计用例

#### 输出格式：
```
### 等价类划分表：
| 等价类编号 | 类型 | 输入条件 | 预期结果 |
|:---:|:---:|:---|:---|
| EC-001 | 有效 | 用户名 6-20 位字母 | 注册成功 |
| EC-002 | 无效 | 用户名 < 6 位 | 提示"用户名长度不足" |
| EC-003 | 无效 | 用户名 > 20 位 | 提示"用户名长度超限" |
```

## 2.0.2 边界值分析法（Boundary Value Analysis）

针对等价类的边界值设计测试用例，70% 的缺陷出现在边界处。

#### 边界选取原则（"三点法）：
| 边界类型 | 选取点 | 示例（范围 1-100） |
|:---|:---|:---|
| **最小值** | min, min-1, min+1 | 1, 0, 2 |
| **最大值** | max, max-1, max+1 | 100, 99, 101 |
| **特殊值** | 0, 空值, null, 极值 | 空字符串, null, -1 |

#### 常见边界场景：
- 数值边界：数字范围、分页页码、数量上限
- 字符串边界：长度限制、特殊字符边界
- 集合边界：空数组、单元素、最大元素数
- 时间边界：开始/结束时间、跨天、跨月、跨年
- 权限边界：权限临界值、角色切换边界

## 2.0.3 判定表法（Decision Table）

适用于多个输入条件组合较多、逻辑关系复杂的场景。

#### 判定表组成：
- **条件桩**：列出所有输入条件 |
- **动作桩**：列出所有可能的操作结果 |
| **条件项**：条件的各种取值组合 |
| **动作项**：对应条件组合的结果 |

#### 示例（登录功能判定表：
```
| 条件桩 | 规则1 | 规则2 | 规则3 | 规则4 |
|:---|:---:|:---:|:---:|:---:|
| 用户名正确 | Y | N | Y | Y |
| 密码正确 | Y | Y | N | Y |
| 验证码正确 | Y | Y | Y | N |
| --- | --- | --- | --- | --- |
| 登录成功 | ✅ | ❌ | ❌ | ❌ |
| 提示用户名错误 | ❌ | ✅ | ❌ | ❌ |
| 提示密码错误 | ❌ | ❌ | ✅ | ❌ |
| 提示验证码错误 | ❌ | ❌ | ❌ | ✅ |
```

## 2.0.4 场景法（Scenario-based Testing）

基于业务场景设计测试用例，覆盖用户真实使用路径。

#### 场景类型：
| 场景类型 | 说明 | 覆盖要求 |
|:---|:---|:---|
| **基本流** | 正常无错误的主路径 | ✅ 必测 |
| **备选流** | 正常分支路径 | ✅ 必测 |
| **异常流** | 错误处理路径 | ✅ 必测 |

#### 设计步骤：
1. 分析业务流程，画出流程图
2. 识别基本流（Happy Path）
3. 识别备选流和异常流
4. 为每条流设计场景
5. 为每个场景设计测试用例

#### 示例（订单流程场景：
```
### 场景清单：
| 场景ID | 场景描述 | 流类型 | 优先级 |
|:---:|:---|:---:|:---:|
| SC-001 | 正常下单支付成功 | 基本流 | P0 |
| SC-002 | 库存不足，下单失败 | 异常流 | P1 |
| SC-003 | 余额不足，支付失败 | 异常流 | P1 |
| SC-004 | 用户取消订单 | 备选流 | P2 |
```

## 2.0.5 错误推测法（Error Guessing）

基于经验和直觉推测可能出现的错误，针对性设计用例。

#### 常见错误推测清单：
- **历史错误**：之前出现过的 Bug 回归
- **常见错误**：空值、特殊字符、格式错误
- **并发错误**：重复提交、竞态条件
- **边界错误**：刚好达到上限、刚好不足
- **依赖错误**：第三方服务失败、网络超时

#### 必测错误场景清单：
```
### 通用错误推测清单（必测）：
1. ✅ 空值/null/undefined 处理
2. ✅ 特殊字符（!@#$%^&*()_+）
3. ✅ 超长文本（数据库字段长度边界）
4. ✅ SQL/XSS 注入尝试
5. ✅ 重复提交（双击、快速点击）
6. ✅ 并发操作（多用户同时修改）
7. ✅ 网络超时与重试机制
8. ✅ 依赖服务降级/不可用
```

## 2.0.6 用例设计优先级与覆盖策略

#### 用例设计优先级排序（从高到低：
1. **P0 冒烟测试 → 等价类有效等价类边界值 → 判定表 → 场景法基本流
2. **P1 核心链路 → 场景法备选流 → 边界值有效边界
3. **P2 异常测试 → 无效等价类 → 异常流 → 错误推测

#### 覆盖度要求：
| 优先级 | 覆盖要求 |
|:---|:---|
| **P0** | 100% 核心功能等价类有效覆盖 |
| **P1** | 100% 核心业务场景覆盖 |
| **P2** | 80% 异常场景覆盖 |

## 2.0.7 用例设计检查清单

在设计完测试用例后，必须逐项检查：
```
✅ 用例设计检查清单：
[ ] 是否覆盖了所有有效等价类
[ ] 是否覆盖了所有无效等价类
[ ] 是否覆盖了所有边界值
[ ] 是否覆盖了核心业务场景
[ ] 是否考虑了并发和竞态条件
[ ] 是否包含了错误推测的常见错误
[ ] 用例是否有明确的预期结果
[ ] 用例是否可重复执行
[ ] 用例是否独立不依赖其他用例
[ ] 是否包含了前置条件说明
```
