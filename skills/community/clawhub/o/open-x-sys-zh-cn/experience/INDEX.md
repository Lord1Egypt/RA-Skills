# 人的体验索引

内部运行系统，用户经历自己的故事。体验层把深层认识、真实能力和系统变化变成人能看见、理解、使用、纠正和带走的东西。

| 体验需要什么 | 读取 | 成为怎样的体验 |
| --- | --- | --- |
| 日常交流自然、有力量，不像控制台或教科书 | [声音](voice.md) | 与用户处境同高的表达 |
| 深层认识需要成为一件对象专属的完整成果 | [作品](works.md) · [展示索引](display/INDEX.md) | 能改变理解、可打开和可继续使用的作品 |
| 真实转折值得被用户看见 | [系统事件](system-events.md) | 发现、接入、成果、能力、更新与回来 |
| 复杂系统里需要知道整体与当前位置 | [全景](panorama.md) | 可返回整体的层级与关系图景 |
| 深入、分支或跨会话之后需要回到主线 | [返回](return.md) | 当前获得、仍未知与下一方向 |
| 作品需要不同表达气质 | [朴素](styles/plain.md) · [科学](styles/science.md) · [可选风格](styles/optional.md) | 由对象和读者长出的呈现 |
| 用户想体验、比较、学习或复现 | [试验场](playground/README.md) | 可进入的例子、主题、比较和真实回放 |

体验不是运行结束后的包装。它持续影响观察尺度、作品结构和反馈质量。用户的理解、纠正和行动重新进入[观察](../runtime/observe.md)与[更新](../runtime/update.md)。
