# 迭代模式参考

## Ralph Wiggum 模式分析

### 核心机制

Claude Code 的 Ralph Wiggum 实现了一种巧妙的自引用循环：

1. **Stop Hook 拦截**：当 agent 尝试停止时，Stop Hook 被触发
2. **Promise 检测**：Hook 检查 agent 输出中是否包含 `<promise>` 标签
3. **自引用喂回**：如果承诺未完成，Hook 阻止停止并将未完成的承诺作为新的 prompt 喂回
4. **循环持续**：agent 被迫继续工作，直到所有承诺兑现

### 关键设计要素

```
Agent 执行 → 产生 <promise> → 尝试停止
    ↓
Stop Hook 检测到未完成的 promise
    ↓
阻止停止 + 将 promise 作为新 prompt
    ↓
Agent 继续执行 → 兑现 promise → 尝试停止
    ↓
Stop Hook 检测：所有 promise 已兑现 → 允许停止
```

### 优势

- **自治性**：agent 自主决定何时完成，无需外部编排
- **可靠性**：不会遗漏承诺的任务
- **简洁性**：仅需一个 Hook 即可实现循环

### 局限

- **依赖特定标签**：需要 agent 输出 `<promise>` 标签
- **难以量化进度**：不知道循环了多少次、还剩多少
- **无状态持久化**：中断后无法恢复

## 我们的实现：状态文件 + 循环控制器

### 设计决策

我们用显式的状态管理替代隐式的 Hook 拦截：

| Ralph Wiggum | 我们的实现 |
|---|---|
| Stop Hook 拦截 | loop-controller.py check |
| `<promise>` 标签 | completion_check 条件 |
| 隐式循环 | 显式迭代计数 |
| 无状态 | JSON 状态文件持久化 |
| 无法中断恢复 | 可从状态文件恢复 |

### 三种迭代模式

#### 1. Fixed（固定次数）

适用场景：已知需要固定轮次的任务（如 5 轮代码审查）。

```
初始化 → 执行 N 轮 → 停止
```

特点：简单可靠，不做条件判断。

#### 2. Max（最大次数 + 完成条件）

适用场景：不确定需要多少轮，但有明确完成标准的任务。

```
初始化 → 检查条件 → 未满足 → 执行一轮 → 更新状态 → 循环
                    → 已满足 → 停止
                    → 达到上限 → 停止
```

特点：有上限保护，避免无限循环。

#### 3. Adaptive（自适应）

适用场景：需要持续改进直到收敛的任务（如性能优化）。

```
初始化 → 执行一轮 → 评估改进
                    → 有改进 → 重置计数器 → 继续
                    → 无改进 → 递增计数器
                    → 计数器 >= patience → 停止
```

特点：自动检测收敛，避免无意义的迭代。

### 与 sessions_spawn 集成

每轮迭代 spawn 独立子代理执行，实现隔离和并行：

```
主代理（循环控制器）
  │
  ├─ init → 初始化状态
  │
  ├─ loop:
  │   ├─ check → 是否继续？
  │   ├─ spawn → 子代理执行一轮
  │   ├─ 子代理完成 → 返回结果
  │   ├─ update → 记录结果
  │   └─ 回到 check
  │
  └─ complete → 生成摘要
```

### 完成条件检测策略

| 类型 | 适用场景 | 示例 |
|------|----------|------|
| regex | 有明确文本输出 | `regex:All tests passed` |
| file | 需要文件产出 | `file:dist/build.zip` |
| file-changed | 需要文件更新 | `file-changed:src/main.py` |
| llm | 需要主观判断 | `llm:代码质量达标` |

### 最佳实践

1. **始终设置 max**：即使使用 adaptive 模式，也设置 max 作为安全阀
2. **记录 artifacts**：每轮产出的文件应记录到 artifacts
3. **使用 metrics**：量化改进（覆盖率、性能指标等）便于 adaptive 判断
4. **保留状态文件**：循环结束后状态文件是复盘的重要数据源
5. **避免空转**：如果连续 2 轮结果相同，考虑调整策略或停止
