# 标准支付系统域地图

国内持牌第三方支付/聚合支付机构的通用域划分。13 个域分四圈：接入圈、交易圈、资金圈、支撑圈。每个域给出：定位一句话、核心职责、持有的权威数据、对外契约、边界（不做什么）。

## 一、总览表

| 圈 | 域 | 定位 | 权威数据 |
|---|---|---|---|
| 接入 | 开放平台/网关 | 对外唯一入口，认证验签、防重放、限流 | 商户密钥、API 契约、回调配置 |
| 接入 | 收银台 | 支付页面/组件编排，支付方式聚合展示 | 收银会话、可用支付方式快照 |
| 交易 | 收单（业务单域） | 外部业务主单持有者、薄编排层 | 业务主单、流程步骤、通知 outbox |
| 交易 | 交易核心/支付引擎 | 资金动作执行者，对接渠道的资金接口 | 支付指令、渠道流水映射、支付结果 |
| 交易 | 产品 | 产品要素与模板定义（费率、流程模板） | 产品配置、费率规则、流程模板版本 |
| 资金 | 账户 | 账户体系与动账执行，账的权威 | 账户/账簿/余额桶、动账明细、冻结单 |
| 资金 | 清结算 | 账房：计费、记账编排、对账、结算、备付金 | 清算事件、凭证、对账批次、结算单 |
| 资金 | 渠道 | 银行/银联/网联/钱包通道适配与路由 | 通道配置、通道流水、通道对账文件 |
| 支撑 | 商户/商服 | 商户全生命周期：进件、签约、审核 | 商户主数据、进件流程单 |
| 支撑 | 会员 | 个人/商户操作者身份与认证 | 会员主数据、凭证 |
| 支撑 | 风控 | 事前准入、事中实时决策、事后处置 | 名单、规则、决策日志 |
| 支撑 | 运营/BFF | 内部运营操作与查询 | 无权威资金数据（只读+工单） |
| 支撑 | IAM/审计 | 统一认证授权、操作审计 | 权限模型、审计日志 |

## 二、各域职责与边界

### 1. 开放平台/网关（Open Gateway）

- 职责：统一认证验签（商户私钥/平台公钥）、防重放（时间戳+nonce 窗口）、限流熔断、参数校验、API 版本路由、异步回调投递（接收业务域 outbox，负责 HTTP 重试管道）。
- 边界：无业务语义，不做资金判断，不持有交易单。
- 契约：对商户是同步受理响应 + 异步回调（带签名、要求 ACK，指数退避重试，终态必达）。

### 2. 收银台（Cashier）

- 职责：按交易上下文聚合可用支付方式（余额/银行卡/扫码/网银）、渲染收银页、发起支付、轮询/推送支付结果。
- 边界：是收单域的一类请求方，不直接调支付引擎；不持有业务主单。
- 红线：支付方式可用性快照在创建会话时锁定，支付过程中不回源变更。

### 3. 收单（Acquiring，业务单域）

- 定位：**对外业务主单持有者与薄编排层**。受理一切外部交易请求（商户 API/收银台/充转提），按产品要素快照驱动流程，调用支付引擎完成资金动作，跟踪业务终态，组织对外通知。
- 三条铁律：
  1. **受理即锁快照**：流程中任何步骤不回源产品域取配置。
  2. **本域不算费**：费用归清结算域。
  3. **业务单状态 = 全部编排步骤终态的汇总**，不手工维护主状态字段。
- 权威数据：业务主单（含产品要素快照、请求指纹）、流程步骤单、定时任务单、通知 outbox。
- 状态机参考：`CREATED → PROCESSING → SUCCESS / FAILED / CLOSED`，外加 `FAIL_PROCESSING`（资金已成功而后续步骤失败的人工查证态，禁止伪造补偿完成）。
- 边界：不直接接渠道、不动账、不算费。

### 4. 交易核心/支付引擎（Trade/Pay Engine）

- 职责：执行资金动作（支付/退款/充提转代付），维护支付指令与渠道流水映射，处理渠道同步应答与异步通知，推进支付终态，向收单/清结算发出事件。
- 边界：不接外部商户请求（只接内部域调用），不持有商户业务语义。
- 红线：出金类动作前置完成计费；渠道结果 UNKNOWN 时按原指令号查证收敛。

### 5. 产品（Product）

- 职责：产品要素定义——费率规则、流程模板（即时到账/担保/顺序扣款/退款/批量）、支付方式开关、限额。
- 契约：以"快照+版本号"向收单提供要素；收单受理时锁定版本，后续变更不影响在途单。

### 6. 账户（Account）——账的权威

详见 `accounting.md`。核心：账户→账簿→余额桶三层模型，语义化记账指令，三口径（外部可用/冻结/内部账面）恒等式，动账明细 append-only，日切快照。

### 7. 清结算（Clearing & Settlement）——账房

- 职责：接收交易核心清算事件 → 计费 → 记账编排（记账簿+科目账双轨）→ 对账 → 商户结算 → 备付金核验 → 会计核算。
- 边界五不：**不动钱、不建交易单、不接渠道回调、不做营销券规则、不替代财务总账**。
- 详见 `accounting.md` 对账/结算/备付金章节。

### 8. 渠道（Channel）

- 职责：银行/银联/网联/第三方支付通道的协议适配、路由（成本/成功率/限额）、通道流水登记、通道对账文件获取与解析。
- 红线：通道报文组装下沉到防腐层；通道回调验签后方可受理；通道故障切换不改变业务单语义。

### 9. 商户/商服（Merchant Service）

- 职责：商户进件（KYC/KYB 资料收集）、多级审核流程、签约产品、商户状态生命周期。
- 模式：流程引擎驱动多节点链（资料校验→风险预审→人工审核→事件发布）；外部依赖未就绪时事务前 fail-closed。

### 10. 会员（Member）

- 职责：个人与商户操作者身份、登录凭证、实名要素、密码/密钥托管（对接加密服务）。
- 边界：不做权限（归 IAM），不持有商户业务资料（归商服）。

### 11. 风控（Risk）

- 职责：事前（准入/名单）、事中（实时决策接口，同步返回 PASS/REJECT/REVIEW）、事后（处置、限权、冻结建议）。
- 红线：风控接口非幂等时禁止自动重试；风控不可用时的降级策略必须显式冻结（默认拒绝 or 放行后置审核，二选一成文，不允许裸奔）。

### 12. 运营/BFF（Operations）

- 职责：内部查询（订单/账务/商户）、人工操作（调账申请、差错处理、人工审核）。
- 红线：**不直接写资金表**；一切人工资金操作走工单+双人复核+调用资金域正式接口；查询走只读库或查询专用接口。

### 13. IAM/审计

- 职责：统一认证（SSO/Token）、逐动作授权、四性审计（机密/完整/可用/不可否认）、敏感操作双人制（operator≠reviewer）。

## 三、标准资金链路（域间协作）

```
商户/用户 → 网关(验签) → 收单(受理,锁快照,建业务主单)
        → 交易核心(支付指令) → 渠道(通道执行)
        ← 渠道异步通知 → 交易核心(终态收敛)
        → 清结算(清算事件: 计费→记账编排) → 账户(动账,append-only)
        → 收单(业务终态汇总) → outbox → 网关(异步回调商户)
T+1: 渠道对账文件 → 渠道域解析 → 清结算对账(三级匹配) → 差异→差错单
     → 日切快照 → 日结勾稽 → 商户结算(到内部户/到卡出金)
```

关键协作契约：

1. **收单 ↔ 交易核心**：同步受理 + 异步事件双路径；以请求号/交易号为全局追踪键。
2. **交易核心 → 清结算**：清算事件 E1~E9 类型化（入金/退款/分账/补贴/转账/出金冻结/费用/退费/担保确认），事件号全局唯一幂等。
3. **清结算 → 账户**：语义化记账指令（指令号幂等），账户只认指令不认业务故事。
4. **一切对外通知**：业务域写 outbox，网关域负责传输与重试，语义与传输分离。

## 四、常见架构反模式（评审时直接点名）

| 反模式 | 后果 |
|---|---|
| 收单直接调账户动账，绕过清结算 | 账实分离，对账无法闭环 |
| 交易核心持有商户业务语义 | 核心腐化，多业务方无法复用 |
| 费率在收单/交易侧各算一次 | 双算费，差异必然出现 |
| 运营后台直接 UPDATE 余额/状态 | 审计断链，资金事故 |
| 渠道回调直接改业务单状态 | 无验签无幂等，伪造回调即资金损失 |
| 业务状态字段手工维护 | 与步骤终态漂移，终态不可信 |
