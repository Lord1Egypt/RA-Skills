# 报告编排与交付公约

适用于产出**完整 HTML / Markdown 报告**的场景技能（市场早报、组合诊断、选基、基金分析、投顾内容、家庭规划、资产配置方案等），以及有客户可见交付物的计算引擎类技能（`wealth-healthcheck`、`wealth-goalcalc`、`wealth-goalmatch`）。各子技能 `SKILL.md`「合规与免责」只写**场景红线** + **链本节 §7 锚点**（禁止内联自拟免责全文）；伴生模式不对客展示的技能见各技能说明。

---

## 1. 编排素材不得进入交付物

**客户可见**的正文、页眉页脚、表格、图表脚注中的禁显与数据来源口径，以 [`MCP数据真实性零容忍.md`](MCP数据真实性零容忍.md) **§0** 为准（含 MCP/API 名称、统一写「数据来源：盈米MCP」等）。本节只补充 **§0 未单独列出** 的编排残留：

| 残留类型 | 示例 | 处理 |
|----------|------|------|
| chart id / DOM id | `chart-nav-trend`、`#hero` | 仅用于 Agent 初始化 ECharts / 映射壳层；**不得**写入交付 HTML 正文 |
| HTML 注释 | `<!-- 仅债券型展示 -->` | 模板源码可保留；**生成交付文件前删除** |
| Agent-only 小节 | fund-screener「筛选概要」 | 不得变为报告内 `###` 标题；信息融入 Hero / AI 卡 / 结论叙述 |
| 字段形状示例 | 各 skill 的 `references/data_schema.md` 或 playbook 字段示例 | **禁止**代填客户字段 |

playbook、`report-templates` 工具矩阵中的接口名：**可保留**供 Agent 调用，**不得**原样进入交付物（同 §0）。

## 2. 文档分工（写死）

| 层级 | 典型文件 | Agent 读什么 | 客户交付物里有什么 |
|------|----------|--------------|-------------------|
| 场景入口 | 各技能 `SKILL.md` | 路由、工作流、必读顺序、降级 | 无 |
| 工具与边界 | `*-playbook.md` | 调哪些 MCP、字段语义、解读、分批/降级 | 无 |
| 结构与占位 | `report-templates.md` | 章节顺序、占位符、Hero/AI 业务规则、chart id | 填入后的正文与图表数据 |
| 视觉壳 | [`HTML视觉模板.md`](HTML视觉模板.md) + [`demo-report.html`](demo-report.html) | CSS/DOM/class、PDF print | 壳层 HTML |
| 数据铁律 | [`MCP数据真实性零容忍.md`](MCP数据真实性零容忍.md) | 禁估算、禁接口名进正文、缺失裁剪 | 「数据来源：盈米MCP」等 |

**原则**：playbook **定工具与数据边界** → report-templates **定呈现** → 公共 references **定壳与合规**。子技能 `SKILL.md` 不重复粘贴 playbook 级工具矩阵。

---

## 3. 无数据时的章节处理

- **默认**：未调用的 MCP 所对应 `report-templates` 章节 / 表 / 图 → **整块删除**，禁止占位或编造。
- **例外与细化**（过滤 0 条、结构性板块保留、模式专属降级等）→ **以各场景 `*-playbook.md`、`report-templates.md` 内注释及该技能 `SKILL.md` 为准**，本节不重复列举。

---

## 4. 内容来源标记（顾问确认类场景）

`[FIXED]` / `[MCP]` / `[ADVISOR]` / `[OPTIONAL]` 及顾问确认后写入交付物的规则，**仅**适用于需顾问采集与确认的场景（如 [`wealth-allocation-proposal`](../../wealth-allocation-proposal/SKILL.md)）。定义与 Agent 行为见该技能 [`proposal-playbook.md`](../../wealth-allocation-proposal/references/proposal-playbook.md) **§二**；其他报告类技能不必使用上述四标记。

## 5. 输出格式与公共壳

| 事项 | 约定 |
|------|------|
| 格式怎么定 | **不设默认格式**。由 [`输出格式确认协议.md`](输出格式确认协议.md) 的 Step 0 闸门与用户确认：进入技能后第一条回复原样弹出 A/B/C 三行话术并停下等答复；用户答复前禁止调用任何 MCP、禁止读 `demo-report.html`、禁止内嵌 ECharts、禁止写出交付文件 |
| 模板怎么选 | 以**各场景 `SKILL.md`「输出格式」表**为准。格式与模板正交：同一模板的 Markdown 版与 HTML 版板块顺序、数据口径、免责声明一致 |
| HTML 壳与必读顺序 | [`HTML视觉模板.md`](HTML视觉模板.md)「HTML 交付铁律」+ 全文 [`demo-report.html`](demo-report.html)（仅确认为 HTML 时） |
| ECharts 库 | 交付 HTML **必须内嵌 ECharts 5.5.0 完整运行时**（见 [`HTML视觉模板.md`](HTML视觉模板.md)「ECharts 库内嵌」）；禁止 CDN、相对路径和本机绝对路径 |
| PDF / 打印 / 下载 | [`HTML报告PDF导出规范.md`](HTML报告PDF导出规范.md) |

## 6. 报告呈现通则（占位符 · 着色 · 脚注）

本节吸收各场景 `report-templates` 中重复的「通用规则」；**免责声明全文不放在此处**（见下）。

### 占位符

- 写法以**本场景** `report-templates` 为准：`{xxx}` 与 `{{xxx}}` 等价，均须替换为本次 MCP 或用户输入的真实值。
- **无对应数据**：标注「数据暂未获取」，不保留占位符；整列/整行无数据时按该技能裁剪规则删除（见 [`MCP数据真实性零容忍.md`](MCP数据真实性零容忍.md) §1.6 及各 skill 说明）。
- **日期类**：替换为工具返回数据的实际截止日期（页眉/脚注可写「数据截至 YYYY-MM-DD」）。

### 涨跌着色（HTML）

- 涨：`class="val-up"`（或 Hero 场景下的 `.val.val-up` / `.kpi-change.val-up`，见场景模板）
- 跌：`class="val-down"`
- 平或无涨跌语义：不加涨跌 class

**DOM 两种 Hero 式样**（直接红/绿 vs 上黑下彩 pill）以 [`HTML视觉模板.md`](HTML视觉模板.md)「Hero KPI」与 [`demo-report.html`](demo-report.html) 为准，本节不重复。

### 数据引用脚注（客户可见）

基础口径见 [`MCP数据真实性零容忍.md`](MCP数据真实性零容忍.md) **§0**（统一「数据来源：盈米MCP」，禁接口名、禁旧写法）。

常见句式（可按场景择一，须与 §0 一致）：

| 场景 | 推荐句式 |
|------|----------|
| 行情 / 报告头 | `数据来源：盈米MCP · …截至 {date}` 或 `数据来源：盈米MCP，截至 {date}` |
| 基金业绩脚注 | `截至 {date}，数据来源：盈米MCP` |
| 经理观点（须标注原始来源时） | `{经理姓名}，{基金公司}（来源：盈米）` — 仅 [`advisor-content-studio`](../../advisor-content-studio/SKILL.md) 等内容类场景 |
| AI 归纳段落 | `来源：盈米 AI 分析` — 仅内容创作类场景 |

### 页末风险提示块（`.risk-notice-card`）

凡 HTML 交付在 **最后一个正文 `.card` 之后**、**`.footer-block` 之前**插入 `.risk-notice-card` 的场景（如 `strategy-analyst`、`wealth-allocation-proposal` 等）：

- **禁止**在块内使用 `<ol>`、`<ul>`、Markdown 有序/无序列表或任何带序号/项目符号的条目样式
- 每条声明用 **独立** `<p class="risk-notice-source">`（或 `.risk-notice-heading` + 紧跟的 `<p>`）分段
- **禁止**给风险提示块本身加「十一、」「六、」等 `.section-title` 章节序号（`wealth-allocation-proposal` 可用 `.risk-notice-title` 写「风险提示」无序号）

### 免责声明

**标准全文**见下文 **§7**（按场景锚点）；`report-templates` 文末与对应 `SKILL.md`「合规与免责」须与 §7 一致，禁止自拟或跨场景套用。
