# dd-checklist

**本文件为中文主面；英文版是同目录下的 `README.en.md`（仓库内查阅用——渠道页不解析相对链接，这里不做可点切换）。**

**公开信息能替你尽到什么程度？** 这份清单的答案是：**能查到的逐条带锚摊开，查不到的逐类写清是「域面没工具」还是「窗口内零条」**。它不给结论——结论位是三行 `[待人工]`。

给「唯一主体 + asof + 回看窗口 + 用途档位」，还你一张固定七列的风险事实表：每条都能回指一条在场披露（公告号 / 函件号 / 裁判文书号 / URL / 研究件 / 法条原文），外加一份九类覆盖率对账表和全链证据快照。
本件最大的敌人不是漏查，而是**编一条看起来像的风险**——所以入类第一闸写死三条：有在场锚、有在场日期且落在窗内、归属可判；任一不满足即不入表，进账。

**输入**：`--subject`（唯一主体）· `--asof` · `--lookback`（如 `36m`，必传）· `--purpose`（investment/credit/mna）· `--sources` · `--evidence`——六参数全必传
**输出**：`dd-<代码>-<asof>/` —— `report.md` · `sources.jsonl` · `evidence/`（含 `LEDGER.sha256`）· `references/coverage-map.md` · `progress.md`
**代价**：五段管线 + 一道八层门禁；深研按缺口发起（发起前报耗时与消耗），计费一律以服务端返回为准

## 一、是什么 / 不是什么

| 你要 | 用什么 |
|---|---|
| 单一主体一段窗口内的公开面风险事项，逐条带锚 | **本 skill** |
| 见客户前多主体速览 | 姊妹件 `tear-sheet` |
| 未来窗口的确定日期 | 姊妹件 `catalyst-calendar` |
| 财报深度点评与兑现度对账 | 姊妹件 `cn-earnings-note` |
| 投资结论、法律定性、宣称「已查全查尽」 | 不做——判断位留白，这三类措辞本身就是机检级禁语 |

## 二、四条为什么钉死

- **锚只认最后一列**：把公告号写进事实列不补位，把金额写成「像事件号」的数字也不算锚。宁可这行空着，不可那行有锚的幻觉。
- **未检到要分三种**：无工具（域面外，需人工/商用库）／零条（查了，窗内没有）／未发起（本次没查）。把第一种写成「该公司无 X」是本件的红线。
- **证据 fail-closed**：`evidence/` 缺失、为空或哈希对不上即不交付，不放行「先交后补」。表内每一行的锚都要能在快照里逐字找到——法定推导行更要找到法条原文。
- **日期算术零自由**：「报告期后 N 日内应披露」这类推导，只有当场取回法条原文（法名+条号+短引三件齐）才落行；`statute` 域不含部门规章与交易所规则，所以这条路径当前**预期零锚**，取不到就拒推并在台账写理由。

取证腿装 `cue-data-mcp`（`cue-omni-reader` 按需）——这两枚由 Cue 官方技能集合（sensedeal）发布：整套 `npx skills add sensedeal/cue-skills`（列出该集合公开的各枚，按提示挑），单装 `npx skills add sensedeal/cue-skills --skill cue-data-mcp`（把末尾那枚换成 `cue-omni-reader` 就只装那一枚）。装本件是上一节那条 `huhoo/cue-awesome --skill dd-checklist`，两件事别混。
注册 <https://cuecue.cn>（新账号注册送 500 积分、每日 10 积分，以服务端为准）→ <https://cuecue.cn/hub/api-key> 取 `CUE_API_KEY` 入本地凭据（**别贴进聊天**，也不在终端回显）。
三层各自能证到什么，互不等价：**装好 skill ≠ 已配凭据 ≠ 通道已连**。配置指路：数据腿官方配置页 <https://cuecue.cn/hub/mcp>（本件的取证以数据腿为主）；取证走解析腿时，其官方配置页 <https://cuecue.cn/hub/omni-reader>（按需的一腿，不配它本件照样出清单，缺的是远端正文那层的逐字与出处）。
- 装好＝重列一次已安装 skill，清单里看得到上面那些名字；这只证明文件到位，不证明取到数。
- 配好凭据＝那把 `CUE_API_KEY` 存在于本地凭据设施即可；**key 在场不等于 key 被接受**，接受与否要到下一层才判得出。
- 已连＝带上那把 key 按目标域 `routing` 里的 `url` 实连（`Authorization: Bearer <$CUE_API_KEY>`，并带 `Accept: application/json, text/event-stream`——缺这个头会 406，是协议行为不是鉴权失败），且 `tools/list` 有返回；本件的发现流程五步在 `references/channel-map.md` §1，那一节是判据所在。
匿名 `GET` 块里那枚 `CATALOG` 有返回**只证目录可达**，本件不把它叫「已连」；它给的是各域 `external_status` 与 live 域的 `routing`，`coming_soon` 域不承诺、不写入覆盖率账的「所需域」列。连接报错≠域无数据：如实报。

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | python3 -c 'import json,sys
rows=json.load(sys.stdin)["data"]["domains"]
[print(r.get("id"), r.get("external_status"), (r.get("routing") or {}).get("url", "-")) for r in rows]'
DOMAIN_ID="<把这里换成上一行列出的那个域 id>"
ROUTING_URL="$(curl -s "$CATALOG" | python3 -c 'import json,sys
rows=json.load(sys.stdin)["data"]["domains"]
hit=[r["routing"]["url"] for r in rows if r.get("id")==sys.argv[1] and r.get("routing")]
print(*hit,sep="\n") if hit else sys.exit("未取到：该 id 不在目录现值里（或它没有 routing 里的 url 字段）——先跑上面那行列出现场的 id 再填")' "$DOMAIN_ID")"
[ -n "$ROUTING_URL" ] || { echo "取值失败：ROUTING_URL 为空——先跑上面那行列出现场 id，再把 DOMAIN_ID 换成其中之一" >&2; exit 1; }
curl -s -X POST "$ROUTING_URL" \
  -H "Authorization: Bearer $CUE_API_KEY" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' \
  -w '\nHTTP %{http_code}\n'
```

取值：块里 `CATALOG` 是本面唯一一处目录入口字面（赋一次、散文不重抄）；`$ROUTING_URL` ＝上面那两行从该域 `routing` 里的 `url` 字段现取的逐字值，别把域名或路径抄死在这张面上；`$CUE_API_KEY` 取自上一层那把本地凭据，不进聊天、不在终端回显，本块不新增任何凭据读取动作。
通过＝HTTP 200，且返回体里 `result.tools` 非空（只按形状认，形如 `{"result":{"tools":[…]}}`；本面不列具体工具名，也不承诺枚数）。
一句现场精度：这处端点可能以 SSE 形回字（一行 event、紧跟一行 data），要看的 result.tools 就在那条 data 载荷里——判据不变，只是回字在外层多包了一层。
一条命令形（不必手改块里那一行）：`cd dd-checklist && python3 -B scripts/cue_connectivity_check.py --domain <你的域 id> --post`。这支随包件缺省一个包都不发——不带 --post 时只把该域 routing 里的 url 取出来给你看；有哪些域 id 可填，先跑同一支脚本的 `--list`（只列在场域与 url，不发 POST）。本件不另立判据：退码 0，退 4＝还没证过连通（带上 --post 再跑一次），退 5＝连上了但现场值没满足它，退 1＝取不到、发不出去、或 HTTP 层报错（含 4xx 与 5xx），退 6＝目的地没过凭据外发两关（本件拒发，一个凭据字节都不附），退 7＝目录入口本身不是 https。按默认目录入口时，本件只验运行端点连通，不向渠道发布、不产生受理。**换源不免检**：无论那个 url 来自缺省目录、--catalog-url 还是 --catalog-file 那份快照，带 key 那一次发出去之前都要过同一道两关——scheme 必须是 https，且 host 命中授权后缀（缺省那一枚由件头那处目录入口现值推出，不是本件另编的一张清单；要显式放行别处请带 --allow-host）；过不了就拒发，并把拒绝原因与那个 host 印在回字里，本件不读 key、也不构造那个请求。代价同句写明：老的「换进去什么就打什么」那一形关掉了，换来的是凭据不会外发到未授权目的地；若你的正当端点恰在授权后缀之外，退 6 是请你用 --allow-host 显式认下它，不是断言那枚端点不该存在。

不装也能跑，代价是覆盖率账上那一行如实写着「本次未经域直查」：你贴披露原文，agent 组织成表并标「可信级 L2（用户直供）」——L2 在本件的用法就这一句：**文本由用户贴入、未经域直查核验**，分档的完整定义在财报点评件那一面（本件只按这一档标注，不另造一套）——这份清单的价值恰好在那张账上。

## 六、常见问题与反模式（你想这么用 → 本件不接，因为 → 替代去向）

只重组已审清条款，不新增承诺；类目、锚种、禁语三套判据一律以 `check_dd.py` 现值为准（定位命令见 §五 注行）。

| 你想 | 本件接不接，为什么不接 | 替代去向 |
|---|---|---|
| 结尾给个结论：能不能投、要不要否 | **不接**。判断位永远是 `[待人工]`，本件交的是带锚事实 + 一张「查不到什么」的账 | 结论由人下；需要一页速览用 `tear-sheet` |
| 查不到的类目写成「该公司没有这类问题」 | **不接**。搜不到 ≠ 不存在；无工具项禁写主体性否定断言 | 写进覆盖率账，标清是域面无工具还是检到零条 |
| 顺手推一下定期报告的法定披露期限 | **无 statute 原文锚在场即拒推**。期限推导只在法条原文与适用条件同时可判时入表 | 拒推不落行，`progress.md` 记一行理由与探针清单（该路径当前预期零锚） |
| 一次跑几家主体横向比 | **不接**（一单一主体）。多主体必然让逐条锚失守 | 一家一次；批量速览走 `tear-sheet` |
| 不给回溯窗口，让我用默认 | **不接**。窗口必传，不用 wall clock 兜默认 | 给一个明确区间（如近三年、自某基准日回看 12 个月） |
| 想要评级段、价位段、法律定性段那三段 | **只转述披露原文并带锚**，不代出意见，也不给合规定性 | 意见与定性由人出；本件负责让每一条都指得回原文 |

## 七、出错了怎么办（症状 → 原因 → 恢复动作）

**未见于本次返回的一律写「未检索到」**：参数名、字段名、枚举值没有出现在本次工具返回里的，不得凭印象填写；写「未检索到」并记入待核清单或覆盖率账，不得留空顶替。

**Error 级＝blocker**：机检报出的 Error 级条目不得称「无害」「可忽略」「先交出去再说」；修完，或在交付面显式申报，才算出口。

形制按 `check_dd.py` **当前出口**现跑取得：详行在前，每行**先打错误码前缀（五枚 `E-*` 之一）、再接本件 `DD-*` 诊断码**、后带行号与中文原因；末两行依次是 `码表:`（只列本次用到的码与含义）与 `RESULT: FAIL report.md（N 项；码集 DD-*…）`。全过印 `RESULT: PASS report.md（八道门禁全过）`。

`E-*` 五码是全族同源封闭集（与四件姊妹件逐字一致），`DD-*` 是本件的八枚分层诊断码——**两码并打**：`E-*` 说处置家族、`DD-*` 说本件哪道闸。归类规则与码表都在脚本里，一条命令原地取（把 §五 那条 grep 的关键词换成下面两个）：

    grep -n "^E_LEGEND\|^E_RULES" ~/.workbuddy/skills/dd-checklist/scripts/check_dd.py

| 症状（详行前缀） | 原因 | 恢复动作 |
|---|---|---|
| `[E-FORMAT] DD-INPUT: …` | 六参数缺项或非法（主体形制、日期形制、用途档位越界） | 补齐六个必传参数再跑；主体写法接受「全称（6位代码.SH\|.SZ\|.BJ）」与纯代码两形 |
| `[E-FORMAT] DD-ROW: 第 N 行：…` / `[E-FORMAT] DD-TABLE: …` | 表行形制不合固定七列、类目或档位取值越界、日期非正序、锚不在末列，或自白词进表 | 按该行括号内规格改形制；含推测词的那行删掉，不用别的词补同一意思 |
| `[E-ANCHOR] DD-EVIDENCE: …` | 有表行无账、或有账无原始快照；`evidence/` 缺失或哈希不符 | 补 `sources.jsonl` 行与 `evidence/` 快照（`LEDGER.sha256` 可核）；目录缺失是 fail-closed，不放行「先交付后补证」 |
| `[E-ANCHOR] DD-STATUTE: …` | 法定推导缺原文锚或适用条件不可判 | 拒推不落行，`progress.md` 记一行理由与探针清单（该路径当前预期零锚） |
| `[E-COVERAGE] DD-COVERAGE: …` | 九类不齐、某类「检到 N」与调用流水对不上，或长窗调了披露域却没写账龄申报那一行 | 逐类补账；长窗按契约 §v2-11 写申报行（先收后判口径），申报窗口与复算窗一致 |
| `[E-COVERAGE] DD-OMISSION: …` | 正文声称查过的域多于对账表记录的调用集（声称而未记账） | 补记须「三件齐」（账格全域、流水含该域、逐域各有一份标类目的原始件）；只删正文不补账正是本件要拦的失效形状 |
| `[E-BANWORD] DD-REDLINE: …` | 投资建议、法律定性或完备性断言那一类进了交付面 | 按码表处置：改中性陈述或删除；判断位回到 `[待人工]` |
| 域没装 / 该类公开面无工具 | 通道缺失或该类目本就无公开检索面 | 降级路径：用户贴披露清单（标可信级 L2（用户直供），`sources` 用 `user_supplied` + `path`）；深研不发起则该类整类标「未检索到」并进账，**不以常识补条目**。代价是覆盖率不是准确度 |
| Traceback 而不是 `RESULT: FAIL …` | 属事故：解析点已 try 化 | 停手回报：稿件与整条命令记进 `progress.md`，先跑 §五 的现跑命令区分稿件问题与脚本问题 |

## 八、怎么开口（触发示例：三条正例 + 一条反例，含档位怎么选）

**开口请带上时点，输出标数据日期**：请求里给出报告期／基准日或回看窗口；成品首行标注**数据日期**，当它与用户所指日期不一致时，正文禁用「今日」「最新」，一律改写为「截至 <日期>」。
- **正例（最简一句）**：「给我做一份北辰股份近三年的公开信息预尽调清单」——缺窗口或用途档位会先追问，不用默认窗兜。
- **正例（档位明确 + 关注点，复杂输入）**：「主体：北京东方雨虹防水技术股份有限公司（002271.SZ)，基准日
