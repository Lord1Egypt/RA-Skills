# 漂移与严重度

只读比较已确认契约与实现。先确定版本和覆盖范围，再读规格、PRD/暂存索引、规则、代码、数据模式/迁移和测试。搜索结果须回到定义核实；上级规格是否覆盖当前模块，以内容为据。缺失或未扫描的代码标为未核实。记法与行为见[规格记法](../../spec-notation.md)。

## 严重度

Critical 须有权限绕过、数据破坏或核心不可用证据。High 为明确违约，Medium 为有影响遗漏，Low 为局部维护。按影响调整须解释；Low 数量不自动升级。

## 分类

| 范围 | 证据 | 默认严重度 |
| --- | --- | --- |
| 概念 | 未记录公开动作、签名/结果变化、新可观察状态、未记录契约参数 | Medium |
| 概念 | 核心定义在语义上依赖另一概念；内部概念缺规格/索引说明 | Medium |
| 概念 | 声明动作在全部相关实现中不存在 | High |
| 概念 | 私有访问、概念互调、共享可变状态、排除动作可达 | High |
| 同步 | 未记录规则；触发变化 | Medium |
| 同步 | 场景证明欠同步、失去控制、目的偏离或协调状态出现独立业务生命周期 | Medium |
| 同步 | 声明规则删除 | High |
| 同步 | 绑定/效果变化、未声明参与者、匹配/关联/基数错误、缺必需响应、非法共同效果、禁止重放、不变量错位 | High |
| 同步 | 必需进展或授权一致性不成立 | 按影响 |
| 同步 | 全部支持入口均证明无法触发规则 | Low |
| 管道 | PIPELINE 缺阶段/来源、数据契约变化 | Medium |
| 管道 | PIPELINE 不变量矛盾/私有访问 | High |
| 图 | 现有地图与规则矛盾 | Medium |
| 验证 | OP 缺代表性测试 | 验证缺口，按风险 |
| 验证 | 动作/查询/签名/结果/类型绑定未解析 | 验证缺口；证实违约后按影响定级 |
| 维护 | 已记录缺口被实现解决 | Low |

逐项检查：

- **规则**：分支、查询基数、参数、关联、失败、重放和循环。
- **管道**：顺序、契约、触发、质量和公开接口。
- **入口**：解析外部入口签名；Requesting 无需虚构 CONCEPT。同步图可只放总体 PRD。
- **工程**：单独检查[工程架构](../../architecture.md#审查与验证)，缺少行为规格时也执行此检查。

## 判定与报告

- 局部模型未声明的行为是覆盖缺口，除非适用契约或明确排除能证明漂移。
- 私有辅助函数/缓存、命名映射、保持行为的 Result/异步包装和旧标题本身不是漂移。
- 已记录例外保留范围/后果；记录互调不恢复独立性。
- Medium 及以上发现 MUST 引用当前位置；跨路径合并共同根因。

报告范围/版本、实测计数、逐类通过/发现/未核实、契约/代码位置、影响和修复步骤。
