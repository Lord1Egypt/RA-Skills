# OPC智脑 - Skill2：MVP精益设计

## 适用阶段和前置条件

### 适用阶段
- **阶段**：原型期（五阶段模型第2阶段）
- **阶段目标**：设计MVP、确定三层产品体系、测算交付成本、完成首单冷交付
- **毕业条件**：MVP可交付 + 首单冷交付成功 + 交付成本可控

### 前置条件
1. 需求已通过可行性验证（Skill1输出可行性≥可行）
2. 核心功能列表已明确（至少1个核心功能）
3. 有明确的交付方式设想（线上/线下/混合）
4. 创业者有基本的产品设计或开发能力

### 不适用场景
- 需求还没验证 → 应先进入Skill1-Idea可行性研判
- 已经有成熟产品了 → 应进入Skill4-种子用户冷启动
- 只是想注册公司 → 应进入Skill3-OPC合规落地

## 诊断任务和详细步骤

### 任务1：MVP极简裁剪

#### 步骤1.1：功能清单梳理

将创业者设想的所有功能列出来，分为三类：

| 功能分类 | 定义 | 处理方式 |
|---------|------|---------|
| 核心功能 | 直接产生价值、用户付费的理由 | MVP必须保留 |
| 增值功能 | 提升体验但不影响核心价值 | MVP砍掉，V2考虑 |
| 锦上添花 | 有了更好、没有也行 | 砍掉，除非零成本 |

#### 步骤1.2：裁剪决策框架

对每个功能用**四问裁剪法**判定：

```
问题1：没有这个功能，用户会拒绝付费吗？
  → 会 → 核心功能，保留
  → 不会 → 继续问

问题2：没有这个功能，核心价值能交付吗？
  → 能 → 继续问
  → 不能 → 核心功能，保留

问题3：这个功能可以在2周内由一人完成吗？
  → 可以 → 继续问
  → 不可以 → 砍掉（开发成本过高）

问题4：这个功能需要外部依赖（API/第三方服务）吗？
  → 需要，且零成本 → 保留
  → 需要，有成本 → 砍掉（增加交付复杂度）
  → 不需要 → 保留
```

#### 步骤1.3：MVP功能上限控制

**一人创业者MVP铁律**：
- 核心功能不超过3个
- 总开发时间不超过2周（80小时）
- 不依赖超过2个外部服务
- 不需要超过1个第三方API集成
- 可以在1天内完成1次完整交付

#### 步骤1.4：裁剪后的功能优先级排序

```
优先级1：用户付费的直接理由（必须第一天就有）
优先级2：核心交付流程的必要环节（第一周完成）
优先级3：提升交付质量的辅助功能（第二周完成）
```

### 任务2：三层产品体系设计

#### 步骤2.1：三层产品模型

一人创业者的产品必须分为三层，形成"引流→转化→复购"的闭环：

```
┌─────────────────────────────────┐
│        被动产品（第三层）         │  自动化交付，边际成本趋零
│   定价：中低  |  利润率：90%+     │  如：录播课程、电子书、SaaS自助版
├─────────────────────────────────┤
│        利润款（第二层）          │  核心收入来源，主要利润
│   定价：中高  |  利润率：50-70%   │  如：1对1咨询、定制服务、高级版
├─────────────────────────────────┤
│        引流款（第一层）          │  低价/免费，获取信任和线索
│   定价：低/免费 |  利润率：0-20%  │  如：免费诊断、低价体验、内容引流
└─────────────────────────────────┘
```

#### 步骤2.2：引流款设计

**引流款的核心目的**：让目标用户从"不知道你"到"愿意了解你"

| 引流款类型 | 适用场景 | 定价 | 交付方式 |
|-----------|---------|------|---------|
| 免费诊断/评估 | 服务型业务 | 0元 | 在线表单+自动报告 |
| 低价体验课 | 知识付费型 | 9.9-49元 | 录播/直播1小时 |
| 试用版/免费版 | SaaS工具型 | 0元 | 功能受限的完整版 |
| 案例展示 | 设计/创意型 | 0元 | 作品集+过程拆解 |
| 社群体验 | 社群/会员型 | 0-19元 | 3天体验期 |

**引流款设计原则**：
- 交付时间不超过30分钟/人
- 能展示核心专业能力
- 自然引导用户了解利润款
- 最好可自动化交付

#### 步骤2.3：利润款设计

**利润款的核心目的**：这是你的主要收入来源，必须能持续交付

| 利润款类型 | 适用场景 | 定价区间 | 交付方式 |
|-----------|---------|---------|---------|
| 1对1咨询/辅导 | 专业服务型 | 500-5000元/次 | 线上视频/线下 |
| 定制项目 | 设计/开发型 | 3000-30000元/项目 | 线上交付 |
| 小班训练营 | 教育培训型 | 999-4999元/期 | 直播+作业 |
| 高级版SaaS | 工具型 | 99-999元/月 | 自助使用 |
| 年度会员 | 内容/社群型 | 365-3650元/年 | 持续内容+服务 |

**利润款设计原则**：
- 毛利率≥50%（一人运营成本结构低，可以做到）
- 单次交付时间不超过1天（服务型）或可自助使用（产品型）
- 有明确的交付标准和验收条件
- 能自然引导用户了解被动产品

#### 步骤2.4：被动产品设计

**被动产品的核心目的**：实现"睡后收入"，突破时间换金钱的限制

| 被动产品类型 | 适用场景 | 定价区间 | 自动化程度 |
|-------------|---------|---------|-----------|
| 录播课程 | 知识/教育型 | 99-999元 | 全自动（购买即学习） |
| 电子书/模板 | 专业/工具型 | 29-199元 | 全自动（购买即下载） |
| SaaS自助版 | 工具型 | 29-299元/月 | 全自动（注册即使用） |
| 付费社群 | 社群型 | 99-999元/年 | 半自动（需定期维护） |
| 数据/报告 | 数据/分析型 | 49-499元/份 | 全自动（购买即查看） |

**被动产品设计原则**：
- 一次制作，无限销售
- 交付过程零人工介入（理想状态）
- 边际成本趋近于零
- 可以作为利润款的"升级版"或"补充版"

### 任务3：单人交付成本测算

#### 步骤3.1：时间成本测算

```
时间成本 = 固定准备时间 + 单次交付时间 × 预计单量

其中：
- 固定准备时间：MVP开发/制作时间（一次性）
- 单次交付时间：每完成1次交付需要的时间
- 预计单量：验证期（1-3个月）的预计订单数

一人创业者时间预算：
- 每周可用时间：XX小时
- 每周最大交付量 = 可用时间 / 单次交付时间
- 如果最大交付量 < 预计单量 → 交付瓶颈！
```

#### 步骤3.2：工具成本测算

| 成本类型 | 常见项目 | 月费区间 | 是否必需 |
|---------|---------|---------|---------|
| 域名/服务器 | 域名+云服务器 | 50-300元 | 是 |
| 开发工具 | IDE/设计工具 | 0-200元 | 视情况 |
| AI工具 | ChatGPT/Claude/Midjourney | 0-400元 | 强烈推荐 |
| 通讯工具 | 企业微信/飞书 | 0-50元 | 是 |
| 支付工具 | 微信支付/支付宝 | 0元（抽佣0.6%） | 是 |
| 内容工具 | 公众号/小红书 | 0元 | 视情况 |
| **合计** | | **50-950元/月** | |

#### 步骤3.3：试错成本测算

```
试错成本 = 前3次交付的额外成本

包括：
- 学习成本：不熟练导致的额外时间（按正常时间的1.5倍计）
- 返工成本：前几次可能需要返工（预留20%预算）
- 工具试错：可能需要尝试2-3个工具才找到合适的
- 客户补偿：首单不满意可能需要退款/补偿

试错成本估算 = (时间成本 + 工具成本) × 30%
```

#### 步骤3.4：总成本与盈亏平衡

```
总成本 = 时间成本 + 工具成本 + 试错成本

盈亏平衡点 = 总成本 / 单均利润

单人交付上限：
- 每周最大工作时长：60小时（含休息）
- 每周最大交付量 = 60 / 单次交付时间
- 月最大营收 = 每周最大交付量 × 4 × 单均价格
```

### 任务4：首单冷交付方案

#### 步骤4.1：冷交付策略

**冷交付**：在没有案例、没有口碑的情况下，完成第一单交付。

| 冷交付策略 | 操作方式 | 适用场景 |
|-----------|---------|---------|
| 免费换案例 | 为1-3人免费服务，换取案例和推荐 | 服务型 |
| 低价破冰 | 首单价格=正常价的30-50% | 所有类型 |
| 自用验证 | 先给自己/自己的项目用，产出案例 | 工具/产品型 |
| 朋友内测 | 请朋友体验并给出真实反馈 | 所有类型 |
| 社群内推 | 在行业社群内推，以超低价获首单 | 服务/内容型 |

**⚠️ 有第一个客户就必须签合同，不可裸奔。**

**合同使用原则**：
- 首单必须签，哪怕是免费服务（明确双方权责）
- 金额<1000元：可用微信文字确认代替纸质合同
- 金额≥1000元：必须签正式合同（电子签/纸质签）
- 合同一式两份，双方各执一份

**不签合同的后果**：
- 对方赖账，没有任何依据
- 交付标准不明确，扯皮
- 发生纠纷，无法维权

**隐私政策使用原则**：

- 违反《个人信息保护法》
- 罚款：5万-500万元
- 可能承担刑事责任

#### 步骤4.6：小样标准

**小样**：首单交付的合格标准，必须明确"什么算交付完成"。

```
小样标准定义：
1. 交付物清单：用户能拿到什么（文件/账号/报告/...）
2. 质量底线：最低可接受的质量标准
3. 交付时限：从接单到交付的最长时间
4. 验收方式：用户如何确认交付合格
5. 售后承诺：交付后的跟进承诺
```

#### 步骤4.3：报价逻辑

```
首单报价 = 成本价 × 1.3（留30%安全余量）

其中成本价 = (单次交付时间 × 时薪) + 工具分摊 + 其他直接成本

时薪计算：
- 参考市场价的50-70%（首单优惠）
- 或按期望月收入 / 每月可用工时计算
- 一人创业者建议时薪区间：100-500元/小时

定价策略：
- 首单价：成本价×1.3（破冰价，仅限前1-3单）
- 正式价：成本价×2-3（正常利润率50-70%）
- 长期价：根据市场反馈调整
```

## 具体的分析框架和判定标准

### MVP裁剪判定标准

```
功能保留条件（必须全部满足）：
1. 用户会因为这个功能付费（或影响付费决策）
2. 一人可在2周内完成开发
3. 不需要超过1个外部API依赖
4. 去掉后核心价值无法交付

功能裁剪条件（满足任一即裁剪）：
1. 用户不会因为这个功能付费
2. 开发时间超过1周
3. 需要2个以上外部API依赖
4. 属于"有了更好"但非必须
5. 可以用人工/手动方式临时替代
```

### 交付成本可控标准

```
成本可控判定：
- 月固定成本 < 预计月营收的30% → 成本可控
- 月固定成本 = 预计月营收的30-50% → 需要优化
- 月固定成本 > 预计月营收的50% → 成本失控，需要重新设计

单人交付上限判定：
- 预计单量 ≤ 每周最大交付量×4 → 可交付
- 预计单量 > 每周最大交付量×4 → 交付瓶颈，需要：
  a. 提升交付效率（自动化/模板化）
  b. 提升单价（减少单量，提升单价）
  c. 引入被动产品（不占时间的收入）
```

### 三层产品体系完整性标准

```
三层产品体系必须满足：
1. 至少有1个引流款（获取线索）
2. 至少有1个利润款（核心收入）
3. 至少有1个被动产品或可自动化的利润款
4. 三层之间有自然的升级路径
5. 每层都有明确的定价和交付标准
```

## 兜底策略

### 策略1：功能裁剪困难时的兜底

当创业者坚持要保留很多功能时：
- 使用"如果砍掉这个功能，用户会怎样？"的追问
- 给出"2周MVP"和"2月完整版"两个方案对比
- 强调"先验证1个核心功能，再逐步增加"的精益原则

### 策略2：交付成本超标时的兜底

当测算的交付成本超出创业者预算时：
- 重新审视三层产品体系，增加被动产品比重
- 推荐AI工具替代人工环节（给出具体工具名和替代方案）
- 调整定价策略，提升单价降低单量
- 考虑"预售制"——先收钱再交付，改善现金流

### 策略3：无法完成首单冷交付时的兜底

当创业者实在找不到首单用户时：
- 推荐"自用验证"路径：先给自己做，产出案例
- 推荐"内容先行"路径：先输出内容建立专业形象，再获客
- 推荐"平台挂单"路径：在猪八戒/闲鱼等平台挂出服务
- 给出"30天首单挑战"的具体行动计划

### 策略4：技术能力不足时的兜底

当创业者没有技术能力开发MVP时：
- 推荐"无代码/低代码"方案（给出具体平台）
- 推荐"服务先行"路径：先做服务型MVP，再产品化
- 推荐"AI辅助开发"路径：用AI编程助手降低开发门槛
- 给出学习路径：最小必要技能+学习时间估算

## 约束规则

1. MVP核心功能不超过3个
2. 所有成本测算必须基于单人交付，不假设有团队
3. 首单定价可以低于正常价，但不能亏本
4. 三层产品体系必须有一层可自动化交付
5. 交付时间线必须具体到天
6. 所有建议必须可执行、可量化
7. 禁止推荐需要多人协作的交付方案
8. 优先推荐AI自动化替代人力的方案
9. 成本评估必须留出30%安全余量
10. 不使用"可以考虑"等模糊表述
