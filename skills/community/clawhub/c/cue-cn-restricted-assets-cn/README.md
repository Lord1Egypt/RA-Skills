# 受限资产·抵押质押冻结逐项登记与可动用资金缺口

给一份年报或半年报，把附注里**「所有权或使用权受到限制的资产」那一张表**读成一张**每个数都能回到附注原句**的登记表：受限资产概况、货币资金受限、非货币资产受限、受限原因与期限、与负债的对应。

这张表常被跳过，但它是财报里最容易被一句话带过的地方：账面 100 亿货币资金，其中 60 亿是银行承兑汇票保证金与冻结存款，能动的只有 40 亿。**数照抄附注原句，合计与分项、受限比例由机检现算**。本件只做前一半：把数抄对、把受限形态与类别按附注写对、把原句挂上。

不重算可动用资金、不判断资产质量与偿债能力、不把受限金额当可动用金额、不给评级目标价。

## 一、零依赖三分钟上手

只装 Python 3，不给任何数据文件，也能跑出一份完整合规的成品，看它长什么样、判据怎么打：

```bash
python3 scripts/check_restricted_assets.py --demo
```

把这份样例存下来再跑一遍机检——它会照七节形制、三元组、合计与分项、比例重算、四条红线逐条判：

```bash
python3 scripts/check_restricted_assets.py --demo > 样例受限资产稿.md
python3 scripts/check_restricted_assets.py 样例受限资产稿.md
```

接着换成你自己那份稿子：

```bash
python3 scripts/check_restricted_assets.py 你的受限资产稿.md
```

退码语义：`0` 五道全过｜`1` 有发条（逐条打印 `码 行号 说明`）｜`2` 用法错（没给稿子路径，也没给 `--demo`／`--selftest`）｜`3` 读不到文件或空稿。零发条但有判据尚未落字时同样退 3——rc=0 只留给「五道全过」，没跑的道不能算过；报告里那几道计「不可判」，**不等于合规**。本件五道已全部落字，这条当前不触发（好样单跑退 0），留着是为了将来某道回退成空壳时不把「没跑」读成「过」。

拿不到成品时，从原文开始的三步：

1. **定主体与报告期**，拿到年报或半年报附注里「所有权或使用权受到限制的资产」那一张表（项目、账面价值、受限类型、受限原因、是否对应负债）。
2. **每节抄事实，连原句一起抄**：一条 = 一行，行首写项名、紧跟 `〔口径：本期末〕`／`〔形态：银行承兑汇票保证金〕`／`〔类别：房屋建筑物〕`／`〔对象：…〕` 标签，再写金额与「万元」，行末挂 `「原句」〔锚：页/表〕[S#]`；附注里没有的数就写 `未取到：项名`，不留空、不借「受限资产一般就是这么几类」这类常识补。
3. **跑一遍自检**，红一条改一条：

```bash
python3 scripts/check_restricted_assets.py --selftest   # 内置夹具自检（档数与结果以末行现报为准）
```

三档一起跑（自测→好样→坏样，坏样注入必先断言落地）：

```bash
bash scripts/fixtures/run_fixtures.sh
```

## 二、五道机检在管什么

现状以脚本里 `UNIMPLEMENTED` 的现值为准：五道**全部已落字**，`UNIMPLEMENTED` 为空——报告里「不可判」的计数当前为 0。将来某道若回退成空壳（重新登记进 `UNIMPLEMENTED`），它会调用即抛、由机检收进「不可判」，既不判也不放行，单稿退 3；`rc=0` 只留给「五道全过」。

| 码 | 名称 | 判什么 | 最常拦住的情况 | 现状 |
|---|---|---|---|---|
| `RA-STRUCT` | 形制 | 头部三件自标（AI 整理初稿／请回原文核对／不构成投资建议）逐字在位、七节齐且按序；认不出的节标题与多出同名节记 stray 逐条发。只判「形」，不判内容；**不判** `主体：`／`报告期：` | 某节名改了个字就整节认不出；同一节写了两次 | 已落字 |
| `RA-QUOTE` | 原句与锚 | 五个内容节每个数字行须挂一对 `「」` 原句（≥8 字，不能只有数字／标点）＋〔锚：…〕＋`[S#]`；例外只有三形：`未取到：` 行、`[待人工]` 行、`〔自算〕` 行。来源行须合 `- [S#] 标题 \| http(s) URL \| 检索日 YYYY-MM-DD`，正文引用与来源登记**两向**都要对得上，来源节一条合规行都没有则单独发一条。**不核对引号里的数与行首是否同一**（那是 `RA-SUM`／`RA-RATIO` 的活——分开判是为了让一支坏样只红一道） | 只写「货币资金受限 1,200.00 万元」没抄原句；检索日写成 `2026/03/20` | 已落字 |
| `RA-SUM` | 合计与分项 | ① 「受限资产概况」里的 `受限资产合计` 与「货币资金受限」＋「非货币资产受限」两节所有金额行之和比对，差 > 0.01 万元 ⇒ 发，消息记 `分项和=X 披露合计=Y`；② 某行同时给了受限金额与「账面总额／资产总额」且受限金额更大 ⇒ 发。**任一侧缺失 ⇒ 整条跳过**，不猜、不按 0 算；**两节缺任何一节也整条跳过**（缺节是 `RA-STRUCT`／`RA-LINE` 的活，这里再比一次会让一支注入同时红三道） | 分项漏抄一行，合计就对不上；某类受限金额抄成大于该类资产总额 | 已落字 |
| `RA-RATIO` | 比例重算 | 只在**同一行**里同时拿到「受限金额」「资产总额（或总资产）」与披露比例时才判：按 `受限金额 / 资产总额` 重算，与披露比例差 > 0.05 个百分点 ⇒ 发，消息记 `重算=X 披露=Y`；> 100% ⇒ 单独发一条（那不是四舍五入能解释的，说明分子分母取错了行）；分母为 0 ⇒ 如实记一句「资产总额为 0，比例无从重算」，不静默除零崩。**跨行拼出来的分母归属不明，宁可跳过也不猜** | 比例抄成相邻那一行的；分子分母取错行 | 已落字 |
| `RA-LINE` | 红线 | ① 给「资产质量好／差」「偿债能力充足／不足」「偿债压力大」的判断 ② 把受限资产说成「已损失」「已减值」「无法收回」 ③ 拿受限金额当可动用金额（出现「可动用」「可自由支配」「实际可用」）④ 给评级、目标价、买卖建议。**同一行同类只报第一处**，免得同一句话刷成一片。另加：「货币资金受限」节缺 ⇒ 发条（这一节是本件存在的理由）。「口径与未取到」与「来源」两节整节豁免 | 顺手写一句「偿债能力充足」；把受限的 6,600 写成「实际可用资金」 | 已落字 |

`--selftest` 末行自报 `自测档数=N｜不合=0｜不可判=N`，**N 以现跑为准，本文件不写死数字**——写死的数字必然落后于代码。夹具覆盖上面五道码，每支坏样只红自己那一道（「删掉货币资金受限整节」那一档按设计同时红 `RA-STRUCT` 与 `RA-LINE`，专门钉住双红不被并成单码）；另有一支**反证档**：往「口径与未取到」里写满红线词，期望零发条，证明该节整节豁免真的生效。

## 三、七节各登记什么

| 节 | 登记什么 | 最常犯的错 |
|---|---|---|
| 受限资产概况 | 受限资产合计账面价值、总资产（比例的分母）、占总资产比例、受限类别数；`〔口径：本期末〕` | 只写合计不写总资产，比例就无从重算 |
| 货币资金受限 | 按受限形态分组：银行承兑汇票保证金／信用证保证金／保函保证金／质押存款／冻结存款／其他，`〔形态：…〕` | 只写「货币资金受限 1,700 万元」不按形态分，看不出哪笔能解 |
| 非货币资产受限 | 按资产类别分组：应收票据／存货／固定资产／无形资产／投资性房地产／其他，`〔类别：…〕` | 类别名不写，归属不明 |
| 受限原因与期限 | 每项受限的原因原句、受限起止或期限，`〔对象：…〕` | 只写「因借款抵押」不写对象，分不清是哪项资产 |
| 与负债的对应 | 该受限资产对应的借款／应付票据／担保债务金额；附注不给就写 `未取到：` | 拿受限金额当对应借款金额填上去 |
| 口径与未取到 | 取法口径 ＋ 缺口逐项点名；零缺口写 `未取到：无` | 正文写了未取到而本节没列，或反之 |
| 来源 | 每条 `[S#]` 一行：`- [S#] 标题 \| URL \| 检索日 YYYY-MM-DD` | 引用了 `[S#]` 却没有登记行；检索日写成斜杠式 |

## 四、四条红线

1. **不判断资产质量与偿债能力**：「资产质量好」「资产质量差」「偿债能力充足」「偿债能力不足」「偿债压力大」一律不出现在内容节，够不够、好不好交 `[待人工]`。
2. **不把受限说成已损失**：抵押、质押、冻结、保证金是**权利受限**——资产还在账上、还有价值、解押后照常使用，不是「已减值」「已损失」「无法收回」。
3. **不拿受限金额当可动用金额**：受限金额恰恰是**动不了的那部分**。「可动用」「可自由支配」「实际可用」这几个词不许出现在受限金额行上；要算可动用资金（账面货币资金减受限部分）属于口径判断，交 `[待人工]`。
4. **不给评级、目标价、买卖建议**。

另有三条由机检强制：合计必须对得上分项（`RA-SUM`）、比例必须与重算对得上（`RA-RATIO`）、受限资产不得被说成已损失或可动用（`RA-LINE`）。「口径与未取到」整节豁免——那一节按设计就要写「本件不判断资产质量与偿债能力、不把受限金额当作可动用金额」，不豁免会自己咬自己。

## 五、与相邻件的边界

| 相邻件 | 它管什么 | 本件不做什么 |
|---|---|---|
| `cn-share-pledge-tracker` | 股东所持股份的质押与解押，标的是「股东手里的股票」 | 本件标的是「公司账上的资产」，不碰股东质押 |
| `cn-contingency-commitment-cn` | 或有事项与承诺，含对外担保，登记的是担保本身 | 本件登记被担保／被抵押的**资产那一侧**，不登记担保责任 |
| `cn-working-capital-quality` | 存货与应收的余额与账龄、计提与转回 | 本件只问这些资产里有多少**受限**，不问账龄与计提 |
| `cn-expected-credit-loss-cn` | 减值准备计提方法、三阶段、组合与单项计提 | 本件不碰减值计提，只登记权利受限 |
| `cn-key-financial-data-cn` | 第一节主要会计数据与财务指标表的逐行登记 | 本件读的是附注，不是第一节那张表 |

## 六、数据通道

- 发现先行：匿名取 live 域清单与 `routing`，**不硬编码工具名与工具数**；连上之后带 `Authorization: Bearer $CUE_API_KEY` 发 `tools/list`，以现场返回为准：

  ```bash
  # ① 匿名取域清单与 routing
  curl -sS https://cuecue.cn/api/mcp-catalog -o /tmp/mcp-catalog.json
  python3 -c "import json;d=json.load(open('/tmp/mcp-catalog.json'));print(d)"

  # ② 带凭据握手取工具表
  curl -sS -X POST "$MCP_ENDPOINT" \
    -H "Authorization: Bearer $CUE_API_KEY" \
    -H 'Content-Type: application/json' \
    -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | head -c 2000
  ```

- 原文腿：年报附注里受限资产那一段在数据腿上，本件不承诺该域开放，也不承诺实时性；
- 正文腿：这一段常是「项目／账面价值／受限类型／受限原因」的横排大表，截图与扫描件交 `cue-omni-reader`（大纲→按节取用，计费以服务端返回为准）；
- 通道配置页只给指针：<https://cuecue.cn/hub/mcp> ／ <https://cuecue.cn/hub/omni-reader> ／ <https://cuecue.cn/hub/api-key>。
