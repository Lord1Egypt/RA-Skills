# 跨子领域标准流程（patterns.md）— 场景 → 推荐路径

## 导读

本文件是 ui-ux-design 领域的**跨子领域流程层**：把 7 个子领域 kb 重组为端到端标准流程。每个 pattern 含五要素：适用场景/前提/步骤/输出物/法则引用。

- laws.md 是约束；子领域 kb 是深度展开；引用记法见 laws.md 导读。
- 排序：P-1 诊断；P-2~P-4 建设；P-5~P-7 验收闸门；P-8~P-14 场景专项（移动端/数据密集/详情页/导航/搜索/引导/错误页）。「诊断→重建→验收→专项」闭环。

## P-1 界面美化走查流程（核心流程）

**一句话**：对既有界面按 **视觉认知 → 布局 → 色彩 → 字体 → 一致性** 五层固定顺序诊断，每层先判定后修参，禁跳层修补。

**适用场景**：「帮我美化一下」类需求；上线前自检；遗留界面体检；生成式 UI 闸门。不适用：从零设计（P-2/P-3）、品牌探索。**前提**：可运行界面或截图 + DevTools；真实数据渲染（含空/加载/错误态）[LAW-13] [AIM-10]。

**原理**：上游错误让下游修复失效；先上游后下游。分层为 [模型经验]。

### 步骤 0：走查准备

1. 真实数据渲染，截取 **375/768/1440** 三宽度截图（含空/加载/错误态）。
2. 缩到 25%~50% 眯眼预览，记录 3 个最刺眼问题；DevTools 就绪；「凭直觉先改哪」推迟到步骤 5 之后。

### 步骤 1：视觉认知层走查 —— 分组与层级是否可感知

本层即 50ms 宏观判断层（Lindgaard 2006，[模型经验]）。

| # | 检查项 | 判定标准 | 修参方向 |
|---|---|---|---|
| 1.1 | 眯眼分组测试 | 眯眼/20px 模糊后仍一眼数出主要分组 | 组间距升档 16→24/32 或加 Common Region；嵌套 ≤2 |
| 1.2 | 间距编码关系 | 组间 ≥ 组内 ×2；组间/组内/同级不共用同一数值 [LAW-1] | 按 4/8/12/16/24/32/48/64 重排；典型 组间:控件间:控件内 ≈ 32:16:8 [G-3] [G-9] |
| 1.3 | 唯一视觉焦点 | 每屏恰 1 个最高强度元素（唯一实心主 CTA）[LAW-3] | 次要操作降档：实心→描边→文本；危险操作不做同屏最醒目 [G-2] [G-4] [AIM-15] |
| 1.4 | 层级信号越阈值 | 相邻层级字号比 ≥1.2 或字重跨档（400→600）；±1px/±100 微差不达标 [LAW-2] | 拉大字阶差或跨字重档；宁可层级少而差大 |
| 1.5 | 强调色配比 | 强调色实心面积 ≤ 约 10%（60-30-10）[LAW-3] [G-21] | 强调色只留主 CTA 与关键状态；大面积底色改中性 |
| 1.6 | 颜色双通道 | 状态/数据/链接不得仅靠颜色区分（红绿尤其）[LAW-4] [AIM-4] | 补图标/形状/文字第二通道；红绿改蓝橙轴 |

溯源：[官方文档](https://lawsofux.com/llms.txt)；眯眼测试 [模型经验]。

### 步骤 2：布局层走查 —— 骨架是否稳定、节奏是否成立

| # | 检查项 | 判定标准 | 修参方向 |
|---|---|---|---|
| 2.1 | 基准网格对齐 | 间距/尺寸落 4 的倍数；无 13/15/18px 杂值 [G-8] | 归档最近刻度；刻度外值须溯源 token（见 5.2） |
| 2.2 | 容器与行长 | 正文容器有 max-width；西文 45~75ch（理想 ~66），中文 25~40 字/行 [LAW-9] [G-10] | 加 max-width: 65ch；全宽容器仅限工具型/数据型 |
| 2.3 | 对齐纪律 | >3 行正文不居中；标题/短文案可居中 [G-11] | 长段落左对齐（RTL 反向） |
| 2.4 | 动态内容稳定 | 长文案不溢出（min-width:0 + 截断三件套 [G-6] [G-12]）；img/table/iframe 限宽或滚动 [G-13]；媒体占位防 CLS [G-14] | 补 min-height + 截断；定高改 min-height；100vh 改 svh/dvh [G-15] |
| 2.5 | 响应式断点 | 断点 ±1px 不破版；移动端间距/字号随宽度缩放 | 断点边界逐像素测试 [LAW-24] |

### 步骤 3：色彩层走查 —— 对比与配比是否达标

| # | 检查项 | 判定标准（WCAG AA） | 修参方向 |
|---|---|---|---|
| 3.1 | 正文对比 | 文本/背景 ≥4.5:1；白底最浅合格灰 **#767676**（#999 ≈2.85:1 不合格）[G-17] [AIM-7] | 加深文字色而非改背景；灰字升 gray-500~600 档 |
| 3.2 | 大字与 UI 对比 | 大字（≥24px 或 ≥18.67px 加粗）≥3:1；非文本 UI（图标/边框/焦点环/描边）≥3:1 | 图标描边降亮度；输入框描边 300 档升 400 |
| 3.3 | 真实背景验证 | 对比度在真实渲染背景上算（图上文字/彩底/渐变/半透明单独验）[LAW-5] | 叠图文字加 ≥0.4 scrim 或实色 tint [G-22]；渐变按最差区校验 [G-19] |
| 3.4 | 语义色纪律 | success/warning/danger/info 不被装饰挪用；品牌色不做语义色除非约定 | 装饰改中性/次级色；语义色仅用于状态 [AIM-4] |
| 3.5 | 工具 | WebAIM Contrast Checker / DevTools / axe | 见 usability-accessibility kb |

### 步骤 4：字体层走查 —— 排版是否可读

| # | 检查项 | 判定标准 | 修参方向 |
|---|---|---|---|
| 4.1 | 字阶系统 | 字号来自 ≤6 级字阶；相邻比 1.2~1.333（推荐 1.25）[LAW-2] | 13/14/15/16px 微差档合并；正文 16px，小屏不 <14px |
| 4.2 | 行高 | 无单位 line-height；正文西文 1.4~1.6、中文 1.5~1.8；标题 1.05~1.25 | 长文行高取上限；大标题压 1.1 |
| 4.3 | 字重纪律 | ≤3 档（典型 400/500/600）；正文 400、标题 600 起 | 500/600 二选一；细字重（<300）仅超大展示字 |
| 4.4 | 语言与对齐 | 中文正文不加 letter-spacing；混排字体栈中文在后 [G-26] [G-27]；禁 justify | 去 letter-spacing；调字体栈；改左对齐 |
| 4.5 | 数字排版 | 表格/计数/金额用 tabular-nums 防跳动 | font-variant-numeric: tabular-nums |

### 步骤 5：一致性层走查 —— 系统是否收敛

| # | 检查项 | 判定标准 | 修参方向 |
|---|---|---|---|
| 5.1 | 同语义同值 | 同语义（主按钮/卡片圆角/标题字号）全站同值；同维度取值来源唯一 [LAW-11] | 合并双轨值；以 token 刻度归一 |
| 5.2 | token 溯源 | grep 组件样式：无硬编码 hex/rgb 与刻度外字面量（13px、border-radius:7px）[LAW-10] [G-16] | 换语义 token；无对应 token 走 P-2 步骤 5 审批 |
| 5.3 | 图标与词汇 | 图标库唯一；同一语义同一词汇（「删除」不混「移除」）[LAW-12] | 统一图标库与线宽；建词汇表禁同义漂移 |
| 5.4 | 状态完整性 | 交互组件状态集完整（default/hover/focus-visible/active/disabled，表单加 error，异步加 loading）[LAW-13] [AIM-6] | 补缺态；对照 style-design-system kb 场景 4 九态矩阵 |

### 步骤 6：回归验证

1. 修改后重跑该层+上游层机械检查项；断点 ±1px 重测；深色重跑步骤 3；收尾眯眼对比步骤 0。

**输出物**：分层问题清单（层号 + 检查项号 + 截图标注 + 修参方向 + 法则引用）+ 回归记录。

**相关法则引用**：LAW-1~5、9~14、22、24；负样本 [G-1]~[G-27]、AIM-4/6/7/10/15。

## P-2 从零建设计令牌体系

**一句话**：把颜色、字阶、间距、圆角、阴影、动效六类决策值固化为三层 token（primitive → semantic → component），可溯源、可全局调整。

**适用场景**：新项目起步；收敛「同语义多值」；为深色模式/换肤/品牌迭代打地基。**前提**：品牌输入已确认（无则用中性方案并声明「未注入品牌」[LAW-22]，禁蓝紫渐变脸 [G-32] [AIM-13]）。

### 步骤 1：建 primitive 层（六类原始刻度）

1. **颜色**：品牌主色 1 + 中性灰 10~11 档 + 语义色 4；OKLCH/HCT 或 sRGB 混色，**禁 HSL lighten/darken 批量生成** [G-20] [模型经验]。
2. **间距**：刻度 **4/8/12/16/24/32/48/64**，移动端下限 4 [G-8]。
3. **字阶**：基准 16px，比例 1.25（窄 1.2 / 展示 1.333），≤6 档 [LAW-2]。
4. **圆角**：3~4 档（典型 4/8/16 + 9999），命名 sm/md/lg/full。
5. **阴影**：3~4 档（sm/md/lg/xl），**单一光源**（右上 45°），只改模糊/偏移/不透明度 [LAW-11]。
6. **动效**：时长 3 档——100~150 / 200~300 / 300~500ms；缓动 2~3 个——ease-out / ease-in / 标准 ease；**禁 transition:all** [G-39] [LAW-15]。

### 步骤 2：建 semantic 层（语义命名）

1. 文本：`--color-text-primary/secondary/disabled`（阈值见 P-1 步骤 3）。
2. 表面：`--color-bg/surface/surface-raised`；反馈：`--color-success/danger/info/warning` + `on-*` 前景对。
3. 品牌：`--color-brand/brand-hover/brand-pressed` + 强调配比预算（≤10%，60-30-10 [G-21]）。
4. 间距：`--space-section`（区块）/ `--space-group`（组内）/ `--space-element`（元素间），层级递减 [LAW-1]。

### 步骤 3：建 component 层（可选）

1. 高频组件（Button/Card/Input）消费 semantic token 组装 variant，样式内**禁任何原始值** [LAW-10]。
2. 只消费语义层，**禁跳线直引 primitive**（`var(--blue-500)` 入组件即违规 [G-23]）[LAW-11]。

### 步骤 4：深色模式预留

1. semantic 层即重映射点：深色只改 semantic→primitive 绑定，component 零改动（见 P-4）。

### 步骤 5：治理规则

1. stylelint：组件样式出现 hex/rgb/刻度外 px 即报错 [G-16]。
2. 新增值审批：刻度外新值须证明无既有档可用，否则归档最近刻度。
3. token 文档：每类一张速查表，与 style-design-system kb 对齐。

**输出物**：`tokens.css`（三层定义）+ token 速查文档 + lint 配置。

**相关法则引用**：LAW-1/2/10/11/15/22；[G-16] [G-20] [G-21] [G-23] [G-39]；三层结构与九态矩阵见 style-design-system kb。

## P-3 落地页设计流程

**一句话**：以唯一转化目标为轴，按「首屏三问 → 骨架 → 逐屏论证 → 转化细节 → 五秒验证」产出说服路径清晰的单页。

**适用场景**：产品/活动落地页、注册引导页、单页宣传站。不适用：多目标门户、内容型首页（信息架构优先）。**前提**：转化目标唯一可度量（注册/购买/留资选一个）；目标用户与核心痛点已知。

### 步骤 1：定目标与主 CTA

1. 单句转化假设：「因为（痛点），（用户）会（动作）」。
2. 主 CTA 一个动词短语（「免费开始」/「预约演示」），全页视觉强调服务于它 [LAW-3]。

### 步骤 2：搭内容骨架（顺序可裁不可乱）

1. 默认骨架：**hero → 社会证明 → 核心特性 → 定价/方案 → FAQ → 尾部 CTA**。
2. 裁剪：低客单去定价、无口碑去社证；但 **hero 与尾部 CTA 永远保留**（峰终定律 [LAW-19]）。

### 步骤 3：首屏三问（hero 逐问验收）

1. **这是什么**：产品名 + 一句话品类定位（≤15 字）。
2. **对我有什么用**：主标题 = 价值主张 ≤10 词，写收益不写口号；副标题补差异化 [LAW-7]。
3. **下一步**：唯一实心 CTA + 次级描边链接；CTA 在首屏内，配视觉引导。
4. 验收：陌生人看首屏 5 秒答全三问（五秒测试，[模型经验]）。

### 步骤 4：扫读模式预判（按内容密度）

1. 文字密集 → **F 型风险**：F 是「文字墙+高效意图+低投入」三条件齐备时的默认最小努力路径，对用户和企业都是坏事（漏看右侧且不自知）——按解药八条处理：前两段放最重要要点、标题自解释且前 2 词承载信息 [LAW-7]、加粗关键词、边框/背景分组、列表化、删冗余 [VP-38] [官方文档](https://www.nngroup.com/articles/f-shaped-pattern-reading-web-content/)。
2. 文字少、视觉强 → 不预设扫视模式，按视觉流编排唯一入口点（layout-composition kb 场景 12）；**Z 型无 NN/g 官方支持，不作设计依据**（降级记录见 visual-perception kb 冲突记录 6）。

### 步骤 5：逐屏论证设计

1. 每屏一个论点，标题自解释（只扫标题能串起逻辑线）[LAW-7]。
2. 社证具体化：具体数字优于形容词；头像+实名优于匿名 logo 墙。
3. 特性区「特性 → 收益」成对（每特性一句用户结果，不堆参数）。
4. 定价：推荐方案视觉强调（唯一描边加粗/角标），≤3 档（Hick's Law [官方文档](https://lawsofux.com/llms.txt)）。

### 步骤 6：转化细节收敛

1. CTA 长页周期复现（每 2~3 屏，措辞不变 [LAW-12]）；尾部 CTA 与 hero 呼应。
2. 表单字段最小化（P-7 步骤 1）；每多一字段都是流失点。
3. 导航锚点直达各区；外链出页谨慎。

### 步骤 7：验证

1. 五秒测试（首屏三问）；2. 375 宽 CTA 拇指可达；3. 过一遍 P-1 走查。

**输出物**：页面结构稿（区块顺序 + 每屏论点句）+ hero 三问文案 + CTA 布点图。

**相关法则引用**：LAW-3/7/12/19；Hick's/Peak-End/Serial Position [官方文档]（URL 见来源索引）；F 型 [官方文档]（[VP-38]，NN/g 已锚定）；Z 型已降级撤销（visual-perception kb）；五秒测试 [模型经验]。

## P-4 深色模式适配流程

**一句话**：通过语义 token 整体重映射实现深色主题——重建层级（surface 提亮）而非反转颜色，逐类重算对比度。

**适用场景**：已有浅色主题+token 分层（无先走 P-2）。**前提**：semantic 已隔离 primitive（跳线直引先修 [G-23]）。

### 步骤 1：策略声明（两个禁止）

1. **禁 `filter: invert()`**：图片负片、品牌变浊、阴影失效、层级坍塌 [G-18]。
2. **禁只换背景色**——逐类重映射（步骤 2~4）。

### 步骤 2：逐类重映射（锚点值与细则见 color-system kb 场景 5，图片见 layout kb 场景 14）

1. surface：层级 = 提亮（越浮起越亮）；elevation（card/popover/modal）各绑一档替代阴影。
2. 文本锚点在新背景重算（浅色合格 ≠ 深色合格）；品牌/语义色提亮降饱和一档（#2563EB→#60A5FA）[G-18]。
3. 深底阴影几乎不可见：elevation 改 surface 提亮+1px 描边（HIG Materials [官方文档]，URL 见来源索引）。
4. 图片：深色版资源 / 降不透明度 ~0.85 / 暗化遮罩。

### 步骤 3：切换机制

1. 默认跟随 `prefers-color-scheme`；手动切换 localStorage 持久化；首屏关键 CSS 内联防白闪/黑闪；`data-theme` 重绑定即时生效。

### 步骤 4：回归验收

1. 浅/深并排截图逐屏对照；2. 全页对比度重跑（P-1 步骤 3）；3. 图片/视频/代码块逐类检查。

**输出物**：深色 token 映射表（semantic → 深色 primitive 对照）+ 切换组件 + 双主题截图集。

**相关法则引用**：LAW-5/10/11；[G-18] [G-22]；细则见 color-system kb（深色模式）与 style-design-system kb。

## P-5 无障碍走查清单流程

**一句话**：按 **对比度 → 焦点 → 键盘 → 目标尺寸 → 动效** 固定顺序执行机械可判的 WCAG 体检——先跑影响面最大的项。

**适用场景**：上线前 a11y 闸门；验收外包/生成代码；整改复检。不适用：读屏脚本级深度适配。**前提**：界面可交互；扫描工具（axe/WAVE/Lighthouse）与键盘。

### 步骤 1：对比度（最机械、影响面最大，先做）

1. 跑 axe/WAVE 全页扫描导出问题清单。
2. 三档阈值（正文 4.5:1/大字 3:1/非文本 3:1）与边界见 P-1 步骤 3 [LAW-5]。
3. 真实背景复验：图上文字、彩底、渐变、半透明逐处手测（扫描只查纯色对）[G-17] [G-19] [G-22]。
4. 豁免登记：logo、纯装饰、禁用元素可豁免。

### 步骤 2：焦点

1. 逐个 Tab 遍历：`:focus-visible` 存在且可见、对比 ≥3:1（SC 2.4.13 [官方文档](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/)）[LAW-21]。
2. 指示器不被 `overflow:hidden` 裁切、不被 sticky 头遮挡。
3. grep `outline: none/0`：无替代焦点样式即违规 [G-49] [AIM-1]。

### 步骤 3：键盘

1. Tab 顺序 = DOM 顺序 = 视觉顺序；跳序即记录 [AIM-2]。
2. 全功能键盘可达：操作有 Enter/Space 等价；hover-only 不可达即违规 [LAW-16] [AIM-6]。
3. 无键盘陷阱：任意位置可 Tab/Esc 离开；模态三件套——焦点入模态、Tab 循环、Esc 关闭并归还焦点 [AIM-3]。
4. skip-link 跳过重复导航。

### 步骤 4：目标尺寸

1. 指针：命中区 ≥24×24 CSS px（SC 2.5.8 AA，[官方文档](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/)）[LAW-6] [G-52] [AIM-5]。
2. 移动触控 ≥44×44（Android 48dp）；间距 ≥8px（细则同 P-8 步骤 3）。

### 步骤 5：动效

1. 实测 `prefers-reduced-motion: reduce`：位移/缩放移除，保留颜色/透明度终态反馈 [LAW-15] [AIM-8]。
2. 无 >3 次/秒闪烁（光敏阈值）；3. 动画仅 transform/opacity，无 layout 属性 [LAW-15]。

**输出物**：a11y 问题清单（SC 编号 + 截图 + 实测值 + 修复方向），按级别与影响面排序。

**相关法则引用**：LAW-4~6、15、16、21；[G-17] [G-49] [G-52]；完整条款表见 usability-accessibility kb。

## P-6 设计评审 checklist 流程

**一句话**：以 Nielsen 十启发式为共同语言——3~5 人独立走查 ≥2 遍，汇总后按 0~4 严重度评级，先谈问题后谈方案。

**适用场景**：里程碑评审、设计稿/实现走查、跨团队交接验收。不适用：真实用户可用性测试（专家法不替代用户测试）。**前提**：范围与用户角色书面定义；评估者 ≥3 人独立走查；十启发式清单人手一份 [官方文档](https://www.nngroup.com/articles/ten-usability-heuristics/)。

### 步骤 1：评审准备

1. 定义范围（页面/流程）、用户画像、关键任务。
2. 分发：设计稿 + 十启发式原文 + 记录模板。

### 步骤 2：独立走查（每人 ≥2 遍）

1. 第一遍整体浏览，感受流程与全局。
2. 第二遍起逐屏逐任务走查，逐条问「是否违反 #1~#10」；记录问题不记录解法。
3. 双遍法为 [模型经验]（NN/g 未抓取）。

### 步骤 3：汇总合并

1. 收集独立记录，同一问题去重（不同位置保留独立条目）。
2. 每条标注启发式编号 + LAW-N（如对比度挂 [LAW-5]）。

### 步骤 4：严重度评级（0~4）

三因子：**使用频率 × 影响程度 × 持久性**（[模型经验]，NN/g severity 页未抓取）。评级 0 非问题 ~4 灾难；处置：≤1 排期、2 本迭代、3 阻断发布、4 立即修复。

### 步骤 5：评审会执行

1. 按维度排序汇报（阻断级 → 细节级）：**可用性/无障碍 → 功能完整（四态）→ 层级/布局 → 一致性 → 色彩 → 排版 → 动效**——先讨论 3~4 级。
2. 纪律：只对照启发式/法则讨论，不辩论品味（「不好看」须翻译成「违反 #8 认知负荷 / [LAW-1]」才入记录）。
3. 先问题后方案：本轮不强制给解法。

### 步骤 6：输出整改清单

1. 按 严重度 × 频率 排序；每条指派负责人 + 验收标准（WCAG SC / LAW-N 可判表述）。
2. 复审闭环：整改后只复验问题条目（对照 P-1/P-5），不全量重审。

**输出物**：问题汇总表（位置 + 启发式编号 + 严重度 + 负责人 + 验收标准）+ 评审纪要。

**相关法则引用**：LAW-5/13/19/21；十启发式 [官方文档]（URL 见前提）；严重度细则见 usability-accessibility kb。

## P-7 表单设计与校验流程

**一句话**：从「要不要这个字段」开始的表单建设——单列布局、持久 label、blur 后就地校验、错误可行动、提交防重、数据不丢。

**适用场景**：注册/登录/结账/设置等录入界面；长表单分步。不适用：行内编辑/表格批量录入。**前提**：后端与校验规则已知（前端校验 ≠ 唯一防线）；服务业务统计而非用户任务的字段优先砍。

### 步骤 1：字段最小化

1. 逐字段问「删掉会怎样」：无阻断影响的删除或合并（姓+名 → 全名）；能推断的不问（从上下文带入）。
2. 可选字段复审：可选率 >90% 建议删；保留的标注统一（`*` 表必填或文案表可选，二选一全站统一 [LAW-12]）。

### 步骤 2：结构与布局

1. **单列布局**：多列破坏 Tab 顺序与扫读（语义对可局部并排）。
2. 每字段持久 label（`<label for>`），placeholder 只作格式示例——**placeholder 不充当 label**（输入后消失、无法核对）[G-1] [AIM-9] [LAW-16]。
3. 相关字段 `fieldset/legend` 分组；label 就近（移动端上方为佳）；字段间距 ≥2× 控件内距 [LAW-1]。

### 步骤 3：输入辅助

1. `type` 正确（email/tel/number/url）唤起对应键盘；`autocomplete` 全字段配置。
2. 格式约束就地提示（`YYYY-MM-DD`）；必要时输入掩码，不阻止粘贴。
3. 密码框可见性切换；强度提示实时但不打断。

### 步骤 4：校验策略（就地 inline）

1. 时机：**blur 后触发**；输入中可转实时反馈；提交时全量兜底——禁逐字符打断。
2. 正确也反馈：通过项给轻量成功标记（对勾）。
3. 错误信息三要素：**发生了什么 / 为什么 / 怎么办**（「邮箱格式不对，应形如 name@example.com」）；定位到字段：红色标记 + `aria-invalid` + `aria-describedby` [LAW-19] [AIM-12]；聚焦第一个错误。
4. 禁笼统 toast「出错了，请重试」；禁只报数量不报位置 [LAW-19]。

### 步骤 5：提交与反馈

1. 提交中：按钮 disabled + loading（防连点重复提交 [LAW-17] [AIM-11] [G-43]）。
2. 失败：**保留全部已输入数据**（仅成功后清理）[LAW-20]；错误同步骤 4；网络错误区别于校验错误。
3. 成功：显著成功反馈（页内/跳转二选一）；转化后页面无死胡同。

### 步骤 6：长表单专项

1. 分步：每步一个主题（≤7 字段/步，组块化而非 ≤7 教条 [官方文档](https://lawsofux.com/llms.txt)）；进度可见；步间不丢数据。
2. 或不分步：草稿自动保存 + 刷新/断网恢复。

### 步骤 7：防误操作

1. 高风险操作（清空表单/删除草稿）：显式确认写明后果，或可撤销 ≥5s [LAW-18]。
2. 禁依赖原生 `confirm()/alert()` 作为唯一防护或反馈 [LAW-18]。

**输出物**：字段清单（autocomplete/校验规则/错误文案三要素）+ 布局稿 + 提交态流转图（idle/validating/submitting/success/error）。

**相关法则引用**：LAW-1/12/16~20；[G-1] [G-43]；校验分层与错误三要素见 usability-accessibility kb；表单视觉负荷见 visual-perception kb。

## P-8 移动端适配流程

**一句话**：按视口→安全区→触摸→手势→键盘→性能→平台惯例逐层适配，每层真机判定后修参。

**适用场景**：桌面界面移动化、移动优先新项目、H5/WebView。**前提**：真机或设备模拟。

### 步骤

1. **视口**：地址栏收展/旋转不裁切不跳动 → `100vh` 改 `100dvh`（防跳 `svh`），留 vh 回退 [G-15]。
2. **安全区**：刘海/手势条不遮挡内容与 CTA → `viewport-fit=cover` + `env(safe-area-inset-*)` padding，底栏补 inset-bottom。
3. **触摸**：可点元素 ≥44×44（Android 48dp）、间距 ≥8px [LAW-6] → 小图标透明 padding 扩命中区。
4. **手势**：左右边缘 ~20px 无核心操作、横滑不与纵滚互踩 → 边缘避让 + `touch-action` 声明。
5. **键盘**：正确键盘、聚焦可见、无 iOS 缩放 → `inputmode`/`enterkeyhint` + `scrollIntoView` + 字号 ≥16px。
6. **性能**：低端机滚动转场流畅 → 动效纪律同 P-5 步骤 5 [LAW-15]，blur 加 `@supports` 兜底。
7. **平台惯例**：返回/分享/弹性滚动符合平台预期 → SPA history 管理 + `overscroll-behavior: contain`。

**输出物**：真机截图集（键盘/旋转/刘海屏）+ 修订记录。溯源 [模型经验](corpus/ui-ux-design/_patterns/08-mobile-adaptation.md)。

## P-9 数据密集界面设计流程

**一句话**：先定信息层级（KPI→趋势→明细）再定容器，密度/加载/数据态随后置约束。

**适用场景**：后台列表、报表、仪表盘。**前提**：数据规模与用户任务（检索 or 扫读）已知。

### 步骤

1. **信息架构**：KPI/趋势/明细三层、首屏指标 ≤5 [LAW-3] → 超出下沉二级页；跨层口径一致。
2. **表格骨架**：粘性表头 + 固定关键列，交叉角双 sticky 实底 → 其余列 min/max-width + 截断，容器横滚。
3. **密度**：compact/default/comfortable 三档（行高 ~32/44/56px，触屏升档）→ 切换持久化。
4. **排序筛选**：排序三态可见、筛选可清空、计数实时 → 状态同步 URL [LAW-12]。
5. **加载方式**：检索型分页、消费型滚动、超大表虚拟滚动（>200 行或可视×10<总量触发）。
6. **数据态**：骨架对齐网格；首载/筛选无果/真空库/局部失败四态分立 [LAW-13]，局部刷新保滚动位置。
7. **批量导出**：跨页选择持久 + 已选 N 项浮条、破坏性操作确认、异步导出有通知，口径随筛选。

**输出物**：层级图 + 列清单（宽度/密度/排序/固定）+ 数据态矩阵。溯源 [模型经验](corpus/ui-ux-design/_patterns/09-data-dense-ui.md)。

## P-10 详情页构图流程

**一句话**：按「头部识别 → 决策信息 → 行动区 → 延伸推荐」四段组织详情页，行动入口长页常驻。

**适用场景**：商品/内容/人物详情页。**前提**：对象的核心决策要素已知。

### 步骤

1. **头部识别**：题图+标题+1~3 关键属性首屏齐备——50ms 识别「这是什么」[LAW-7]。
2. **决策信息**：按决策权重排序（商品：规格→评价→售后）；评价近行动区。
3. **行动区**：主操作唯一实心 [LAW-3]；长页常驻——桌面侧栏 sticky、移动底部栏（价格+CTA，拇指可达）。
4. **构图**：桌面两栏（左媒体右信息）、移动单列；题图 aspect-ratio 占位防 CLS [LAW-14]。
5. **延伸区**：相关推荐置尾部、不早于决策信息，关系明确（「同类」非裸「推荐」）。
6. **失效态**：下架/删除页给替代出口 [LAW-13]；回列表不丢筛选，返回恢复滚动位置。

**输出物**：四段式区块图 + 行动区布点。溯源 [模型经验](corpus/ui-ux-design/_patterns/10-detail-page.md)。

## P-11 导航系统设计流程

**一句话**：按「全局/层级/关联」三类组件拆解，先选型后定结构——每页可答「你在哪、能去哪、怎么回」。

**适用场景**：新站导航搭建、导航改版、「迷路/找不到/回不去」诊断。**前提**：信息架构（页面清单与层级）已知。

### 步骤

1. **分类**：需求拆为全局（顶部/侧边/底部 tab）、层级（面包屑/返回）、关联（相关链接/TOC）三类，分别设计。
2. **选型**：Web 一级 ≤7 项顶部导航；深结构（>10 页/2 层）加侧边栏；移动 App 底部 tab 3~5 项；汉堡只装低频项（可发现性差，移动 Web 不作核心导航）。
3. **排序与标签**：按任务频率排（高频靠前 [LAW-1]）而非组织架构；标签用用户语言、全站一致 [LAW-12]。
4. **状态**：active 可见且双通道（加粗/指示条，非纯颜色）[LAW-4]；SPA active 与路由同步、切换保滚动位置；全局导航跨页恒定。
5. **无障碍**：nav + aria-label；当前项 aria-current="page"；skip link；下拉键盘可达非 hover-only [LAW-16]；导航项 ≥44×44 [LAW-6]。
6. **验收**：任意页 ≤3 次点击回首页；「你在哪/能去哪/怎么回」每页可答。

**输出物**：导航地图（层级树+可达路径）+ 标签表。溯源 [模型经验](corpus/ui-ux-design/_patterns/11-navigation-systems.md)。

## P-12 搜索体验设计流程

**一句话**：搜索框 → 输入反馈 → 结果呈现 → 无结果策略四段闭环，防抖与竞态守卫内建。

**适用场景**：站内/应用内搜索、命令面板、列表筛选搜索框。**前提**：数据规模与延迟已知。

### 步骤

1. **搜索框**：位置显著；宽度预示容量（桌面 ≥40ch）；placeholder 示例化；`Ctrl/⌘+K` 快捷键。
2. **输入反馈**：即时搜索 ~300ms 防抖；**竞态守卫**（AbortController/请求序号，迟到响应丢弃）；loading <100ms 不显示；结果计数常显。
3. **结果呈现**：命中词 `mark` 高亮；按类型分组（最近/推荐/分类）；键盘 ↑↓+Enter+Esc 全可达；查询同步 URL [LAW-12]。
4. **无结果**：区分「库为空」（引导创建）与「无匹配」（保留查询可改+近似项+清筛选出口），永不死胡同 [LAW-13]。

**输出物**：搜索状态机（idle→no-results 六态）+ 竞态守卫方案。溯源 [模型经验](corpus/ui-ux-design/_patterns/12-search-experience.md)。

## P-13 首次引导与激活流程

**一句话**：以「注册 → 核心价值」最短路径为轴，引导模式从轻到重选——空态与上下文引导优先，checklist 次之，tour 是最后手段。

**适用场景**：新产品/新功能首次体验、激活率优化。**前提**：核心价值动作（aha moment）已明确。

### 步骤

1. **TTV 路径**：列出注册完成→体验核心价值的每一步，删非必需前置（教程/填资料/订阅提示后置）。
2. **模式阶梯**：产品自解释（默认数据/示例内容）> 上下文内引导（空态创建，同 P-12 步骤 4）> checklist（3~7 项关键动作+进度+每项即时反馈）> tour（仅复杂界面无法自解释时）。
3. **tour 纪律**：≤5 步、一步一个点、必有跳过且完成后永不重现；spotlight 不遮挡目标、视口外先滚动定位；步骤绑定选择器，改版同步验收。
4. **提问纪律**：个性化问题 ≤3 且可跳过，答案即时改变体验；tooltip 只在高频困惑处（就近、单点、dismiss 记忆）。
5. **分流**：首访/回访分流，跳过状态持久化；被跳过的引导在帮助菜单可重放。

**输出物**：TTV 步骤图 + 引导模式决策 + 触发/重放清单。溯源 [模型经验](corpus/ui-ux-design/_patterns/13-onboarding-activation.md)。

## P-14 错误与失效页面系统

**一句话**：404/401/403/410/500/503/离线按 HTTP 语义分型处理——全局导航与搜索恒在，透明+道歉+出路，永不死胡同。

**适用场景**：错误页、errorBoundary fallback、离线页。**前提**：监控上报通道已知（可生成错误 id）。

### 步骤

1. **分型**：404 给近似建议+搜索+回首页；401 未登录给登录入口、403 无权限给说明与申请路径；410 给替代位置；500 给道歉+重试+状态页链接+上报 id；503/维护给预期恢复时间+「恢复后通知我」；离线给明确状态+缓存可用内容清单。
2. **恒定骨架**：全局导航与站点搜索保留（用户可自救 [LAW-13]）；唯一主行动（404=回首页/搜索，500=重试）；错误 id 可复制（报障定位）。
3. **语气三段式**：发生了什么+对不起（500/503 归属我方）+能做什么；禁指责用户；禁技术细节泄漏（堆栈/SQL/内部路径）；IP 卖萌限低挫败场景——404 可轻松、500 严肃。
4. **工程托管**：SPA 未匹配路由渲染通用 404（非空白）；errorBoundary 必配 fallback UI（NEVER 白屏）；错误页资源本地化（防 webfont 失败二次白屏）；页面挂载即上报（URL+错误码+referrer）。
5. **离线专项**：service worker 预缓存 offline 页；输入数据本地暂存；`online` 事件自动恢复+提示刷新。

**输出物**：六型页面稿 + 上报字段清单。溯源 [模型经验](corpus/ui-ux-design/_patterns/14-error-pages.md)。
