# 边界与异常处理

| 情形 | 怎么处理 |
|---|---|
| 原文只有 3 行 | 不硬套格式族，直接给一句话总览 + 保留原文关键句 |
| 用户同时要纪要 + 对比 | 先纪要后对比，分两段，不要混在一张表里 |
| 原文自相矛盾 | 不替原文裁决；并列两处说法并标注「原文存在冲突」 |
| 含敏感个人信息 | 输出前脱敏（手机号/身份证/地址打码），并提示已脱敏 |
| 多语言输入 | 默认用用户提问语言输出；专业术语保留原文并括注译名 |
| 用户只要「一句话总结」 | 严格一句话，不附加 bullet，除非用户追问 |

## 异常输入纠错协议

特殊输入不要硬套格式，按下表处理并在输出中说明处理方式：

| 异常 | 识别信号 | 处理 |
|---|---|---|
| 极短输入 | 少于 50 字或只有一两句 | 不套格式族；一句话总览 + 保留原句 |
| 无结构长文 | 无标题、无分段、通篇一段 | 先按主题切 3–5 段再摘要；段间不自行建立因果 |
| 表格破损 / 乱码 | 列错位、字符异常 | 保留可读单元格；破损处标「原表损坏，X 列不可读」 |
| 数字或日期冲突 | 同一事实两处不一致 | 并列两值并标「原文冲突，需人工确认」；不替原文裁决 |
| 多语言混杂 | 中英日等混排 | 按用户提问语言输出；术语保留原文并括注译名 |
| 转写错字 | 同音词异常（如「连接迟」） | 按上下文推定并标「按上下文推断，原文为 X」 |
| 原文缺失关键项 | 无责任人、无期限、无结论 | 保留空格并标「原文未提及」，禁止补全 |
