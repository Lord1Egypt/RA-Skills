# 插图类别与推断规则

插图不是图片，是**程序化线条画**：由「类别 + 种子哈希」决定构图，同一道菜名永远画出同一幅，零成本、毫秒级。

## 22 个类别

| kind | 画的是什么 | 常见菜 |
|---|---|---|
| `pork` | 盘上叠放方肉块，带葱段 | 红烧肉、东坡肉、回锅肉、糖醋里脊 |
| `beef` | 不规则肉块 + 肌理纹 + 黑胡椒 | 牛排、牛腩、夫妻肺片、麻辣牛肉 |
| `chicken` | 鸡腿带骨 / 白切鸡切片 / 鸡块配辣椒 | 白切鸡、烤鸡腿、辣子鸡 |
| `fish` | 整鱼（梭形身+尾鳍+鳃+鳞）／汤碗鱼片／花刀鱼 | 清蒸鲈鱼、酸菜鱼、松鼠鳜鱼 |
| `shrimp` | 弯虾身 + 分节 + 触须 | 白灼虾、蒜蓉虾、小龙虾 |
| `crab` | 圆壳 + 双螯 + 步足 | 大闸蟹、香辣蟹 |
| `shellfish` | 扇形贝壳 + 放射纹 | 扇贝、蛤蜊、生蚝、螺 |
| `veg` | 两棵小油菜（白帮+叶）／一丛炒叶菜 | 清炒时蔬、蒜蓉菠菜、手撕包菜 |
| `mushroom` | 菌盖 + 菌柄丛生 | 香菇、松茸、木耳 |
| `tofu` | 方块豆腐叠放 | 麻婆豆腐、铁板豆腐、家常豆腐 |
| `egg` | 整蛋／蒸蛋／番茄块配蛋块 | 卤蛋、蒸蛋、番茄炒蛋 |
| `salad` | 盘上交错细丝 + 碎粒 | 凉拌菜、拍黄瓜、沙拉 |
| `noodle` | 碗 + 挑起的曲线面条 + 配料 | 各种面、粉、米线、意面 |
| `rice` | 碗 + 堆起的饭粒 | 蛋炒饭、煲仔饭、咖喱饭 |
| `soup` | 汤碗 + 汤面涟漪 + 蒸汽 | 各种汤、羹、粥 |
| `dumpling` | 月牙饺子 + 褶 | 饺子、馄饨、抄手、烧麦 |
| `pancake` | 叠层圆饼 + 焦斑 | 葱油饼、肉夹馍、披萨、三明治 |
| `skewer` | 竹签穿肉块 | 羊肉串、烤鸡翅、烤蔬菜 |
| `hotpot` | 锅体 + 红油 + 蒸汽 | 火锅、干锅、麻辣香锅、毛血旺 |
| `dessert` | 小碟甜点 + 点缀 | 布丁、蛋糕、杨枝甘露、蛋挞 |
| `drink` | 杯或壶 + 液面 | 茶、酒、可乐、酸梅汤、豆浆 |
| `generic` | 盘 + 散落配料（兜底） | 无法归类的菜 |

## 推断顺序（很关键）

菜名 → 别名的顺序是**形态优先于食材**：

```
精确别名表 → 饮品 → 锅 → 面 → 汤 → 饭 → 饺子 → 饼 → 串
→ 甜点 → 蟹 → 虾 → 鱼 → 贝 → 牛 → 猪 → 禽 → 菇 → 豆腐 → 蛋 → 凉菜 → 蔬菜
```

所以「牛肉面」判成 `noodle` 而不是 `beef`，「虾仁炒饭」判成 `rice`，这是对的——菜单上顾客先看到的是**这是什么形态的一盘菜**，不是用了什么料。

**精确别名表**专治歧义：`鱼香肉丝 → pork`（不是鱼）、`鱼香茄子 → veg`、`蚂蚁上树 → noodle`、`夫妻肺片 → beef`、`宫保鸡丁 → chicken`。

推断不放心时，直接在数据里写死 `kind`，会覆盖自动推断。

## 变体：同一类别的不同构图

只有部分类别带变体，由菜名哈希决定用哪一个：

`fish`、`veg`、`noodle`、`egg`、`hotpot`、`dessert`、`drink` 各 2 种；
`pork`、`beef`、`chicken` 的构图画法内部按随机数分支，实际也是多种。

所以「清蒸鲈鱼」和「酸菜鱼」虽然都是 `fish`，画面不同。**这是刻意的**：一页菜单上出现四碗一模一样的面，会立刻露馅。

## 换一幅插图

同一道菜觉得画得不好看，不要改 `kind`，改种子：

```js
dish._seed = '任意新字符串'   // 或用 uid() 生成
```

这会重跑一次构图随机数，换一个布局但保持同一类别。反复换几次直到满意，然后把结果固定下来（`_seed` 存进数据里就不会再变）。

## 外部 SVG 也能用

`dish.art` 填 SVG 片段，优先于引擎生成。会被白名单清洗：

- **保留**：`svg g path line polyline polygon rect circle ellipse text tspan defs linearGradient radialGradient stop clipPath use`
- **剔除**：`script style foreignObject iframe`、所有 `on*` 事件、外部 `href`
- **建议**：`viewBox="0 0 100 100"`，只用 `stroke` 描边，颜色写 `INK` / `ACCENT` 两个 token（会被替换成当前主题的真实色值），这样换主题时插图自动跟随

清洗后图元少于 4 个会报 `art-thin`（辨识度不足），超过 70 个报 `art-busy`（缩小会糊）。

## 菜品过多时怎么办

**插图关不掉。** 每一行都会画，没有「纯文字行」这个开关——这是当前实现的硬约束，不要向用户承诺「招牌配图、其余纯文字」。

菜太多只能从这三处省空间：

1. **拆成两张菜单**（正餐 / 酒水 / 午市套餐），这是最优解，也是最像真店的做法
2. **砍描述**：`blurb` 留空，每行省一行字高
3. **砍标签**：`tags` 清空，再省一行

三者都做完仍然超过 `maxHeight`，就说明这道数不适合单页，直接建议拆。
