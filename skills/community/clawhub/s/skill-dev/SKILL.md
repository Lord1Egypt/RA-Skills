# Skill 开发 — 技能优化修复助手

> @scene#18: 专门负责修改和优化已有技能。
> 当发现技能有漏洞/流程缺失/逻辑错误/经验教训需要沉淀时触发。

## 触发词

- 优化技能
- 修改技能
- 技能有问题
- 技能漏洞
- 改进技能
- 技能踩坑
- 把这个经验写进技能
- 技能加一条规则

## 工作流

```
触发 → 分析问题 → 定位根源 → 修改技能 → 回归验证 → 记录影响范围
```

### 1. 分析问题
确认问题类型（漏洞/流程缺失/逻辑错误/经验沉淀），复现路径是否清晰，影响范围多大。

### 2. 定位根源
读取目标 Skill 的 SKILL.md 和相关脚本，找出问题所在的具体行/段落，判断局部修复还是需要重构。

### 3. 修改技能
使用 SkillManage (modify) 精确修改。如果是跨文件改动，核对所有引用。保持 SKILL.md 格式规范。

### 4. 回归验证
检查修改后逻辑是否闭环，确认没引入新问题，更新 changelog（如有）。

### 5. 记录影响范围
在 MEMORY.md 记录改动。如有影响其他技能，标注联动关系。

## 核心信条

- **主动修复，不等指令**：发现 bug/typo/缺失步骤/过时信息，直接改，改完告知
- **改动最小化，但闭环**：修一个 typo 别顺手重构整个文件；如果改一行导致别处也要联动，必须全部改到位
- **经验即资产**：每次踩坑都应写进技能，技能是活的文档

## 注意事项

- 只改技能文件（SKILL.md + scripts/ + references/），不动用户数据
- 先读后改：永远先 Read 目标文件，确认现状再动手
- 精确匹配：确保 old_string 完全精确
- 涉及删除用户数据的操作必须确认
