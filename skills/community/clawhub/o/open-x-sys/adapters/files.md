# Files: Make Systems, Works, and Change Ownable

Files are the most common sensors, actuators, and portable carriers OpenXSys has in a computer environment. They can hold materials, works, code, tests, configuration, and `SYSTEM.md`; composition, relations, purpose, and feedback make those files act together as a system.

## Reading

Locate the relevant entry and real owner first, then read along the object's relations as needed. Respect the existing project structure, instructions, version-control state, and the user's uncommitted changes. Keep source material, generated output, caches, authoritative state, and historical archives in clear roles.

## Writing

Write where the object naturally belongs, preserving established formats and naming. Keep important edits small and locatable; inspect the target and impact first. Separate generated output from sources and preserve user work. Open, parse, run, or render the result when the environment allows. Where verification is still pending, state the remaining uncertainty precisely.

`SYSTEM.md` carries the most useful natural-language entry to a system now: purpose, central understanding, usable capabilities, relations, works, corrections, and handoff points. Its structure follows the system, while external authoritative state remains in the system that owns it.

## Migration and recovery

Files help a person carry a system across hosts; paths, tools, permissions, and external connections are re-established in the new environment. Before bulk or irreversible change, resolve the exact target and preserve a suitable snapshot, backup, or rebuildable source. Update only what depends on the changed part.
