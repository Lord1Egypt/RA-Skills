# System Entry and Continuity

Use the entry named by the user, an authorized project `.openxsys/SYSTEM.md`, or the portable root entry the user has chosen at `~/.openxsys/SYSTEM.md`. Explicit user choice, the active conversation, and the Skill actually loaded by the host determine which system continues the work.

## Continue on an existing system

Carry forward the original object, location, works, explicit goals, user corrections, and current authority. Read the entries and materials relevant to this run; determine what still holds, what changed, and what remains unseen. Make the first continuation perceptibly valuable—for example by explaining a new phenomenon the old model cannot explain, reusing one tool across projects, or completing a work that previously existed only as intent.

Build the active system map around the current object. The root entry provides cross-project purpose, understanding, and capability. The project entry supplies local facts, works, and constraints. The host supplies current tools, permissions, and events. Reality supplies what must be judged again. Load only the relevant parts. When entries conflict, use actual ownership, the newest checkable state, and the user's current correction, while preserving differences that remain unresolved.

Continuation combines old works and real change into a higher starting point today. Background enters the active picture when it changes present understanding, choice, or action. The system preserves structures that can act again in the future.

Existing system agreements remain readable. Skill selection and changes to a user system each follow their own authorization. A trial preserves the original entry and works. An authorized workspace may contain a separate result or verification artifact. When the user wants an improvement to remain in the existing system, update only what it truly changes and preserve links, user edits, and valid constraints. Independently maintained systems are changed by their respective owners.

## Locate, recover, and hand off

- The object the user currently identifies comes first, followed by the active conversation and real workspace. The root system supplies personal context and cross-project relations; the project entry supplies project facts and constraints. When two directions create materially different results, explain the difference and proceed through their reversible common ground.
- After interruption, check work that actually happened, results that can be retrieved, and actions awaiting confirmation. When external state is unclear, check with the holder of that state. The user may continue, pause, redirect, or cancel arrangements that have yet to execute.
- Another AI can continue from the same natural-language entry and existing materials. Distinguish portable understanding, works, and validated capabilities from host-specific authority. When the current host cannot reach a location, use a user-provided snapshot or deliver a portable entry and works.

The user decides where a new system lives, and private content remains in the appropriate scope. Information with long-term value may be carried by a short explanation, references to primary material, or actual tools. Its structure follows the object.

## A useful continuation

Let later work reconnect reality to prior understanding. Preserve confirmed purpose, current understanding of the object, sources that need rechecking, runnable tools, and actions known to depend on a particular host. Root entry, project entry, and works may point to one another. When work changes one area, update only affected material. When host tools, authorization, or data sources change, determine whether that difference changes the current action. One ordinary text entry can say everything a successor needs to take over.
