# 实战案例：WorkBuddy 每日自动领积分

真实跑通的完整案例，可直接作为同类客户端签到/领奖的参照。

## 目标与结论

每天自动在 WorkBuddy 客户端领两样东西：
1. **Buddy 加油站「每日可领 100 积分」**（左下角卡片）——真正加积分的入口。
2. **成长计划「兑换奖励」入门档**（+2 能量 / +1 补签卡 / +1 抽奖卡，不含积分）。

关键发现：一开始误以为入口是"成长计划签到"，实际那里**没有独立签到按钮**（连登是打开即记录），积分来自左下角加油站卡片。找对入口比写对脚本更重要。

## 界面入口与幂等信号

| 项目 | 入口 / 信号 | 幂等判断 |
|---|---|---|
| 100 积分 | 左下角卡片「Buddy加油站 / 每日可领 100 积分 / 立即领取」 | 按钮变灰「今日已领取」→ 跳过；黑按钮点击（领分或打开面板都无害） |
| 成长计划 | 左下账号头像 → 账号菜单「成长计划」→ 活跃地图「兑换奖励」 | 选择奖励对话框里入门档显示「已兑换」→ 跳过 |

积分余额验证：领前 593.47 → 领后 693.47（+100），确认真实到账。

## 三态按钮（核心难点）

同一张卡片在不同时候出现三种按钮：
- 黑色「立即领取」= 未领，点击领 100 分。
- 灰色「今日已领取」= 已领，**跳过**。
- 黑色「立即前往」= 已领的另一形态，点击会打开成长计划（无害）。

判断策略：
1. 先找灰「今日已领取」，命中即跳过（最高优先级）。
2. 否则找黑按钮（「立即领取」或「立即前往」任一模板），点一次。
3. 靠颜色辅助：采样按钮中心像素，灰≈230、黑≈0，比文字模板更稳。

## 踩坑复盘（按时间线）

1. **会话隔离**：WorkBuddy automation 连续 6 天报 `screen grab failed` / `Error 5`，脚本本身在主会话完全正常。→ 改 Windows 计划任务，方案 A。
2. **坐标全空**：照缩放预览图估算坐标，点击落到别的对话。→ 改用原始像素裁剪 + 倍数反算。
3. **入口漂移**：左侧「做任务赢积分好礼」卡片会被对话列表挤走。→ 改走账号头像菜单这一稳定入口。
4. **模板误匹配**：confidence 0.7 时灰「今日已领取」被误判成黑「立即领取」，误点账号头像。→ 提高到 0.75+，颜色辅助。
5. **滚动漂移**：固定拖动量导致「兑换奖励」时隐时现。→ 多次滚动 + 模板全区域搜索兜底。
6. **找错领奖点**：成长计划兑换不含积分。→ 加油站的 100 积分才是主任务。

## 验证方式

- 手动跑业务脚本：识别"今日已领取"和"已兑换"都正确跳过，无重复领取。
- 计划任务手动触发：`LastResult=0`，生成 5 张证据截图，日志正确。
- 汇报层：WorkBuddy automation 9:20 只读日志和截图汇报，把加油站 100 积分纳入判断规则。

## 复用建议

换任何客户端软件时，保留上述五步流程范式，只替换：窗口标题、入口模板、幂等信号、关闭按钮坐标、业务动作。核心资产是 `gui_auto.py`，业务逻辑写在独立脚本里，两者解耦。
