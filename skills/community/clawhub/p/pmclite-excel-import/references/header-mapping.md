# 表头映射与脏数据处理

客户的列名千奇百怪，但落到契约上只有几十个字段。这份表覆盖常见的叫法；没有命中的列不要硬猜，问用户一句比导错一批便宜。

| 单位、计量单位、基本单位、UOM | unit |
| 类别、分类、物料类别、物料组 | category |
| 供应商、厂商、供货商 | supplier |
| 单价、含税单价、采购价、标准价 | unitPrice |

## products

| --- | --- |

## bomItems

一张 BOM 表通常有两种写法，先判断是哪一种再转：

- **单层展开式**：每行是“父产品 + 子件 + 用量”，直接映射。
- **层级缩进式**：用缩进或“层级”列表示多级 BOM。这种情况需要先确认父子关系，不要按行号猜层级。

| 常见表头 | 字段 |
| --- | --- |
| 父件编码、产品编码、成品编码、母件 | productCode |
| 子件类型（物料/半成品） | type（物料→`material`，半成品→`subproduct`） |
| 子件编码、物料编码、组件编码 | materialCode |
| 半成品编码、子产品编码 | subProductCode |
| 用量、单位用量、数量、装配数量 | quantity |

| 常见表头 | 字段 |
| --- | --- |
| 工单号、制令单号、生产订单号、MO | orderNumber |
| 产品编码、成品编码、机种 | productCode |
| 计划数量、工单数量、生产数量 | quantity |
| 优先级、紧急度（高/中/低，或 P0/P1/P2） | priority |

优先级要把客户的写法统一成三档再导，转换规则要告诉用户。常见映射：P0/特急/加急/Urgent → 高；P1/急 → 高或中（看用户口径）；P2/普通 → 中；低/不急 → 低。

## 多余列

序号、行号、备注、制表人、制表日期、审批、签字、金额合计——这些列对导入没有意义。直接忽略，不要在回执里逐条解释“这列没导”。如果备注里含关键信息（比如“替代料”“停用”），单独问用户要不要落进 spec 或 category。

## 合并单元格

Excel 里合并的单元格只有一个值，取左上角的值向下填充即可，前提是该列在业务上确实表示“同属一组”（比如同一产品的多行 BOM）。如果合并列是编码类字段，填充前要跟用户确认，因为填错会把多个物料并成一个。

## 没有表头或表头不在第一行

1. 看前 3 行：全是文本且各列取值分散，才可能是表头；
2. 第一列是序号、第二列开始才是字段名，这种表头是“错位”的，按值判断而不是按位置；
3. 表头在第 2、3 行（上面有标题、制表信息）时，跳过前几行再取；
4. 完全无表头（首行就是数据）：只能看样例推断列义，准确率上限低，**必须让用户逐列确认**再导，不要自行拍板。

## 值的清洗

| 脏数据 | 处理 |
| --- | --- |
| `1,200.00`、`￥1200`、`1200元` | 去掉千分位与货币符号转成数字；转换前把结果复述给用户 |
| 全角数字、全角逗号 | 转半角后按数字解析 |
| `2026/11/20`、`11月20日`、`2026.11.20` | 统一成 `YYYY-MM-DD`；缺年份时问用户 |
| 单位与数量混写（`500个`） | 拆成 quantity=500、unit=个 |
| 空白行、小计行、合计行 | 跳过，并在回执里说明跳过了几行 |
| 编码前后有空格 | 去空格；编码中间的空格保留，可能是业务编码的一部分 |
