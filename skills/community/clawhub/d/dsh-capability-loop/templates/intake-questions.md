# 项目接入问题模板（可直接复制问用户）

> 用途：`references/05-intake.md` 的**可粘贴版本**。一次性问完（≤6 问），能默认就给默认，用户已给的不重复问。
> 用法：把下面「粘贴块」原样发给用户（或作为 `ask_user_question` 的题干）；答复写进 `templates/project-profile.md`。
> 原则：**不问就不假设**；答不了的进 D-ID，不阻塞其它可做部分。

## 粘贴块（6 问）

```text
接入这个项目，先确认 6 件事（可简答，能默认我会标注）：

1) 系统/模块是什么？谁在用（角色）？当前阶段：0-1 / 改版 / 维护？
2) 行业与合规：燃气 / 电网 / 碳 / VPP / 电价 / 标书 / 其他（其他=不加载行业框架）
3) 真相源在哪：运行地址 / 代码仓库 / 接口文档 / 只读数据或 DB / 现有文档（缺哪项我登记 GAP，不猜）
4) 本次目标一句话 + 验收口径（怎么算完成；可量化最好）
5) 技术栈与设计体系：UI 框架/组件库/主题/设计稿来源（不清楚我先扫工程再问）
6) 交付形态：需求 SRS / 设计稿 / 原型 / 测试 / 交给 Trae 实现（默认：先需求后设计）
```

## 追问规则（最多再问 3 个，不要连环追问）

| 情况 | 只追问这一个 | 不要问 |
|---|---|---|
| 第 3 项只说「有文档」 | 「文档路径 + 最后更新日期？哪份是权威？」 | 文档里每一条细节 |
| 第 4 项只说「做好用」 | 「谁来验收、用什么证据判定？给一个反例」 | 具体 UI 像素 |
| 第 5 项不清楚 | 「我先扫工程（product-context.ps1）再给你确认，行吗？」 | 让用户背 dependency 列表 |
| 第 6 项要「都要」 | 「第一步先做哪个？其余排到后续」 | 一次全做 |

## 默认值与降级（不问也先这么办）

| 项 | 默认 | 降级 |
|---|---|---|
| 行业 | 其他（不加载 `energy-pm-framework`） | 用户提到燃气/电网/碳/VPP/电价/标书 → 自动加载 |
| 真相源缺失 | 标 GAP-ID，逻辑可测、数据未实测 | 禁止用 mock/旧文档数值反推口径 |
| 技术栈不清 | 先 `scripts/product-context.ps1 -Project <仓库>` 扫 | 扫不到 → 让用户给 `package.json` 或截图 |
| 交付形态 | 需求 SRS → 设计 → 测试 →（UI 时）Trae 交接 | 小改直接做，不组队 |
| 验收口径 | 先给「可判定草稿」让用户改 | 用户不答 → D-ID 挂起，不宣称完成 |

## 答完后的产物（必须落盘）

1. `docs/_context/project-profile.md`（或任务目录）——六问答案 + 真相源可用性 + 专家编排 + D-ID；
2. 若设计相关：`design-context.md`（`55-design-intake.md`）；
3. 若测试相关：`business-rules.md` 初版（R-ID + 来源 + 置信度）。

## 反模式

- ❌ 把 6 问拆成 6 轮对话（用户烦、上下文碎）；
- ❌ 用户没答就「按经验假设」业务口径；
- ❌ 专家一次全上（Designer+Reviewer+QA+评审员）—— 按最小必要派；
- ❌ 跳过行业判断直接套模板（能源类必须先叠加 `energy-pm-framework`）。
