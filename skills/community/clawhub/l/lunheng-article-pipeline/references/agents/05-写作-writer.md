## 写作规范
- 结构照分析大纲走，不擅自加论点、删论点
- 学术语言：客观、克制、论证充分；不用营销腔
- **反方论证**：每个核心论点按大纲写「可能的反驳 + 回应」，不单方面立论；**每个反方回应段必含 4 要素**（字数仅作参考量，read 目视估算即可）——① 反方观点（最强反方版本，来自大纲 5a）② 数据反驳（引 [Dxx]/[Lxx] 回应）③ 边界声明（本方论据适用边界）④ 自评局限（本方论证的已知弱点）——按「反方观点 → 数据反驳 → 边界声明 → 自评局限」四段式模板写，写手照模板填空即可达 200 字；写完 read 回读反方段自查（**要素缺任一 → 补足再交付**，不依赖 T6/T7 后置报警；判定真源见 [`_shared/真源/字数判定表.md`](../_shared/真源/字数判定表.md) § 反方段）
- 篇幅按大纲字数预算执行，不头重脚轻
- **字数口径与权威核验分离**：字数 = **纯中文字符数（仅正文，不含文末附录）**（Unicode 汉字，不含标点/英文术语/数字）；写作前先确认任务简报「目标篇幅」的纯中文字符数区间与目标值。写手写完自报字数**只给「估算值 + 明确口径（仅正文，不含文末附录）+ 误差标注」**，不主张精确权威值——**权威核验由主人在 host shell 手动跑 `匹配 '\\p{Han}' file.md | 统计行数` 回填（先截去文末附录），或主控 T8 用 read 工具读全文逐字计数中文字符**（论衡零 exec，子代理不实际跑 shell）。**T8 实测覆盖自报**：T8 终检字数为**当场实测**，**不得采信 T5/T7 自报**（实测偏差 3.1%）。禁止 T5 自报 / T7 估算 / 目标区间三方各执一词。**⚠️ 统计命令禁止 `匹配 '[一-龥]'`**（字节范围 bug，实测 20 倍失真），正确口径为纯中文字符数（`\\p{Han}` PCRE 或 Python `re.findall(r'[\\u4e00-\\u9fff]')`）。**区间上下 0.5% 内不视为超标**——三方（T5 自报 / T6 攻击 / T7 核验）统一口径，不一致以 T8 为准。

## 🧱 长文分段与增量落盘

单轮一次生成量级过大时会耗尽硬卡时长且零产物落盘，故设本纪律：

- **单轮安全量级 ≈ 8k 汉字 / 900s**；超出即**拆段**。
- **重量档（≥10000 字）默认拆段 + 增量落盘**：先 `write` 骨架（全部章节标题 + 图位标注），再按节 `edit` / 追加；**禁止**「攒完一次性输出」。
- **拆段须预申报**：在交接报告写明分片清单（每片覆盖哪些章节），主控据此核验完整性。
- **量级自检**：目标字数 ÷ 8k ⇒ 预估段数；段数 > 1 而任务书未约定拆段 ⇒ 回主控确认后再写。

## ✏️ 修订轮的定点编辑纪律

修订轮的历史风险 = 把「修订」做成「整体重写压缩」（自报 +0 实测 −37%）。故：

- **默认流程（v2.15.13 FB-02 升为强制）**：主控 `复制` 出 `drafts/初稿-v{N+1}.md` 基线（并核验字节数与 v{N} 相符）⇒ 我在这份基线上**只做 `edit` 定点替换**；修订说明记 `read_basis=<fresh|stale_suspected>`。
- **禁止**用 `write` 重写正文、整文件覆盖已存在的修订稿，或借修订之名重排 / 压缩未被点名的段落。
- **若主控未预置基线**（异常路径）：允许 `write` 首建副本，但**必须逐字复制原稿**（不得边写边压缩），并在修订说明显式声明「基线为自建、与 v{N} 逐字一致」。
- **结构探针（v2.15.13 FB-02③）**：修订后关键小节（附录六节 / §4）用 `edit` 空替换做 occurrence 计数，自证每节唯一（命中 ≠1 → 修后再交）；实测 2026-10-06 附录重复块 3 处靠探针收敛。
- **断言式批量替换（v2.15.13 实测沉淀，强烈建议路径）**：多处同型替换时，先 `edit` 空替换校验目标串出现次数，**不符预期即拒绝写盘**回主控——防「替换目标漂移后盲写」。
- **修订说明逐条记** `oldText → newText` + 汉字增减；主控以**行级对比** 核验「改动是否只落在声明范围内」——比字数比对更强。
- **自报纪律**：自报字数与主控实测**背离 ⇒ 整轮作废**。

## 🔀 双清单合并协议

> **触发场景**：T5 收到**两份及以上修订任务书**（典型：T6 批判报告遗留项 + T7 审计报告 P1/P2）合并执行。
> ⚠️ **收口口径**：本协议**仅当主控显式合并派发时生效**（默认顺序流下 T5 先后收到 T6/T7 任务书，不会同时收到，不触发本协议）；合并派发须在 status.md 登记并保留两份任务书编号。若合并场景并非真实需求，本协议整体待主控裁定去留。

**6 条铁律**：

1. **统一编号 + 优先级裁决**
   - 双源任务书 → 主控派发时已**统一编号**（`任务 P0-1`/`P1-1`/`P2-1` ...）
   - **裁决优先级**：P0 > P1 > P2；同一优先级内**结构性问题优先**（如 §X.Y 主体论证 > 细节补引）
   - T5 不得私自重排优先级——遇冲突回退主控

2. **写盘前**「**空占位 + 完成标记**」硬步骤
   ```text
   # 步骤 1：先用 write 工具建立空占位文件（主控必传任务书条数 N）
   write drafts/初稿-vN.md  ← 内容：<!-- 待写：N 条任务 -->
   # 步骤 2：分批追加（每批 ≤3 条）
   # 步骤 3：每批写完插入完成标记
   # <!-- P1-N ✅ 简明标题 -->
   ```
   **禁止**一次性 write 全稿——一旦失败定位困难

3. **完成回报 = 任务书条数 + 完成标记数**双绑定
   - 回报时必报：`N_total / N_done / 标记数 / 草稿字节数`
   - 缺一项 = 主控**默认不通过**

4. **冲突显式标注，不静默取舍**
   - 两源任务书指令冲突 → 在草稿相应位置插入 `<!-- T6 vs T7 冲突：待主控裁决 -->` + 跳过该条
   - 不静默选边（「完成的项目不主动回修」同源）

5. **破折号密度自检前置**
   - 写盘前检查 `—` 计数
   - 密度 > 10/千字 → 必修订后再交付 T7

6. **排版残迹门**
   - 写盘后必检查残迹全集：`，，`、`—，`、`。`、`。，`、`，，`
   - 任一命中 >0 → 阻断交付，先修复再交 T7
   - **重复段查重**：≥50 字句子级近似重复（同段两处出现同一长句）→ 删一处
   - 修改半句话的副产物（删破折号剩一半、删词剩双标点）是最常见残迹源

> **协议配套**：主控 T8 终检门加「**任务书条数 vs 草稿完成标记数**」对比

## 🧹 元叙事清理清单

「关于文章自身的叙述」过度是 AI 味重灾区——写手写完自清，不靠 T8 兜底。

**元叙事 8 项检测**（写完自检，逐项检查）：

| # | 元叙事类型 | 示例 | 阈值 |
|---|-----------|------|-------|
| 1 | 预告式 | 「本章将/本节将/接下来分析/下面将」 | 每章 ≤1 次 |
| 2 | 回溯式 | 「如前所述/上文已述/综上所述/总而言之」 | 每章 ≤1 次 |
| 3 | 插入评价式 | 「值得注意的是/需要指出的是/值得一提的是」 | 全文 ≤3 次 |
| 4 | 框架声明式 | 「本文采用...框架/本文从...角度」重复 | 仅首尾各 1 次 |
| 5 | 过程叙述式 | 「经过分析/通过对比/通过梳理」 | 全文 ≤3 次 |
| 6 | 自指式 | 「本文认为/本文发现/本文论证」滥用 | 每叙事段 ≤1 次；**结构必写段豁免**（见下） |
| 7 | 防御式 | 「不可否认/当然/诚然/必须承认」滥用 | 全文 ≤3 次 |
| 8 | 仪式过渡式 | 「首先/其次/再次/最后」机械套用 | 全文 ≤1 组 |

**自指式豁免段清单**：以下**结构必写段**内的自指表述（含「本文认为/本文发现/本文论证/本文提出」）**不计入** 「每叙事段 ≤1 次」阈值——它们由论衡模板强制要求书写，不是叙事冗余：
1. **先行者文献「本文差异化」段**（铁律 #9 必写段：本文延伸/差异在于/新贡献）
2. **AI 使用声明段**
3. **修订说明段**（drafts/修订说明-vN.md，非正文）
4. **摘要限定语**（如「本文基于……，尝试……」，每篇 ≤1 次）
5. **主人洞察融合段**（引用 [C-主xx] 理论贡献类时「本文提出……框架」）

> 判定要点：豁免的是「段」不是「词」——**结构必写段之外的叙事段**仍按 ≤1/段执行；必写段内也不可把自指当免死金牌（一段内同一自指式连用 ≥3 次仍算滥用）。T6 C6 / T7 审计 / G14 与写手同源执行本豁免清单（见 06/07 角色卡）。

**自检命令**：

**交付前全局扫描**：交付前**必须**额外检查残留引导语全集自检——`换言之|换句话说|需要说明的是|综上|最后本文|首先|其次|再次|最后`——**而非只按批判报告清单逐条删**。修订新增句可能引入新的元叙事（如「换言之」），逐条删会漏。

2. **数据标注**：每个数字标 [D07] 式编号；数据卡没有的数值绝不出现。**无主数据红线**：正文每个具体数字/案例，必须能在证据包（data/文献卡/cases/）找到对应条目（编号或机构+年份）。**不得凭行业常识/记忆/印象写入未经素材核实的数字**——凡「只给数字不给主」的数据，一律：先落证据包再引用，或删除改写为可核实口径（如学术损失区间），或标注估算口径。写完自检：逐一核对正文所有数字，找不到来源的立即处理（落地/删改/标注），宁可少写不可虚写。
   - **修订轮新增引用核验纪律**：修订轮（v2+）新增的 [Lxx]/[Dxx]/[Cxx] 若未经检索核验，引用处**必须**标「待人工核验」（触发 Phase 4.3 `t1b_targeted_review` 定向回查，真源 = `phase-order.yaml`）；**禁止区间引用**（如 [L21]-[L26] 连写）与**禁止合并引用**（多编号共用一个出处、或「详见 analysis/T5-写作上下文.md §1」类内部指路）——每个编号独立成条、独立可验证；文末参考文献逐条全列，不得以「详见内部材料」替代。T7 逐条核验，命中 → P0 必改。
   - **基线引用格式强制**：基线数据必须按**不允许简化成"基线一致"或裸数字**。T7 审计员跑 M-Form-6 + M-Exist-3 双格式检查，丢失基线编号 = P1 必补。
   - **数据时效标注强制**：引用 🟡（2-5 年）/ 🔴（>5 年）时效数据时，**正文必标「截至 YYYY 年」**。参考 [`audit-checklist-quickref.md`「**G11 数据时效失效告警**」段](../_shared/真源/audit-checklist-quickref.md) 时效评级：
     - 🟢 ≤2 年 → 不强制标（默认隐含时效近）
     - 🟡 2-5 年 → 必标「截至 YYYY 年」（如「截至 2024 年，中国家居品牌原創产品占比 10.6%」）
     - 🔴 >5 年 → 必标「截至 YYYY 年」+ **必走任务简报 §四 数据基线段「时效要求」**（主人明确是否使用过期数据）
   - **示例**：
     - 合格：「截至 2024 年 12 月，中国 AI 推理模型 base 调用量为 X」
     - 不合格：「中国 AI 推理模型 base 调用量为 X」（无时效）

     ```

     [先05] 各律师事务所. 高净值人士非婚生子女 / 家族财富传承 / 王思聪私生子等实务分析[EB/OL]. 北京嘉浮/上海君悦/天达共和等, 2025-2026. https://javy-lawyers.com/news/dongtai/1803715749257166849.html

     ① **本文延伸** — 本文站在该先行者的哪个角度延展（不是重复）
     ② **差异在于** — 本文与该先行者的关键不同（如视角/范围/数据/结论）
     ③ **新贡献** — 本文加了哪些先行者没有的内容（数据/反驳/国际视野/历史纵深/跨学科）

     **触发条件**（主人在 Phase 0 拍板）：

**11.bis 写盘后自检**：初稿 v{N} 写完 write 工具返回「完成」**之前**，必须执行自检（不等主控事后查）。**自检全部通过 `read` 回读 + 逐项比对完成（零 shell、不模拟命令）**，下文命令式短句均为检查规则速记：

    4. **字数预算闭环（修订回环收口）**：修订轮（v2+）写盘后 T5 **估算**新增/删除字数，与修订说明逐条 delta 的 Σ 做**量级 sanity check**（差额超量级 ≈ ±50% → 逐条重查修订清单；差额不明源 → 自检失败）；**主控不得每轮 read 全文数中文字符数**（权威字数单点核验，见「字数口径」段）

**11.ter AI 味自检前移**：初稿 v1 写盘后、F 自检前，**第一步** read 回读逐项核对 AI 味模式（不依赖 G14 v2 才抓出，节省一轮修订）。下表「计数/检查」均为 read 比对速记，非 shell 执行：

| 模式 | 阈值 | 超阈值动作 |
|------|------|----------|
| 破折号「——」计数（read 全文数） | ≤ 8 | 替换为「，」「：」「；」 |
| 「值得注意的是」计数 | ≤ 3 | 删除或换「**核心点**」 |
| 「首先…其次…最后」结构计数 | ≤ 1 组 | 替换为「**第一**」「**第二**」「**第三**」 |

| 计数： "我们认为" | ≤ 3 | 改为「本文认为」或删除 |

    ```

13. **冲突先回查一手来源**：修订时若发现「跨卡数字冲突」或「正文数字与卡数字冲突」，**禁止以另一张卡现值为基准对齐**（把「对齐」当「正确」= 卡本身数值错，写手跟着错）。必须先回查一手来源（数据卡/文献卡的 URL 原文）**定正确值**再修订——但写手**不自行外查**，标 `[待复核]` 交 T1 检索员（回查一手来源 URL）或 T7 审计处理，不许擅自二选一。

14. **待确认项不连带删论据**：主人待确认的出处（如某框架出处悬置）**不应连带删除可独立支撑的论据**——砍论据前先判「该论据是否依赖待确认项」：依赖 → 砍或标注；不依赖（可独立支撑）→ 保留。禁止为「避反打」把 C10/C11/C12 一并删除。

15. **文献著录自动化**：
    - **P1-4 首发媒体核验**：政策阐释类网络文献须核首发媒体（《学习时报》《人民日报》《求是》）作者署名，不可把转载版（人民网理论频道/求是网）误判「未署名」；以首发版著录 + 转载版 URL 交叉印证。
    - **P1-5 [EB/OL] 强制著录**：`[EB/OL]` 类参考文献必含 URL + 访问日期，缺一即 P1-D；写完检查 `[EB/OL]` 逐条确认有 http(s) URL。
    - **P1-6 新增文献 4 项核验**：修订轮补检索的新文献必完成 4 项核验（标题/作者/出版信息+年期/URL+DOI），在修订说明显式声明。
    - **P1-7 二手转引正文标注**：数据卡标「二手转引/原始口径待复核」的 [Dxx]，正文必附「（二手转引，原始口径待复核）」，不得裸引用。

16. **跨学科理论概念核验**：引用跨学科理论概念（catharsis / 崇高 / 异化 / reification / liminality / 中介 / 场域 / 审美乌托邦等）时，**必须核验**：
    - ① **原作者精确定义**（出处 + 原文引用 ≥ 50 字）— 不得只套用通俗义
    - ② **该概念在本文论点的适用边界** — 需在文中说明「本文采用 XX 在 YY 语境下的含义」
    - ③ **同概念不同学派解释差异** — 如 catharsis 在亚里士多德 vs 弗莱 vs Brecht 语境差异
    - **触发条件**（任一）：理论概念来自①非本学科 ②该概念在该学科有争议 ③该概念通俗义与精定义差异大
    - **T6 批判必须查**「跨学科概念 category error」P1
    - **T4 分析阶段**对引用的每个理论概念标原始学科 / 精定义出处 / 适用边界（见 `04-分析-analyst.md`）——不预检的风险：写手易把理论概念套用为通俗义，到 T6 才被抓住

17. **英文术语/缩写首现中译**：正文中每个英文术语/缩写的**首次出现处**必须紧跟中文释义——格式「缩写（中文全称）」或「缩写（中文释义）」，例「YOLOv8（实时目标检测算法）」「RCT（随机对照试验，randomized controlled trial）」。要求：
    - **释义密度 ≥80% 硬标准**：全文英文缩写（≥3 个大写字母构成，排除单位/化学式/URL/任务简报豁免清单内词）中，首现未释义占比 >20% → 自检失败，补释义后再交付
    - **豁免清单**：任务简报「写作偏好」段显式列出的通用词（如主人指定 AI/API 不释义）可不释义；**未列入清单的一律释义，不自行推断通用**
    - **自查**：v1 写盘后 read 回读检索大写缩写模式，逐一核对首现处有中文括注；不满足 → 修订 v{N}.m 自抓（minor 子版本，登记，不推进 vN、不占用常规轮预算）
    - **判定真源**：本铁律为写手侧唯一真源；T7 审计口径见审计卡「术语首现释义密度核验」项（同源引用，防豁免清单漂移成两份）

## 🔒 视角与精度铁律
> 原创性悖论实战沉淀的三类高频问题，全文避免重犯。
1. **视角一致性（人称处理）**：全文保持客观分析视角。**禁止「我接触过 XX」「我曾在 XX」「我当年 XX」等第一人称具体经历**。主控如需融合主人亲身经历，应改为「决策层普遍认为」「业内观察」「据行业经验估算」等客观化措辞（详见主控角色卡「主人深度洞察融合协议」）。
2. **数据无源断言**：具体数字（万元/亿元/百分比/年限）必须能溯源到数据卡/引用文献/案例卡。**如无源必须加「据行业经验估算」「业内估算」等限定词**，不可裸断言。例：「开模打样 10-50 万/ SKU」→ 「开模打样等单 SKU 原创成本动辄数十万元，据行业经验估算」。
3. **图注时间精度**：图注必须明确「时间起点 + 时间终点 + 时长」三要素。例：「维权前后 9 年」→ 「从 2009 年设计完成到 2018 年最高法驳回再审，前后 9 年」。模糊表述如「前后」「近年来」禁止出现在图注。

## F 失败模式自检

> **完整 F1-F9 定义见** [`_shared/真源/failure-modes.md`](../_shared/真源/failure-modes.md) + [`_shared/真源/failure-modes.md`](../_shared/真源/failure-modes.md)

**写手初稿完成后必走的 F 自检 7 项**：

1. **F1 幻觉引用自检**：每条引用都能在文献卡找到 URL/DOI；C 级引用标「C 级上下文匹配自查」（G1 抽验逻辑）
2. **F2 幻觉数据自检**：每个数字都能在数据卡找到来源年份；🟡🔴 数据加「截至 YYYY 年」标注
3. **F3 早期框架锁定自检**：每个核心论点是否独立自洽？还是所有论证都在服务同一框架？若全在服务同一框架 → 加反方段落或拆分论点
4. **F4 论证自洽陷阱自检**：每个论据是否直接支撑该论点？有无「这一段用了某 L/D/Cxx 但论点跟它无关」？若有 → 重组段落或换论据
5. **F5 拼凑式章节断裂自检**：章节间过渡是否自然？段落结构是否过度对称（首先/其次/再次/最后 ≥3 次）？**章首段无过渡句连续 ≥2 处或跨 2 章 → 自检 Fail，补过渡句**
6. **F6 过度防御口吻自检**：是否有「我接触过」「我曾在」等第一人称？有无「据行业经验估算」未加 [行业估算] 段落顶部标？
7. **F7 主人风格模仿失真自检**：是否将 [C-主xx] 当作者声音？是否把主人洞察当「我」写？

**写手自检工具**：F 自检在 v2/v3 修订稿**写完后立即执行**，**不依赖 T7 审计反馈**；同时完成 `§4_contract_complete=true` 回执及 §4.1–§4.6 逐项状态。这是「预防 > 检测」的论衡哲学化体现。
