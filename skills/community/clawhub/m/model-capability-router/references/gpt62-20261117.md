## Price comparison and effort

Standard API USD per million tokens, up to 272K input tokens; cache here means
cache reads, not writes. Sources: [old Astra](https://developers.openai.com/api/docs/models/gpt-6-astra),
[new Astra](https://developers.openai.com/api/docs/models/gpt-6.2-astra),
[old Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol),
[new Sol](https://developers.openai.com/api/docs/models/gpt-6.2-sol).

| Model | Input | Cache read | Output including reasoning |
|---|---:|---:|---:|
| Astra 6 | $10 | $1 | $50 |
| Astra 6.2 | $8 | $0.40 | $40 |
| Sol 6.1 | $2 | $0.10 | $10 |
| Sol 6.2 | $2 | $0.10 | $10 |

Astra: 20% cheaper input/output and 60% cheaper cache reads; Sol unchanged.
The new Astra rates are four times Sol's in each column. This is a per-token
ratio, not a task-cost ratio or subscription allowance multiplier.

[Reasoning billing](https://developers.openai.com/api/docs/guides/reasoning):
effort does not have its own token tariff. Reasoning tokens are charged as
output; higher effort can consume more tokens, but better reasoning may reduce
failed steps and rework. Compare complete successful tasks, including all
calls, cache, retries, visible output and reasoning. Omitted effort uses the
route's default; it is not a zero-reasoning or free setting. Both 6.2 APIs
reject explicit `none`; OpenClaw controls must be mapped through its provider.

Illustration, not benchmark: 100K uncached input plus 10K total output costs
$1.50 on old Astra, $1.20 on new Astra and $0.30 on either Sol. Reusing the
same 100K as a cache hit gives $0.60, $0.44 and $0.11 respectively. Tool fees,
cache writes and higher-priced processing tiers are excluded. With output
dominating, new Astra can generate 25% more tokens before losing its 20%
price advantage over old Astra; that does not prove high beats medium.

Subscription routes draw on provider allowance rather than necessarily
charging these API dollars. Use API figures for economic context, not to
claim how Plus/Pro/Max allowance changes. No paid experiment is authorized
or necessary to record this comparison.

### Adopted general-edition roles

Use Sol 6.2 medium for everyday defined work, high for sustained coordination
and complex coding. Use Astra 6.2 medium for difficult judgment and demanding
professional deliverables. Include Fable 5.2 medium for technical analysis and
expert consultation, high for ambiguous or substantial technical execution;
xhigh/max require a workload that warrants them. High's published coding
result supports that choice, not a claim that it always beats medium.

Keep Opus/Sonnet/Haiku and the existing Gemini/Composer/Grok roles available;
choose based on the task, useful context, supported tools and account allowance.
No model handoff is mandatory, and a missing Fable route must not silently
activate direct API billing. Fable's safeguards may invoke another model on
some requests: report actual identity when exposed rather than presenting a
fallback as Fable. Mythos remains a separate access decision.
