# 方法与体验示例

人可以用自己的话托付，也可以选择方向、点名或组合方法，或者让 AI 带着自己学。AI 按当前对象选择有价值的用法。用户点名完整路线时按该方法本来的意思工作，说明为了当前对象做了什么调整。

这里是能力资源总索引。需要一个具体认知动作时进入[方法索引](methods/INDEX.md)；现象像反复出现的因果结构时进入[系统模式库](patterns/README.md)；用户点名成熟思路或需要一条完整实践脉络时进入[路线索引](routes/INDEX.md)。资源增强现场判断，不替运行时决定全局顺序。

| 方法 | 何时值得用 |
| --- | --- |
| **透视、回路、尺度** | 当现象来自看不见的资源流、延迟、相互作用或上下层关系时，用一次可核对的观察把关键结构讲清。 |
| **第一性原理、反过来想** | 当争论建立在沿用的假设上，拆开真正条件、惯例与可改变规则。也可从失败条件反推应当观察什么。 |
| **杠杆、瓶颈、权衡** | 当局部指标容易把问题挪给别人时，比较对整体的影响、代价、可逆性和可选空间。 |
| **情景推演** | 当不确定性会改变决定时，保留几个有依据的解释或可能世界，比较什么信号能区分它们。 |
| **搭建能力、复盘** | 将重复有用的做法变成真实工作中的能力，用已经观察的结果决定继续、修改或结束。 |

常见完整路线也可被点名或结合使用。这里的说明是选择与交互提示，实际使用时把判断落到对象和证据上。

- **马斯克五步法。** 质疑要求，删除能删的部分，简化，缩短周期，最后考虑自动化。
- **丰田式改善。** 去现场观察，追查原因，验证对策，保留有效做法，再寻找下一轮改善。
- **高德拉特五步聚焦。** 识别整体约束，充分利用，让其他环节配合，必要时提升，再检查约束是否移动。
- **芒格的多模型检查。** 从失败、激励、不同学科和后续后果分别检查同一个决定。
- **费曼技巧。** 用自己的话讲清楚，发现哪里讲不通，回到材料，再用可核对的语言解释。
- **戴明的 PDSA。** 计划时写下预期，执行，拿结果和预期对照，再决定采纳、调整还是结束。
- **博伊德循环。** 看见情况，调整对情势的理解，作出选择，以结果重新校正。
- **情景规划。** 选出影响决定的关键不确定性，构造可信的不同情景并找到能提前区分它们的迹象。

## 用户想试一试或学一种方法时

可以直接用其关心的对象，也可以从一个自足的小例子开始。让用户先提出猜想，给他可操作的比较，最后看能否用新认识解释另一个情形。用户可以选一种方式深入，也可以随时回到自己的问题。

例如「公交车为什么扎堆」。先让人猜晚到的前车和正常的后车，哪一辆会接到更多等待乘客。再比较两辆车的停站时间，观察差距怎样改变。若换成部分班次大量上下客的车站，了解原来的解释还剩多少解释力。这个例子可以做成图、短文字或可操作模拟，形式由现场条件决定。

想进一步判断一个系统的作用，可以结合[系统科学与判断](../core/system-science.md)选出值得验证的机制。
