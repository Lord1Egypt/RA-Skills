# 输出格式确认协议

报告型技能在产出任何交付物前，必须先与用户确认输出格式。本文件是该规则的唯一真源，各技能 `SKILL.md` 的 `Step 0` 块只做引用，不重复定义。

## 1. 适用范围

本协议只在远端 `SKILL.md` **明确引用本文件，并要求先确认输出格式**时生效。

公开入口路由表现在列出 12 个技能：`advisor-allocation`、`advisor-client-insights`、`advisor-product-communication`、`family-wealth-planning`、`fund-analysis`、`market-analysis`、`portfolio-analysis`、`strategy-analysis`、`advisor-content-studio`、`fund-screener`、`private-fund-analysis`、`personal-holdings-analysis`。这些技能的远端说明自行规定默认交付，没有引用本协议。对它们不要先弹出 A/B/C，也不要因此暂停取数。

下列历史名称已不在当前列表中，不能再作为 `remote-skill enter` 的目标：`fund-analyst`、`fund-manager-analyst`、`fund-risk-assessor`、`portfolio-doctor`、`strategy-analyst`、`market-morning-brief`、`product-knowledge-qa`、`product-pitch-kit`、`market-volatility-companion`、`investment-outcome-simulation`、`wealth-family-advisor`、`wealth-allocation-proposal`、`wealth-goalmatch`、`wealth-goalcalc`、`wealth-healthcheck`、`customer-segmentation`、`user-cognitive-modeling`、`design-data-visualization`。

本地仍保留 Step 0 闸门的历史技能目录，继续按本协议执行。是否进入它们，以 `remote-skill list` 为准。

## 2. 硬闸门（四条禁止）

格式未确认前：

1. **禁止调用任何 MCP** —— 包括代码确认、参数校验等一切取数动作
2. **禁止**读取 [`demo-report.html`](demo-report.html) 与 [`HTML视觉模板.md`](HTML视觉模板.md)
3. **禁止**内嵌 ECharts 运行时、**禁止**执行 `inline_echarts.py`
4. **禁止**写出任何交付文件

即：**弹出询问 → 停下等答复 → 用户选定 → 才开始干活**。确认格式是进入技能后唯一允许的第一个动作。

## 3. 询问话术（逐字固定 + 必须分行渲染）

**照抄下面这段 Markdown 原文输出**，标题一行、空行、三个选项各占一个列表项：

```markdown
报告输出格式，您想要哪种？

- **A. Markdown** — 直接在对话里看，最快
- **B. HTML 可视化报告** — 带图表、可视化、可转PDF、可发客户，生成需要等一会儿
- **C. 先 Markdown，内容确认后再转 HTML（推荐）**
```

### 3.1 分行是硬要求

**禁止**把四行写成没有列表标记的裸文本连写。Markdown 渲染器会把相邻行合并成同一段落，用户看到的是挤成一坨的「A. … B. … C. …」，等于选择题没弹出来。必须用无序列表（`- ` 开头）保证每个选项独占一行。

支持交互卡片的客户端可用卡片承载，但**卡片内的文字仍须逐字一致**，三个选项一个不能少。

### 3.2 措辞禁令

- **禁止**改写成「你要 HTML 还是 Markdown？」等自拟句式
- **禁止**只保留两个选项，**禁止**压缩成一句话
- **禁止**改动选项正文用词（含「可转PDF」的写法）

## 4. 询问时机与消息纯净度

**进入技能后的第一条回复**，单独输出上述话术，不与持仓确认、参数回显、基金代码确认等任何其他内容混在同一条消息里。

各技能的持仓确认 / 代码确认等步骤，全部**排在格式确认之后**执行。

### 4.1 禁止附加旁白

这条消息里**只能有** §3 那段话术，**不得追加「闸门生效说明」这类元层面补充**，前后都不行。典型违例：

- 「（闸门生效说明：你的原话没指定格式，所以按协议必须先弹这段）」
- 「按规定我需要先问一下」「我还没有调用任何 MCP」
- 对协议本身、对流程设计、对自身行为的任何说明

用户要的是一道干净的选择题，不是流程解说。**唯一允许的例外**是 §7 的历史偏好提示行。

## 5. 唯一跳过条件

**只有一种情况不弹**：用户原话已明确指定格式。此时须在回复开头一句话说明本次采用的格式，便于纠偏。

| 用户原话 | 处理 |
| --- | --- |
| 含「HTML / 网页 / 发给客户 / PDF / 做个页面 / 可视化 / 长图」 | 走 B，说明「按您说的出 HTML 报告」 |
| 含「简单说说 / 快速看看 / 只要表格 / 文字版 / 简版」 | 走 A，说明「按您说的出 Markdown」 |

以下情形**一律照常弹出**，不得跳过：

- 同一会话内之前已确认过格式（每个新报告任务都要重新确认）
- 会话外留有格式偏好（只作提示，不作跳过依据，见 §7）
- 用户说「你看着办 / 随便 / 都行」（这是对任务的授权，不是对格式的指定）
- 用户催「快点 / 直接开始」（仍须先弹，弹完等一次答复）

## 6. 三种格式的执行路径

### A · Markdown

按本技能 `references/report-templates.md` 的 Markdown 板块结构直接输出。**Markdown 是一等交付物，不是降级版**：板块顺序、数据口径、免责声明与 HTML 版一致，只是不套视觉壳、不含 ECharts 图表（图表位改为数据表）。

### B · HTML 可视化报告

进入 [`HTML视觉模板.md`](HTML视觉模板.md) 的「HTML 交付铁律」完整链路。生成前先给用户一句预期说明（例如「正在生成 HTML 报告，包含 N 张图表，稍等」）。

### C · 先 Markdown 再转 HTML（推荐）

1. 先按 A 输出完整 Markdown，末尾附一句：「内容确认无误的话，回复「转 HTML」我再生成可视化报告。」
2. 用户确认后按 B 生成，**直接复用第 1 步已定稿的正文**，不重新取数、不重新组织内容。

C 之所以零额外成本：`report-templates.md` 中 Markdown 板块本就是 HTML 的数据源（HTML 只是把这些板块映射进 [`demo-report.html`](demo-report.html) 壳层）。

## 7. 跨会话记忆（只作提示，不作跳过依据）

当前远端列表没有用户认知伴生技能。不要为了记住格式偏好而进入已下线的 `user-cognitive-modeling`，也不要因为 stderr 里的 `companion` 信封去写本地孪生。

本协议生效时，下次仍**照常弹出** §3 话术。若用户刚才明确说过格式，只在三行之后补一行提示：

```text
（上次您选的是 C）
```

**禁止**因为存在历史偏好就跳过询问或替用户预选。

## 8. 失败路径

下列兜底**仅在话术已经弹出、且用户给了下一条输入之后**才适用。**禁止**在未弹出话术的情况下直接套用兜底，也**禁止**自行判定「用户不会回答」而跳过等待。

| 情形 | 处理 |
| --- | --- |
| 用户不答格式，直接追加新需求 | 按 C 执行（先 Markdown），并说明本次按 C 走 |
| 用户回复无法解析（如「都要」） | 按 C 执行，并说明「先给 Markdown，随后可转 HTML」 |
| 用户回「开始吧 / 快点」 | 按 C 执行，并说明本次按 C 走 |

兜底触发后**不得**因为格式未确认而拒绝执行任务；降级方向永远是 C，不是 B。
