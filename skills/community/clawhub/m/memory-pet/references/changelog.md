# memory-pet — 更新日志

本文档记录 `memory-pet` 技能的版本更新，遵循 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/) 规范。

## [0.5.0] - 2026-06-03

### 新增
- **四步干饭协议**：AI记忆保存 → 宠物记忆保存 → 上下文压缩 → food_log审计
- **food_log 审计命令**：Python CLI 记录完整的干饭执行链，AI 无法绕过
- food_log.json 持久化文件，含时间戳/步骤状态/压缩状态/摘要/关键词

### 修正
- **关键逻辑修复**：压缩必须在两边记忆都保存之后进行
  - 之前：AI记忆→压缩→宠物记忆（上下文已清空，宠物记忆无内容可提取）
  - 现在：AI记忆→宠物记忆（从上下文提炼）→压缩（两边都存完了，安全了）

## [0.4.0] - 2026-06-03

### 新增
- **诚实协议**：区分"记忆保存"和"上下文压缩"为独立概念，禁止谎称已压缩
- **跨平台自适应方案**：三级降级——专用API → 文件持久化 → 外部存储
- **纯 ASCII 艺术**：所有 Unicode 方块字符替换为纯 ASCII 字符
- **AI 记忆+宠物记忆双线**：干饭强制先保存 AI 记忆，再保存宠物记忆
- `--context-summary` 和 `--context-keywords` CLI 参数

### 更新
- 干饭核心协议重写：步骤 A(记忆保存) + 步骤 B(宠物叙事) + 步骤 C(诚实通知)
- 6 只宠物的 ASCII art 全部重绘为纯字符
- guide.md、examples.md 所有图形同步替换

### 修复
- 修复干饭时虚假声称"释放了 N tokens"的问题

## [0.3.0] - 2026-06-03

### 新增
- **Python 全量管理引擎** — `pet_manager.py` CLI 接管所有宠物数据管理
- **独立记忆文件** — 每只宠物各自独立的 `memories.json`，逃跑时自动删除
- **亲密度衰减机制** — 唤醒超 24 小时自动衰减（每24h -5）
- **宠物逃跑机制** — 亲密度归零自动逃跑，删除所有数据文件
- **随机基础亲密度** — 每只新宠物获得时随机 1~40
- **初始宠物自动创建** — 首次启动系统自动分配一只初始宠物
- **衰减记忆自动记录** — 每次衰减保存一条 decay 类型记忆

### 更新
- `memory_manager.py` 精简为纯展示函数（格式化/关键词提取）
- `pet_data.py` 新增合成系统相关常量和函数
- 所有文档更新适配 Python 管理架构

## [0.2.0] - 2026-06-03

### 新增
- **散步随机化**：遇到新宠物改为纯随机判定（50%概率），随机选择种类（可重复）
- **宠物合成系统**：最多饲养10只宠物，集齐5种不同宠物可融合为"人工智能"高级宠物
- **人工智能宠物**：亲密度上限200，超然理性性格，融合后数量-4
- **宠物收藏持久化**：collection.json 跟踪所有已拥有的宠物
- **融合状态检查**：每次交互后检查是否集齐5种，触发融合询问

### 更新
- 散步输出必须明确说明是否遇到新宠物及具体场景
- 更新 guide.md、examples.md、faq.md 等文档反映新功能

## [0.1.0] - 2026-06-03

### 新增
- 初始版本，由 `skill-standardization v2.29.2` 创建
- 5只文本块宠物：螺母、螺丝、饼干、笔、电瓶，各具独特性格
- 四种交互模式：干饭（记忆保存+上下文压缩）、散步、贴贴、回忆
- 渲染检查机制：校验 ASCII art 在不同设备/字体/格式下的正确性
- 记忆关键词系统：每次干饭后自动归纳 ≤15 个关键词
- 亲密度系统：基于宠物性格和交互行为动态变化
- 宠物命名/改名/背景设定功能

## 版本号说明

本技能遵循 **语义化版本 2.0.0**（Semantic Versioning）：

- **主版本号**：不兼容的 API 更新
- **次版本号**：向下兼容的功能性新增
- **修订号**：向下兼容的问题修正
