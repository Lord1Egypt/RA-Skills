## 从 IP、URL、产品组成条件

日志检索与统计的 `--query` 是非空明文表达式，CLI 自行编码，不手动 Base64。初次使用不熟悉的字段或运算符时读取字段目录，已有本次有效目录就复用；不把同一检查重复加到每条查询。缺少权威角色编号时可用性未知，不按会员等级猜授权；未知也不是明确拒绝，已授权的具体公共查询由后台判定。

| 表达式写法 | 含义 |
|---|---|
| `'url=="https://example.invalid/api/auth/login"'` | `==` 匹配完整存储值。查路径片段用下一行的 `url="*片段*"`。 |
| `'url="*/api/auth/login*"'` | 查路径片段用这个。两侧加 `*` 才是包含。不带 `*` 的 `url="login"` 是分词，会命中无关路径。 |
| `'ip="203.0.113.10"'` | 查询指定 IP。不要加 `*`，`ip="*1.2.3.4*"` 会直接报格式错误。 |
| `'product="Crocus"'` | 按产品名称片段匹配。不要照 `url` 加 `*`，加了结果一样。 |
| `'product=="Crocus"'` | 按完整名称解析产品。同名仍可能对应多个 ID。 |
| `'(product="Crocus") && (ip="203.0.113.10")'` | 保留原产品范围再增加来源条件；括号保护原条件中的逻辑，不用新条件替换原条件。 |

字段与取值依后台实现。产品条件按名称解析为后台的产品集合，产品编号只从返回记录取得。要确认目录候选，读 [product.md](product.md)。目录候选和日志命中范围可能不同。只知道目录名称且要查日志时，先用上表的片段条件取少量样例，查看结果实际使用的 `product_name`。仅在需要收窄且已确认名称时才用完整匹配。完整匹配返回空时，说明该条件在当前窗口没有记录。只给产品 ID、品牌别名或 CVE 时，不擅自编造名称映射。不要把路径分布名称当成完整 URL，不凭猜测的产品名、类型编号或已打码值继续检索。仅当歧义会改变目标时澄清，不把已给出的 URL、IP 或产品名再问一遍。

## 日期与公共范围

- 日志检索、两种统计、IP 活动的 `--start/--end` 必须同时提供或同时省略；省略时默认当前日期前一个月至今天。
- 日期格式 `YYYY-MM-DD`；开始不晚于结束，日期差最多 365 天。默认窗口只是上限，按用户问题缩小范围，服务端还可能按账号进一步裁切。
- 以上查询及日志全文、解密、上下文仅支持 `--scope public`，其他范围直接拒绝，不回退、不绕到私有接口。字段目录、身份、IP基础信息没有 scope 参数。
- `requested_start/end` 是请求窗口，不等于后台实际允许范围。日志单条操作的 `--date` 使用各自定位契约，见日志文档。

## 分页与请求预算

日志检索与统计分布默认第 1 页、每页 20 条；每页允许 1–100，页码乘条数最多 10000。取样时显式用少量条数，不自动翻页；返回 `total` 较大不表示用户授权读取全部。去重对象计数、IP活动和相邻日志没有通用分页入口，不给它们拼分页参数。

## 自检

- [ ] 条件来自真实线索，日期与结果规模符合任务；数据范围未扩大。
- [ ] 对字段、类型或脱敏值的未知保持未知，没有猜测授权、补造 ID 或回填不可靠过滤条件。
