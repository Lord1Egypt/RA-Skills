# 全局宪法（laws.md）— ai-docgen 领域全局法则

本文件是 ai-docgen 领域的**全局宪法**：任何文档动笔前必读。初版从 8 个子领域（DT/AD/CC/AC/AW/AV/DG/DQ）的法则化萃取中收集全部 `[GLOBAL]` 候选（共 20 条），经查重合并形成 LAW-1~16；第 5 轮 doc-templates 扩展子域再贡献 4 条候选，1 条收录为 **LAW-17**、3 条未收录（见「未收录登记」）；第 6 轮 proj-docs 扩展子域贡献 4 条候选，2 条收录为 **LAW-18/LAW-19**、2 条未收录，现为 **LAW-1~19**。

## 宪法导读

**全局法则与子领域法则的关系：**

1. **分层治理**：全局法则回答"任何文档产出都不可违背什么"；子领域法则（DT/AD/CC/AC/AW/AV/DG/DQ-N）是全局法则在其领域的具体化与收紧。
2. **冲突裁决**：子领域细则与全局法则冲突时**细则优先**；全局法则兜底，覆盖未枚举场景；两者同时违反，以更严格者为准。
3. **引用规则**：正文用编号引用（`LAW-N` 全局 / `DT-N` 等子领域前缀）。
4. **因果链排序**：先事实纪律（AI 产出什么），再类型/结构/同步纪律（信息放哪、怎么保鲜），最后验证与治理纪律（怎么验、谁负责）。

**分组结构**：第一组 事实纪律（LAW-1~4）→ 第二组 类型与结构纪律（LAW-5~8、18）→ 第三组 同步纪律（LAW-9~10）→ 第四组 验证纪律（LAW-11~13、17）→ 第五组 治理纪律（LAW-14~16、19）。

## 第一组：事实纪律

> AI 生成文档的第一风险是编造——结构与事实分离，无源即降级。

[LAW-1] **NEVER**: 硬事实零编造。版本号、API 签名、参数名、默认值、错误码、移除版本、发布日期、issue/PR 号、贡献者、性能数字、badge/CI 状态、配置全表、交叉引用是事实数据，必须来自源码/类型/官方文档/项目记录；无源时只能产出「结构模板 + 待填标注」，不得以「同类典型形态」补全；补全欲（表格凑齐、FAQ 凑三、结构填满）视同编造。
  违反后果: 编造项与真实项输出形态相同，读者无法分流——照抄即崩溃、引用 404、事实记录被污染且后续基于它的自动化与信任坍塌。
  溯源: DT-12, AD-2, AC-11, CC-2 + [模型经验]

[LAW-2] **NEVER**: 理由零编造（结构与事实分离）。项目私有理由——决策 forces、why/动机、备选对比、后果、设计动机——无输入不生成；AI 的角色是结构师 + 提问者，不是决策代笔；无输入时只能产出模板 + 引导提问（「什么约束驱动这个决策？备选考虑过谁？」），不得用社区最优解释或同类项目惯例填补项目私有决策。
  违反后果: 合理想象进入仓库污染决策史——上下文、备选、决策全是虚构，后人以编造前提重构。
  溯源: AC-5, CC-2（理由部分）, DT-12（设计动机部分）, AD-2（典型形态补全部分） + [模型经验]

[LAW-3] **MUST**: AI 起草必须配输入契约。事实源（代码/类型/diff/既有文档）、类型与受众约束、风格样例齐备才可起草；无事实源、无约束、无样例的空手调用（「帮我写文档」）只能产出结构——正确响应是索取输入或降级为模板 + 提问。
  违反后果: 无输入契约迫使 AI「尽力完成」——看似完整实则虚构的文档幻觉直出。
  溯源: AW-3 + [模型经验]

[LAW-4] **MUST**: 生成内容以信息密度为质量判据。低信息密度的高完成感即 AI 腔；删除测试（删掉后信息量不变 = 删）；腔在骨架（结构对称/每节总结/均匀节奏）不止在词汇。
  违反后果: 文档「看起来完整」实则无信息，读者时间被浪费；只清理词汇层保留骨架则治理无效。
  溯源: DQ-8 + [模型经验]

## 第二组：类型与结构纪律

> 信息放什么类型、进哪一层载体、怎么披露——结构错误在动笔前已注定。

[LAW-5] **MUST**: 先判型，后写作。动笔前过官方判型四问（"Can you teach me to…?" / "How do I…?" / "What is…?" / "Why…?"），落到 tutorial / how-to / reference / explanation 之一；一份文档只服务一种类型；判不出型说明内容该拆分。
  违反后果: 类型失守向下游传染——写作全程无结构准绳，产出混写文档（blur），任何读者都需跳读大半。
  溯源: DT-1 + [官方文档](https://diataxis.fr/map/)（判型四问） + [模型经验]

[LAW-6] **MUST**: 信息进入能表达它的最高载体层。类型 > 命名 > 结构 > 注释 > 手写文档；能进类型系统的不写注释，能命名自明的不解释；注释/文档只写载体表达不了的（why > context > how > what），what 复读是噪音。
  违反后果: 信息双份存储——重构后注释/文档漂移，读者照过期文档写代码；what 噪音淹没高价值 why，读者对注释建立「可忽略」惯性。
  溯源: AD-1, CC-1 + [官方文档](https://google.github.io/styleguide/docguide/best_practices.html)（注释提供代码无法包含的信息，如 why） + [模型经验]

[LAW-7] **MUST**: 渐进披露三层。TL;DR ≤3 行 → 主体 → 深水区；每长页有第一层；先结论后论证（BLUF），无悬念结构；边缘情况独立小节不污染主流程；标题串能独立还原文档结构（标题测试）。
  违反后果: 无 TL;DR 的长页迫使读者通读全文才能定位，扫读者直接离开；悬念结构使读者无法中途着陆。
  溯源: DQ-3 + [模型经验]

[LAW-8] **MUST**: 图优于文须过四判据。空间关系 / 拓扑结构 / 时序交互 / 对比矩阵，不满足不画图；文本可 diff 图（Mermaid 类）优先于二进制图；图是事实的投影，架构变更必须触发图更新。
  违反后果: 不满足判据的图是纯维护负担；二进制图不进 diff，图腐烂比无图更糟（主动误导）。
  溯源: DQ-5 + [模型经验]

[LAW-18] **MUST**: 正常路径与异常路径并重。凡描述行为或交互的文档（流程/时序/接口契约/处置步骤/状态矩阵/验收场景），必须与正常路径同等力度地定义异常路径——失败去向、回退、兜底角色与权限时限、超时处理；判断分支穷尽（禁悬空分支）；时序图含失败/超时消息；NEVER 只写成功路径。
  违反后果: 异常发生时文档无据可依——兜底缺失放大线上事故（「联系管理员」不是人工介入方案）；文档只在 happy day 有效。
  溯源: 第 6 轮 proj-docs [GLOBAL] 候选 G1 升格；跨子域成立点：PJ-5 流程异常三件套 + PJ-6 状态矩阵三列必填 + PJ-9 错误码消费方动作 + PT-10 回滚预案 + PT-13 失败分叉出口 + AD-6 错误清单同文档化 + [模型经验]（「Happy path 偏置」——生成分布不自发覆盖异常路径）

## 第三组：同步纪律

> 文档腐烂是默认归宿——靠机制保鲜，不靠人的记性。

[LAW-9] **MUST**: SSOT——每个事实只有一个权威存放处。链接 > transclusion > 复制（复制必须配同步检查或显式标注复制日期）；事实刚性而表达自由（判据问句：改一处另一处必错吗）；生成物单向——改源再生成，不手改编译产物。
  违反后果: 事实多处手写→改一处漏两处，读者无法判断哪份是权威版；生成物手改→下次生成覆盖/冲突。
  溯源: DG-8 + [官方文档](https://google.github.io/styleguide/docguide/best_practices.html)（"Duplication is Evil"） + [官方文档](https://keepachangelog.com/en/1.1.0/)（GitHub Releases 双份漂移官方素材） + [模型经验]

[LAW-10] **MUST**: 文档同步靠结构触发，不靠记忆。代码变更必须结构性触发文档动作：接口变更 → reference + changelog；行为变更 → 受影响文档扫描（全站 grep 旧行为）；纯实现 → 无动作；PR 模板含文档影响 checkbox——「记得更新文档」不是机制。
  违反后果: 断链高频发生——行为变更无人扫描受影响文档、hotfix 跳过文档影响判断，文档持续腐烂且无人有责任。
  溯源: AW-1 + [官方文档](https://google.github.io/styleguide/docguide/best_practices.html)（"Update Docs with Code"） + [模型经验]

## 第四组：验证纪律

> 错误文档负价值大于缺失——验证先于放行，度量不被劫持，发现必须回流。

[LAW-11] **MUST**: 质量多维评估缺一不可，准确性优先。准确/完整/一致/时效/可发现/可读每维至少一句结论；优先级：准确 > 时效 > 完整 > 一致 > 可发现 > 可读（错误负价值 > 缺失 > 难读）。
  违反后果: 评审被可读性（最易评维度）劫持而漏准确性（最重要维度）——「错而美」的文档通过评审，误导读者。
  溯源: AV-1 + [模型经验]

[LAW-12] **MUST**: 度量必配对，warning 不做 KPI。量度量（覆盖率类）必配随机质量抽查（Goodhart 防御）；分母必须来自代码侧（类型导出）而非文档侧（幸存者偏差）；分级阈值：新增 blocking + 存量基线渐进。
  违反后果: 覆盖率 100% 全是垃圾凑数（Goodhart 全额发作）；从未被文档提及的公共 API 不在分子分母里。
  溯源: AV-5 + [模型经验]

[LAW-13] **MUST**: 验收是校准数据，发现必须回流。验收/审校不只是放行把关——发现按错误模式归类沉淀进生成规则（发现归类 → 规则更新 → 下批错误率下降）；「把这个文档改对」是一次性动作，「把生成器校准」是系统性改进；不回流的验收是纯成本。
  违反后果: 错一批修一批、生成规则不变——同类幻觉每批重犯，审校预算白烧。
  溯源: AV-9, AW-10（同根合并） + [官方文档](https://google.github.io/styleguide/docguide/best_practices.html)（文档修剪常态，盆景隐喻——反馈回流同向） + [模型经验]

[LAW-17] **MUST**: 任何用作通过/不通过判据的语句必须可机械判定。验收标准、准出标准、回滚与灰度触发条件、行动项验收、文档门禁 CI 判定——一律 Given/When/Then 或可勾选条件；「完成/合格/稳定/易于使用/酌情」类主观词禁入判据位。
  违反后果: 判据无法统一执行——不同执行者得出相反结论，门禁形同虚设；主观词沦为事后免责与扯皮空间，判据失去裁决力。
  溯源: 第 5 轮 doc-templates [GLOBAL] 候选升格（PT-4/PT-10/PT-13 域内具体化）；跨子域共性：doc-templates 验收/准出/回滚触发 + DG 文档门禁 CI 判定 + AV 人工评审清单 + [模型经验]

## 第五组：治理纪律

> 文档是资产——有主、有规、有责。

[LAW-14] **MUST**: 每个文档资产有 owner，目录级归口。「文档人人有责」= 无人负责；CODEOWNERS 覆盖 docs/；owner 三职责：评审归口、时效性负责、争议裁决；所有权团队化（`@team` 防单点）；分级治理——无分级的强治理被绕过。
  违反后果: 无主文档改坏无人回滚、过时无人更新、owner 离职即所有权真空；文档 PR 挂两周找不到 reviewer。
  溯源: DG-1 + [模型经验]

[LAW-15] **MUST**: 规范移植分层——原则层可迁移，惯例层必须本地化。可 lint 的规则进 lint（原则层）；术语/格式/语态等惯例层必须按语言与团队本地化，生搬是双输；指南 ≤2 页核心且自身遵守自己（自指一致）。
  违反后果: 中文团队直译英文惯例层→读者别扭、规则被弃用；有指南零 enforcement→装饰品。
  溯源: DG-7 + [模型经验]

[LAW-16] **MUST**: 发布即担责——AI 参与度是归因线索不是责任转移。责任链终点是人（发布者），「AI 写的」不构成任何免责；AI 参与度影响审校强度（风险分级）不影响责任归属；追溯类资产 AI 修改过人工门；审校记录不可省（谁/何时/抽了什么）。
  违反后果: 责任真空——「AI 写错了」成为免责叙事，低质量被归因于工具而非流程缺失。
  溯源: DG-10 + [模型经验]

[LAW-19] **MUST**: 行动项三要素齐全——具名责任人 + 可判定完成的事项 + 具体截止日，缺一即不合格。适用于一切待办/未决/行动条目：会议纪要行动项、复盘 action items、开放问题、TODO 标记、风险缓解措施；「尽快/近期/持续跟进/团队名」不合格。
  违反后果: 缺责任人则无人兜底（团队名 = 每人都以为对方负责）；缺截止日则待办变永久装饰；缺可判定事项则完成与否永远扯皮。
  溯源: 第 6 轮 proj-docs [GLOBAL] 候选 G2 升格；跨子域成立点：PJ-11 纪要行动项与 RACI + PJ-12 风险缓解复审日期 + PT-15 复盘行动项 + PT-9 开放问题三要素 + CC-8/CC-11 TODO 三要素 + [模型经验]（「责任主体缺席」生成偏置）

### 第 7 轮（refresh 补锚对账，2026-11-18）

**G4「坏消息显性化」终裁：不升格，关闭候选。** 第 6 轮登记的升格前提（「再核 doc-quality/api-doc-gen 是否有更稳定成立点」）逐项核对：

| 核对对象 | 结果 |
|---|---|
| doc-quality | 无直接成立点——「防御性填充/被动语态」为相邻主题（信息密度与可追责性），非坏消息显性化 |
| api-doc-gen | AD-13/AD-6「错误响应（非 200）必入 spec」为坏消息显性化的 API 契约面，但实质是 LAW-18（正常/异常路径并重）的实例化（proj-docs 叙事偏置族同根，第 6 轮已归 G1→LAW-18） |
| ai-doc-verification | 「匿名反馈缺追问通道是已知局限」为边界条件自述，非成立点 |

裁决理由：① 升格前提不成立——无独立于既有 LAW 的新稳定成立点；② 与 LAW-18 在「异常态必须显性」维度重叠，独立立条将产出「要写坏消息」式弱条款，可判定性不足（与 G3 未收录理由同构）；③ 三成立点域层立法完备（PJ-13 状态报告坏消息前置 / PT-12 遗留风险段必含 / AC-1 负后果必写）。**LAW 维持 19 条（上限 20，余 1 位），G4 候选关闭**；除非未来出现独立于 LAW-18 语义的新成立点，不再复议。

## 维护纪律

1. **查重收录**：新 LAW 候选先与既有 LAW-1~19 查重——跨子域共性才可收录，仅单子域适用的留在该子域 kb。
2. **退役登记**：LAW 被文档证伪或长期失去适用场景时移除，并在本文件登记退役原因，不静默删除。
3. **总数硬顶**：LAW 总数上限 20；达顶后新候选只能并入既有 LAW（修订条款并在溯源登记合并），不开新组绕过上限。
4. **可判定性**：每条 LAW 必须能机械判断"是否违反"；不可判定的条款降级为子领域最佳实践。
