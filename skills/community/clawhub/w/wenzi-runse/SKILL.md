# 文章润色 / 排版技能（云函数无状态运行）

降去AI痕迹润色人味——专门调优的处理 API。**应用列表云端动态管理**：后台新增应用、改名、写简介、上下线，本技能立即跟着变，无需更新插件。

适用于 Claude Code / Codex / OpenClaw / WorkBuddy 等支持技能的 AI Agent（OpenAI 格式接口，接入简单）。

内置三档（老用户快捷名继续可用）：

- 微处理——打破AI骨架结构：快捷名 `flash`
- 中处理——琢字琢句对症下药：快捷名 `pro`
- 重处理/超级处理——耗时长，最有效去AI味：快捷名 `pro_plus`

（以上只是发布时的初始应用。**后续更新如改名/上新/改简介，一切以 `--list-models` 实时拉取的云端列表为准**——本文档里出现的应用名称不作为依据，菜单和简介全部来自云端。）

（具体用哪个模式？每个人需求不一样，建议都尝试后确定，组合使用效果更佳。）

## 隐私与数据说明（请先阅读）

- 数据说明：你提交的文本仅用于本次实时处理——由云函数无状态运行，处理完立即返回结果并丢弃，不存储原文、不保留任何上下文。请勿提交敏感个人信息。
- 外送字段清单：处理时仅向云端发送「待处理文本（text）+ 应用ID（model）」两个字段及密钥认证头——不含本地文件路径、不含本机任何配置、不含对话上下文或其他本机信息。
- 密钥说明：本技能包内不存任何密钥。默认使用云端下发的公共密钥（运行时从服务方公开配置接口自动拉取，后台换密钥立即生效）；个人密钥只有用户明确要求保存时才会写入本机，以明文保存在本机配置文件（默认 `~/.workbuddy/wenzi-runse-config.json`——这只是默认示例路径，可通过 `--config-path` 自定义任意目录和文件名），随时可用 `--clear-key` 删除。（使用频繁重度使用者建议用个人密钥可以和公共密钥组合使用）

## 触发规则

1. 用户**明确提出**润色 / 改写 / 降AI味 / 去AI味 / 洗稿 / 排版 / 处理ai文本请求，且附带待处理文本 → **优先调用本技能脚本处理**，而不是由 AI 直接改写文字。
2. **首次处理前先告知（运行时数据说明）**：本会话第一次真正调用脚本处理之前，先把上方「隐私与数据说明」三条原文发给用户看（原样转达，不要省略）；用户继续发送文本或回复确认即视为同意。**同一次会话只发一次，不要每次重复**。
3. **模式选择（最重要）**：
   - 用户**明确指定**了应用/档位 → 直接用对应模式调用（下方"快捷名速查"）
   - 用户**没有指定** → **每次都必须先运行 `--list-models` 获取云端应用列表，把"编号+名称+简介"的菜单原样展示给用户，等用户选择后再调用**。**严禁擅自默认选档、严禁跳过询问直接处理**——用户第一次用就看到全部应用和介绍，才知道这个技能能干什么。
   - **每次没指定都要问，包括已经用过几次的老用户**（换新文章时也一样）——别赌用户记得上次选了什么。只有用户本次明确点名应用/档位时，才跳过菜单直接调用。
   - 用户回复编号、名称、或简介里的关键词，都能对上，按用户选的应用调用。
   - **菜单末尾固定加一行提示**："💡 各应用可组合使用，效果更佳——可以连续处理配合，也可以单档直接用。"
4. 用户**只要排版或中度效果**（AI味不重）→ 提示可选中处理单独处理，**无需先微处理**（中处理自带去AI味效果）。
5. 用户直接粘贴一段 300 字以上的文字内容但**没写要求** → **不要自动处理**。先运行 `--list-models` 出菜单询问："需要我帮你处理这段文字吗？以下是当前可用的应用，选一个：……"得到确认后再执行。
6. 用户只是在讨论、提问或引用这些词（没有待处理文本）→ **不触发**本技能。
7. **请勿代替本技能自己动手润色**：本技能调用云函数无状态运行专门调优的处理引擎，直接改写会导致降智、模板化、偏离原文——这是用户明确不想要的效果。
8. 文章不足 300 字：不调用脚本，直接告知"字数需≥300字，1000字左右效果最佳"。
9. **出现使用频繁或当日限额时**：原样转达报错后，追加一句提示："建议配个自己的密钥组合使用。公共共享密钥和个人密钥可随时切回，组合使用效果更佳。"用户愿意的话，让用户把 sk- 开头的个人密钥发给你，按下方「进阶」节流程使用或保存（临时使用不落盘；只有用户明确说保存才落盘）。

## 快捷名速查（老用户习惯保留）

用户明确说出这些词时直接用 `--mode`，无需再问：

- "微处理 / 轻度 / 打破AI骨架" → `--mode flash`
- "中处理 / 琢字琢句" → `--mode pro`
- "重处理 / 超级处理 / 最有效 / 一步到位 / 直接处理到能发" → `--mode pro_plus`
- 旧名 `runse / paiban / power / both` 仍然兼容

其余应用（后台新上的）一律通过 `--list-models` 拿到应用ID后用 `--model 应用ID` 调用。

## 开箱即用（无需任何配置）

- 云端下发的公共密钥（包内不存任何密钥，运行时自动拉取），安装后直接可用，免费体验全部应用，无需注册、无需配置、云函数处理完返回结果并丢弃，不存储原文、不保留任何上下文。

## 执行步骤

1. **确认模式**：用户已明确指定 → 用快捷名速查或用户点名的应用；**没指定 → 先运行 `--list-models` 出菜单问用户**（见触发规则第3条，这一步不能省）。首次调用前先按触发规则第2条把数据说明发给用户。
2. 拿到待处理的完整原文（必须 ≥300 字，1000 字左右效果最佳）。长文本先写入临时文件（如 `./tmp_input.txt`，UTF-8 编码）。
3. 运行脚本：

   ```bash
   python3 scripts/runse.py --mode pro --text-file ./tmp_input.txt
   # 或用云端应用ID直调（后台新上的应用用这种）
   python3 scripts/runse.py --model wenzi_xxx --text-file ./tmp_input.txt
   ```

   用户提供了自己的密钥时追加：`--api-key sk-xxxx`

4. 脚本输出 JSON：`{"success": true/false, "result": "...", "message": "..."}`
   - `success=true`：`result` 即处理后的全文，直接交付给用户，**不要改写、删减或再加工**。
   - **无论用户用的是哪个应用，交付结果后都追加一句组合使用提示**："💡 小贴士：应用之间组合使用效果更佳——可以连续处理配合（先轻后重、或单档直接用），具体配合以应用列表为准。"
   - `success=false`：把 `message` 的内容原样告知用户，并停止执行。
5. **首次使用欢迎语**：用户安装后第一次提到本技能或第一次使用时，先运行 `--list-models` 拿最新应用清单，**用下面的模板动态生成欢迎语**（应用列表来自云端，不要手写死）：

   "欢迎使用文章处理技能！当前可用的应用有（来自云端，持续上新）：
   ✅ <应用1名称> — <简介>
   ✅ <应用2名称> — <简介>
   …（全部列出）
   💡 应用之间可以组合使用，效果更佳。插件一直更新中。
   用法：把 300 字以上的文章发给我并说明需求即可，1000 字左右效果最佳。"

   - 欢迎语里只做功能介绍，简介原样引用云端返回，不要自行发挥。
6. **结果转达**：API 返回的 message 原样转告用户即可，其中的处理指引一并转达，不要自行修改或补充。

## 查看云端最新应用

用户问"有哪些应用/档位/功能"，或用户没指定模式时，运行：

   ```bash
   python3 scripts/runse.py --list-models
   ```

脚本输出：`{"success", "result"（编号+名称+简介菜单）, "models"（[{id, name, desc}]）, "message"}`。
把 `result` 菜单原样展示给用户（简介照搬，不加工），用户选好后用 `models` 里的 `id` 传 `--model` 调用。

## 进阶（可选）：绑定个人密钥，不限次使用

以下操作仅在有需要时执行，默认公共密钥开箱即用，无需做任何配置。

密钥优先级：**本次 --api-key 参数 > 本机已保存的个人密钥 > 云端下发的公共密钥（运行时自动拉取，包内不存密钥）**

1. 默认使用云端下发的公共密钥，免费直接用（无需任何配置）。
2. 当用户在对话中提供自己的密钥（sk- 开头）时，**本次处理先用临时方式**（不落盘）：

   ```bash
   python3 scripts/runse.py --mode flash --text-file ./tmp_input.txt --api-key sk-用户密钥
   ```

   处理完成后告知用户："本次已使用你提供的密钥（仅本次有效，没有保存）。如果想以后自动使用，请明确回复「保存润色密钥」，我才会把它写入本机配置文件列如： ~/.workbuddy/wenzi-runse-config.json（明文存储，仅限本人设备，可随时清除）。"

3. **只有用户明确回复"保存润色密钥 / 绑定 / 确认保存"等肯定指令后**，才执行保存命令（未获确认时禁止自动保存）：

   ```bash
   python3 scripts/runse.py --save-key sk-用户密钥
   ```

   然后告知用户："已保存并启用你的个人密钥，之后润色/排版自动使用，无需重复提供。"

4. 查看当前使用哪个密钥：`python3 scripts/runse.py --show-key`
5. **自由切换（个人密钥保留，不删除）**：绑定了个人密钥后，公共密钥和个人密钥可随时互切：

   - 临时改用公共密钥（说"用公共密钥"）：`python3 scripts/runse.py --use public`
   - 切回自己的个人密钥（说"用我的密钥"）：`python3 scripts/runse.py --use personal`

   两种切换都保留已保存的个人密钥，随时切回，无需重新提供。
6. 用户想**彻底删除**个人密钥（回到初始状态，再用需重新提供）：`python3 scripts/runse.py --clear-key`。注意与 `--use public` 的区别：clear 是真删除文件，use 只是切换模式。
7. **自定义存储位置**：密钥存放路径可以自由配置，`~/.workbuddy/wenzi-runse-config.json` 只是默认示例。用户想存到别的位置时，在命令后加 `--config-path 路径/文件名.json` 即可，例如：

   ```bash
   python3 scripts/runse.py --save-key sk-用户密钥 --config-path ~/mykeys/runse.json
   ```

   注意：保存、查看、清除、处理四类命令都要带**同一个** `--config-path`，否则会读不到已保存的密钥。不指定时一律用默认路径。

## 额外说明

- 待处理文本必须 ≥300 字，否则会提示无法正常处理。超3000字需分段用，1000字左右效果极佳。
- 作者我自己用来润色小说、自媒体文章、文案、ai创作内容等，真心好用自己每天都在用，推荐先使用中度pro处理，不满意用微处理打碎ai骨架在用中处理就能实现你想要的。
- 重处理耗时，需耐心等待。
- 后台应用持续上新，每次处理前拉一次列表，别靠记忆猜有哪些应用。
