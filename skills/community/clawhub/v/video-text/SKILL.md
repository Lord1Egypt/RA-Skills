# Video Text — 画面文字提取与分区分析

## 它解决什么

一条视频的画面里到底写了什么字？

**这个问题比听起来重要：**

```
烧录的字幕        要转成文本，只能看画面
水印和台标        要清掉，得先知道在哪个区域
宣传片的标题      要核对，看和文案对得上吗
素材审查          拿到的片子有没有别人的标记
```

**这个技能把画面上的字全部读出来，按区域分开，并且区分「一直在的」和「真正在变的」。**

## 为什么分两层

```
固定层    多帧重复出现  → 水印、台标、频道名、常驻标题
内容层    只出现几次    → 真正的字幕、弹出的标题、对白
```

**这两类该不该在、能不能删，答案完全不同。**

- 固定层是「来源的印记」，通常要清
- 内容层是「这条片子要说的东西」

**混成一张清单没用。分开才有用。**

## 为什么分区域

```
顶部 0-18%     台标、频道名
底部 78-100%   字幕
中间 18-78%    标题、图表文字
```

**水印在角上，字幕在下方。按区域统计比全图混在一起准得多。**

## 实测效果

**一条 257 秒的官方宣传片，每 4 秒抽一帧，65 帧：**

```
固定层 3 条（全是顶部）：
  91%  火影忍者手游情报君
  85%  NARUTO
  66%  bilibili

内容层 298 条（只出现几次）
```

**三个水印全在顶部，91%/85%/66% 的帧都出现过。一次全抓出来。**

## 用法

```bash
# 概览（看固定层和内容层）
python scan.py 片子.mp4

# 抽密一点，导出 SRT 字幕
python scan.py 片子.mp4 --step 0.5 --srt 字幕.srt

# 出 markdown 报告（含逐帧文字量曲线）
python scan.py 片子.mp4 --step 2 --report 报告.md

# 全都要
python scan.py 片子.mp4 --step 1 --srt 字幕.srt --report 报告.md --json 数据.json
```

## 参数

```
--step N       每 N 秒抽一帧（默认 1.0）。0.5 更细但更慢
--srt PATH     导出 SRT。只取底部区域，连续相同的行会合并
--report PATH  导出 markdown 报告
--json PATH    导出原始数据
```

## 输出长什么样

**概览：**

```
扫描: 片子.mp4
   1280x720  257.4s  65 帧

固定层 3 条（多帧重复，多半是水印/台标）:
   91%  [顶部]  火影忍者手游情报君
   85%  [顶部]  NARUTO
   66%  [顶部]  bilibili

内容层 298 条（只出现几次）
```

**报告（markdown）三段：**
1. 固定层表格（出现比例 / 区域 / 文字）
2. 内容层表格（次数 / 区域 / 文字）
3. 逐帧文字量（带条形图）

```

```

**ffmpeg 找不到的三种情况都处理了：**

```
一、环境变量 FFMPEG_DIR 指向目录
二、脚本同目录下放了 ffmpeg.exe
三、PATH 里有
```

## 已知限制

1. **读不出「用字画成的图」。** 如果画面是拿字符拼成的图案（字符画、ASCII 艺术），OCR 看到的是网格，不是句子。这类东西它测不了。
2. **OCR 会认错字。** 实测同一个水印（bilibili）在两帧里被读成 `Liibili` 和 `Lilibii`。所以关键判断要对一眼原图。
3. **只读画面，不读音频。** 没有说话的声音转录。要那个用 whisper。
4. **抽帧越密越慢。** 0.5 秒一帧的价格大约是 1 秒一帧的两倍。
5. **文字太小读不出。** 小于画面高度 1.2% 的字，OCR 基本失效。

## 它不适合什么

```
✗ 想听人说了什么        → 用 whisper，不要用这个
✗ 想识别画面里的人和物  → 那是视觉模型，不是 OCR
✗ 想给视频打标签        → 这个只给字，不给语义
```
