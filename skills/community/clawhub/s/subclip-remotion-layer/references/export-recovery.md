# Recover missing Remotion elements in exports

When the user reports an element missing from an exported video and it belongs to a Remotion layer, convert the affected layer to HyperFrames while matching the original design exactly. Remotion client-side export can omit elements that appear correctly in the browser preview. This recovery rule overrides the usual preference to keep an existing layer in Remotion; it does not authorize converting unrelated layers.

1. Identify the exact project, Remotion item and affected timestamps using the project outline, targeted section/source reads and asset inventory. Inspect the original preview/reference and, when available, the failed export at those times. Check visibility, timing, asset/font loading and stacking so an unrelated missing native item is not mistaken for a Remotion export problem.
2. Read `subclip-hyperframes-layer` and its authoring contract. Capture the original source, props, assets, start/end times, geometry, fit, opacity, lane and hierarchy before replacing anything. Keep the original recoverable through project history/checkpoint tools available in the live schema.
3. Rebuild that layer as a HyperFrames document. Look up each Remotion API's equivalent in the official conversion references listed under "Converting Remotion to HyperFrames" in `subclip-hyperframes-layer`'s `references/official-index.md` (start with `api-map.md`, then `timing.md` and `sequencing.md`). Preserve every visible element, exact text, fonts/weights, line breaks, colors, gradients, borders, shadows, spacing, crop, transparency, positions and proportions. Translate frame-based animation into deterministic seekable timing at the project FPS, preserving entrances, holds, exits, easing and synchronization. Reuse the same imported media and keep native audio/media ownership unchanged. Do not simplify the design or substitute a similar template to hide the export defect.
4. Validate with `validate_runtime_layer_source` using `kind: "hyperframes"`, then create the replacement through `add_runtime_layer` with the original placement and hierarchy. `update_runtime_layer` targets an existing item of the supplied kind; do not assume changing its kind converts the original. Use supported visibility/opacity controls to compare one layer at a time, keeping the original recoverable. After checking the replacement, remove only the superseded Remotion item with `delete_runtime_layer`. Verify that only one intended layer is visible and no audio is doubled.
5. Compare the composition at the reported failure, entrance, settled state and exit. Check a short exported segment through the normal export workflow when export is authorized, then inspect its actual output frames. A preview or successful source validation alone cannot prove this export defect is fixed. Preserve the user's requested export format/settings and existing authorization; if output inspection is unavailable, report that export verification remains pending.

Exact visual matching is the acceptance criterion, not an unverified guarantee. If a required effect or asset cannot be reproduced, state the specific mismatch and keep the original recoverable rather than claiming an exact match. Follow the session's Plan/Default mode: Plan mode describes the conversion without changing the project.
