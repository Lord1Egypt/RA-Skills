# mpress · 公众号固定排版 + 草稿上传

输入一条 `.md` 路径，脚本完成固定形态映射、HTML 渲染和草稿上传。Agent 只执行命令、查看映射报告、处理失败，不改写文章。

> **源稿只读。** 不重写、不补标题或编号、不改标点、不断句、不增删段落、不把普通段落改成组件。没有派生稿，也没有 `--slug`。源稿缺少某种形态时，只按普通 Markdown 输出；缺必需资源时，报告失败，不擅自修补。

> **不做语义识别。** 脚本只匹配下面的字面形态和相邻位置。语气、主题、重要程度、章节是否“适合折叠”等判断一律不参与输出。

## 1. 运行方式

一条命令生成并推送草稿：

```bash
node scripts/wechat.mjs push 文章.md
```

`gen` 只生成、不联网，用于本地检查排版映射：

```bash
node scripts/wechat.mjs gen 文章.md
```

- 路径按当前目录解析。任意位置、任意文件名的 `.md` 都可以；不要求 `content/`，不要求 frontmatter。
- 标题取 `frontmatter.title` → 首个 `#` → 文件名。
- 封面取 `frontmatter.image` → `banner.image` → 正文第一张本地图 → `assets/default-cover.png`，独立文稿不会因为没封面失败。
- 站内链接补全读 `WECHAT_SITE_URL`；`/public` 开头的图片需要 `BLOG_ROOT`。独立写稿用相对图片和完整外链，就不用设这两项。
- 可选覆盖：`WECHAT_APP_ID` / `WECHAT_APP_SECRET` / `WECHAT_CREDENTIALS`（凭证）、`WECHAT_WORK_DIR`（产物目录）。

### 2.1 公众号开篇与移动端节奏规范（固化）

- **固定开篇范式**：正文顶部采用 **`kicker`（刊头信息条） + `lead`（核心结论）** 两段直出，中间**永久不加铺垫过渡段**。`lead` 必须高度凝练，用最直白的一两句话给出全文核心结论——让读者看完标题再看这一块，后面正文不看也能带走结论。
- **紧凑移动端间距**：针对 390px 手机竖屏收紧全站留白——正文段距 `0.72em`、长引上下 `14px`、组件块上下 `16px`、二级标题上 `28px` / 下 `12px`，避免手机端大段空白。
- **移动端插图红线**：公众号在手机竖屏阅读，**严禁直接把宽屏网站展板图缩小塞进正文**（字号在手机上会完全看不清）；自制信息图应采用竖版或紧凑比例（如 3:4 / 4:5，逻辑画布宽 750–900px，正文字号 ≥26px）确保手机一屏内文字清晰可读。

段落以源稿空行分块。普通正文、列表、表格、链接、加粗等保持原顺序和文字，不做智能断句、同义改写、段落合并或重排。折叠块内部按固定字符宽度换行，只影响显示，不回写源稿。

未列出的形态不扩展规则。尤其不要根据“这句话像提示”“这段适合收尾”“这里应该有 01”创建标记。

## 3. 映射报告与产物

每次 `gen` 或 `push` 都写入 `~/.wechat-article/work/<slug>/`（`WECHAT_WORK_DIR` 可改），仓库目录只读：

- `layout.json`：源稿相对路径，以及 `{ line, rule }` 映射记录；`line` 是包含 frontmatter 的源文件行号。先查它，确认实际触发规则。
- `article.md`：组件展开后的渲染输入，只存在于产物目录。
- `body.html`：固定主题渲染后的正文。
- `meta.json`：标题、封面和资源统计。

`layout.json` 用于解释脚本行为，不是创作建议。相同源稿和脚本应得到相同产物；差异只能来自输入、脚本、固定主题或站点配置变化。

视觉只有 `assets/theme.css` 这一套。不要在提示词、源稿或 HTML 中另配颜色、字号、圆角、主题或装饰。

## 4. 图片与草稿身份

- 图片只接受 JPG / PNG / GIF，单张不超过 10MB；WebP、`data:` 内联图和缺失文件报「图片」失败，脚本不改图补图。
- 封面不再取 `frontmatter.image`，固定为脚本合成的头图（见 §5）；`image` 只服务站点与正文，不参与封面。
- 正文图片上传微信素材库后替换为微信地址，相同图片内容复用上传缓存。
- slug：`content/` 内用相对路径拼，其他位置用文件名，`样例/` 下加 `sample-` 前缀。重复 `push` 根据 `~/.wechat-article/work/state/drafts.json` 更新同一 `media_id`；旧草稿已失效时才新建。
- 产物和状态只写 `~/.wechat-article/`（或 `WECHAT_WORK_DIR`），源稿目录只读。

## 5. 头图

公众号封面固定由脚本合成，不是直接取 `frontmatter.image`：底图 + 由页面排上去的文字，输出 1800×766（2.35:1）PNG，作为 `thumb_media_id` 上传。同一张在站内更接近订阅 / RSS 入口，所以是「一图多用」，不为公众号另做一版。

- **底图必须无字**。优先级：`WECHAT_HEAD_BASE` → `banner.image`（书稿插画）→ 运行包内 `assets/head-base.jpg`。封面图常常自带标题，不能拿来当底图。
- **压色**：底图铺满后压一层 58% 墨青 `#007275`，保证白字可读；底图只作纹理，不承担信息。
- **安全区**：四边各留 8%（144px），文字只排左侧 76% 宽度以内。
- **文字层数按文章类型**：
  - 散篇两层：标题 + 摘要。摘要取 `description`，为空则不排；**没有第三层**，不写 RSS、订阅或任何占位词。
  - 书稿三层：标题 + 摘要 + 书名。书名取 `banner.book` → `book` → `content/books/<name>.md` 的 title。
- **字号**（按 1800 宽）：标题 79px 粗体无衬线；摘要 39px 衬线，前面一段细横线；书名 36px，大字距，上方一条细分隔线，贴安全区底部。
- **超长标题**：先缩字号，79 → 34px，每档 2px，直到放进安全区；缩到 34px 仍放不下就截断为三行。摘要自然折行，不缩字号。
- **不要用设计工具再手动加字**。在 Figma / PS 里补标题，等于把文字焊进底图：换一次标题就要重做一次图，还会和页面上的实际排版对不上。文字只由脚本排。

## 6. 链接

能写：

- 站内：`/case/codingbook/`，前导斜杠加站点路径。脚本按 `WECHAT_SITE_URL` 补成绝对地址；没设就报「结构」失败。
- 站外：`https://…` 或 `http://…` 完整地址。
- 邮箱与电话：`mailto:…`、`tel:…`。

不能写——会让 `push` 直接失败，脚本以「结构」退出 5：

- `#锚点`：实测 45166。
- `mp.weixin.qq.com` 的任意地址（首页、`/s/…`、带参数）：实测 45166。
- 渲染后仍然以单个 `/` 开头的地址：说明补全逻辑失效，按错误排查。

不要写——微信不报错，但保存时会把 `<a>` 剥成纯文字，脚本只打提示：

- 不带前导斜杠的站内路径（`case/codingbook/`）、`../` 相对路径、`//host/…` 协议相对地址。
- `javascript:` 伪协议、空 `href`。

必须知道：本账号没有微信支付权限，微信保存草稿时会把 `<a>` 整条剥掉，只留文字。实测 `draft/get` 回读，`<a href="https://example.com/article">站内</a>` 变成 `站内`。因此正文链接**一律不可点**，补绝对地址只是为了让 `draft/add` 不返回 45166。写法照此执行：

- 链接文字要自解释，不写「点这里」「详见」「戳我」。
- 需要读者拿到地址就写完整裸 URL 文本，它会原样显示为文字，例如 `https://example.com/article`。
- 折叠块正文在 SVG 里，永远不可点；`[文字](url)` 由脚本降级成 `文字（url）`，写裸 URL 结果相同。
- 链接包图片 `[![alt](img)](/x)`：脚本只保留图片、丢掉链接，避免渲染成乱码。
- 官方依据：上传图文消息素材接口写明「具备微信支付权限的公众号，可以使用 a 标签，其他公众号不能使用」。开通支付权限后的点击行为未在本账号验证。

## 7. 失败只看五类

| 退出码 | 类别 | 处理 |
| --- | --- | --- |
| 2 | 凭证 | 核对 AppID / AppSecret；48001 表示账号未认证或没有接口权限 |
| 3 | 白名单 | 把当前出口 IP 加入公众号后台的 IP 白名单 |
| 4 | 图片 | 修正图片格式、大小或路径；不改正文内容替代处理 |
| 5 | 结构 | 检查 title、纯 `.md` 输入、围栏闭合、链接形态和源稿位置；不擅自补写内容 |
| 6 | 网络 | 检查 `api.weixin.qq.com` 连通性，稍后重试同一命令 |

先按退出码处理，不跨类猜测。上传部分仍使用固定微信接口和缓存，不增加人工确认、主题开关或语义审稿步骤。

验收判据与耗时基线见仓库根目录 `README.md` 的「实测」一节；本页只保留调用、映射与失败处理，不重复实测数据。
