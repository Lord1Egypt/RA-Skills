# Website Transformation Workflow

## Headline

Transform a Dated Business Website in 7 Steps, in Plain Words

## Hook

Give your AI agent one dated business website. It audits the site, studies the competitors, drafts the brand and the wireframes, then gives a step by step redesign plan with a before and after audit sheet, for owner review.

## Pain, in plain words

A dated business website looks tired at first glance. The same layout on every page, no real photos, no real numbers, no clear next step, and a visitor who leaves without calling. The owner knows the site needs work, but not where to start, and a full rebuild feels too big, too slow, and too costly. The fix is not a rebuild on day one. The fix is a plan first, step by step, with an audit that shows what is broken, and a before and after sheet that shows what changed.

## What you get

A 7 step workflow for transforming a dated business website, in plain words, for any small business site, not only a Shopify site. The workflow covers the site audit, competitor analysis, brand guidelines, wireframes, UI images, pixel perfect UI refine, and the deploy checklist. Each step ends with a draft for owner review, never a changed live site by itself. It gives you a before and after audit sheet, with evidence pasted in the message, and a redesign plan draft, labelled DRAFT, NOT SENT.

## Who this is for

People who run a dated business website, and want it transformed in 2 to 3 weeks, step by step, in plain words. People who build websites with an AI agent, for any small business, and want a clear plan before they touch the site. People who hand a redesign to a builder, and want a clear brief at handoff, in plain words.

## Why this saves money

A plan first stops you from rebuilding a whole site when only a few pages need work. A before and after audit sheet stops you from paying twice for the same fix. A redesign plan draft, reviewed first, stops a live site from changing in a way the owner did not approve. A deploy checklist stops a broken launch.

## How to use it

Hard rule, read this first: the agent does not audit, change, or deploy a live site itself. It drafts the words for each step, and only checks evidence the user pastes in the message. The USER does each step. The user runs the audit and pastes the report back. The user studies the competitors and pastes the notes back. The user runs the brand step and pastes the guidelines back. The user makes the wireframes and the images. The user runs the refine step and pastes the code snippets back. The user deploys. A page description alone is not code evidence. Never mark an audit item Checked without pasted text quoted as the evidence. Never mark an item Missing unless the pasted text shows it is absent, with the words quoted. Never claim the agent opened a live site, or changed anything on a live site.

Fast path: If the user already gives the site, the goal of the site, and the audience in the first message, do NOT ask a long list of questions first. Do the full audit and the redesign plan draft in the SAME reply, then the before and after audit sheet. Never stop at questions alone.

Step 1: audit the existing site with Claude, and list each audit item as Checked, Missing, or Not confirmed, with evidence.
Step 2: run the competitor analysis, and list what each competitor does better, with pasted notes quoted as the evidence.
Step 3: draft the brand guidelines with ChatGPT, colors, fonts, logo, and tone, with pasted guidelines quoted as the evidence, or Not confirmed.
Step 4: draft the wireframe brief, page by page, main point and main action per page.
Step 5: draft the UI image briefs, one real photo per page, what it must show.
Step 6: refine the pixel perfect UI with Claude Code, and check the code snippets the user pastes back, screen by screen.
Step 7: run the deploy checklist, and push the custom Shopify theme, or the same checklist on the host the site already uses.

Ask only what is missing, in plain words, one short list at a time:
1. What is the site, paste a description of each page, in plain words?
2. What is the goal of the site, sell, book, call, or show work?
3. Who is the site for, in plain words?
4. What do the competitors do better, paste one short note per competitor?
5. What is the brand today, colors, fonts, logo, tone, or Not confirmed?
6. What must the new site do on a phone, in plain words, or Not confirmed?
7. Where does the site live today, Shopify, or another host, or Not confirmed?

If the user does not know an answer, mark it Not confirmed, and use the most common answer for that business type, and say so, marked Suggested, not confirmed. Do not invent an answer. If the user says use the live site for a question, use only what is visible on that site, and say so.

## The transformation bar, in plain words

This is the bar every step is judged against. A site is transformed only if the evidence shows it.
1. One clear main point per page, easy to see in seconds.
2. One color palette and one type system, used the same way on every page.
3. Real photos, real numbers, real project details, in the voice of the business.
4. One clear next step on every page, in plain words.
5. A phone first layout, readable without zooming, with tappable buttons.
6. Fast to load, with no heavy effect that slows the page.
7. A before and after audit sheet, with evidence for every change.

## Step 1: audit the existing site with Claude

The user runs the audit with Claude, and pastes the audit report back in the message. The agent drafts the audit questions first: main point per page, palette, type, real photos, real numbers, real testimonials, contact details, main action, phone layout, and load speed. The agent then checks the pasted report, item by item, as Checked, Missing, or Not confirmed, with the pasted words quoted as the evidence. Checked means the pasted text describes the item. Missing means the pasted text shows the item is absent. Not confirmed means the pasted text says nothing about the item. Never mark Checked without a quote. Never mark Missing without the words that show it is absent.

## Step 2: competitor analysis

The user pastes one short note per competitor, in plain words. The agent drafts the comparison sheet: competitor name, what they do better, the pasted note quoted as the evidence, what to copy, and what not to copy. Mark what a competitor does better only with a pasted note quoted as the evidence. If no note was pasted, mark it Not confirmed, and do not invent a competitor strength.

## Step 3: brand guidelines with ChatGPT

The user runs the brand step with ChatGPT, and pastes the guidelines back in the message. The agent drafts the brand sheet: colors, fonts, logo, and tone, in plain words, with the pasted guidelines quoted as the evidence. If no guidelines were pasted, mark the brand Not confirmed, and use the most common brand for that business type, marked Suggested, not confirmed. The brand sheet is a draft for owner review, not a live change.

## Step 4: wireframes

The agent drafts the wireframe brief, page by page: page name, main point, main action, and sections in order, in plain words. The user makes the wireframes. The agent checks the wireframe list only from pasted text. A wireframe is Checked only when the user pastes its description, quoted as the evidence. If no wireframe was pasted, mark it Not confirmed, and do not claim it exists.

## Step 5: UI images

The agent drafts the image briefs, one real photo per page: what the photo must show, in plain words, and where it sits on the page. The user makes the images. The agent checks only pasted image descriptions. An image is Checked only when the user pastes its description, quoted as the evidence. A stock photo with no link to the business does not count as a real photo. If no image was pasted, mark it Not confirmed.

## Step 6: refine pixel perfect UI with Claude Code

The user runs the refine step with Claude Code, and pastes short code snippets back in the message. The agent checks the snippets, screen by screen, and quotes each snippet as the evidence. A screen is Checked only when its snippet is pasted in the message. A page description alone is not code evidence, and a screen with no snippet is Not confirmed, never Checked. The agent drafts the refine list, one plain line per screen, and the user makes the changes.

## Step 7: push a custom Shopify theme

The source workflow pushes a custom Shopify theme. For any other host, use the same deploy checklist with the host the site already uses. The user deploys, the agent never deploys anything itself. The agent drafts the deploy checklist: backup first, test on staging, check the phone layout, check the forms, check the main action, then go live, then check again after go live. Each checklist item is Checked only when the user pastes the test result back, quoted as the evidence. If a test result was not pasted, mark it Not confirmed, and do not go live on a guess.

## The before and after audit sheet

Run the audit sheet before step 1 and again after step 7, and show each item with evidence:
- Item: [item name, in plain words]
- Before: [Checked, Missing, or Not confirmed, with pasted text quoted, or Not confirmed]
- After: [Checked, Missing, or Not confirmed, with pasted text quoted, or Not confirmed]
- Change: [one line, in plain words, or None]

Use Checked only with pasted text quoted as the evidence. Use Missing only when the pasted text shows the item is absent, with the words quoted. Use Not confirmed when the pasted text says nothing about the item. Never mark a check Pass, Built, Done, or Now without pasted evidence that supports exactly that mark.

Audit items, in order:
1. Main point per page, one clear point, easy to see in seconds.
2. Palette, one palette, used the same way on every page.
3. Type, one type system, readable, with clear headings.
4. Real photos, real photos of the business, not stock images.
5. Real numbers, in one format, with no invented statistic.
6. Real testimonials only, no fake review, no sample work shown as client work.
7. Contact details, easy to find, and correct, on every page.
8. Main action, one clear next step, in plain words, on every page.
9. Phone layout, readable without zooming, tappable buttons, no cut off section.
10. Load speed, fast to load on a phone, with no heavy effect that slows the page.

## What good looks like

A good transformation has one clear point per page, one palette, one type system, real photos, real numbers, and one clear next step on every page. A good redesign plan draft lists the audit items first, in order, with one plain line each, and keeps what already works. A good before and after sheet has every item marked Checked, Missing, or Not confirmed, with pasted text quoted as the evidence for every Checked item, and the words quoted for every Missing item.

## Common mistakes

These mistakes show up often, and they are easy to avoid if you check for them.

- Calling the site transformed when only the home page changed. Check every page the owner cares about, or say plainly which pages were not checked.
- Marking an audit item Checked from a short description. A description that says "the site looks nice" is not evidence for any item.
- Marking an item Missing with no words to show it. Missing needs the pasted words that show it is absent, quoted as the evidence.
- Skipping the competitor step. A redesign with no competitor note is a guess, not a plan.
- Using sample work as client work. Only real project details count, and a fake testimonial is a blocker, not a gap.
- Deploying without a backup, or without a staging test. A deploy checklist item with no pasted test result is Not confirmed, and the site does not go live on a guess.
