# Skill组合与调度方案 v1.0

> **依据**：《中华人民共和国职业分类大典（2022版）》职业编号 2-06-07-16  
> **核心原则**：不定义角色名，只说明每组的Skill集合及调度逻辑

---

## 一、Skill集合分组

### 1.1 前端组（成果进来）

**包含Skill**：
| Skill编号 | Skill名称 | 核心职能 |
|-----------|-----------|---------|
| S-FR-01 | 成果挖掘 | 识别、接触、收集有转化潜力的成果 |
| S-FR-02 | 成果培育 | 提升技术成熟度，完善知识产权布局 |

**前端组不做的**：
- 不做深度技术评价（那是中端的事）
- 不做交易谈判（那是后端的事）
- 不做法律判断（那是横切的事）

**典型输出**：《成果挖掘报告》 → 《成果培育方案》

---

### 1.2 中端组（评估论证）

**包含Skill**：
| Skill编号 | Skill名称 | 核心职能 |
|-----------|-----------|---------|
| S-MD-01 | 成果评价 | 判断成果值不值做、能不能做 |
| S-MD-02 | 知识产权服务 | 核查权属、排查侵权、设计保护方案 |
| S-MD-03 | 金融服务 | 匹配资金方、完成估值、设计融资路径 |

**中端组不做的**：
- 不做技术挖掘（那是前端的事）
- 不做工程化落地（那是后端的事）
- 不做交易执行（那是后端的事）

**典型输出**：《成果评价报告》 → 《金融服务方案》

---

### 1.3 后端组（转化落地）

**包含Skill**：
| Skill编号 | Skill名称 | 核心职能 |
|-----------|-----------|---------|
| S-BK-01 | 成果熟化 | 完成工程化、生产工艺、产品验证 |
| S-BK-02 | 成果推广 | 接触市场、收集意向、建立渠道 |
| S-BK-03 | 成果交易 | 完成转让/许可/作价投资的合同签署与交割 |
| S-BK-04 | 成果孵化 | 组建公司、运营项目、规划退出 |

**后端组不做的**：
- 不做前期判断（那是中端的事）
- 不做技术完善（那是前端的事）

**典型输出**：《成果熟化报告》 → 《推广执行报告》 → 《交易结算报告》

---

### 1.4 横切组（风控合规）

**包含Skill**：
| Skill编号 | Skill名称 | 核心职能 |
|-----------|-----------|---------|
| S-XC-01 | 法律服务 | 全流程法律风险识别、合同审核、合规审查 |

**横切组的特点**：
- 不独立推进项目
- 响应任意阶段的法务需求
- 可触发项目终止建议
- 贯穿前端、中端、后端全程

---

### 1.5 调度组（所长编排引擎）

**包含Skill**：
| Skill编号 | Skill名称 | 核心职能 |
|-----------|-----------|---------|
| S-DP-01 | 所长编排引擎 | 决策调度、阶段流转判定、异常处置 |

**所长编排引擎的职责**：
- 确定项目进入哪个阶段
- 判定阶段完成后进入下一阶段的时机
- 处理跨组协同
- 决策终止/转方向

## 二、典型项目流程中的Skill调用链

### 2.1 标准转化路径（外部转让/许可）

```
[成果进入]
    ↓
[S-FR-01 成果挖掘] → 产出《成果挖掘报告》
    ↓ (通过)
[S-FR-02 成果培育] → 产出《成果培育方案》
    ↓ (完成)
[S-MD-01 成果评价] → 产出《成果评价报告》
    ↓ (通过) → [S-XC-01 法律服务]（全程介入）
          ↓
    [并行执行]
    ├── [S-MD-02 知识产权服务] → 产出《知识产权尽职调查报告》
    └── [S-MD-03 金融服务] → 产出《金融服务方案》
          ↓ (两者都完成)
[S-BK-01 成果熟化] → 产出《成果熟化报告》
    ↓ (完成)
[S-BK-02 成果推广] → 产出《推广执行报告》
    ↓ (获得意向)
[S-BK-03 成果交易] → 产出《交易结算报告》
    ↓
[项目完成]
```

### 2.2 自孵化路径

```
[成果进入] → [S-FR-01] → [S-FR-02] → [S-MD-01]
    ↓ (评价通过，且决策自孵化)
    ├── [S-MD-02]（知产服务）
    └── [S-MD-03]（金融服务）→ 孵化资金到位
    ↓
[S-BK-04 成果孵化] → 产出《孵化运营报告》
    ↓
[持续运营直到退出]
```

### 2.3 磁性超级电池完整调用链（案例）

```
【项目背景】
某科研团队声称研发出"磁性超级电池"，能量密度是锂电10倍，循环寿命无限

【调用链展开】

阶段1：前端 - 成果挖掘
─────────────────────────────────────────
[S-FR-01 成果挖掘] 
输入：科研团队的技术论文初稿、实验数据
输出：《成果挖掘报告》

发现：
- 论文声称"突破热力学第二定律"
- 实验数据仅在特定条件下可复现
- 团队缺乏工程化经验
初步判断：存在重大争议，需中端深度评价

────────────────────────────
触发决策：所长编排引擎
决策：通过，进入成果培育
────────────────────────────

阶段2：前端 - 成果培育
─────────────────────────────────────────
[S-FR-02 成果培育]
输入：《成果挖掘报告》、补充实验方案
输出：《成果培育方案》

培育方案：
- 目标：完成100次以上稳定循环测试
- 路径：补充第三方验证数据
- 里程碑：第三方机构出具测试报告

────────────────────────────
触发决策：所长编排引擎
决策：培育方案通过，进入中端评价
────────────────────────────

阶段3：中端 - 成果评价
─────────────────────────────────────────
[S-MD-01 成果评价]
输入：《成果培育方案》、第三方测试报告
输出：《成果评价报告》

评价结果：
【技术评价】❌ 不通过
- 违反热力学第二定律（永动机概念）
- 实验数据无法在独立机构复现
- 无可行的工程化路径

【结论】该成果不具备转化价值，建议终止

────────────────────────────
触发决策：所长编排引擎
⚠️ 技术评价不通过，启动法律服务介入
────────────────────────────

阶段4：横切 - 法律服务介入
─────────────────────────────────────────
[S-XC-01 法律服务]
触发时机：评价阶段发现重大基础科学问题

审查内容：
1. 该成果对外宣传是否存在虚假陈述风险？
2. 已对外发布的融资材料是否涉及欺诈？
3. 研究所签署的保密协议是否需要补充风险告知？

法律意见：
【高风险】项目方已对投资人进行路演，存在误导陈述风险
【建议】立即向所长提交终止建议，并启动投资人沟通

────────────────────────────
触发决策：所长编排引擎
⚠️ 法律服务提交《风险预警报告》
────────────────────────────

阶段5：所长决策
─────────────────────────────────────────
[S-DP-01 所长编排引擎]

决策依据：
- 技术评价：不通过（违反基础物理定律）
- 法律服务：高风险预警（误导投资人风险）
- 知识产权：无布局价值
- 金融服务：无融资可行性

【所长决策】
┌────────────────────────────────────────┐
│ 决策：终止项目                          │
│ 理由：                                   │
│ 1. 技术评价明确否定技术可行性             │
│ 2. 法律风险不可控                        │
│ 3. 继续推进将损害事务所信誉              │
│                                         │
│ 后续动作：                               │
│ 1. 出具《项目终止报告》                  │
│ 2. 协助项目方与投资人沟通澄清            │
│ 3. 将该项目纳入"高风险案例库"备查        │
└────────────────────────────────────────┘

────────────────────────────
[项目终止]
```

## 三、所长编排引擎调度逻辑

### 3.1 调度决策框架

```
                    ┌─────────────────┐
                    │   成果进入      │
                    └────────┬────────┘
                             │
                    ┌────────▼────────┐
                    │  S-FR-01 挖掘   │
                    └────────┬────────┘
                             │
              ┌──────────────┴──────────────┐
              │         通过                  │  不通过
              │         ↓                   │  ↓
     ┌────────▼────────┐          ┌────────▼────────┐
     │  S-FR-02 培育   │          │   项目终止       │
     └────────┬────────┘          │   输出终止报告   │
              │                    └──────────────────┘
              │         通过
              │         ↓
     ┌────────▼────────┐
     │  S-MD-01 评价   │◄── S-XC-01 法律服务（任意阶段触发）
     └────────┬────────┘
              │
   ┌──────────┴──────────┐
   │       通过           │   不通过
   │       ↓              │   ↓
   │  ┌────┴────┐         │  ┌──────────────────┐
   │  ↓         ↓          │  │   项目终止       │
   │ [并行]    [并行]      │  │   输出终止报告   │
   │ S-MD-02   S-MD-03     │  └──────────────────┘
   │ 知产服务  金融服务    │
   │  ↓         ↓         │
   │  └────┬────┘         │
   │       ↓              │
   │   两者都完成          │
   │       ↓              │
   │  ┌────┴────┐         │
   │  ↓         ↓         │
   │ [熟化]   [孵化]       │
   │ S-BK-01  S-BK-04     │
   │  ↓                     
   │ [推广]               
   │ S-BK-02              
   │  ↓                     
   │ [交易]               
   │ S-BK-03              
   │  ↓                     
   │ 项目完成              
```

### 3.2 调度触发条件表

| 当前Skill | 完成信号 | 触发下一Skill | 终止条件 |
|-----------|---------|--------------|---------|
| S-FR-01 | 报告产出 | S-FR-02 | 无价值/硬障碍 |
| S-FR-02 | 里程碑达成 | S-MD-01 | 培育失败 |
| S-MD-01 | 评价通过 | S-MD-02+S-MD-03并行 | 评价不通过 |
| S-MD-02 | 报告产出 | 等待S-MD-03 | 知产风险不可控 |
| S-MD-03 | 资金到位/方案完成 | S-BK-01或S-BK-04 | 无资金支持 |
| S-BK-01 | 熟化完成 | S-BK-02 | 技术不达标 |
| S-BK-02 | 有意向 | S-BK-03 | 无意向转S-BK-04或终止 |
| S-BK-03 | 合同签署 | 项目完成 | 交易失败转S-BK-04或终止 |
| S-BK-04 | 退出 | 项目完成 | 孵化失败转S-BK-03 |
| S-XC-01 | 风险报告 | 可触发所长决策 | 高风险建议终止 |

### 3.3 跳过/终止/转交条件

| 条件类型 | 具体情形 | 调度动作 |
|---------|---------|---------|
| **跳过** | 知识产权已完整，无需再布局 | S-MD-02标记完成，直接进入S-MD-03 |
| **跳过** | 发明人自备资金，无需外部融资 | S-MD-03标记完成，直接进入S-BK-01 |
| **终止** | 违反物理定律/法律硬边界 | 立即终止，出具报告 |
| **终止** | 三次重复评价不通过 | 终止项目 |
| **转孵化** | 评价通过但无合适受让方 | S-BK-04替代S-BK-03 |
| **转交易** | 孵化过程中出现优质收购方 | S-BK-03替代S-BK-04 |
| **暂停** | 资金暂时不到位 | 暂停，等待资金到位信号 |

## 四、各组协同规则

### 4.1 前端→中端交接规则

**交接触发**：S-FR-02（成果培育）完成

**交接内容**：
- 《成果培育方案》完整版
- 培育过程全部技术文档
- 知识产权申请/授权文件
- 发明人配合意愿确认函

**交接确认**：
```
前端 → 中端 交接检查清单：
□ 技术成熟度达到TRL 4-5
□ 核心专利已获受理或授权
□ 无重大知识产权纠纷
□ 发明人签署转化授权书
□ 培育过程数据完整存档
```

**中端接收标准**：
- 符合上述全部条件 → 接收，进入S-MD-01
- 不符合 → 退回前端补充或终止

---

### 4.2 中端→后端交接规则

**交接触发**：S-MD-02 + S-MD-03 全部完成

**交接内容**：
- 《成果评价报告》（正向结论）
- 《知识产权尽职调查报告》（无不可控风险）
- 《金融服务方案》（资金已到位或有明确来源）
- 交易条件框架

**交接确认**：
```
中端 → 后端 交接检查清单：
□ 技术评价正向
□ 知识产权风险可控
□ 资金已到位或有明确承诺
□ 无法律硬障碍
□ 发明人签署转化授权书
□ 商业化路径已明确（熟化 or 孵化）
```

**后端接收标准**：
- 符合上述全部条件 → 接收，进入S-BK-01或S-BK-04
- 不符合 → 退回中端补充或终止

---

### 4.3 横切组协同规则

**触发机制**：
1. **主动触发**：所长编排引擎指定在特定阶段需要法律审查
2. **被动触发**：任意阶段发现疑似法律风险，主动发起咨询
3. **预警触发**：法律法规重大变化，影响在执行项目

**响应时效**：
| 风险等级 | 响应时效 | 处理方式 |
|---------|---------|---------|
| 高风险（可能导致重大损失）| 2小时内 | 出具书面风险提示，建议所长立即决策 |
| 中风险（需要关注）| 24小时内 | 出具法律意见书，提出缓释建议 |
| 低风险（常规审查）| 72小时内 | 在正常流程中完成审查 |

**终止建议权**：
```
法律服务可向所长提交《终止建议书》，触发条件：
1. 项目存在不可修复的法律硬伤
2. 项目涉及法律明确禁止事项
3. 继续推进可能导致事务所承担连带责任
4. 违反国家重大产业政策且无豁免可能

所长收到《终止建议书》后，必须在48小时内给出书面决策。
```

## 五、异常场景调度规则

### 5.1 发明人中途退出

```
触发：发明人通知不再配合转化

调度动作：
1. S-FR-01/S-FR-02阶段 → 立即终止
2. S-MD-01阶段 → 终止（无发明人配合无法完成评价）
3. S-MD-02/03阶段 → 评估是否有足够的存量资料可继续
4. S-BK阶段 → 评估成果的独立转化可行性
   - 可独立转化 → 继续，由法律服务处理权属问题
   - 不可独立转化 → 终止

所长决策后输出《项目终止报告》或《继续执行备忘录》
```

### 5.2 资金链断裂

```
触发：S-MD-03阶段承诺的资金未到位，或后端阶段资金耗尽

调度动作：
1. 已进入熟化/推广 → 暂停，等待资金
2. 暂停超过3个月 → 评估是否终止
3. 有新的资金来源 → 重新评估进入条件

所长决策：是否寻找替代资金方，或启动终止流程
```

### 5.3 政策重大变化

```
触发：S-XC-01预警，政策法规重大调整影响项目

调度动作：
1. S-XC-01出具《政策影响评估报告》
2. 所长编排引擎评估影响程度
3. 高影响 → 立即暂停，评估是否终止
4. 中低影响 → 调整方案后继续

所长决策后输出《政策影响应对方案》
```
