# AI 文档生成工作流（ai-docgen-workflow）

> **证据层级总声明**：本子域种子 docs.anthropic.com 区域封锁（BLOCKED），全文按降级纯模型模式书写。
> 除特别借道标注外，证据层级统一为「实践归纳（降级域，官方锚借道 Google docguide）」[模型经验]。
> 涉 docs.anthropic.com 的引用一律标注「不可达（区域封锁），降级」；不虚构 Anthropic 官方立场——BLOCKED 即未知。

## 定位与心智模型

- **是什么**：本域不回答「怎么写好文档」（内容层，归 code-comment / api-doc-gen 子域），而回答工作流层四问：
  1. 文档动作如何被代码变更**结构性触发**（而非靠人记忆）；
  2. AI 如何被**正确调用**（输入契约、批量会话管理）；
  3. 产出如何被**校验**（人机分工、事实核查分层）；
  4. 全流程如何过**门禁**（CI、反馈回流）。
- **核心心智模型**：
  - 文档过时不是写的问题，是**触发**的问题——「记得更新文档」必然忘记（AW-1）。
  - AI 产出质量 = f(输入质量 + 反馈回流)——无输入契约的调用只能产出结构（AW-3）；无反馈回流的审校是无限循环的修补（AW-10）。
  - 文档债 = 漂移度 × 触达度 × 误导度——triage 先于动手（AW-2）。
- **适用边界**：适用于一切「文档需随代码/系统演进保持同步」的团队工程场景；纯一次性写作、无代码锚定的自由文本创作不在本域。工具具体选型（markdownlint 类生态）以类指称书写，版本事实归 doc-governance 子域。[模型经验]

## 法则

编号与 `08-laws.md` 完全一致（AW-1 ~ AW-11），未增删改号。

**AW-1 [GLOBAL] 文档过时是触发问题不是记忆问题。**
代码变更必须结构性触发文档动作：接口变更 → reference + changelog；行为变更 → 受影响文档扫描（全站 grep 旧行为）；纯实现 → 无动作；PR 模板含文档影响 checkbox；hotfix 流程强制文档影响判断（哪怕「无影响」的显式结论）。
- 违反后果：断链高频发生——行为变更无人扫描受影响文档、hotfix 跳过文档导致用户按错误文档排障、示例烂掉无人知晓；文档持续腐烂且无人有责任。
- 溯源：[官方文档](https://google.github.io/styleguide/docguide/best_practices.html)（Google docguide "Update Docs with Code" 借道锚：文档与代码同一 CL 变更）+ [模型经验]（触发链三态分类，实践归纳（降级域，官方锚借道 Google docguide））｜elicited/01-end-to-end-trigger-chain.md

**AW-2 文档债 = 漂移度 × 触达度 × 误导度，triage 先于动手。**
盘点四象限：高误导×高触达 → 立即修；高误导×低触达 → 修或删；低误导 → 排期/归档。修不完先挂显式警示（错误文档+警示 > 静默错误文档）。大爆炸重写（人工版与 AI 版）都是反模式——分目录增量迁移，每步可用。
- 违反后果：无盘点则债务不可见；「全部重写」烂尾留下半拉子新结构+全量旧内容；静默错误文档让读者按错误操作失败还归咎于自己。
- 溯源：[官方文档](https://google.github.io/styleguide/docguide/best_practices.html)（Google docguide "Minimum Viable Documentation" 借道锚：小而新优于大而烂）+ [模型经验]（triage 矩阵，实践归纳（降级域，官方锚借道 Google docguide））｜elicited/02-doc-debt-triage.md

**AW-3 [GLOBAL] AI 起草必须配输入契约。**
无事实源（代码/类型/diff/既有文档）、无类型与受众约束、无风格样例的空手调用只能产出结构——「帮我写文档」的正确响应是索取输入或降级为模板+提问。
- 违反后果：无输入契约的调用迫使 AI 编造事实——幻觉直出；AI 在无源时「尽力完成」产出看似完整实则虚构的文档。
- 溯源：[模型经验]（实践归纳（降级域，官方锚借道 Google docguide））｜elicited/03-human-ai-division.md、07-ai-workflow-design-mistakes.md

**AW-4 人审定位：抽查 + 幻觉高发位重点核，不做全量质检。**
逐字审校不可持续（强度必然衰减到零）；抽查按高发位加权（数字/版本 > 链接 > 名称 > 断言 > 常识）；「太流畅」警惕——流畅性与事实性无关，对照源读；历史记录类（ADR/changelog）修改必过人工门。
- 违反后果：逐字审校一周后衰减为「看着没问题」直发——审校强度归零比无审校更具欺骗性；全文照发 AI 起草则幻觉长驱直入。
- 溯源：[模型经验]（高发位分布为内省+经验，置信度中高；实践归纳（降级域，官方锚借道 Google docguide））｜elicited/03-human-ai-division.md、05-fact-check-protocol.md

**AW-5 事实核查三分层：工具可验 / 人工必验 / 不可验降级。**
工具层（链接/锚点/示例运行/版本一致性）自动化；人工层（语义/决策真实性/误导性）判断性抽查；不可验断言显式标注（待确认/据 X）或删除——静默的不确定性是缺陷。
- 违反后果：全人工核查不可持续，全工具核查覆盖不了语义；不可验断言静默存留 = 未标注的不确定性长期误导读者。
- 溯源：[模型经验]（协议设计，实践归纳（降级域，官方锚借道 Google docguide））｜elicited/05-fact-check-protocol.md

**AW-6 来源分级：源驱动 > 推断（标注依据）> 先验（高风险降级）> 无源（禁止输出）。**
AI 起草的事实声明按来源分级标记，审校按标记分层抽查；终稿清洗标记后「先验」类必须已验证或已删除。
- 违反后果：无来源分级的草稿使审校者无法定位高风险声明；先验知识（版本/API 细节类）未验证即输出是幻觉的高发通道。
- 溯源：[模型经验]（实践归纳（降级域，官方锚借道 Google docguide））｜elicited/05-fact-check-protocol.md

**AW-7 批量生成四锚：分域分批、风格锚先行、术语表先行、批间 checkpoint。**
一批一个内聚域（10-20 篇内）；风格样例 2-3 篇 few-shot；跨批术语表防漂移；每批人工抽检再开下批（错误模式跨批复制前拦截）；跨批约定显式落盘，不依赖会话连续性。
- 违反后果：全量一次生成窗口溢出或后段烂尾；错误模式跨批复制——第一批的错污染全部批次；术语漂移使同一概念全站三种写法。
- 溯源：[模型经验]（实践归纳（降级域，官方锚借道 Google docguide））｜elicited/04-batch-session-management.md

**AW-8 长会话疲劳是物理约束：批次内设人工中断点，法则写结构性原则不写 token 参数。**
注意力衰减与疲劳漂移真实存在（行业共识性现象，量化数据待考）；量化阈值随模型代际过时——分批/checkpoint/重启的**结构**是稳定层，具体窗口数字是易变层。
- 违反后果：长会话不重启则疲劳漂移累积——前 20 条严谨、后面复读化；把 token 参数写进规则则模型换代即失效。
- 溯源：[模型经验]（长上下文衰减为行业共识性现象，量化待考；实践归纳（降级域，官方锚借道 Google docguide））｜elicited/04-batch-session-management.md、07-ai-workflow-design-mistakes.md

**AW-9 文档 CI 渐进式：链接检查起步，门禁分级（blocking/warning/报告），warning 配额制。**
门禁价值在于被遵守：一步到位全量门禁必被绕过；外链检查三态处理（内链 blocking、外链 warning+豁免、403/429 反爬族豁免）；报错必须可操作；合理例外走豁免流程。
- 违反后果：全量门禁过重被团队整体绕过；warning 泛滥使「黄灯=绿灯」真问题被忽略；无豁免机制的门禁因历史文档无法通过而被关闭。
- 溯源：[模型经验]（实践归纳（降级域，官方锚借道 Google docguide））｜elicited/06-ci-gates.md

**AW-10 反馈回流：审校修正按错误模式归类沉淀，审校是校准不是修补。**
「把这个文档改对」是一次性动作，「把生成器校准」是系统性改进——错误模式清单回流进后续生成规则；无回流的审校使同一错误每次生成重犯。
- 违反后果：审校者每次修同类错误（同样的营销腔、同样的 FAQ 凑数），三个月后 AI 产出风格不变——审校预算白烧。
- 溯源：[官方文档](https://google.github.io/styleguide/docguide/best_practices.html)（Google docguide 借道锚：文档修剪为常态，盆景隐喻——反馈回流同向）+ [模型经验]（实践归纳（降级域，官方锚借道 Google docguide））｜elicited/07-ai-workflow-design-mistakes.md

**AW-11 人机边界双向对齐：AI 不做决策代笔，人不做机器可验之事。**
正向错配（AI 编 ADR forces）与反向错配（人逐字找死链）都是浪费——按角色表与核查分层分工；发布类动作保留人工放行门。
- 违反后果：AI 编造决策记录使历史失真且不可逆；人工预算烧在低价值层导致高价值语义核查无人做；全自动发布无放行门则错误文档直达读者。
- 溯源：[模型经验]（实践归纳（降级域，官方锚借道 Google docguide））｜elicited/03-human-ai-division.md、07-ai-workflow-design-mistakes.md

## 核心概念速览

| 概念 | 一句话定义 |
|---|---|
| 触发链（trigger chain） | 代码变更 → 变更分类 → 文档动作映射 → 动作完成检查的结构性链路（AW-1） |
| 变更分类三态 | 接口变更（必触发 reference+changelog）/ 行为变更（必触发受影响文档扫描）/ 纯实现（默认无动作） |
| 文档债（documentation debt） | 文档与现实的差距 × 读者触达频率；按漂移度/触达度/误导度三维盘点（AW-2） |
| 输入契约（input contract） | AI 起草的四要素输入：事实源、类型与受众约束、风格样例、边界说明（AW-3） |
| 幻觉高发位 | 事实核查优先攻击位排序：数字/版本 > 引用链接 > 名称 > 断言 > 常识性陈述（AW-4） |
| 验证三分层 | 工具可验（自动化）/ 人工必验（判断性）/ 不可验降级（诚实标注）（AW-5） |
| 来源四级标记 | 源驱动 [S] / 推断 [I] / 先验 [P] / 无源（禁止输出）（AW-6） |
| 批量四锚 | 分域分批、风格锚先行、术语表先行、批间 checkpoint（AW-7） |
| 疲劳漂移（fatigue drift） | 长会话后段生成质量下滑、前严谨后复读的现象（AW-8） |
| 门禁分级 | blocking（必过）/ warning（可见不拦+配额制）/ 报告（定期）（AW-9） |
| 反馈回流（feedback loop） | 审校 diff 按错误模式归类沉淀进后续生成规则——审校是训练数据（AW-10） |
| 人机双向错配 | 正向：AI 做决策代笔；反向：人做机器可验之事（AW-11） |

## 最佳实践

### 场景 1：为仓库搭建代码变更 → 文档动作触发链

本实践源于 [AW-1]。

推荐路径：
1. PR 模板加「文档影响」checkbox，强制作者自答（接口变了吗/行为变了吗/均无）。
2. 建立变更分类三态判据与动作映射：接口变更 → reference 更新 + changelog Unreleased；行为变更 → 全站 grep 旧行为关键词建立「受影响文档清单」再改；破坏性变更 → 迁移指南 + deprecated 标注 + 全站 grep 旧用法；纯实现 → 无动作。
3. hotfix 流程强制含「文档影响一句话」（显式的「无文档影响」也算数），并设次日补账机制。
4. 文档与代码同 PR（小变更）或同里程碑（大变更）——不允许文档 PR 跨版本悬置。
5. 文档任务一律 issue 化——「有空再写」永无空。

do/don't：
```
✗ // 指望作者记忆
   PR 描述模板：「如有需要请记得更新文档」
✓ // 结构性触发
   PR 模板 checkbox：
   - [ ] public API 变更 → 已更新 reference + changelog Unreleased
   - [ ] 行为变更 → 已 grep 受影响文档（清单见评论）
   - [ ] 均无
```

边界条件：行为承诺扫描依赖关键词——真实「行为承诺」可能用同义表述，关键词清单应来自全站文档而不是作者猜测；触发链设计要可承受——每 PR 十几道检查的摩擦会被绕过。[模型经验]

### 场景 2：盘点与偿还文档债

本实践源于 [AW-2]。

推荐路径：
1. 三维盘点：漂移度（对照当前代码/行为）、触达度（流量/入口位置/链接入度）、误导度（错误导致的代价）。
2. 四象限 triage：高误导×高触达 → 立即修；高误导×低触达 → 修或删（删掉过时文档比留着更负责）；低误导×高触达 → 排期更新；低误导×低触达 → 归档候选。
3. 修不完先止损：挂显式警示横幅（版本对应关系 + 正确入口链接）——警示本身也进盘点（警示是债务标记不是清偿）。
4. 偿还三通道：随代码还（触发链联动）、专项还（文档日）、止损优先。
5. 大规模偿还走分目录增量迁移：每篇迁移完即合，新旧并存期短——不搞「文档重构月」。

do/don't：
```
✗ // 大爆炸偿还
   「本月用 AI 重写全部文档」一次合入
✓ // 增量迁移
   一次一个目录/域，每步可用，域间 checkpoint
```

边界条件：无真实用户数据（流量/报错关联）时，触达度用结构代理（入口位置/入度/版本关联）；警示横幅中的版本对应关系需对账——编造「本页对应 v2」是新增错误。[模型经验]

### 场景 3：调用 AI 起草前的输入契约设计

本实践源于 [AW-3]、[AW-6]。

推荐路径：
1. 备齐四要素：事实源（代码/类型/既有文档/diff）、类型与受众约束（判型三问）、风格样例（既有文档 2-3 篇）、边界说明（哪些不确定需标注）。
2. 要求 AI 对事实声明做来源标记（草稿态可见、终稿移除）：`[S:src/client.ts:42]` / `[I:由默认导出推断]` / `[P:先验未验]`。
3. 终稿清洗后 `[P]` 类必须已验证或已删除。
4. AI 应在输入缺失时主动声明缺口（「未提供类型源，以下 API 签名为示例」）而不是等待审校兜底。

do/don't：
```
✗ // 空手调用
   「帮我写文档」——AI 只能编
✓ // 契约化调用
   「基于 src/api/*.ts 的类型定义，为本库写 API reference。
    读者：初次接入的中级前端。风格样例：docs/现有两篇。
    所有签名标注来源文件；不确定处标 [P] 留白。」
```

边界条件：低风险语境（结构模板/骨架/语言润色）可无事实源；事实性内容无源时宁可不输出。[模型经验]

### 场景 4：人审校与事实核查的分层落地

本实践源于 [AW-4]、[AW-5]。

推荐路径：
1. 三分层分工：工具层自动化（链接可达性、锚点存在性、示例编译运行、版本号与 package.json 一致性）；人工层抽查（语义准确性、决策真实性、误导性）；不可验断言显式标注或删除。
2. 人工抽查按高发位加权：数字/链接全核（工具可自动）、名称抽 30%、散文抽 10%——随机均匀抽查是低效的。
3. 审校清单四件：事实抽查（随机 3 处核源）、高发位重点（数字/版本号/链接/API 名/引用）、「太流畅」警惕（对照源读一遍）、删除审（AI 补全欲产物该删就删）。
4. AI 起草的 PR 强制人工 approve，走 draft PR。
5. 历史记录类（ADR/changelog）修改必过人工门。

do/don't：
```
✗ // 全量人工质检
   逐字核对每篇 AI 草稿——一个月后审校强度衰减到零
✓ // 抽查 + 高发位重点核
   工具先跑（链接/版本/示例），人只核语义与高发位
```

边界条件：URL 可达 ≠ 内容正确——链接 200 但目标页已重写；高风险引用带锚文本快照（「官方文档『缓存策略』一节」）进人工必验层。AI 能力代际变化会改变分工边界——模型幻觉率下降时抽查密度可调。[模型经验]

### 场景 5：批量生成文档的分批与一致性管理

本实践源于 [AW-7]、[AW-8]。

推荐路径：
1. 按子域分批：一批 = 一个内聚主题域 × 中等规模（10-20 篇内，超出再按模块拆）——不按文件名字母序分批。
2. 风格锚先行：批前人工认可 2-3 篇标准件，每批以样例为 few-shot 输入。
3. 术语表先行：跨批共享术语表显式进 prompt，生成后跑术语一致性扫描脚本。
4. 批间 checkpoint：每批人工抽检再开下批；批次内也设人工中断点（错误模式在同批内自增强）。
5. 跨批约定显式落盘（决策文件/术语表/风格规范），每批显式输入——不依赖会话连续性。
6. 长会话主动重启，防疲劳漂移累积。

do/don't：
```
✗ // 一次全量生成
   「把 docs/ 目录 200 篇全部重新生成」
✓ // 分域 + checkpoint
   「本批只做 API reference 的 auth 模块（12 篇），
    附术语表与两篇风格样例；完成后人工抽检再开下批。」
```

边界条件：正确批次粒度由人工验收吞吐决定，不是模型窗口上限；样例选择不当（样例本身是烂文档）会使错误锚定放大。[模型经验]

### 场景 6：文档 CI 门禁的渐进式接入

本实践源于 [AW-9]。

推荐路径：
1. 第一步：链接检查（半天接入，立刻拦最高频错误）。
2. 第二步：lint + 格式校验（markdownlint 类 + 术语一致性 + changelog 格式校验）。
3. 第三步：示例可运行（成本最高，先只跑 reference 示例；分层：reference 示例必跑、tutorial 全流程跑、散文内片段编译）。
4. 门禁分级：blocking（链接 404、changelog 格式、示例编译失败）/ warning（覆盖率阈值、文风，配额制：新 warning 不许增加，旧 warning 逐步清零）/ 报告（orphan 扫描、过时文档扫描，定期）。
5. 外链三态处理：本站内链 blocking；外链可达性 warning + 豁免清单；403/429 反爬族直接豁免。
6. 生成物新鲜度检查：TypeDoc 类产物与源码同步校验，防「生成过一次再也不跑」。
7. 报错必须可操作（文件/行/修复建议）；合理例外（历史文档不改）走豁免流程。

边界条件：工具名以「此类工具存在」的类指称使用，具体版本事实归 doc-governance 子域；门禁失败必须可修复，否则团队绕过门禁。[模型经验]

### 场景 7：建设审校反馈的回流机制

本实践源于 [AW-10]。

推荐路径：
1. 审校 diff 不止修文档——按错误模式归类（营销腔/FAQ 凑数/幻觉归因……）。
2. 错误模式清单沉淀为生成规则：进后续生成的 prompt / few-shot / lint 自定义规则。
3. 验证结果记录归档：同一错误不再犯的可核查依据。
4. 把审校视为训练数据：「把这个文档改对」是一次性动作，「把生成器校准」是系统性改进。

do/don't：
```
✗ // 一次性修补
   审校者每次手改同样的营销腔，AI 产出永不变化
✓ // 模式沉淀
   「营销腔」列入生成规则禁用清单 → 后续 prompt 显式排除 → lint 扫描兜底
```

边界条件：回流机制依赖团队对「错误模式」的抽象能力——个案无法归纳时先记录原样，积累后再归类。[模型经验]

## 高频坑点（速查）

### 深度展开 Top 2

**坑 1：零审校直出（幻觉长驱直入）**——违反 [AW-4]、[AW-6]
- 症状：AI 生成文档直接 commit/publish，幻觉内容长期在位，读者无法分辨。
- 根因：「看起来很好」的生成质量让审校显得多余——恰恰是最危险时；流畅性与事实性无关。
- 修复：AI 起草的 PR 强制人工 approve + draft PR 标记；抽查按高发位加权；对照源读一遍。
- 报错特征：无报错——静默失效类，最危险。

**坑 2：AI 加持的大爆炸重写**——违反 [AW-2]、[AW-7]
- 症状：「一周用 AI 重写全站」开工，产出风格漂移 + 错误模式全量复制 + 新旧断档三害并发。
- 根因：AI 让大爆炸「更可行」从而更诱人，但一致性风险被放大；文档重写被当「写作项目」而非「增量迁移项目」。
- 修复：域级增量——一次一个域，风格锚先行，域间 checkpoint，每步可用。

## API 速查表

本域无代码 API。本节以三类操作表代之：**生成 prompt 结构模板表**、**生成时机决策表**、**幂等性检查清单**。

### 表 1：文档生成 prompt 结构模板（四件套）

| 约束槽 | 含义 | 必填内容 | 缺失后果 |
|---|---|---|---|
| 类型约束 | 写什么类型的文档（判型） | reference / tutorial / how-to / conceptual / changelog / ADR 之一 + 该类型结构模板 | 结构漂移，类型混写（tutorial 里塞 reference 罗列） |
| 读者约束 | 为谁写 | 受众水平（初级/中级/专家）+ 使用场景（初次接入/排障/迁移） | 深度错配——对新手讲 internals，对专家讲 hello world |
| 格式约束 | 什么风格与骨架 | 风格样例 2-3 篇（few-shot）+ 结构模板 + 术语表 | 「AI 味」输出，与库存量风格割裂 |
| 事实来源约束 | 内容从哪来 | 事实源（代码/类型/diff/既有文档）+ 来源分级标记要求（[S]/[I]/[P]）+ 禁令（无源不输出） | 幻觉直出——AI 以先验补白 |

模板骨架（组合四件套即完整调用契约，对应 [AW-3]、[AW-6]）：
```
基于 <事实源路径/diff> 为 <受众+场景> 写 <类型> 文档。
风格参照 <样例路径×2-3>；术语以 <术语表> 为准。
所有事实声明标来源：[S:文件:行] / [I:依据] / [P:先验未验]。
无源断言不输出；不确定处显式留白标注。
```

### 表 2：生成时机决策表（pre-commit / hook / CI 全量 vs diff 驱动增量）

| 时机 | 适用产物 | 模式 | 理由与注意 |
|---|---|---|---|
| pre-commit | 单文件级小修（ typo / 格式 / 注释微调） | diff 驱动增量 | 秒级反馈；勿做生成式任务（慢且阻断提交） |
| git hook / PR 阶段 | reference 增量、deprecated 标注 | diff 驱动增量 | 变更触发的核心阵地——接口变更 PR 内完成文档动作（[AW-1]） |
| CI 定时全量 | 术语一致性扫描、链接检查、orphan 扫描、生成物新鲜度 | 全量 | 门禁分级落地（[AW-9]）；生成式任务不阻塞合并则用报告级 |
| 发布节点 | changelog 汇编、release notes | diff 聚合（tag 区间） | 有 diff 输入的发布类，AI 起草人终审（[AW-11]） |
| 专项批量 | 文档债偿还、新站建设 | 全量但分域分批 + checkpoint | 批量四锚（[AW-7]）；禁止大爆炸一次合入 |

决策原则：**增量优先、全量兜底**——凡有 diff 锚点的用 diff 驱动；无锚点的周期性检查走 CI 全量但仅报告级起步。

### 表 3：幂等性检查清单（重复生成不产生漂移）

| 检查项 | 判定 |
|---|---|
| 同一输入（源码+diff+样例+术语表）重复生成，事实声明是否一致？ | 事实层必须幂等；语言层允许措辞差异 |
| 术语表命中词是否全部按表内写法输出？ | 术语层必须幂等（扫描脚本可验） |
| 结构模板槽位是否齐全且顺序稳定？ | 结构层必须幂等 |
| 手工修订段落是否被二次生成覆盖？ | 生成范围显式划定（仅生成标注区块），人工区不进 prompt |
| 来源标记是否可复现（[S] 指向确定文件行）？ | 标记层必须幂等 |
| changelog/ADR 等追加型资产是否只追加不改写？ | 历史类永不幂等重写——只追加，修改必过人工门（[AW-11]） |

## 版本注意

- 本子域为**工作流实践域，无规格版本**；工具链（markdownlint / markdown-link-check / TypeDoc 类生态）版本事实以 doc-governance 及对应子域 kb 为准。
- 降级状态声明：种子 docs.anthropic.com 区域封锁（BLOCKED），本子域无官方文档锚定；官方背书仅借道 Google docguide 三条（AW-1 / AW-2 / AW-10）。涉 Anthropic 官方建议的一切表述均为「不可达（区域封锁），降级」——不得以先验补写。
- 结构性原则（分批/checkpoint/门禁分级）为稳定层；量化参数（窗口大小、抽查百分比、覆盖率阈值）随模型代际与团队吞吐变化，使用时按现状校准（[AW-8]）。
