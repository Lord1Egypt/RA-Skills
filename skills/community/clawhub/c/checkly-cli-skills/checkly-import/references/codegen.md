# Generating construct source from payloads

For integrations that already have resource payloads, `checkly/codegen` exports `generateConstructFiles(changes, options)` and its types. This experimental API is intended for Checkly's own services and has no semver stability guarantee. Minimum CLI package version for this export: 10.2.0. Prefer the documented import lifecycle for adopting live resources.

`changes` contains `resources` and optional `auxiliary` snippets. Generation returns `files` (relative `path` plus `content`) and `failures` (resource plus cause); importing the entry and generating files reads no configuration or credentials and writes no files. Inspect failures before using partial output, and handle thrown errors too: an auxiliary resource of a type other than `snippet` throws rather than returning a per-resource failure. The API does not accept an import plan's project `friends`; references to undeclared resources use `fromId()`.

`options.projectDefaults` describes the destination project's shared, browser and multi-step defaults. Omission means the project is unknown: generated properties and empty relation/variable arrays are spelled out where project defaults might otherwise change them. `{}` means a known project with no defaults. `referencedNames` can annotate `fromId()` references with names in trailing comments. A stored runtime is retained; where the construct cannot express an explicit reset to account/global settings, a project runtime or alert-escalation default can still apply. Review those settings in the destination project.

A locked key/value whose value is hidden as `null` is generated using a shared environment-backed `secret()` reference while retaining `locked`, rather than overwriting the stored value with a blank. Supply the intended value through the destination environment before any authorized deployment. This does not convert the pair into a Checkly secret. Deploy previews keep their existing masked-value/coarser-diff behavior for values that cannot be rendered. Source: `packages/cli/src/constructs/key-value-pair-codegen.ts` at the commit below.

Generated check/group locations omit retired Bahrain (`me-south-1`). Unsafe import filename tags that would escape the output directory are ignored in favor of generated names. Generation handles unsupported resources or snippets through failures; inspect those instead of assuming all resources were converted. Browser and multi-step resources with no stored script generate a spec containing an explanatory comment; a stored empty script remains empty. Neither is evidence of a working test. Returned source is for review, not an instruction to apply or deploy it.

The CLI's import command shares this generation implementation and supplies the loaded project's defaults and friend mappings. It still owns plan/apply/commit behavior. Internal `sourcegen` modules support rendering; there is no public `checkly/sourcegen` export to invent.
